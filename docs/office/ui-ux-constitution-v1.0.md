### UX11 단순성과 점진적 공개

자주 하는 업무를 앞에 배치하고 드문 고급 옵션은 필요한 맥락에서 펼친다. 회원·반·날짜·월을 불필요하게 재선택하지 않는다. 개발자가 정할 공통 동작을 사용자 설정으로 떠넘기지 않는다.

단순화를 이유로 대상·금액·상태·실패 원인·복구 수단을 숨기지 않는다. 모든 업무를 같은 Modal이나 같은 단계 수로 강제하지 않는다. 관련 업무는 연결하되 상담·교육·수납의 데이터 의미를 섞지 않는다.

#### 자동화와 사용자 통제

저위험 화면 상태 복원과 유효한 기본값은 자동 처리한다. 불확실한 대상·금액을 추측해 실행하지 않는다. 고위험 업무는 사용자 확인을 유지한다. 화면과 버튼은 수영장 운영 용어를 사용하고 내부 DB명·API명은 그대로 노출하지 않는다.

#### 지침의 최신성

사용자가 제공한 Powerful and Simple 자료는 Windows 7 시대 지침임을 명시한다. 생산성과 단순성의 철학은 참고하되, 최신 Windows 외형·동작의 의무 규정으로 취급하지 않는다. 본 문서의 구체적 설정은 OFFICE 제품 결정이다.

#### 메뉴와 업무 탭

상위 메뉴는 회원관리·수업관리·출결 및 보강·교육관리·재등록 및 수납 등 확정 메뉴 맵을 따른다. 상위 항목의 펼침 버튼과 실제 페이지 이동 버튼을 구분한다. 현재 메뉴의 상위 그룹을 처음에는 펼쳐 보여주고 이후 사용자의 접기 상태를 유지한다.

메뉴 접기는 탐색 공간 정리, 탭 전환은 작업 교체, 탭 닫기는 업무 종료다. 메뉴를 접거나 탭을 바꾸어도 입력을 버리지 않는다. 같은 업무·대상은 기존 탭을 활성화하고, 다른 대상의 미저장 편집을 덮어쓰지 않는다.

업무 탭은 필요한 범위만 도입한다. 화면 내부의 자유로운 겹침 창이나 무제한 다중 탭 관리 기능을 선개발하지 않는다. 탭은 이름·활성 상태·닫기 수단을 표시하고 넘침은 탭 목록으로 접근 가능하게 한다.

#### 페이지와 보조영역

주요 업무는 본문 페이지, 회원 상세는 우측 Drawer, 짧은 입력·확인은 Modal, 복잡한 입력·대량처리는 전용 페이지 또는 단계형 화면을 사용한다. Side Workspace는 실제 업무화면을 사용하며 AI용 복제 업무 로직을 만들지 않는다.

프로그램 내부 업무마다 별도 Windows 창을 생성하지 않는다. 시작 화면의 바로가기와 요약은 허용하되, 회원 업무를 할 때마다 바탕화면으로 돌아가 아이콘을 다시 열도록 만들지 않는다.

### 집중을 방해하지 않는 구성

카드·그래프는 운영 요약에 사용하고 반복 업무는 목록·검색·필터 중심으로 배치한다. 페이지마다 가장 중요한 행동을 명확히 한다. 위험 행동은 일반 저장과 시각적으로 구분한다. 아이콘 단독 버튼은 이름 안내와 접근 가능한 이름을 갖춘다.

### 공간 부족 시 우선순위

먼저 보조 패널을 접고, 다음으로 사이드바를 축소한다. 핵심 회원명·대상·금액·상태·실행 버튼은 유지한다. 넓은 표의 내부 가로 스크롤은 허용하되 전체 페이지의 불필요한 가로 스크롤과 글자 축소로 해결하지 않는다.

## 4 실행과 종료 및 입력 동작

### UX02 프로그램 생명주기

기본 업무 창은 하나다. 재실행 시 기존 창을 복원하고 앞으로 가져온다. 시작 시 기존 인증정책에 따라 대시보드 또는 로그인/PIN으로 이동한다. 마지막 정상 위치·크기·최대화를 복원하고 모니터 변경으로 화면 밖에 있으면 보정한다.

최소화는 작업표시줄, X와 Alt+F4는 같은 정상 종료 절차다. 트레이 숨기기를 기본 종료로 사용하지 않는다. 로그인 유지와 Windows 자동 실행은 기본 OFF다. 자동 실행 설정은 Foundation에서 선개발하지 않는다.

인증 유지는 명시적 선택 시에만 safeStorage/DPAPI를 사용한다. 비밀번호·PIN·임시 web_session은 저장하지 않고 기존 인증 재검증 계약을 유지한다. 정상 종료 시 stream·timer·안전 저장 처리를 정리한다.

### UX04 닫기와 미저장 보호

| 상황 | 공통 동작 |
| --- | --- |
| 조회 Drawer | X·ESC·바깥 클릭으로 닫기 |
| 입력 Modal 및 Drawer | 바깥 클릭으로 닫기 금지. 수정 없으면 X·ESC·취소로 닫기 |
| 미저장 이동 및 종료 | 저장하고 이동 / 버리고 이동 / 계속 편집. 종료 문맥에서는 동사 변경 |
| 저장 선택 | 저장 성공 후 이동·종료. 실패하면 내용과 화면 유지 |

| 겹친 메뉴와 팝업 | 가장 위 레이어 하나만 ESC 처리. 중복 확인창 방지 |

### UX05 버튼과 키보드

일반 편집 하단 오른쪽 버튼 순서는 저장 → 취소, 위험 확인창은 실행 → 취소이며 취소에 초기 포커스를 둔다. 버튼 이름은 회원 등록·반 이동·환불 실행처럼 실제 행동을 표시한다.

검색창 Enter는 검색, 여러 줄 Enter는 줄바꿈이다. 일반 입력 중 임의 저장을 금지하되 포커스된 버튼의 Enter/Space 활성화는 유지한다. Ctrl+S는 활성 화면의 일반 저장만 처리하며 금융·삭제 최종 실행에는 적용하지 않는다.

Tab/Shift+Tab은 논리적 순서, Modal은 내부 포커스 순환과 배경 조작 차단을 적용한다. 포커스를 눈에 보이게 표시한다. 한글 IME 확정 Enter를 검색·저장·AI 전송으로 중복 처리하지 않는다.

업무 데이터는 명시적 저장을 기본으로 한다. 필터·정렬·창 크기 자동 유지는 업무 데이터 저장과 구분한다. 실행 중 해당 버튼에 진행 표시를 제공하고 중복 실행을 차단한다. 서버 확인 후 성공 표시와 관련 화면 갱신을 수행한다.

| 상태 | 사용자에게 보이는 처리 |
| --- | --- |
| 조회 중 | 해당 영역의 진행 표시. 다른 무관한 업무까지 잠그지 않음 |
| 빈 결과 | 등록 데이터 없음과 검색 결과 없음을 구분하고 다음 행동 안내 |
| 입력 오류 | 해당 항목 옆 오류와 첫 오류 포커스. 입력 내용 유지 |
| 저장 성공 | 간단한 알림과 데이터 반영. 매번 확인창을 띄우지 않음 |
| 실패 | 중요 실패는 지속 표시하고 재시도 또는 해결 방법 제공 |
| 오프라인 | 연결 상태 표시. 인증 만료로 오인해 token을 삭제하지 않음 |
| 결과 불명 | 처리 상태 확인 필요 표시. 성공·실패를 단정하지 않음 |
| 버전 충돌 | 다른 변경과 충돌했음을 표시. 입력을 무단 덮어쓰지 않음 |

창 닫기와 서버 작업 취소는 다르다. 요청이 전달된 뒤 창을 닫았다는 이유로 취소 완료를 표시하지 않는다. 재시도 가능 여부는 작업 성격과 서버 계약에 따라 결정한다.

### UX07 목록과 Context

상세 닫기·뒤로가기 시 검색·필터·정렬·페이지·스크롤을 복원한다. 행 상세 열기와 체크박스 선택을 분리한다. 필터·페이지 변경 시 일괄 선택을 해제하고 실행 전에 대상과 건수를 표시한다.

서버의 현재 데이터와 권한이 저장된 화면 상태보다 우선한다. 사용자·Pool 전환 시 이전 데이터·선택·민감한 Context를 제거한다. 접기·탭 전환·모드 전환 자체는 편집 취소가 아니다.

#### 백그라운드 변경과 편집 충돌

조회 상태에서는 관련 데이터만 갱신한다. 사용자가 편집 중인 필드가 다른 경로에서 변경되면 입력을 덮어쓰지 말고 충돌을 표시한다. 재조회·비교·재적용은 해당 Action의 버전 검증 규칙을 따른다. SSE는 갱신 신호이며 금융 원장과 영구 전달 보장을 대신하지 않는다.

## 6 AI 공통 실행 계약

### UX08 위험 작업과 사용자 확인

대량변경·삭제·결제·환불·권한변경은 대상·건수·금액·변경 결과 Preview → 사용자 확인 → 실행 순서다. 동명이인은 먼저 해소한다. 확인 후 대상·금액·revision이 달라지면 다시 확인한다. AI가 사용자 확인을 대신 승인하지 않는다.

### UX12 메뉴와 AI의 동일 실행 경로

메뉴·업무 링크·AI는 동일 Action과 canonical Service/API를 사용한다. GPT는 의도·대상 해석·계획을 담당하고 서버가 권한·검증·금액 계산·실행·Audit·Realtime을 담당한다. 백그라운드 업무는 사용자가 지시하거나 승인한 범위 안에서 수행한다.

| 계약 요소 | 필수 원칙 |
| --- | --- |
| 대상 식별 | 확정된 entity ID·Pool·현재 권한. 이름 문자열만으로 수정 금지 |
| 허용 입력 | Action별 필수값·허용 필드·검증 규칙. 임의 필드 수정 금지 |
| 실행 조건 | 최신 상태·권한·revision 재검증. 오래된 Context로 실행 금지 |
| 확인 정책 | 조회·일반 수정·고위험을 Action별로 고정. 일반 수정도 지시 범위 명확화 |
| 중복 방지 | 동일 요청 재전달 시 중복 변경 방지. 필요한 쓰기 작업에 멱등성 적용 |
| 결과 상태 | 성공·실패·충돌·결과 불명을 공통 의미로 반환. 구체 schema는 구현 시 확정 |
| 감사기록 | 실행 주체·대상·필요한 변경 내역·결과·menu/ai 출처 기록 |
| 화면 반영 | 관련 query만 갱신. 편집 중 입력 보존과 충돌 정책 적용 |

회원번호·전화번호·정확한 대상 등 구조화 입력은 가능한 경우 LLM 없이 FAST PATH로 처리한다. 금융 timeout은 거래 상태와 멱등성 계약을 확인하고 무조건 재전송하지 않는다. 화면 OPEN만으로 업무 실행 완료를 선언하지 않는다.

AI 결과는 초안·저장·공개를 구분한다. GPT 직접 SQL/DB write, secret·비밀번호·카드 원문 prompt 전달을 금지한다. 민감한 변경 내역은 권한이 있는 감사 저장소에서 관리하며 일반 Production 로그에 원문을 남기지 않는다.

#### 확장성의 경계

일관된 실행 계약으로 메뉴와 AI를 연결한다. 속도 향상은 실제 시나리오에서 측정한다. 범용 Workflow Engine·미래 산업 Adapter·새 ENGINE을 선개발하지 않으며, OFFICE 업무 Action과 수영 전문 AI ENGINE의 책임을 섞지 않는다.

## 7 Replit 적용과 최종 검수

### UX09 공통 구현과 예외

기존 공통 컴포넌트를 우선 확인하고 Modal·Drawer·미저장 확인·알림·실행 상태를 공통 경로로 구현한다. 개별 override는 이유·영향·승인 기록이 있어야 한다. 새 UI framework나 dependency 도입을 본 문서가 승인하지 않는다.

### UX10 문서 고정과 개발 순서

| 순서 | 결과와 진행 조건 |
| --- | --- |
| UI 기준 검증 | 두 모드 시안과 권장 치수 확인. 화면 비교 전 시안 완료로 보고하지 않음 |
| UX00 문서 고정 | UX01~UX12를 저장소 문서에 통합. 적용 AGENTS.md 등에서 필수 참조 |
| UX00 검수 | 문서·지침 diff와 누락·충돌 확인. 앱 구현·설치·배포 없이 보고 후 정지 |
| F01 | 대상 계정·인증·Origin·Windows 환경과 실제 계약 확인 |
| F02~F07 | 해당 Task의 창·인증·연결·종료 규칙만 구현하고 Windows 증거 확보 |
| Stage 2 | Navigation·탭·상태 복원·Side Workspace 확장 |
| Stage 3 이후 | Slice별 Menu·Action·AI·UX 연결. 공개 기능 coverage 검증 |

이전에 작성한 UX01~UX10 지시문만으로는 최신 합의가 모두 반영되지 않는다. UX11 설계 철학과 UX12 실행 계약을 포함한 통합본을 사용한다. 현재 Replit 고정 완료 증거는 제출되지 않았다.

#### 시안과 구현의 검수 시나리오

① 회원검색 → 상세 → 수정 → 저장 → 목록 복귀. ② 미저장 상태에서 메뉴 이동·탭 닫기·앱 종료. ③ AI 검색 → 실제 화면 OPEN → 허용 수정 → 결과 반영. ④ 사용자 편집 중 AI 변경 충돌. ⑤ 미납 → Invoice → 수납·환불 Preview와 확인. 각 흐름에서 단계 수·반복 입력·오조작·상태 유실을 확인한다.

Windows 배율·좁은 화면·긴 이름·한글 입력·키보드만 사용·권한 회수·중복 클릭·오프라인·결과 불명을 관련 단계에서 검증한다. 전체 suite나 installer를 매 Slice마다 반복하지 않는다.

#### 완료보고와 변경 통제

보고 항목: TASK PASS/HOLD/FAIL, CHANGED, VALIDATED, NOT RUN, UX RULES APPLIED, UX VALIDATED, UX EXCEPTIONS, KNOWN ISSUES, CREDIT/USAGE, SHA/PUSH, NEXT. 문서 고정 PASS와 UI 구현 PASS, 실제 Windows PASS는 구분한다.

규칙 변경은 변경 이유 → 영향범위 → 추가 작업량 → 기존 기능 영향을 보고하고 승인 후 버전을 올린다. 완료보고 검수와 다음 Task 승인 없이 자동 진행하지 않는다.
