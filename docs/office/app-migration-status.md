# 기존 앱 → OFFICE 운영 기능 연결 목록

이 목록은 메뉴 수나 완료율이 아니다. **연결**은 기존 실제 API를 호출하도록 구현했다는 뜻이며, 운영 계정으로 저장·발송까지 실증했다는 뜻이 아니다. 변경부의 제한 검사와 운영 미실행 범위는 통합본 전달 보고에서 구분한다.

## 공통 증거 경계
- 기존 PASS 결과를 재사용한다. 이번 변경부만 제한 검사하며 새 검증 환경·전체 suite·전체 monorepo 검사를 만들거나 실행하지 않는다.
- 운영 DB/schema·서버 배포·실발송·실거래·유료 AI 호출은 이 구현 작업의 테스트로 수행하지 않는다.
- 업로드·API 저장의 HTTP 성공과 서버 재조회 결과를 구분한다. 성공 후 재조회 실패·서버 실패 응답·결과 불명을 완료로 표시하거나 자동 재전송하지 않는다.
- 연결되지 않은 자연어 입력/실행을 화면 이동이나 공통 Action 존재만으로 AI 완료라고 표시하지 않는다.
- PC 영상은 기존 원본 multipart 업로드와 공용/개인 첨부 API에 연결했다. 모바일 압축을 복제하지 않는다. 원본 업로드 ID 확인, 첨부 대상 반/노트 재확인, updated 개수와 대상 일지 영상 목록을 각각 확인한다.
- 서버 승인 대기: 관리자 보강 5개 처리 경로 및 영상 목록의 직접 재생주소 응답 보완. 두 패치는 미적용 상태이며 서버 배포·schema 변경·운영 쓰기는 수행하지 않았다. 재생주소가 없는 목록은 메타데이터 확인만 제공하며 재생 완료로 표시하지 않는다.
- 정책상 제외: super_admin 커리큘럼 최종 승인/구조화 편집, 학부모 본인의 OTP 입력을 센터 계정에 개방하지 않는다. 요청 없는 보호자 계정 수동 연결은 여전히 미연결이며, 요청 승인 UI로 대체해 완료로 계산하지 않는다.
- 실제 자연어 실행 연결: 기존 Stage 3 회원 수정/반이동(서버 활성화 조건 유지)과 `일지 ID 삭제`의 제한 명령. 삭제는 실시간 조회·작성자 검사·사용자 확인 후 같은 Action/API를 사용한다. 단순 화면 열기와 구분한다.
- 실제 미지원: 임의 자연어의 모든 필드 입력/저장·파일 자동 선택/전송·범용 HTTP 실행. 파일은 사용자가 고른 실제 File만 전송한다. 레거시 신규 CRM·Billing 원장도 후속 범위로 남긴다. **100% 앱 이식·AI 실행 완료가 아니다.**
- 강사 리포트 본문 직접 수정은 기존 서버 계약상 금지이며 승인/재분석 요청만 연결한다. 재분석 접수는 분석 완료나 발행 완료가 아니다.

## 2026-10-18 — Smartro 전 운영 통합 (앞선 후속/미구현 표기의 현재 대체 상태)

기능별 설치본·중간 수용 대기 없이 기존 제품에 합쳤다. 아래의 **구현/연결**은 소스 상태이며 운영 서버 적용·실제 저장·Windows 수용 PASS가 아니다.

### 최신 지시 대조·잔여 구현
- 운영 적용 완료 기준은 승인된 `65970347d33889c90e896ed2b236da45ac1ae290`·schema 2다. 이전 표의 해당 migration 대기 표기는 이 기준으로 대체한다. 기존 조회 성공은 새 쓰기/Windows 성공으로 확대하지 않는다.
- 재사용: 상품·계약 스냅샷, 개별 청구·부분수납·배분·환불·마감, 관리자 리포트, 다중 파일 이전, 제한 태블릿 서명, NFC 출결 및 수동 운영지원.
- 잔여 연결: 대량 청구의 원자적 처리, 재등록 대상→새 계약→청구→잔액, 검색/회원 필터와 출력·합계, 회원 이전의 결과 불명 잠금·영수증 복구, 가맹점 신청 안내·수동 단계 이력.
- 외부 조건 대기: Smartro 공식 계약·서류·승인·활성화 연동, 배차 원문, 실제 Windows 출력·태블릿 서명·NFC reader. 이 조건으로 독립 구현을 중단하지 않는다.
- 모바일 신청 진입·상품 노출 변경은 후속 앱 빌드에 모은다. 새 서버 소스는 별도 운영 승인 대상이며 기존 migration은 재적용하지 않는다.

### 공통 Action/AI
- 새 일반 업무도 기존 `OfficeActionCore`/Native 권한·공통 API를 사용한다. 신규 운영 GET/POST는 관리자만 허용하며 교사에게 관리자 monthly-list를 열지 않는다.
- 일반 메뉴·조회는 AI 없이 무료로 사용한다. 새 운영 AI는 선택 자료의 동일 입력 양식/재무 impact-preview로만 초안을 전달한다. 실행은 같은 권한·revision·명시적 금액/영향 확인을 거친다. 직접 서명이나 임의 대상 선택을 AI가 대신하지 않는다.
- **이동/조회 연결**, **초안 연결 코드(모델 별도 승인 전 OFF)**, **동일 일반 실행 연결**, **실제 모델 동작 미확인**을 구분한다. 모든 자연어·파일 자동 선택/전송 완료를 주장하지 않는다.
- 5xx/연결 단절은 UNKNOWN, 404/빈 영수증은 미처리 증거가 아니다. 확인 전 새 요청으로 재전송하지 않는다.

3. 10만 원 청구에 4만 원 부분 배분, 미납 6만 원·미배분금, 중복 배분 거부, 가족 표시와 회원별 귀속을 확인한다.
4. 청구 감액·배분 해제·오입력 취소·부분환불 기록을 구분하고 원금 초과/같은 식별자 거부, 마감 후 수정 차단과 사유 있는 해제를 확인한다. 실제 결제/환불은 하지 않는다.
5. 기간 수납/환불/지출과 누적 미납의 기준·CSV·인쇄/PDF를 대조한다. 강사정산을 학생 청구로 합산하지 않는지 확인한다.
6. 이전 규칙 수정/취소로 기존 preview가 폐기되는지, 모호한 회원·중복 잔여·운영 시작 후 자료가 보류되는지, 정상/보류/실패·원본·금액/횟수·이어하기를 대조한다.
7. 태블릿 제한 링크로 직접 동의/서명 후 관리자가 실제 회원을 연결하고 당시 양식/문서를 다시 열어 인쇄/PDF를 확인한다. 만료 링크·서명 대필·관리자 전체 화면 노출이 없어야 한다.
8. UID+Enter 리더를 연결해 대상 수업 선택/출석, 중복 탭·분실/다른 센터 카드 거부를 확인한다. 알림은 별도 승인 없이 켜지 않는다.

10. 승인 없이 자동 모델 호출이 없고 일반 입력은 계속 되는지, 금액 영향 확인과 결과 불명 잠금이 정상인지 확인한다.

운영 미적용 상태에서는 위 새 저장/서명/reader 출결 시나리오를 성공으로 확인할 수 없다. 서버 적용 대기·실장비 미확인·Windows 미확인을 분리한다. 소스와 최종 installer 식별/검사 수치는 최종 채팅 보고 및 installer-result.json을 기준으로 한다.

15. **가맹점/외부 조건:** 수납→가맹점 결제 신청에서 단계별 수기 참조·확인일과 이력을 확인한다. 이전 단계에 근거가 없으면 완료로 추정하지 않아야 한다. 휴대폰 안내에는 센터 개인정보·개별 상태·민감 서류 입력이 없어야 한다. 공식 문서가 오기 전 실제 제출/승인/활성화 버튼은 없어야 한다.
16. **Windows/장비:** 최종 설치본을 기존 PC에 설치해 기존 사용자 데이터 유지, 현재 화면 인쇄/PDF, 기존 태블릿 제한 링크 서명과 UID+Enter reader를 함께 확인한다. 실패 시 재설치/재청구를 반복하지 않고 요청 ID·서버 결과/원본을 먼저 확인한다. 개발 도구 설치나 소스 빌드는 필요 없다.
