### 배차 V2 후속 source 통합 — 운영 미적용

- 기준은 2026-10-19 V2 설계서다. GPS는 운행 중 안내 조건으로 허용하며, 이전/다음은 화면만 이동한다. C를 A/B보다 먼저 확인해도 A/B 미처리를 보존한다. 내비·길찾기·학부모 차량 추적·셔틀 NFC는 계속 제외한다.
- PC: 기존 차량·승차지를 재사용한 날짜별 혼합 CENTER_BOARD→DROP/PICKUP→CENTER_HANDOVER 편집, 정기/기간/요일/임시 이용 설정, 전체 회원 대상 검색, 날짜별 후보 조회, 차량 가용 시간, 저장·검수·확정·명시적 게시·서버 현황/사유 있는 정정 이력·업무용 출력. 등록 구간 시간 부분 재계산은 AI/Solver/도로 ETA가 아니다.
- 권한: 기존 로그인 신원을 그대로 쓰는 센터별 DRIVER/ESCORT 멤버십. 관리자 명시 초대→본인·동일 센터·만료 확인 수락→배정→회수. 전역 role enum·강사/관리자 권한을 부여하지 않는다. 신규 계정 최초 가입 동선은 미결정이며 임의 계정을 만들지 않았다.
- 공통 서버: 센터·기존 실제 관리자/승인 보호자·활성 운행 멤버십 검사, 현재 담당 운행만 명단/연락처 제공. 구간별 정원, 현재 수강 기간·보강 배정, 운영자 결석, 가용 시간, 확정/게시 운행 간 겹침을 검사한다. 실제 수업 요일·시작/종료·휴강/수업 변경·센터 버퍼 자동 대조는 아직 부족하므로 운영 최종 검수 완료가 아니다.
- 초안·확정·게시·현재 버전 ACK를 구분한다. 이미 게시된 운행 수정은 pending 버전으로 분리하며 게시 전 기사에게 바꾸지 않는다. 실제 확인 구간의 당시 자료는 master 수정으로 덮어쓰지 않는다. 공통 영수증·센터 transaction lock·append-only 버전/이벤트를 사용하며 새 업무 DB가 없다.
- 기사/인솔자 앱: 기존 로그인·메뉴와 root 운행 화면 연결. ACK·운행 시작·전원/일부 승하차·명시 미탑승·선택 연락처 전화 앱·직전 본인 오입력 사유 정정·센터 복귀/미하차/차내 최종 확인을 연결했다. 실제 벨트/차내 잔류/법정 장치의 자동 증명이 아니다.
- native 보호 보관: 계정/센터별 SecureStore 분할 commit-head와 직렬 읽기/쓰기. 기기 입력·전송 대기·서버 반영을 분리하고 원 requestId/본문/버전을 재시작 후 보존한다. 새 버전/권한 회수 충돌은 보류하며 삭제·다른 계정 재전송하지 않는다. 회수 후 서버 신규 요청은 거부하고 앱 재조회 시 명단을 닫는다. 오프라인 기기 원격 즉시 삭제나 관리자 대조 해결 UI는 구현/증명하지 않았다.
- GPS: 관리자가 좌표/반경/머무름을 직접 입력·현장 확인한 정류장만 사용한다. 기본 반경/머무름을 추정하지 않으며 앱 사용 중·운행 중 명시 opt-in 위치 감시만 한다. 신호 신선도·정확도·머무름을 검사한다. GPS/시간 중 먼저 안내하고 운행/버전/정류장 키로 중복을 막는다. 위치 서버 전송·자동 승하차가 없고 거절/신호 부족 시 직접 확인이 가능하다.
- 학부모 앱: 승인된 자기 자녀의 게시 일정·승차/하차/미탑승·기기/서버/조회 시각만 투영한다. PC/학부모는 유한 주기 재조회다. 차량 푸시 희망 ON/OFF를 저장하고 승인 관계·ON인 수신자만 고유 알림 intent를 만든다. intent는 HELD_FOR_DISPATCH_APPROVAL이며 기존 push dispatcher 미연결·실발송 0이다. 정정된 intent는 무효화한다. SMS 자동 전환은 없다.
- `office-transport-v2.sql`은 V1 준비 migration 뒤에 적용할 **미적용 신규 SQL**이다. 7개 V2 테이블·보호자 관계 1개 선택 열·기존 영수증 재사용이다. API startup은 SQL을 실행하지 않으며 미적용이면 503이다. 운영 자동 활성화/배포/새 유료 호출 승인이 아니다.
- Expo SDK 55의 SecureStore/Location 의존성과 foreground 전용 native 설정을 추가했다. Always/Background/Android foreground service 권한은 켜지 않았다. **기존 앱에 OTA만 보내면 되는 변경이 아니다.** iOS/Android 통합 native 빌드·실제 binary target/min OS 및 실기기 검증이 필요하며 이번에 생성/배포하지 않았다.

### 실제 남은 V2 구현과 검증

- 회원/수업 원본 계약의 실제 요일·시작/종료/휴강·변경·센터 버퍼 대조, 후보의 자동 혼합 초안 생성·AI 의도 해석/배차 제안·제약 Solver·등록 pairwise 시간 매트릭스. 고정/처리 구간 제약을 임의로 풀지 않는다.
- Android 다른 앱/잠금 상태의 알림 action/foreground service, iOS 알림 action/Live Activity와 지원 불가 시 카드 진입 fallback. 현재 foreground GPS/시간 안내만 연결됐으며 백그라운드·종료 상태 실행을 보장하지 않는다.
- 푸시 ON 조건의 기존 dispatcher 연결·실패 상태/재시도 운영 검증, SSE가 필요한 갱신 경로, 보류 관측의 관리자 대조·해결 UI, 외부 직원의 신규 가입/초대 UX 결정, 운행 당시 인계조건 snapshot·기사 표시.
- 주유/정비/보험/검사와 실제 확인 기반 분기 법정 XLSX/PDF·검수·서명. 현재 `window.print()`는 비공식 업무 출력이며 법정 장부 완료가 아니다.
- 실제 PostgreSQL 새 SQL/트리거·동시성·rollback과 기존 인증으로 세 클라이언트 저장/ACK/부모 투영, Windows 10/11·iPhone/Android·통화/권한/오프라인 재시작·화면 잠금 통합 검수. 단위 mock·타입/번들은 이를 증명하지 않는다.
- 새 운영 SQL/배포/실발송/추가 유료 모델은 기존 소진된 4회 승인을 재사용하지 않고 정확한 범위·모델/횟수/token/금액을 모아 따로 승인받는다. 설치본·앱 빌드도 의미 있는 통합 단위 한 번으로 모은다.
- 이번 변경 관련 고유 검사 **76건**: 서버 순수/주입 단위 47, PC UI/Native 경로/복구 24, 기기 보관 5. 재실행을 합산하지 않았다. Desktop main+renderer, 변경 native 경로, 공유 transport strict 타입·신규 API bundle·diff 검사가 통과했다. 앱 전체 타입 검사는 기존 테스트 전역 선언 오류 등으로 실패했으며 전체 PASS로 바꾸지 않는다.

## 공통 증거 경계
- 기존 PASS 결과를 재사용한다. 이번 변경부만 제한 검사하며 새 검증 환경·전체 suite·전체 monorepo 검사를 만들거나 실행하지 않는다.
- 운영 DB/schema·서버 배포·실발송·실거래·유료 AI 호출은 이 구현 작업의 테스트로 수행하지 않는다.
- 업로드·API 저장의 HTTP 성공과 서버 재조회 결과를 구분한다. 성공 후 재조회 실패·서버 실패 응답·결과 불명을 완료로 표시하거나 자동 재전송하지 않는다.
- 연결되지 않은 자연어 입력/실행을 화면 이동이나 공통 Action 존재만으로 AI 완료라고 표시하지 않는다.
- PC 영상은 기존 원본 multipart 업로드와 공용/개인 첨부 API에 연결했다. 모바일 압축을 복제하지 않는다. 원본 업로드 ID 확인, 첨부 대상 반/노트 재확인, updated 개수와 대상 일지 영상 목록을 각각 확인한다.
- 서버 승인 대기: 관리자 보강 5개 처리 경로 및 영상 목록의 직접 재생주소 응답 보완. 두 패치는 미적용 상태이며 서버 배포·schema 변경·운영 쓰기는 수행하지 않았다. 재생주소가 없는 목록은 메타데이터 확인만 제공하며 재생 완료로 표시하지 않는다.
- 정책상 제외: super_admin 커리큘럼 최종 승인/구조화 편집, 학부모 본인의 OTP 입력을 센터 계정에 개방하지 않는다. 요청 없는 보호자 계정 수동 연결은 여전히 미연결이며, 요청 승인 UI로 대체해 완료로 계산하지 않는다.
- 실제 자연어 실행 연결: 기존 Stage 3 회원 수정/반이동(서버 활성화 조건 유지)과 `일지 ID 삭제`의 제한 명령. 삭제는 실시간 조회·작성자 검사·사용자 확인 후 같은 Action/API를 사용한다. 단순 화면 열기와 구분한다.
- 실제 미지원: 임의 자연어의 모든 필드 입력/저장·파일 자동 선택/전송·범용 HTTP 실행. 파일은 사용자가 고른 실제 File만 전송한다. 레거시 신규 CRM·Billing 원장도 후속 범위로 남긴다. **100% 앱 이식·AI 실행 완료가 아니다.**
- 강사 리포트 본문 직접 수정은 기존 서버 계약상 금지이며 승인/재분석 요청만 연결한다. 재분석 접수는 분석 완료나 발행 완료가 아니다.

### 공통 Action/AI
- 새 일반 업무도 기존 `OfficeActionCore`/Native 권한·공통 API를 사용한다. 신규 운영 GET/POST는 관리자만 허용하며 교사에게 관리자 monthly-list를 열지 않는다.
- 일반 메뉴·조회는 AI 없이 무료로 사용한다. 새 운영 AI는 선택 자료의 동일 입력 양식/재무 impact-preview로만 초안을 전달한다. 실행은 같은 권한·revision·명시적 금액/영향 확인을 거친다. 직접 서명이나 임의 대상 선택을 AI가 대신하지 않는다.
- **이동/조회 연결**, **초안 연결 코드(모델 별도 승인 전 OFF)**, **동일 일반 실행 연결**, **실제 모델 동작 미확인**을 구분한다. 모든 자연어·파일 자동 선택/전송 완료를 주장하지 않는다.

최종 패키지 검토에서 양식별 별도 AI 버튼과 재무 입력의 late-response 보호를 보완했다. 운영 양식은 현재 필드 fingerprint, 재무 양식은 현재 업무·날짜·금액·대상·잠금/처리 상태를 동일 editor 계약에 포함한다. 요청 후 수동 편집 시 이전 응답은 현재 양식을 덮어쓰지 않는다. 다른 재무 탭에서 기존 미저장 초안을 소리 없이 교체하지 않는다. 이 보완 전 제작을 시작한 전달 디렉터리는 중단 후보로 보존하고 전달하지 않는다. 최종 설치본과 소스 식별은 이후 성공한 installer-result.json을 기준으로 하며 실 Windows 수용을 주장하지 않는다.

## 잔여 기능 연속 구현 — 기능 우선, 설치본 재제작 없음

이 절은 앞 표 ⑥의 **공지·학부모 요청 답장 AI 필드 입력 미구현** 상태를 대체한다. 파일 자동선택·직접 서명 대행·모든 메뉴의 범용 AI 실행까지 완료했다는 뜻은 아니다.

- 공지 제목/본문과 선택한 요청의 답장 본문을 기존 editor 계약에 연결했다. 메뉴의 선택형 AI 버튼과 일상 AI 작업창이 같은 입력 양식에 초안만 전달한다. 고정 미리보기/저장/발송 명령은 모델 없이 기존 사용자 확인·공통 Action으로 연결한다.
- 공지의 고정/푸시, 답장의 수신 요청/상태/처리 메모는 모델 변경 대상이 아니다. 현재 센터의 선택 자료만 서버에서 읽고, 답장 모델 문맥은 최근 6개 메시지로 제한한다. 읽음 처리 GET은 AI 문맥 조회에 사용하지 않으며 내부 처리 메모는 전송하지 않는다. 서버 원문이 모델 응답 중 바뀌거나 로컬 대상·필드·잠금이 바뀌면 초안을 폐기한다.
- 공지/답장 미리보기는 대상·텍스트·알림 영향을 확인하며 수정 후 무효화된다. 실제 저장/발송은 기존 API와 공통 Action을 통한다. 요청별 답장/메모, 사용자·센터·역할별 세션 초안을 보존하고 다른 요청의 늦은 성공/실패가 현재 입력을 지우지 않는다. 결과 불명은 재전송하지 않는다.
- 확인된 수납→원래 청구의 배분 연결을 메뉴 이동 뒤에도 보존한다. UNKNOWN은 같은 영수증 확인 후 연결을 복원하며 재수납하지 않는다. 배분은 다시 현재 원장 미리보기·확인을 거친다. 이미 배분/환불/무효 처리되어 잔액이 없거나 청구가 끝난 것이 현재 원장에서 확인되면 해당 후속 연결을 제거한다. 조회에 행이 없다는 이유만으로 완료 처리하지 않는다.
- 성장리포트 PDF 비활성 버튼을 같은 ID·버전의 기존 상세/본문 렌더러에 연결했다. 선택한 보고서만 OS 인쇄·PDF 저장창으로 전달하고 다른 ID 응답은 표시·출력하지 않는다. 재분석·발급·발송·새 파일 서버 저장은 하지 않는다. OS 출력/저장 성공은 미검증이다.
- 기존 회원/수강/청구/환불/마감·보고서/문서/운영지원·무료 이전 회원/금융/권리 파이프라인은 보존했다. 전체 검사·기능별 설치본·schema 2 재적용은 하지 않는다.

최종 통합 검수 추가 항목:
17. Normal 직접 공지/답장 입력과 X 초안 입력 모두 미리보기→확인→같은 Action을 거치며, AI 초안을 저장/발송 성공으로 표시하지 않는지 확인한다.
18. A 요청 발송 중 B 요청을 열어 입력한 뒤 A 응답이 도착해도 B 입력이 보존되는지, 수동 입력/대상 변경 뒤 늦은 AI 응답을 폐기하는지 확인한다.
19. 수납 성공/UNKNOWN 영수증 확인 뒤 메뉴를 나갔다 돌아와도 원래 수납·청구 ID로 배분을 시작하고 수납을 다시 기록하지 않는지 확인한다.
20. 발행 당시 ID·버전 본문을 인쇄·PDF 저장하고 다른 화면/보고서가 섞이지 않는지, 취소/인쇄 장애를 저장 성공으로 표시하지 않는지 Windows 최종본에서 확인한다.

별도 모델 시험 승인 요청(새 제안, 미실행):
- 비식별 회원 열 1회 + 금융/잔여·보강 열 1회 + 공지 초안 1회 + 현재 요청 답장 초안 1회. 총 최초 **4회**, 자동/수동 재시도·대체 호출·추가 승급 **0회**. 실패한 호출도 4회에 포함하며 소진 후 중단한다.
- 네 호출 모두 `gpt-4o-mini-2024-07-18`, 요청당 입력 **20,128 tokens 이하의 보수적 상한**, 출력 **1,200 tokens 이하**. 입력은 텍스트 messages 전체 JSON UTF-8 20,000 bytes 이하·최대 4 messages로 제한한다. byte-fallback BPE에서 내용 토큰은 byte 수를 넘지 않으며, 고정 system/user chat framing 여유 128 tokens를 더한 상한이다. 실측 토큰 수와 혼동하지 않는다. 이미지·tools·외부 파일 원문·임의 역할 메시지는 받지 않는다.
- 공식 단가(2026-10-18 확인): 입력 $0.15 / 출력 $0.60 per 1M tokens. 할인 없는 최대 1회 `(20,128×0.15 + 1,200×0.60)/1,000,000 = $0.0037392`, 4회 합산 **$0.0149568 USD 이하**(환율·세금 별도). 공식 근거 https://developers.openai.com/api/docs/models/gpt-4o-mini/
- 복합 문서 전용 `gpt-4.1-2025-04-14`는 별도 실행 스위치 기본 OFF다. 입력 $2 / 출력 $8 per 1M tokens(https://developers.openai.com/api/docs/models/gpt-4.1/). 이번 4회에 포함하거나 자동 승급하지 않는다. 회원 수·파일 크기로 모델을 바꾸지 않으며 모호한 대상은 확인 질문으로 돌린다.
- 글로벌 운영 모델 스위치를 켜는 승인이 아니다. 승인된 비식별 고정 fixture의 제한된 모델 결과만 확인하고, 실제 공지/답장 발송·회원/금융 반영·운영 DB 쓰기는 하지 않는다. 실제 사용자 기능 확인은 최종 통합 목록에 남긴다.
