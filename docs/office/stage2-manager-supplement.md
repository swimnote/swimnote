## 현재 구현 UI

기존 접기 가능한 Sidebar, 상부 Dashboard·회원목록·상세, 하부 AI 매니저 카드 하나를 사용한다.
별도 모드·오른쪽 AI 패널·떠다니는 모달을 만들지 않는다.
카드는 둥근 모서리·절제된 테두리·약한 그림자로 기존 업무와 구분한다.
기본 처리 내역 약 10줄을 목표로 하며, 상단 수직 조절 막대의 pointer drag와 ArrowUp/Down·Home/End로 높이를 조절한다.
접으면 제목·연결 상태·입력창이 남는다. 펼치면 선호 높이를 복원하며, 크게 보기와 원래 크기를 제공한다.
선호 높이는 현재 세션에만 유지하고 실제 창의 업무 최소 높이로 표시 높이를 제한한다.
낮은 창에서는 처리 내역부터 줄이고 업무·입력·조작을 우선한다. 치수는 CSS 구현값이며 Windows 배율 확정값이 아니다.
업무·처리 내역·Drawer 본문은 각각 스크롤하며 카드가 상세를 덮지 않는다.
접기·크기 변경·메뉴 이동은 취소가 아니며 초안·로컬 첨부·업무 필터·선택·스크롤을 유지한다.
로그아웃·사용자/Pool/권한 교체 시 키가 바뀌는 기존 세션 subtree와 함께 상태·File 참조를 폐기한다.

상단 정상 상태는 짧게 표시하고 PACKAGE ID·Origin·인증·저장 상세는 진단에서 펼친다.
인증 실패·진입 차단·SSE 재연결/실패 등 조치가 필요한 표시는 접어 숨기지 않는다.
서버 권한 확인, main 안전 저장 성공 응답, SSE 연결, 관련 업무 재조회 완료는 다른 증거다.
Sidebar의 AI 매니저는 카드 펼침과 입력 포커스만 수행하고 N01 이력을 추가하지 않는다.

## OFFICE 공통 상호작용

OFFICE root 안에서만 공통 hover·pressed·focus-visible·disabled 규칙을 사용한다.
선택은 지속 표시와 굵기를 함께 쓰며 hover 후에도 구분한다.
disabled는 실제 HTML disabled와 실행 차단을 사용한다. 뒤로/앞으로는 실제 이동 가능 상태를 따른다.
현재 Breadcrumb·비클릭 현황 카드에 가짜 hover를 붙이지 않는다.
버튼·링크·summary·조회 행은 pointer, 입력은 text, 조절 막대는 resize cursor다.
위험 버튼과 실패 의미색은 유지하며 Web의 기존 화면과 스타일은 변경하지 않는다.

## 입력·로컬 첨부

기본 구성은 첨부·입력·전송이다. 연결 후 Enter는 전송, Shift+Enter는 줄바꿈 계약이다.
현재는 버튼 disabled, Enter 차단, form preventDefault로 모든 전송을 막는다.
IME 조합 중 Enter/isComposing/229는 전송으로 해석하지 않는다.
입력과 File 객체 참조는 세션 메모리만 사용한다. localStorage·IndexedDB·로그·서버·Electron 파일 경로에 저장하지 않는다.

선택 방법: browser file input, 파일 drop, clipboard 이미지 paste.
파일명·확장자/제공된 MIME·크기·개별 제거를 표시한다. 최대 5개, 파일당 10MiB, 총 25MiB.
허용 선택 확장자: PDF, PNG, JPG/JPEG, WEBP, HWP/HWPX, DOCX, XLSX, CSV, TXT.
실행 파일·매크로 문서·기타 형식은 거부하고, 알려진 MIME 불일치도 거부한다.
빈 MIME/octet-stream은 OS가 형식을 모르는 경우만으로 취급한다. 확장자 검증은 내용 안전 검사나 파싱 검증이 아니다.
같은 파일 재선택을 위해 file input 값을 비우고, 제거·세션 종료 시 참조를 해제한다.
object URL·파일 내용 읽기·업로드·광범위 IPC·파일시스템 권한·문서 실행은 사용하지 않는다.
로컬 선택은 업로드/읽기/분석/저장 완료가 아니며 지원 형식 선택을 내용 해석 지원으로 광고하지 않는다.

## 작업 카드·결과 열람 공통 계약

`OfficeTaskContract`와 `OfficeTaskCard`는 제어형 UI/순수 검증 계약이며 범용 실행 엔진이 아니다.
현재 실제 앱에는 작업을 주입하거나 가짜 결과를 표시하지 않는다. 상태별 표시는 synthetic fixture에서만 검증한다.
공통 구조: 요청·대상·준비/확인 대기/실행 중/완료/일부 완료/실패/결과 불명, 요약, 이전 값→새 값,
대상·메시지·첨부 미리보기, 실행 확인, 결과 이동, 이미지·표·파일 결과 종류와 별도 보관 상태.
실행 전 확인은 실행 후 결과 열람과 다르다. 열람은 업무 승인·업무 적정성 확인도 아니다.

| 상태 | 공통 표현 |
| --- | --- |
| 완료·미열람 | 파란 표시 + 미열람 |
| 완료·열람함 | 기본 글자색 + 열람함 |
| 일부 완료 | 주황 + 구체적 미완료 내용, 결과별 열람 |
| 실패 | 빨강 + 사유 |
| 결과 불명 | 별도 상태, 성공·실패로 단정하지 않고 상태 확인 필요 |

완료만으로 강제 이동하지 않는다. 결과 보기만 기존 N01 `open(target, {directReturn:true})`에 연결한다.
이 옵션은 결과 이동에 목록 이력을 합성하지 않아 직전 화면으로 직접 복귀한다. 일반 메뉴 OPEN의 기존 동작은 유지한다.
버튼 클릭·화면 진입만으로 열람 처리하지 않는다.
동일 사용자/Pool scope·동일 결과·동일 대상 화면 진입과, 완료 시각 이후 시작한 실제 재조회 성공 증거가 필요하다.
cache-only·실패·권한 거부·대상 없음·이전 query 완료·다른 scope·revision 불일치는 미열람 유지다.
변경 후 기대 revision이 있으면 일치해야 한다. 여러 결과는 개별 viewedAt으로 관리한다.
접힌 카드의 미열람 집계는 결과별 상태 합계다. `OfficeTaskSummary`를 fixture로 검증하며 운영 이력/지속 보관은 연결 전이다.
후속 실제 연결 시 서버 응답·권한·Action 식별에 근거한 fresh-query evidence adapter가 필요하다.
클라이언트 계약 자체는 서버 권한·금융 멱등성·승인 증거를 대신하지 않는다.
뒤로는 결과 이동 직전 화면·검색·필터·스크롤, 앞으로는 결과 화면, Breadcrumb은 현재 메뉴 상위를 따른다.
같은 화면 OPEN을 중복 이력으로 쌓지 않고, 뒤로가기를 이미 완료된 데이터 변경 취소로 해석하지 않는다.

## 후속 AI·자료·보관·지원 범위 — 현재 구현 아님

업무 전체의 자연어 목표는 메뉴와 같은 Action·Service/API·권한·검증이다. 모호한 대상은 추측하지 않는다.
단체 Push/SMS는 준비 후 사용자 실행, 명확한 단일 일반 정보는 업무별 정책에 따라 실행 후 보고한다.
결제·환불·삭제·퇴원·대량 변경은 사전 확인, 실행 직전 대상·내용·revision 변경 시 재확인한다.
중복 실행 방지·일부 성공·결과 불명은 별도 처리하고, 생성 중지와 이미 시작한 업무 취소를 구분한다.

후속 자료 목표: HWP/HWPX·Word·Excel/CSV·PDF·사진 읽기/분석, 문서·표·이미지 생성, 실제 파일 변환.
HWP 생성 미지원 시 Word 등 실제 지원 형식으로 제공한다. 해석/변환/서식 손실은 실제 검증 후 지원 표시한다.
얼굴 모자이크는 원본 보존·지정 영역 최소 편집, 감지 누락 검토와 영역 추가/해제를 포함한다.
