# 보고서 형식 헌법

## 원칙 1 — 채팅창 직접 출력

설계/감사/보고서/계획 문서는 **채팅창에 직접 출력**한다.

docs/ 파일로 작성하지 않는다.

**Why:** 문서 파일 작성 + commit이 불필요한 시간과 크레딧을 소모한다.

## 원칙 2 — 단일 코드블럭 (2026-08-21 추가)

모든 완료 보고서는 **하나의 코드블럭 안에 전체를 넣어서 출력**한다.

운영자가 GPT 등 다른 곳에 그대로 붙여넣을 수 있도록.

형식:

```
```
[AI01-XX IMPLEMENTATION REPORT]

## 1. Result
...전체 보고서 내용...
```
```

코드블럭 밖에 보고서 내용 일부를 분리해서 넣지 않는다.

**Why:** 운영자가 보고서를 GPT에 전달할 때 복사-붙여넣기가 한 번에 가능해야 함.

## 파일 작성 허용 조건 (명시 요청 시만)

- 운영자가 "파일로 저장해줘" 또는 "docs에 써줘" 등으로 명시적으로 요청
- 실제 코드 변경 (구현 파일, 설정 파일)
- Migration script 등 실행 가능한 파일

## 적용 범위

- 설계 검증 보고서 → 채팅창, 단일 코드블럭
- 감사 결과 → 채팅창, 단일 코드블럭
- 구현 계획 → 채팅창, 단일 코드블럭
- Alignment 보고서 → 채팅창, 단일 코드블럭
- WP 완료 보고 → 채팅창, 단일 코드블럭
