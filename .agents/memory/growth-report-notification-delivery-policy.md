---
name: 성장리포트 알림 전송 결과 불확실성
description: 명시적 전송 실패 재시도와 결과를 모르는 PUSH의 중복 방지 기준
---

성장리포트 관리자 준비 알림과 학부모 발행 알림은 저장된 notification 또는 전송 claim만으로 실제 PUSH 성공을 판단하지 않는다. 전송 전 실패나 제공자의 명시적 거절은 재시도할 수 있지만, 제공자가 수락했을 수도 있는 timeout·프로세스 종료는 확인 없이 재전송하지 않는다. 수락 여부가 불확실한 전송은 receipt나 명시적 운영 확인으로 정리한다. PUSH 실패는 이미 발행된 리포트를 비공개로 되돌리는 이유가 아니다.

**Why:** 사용자는 같은 월·리포트에 대한 중복 PUSH를 금지했다. 제공자 수락 직후 서버 저장이 실패하는 구간에서는 DB 멱등성만으로 제공자 exactly-once를 보장할 수 없다. 자동 재전송보다 불확실한 결과를 확인 대기 상태로 유지하는 결정을 택했다.

**How to apply:** 전송 복구를 개선할 때 “lease 만료면 모두 다시 보낸다”로 단순화하지 않는다. 제공자가 idempotency key를 지원하거나 receipt로 전송 여부를 확정할 수 있다는 근거가 생기기 전에는 불확실한 전송을 자동 재시도 대상으로 합치지 않는다.
