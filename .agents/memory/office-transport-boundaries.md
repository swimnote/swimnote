사용자가 제공한 2026-10-19 V2 설계서가 이전 무료 배차 V1 경계를 대체한다. GPS 접근 또는 예정 시간 도래는 먼저 발생한 안내 조건으로 허용한다. 내장 내비·길찾기·학부모 차량 위치 추적·셔틀 NFC는 제외한다. 위치·알림 권한이 없어도 수동 안전 확인은 가능해야 한다.

**Why:** 사용자가 V2 원문과 PC·기사/인솔자·학부모 공통 서버 계약의 연속 구현을 명시했다. 이전 “GPS 제외”·“이전 미처리 시 다음 화면 차단” 규칙을 재적용하면 최신 설계에 어긋난다.

**How to apply:** 혼합 CENTER_BOARD→DROP/PICKUP→CENTER_HANDOVER를 같은 구조로 다룬다. 이전/다음은 화면만 이동하고 C를 A/B보다 먼저 확인해도 A/B 미처리는 남는다. GPS/시간/화면 이동은 승하차 증거가 아니다. 승인 배차 버전과 실제 event가 공통 원본이며, 기기 전송 대기·서버 반영·확정·게시·기사 ACK를 구분한다. 오입력은 원기록과 사유를 보존하며 누락된 안전확인을 자동 정상 처리하지 않는다. 기존 신원을 쓰되 직원에게 강사/관리자 권한을 대용 부여하지 않는다.

앱 확인은 실제 안전띠·잔류아동 점검·법정 장치를 대체하지 않는다. 반경/머무름 값은 현장 확인 없이 보편 기본값으로 확정하지 않는다. 오프라인 기기에서 서버 권한 회수 즉시 원격 삭제가 가능하다고 주장하지 않는다. source 연결·mock/타입 검사와 실제 PostgreSQL·정상 인증·Windows/native OS 실증을 구분하고 PC만으로 전체 완료를 보고하지 않는다.

신규 migration·운영 배포·실발송·추가 유료 모델은 정확한 범위/비용을 모아 별도 승인받는다. 이미 소진한 모델 시험 승인은 재사용하지 않는다. 별도 업무 DB·합성 인증 환경·검증 전용 제품을 만들지 않는다. 설치본/native 빌드는 의미 있는 통합 단위로 모으며 새 native 모듈을 기존 binary에 OTA만으로 넣을 수 있다고 가정하지 않는다.

차량 소스와 통합 산출물 정리 전에는 다중 업무창을 병행하지 않는다. 그 뒤 외부 승인·실기기 확인만 남았다면 다중 업무창의 독립 개발은 진행하되 차량 승인 SHA를 먼저 고정·보존한다.

**Why:** 사용자의 2026-10-19 후속 지시는 차량 통합을 선행 조건으로 삼되 외부 대기 때문에 이후 개발 전체가 중단되지 않도록 명시했다.
