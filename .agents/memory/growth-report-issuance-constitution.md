# 무료 월간 AI 성장리포트 발급 정책

## pool·발급월별 100% 분모 고정

`target_report_count`는 전체 회원 수가 아니라 해당 pool·report_month의 발급조건을 모두 충족해 최종 확정된 회원 수다. 발급대상 확정 후 실패·누락 회원을 재계산으로 분모에서 제외해 READY를 만들어서는 안 된다. READY는 확정 대상 전원이 정상 생성 완료, 승인된 근거부족 정상 최종 결과, 또는 확정 이후 실제 퇴원 등 명확한 정책상 발행제외로 귀결되고, 대기·처리·재시도·실패·UNKNOWN·누락·중복·잘못된 pool이 모두 0일 때 pool별로 판정한다. 대상 산정 자체의 오류만 일반 재시도와 분리된 명시적 대상정정으로 처리한다.

**Why:** 2026-10-02 사용자가 분모 불변 원칙을 확정하고, 이후 퇴원은 과거 대상 산정을 취소하지 않되 발행 전 active/nondeleted 검사를 유지하는 정책상 최종 귀결로 분리하도록 승인했다. AI·ENGINE·APP 실패나 retry 소진·유실을 정책상 제외로 바꿔 완료율을 만드는 것은 금지했다.
**How to apply:** pool+report_month의 봉인된 대상 명단과 사후 상태변경의 시점·근거를 구분한다. 최초 조건 미충족 제외와 사후 정책상 발행제외를 혼합하지 않는다. 처리 귀결률, 실제 생성 수, 정책상 발행제외 수를 각각 표시하고, 사후 제외로 기존 실패를 지우지 않는다. 발행 전 퇴원한 대상은 학부모에게 제공하지 않으며, 이미 PUBLISHED된 과거 보고서는 보존한다.

발급월 M의 분석월은 M−1이다. 해당 분석월에 수영장 반 재원 이력이 유효하고, 다음 달 1일까지 계속 재원이어야 한다. 분석월 중도 등록도 인정수업 3회와 유효 학생 개인 일지 1건을 충족하면 대상이다. 예정수업에서 결석을 뺀 횟수에 완료 보강을 더하며, 예정수업이 아닌 단순 출석기록은 추가 수업으로 세지 않는다. 월 데이터는 KST의 반개방 구간으로 고정한다.

매월 1일 전월 cycle을 준비하고 1~4일 분석·재시도·복구한다. 월간 자동화의 마지막 역할은 5일에 관리자에게 완성된 리포트와 월 1회 준비 알림을 제공하는 것이다. 관리자 확인·검토·승인·개별/일괄 발송, PC 관리자 화면, 이후 학부모 발행·표시·PUSH는 기존 구현을 그대로 사용한다. 자동생성을 이유로 이 영역의 UI/API/권한/상태 머신/발행 정책을 재설계하지 않는다. 월간 scheduler/worker가 관리자 대신 발송하거나 직접 학부모에게 공개해서는 안 된다. 기존 발행 유효성 조건과 PUBLISHED 보존은 유지한다.

**Why:** 2026-10-01 사용자가 과도하게 확장된 변경을 선별 복구하도록 지시하고, 이번 개발 범위를 1~5일 자동생성·복구·관리자 준비 알림으로 한정했다. 기존 관리자와 학부모 시스템을 새 구조로 대체하면 정상 승인·발송 경로가 끊길 수 있다. 학생별 독립적인 월별 결제·재등록 증거는 없으므로 active 상태만으로 재등록을 추정해서는 안 된다.

**How to apply:** 무료 월간 AI 성장리포트의 후보 생성·분석·재시도·restart 복구·관리자 준비 알림에만 필요한 최소 변경을 적용한다. 자동화 flag는 준비·분석·복구·관리자 알림까지만 제어하며 학부모 공개 권한을 부여하지 않는다. 기존 수동 승인/발송·학부모 알림의 변경은 별도 명시 요청 없이 수행하지 않는다. 유료 AI 인사이트 전략 리포트나 다른 보고서에 확대 적용하지 않는다.

## 근거부족 정상 귀결과 자동화 범위 확정

ENGINE의 `DATA_ACCUMULATING`은 보존하고 APP의 월간 정상 최종 귀결을 `INSUFFICIENT_EVIDENCE`로 구분한다. 생성 성공·실패·퇴원 제외로 위장하거나 대상에서 제거하지 않는다. 처리 귀결 수는 실제 생성 수 + 근거부족 정상 귀결 수 + 정당한 정책 제외 수이며, READY는 이 합계가 봉인된 분모와 같고 미해결 blocker가 없을 때만 허용한다. 근거부족 결과도 기존 관리자 확인·수동 발송 흐름에서 확인 가능한 정상 월간 안내여야 한다.

**Why:** 2026-10-02 사용자가 이 정상 귀결 정책을 승인하고, “완전자동 발행”의 범위를 pool READY와 관리자 PUSH까지만으로 명시 정정했다. 학부모 자동 PUBLISHED나 관리자 승인 우회는 요청 범위를 벗어난다.

## 기존 월 운영과 코드 배포의 분리

새 월간 자동화의 배포·migration 자체가 과거 cycle의 recovery나 최종 귀결 변경을 승인한 것은 아니다. 과거 대상을 새 자동화에 소급 편입하거나 성공·UNKNOWN·근거부족 상태를 자동 정리하지 않는다.

**Why:** 사용자는 2026-10-02 배포 검증과 기존 월의 운영 처리를 별도 승인 단계로 분리했다. 과거 ENGINE 요청의 실제 실행 여부와 기존 성공 결과를 보호해야 한다.

**How to apply:** 기존 월을 처리하려는 작업에서는 별도 운영 지시와 해당 요청의 복구 가능 근거를 먼저 확인한다. 배포 과정의 migration·시작·재시작에는 데이터 backfill이나 recovery를 결합하지 않는다.

**How to apply:** 안내 문구는 “이번 달은 성장 판단에 필요한 충분한 변화 근거가 아직 축적되지 않았습니다.”를 사용하고 성장 평가를 창작하지 않는다. 해당 결과는 같은 입력으로 재분석하지 않으며 recovery에서 제외한다. UNKNOWN은 집계·보고·READY 차단까지만 수행하고 안전 재분석 계약은 별도 후속 범위로 둔다. 기존 관리자 발송 이후 학부모 공개 경로와 일반·유료 publish 정책은 유지한다.
