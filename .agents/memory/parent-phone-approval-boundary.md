---
name: 학부모 전화 기반 자동승인 경계
description: V2 전화 자동승인과 학생 등록 승인·구형 인증의 작업 경계를 유지하는 이유
---

전화 기반 보호자 연결은 학생 등록 승인과 분리한다. 정상 등록 학생의 관계만 추가하며 학생 상태와 기존 승인 관계를 변경하지 않는다.

**Why:** 기존 형제 helper에는 미등록·승인대기 학생을 active로 바꾸는 부수효과가 있다. 사용자는 보호자 연결 조건 변경이 학생 등록 승인까지 확대되는 것을 명시적으로 금지했다.

**How to apply:** 자동연결 경로를 재사용하거나 확장할 때 관계 생성 외 부수효과를 확인한다. 자동연결 변경 요청만으로 관리자 수동승인·구형 scheduler까지 함께 개편하지 않는다.

계정에 전화 인증 이력이 있다는 사실과 현재 요청자가 해당 계정의 정당한 사용자라는 사실을 구분한다.

**Why:** 기존 공개 소셜 연결의 인증 문제를 전체 개편하지 않는 범위에서, 그 경로가 발급한 세션에 새로운 phone-only 권한을 부여하면 공격 범위가 확대된다.

**How to apply:** 신규 자동연결 권한은 OTP 또는 비밀번호로 인증된 세션과 전화 소유 이력을 모두 확인한다. 증명이 없는 구형·소셜-only 세션은 승인대기를 유지한다.

이미 승인된 관계의 stale 요청 상태 정리와 새로운 관계 승인을 구분한다. 기존 승인은 전화 소유 증명을 새로 만들어 주지 않는다.

**Why:** 사용자가 승인한 운영 정리는 정상 existing approved 관계에 남아 있는 요청 메타데이터만 맞추는 작업이다. 이를 새 자동승인이나 구형 SMS 이력의 계정 소유 증명으로 해석하면 보안 경계가 확대된다.

**How to apply:** 요청과 동일 parent/student의 실제 approved 관계가 명확히 대응할 때만 요청 상태를 정리한다. 전화번호만으로 학생을 선택하거나 이름 유사도로 추정하지 않는다. 대응이 불명확하면 보존한다. 연결되지 않은 과거 OTP 기록을 임의 결합하지 않는다.

정상 자동가입과 관리자 예외 승인은 서로 다른 정책이다. 정상 자동가입은 SMS 인증 전화번호 기반 규칙을 보존한다. 자동연결 실패로 pending에 남은 요청은 관리자가 같은 수영장의 실제 학생을 명시적으로 확인·선택한 경우 전화번호 불일치 자체로 수동 승인을 차단하지 않는다.

**Why:** 2026-10-01 사용자가 정상 자동가입은 그대로 유지하면서, 등록 보호자 전화번호 오류 때문에 연결되지 않는 사용자를 수동 확인으로 구조하도록 범위를 확정했다. 자동승인의 전화번호 일치 조건을 수동 예외 경로에 그대로 적용하면 이 목적을 달성할 수 없다.

**How to apply:** 수동 예외는 pending 요청·관리자·선택 학생·수영장·기존 관계를 저장 직전에 검증한다. 인증 근거 없는 계정 전화번호를 인증된 번호로 표시하지 않는다. 불일치는 명확히 표시하되 전화번호·학생정보를 자동 수정하지 않는다. 학생 선택 기능은 유지하고 검색창/자동 키보드만 제거한다.
