4. 실기기 판정 절차

Case A

1. 오늘 수업 카드의 group id 확인
2. 그 카드에서 일지 작성
3. 저장 직후 saved.class_group_id / saved.lesson_date 확인
4. 스케줄러 복귀
5. done 값 확인

비교:

saved.class_group_id === schedule group id
saved.lesson_date === schedule date

인데 done=false이면
→ 서버/DB 조회 문제 후보 A.

━━━━━━━━━━━━━━━━━━━━
5. 반드시 앱 재진입 테스트

같은 상태에서:

A. 다른 화면 갔다가 today-schedule 다시 진입
B. 그래도 done=false인지 확인
C. 앱 완전 종료 후 재실행해서 다시 확인

판정:

1.
저장 직후 false
→ 재진입 true
= 후보 B 확정
즉시 이벤트 갱신 문제

2.
저장 직후 false
→ 재진입 false
→ 앱 재실행 후에도 false
= 후보 A 확정
DB 또는 today-schedule 서버 매칭 문제

3.
saved.class_group_id !== schedule item.id
= class group 전달 문제 확정

4.
saved.lesson_date !== schedule date
= 날짜 전달 문제 확정

━━━━━━━━━━━━━━━━━━━━
6. 추가 DB 조회

문제가 발생한 diary_id가 확보되면
Production DB READ ONLY 조회:

SELECT
  id,
  class_group_id,
  swimming_pool_id,
  lesson_date,
  is_deleted
FROM class_diaries
WHERE id = '<실제 diary_id>';

그리고 해당 schedule class_group 조회:

SELECT
  id,
  swimming_pool_id,
  is_deleted
FROM class_groups
WHERE id = '<schedule group id>';

비교:

- class_group_id
- swimming_pool_id
- lesson_date
- is_deleted

DB 수정 금지.
