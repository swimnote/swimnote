확인 =

   Render 전환 보고의 문서 변경 등 기존 작업 보존.

2. 개발 저장소 기준
   GitHub origin은 보존한다.
   현재 GitLab remote와 APP 작업 branch의 fetch/push 대상 확인.
   앞으로 일반 push가 실패한 GitHub 인증으로 향하지 않도록
   필요한 branch별 upstream/push 설정안을 보고한다.
   이번에는 설정 변경·push·main 반영하지 않는다.
   main은 웹 자동배포 대상이므로 검증용 push 금지.

3. 계정 조건
   사용자 확인으로 PIN 설정 성공을 반영한다.
   toykids 계정의 TOTP 여부·Pool·X 상태는
   기존 확보 증거가 있으면 재사용하고 없으면 UNKNOWN.
   운영 로그인/API 호출/DB 조회는 이번에 하지 않는다.
   사용자가 설정했다는 사실을 Agent 런타임 검증으로 표현하지 않는다.

4. 인증 정책
   기본 로그인 유지 OFF 및 기존 안전저장 정책 유지.
   로그인 유지 ON일 때는 유효 token과 권한 재검증 후 진입하고
   추가 시작 PIN 흐름은 선개발하지 않는 방안을 권장안으로 보고한다.
   기존 계약을 바꾸거나 사용자 승인 없이 정책을 확정하지 않는다.

5. Windows 검증 준비
   사용자 PC에서 x64 여부를 확인하는 간단한 방법과,
   F02 unsigned unpacked 실행본의 전달·실행·결과 수집 절차를
   짧게 제시한다.
   아직 실행본을 만들거나 Windows 실행 성공을 선언하지 않는다.
   보안 기능 해제는 요구하지 않는다.

   F02 타입검사에서 실제 blocker일 때만 최소 수정하는 범위를 제시.
