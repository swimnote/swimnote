SWIMNOTE 학부모 쪽지 기능 제거 및 일지 댓글·반응 시스템 구축

현재 학부모 화면의 별도 쪽지 기능은 제거하고,
모든 학부모–선생님 소통을 ‘해당 수업 일지’ 안의 댓글로 통합합니다.

이번 작업은 단순히 타이핑창을 보이게 고치는 것이 아니라,
기존 쪽지 기능을 일지 댓글 시스템으로 전환하는 작업입니다.

==================================================
1. 핵심 정책
==================================================

1. 학부모는 선생님에게 별도 쪽지를 보내지 않습니다.

2. 학부모는 자신에게 공개된 해당 수업 일지 아래에 댓글을 작성합니다.

3. 선생님은 자신이 작성한 일지 아래에서
해당 일지에 달린 모든 학부모 댓글을 확인합니다.

4. 학부모끼리는 서로의 댓글을 절대 볼 수 없습니다.

5. 선생님은 해당 일지에 달린 모든 학부모 댓글을 볼 수 있습니다.

6. 선생님 화면에는 댓글 작성자가 누구인지 표시합니다.

7. 댓글에는 답글을 달 수 있어야 합니다.

8. 좋아요와 감사합니다 반응도 해당 일지에 연결합니다.

9. 선생님은 해당 일지에서
좋아요 수, 감사합니다 수, 댓글 수를 확인할 수 있어야 합니다.

10. 좋아요와 감사합니다를 누른 학부모도 선생님에게 표시합니다.

==================================================
2. 기존 쪽지 기능 처리
==================================================

현재 학부모 화면의:

- 쪽지함
- 선생님에게 쪽지 보내기
- 쪽지 입력창
- 쪽지 전송 API
- 쪽지 관련 네비게이션

을 조사하세요.

기존 쪽지 기능은 신규 사용 흐름에서 제거합니다.

학부모가 기존 쪽지 메뉴를 누르면
가능하면 해당 학생의 최근 일지 또는 일지 목록으로 이동시키세요.

기존 쪽지 데이터가 이미 있다면 즉시 삭제하지 말고,
읽기 전용 보관 여부를 확인한 뒤 보고하세요.

신규 쪽지 작성 기능은 제거합니다.

==================================================
3. 학부모 일지 화면
==================================================

학부모가 자신의 자녀 일지를 열면
일지 본문 아래에 다음 영역을 배치합니다.

[좋아요] [감사합니다] [댓글]

반응 영역 아래:

- 내 댓글 목록
- 선생님 답글
- 댓글 입력창
- 전송 버튼

을 표시합니다.

학부모에게 보이는 댓글 범위:

- 본인이 작성한 댓글
- 본인 댓글에 대한 선생님 답글
- 같은 대화 흐름에서 본인이 추가로 작성한 답글

다른 학부모가 작성한 댓글은 절대 표시하지 않습니다.

댓글이 하나도 없으면:

“선생님께 수업에 대해 궁금한 점이나 감사한 마음을 남겨보세요.”

입력창 placeholder:

“댓글을 입력하세요”

키보드가 열릴 때 입력창이 가려지지 않도록 처리하세요.

현재 쪽지 화면에서 발생한 것처럼
키보드는 보이는데 타이핑창이 화면 밖으로 밀리는 문제가 없어야 합니다.

확인 항목:

- KeyboardAvoidingView
- KeyboardAwareScrollView
- safe area
- bottom inset
- 하단 탭바 높이
- 입력창 sticky footer 여부
- iOS keyboard offset
- Android adjustResize
- 긴 댓글 작성 시 입력창 높이 확장
- 전송 후 키보드 닫힘 또는 유지 정책

==================================================
4. 선생님 일지 화면
==================================================

선생님이 자신이 작성한 일지를 열면
일지 본문 아래에 다음 요약을 표시합니다.

좋아요 0
감사합니다 0
댓글 0

반응이나 댓글이 생기면 실시간 또는 화면 재진입 시 반영합니다.

댓글 영역에서는 해당 일지에 댓글을 남긴 모든 학부모를 표시합니다.

예:

김민준 보호자
오늘 아이가 정말 즐거워했습니다.
오후 7:12

↳ 서경민 선생님
오늘 집중을 정말 잘했습니다.
오후 7:20

박서윤 보호자
평영 발차기는 집에서 어떻게 연습하면 좋을까요?
오후 7:30

작성자 표시 기준:

- 학생 이름
- 보호자 호칭 또는 보호자 이름
- 보호자와 학생의 관계가 저장돼 있다면 관계 표시

예:

김민준 어머니
김민준 보호자
박서윤 아버지

보호자 개인정보를 과도하게 노출하지 마세요.

선생님은 댓글별로 답글을 작성할 수 있어야 합니다.

==================================================
5. 댓글 권한 구조
==================================================

댓글 접근 권한을 서버에서 강제하세요.

학부모:

- 자신의 자녀에게 공개된 일지에만 댓글 작성 가능
- 자신이 작성한 댓글만 조회 가능
- 자신의 댓글에 달린 선생님 답글만 조회 가능
- 다른 학부모 댓글 조회 불가
- 다른 학부모 댓글 ID를 직접 요청해도 접근 불가

선생님:

- 자신이 소속된 센터와 담당 범위의 일지 댓글 조회 가능
- 자신이 작성한 일지 또는 권한 있는 반의 일지에 답글 가능
- 다른 센터 댓글 접근 불가

운영자:

- 센터 정책에 따라 조회 가능 여부 확인
- 가능하면 감사 로그를 남기세요

모든 권한은 프론트 필터가 아니라 서버 쿼리와 권한 검사에서 보장해야 합니다.

==================================================
6. 댓글 데이터 구조
==================================================

기존 댓글 테이블이 없다면 다음 구조를 검토하세요.

diary_comments

- id
- center_id
- diary_id
- student_id
- parent_user_id
- teacher_user_id
- author_user_id
- author_role
- parent_comment_id
- body
- is_deleted
- created_at
- updated_at
- deleted_at

권장 구조:

학부모 원댓글:
- parent_comment_id = NULL
- author_role = parent
- student_id = 해당 자녀
- parent_user_id = 작성 보호자

선생님 답글:
- parent_comment_id = 원댓글 ID
- author_role = teacher
- teacher_user_id = 작성 선생님

학부모 추가 답글:
- parent_comment_id = 최초 원댓글 ID
- author_role = parent
- 동일 parent_user_id 및 student_id 대화에만 허용

대댓글 깊이는 무한 중첩으로 만들지 말고
하나의 대화 스레드 형태로 처리하세요.

즉:

원댓글
 ├ 선생님 답글
 ├ 학부모 추가댓글
 └ 선생님 추가답글

UI는 1단계 들여쓰기만 사용합니다.

==================================================
7. 댓글 API
==================================================

필요한 API를 정리하고 구현하세요.

예시:

GET /api/diaries/:diaryId/comments

학부모 응답:
- 본인 스레드만 반환

선생님 응답:
- 해당 일지 전체 학부모 스레드 반환

POST /api/diaries/:diaryId/comments

body:
{
  studentId,
  body
}

POST /api/diary-comments/:commentId/replies

body:
{
  body
}

PATCH /api/diary-comments/:commentId

DELETE /api/diary-comments/:commentId

댓글 수정·삭제 정책:

- 작성자만 수정 가능
- 작성자 또는 정책상 운영자만 삭제 가능
- 실제 row 삭제보다 soft delete 권장
- 삭제된 댓글은 “삭제된 댓글입니다” 표시 여부를 결정

각 API에서 반드시 검증:

- diary 존재
- diary is_deleted=false
- center 일치
- 학부모–학생 연결
- 해당 학부모에게 일지 공개 여부
- 선생님 권한
- 댓글 작성자 권한

==================================================
8. 좋아요·감사합니다 반응
==================================================

일지별 반응은 두 종류입니다.

- like
- thanks

학부모는 같은 일지에 각 반응을 한 번만 누를 수 있습니다.

다시 누르면 취소되는 토글 방식으로 구현하세요.

예:

POST /api/diaries/:diaryId/reactions

body:
{
  studentId,
  reactionType: "like"
}

DELETE 또는 동일 POST 토글 방식 사용 가능

권장 테이블:

diary_reactions

- id
- center_id
- diary_id
- student_id
- parent_user_id
- reaction_type
- created_at

unique constraint:

UNIQUE(diary_id, parent_user_id, student_id, reaction_type)

반응 종류:

like
thanks

==================================================
9. 학부모 반응 표시
==================================================

학부모 화면에서는:

좋아요
감사합니다

두 버튼의 선택 상태를 표시합니다.

예:

♡ 좋아요
❤️ 좋아요

🙏 감사합니다
🙏 감사합니다 완료

같은 반응을 다시 누르면 취소합니다.

반응 처리 중 연속 클릭으로 중복 요청이 발생하지 않도록
버튼을 잠시 비활성화하거나 idempotent 처리하세요.

다른 학부모가 누른 사람 목록은 학부모에게 보여주지 않습니다.

전체 숫자를 학부모에게 표시할지는 서비스 정책상 선택할 수 있지만,
기본 권장안은 자신의 반응 상태만 보여주는 것입니다.

학부모끼리 반응 인원으로 서로 존재를 추측하지 않도록
개인정보 보호를 우선하세요.

==================================================
10. 선생님 반응 표시
==================================================

선생님 일지 아래에는 다음을 표시합니다.

좋아요 5
감사합니다 3
댓글 4

누르면 상세 목록을 볼 수 있게 합니다.

좋아요 상세:

김민준 보호자
박서윤 보호자
이도윤 보호자

감사합니다 상세:

김민준 보호자
최하은 보호자

댓글 상세:

댓글 스레드 전체

반응 작성자 목록은 선생님만 확인 가능하게 하세요.

학생 이름과 보호자 호칭을 표시하고,
필요 이상으로 전화번호나 이메일을 표시하지 마세요.

==================================================
11. 일지 목록 요약 표시
==================================================

선생님의 지난 일지 목록 또는 일지 카드 아래에도
반응과 댓글 요약을 표시합니다.

예:

❤️ 5  ·  🙏 3  ·  💬 4

새 댓글이 있으면:

새 댓글 2

배지 표시를 검토하세요.

각 일지 카드마다 별도 API를 호출해 N+1 문제가 발생하지 않도록
일지 목록 API에 집계값을 포함하세요.

예:

reactionCounts: {
  like: 5,
  thanks: 3
},
commentCount: 4,
unreadCommentCount: 2

==================================================
12. 읽음 상태와 알림
==================================================

학부모가 댓글을 작성하면 선생님에게 알림:

“김민준 보호자가 7월 23일 일지에 댓글을 남겼습니다.”

선생님이 답글을 작성하면 해당 학부모에게 알림:

“서경민 선생님이 일지 댓글에 답변했습니다.”

좋아요 또는 감사합니다 알림은 개별 푸시를 너무 많이 보내지 않도록
기본적으로 앱 내부 활동 내역에 누적 표시하는 방식을 검토하세요.

예:

7월 23일 일지
좋아요 5 · 감사합니다 3 · 댓글 2

댓글은 답변이 필요한 항목이므로 푸시 알림 우선순위를 높입니다.

읽음 상태가 필요하면 다음 구조 검토:

- teacher_read_at
- parent_read_at

또는 별도 notification/read receipt 테이블 사용

==================================================
13. 기존 일지 삭제와 댓글 처리
==================================================

일지가 삭제되면:

- 학부모는 댓글 작성 불가
- 기존 댓글 조회 불가 또는 읽기 전용 처리
- 반응 추가/취소 불가
- 선생님 일지 목록에서도 일반적으로 미표시

일지 삭제 시 댓글과 반응을 물리 삭제하지 말고
일지 상태에 따라 노출을 차단하세요.

복구 가능성을 고려해 원본 데이터는 유지합니다.

14. UI 세부 기준
==================================================

학부모 화면:

일지 본문
사진/영상
반응 버튼
내 댓글 스레드
댓글 입력창

선생님 화면:

일지 본문
사진/영상
반응 및 댓글 요약

키보드가 열린 상태에서도:

- 입력창 보임
- 전송 버튼 보임
- 입력 내용 보임
- 홈 인디케이터에 가리지 않음
- 하단 탭에 가리지 않음

긴 댓글:

- 최대 글자 수 설정
- 권장 1,000자
- 글자 수 초과 안내
- 빈 댓글 전송 금지
- 공백만 있는 댓글 금지
- 전송 중 중복 전송 방지

15. 캐시 동기화
==================================================

댓글 또는 반응 변경 후 다음 화면을 갱신하세요.

- 학부모 일지 상세
- 학부모 일지 목록
- 선생님 일지 상세
- 선생님 지난 일지
- 선생님 홈 알림
- 읽지 않은 댓글 수
- 반응 수
- 댓글 수

query invalidation과 request race를 점검하세요.

==================================================
16. 보안 테스트
==================================================

반드시 다음 권한 테스트를 수행하세요.

테스트 1

학부모 A가 댓글 작성
→ 학부모 A에게 보임
→ 선생님에게 보임
→ 학부모 B에게 안 보임

테스트 2

학부모 B가 같은 일지에 댓글 작성
→ 학부모 B는 자기 댓글만 보임
→ 학부모 A는 B 댓글을 못 봄
→ 선생님은 A와 B 댓글 모두 확인

테스트 3

학부모 B가 A의 commentId를 직접 API에 넣어 조회
→ 403 또는 404

테스트 4

선생님이 A 댓글에 답글
→ A에게만 표시
→ B에게 안 보임

테스트 5

학부모 A가 추가 답글
→ 같은 스레드에 표시
→ 선생님에게 표시

테스트 6

다른 센터 선생님이 댓글 조회
→ 접근 거부

17. 반응 테스트
==================================================

테스트 1

학부모 A 좋아요 클릭
→ 선생님 일지 좋아요 1
→ A 선택 상태 활성화

테스트 2
