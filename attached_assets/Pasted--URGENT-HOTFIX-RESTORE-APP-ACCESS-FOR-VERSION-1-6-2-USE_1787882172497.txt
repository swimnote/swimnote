[URGENT HOTFIX — RESTORE APP ACCESS FOR VERSION 1.6.2 USERS]

목표:

현재 기존 SWIMNOTE Android/iOS 사용자 중
앱 버전 1.6.2 사용자가

"서버 점검중입니다"

가림막 때문에 앱에 진입하지 못하고 있다.

스토어 수동 업데이트를 강제하기 전에
기존 1.6.2 바이너리에 OTA HOTFIX를 배포해서
가림막을 제거하고 기존 앱을 다시 정상 사용 가능하게 한다.

이번 작업은
VERSION 1.6.2 RECOVERY HOTFIX ONLY.

==================================================
1. FIRST — 1.6.2 OTA COMPATIBILITY 확인
==================================================

코드 수정 전에 반드시 실제 repository / EAS 기준으로 확인:

- app version 1.6.2 당시 runtimeVersion
- expo-updates 활성 여부
- production channel
- production branch
- 1.6.2 바이너리가 바라보는 update URL
- current OTA runtimeVersion 1.6.3과 호환 여부
- 1.6.2에서 마지막으로 수신 가능한 OTA group/update

추측 금지.

특히:

현재 최신 production OTA가 runtimeVersion 1.6.3이면
1.6.2 binary가 해당 OTA를 받을 수 있는지 실제 설정 기준으로 확인.

runtime이 다르면
반드시 1.6.2 runtime 전용 OTA를 생성한다.

==================================================
2. 1.6.2 기준점 찾기
==================================================

실제 version 1.6.2 production binary가 만들어졌던

- commit SHA
- app config
- runtimeVersion
- production branch/channel

을 확인한다.

가능하면 해당 stable commit에서
HOTFIX branch를 만든다.

예:

hotfix/v1.6.2-maintenance-gate

현재 1.6.4/새 버전 코드를
1.6.2에 통째로 backport 하지 않는다.

==================================================
3. ROOT CAUSE — MAINTENANCE GATE
==================================================

현재 화면:

"서버 점검중입니다"

를 표시하는 실제 코드를 찾는다.

반드시 확인:

- maintenance flag
- version gate
- minimum version check
- remote config
- server response
- forced update check
- hardcoded app version condition
- startup route
- API health fallback

왜 1.6.2에서 이 화면만 표시되는지
ROOT CAUSE를 확정한다.

==================================================
4. HOTFIX SCOPE
==================================================

1.6.2에서 필요한 수정은 최소화한다.

목표:

기존 정상 SWIMNOTE 기능에
다시 진입할 수 있도록 한다.

가능하면 수정:

"서버 점검중입니다" 강제 가림막 제거/해제

절대 하지 말 것:

- 가격 변경
- subscription 변경
- RevenueCat 변경
- X 가격 변경
- X 신규 기능 backport
- 관리자 Hub 신규 코드 backport
- UI redesign
- 새로운 logo/native splash backport
- DB migration
- native dependency 변경
- Expo SDK 변경

1.6.2를 살리기 위한
JS/TS HOTFIX만 적용한다.

==================================================
5. SERVER-ENFORCED GATE 여부 확인
==================================================

매우 중요:

가림막이 앱 JS 코드가 아니라
production server에서 minimumVersion 등의 값으로 강제되는 경우

OTA 코드만 수정해서 해결 가능한지 확인한다.

서버 정책 변경이 필요하면:

- 1.6.2 접근을 다시 허용
- 최신 버전 접근 영향 없음
- 다른 버전 영향 없음

최소 범위로 처리한다.

==================================================
6. OTA TARGET
==================================================

HOTFIX는 반드시

또 publish해서 끝냈다고 판단하면 안 된다.

보고서에 반드시:

1.6.2 RUNTIME VERSION =
OTA TARGET RUNTIME =
CHANNEL =
BRANCH =

기록.
