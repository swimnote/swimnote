[SWIMNOTE 최우선 긴급 복구 — 구독 취소 오판 화면 즉시 롤백]

현재 운영 앱에서 실제 구독 중인 계정이

“구독이 취소되었습니다”
“오늘 자정 이후 데이터가 영구 삭제됩니다”

화면으로 진입하는 치명적 회귀가 발생했다.

보강 오류 조사와 신규 수정은 전부 즉시 중단한다.

최우선 목표:

현재 production OTA를
마지막으로 구독 판정이 정상 작동했던 검증 버전으로 즉시 되돌린다.

━━━━━━━━━━━━━━━━━━━━━━
STEP 1. 현재 실제 적용 OTA 확인
━━━━━━━━━━━━━━━━━━━━━━

먼저 아래 내용을 5분 이내에 확인한다.

1. production channel 최신 Update Group ID
2. production branch 최신 update ID
3. runtimeVersion
4. 해당 OTA에 포함된 commit SHA
5. 앱에서 실제 적용된 update ID
6. 현재 앱이 참조하는 API_BASE
7. 현재 Render live commit SHA

“배포했다”는 설명 금지.
실제 SHA와 Update Group ID를 제출한다.

━━━━━━━━━━━━━━━━━━━━━━
STEP 2. 즉시 OTA 롤백
━━━━━━━━━━━━━━━━━━━━━━

마지막 구독 정상 검증 기준:

commit:
651b1a95

production OTA:
e1938d77-d7d1-43c2-9593-84c8422c3134

preview OTA:
1a9e32fb-db9f-4d67-9d8d-960838c0866a

위 버전이 실제로 구독 정상 버전이 맞는지 git diff와 배포 이력으로 확인한다.

맞다면:

- commit 651b1a95 기준 앱 번들을 다시 생성
- 동일 production channel에 새 OTA 발행
- 동일 preview channel에도 새 OTA 발행
- 기존 update 삭제 방식 금지
- 새 native build 금지
- runtimeVersion 변경 금지
- 서버 롤백 금지
- DB 수정 금지

OTA 메시지:

hotfix: restore subscription access after regression

중요:

현재 HEAD에서 구독 코드만 대충 되돌리지 않는다.
반드시 검증된 651b1a95 전체 앱 번들을 다시 발행한다.

━━━━━━━━━━━━━━━━━━━━━━
STEP 3. 서버 상태는 건드리지 말 것
━━━━━━━━━━━━━━━━━━━━━━

현재 화면이 OTA 회귀인지 서버 구독 응답 문제인지 아직 미확정이다.

따라서:

- Render rollback 금지
- subscription DB 수정 금지
- swimming_pools 구독 컬럼 수정 금지
- RevenueCat entitlement 수정 금지
- 수영장 만료일 임의 연장 금지
- 사용자 데이터 삭제 로직 실행 금지

먼저 OTA 원복 후 앱을 재실행해 구독 화면이 정상 복구되는지 확인한다.

━━━━━━━━━━━━━━━━━━━━━━
STEP 4. 원복 후 실기기 검증
━━━━━━━━━━━━━━━━━━━━━━

앱 완전 종료
→ 다시 실행
→ OTA 적용 후 재시작

확인:

1. 관리자 로그인 정상
2. 홈 진입 정상
3. 구독 취소 화면 미노출
4. 수업관리 진입 정상
5. 수강관리 진입 정상
6. 스케줄러 진입 정상
7. 기존 데이터 정상 표시
8. 서비스 중단 경고 미노출
9. 실제 구독 플랜·만료일 정상 표시
10. 데이터 삭제 카운트다운 미노출

실패하면 즉시 다음을 제출한다.

- 앱 적용 update ID
- subscription API HTTP status
- response body
- pool_id
- 서버 live SHA
- 클라이언트에서 취소 화면으로 보내는 조건문 원문

━━━━━━━━━━━━━━━━━━━━━━
STEP 5. 구독 오판 원인 포렌식
━━━━━━━━━━━━━━━━━━━━━━

━━━━━━━━━━━━━━━━━━━━━━
STEP 6. 데이터 삭제 안전장치 확인
━━━━━━━━━━━━━━━━━━━━━━

화면 문구에 “오늘 자정 이후 데이터 영구 삭제”가 표시된다.

실제 자동 삭제 Worker가 존재하는지 즉시 확인한다.

검색:

- DELETE FROM students
- DELETE FROM swimming_pools
- subscription cleanup
- cancelled subscription cleanup
- permanent delete
- midnight cleanup
- cron
- worker
- data deletion
- scheduled deletion

중요:

실제 삭제 Worker가 존재한다면 즉시 실행 중지 계획을 보고한다.
사용자 승인 없이 DB 삭제 로직을 실행하거나 수정하지 않는다.

현재 계정의 삭제 예약이 실제 DB에 생성됐는지도 조회만 한다.

UPDATE / DELETE 금지.
