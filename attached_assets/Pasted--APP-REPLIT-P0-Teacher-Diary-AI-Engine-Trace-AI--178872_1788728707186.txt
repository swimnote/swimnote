[긴급 P0 — Teacher Diary AI Engine 실제 호출/응답 Trace 검증]

현재 실기기 증상:
교사가 AI 일지 작성에서 말한 내용이 거의 그대로 입력되고,
AI Engine의 수영 전문 검색/grounded 생성이 실제로 작동하지 않는 것으로 의심된다.

지금은 기능 수정부터 하지 말고,
실제 Production 호출 경로를 1회 end-to-end trace하여 원인을 확정한다.

- mock/stub 응답 사용

3. 실제 요청 1건 Trace
━━━━━━━━━━━━━━━━━━━━━━

교사 일지 AI 요청 1건을 실제로 실행하고
request_id 하나를 기준으로 다음을 확인:

APP:
- request_id
- 호출 endpoint host/path
- HTTP status
- latency
- student_count
- text_length

AI Engine 응답/로그:
- 동일 request_id 존재 여부
- pipeline_mode
- generation_mode
- matched student refs
- template_ids
- knowledge_ids
- grounding_validation
- fallback 여부
- HTTP status

개인정보 보호:
학생 이름, 교사 입력 원문, 생성 일지 원문, JWT는 보고하지 말 것.

━━━━━━━━━━━━━━━━━━━━━━
4. 판정 기준
━━━━━━━━━━━━━━━━━━━━━━

A. AI Engine 로그에 동일 request_id 자체가 없음
→ APP 호출 경로/환경변수/endpoint 문제

B. AI Engine 도달했으나 pipeline_mode != grounded_v1
→ 잘못된 pipeline/adapter 문제

C. pipeline_mode=grounded_v1이나
template_ids=[], knowledge_ids=[]
그리고 generation_mode=POLISH_ONLY
→ 검색/지식 매칭 문제

D. AI Engine에서 GROUNDED + template/knowledge 정상인데
앱 화면에는 원문 수준 결과만 표시
→ Response normalize/UI mapping 문제

E. Engine 오류 후 앱이 원문을 그대로 넣음
→ silent fallback 버그이며 P0
