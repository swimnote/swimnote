==================================================
2. SEMANTIC SAFETY RULE
==================================================

ticket_id 컬럼에
ticket이 아닌 case_id를 저장하는 구조가

기존 query / future join / analytics / migration에서
semantic ambiguity를 만들면 수정한다.

권장 우선순위:

A. 기존 replies table에 nullable case_id 추가
   - human ticket message: ticket_id=<ticket>, case_id=<linked case if exists>
   - AI-only message: ticket_id=null, case_id=<case>

또는

B. 기존 schema에 이미 thread_id/thread_type과 같은
명확한 구조가 있으면 그것을 재사용.

금지:

case_id를 ticket_id로 위장하여 장기 저장.

새 message table 생성은 기본적으로 금지.

최소 schema extension 우선.

==================================================
3. THREAD QUERY CONTRACT
==================================================

message thread 조회는 명확히 분리:

AI-only case
→ case_id 기준

Human escalated case
→ case_id 기준으로 전체 conversation을 보되
   linked ticket/replies도 포함

Legacy human-only ticket
→ ticket_id 기준 기존 동작 유지

한 conversation이 human escalation 되었다고
AI 이전 메시지가 사라지면 FAIL.

==================================================
6. SUPER ADMIN DOES NOT MEAN INVALID STATE
==================================================

super_admin도
기본적으로 invalid state jump를 하면 안 된다.

예:

NEW → RESOLVED
AI_PROCESSING → PHONE_REQUIRED
RESOLVED → HUMAN_RESPONDED

등 contract 밖 jump를
아무 이유 없이 허용 금지.

운영상 정말 override가 필요하다면:

명시적 force=true
+
reason 필수
+
audit event 필수

형태의 별도 override contract가 필요.

하지만 이번 WP에서는
가능하면 override 자체를 만들지 않는다.

정상 transition service 사용 우선.
