1. 일반 ScrollView 대신 KeyboardAwareScrollView를 사용하십시오.
━━━━━━━━━━━━━━━━━━━━━━

현재 설계에서는

KeyboardAvoidingView
+
일반 ScrollView

조합으로 되어 있습니다.

이 구조는 키보드가 모달을 밀어 올리는 것은 가능하지만,
긴 RESULT 화면이나 학생별 TextInput에서

사용자가 탭한 입력란이
항상 키보드 위로 자동 스크롤된다고 보장하기 어렵습니다.

react-native-keyboard-controller의

KeyboardAwareScrollView

를 단일 세로 스크롤 소유자로 사용하십시오.

최종 구조:

Modal
└─ Overlay
   ├─ Backdrop
   └─ KeyboardAvoidingView
      └─ Sheet
         ├─ Handle
         ├─ Header
         ├─ KeyboardAwareScrollView
         │  └─ 모든 상태 콘텐츠
         └─ ActionBar

KeyboardAwareScrollView 필수 설정을 검토하십시오.

- keyboardShouldPersistTaps="handled"
- keyboardDismissMode="interactive" (iOS)
- bottomOffset
- extraKeyboardSpace
- mode="insets" 우선 검토
- showsVerticalScrollIndicator 필요 여부
- contentContainerStyle의 하단 여백

일반 ScrollView와 KeyboardAwareScrollView를 중첩하지 마십시오.

━━━━━━━━━━━━━━━━━━━━━━
2. KeyboardAvoidingView와 KeyboardAwareScrollView 역할을 분리하십시오.
━━━━━━━━━━━━━━━━━━━━━━

KeyboardAvoidingView는

Sheet 전체가 키보드에 가려지지 않도록
사용 가능한 영역을 조정하는 역할만 담당합니다.

KeyboardAwareScrollView는

포커스된 TextInput을 추적하고
필요할 때 해당 위치까지 자동 스크롤하는 역할을 담당합니다.

두 컴포넌트에 동일한 키보드 보정값을 중복 적용하지 마십시오.

특히 아래를 동시에 과도하게 적용하지 마십시오.

- KeyboardAvoidingView padding
- KeyboardAwareScrollView extraKeyboardSpace
- contentContainer paddingBottom
- Safe Area bottom

각 값의 역할을 분리하고
실기기에서 빈 공간이 중복되지 않도록 하십시오.

━━━━━━━━━━━━━━━━━━━━━━
3. KeyboardAvoidingView에는 automaticOffset을 검토하십시오.
━━━━━━━━━━━━━━━━━━━━━━

현재 구조는 일반 화면이 아니라
transparent Modal 내부의 Bottom Sheet입니다.

react-native-keyboard-controller 문서상
Modal 내부에서는 위치 보정을 위해
keyboardVerticalOffset 또는 automaticOffset이 필요할 수 있습니다.

따라서

automaticOffset={true}

사용을 우선 검토하십시오.

임의의 keyboardVerticalOffset 숫자를 하드코딩하지 마십시오.

automaticOffset 사용 시에도

- 상단 Safe Area
- Modal 위치
- Sheet 최대 높이

가 올바르게 계산되는지 실기기에서 확인하십시오.

━━━━━━━━━━━━━━━━━━━━━━
4. sheet의 flex: 0만으로 높이를 결정하지 마십시오.
━━━━━━━━━━━━━━━━━━━━━━

현재 제안된

sheet: flex: 0
maxHeight: screenHeight - insets.top - 16

구조는 콘텐츠 높이에 따라서는
Scroll 영역이 충분히 제한되지 않을 가능성이 있습니다.

다음 조건을 보장하십시오.

- sheet가 maxHeight를 넘지 않음
- KeyboardAwareScrollView가 실제 가변 영역을 차지함
- 긴 RESULT에서 Sheet가 화면 밖으로 성장하지 않음
- 짧은 INPUT에서는 불필요한 빈 공간이 과도하지 않음
- Scroll 영역에 flexShrink: 1 또는 flex: 1, minHeight: 0이 정확히 적용됨

구체적인 flex 값은 구현 후
작은 화면과 긴 결과 화면에서 검증하십시오.

━━━━━━━━━━━━━━━━━━━━━━
5. RESULT TextInput의 scrollEnabled={false}는 동적 높이를 보장해야 합니다.
━━━━━━━━━━━━━━━━━━━━━━

StudentNoteCard와 공통 일지 TextInput이

scrollEnabled={false}

인 경우 각 TextInput의 높이가
내용에 따라 자동 증가해야 합니다.

다음 사항을 확인하십시오.

- onContentSizeChange로 높이 갱신 여부
- 최소 높이
- 최대 높이 필요 여부
- 매우 긴 텍스트에서 화면 전체를 한 입력란이 독점하지 않는지
- 외부 KeyboardAwareScrollView가 끝까지 스크롤 가능한지

단순히 scrollEnabled={false}만 설정하고
고정 height를 유지하면 긴 결과가 잘릴 수 있습니다.

━━━━━━━━━━━━━━━━━━━━━━
6. ActionBar는 일반 flex 하단 고정을 우선 사용하십시오.
━━━━━━━━━━━━━━━━━━━━━━

현재 설계대로

Header
Scrollable Content
ActionBar
