[SWIMNOTE — GLOBAL TRANSIENT MENU UX CONSTITUTION 교체 + 현재 ⋯ 메뉴 수정]

현재 SiteHeader의 ⋯ 확장 메뉴 UX가 잘못되어 있습니다.

현재 문제:
- ⋯ 메뉴에서 페이지를 클릭하여 route가 변경되어도 메뉴가 계속 열려 있음
- 새 페이지 본문을 클릭하거나 마우스를 본문으로 이동해도 메뉴가 닫히지 않음
- 다시 ⋯ 버튼을 눌러야만 닫힘

이 동작은 폐기합니다.

이번 수정으로 기존 "메뉴/드롭다운/오버레이 닫힘 규칙" 헌법을
아래 규칙으로 완전히 교체하십시오.

이 규칙은 현재 공식 홈페이지뿐 아니라
향후 PC Dashboard 재구성 때도 동일하게 적용하는
SWIMNOTE 전역 UX 헌법입니다.

TRANSIENT UI DISMISSAL CONSTITUTION

SWIMNOTE에서 다음과 같은 임시 UI:

- ⋯ 확장 메뉴
- dropdown
- popover

은 사용자가 "닫기"를 따로 학습할 필요가 없어야 합니다.

절대 원칙:

"사용자의 다음 행동이 시작되면,
이전의 임시 UI는 자동으로 사라진다."

1. NAVIGATION 발생 시 즉시 닫힘
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

가장 중요합니다.

열려 있는 ⋯ 메뉴에서:

- SWIMNOTE AI
- 기술 및 개발
- 특허/IP

- 앱 설치
- 이용약관
- 개인정보처리방침

등 어떠한 navigation item을 클릭하든:

1. 메뉴 state를 즉시 close
2. route navigation 실행
3. 새 페이지는 메뉴가 닫힌 상태로 표시

되어야 합니다.

route가 실제로 변경된 뒤에도
open state가 남아 있어서는 안 됩니다.

가능하면 route/location 변화 자체도 감시하여:

location pathname/search/hash 변경
→ open=false

가 되도록 안전장치를 추가하십시오.

페이지가 바뀌더라도 transient menu가 남지 않아야 합니다.

2. DESKTOP — 포인터가 메뉴 영역을 떠나면 자동 닫힘
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Desktop에서는 ⋯ 메뉴가 열린 상태에서
마우스가 다음 영역 밖으로 이동하면 자동으로 닫습니다.

"유효 메뉴 영역":

SiteHeader
+
열린 Expanded Menu Panel

이 둘을 하나의 interaction region으로 취급합니다.

→ Expanded Menu

하지만 포인터가:

Header/Menu
→ 실제 페이지 본문

으로 이동하면 자동으로 닫아야 합니다.

사용자가 본문을 클릭할 필요도 없습니다.

즉 대표가 요구하는 최종 동작:

→ Mega Menu OPEN
→ 메뉴를 살펴봄

→ Mega Menu 자동 CLOSE

입니다.

3. HOVER CLOSE 구현 안정성
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

단순히 각각의 요소에
onMouseLeave를 무작정 붙이지 마십시오.

Header와 Panel 사이를 이동하는 순간
잘못 닫히는 flicker가 생기면 안 됩니다.

권장 구현:

A.
Header + ExpandedPanel을
하나의 공통 interaction boundary로 구성할 수 있다면
outer wrapper의 pointer enter/leave 사용.

또는

B.
headerRef / panelRef와
event.relatedTarget을 사용하여
다음 pointer target이 두 영역 안에 있는지 판단.

또는

C.
document pointer movement를 사용하되
header/panel containment를 정확히 판별.

조건:
- Header → Menu 이동: 유지
- Menu → Header 이동: 유지
- Menu/Header → Body 이동: close
- Menu item 클릭: 즉시 close

새 package 설치 금지.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
4. 짧은 DISMISS DELAY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Desktop pointer-leave 자동 닫힘은
실수로 경계를 1~2px 벗어났을 때 깜빡이지 않도록
아주 짧은 delay를 둘 수 있습니다.

권장:
80~150ms

절대:
300ms 이상의 느린 delay 금지.

pointer가 delay 안에
Header/Menu 영역으로 다시 들어오면
close timer를 취소합니다.

이 delay는 "애니메이션 효과"가 아니라
flicker 방지용입니다.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
