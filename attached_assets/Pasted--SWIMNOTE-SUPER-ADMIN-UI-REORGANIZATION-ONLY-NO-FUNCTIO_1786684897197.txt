==================================================
1. SUPER ADMIN 전체 방향
==================================================

Super Admin은 앞으로 다음을 자주 관리한다.

- 운영처
- X모드
- 결제/구독
- 커리큘럼
- 홈페이지
- 성장리포트
- 향후 AI 사용량/비용
- 기타 운영정보

따라서 현재 화면을
단순 기능 버튼 모음처럼 두지 말고

“관리 콘솔”

형태로 정리한다.

==================================================
2. TERMINOLOGY
==================================================

UI에서 무조건 “수영장”이라고 표현하지 않는다.

가입 주체는:

- 수영장
- 수영클럽
- 개인레슨 선생님
- 개인 코치
- 기타 운영자

가 될 수 있다.

Super Admin UI 공통 용어:

“운영처”

사용.

기존 DB swimming_pools 이름은 변경 금지.

==================================================
3. SUPER ADMIN HOME 구조
==================================================

Super Admin 첫 화면을
관리용 Dashboard 형태로 정리.

상단:

SUPER ADMIN
운영 관리

그 아래 주요 관리영역을
큰 기능 버튼 여러 개 난립시키지 말고
명확한 메뉴 구조로 정리.

예:

운영처 관리
X모드 관리
가입/승인 관리
기타 기존 관리자 기능

현재 존재하는 기능은 삭제하지 않는다.

위치만 재정리.

==================================================
6. OPERATOR LIST UI
==================================================

운영처 목록 화면은
500개 이상 사용을 전제로 UI 구성.

필수 UI:

- 상단 검색창
- 상태 필터 영역
- 목록
- pagination 또는 기존 infinite list 표시

중요:

검색 기능 자체가 이미 있으면 그대로 사용.
없으면 이번 UI 작업에서 server 검색 기능 새로 만들지 않는다.

기능이 없는 search UI를 fake로 만들지 않는다.

기존 지원 기능 범위만 표시.

==================================================
7. LIST ROW DESIGN
==================================================

각 운영처 row는
옆에 버튼 여러 개를 붙이지 않는다.

전체 row press 방식.

표시 가능한 기존 데이터만 사용:

운영처명
관리자명
승인 상태
X 상태
기타 현재 API가 주는 상태

정보 계층:

1. 운영처명
2. 관리자/보조정보
3. 상태 badge

정도로 깔끔하게.

==================================================
8. DETAIL DASHBOARD UI
==================================================

운영처를 누르면
상세를 “정보 대시보드”처럼 보이게 정리.

기존 기능은 그대로.

Section 형태로 정리:

[기본정보]

[X모드]

[결제 / 구독]

[커리큘럼]

[홈페이지]

[기타 기존정보]

중요:

해당 기능/데이터가 아직 없으면
UI에서 fake section contents를 만들지 않는다.

현재 존재하는 값만 표시.

향후 붙이기 쉬운 layout structure만 잡는다.

==================================================
9. CARD / SECTION STYLE
==================================================

정보 밀도가 조금 높아도 된다.

추천:

- page background
- section title
- white surface
- thin divider
- status badge

모든 줄을 각각 별도 카드로 만들지 않는다.

한 section 안에 관련 데이터를 grouping.
