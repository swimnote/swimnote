[WP-CS-07R — SUPPORT RESOLUTION ROUTER]

목적:

지금까지 만든 지원 자산을
하나의 실제 Resolution Router로 통합한다.

이번 WP에서는 LLM/OpenAI를 호출하지 않는다.

최종 우선순위:

1. RULE / deterministic state
2. DB state
3. Solution DB
4. Frontend Map
5. FAQ / Knowledge
6. Known Issue
7. NO_MATCH

Semantic Cache / Lightweight AI / High Capability AI는
후속 WP에서 추가한다.

==================================================
0. BASELINE
==================================================

재사용:

- support_cases
- support_knowledge_items
- Solution DB
- Frontend Map Registry
- super_incidents / KNOWN_ISSUE link
- event_logs(SUPPORT)

새 병렬 시스템 금지.

==================================================
1. ROUTER ENTRY
==================================================

예:

POST /support/resolve

입력:

query
case_id?
role
mode
pool context
screen_id?
app_version?

실제 repository convention 우선.

client가 role/pool을 조작하지 못하게
auth context 우선.

==================================================
2. RESOLUTION ORDER
==================================================

반드시 순서 고정:

RULE
→ DB_STATE
→ SOLUTION
→ FRONTEND_MAP
→ FAQ_KNOWLEDGE
→ KNOWN_ISSUE
→ NO_MATCH

한 단계에서 HIGH-confidence deterministic 해결이 되면
뒤 단계 실행 중지.

==================================================
3. RULE
==================================================

현재 support_knowledge_items item_type=RULE 재사용.

ACTIVE만.

role/mode/pool 조건 적용.

==================================================
4. DB STATE
==================================================

실시간 데이터로 확정 가능한 문의만.

예:

구독 상태
X 활성화 여부
리포트 생성 상태
기능 활성화 상태

read-only만.

Production mutation 금지.

==================================================
5. SOLUTION DB
==================================================

CS-06R 검색 사용.

MATCHED
NEEDS_DIAGNOSTIC
NO_MATCH

계약 존중.

exact ACTIVE solution이면
llm_required=false.

==================================================
6. FRONTEND MAP
==================================================

기능 위치/화면 이동 문의에 사용.

role/mode/version 필터 필수.

다른 role 화면 반환 금지.

==================================================
7. FAQ / KNOWLEDGE
==================================================

CS-05R Active Knowledge만.

PENDING/INACTIVE/ARCHIVED 제외.

==================================================
8. KNOWN ISSUE
==================================================

현재 활성 Known Issue만.

super_incidents 연결 유지.

resolved incident를 현재 장애처럼 반환 금지.

10. NO LLM YET
==================================================

까지만 반환.

#29 검색→LLM fallback 구현 금지.

==================================================
12. LLM AVOIDANCE FOUNDATION
==================================================

deterministic resolution이면:

llm_required=false

향후 LLM Avoidance Rate 계산 가능하게.

이번 WP에서 KPI 계산은 하지 않는다.

==================================================
13. DIAGNOSTIC
==================================================

Solution이 NEEDS_DIAGNOSTIC이면
required checks 반환.

Router가 임의 root cause 추정 금지.

==================================================
14. HUMAN ESCALATION
==================================================

현재 단계에서 자동 human ticket 생성 금지.

requires_human=true 반환 가능.

실제 버튼/전환은 기존 SupportChat 흐름 사용.

==================================================
15. #29~31 HOLD
==================================================

→ HOLD

→ HOLD

→ HOLD
