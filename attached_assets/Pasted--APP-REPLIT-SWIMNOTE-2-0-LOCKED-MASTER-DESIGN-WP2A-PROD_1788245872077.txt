7. 기존 extra_storage_gb BACKFILL
==================================================

현재:

pool_subscriptions.extra_storage_gb
swimming_pools.extra_storage_gb

값이 다를 가능성이 있음.

Production write 금지 상태이므로:

1.
현재 migration/backfill SQL 작성

2.
중복 데이터 발생 시 우선순위 정의

권장:

existing_effective_extra =
MAX(
  swimming_pools.extra_storage_gb,
  pool_subscriptions.extra_storage_gb
)

단 이 방식이 데이터 구조상 안전한지 실제 schema 확인 후 적용.

중요:

- 값을 잃으면 안 됨
- 기존 구매자가 가진 extra storage 감소 금지
- migration은 idempotent 해야 함
- Production migration 실행 금지
- migration file 작성만 가능

완료보고에:

BACKFILL STRATEGY

를 명시.
