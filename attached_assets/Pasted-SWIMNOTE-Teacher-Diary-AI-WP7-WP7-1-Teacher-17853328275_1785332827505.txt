SWIMNOTE Teacher Diary AI
WP7 — 운영 예외 처리 및 개인정보 로그 안전화

이번 작업은 WP7 하나만 진행한다.

목표:

1. Teacher Diary AI의 기존 기능 흐름은 변경하지 않는다.
2. 운영 환경에서 일지 내용·학생 ID·파일 URI·서버 응답이 로그로 노출되지 않게 한다.
3. Whisper 및 Diary Generate 실패 시 사용자에게 안전하고 이해 가능한 오류를 표시한다.
4. 기존 WP1~WP6 기능을 파손하지 않는다.
5. 작업 완료 후 실제 Git·코드 근거를 제출한다.

중요:

- 새 기능을 임의로 추가하지 않는다.
- AI 구조를 리팩터링하지 않는다.
- Request/Response Contract를 변경하지 않는다.
- API endpoint를 변경하지 않는다.
- 저장 구조를 변경하지 않는다.
- Production 배포 금지.
- Preview OTA도 사용자 승인 전 수행 금지.
- 한 번에 WP7만 수행하고 완료 후 멈춘다.
- 테스트하지 않은 내용을 테스트했다고 보고하지 않는다.

2. 로그 처리 원칙
──────────────────────────────────

다음 원칙으로만 수정한다.

운영 환경에서 절대 로그에 출력하지 않는 값:

- 일지 본문
- 공통 일지 일부 문자열
- 학생별 일지 내용
- transcript
- 학생 이름
- 학생 ID
- student_ref
- JWT
- Authorization
- Bearer token
- access token
- 녹음 파일 URI
- 사진 ID 목록
- 서버 응답 전체 JSON
- AI 응답 원문

운영 환경에서 허용되는 최소 로그:

- request_id
- 오류 코드
- HTTP status
- 요청 duration
- 학생 수
- 입력 글자 수
- 성공/실패 여부

단, 사용자 식별이 가능한 ID나 실제 텍스트는 출력하지 않는다.

개발용 로그가 정말 필요하면 반드시 다음 형태로 제한한다.

if (__DEV__) {
  console.log(...)
}

개인정보가 포함된 로그는 __DEV__ 안에서도 가능한 한 제거한다.

단순 상태 전환 로그는 필요성이 없다면 삭제한다.

3. diary.tsx 로그 수정
──────────────────────────────────

다음을 실제 코드에서 찾아 최소 수정한다.

A. commonContent 내용 출력

예상 형태:

commonContent.slice(...)
console.log(...commonContent...)

처리:

- 내용 출력 완전 제거
- 필요 시 contentLength만 출력
- production에서 실행되지 않도록 처리

허용 예:

if (__DEV__) {
  console.log('[DIARY_LOAD]', {
    hasCommonContent: Boolean(parsed.commonContent),
    contentLength: parsed.commonContent?.length ?? 0,
  });
}

B. handleSave 서버 응답 전체 출력

예상 형태:

JSON.stringify(data)

처리:

- 전체 응답 출력 제거
- 필요 시 성공 여부와 status만 기록
- 서버 응답에 일지 내용이 포함될 가능성이 있으므로 원문 로그 금지

C. 학생·사진 ID 로그

처리:

- 실제 ID 배열 출력 금지
- 개수만 출력
- 가능하면 __DEV__ 안에서만 출력

예:

{
  studentCount: effectiveNotes.length,
  selectedPhotoCount: selectedAlbumIds.length
}

D. Save 로직 자체는 변경하지 않는다.

- POST /diaries payload 변경 금지
- 사진 attach 로직 변경 금지
- student_notes 구조 변경 금지
- 저장 순서 변경 금지

6. 사용자 오류 메시지 원칙
──────────────────────────────────

사용자에게는 기술 내부 정보 대신 행동 가능한 메시지를 표시한다.

권장 메시지 기준:

마이크 권한 거부:
“마이크 권한이 필요합니다. 기기 설정에서 마이크 사용을 허용해 주세요.”

녹음 실패:
“음성 녹음을 시작하지 못했습니다. 잠시 후 다시 시도해 주세요.”

음성 파일 없음:
“녹음 파일을 확인하지 못했습니다. 다시 녹음해 주세요.”

Whisper timeout:
“음성 변환 시간이 초과되었습니다. 다시 시도해 주세요.”

빈 transcript:
“음성이 인식되지 않았습니다. 조금 더 크게 다시 말씀해 주세요.”

네트워크 오류:
“서버에 연결하지 못했습니다. 인터넷 연결을 확인한 후 다시 시도해 주세요.”

인증 오류:
“로그인 정보가 만료되었습니다. 다시 로그인해 주세요.”

요청 과다:
“요청이 많아 처리가 지연되고 있습니다. 잠시 후 다시 시도해 주세요.”

AI Generate timeout:
“일지 작성 시간이 초과되었습니다. 다시 시도해 주세요.”

Response Contract 오류:
“AI 결과를 안전하게 처리하지 못했습니다. 다시 시도해 주세요.”

학생 매칭 오류:
“일부 학생 정보를 확인하지 못했습니다. 학생 선택을 확인한 후 다시 시도해 주세요.”

오류 메시지에 다음을 노출하지 않는다.

- endpoint
- stack trace
- JWT
- 내부 서버 메시지 전체
- 학생 ID
- request body
- AI response 원문

내부 오류 코드는 privacy-safe 로그에만 남길 수 있다.
