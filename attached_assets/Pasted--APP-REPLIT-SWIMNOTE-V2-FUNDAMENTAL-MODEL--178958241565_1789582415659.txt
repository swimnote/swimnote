이전 설계에서 사용한
“시수”, “회원시수” 같은 현장 용어를
SWIMNOTE 핵심 데이터 개념으로 사용하지 않습니다.

수영장마다 같은 단어를 다르게 사용할 수 있으므로
SWIMNOTE는 업계 은어가 아니라
실제로 존재하는 원시 사실을 기준으로 설계합니다.

이번 단계는 최종 설계 확인입니다.

아직 코드 수정 / migration / 배포하지 마십시오.

0. 설계 철학
━━━━━━━━━━━━━━━━━━━━━━

SWIMNOTE 정산은 아래의 사실만 사용합니다.

1. 반이 주 몇 회 개설되어 있는가
2. 학생이 언제부터 언제까지 그 반에 등록되어 있었는가
3. 해당 기간에 시간표상 몇 번의 정규수업 대상이었는가
4. 완료된 보강이 몇 번 있었는가
5. 해당 학생의 정상 월 수업료와 기준 회수는 얼마인가
6. 자동계산으로 알 수 없는 예외금액을 사람이 얼마 조정했는가

끝입니다.

“시수”라는 추상 용어를
DB 계산의 핵심 단위로 만들지 마십시오.

9. 자동 매출 공식
━━━━━━━━━━━━━━━━━━━━━━

학생별 공식은 이것 하나입니다.

standard_monthly_fee
=
pool_class_pricing.monthly_fee

standard_session_count
=
pool_class_pricing.sessions_per_month

per_session_amount
=
standard_monthly_fee
/
standard_session_count

scheduled_regular_count
=
해당 월 시간표상 정규수업 대상 횟수

completed_makeup_count
=
해당 월 완료 보강 횟수

service_count
=
scheduled_regular_count
+
completed_makeup_count

billable_count
=
MIN(
  service_count,
  standard_session_count
)

auto_amount
=
ROUND(
  billable_count × per_session_amount
)

다른 자동 가감식 추가 금지.

12. 선생님 업무량도 원시 사실로 표시
━━━━━━━━━━━━━━━━━━━━━━

필요하면 관리자/선생님 화면에
다음처럼 실제 숫자를 표시합니다.

- 담당 회원 수
- 정규 반 수업 횟수
- 완료 보강 횟수
- 담당 회원 기준 매출

정규 반 수업 횟수:

해당 선생님 담당 class_group별
그 달 schedule_days 발생 횟수.

단 그 날짜 기준
active 학생이 최소 1명 있는 수업만 count.

학생이:

1명이어도
→ 반 수업 1회

5명이어도
→ 반 수업 1회

학생 0명
→ 0회

이것은 회원매출 계산과 별도 지표입니다.
