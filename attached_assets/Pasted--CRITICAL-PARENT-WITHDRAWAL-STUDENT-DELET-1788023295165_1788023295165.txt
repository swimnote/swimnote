==================================================
[추가 CRITICAL — PARENT WITHDRAWAL ≠ STUDENT DELETE]
==================================================

최상위 정책:

학부모 회원탈퇴와
수영장 학생회원정보 삭제/퇴원은 완전히 별개다.

학부모가 탈퇴해도
학생정보는 절대 삭제하지 않는다.

==================================================
A. 학부모 탈퇴 시 처리
==================================================

학부모 탈퇴 대상:

- 현재 parent account
- 현재 parent session/token
- 현재 parent의 해당 pool access
- parent/student 연결 관계는
  현재 schema에 맞게 unlink 또는 inactive 처리

삭제 금지:

- student
- student profile
- class membership
- attendance
- diary
- feed
- photos
- level
- curriculum progress
- growth reports
- AI reports
- 수영장 교육 데이터

==================================================
B. 학생정보 소유권
==================================================

student record는
학부모 개인 계정 소유가 아니라
수영장 tenant 데이터다.

학생은 관리자가 퇴원/삭제 처리하기 전까지
계속 유지되어야 한다.

==================================================
C. 재가입
==================================================

학부모가:

잘못 가입
→ 탈퇴
→ 같은 수영장 재가입

할 수 있어야 한다.

재가입 후
기존 학생정보가 수영장에 남아 있으면
정상적인 본인/보호자 확인 절차를 거쳐
기존 student에 다시 연결 가능해야 한다.

새 student를 무조건 중복 생성하지 않게 확인.

==================================================
D. 다른 보호자 영향
==================================================

학생에게 보호자가 2명 이상 연결된 경우:

보호자 A 탈퇴
→ 보호자 B 연결 유지
→ student 유지

보호자 A 탈퇴 때문에
학생 자체가 삭제되거나
다른 보호자 연결이 삭제되면 FAIL.

==================================================
E. 학생 삭제/퇴원 권한
==================================================

학생정보 삭제/퇴원은 별도 관리자 기능.

허용:

pool_admin
또는 현재 정책상 승인된 관리자 role

학부모 회원탈퇴 API에서
student DELETE 금지.

==================================================
F. 테스트
==================================================

1.
Parent A + Student S

Parent A 탈퇴
→ Parent A account 탈퇴
→ Student S 유지

2.
Student S attendance/diary/report
→ 모두 유지

3.
Parent A 재가입
→ 기존 Student S 재연결 가능

4.
Parent A + Parent B → Student S

Parent A 탈퇴
→ Parent B 유지
→ Student S 유지

5.
관리자가 Student S 퇴원 처리
→ 이때만 학생 상태 변경
