TASK = 무료 AI 배차·안전운행 도우미 설계 확정 및 연속 구현

첨부한 「무료 배차·안전운행 도우미 설계도 V2」를
이번 업무 범위의 기준으로 사용하세요.

목표:
PC에서 AI 배차 작성·관리자 확정·기사 등록과 차량 배정을 관리하고,
스윔노트 기사 앱에서 운행을 수행하며,
승하차 확인 결과를 PC와 학부모 앱에 함께 반영합니다.

1. 기존 구현 대조와 필수 보완

기존 수동 배차 준비·검수·확정본 코드를 재사용하세요.
보고된 배차 개발 SHA e10aee0071493b1b2ebd22d49b00da8c24900251과
현재 작업 상태를 확인하되, 이후 변경을 되돌리지 마세요.

첨부 설계와 기존 코드의 차이를 확인하고 다음만 한 번에 정리하세요.
- 빠진 필수 업무
- 기사 계정·역할·센터 귀속 연결
- 모바일 백그라운드·잠금화면의 실제 지원 제약
- 필요한 서버/API/schema 변경

새 비용·중대한 정책 변경·기존 권한 확대가 필요한 부분은
의견과 선택지를 제시하세요.
그 부분과 독립적으로 구현 가능한 업무는 계속 진행하세요.
전면 재설계나 검토만 반복하며 멈추지 마세요.

2. PC 중심 구현

다음을 같은 업무 흐름으로 연결하세요.
- 차량·기사·인솔자 등록 및 배정
- 회원별 요일·기간·등하원 정류장과 임시 변경
- 수강·결석·보강을 반영한 배차 초안
- AI 배차 제안·필요한 부분 재계산
- 정원·시간·중복·수업 도착 조건 검수
- 관리자 확정·기사 게시·수신 확인
- 운행 현황·예외·이력·필요한 출력

AI는 초안과 변경 제안에 사용합니다.
실제 운행의 버튼 처리마다 모델을 호출하지 마세요.
정원·권한·시간 조건은 코드로 검사하세요.
AI가 만든 이동시간을 실제 도로 이동시간으로 표시하지 마세요.

3. 기사 앱

기존 스윔노트 앱에 운행 전용 진입을 연결하세요.
관리자·강사 권한을 기사 권한의 대용으로 부여하지 마세요.

정상 조작은 다음으로 단순화하세요.
운행 시작 → 정류장별 승하차 확인 → 최종 확인·종료.

- 정상 정류장: 전원 탑승·벨트 확인 또는 전원 하차·인계 확인
- 예외: 학생 선택 후 일부 처리·미탑승·보호자 전화
- 이전/다음: 화면만 이동하며 승하차 처리하지 않음
- 예정 순서와 다르게 실제 처리해도 앞쪽 미처리 대상 보존
- 통화는 회원정보의 연락처로 기본 전화 앱 연결
- 오입력 정정은 원기록과 정정 이력 보존
- 센터 복귀·인계·미하차·차량 내부 최종 확인 포함

조작은 정차 후 또는 인솔자가 수행하도록 구성하세요.

4. GPS·시간·백그라운드 표시

GPS 접근 또는 예정 시간 도래 중 먼저 발생한 조건으로
현재 정류장 확인을 안내하세요.
같은 정류장에 안내창과 알림을 중복 생성하지 마세요.

GPS와 시간은 안내 조건이며 자동 승하차 처리 근거가 아닙니다.
위치·알림 권한이 없어도 수동 확인은 가능해야 합니다.

하나의 운행 상태를 다음 환경에 맞춰 표현하세요.
- 앱 사용 중: 현재 운행 카드
- 다른 앱 사용·잠금 상태: 지원되는 알림 액션/Live Activity

Android와 iPhone의 지원 범위를 실제 대상 버전에서 확인하세요.
지원되지 않는 잠금화면 조작은 현재 운행 카드로 바로 연결하세요.
다른 앱 위에 띄우는 별도 오버레이는 초기 필수 범위에 넣지 마세요.

내장 내비·길찾기·학부모 차량 위치 추적·셔틀 NFC는
이번 범위에 추가하지 마세요.

5. PC·학부모 상태 공유

기사 확인이 서버에 반영되면
PC 운행 현황과 학부모의 자기 자녀 차량 확인에 반영하세요.

- 승차·하차·미탑승·확인 시각·최근 갱신 상태 구분
- 푸시 OFF여도 앱에서 상태 조회 가능
- 푸시 설정 ON일 때만 기존 알림 경로 사용
- 푸시 실패와 승하차 저장 실패 구분
- 오프라인 확인은 전송 대기로 표시
- 중복 터치·재전송·재시작으로 중복 기록/알림 생성 금지
- 운행 변경 버전과 기사 수신 여부 구분

실시간 탑승정보를 실시간 차량 위치나 정확한 ETA로 표현하지 마세요.

6. 개발·전달 방식

PC와 공통 서버 계약부터 완성하고,
기사 앱과 학부모 앱을 같은 계약에 연결하세요.
모바일 연결도 이번 설계 범위이며,
PC 화면만 완료하고 전체 차량 기능 완료로 보고하지 마세요.

기존 인증·회원·수강·권한·푸시·업무 서비스를 재사용하세요.
별도 업무 DB·검증 전용 제품·합성 인증 환경은 만들지 마세요.

변경 경로의 필수 검사와 컴파일만 수행하고,
변경 없는 전체 검사를 반복하지 마세요.
사용자 확인과 설치본·앱 빌드는 의미 있는 통합 단위로 모으세요.

신규 운영 migration·배포·실발송·새 유료 모델 호출은
정확한 변경 및 비용 범위를 모아 별도 승인 요청하세요.
이전 승인 4회 모델 시험은 이미 소진됐으므로 재사용하지 마세요.
