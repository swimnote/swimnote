PROJECT = 스윔노트 오피스 / SWIMNOTE OFFICE
TASK = 무료 기본 정책 반영 + 관리자 핵심 업무 통합본 구현
MODE = 기존 설계 보완 후 연속 구현
PRIORITY = 사용 편의 → 업무 완결성 → 디자인

[1. 이제 검토 반복을 끝내고 구현한다]

최근 제출한 ‘관리자 중심 초기 모델 수정 검수안’을 기준으로,
아래 사용자 확정 사항을 반영하고 구현에 착수한다.

같은 범위를 다시 조사하거나 설계 승인 대기를 반복하지 않는다.
기존 분석·코드·검사 증거를 재사용하고,
실제 모순이나 구현에 필요한 부분만 제한적으로 확인한다.

기존 실행 제품을 이어서 완성한다.
Foundation 재시작·별도 검증 제품·새 인증 체계를 만들지 않는다.

[2. 최종 확정된 무료·유료 정책]

무료 ‘스윔노트’:
- 기본 앱 운영 기능
- PC 오피스 일반 전산 업무
- 초기 전산 세팅과 데이터 이전
- 무료 AI 데이터 이전
- 카드·모바일 수강료 결제 기능
- 기존 설계의 무료 배차·셔틀 및 센터 NFC 출결

유료 ‘스윔노트 AI’:
- AI 기능
- 성장리포트
- AI 작업창
- 인원별 저장용량 제공
- 현재 유료 상품의 가격·할인·약정 정책 유지
- 세부 상품·용량 구성은 추후 사용자 가격 설계에 맞춤

무료 AI 데이터 이전은 유료 AI의 명시적 예외다.

무료 이용자가 PC에 들어가기 위해
기본 월 9,900원 또는 X 이용권을 요구하는 설계는 폐기한다.

단, 무료는 무인증·무권한·무제한 저장공간을 뜻하지 않는다.
기존 로그인·역할·Pool 격리·개인정보 보호는 유지한다.

무료 기본 저장용량·추가 용량 가격을 임의로 확정하지 않는다.
미정 조건은 설정과 상품 계약에서 분리하고,
관련 없는 일반 전산 업무를 차단하지 않는다.

[3. 결제 정책·표현]

카드·모바일 결제 기능은 유료 AI 가입 없이 제공한다.
스윔노트가 센터에 추가 결제 수수료를 붙이지 않는 방향이다.

표현:
‘모바일 결제도 스윔노트 추가 수수료 0원’

카드사·결제사 수수료까지 0원인 것처럼 표시하지 않는다.
0.2% 제휴 수익을 센터 부담 수수료에 임의로 추가하지 않는다.
실제 제휴 계약·정산 조건은 별도로 관리한다.

Smartro 연결은 기존 외부 연동 단계로 유지한다.
그 전에 상품·청구·수기수납·미납·환불·마감은 완성한다.

[4. 제품 역할·명칭]

PC는 ‘관리자 모드 + 수영장 운영 전산’이다.
강사 앱 전체를 PC에 복제하지 않는다.

- 일지 작성·작성 중 사진 업로드: 기존 강사 앱 기능 유지
- PC 일지: 검색·열람·기존 권한의 관리
- PC 사진: 관리자 앨범 업로드·대상 지정·자료 관리
- PC 성장리포트: 본문 열람·검수·허용 수정·발급·발송·이력

PC 일지 작성 확장을 이번 작업에 넣지 않는다.
이미 존재하는 강사 PC 코드는 불필요하게 삭제하지 않고
관리자 기본 메뉴와 분리한다.

외부 명칭:
- 스윔노트 오피스 / SWIMNOTE OFFICE
- 스윔노트 X → 스윔노트 AI

내부 X 식별자·SKU·API·DB 이름은 유지한다.

[5. 이번 완료 목표 — 관리자 핵심 업무 통합본]

최근 검수안의 묶음 1+2를 실제 연결한다.

A. 관리자 접근·이용권
- 무료 관리자의 PC 진입 허용
- 현재 사용자·역할·Pool·계정 상태 검증 유지
- 일상 AI 작업창은 기존 X 자격을 UI와 서버에서 확인
- 일반 조회·저장 API 전체를 X 전용으로 잠그지 않음
- 기존 앱 AI·성장리포트 자격은 현재 계약을 확인해 연결
- 무료 이전은 서버에서 실제 이전 작업과 허용 도구로 제한
- 기존 결과 열람과 새 유료 생성·실행을 구분

B. 성장리포트 관리자 업무
- 검수·발행 대기·발행 이력·회원 상세에서 본문 진입
- 앱과 같은 본문·버전·상태 사용
- 관리자 mark-reviewed와 강사 review 구분
- 요청 메서드와 Native 허용 경로 정리
- 기간·회원별 전체 탐색
- 기존 권한의 검수·발급·발송 경로 연결
- 검수 완료·발급 완료·발송 완료 구분
- 발행본과 당시 이력 보존
- 새 리포트 엔진·별도 원장 신설 금지

C. 관리자 사진·교육기록
- 반·날짜·회원·작성자별 기존 기록 조회
- 관리자 사진 업로드·대상 지정·결과 재조회
- 업로드·일지 첨부·학부모 공개 상태 구분
- 강사 앱의 기존 사진 선택·첨부 흐름 재사용
- 열람할 수 없는 사진의 알림이 먼저 나가는 경로 확인
- PC에서 새로 만드는 흐름은 실제 공개 시점과 알림 의미를 맞춤
- 공유 서버 동작 변경이 필요하면 앱 영향과 함께 최소 수정안 준비
- 빈 일지 자동 생성·임의 발행 금지

D. 회원·상담·등록
- 기존 회원·보호자·가족 자료 재사용
- 상담·담당자·후속 연락
- 체험·레벨테스트·대기·자리 제안
- 기존 회원 중복 확인과 등록전환
- 운영에 필요한 회원정보·변경 이력
- 휴회·복귀·반이동·퇴원의 적용일 구분
- 가족 연락처와 실제 열람 권한 구분

E. 일정·최소 수강 연결
- 날짜별 실제 수업·정원·강사·레인
- 휴강·대강·일정 변경과 충돌 표시
- 회원 등록부터 최소 상품·계약·수강권·반/수업 배정 연결
- 이후 청구·수납이 같은 자료를 이어받도록 구현
- 기존 출결·보강 기록을 별도 원장으로 복제하지 않음
- 승인 대기인 관리자 보강 서버 경로는 해당 동작만 분리

F. 함께 반영할 것
- 관리자 중심 메뉴와 공통 화면 구조
- 현황 숫자 → 같은 조건의 상세 목록
- 검색·필터·스크롤·초안 보존
- Excel/CSV·해당 업무의 필요한 인쇄/PDF
- 기존 공통 Action과 AI 도구 연결
- AI가 없어도 메뉴로 모든 일반 업무 사용 가능

[6. 준비된 기능은 큰 묶음 안에서 함께 진행]

무료 AI 이전:
- 이번에는 회원 자료 이전을 위 등록 흐름에 연결
- 여러 파일·시트 누적, 대화와 미리보기, 규칙 수정
- 중복·충돌·원본 추적·이어하기·변경 요약·결과 출력
- 실제 반영과 초안 구분
- 운영 후 변경 덮어쓰기 방지
- 금융·잔여권리 이전은 해당 원장 완성 때 연결
- 미반영 자료를 성공으로 표시하지 않음
- 정형 처리는 코드, 필요한 의미 해석만 AI 사용

마케팅:
- 관리 주소·홍보 자료·일정·담당자·게시 링크
- 소개/공유 캠페인과 상담·등록 유입 연결
- 외부 자동 연동 없이 수동 관리부터 제공
- 미연동 성과·자동 게시를 실제처럼 표시하지 않음

NFC:
- 기존 출결과 카드 등록·해제·분실·재발급 연결
- 범용 지원 규격을 명확히 구분
- 중복 출결·차감·푸시 방지와 수동 출결 유지
- 준비된 연결 방식이면 같은 제품에 통합
- 실장비 미확인 부분만 예정으로 표시
- 모든 장비 호환 약속·별도 검증 프로그램 제작 금지

배차:
- 기존 설계 원문을 먼저 대조
- 원문 미확인을 임의 재설계 근거로 삼지 않음
- 셔틀 NFC·내비게이션 추가 없음
- 원문이 없으면 해당 부분만 대기하고 다른 구현 계속

[7. 후속 범위는 삭제하지 않는다]

이번 통합본 다음은 Smartro 전 운영 통합본이다.

유지 범위:
- 전체 상품·가격·할인·회차조정·재등록
- 청구·부분수납·배분·미납·환불·정정·마감
- 운영 지출·자금수지·필수 증빙
- 태블릿 신청·직접 서명·확정 문서
- 무료 이전의 금융·잔여권리
- 배차·시설·물품·대회·본사 신청·운영지원
- 업무별 AI·대량 처리·출력 누락 보완

기존 Stage 5~8 안에서 진행한다.
새 단계를 만들거나 독립 업무를 불필요하게 대기시키지 않는다.

[8. 앱 개편 범위]

앱도 무료 기본 + 유료 AI 정책에 맞춰 개편할 예정이다.

이번에는 PC와 서버가 공유할 자격·상태 계약을 맞추고,
앱에 필요한 변경 목록과 호환성을 함께 관리한다.

앱 가입·상품 안내·기능 잠금·용량 표시·결제 진입·외부 명칭은
관련 변경을 모아 후속 통합 앱 빌드에 반영한다.
작은 변경마다 앱을 빌드하지 않는다.

기존 유료 구독을 임의 취소하거나 실제 청구를 변경하지 않는다.
기존 구매자 전환·이미 발급된 리포트 열람·만료 후 정책은
전환안으로 준비하고 실제 적용 전에 필요한 결정만 요청한다.

[9. 개발·운영 경계]

승인된 작업:
- 제품 PC 코드 구현
- 필요한 기존 서버의 호환 확장 코드
- 필요한 DB migration 작성
- 기존 개발환경에서 변경 범위 확인
- 관리자 핵심 업무 통합 설치본 제작

별도 범위 확인 후 적용:
- 운영 DB migration·실제 데이터 일괄 변경
- 운영 서버 배포·기능 활성화
- 기존 구독·실제 가격·청구 전환
- 실발송·실거래·실환불
- 새 유료 모델 호출

운영 적용이 필요한 동작만 대기시키고,
소스 구현·독립 업무·통합 빌드는 계속한다.
서버 미적용 상태를 실제 사용 가능으로 표시하지 않는다.

[10. 속도와 확인 기준]

- 기존 실행 기반·인증·보안 저장·API를 재사용
- 변경 없는 전체 suite·monorepo 검사 반복 금지
- 변경한 권한·금액·중복·데이터 변경 경로는 필요한 직접 검사
- 새 로컬 DB·합성 인증·검증 전용 설치본 금지
- 사용자에게 개발 도구 설치·소스 빌드·터미널 진단 요구 금지
- 기능 하나마다 설치본을 만들거나 확인 요청하지 않음
- 사소한 구현 선택은 합리적으로 처리하고 계속 진행
- 정책 결정은 현재 동작에 영향을 주는 것만 묶어서 질문
- 결정 대기 중에도 독립 작업 계속
- 기존 소스·첨부·후보·설치본·증거 보존
- main 반영·공개 배포는 이번 승인에 포함하지 않음

[11. 완료보고]

다음을 구분해 제출한다:
1) 실제 구현·연결한 관리자 업무
2) 앱·서버·DB 변경 범위
3) 필요한 운영 적용과 아직 미적용인 동작
4) 변경 범위 확인 결과
5) 실제 미실행·실장비 미확인 항목
6) 통합 설치본과 식별정보
7) Smartro 전 운영 통합본에 남은 항목
8) 사용자 결정이 꼭 필요한 사항

화면 존재·API 연결·실제 저장 성공을 구분한다.
전체 완료나 Windows 수용을 근거 없이 선언하지 않는다.

같은 설계 검토를 다시 제출하고 멈추지 말고,
위 범위의 관리자 핵심 업무 통합본을 구현해 전달한다.
