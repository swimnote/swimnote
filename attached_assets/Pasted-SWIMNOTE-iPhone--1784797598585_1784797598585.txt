SWIMNOTE 긴급 안정화 작업

어젯밤 전체 재정비 이후에도 실제 iPhone에서 핵심 기능 오류가 계속 발생하고 있습니다.

이번에는 코드상 “수정 완료”라고 보고하지 말고,
실제 production 서버 + 실제 iPhone 앱에서 아래 모든 항목을 재현하고 수정한 뒤
테스트 결과를 증거와 함께 보고하세요.

==================================================
현재 실제 발생 중인 문제
==================================================

1. 일지를 삭제했는데 앱을 완전히 종료하고 다시 실행하면 삭제한 일지가 다시 나타남

2. 일지를 삭제했는데 앨범 사진에 “사용 중” 표시가 남아 있음

3. 앨범에서 사진이 보이지 않거나 상태가 실제 연결 상태와 맞지 않음

4. “전체 앨범” 또는 “앨범에서 선택” 화면 상단 제목이
iPhone 상태바의 시간·5G·배터리 영역과 겹침

5. 스케줄러에서 일지를 작성하고 저장하면
원래 스케줄러로 돌아가지 않고 홈 화면으로 이동함

6. 홈, 스케줄러, 지난 일지, 앨범이 서로 다른 상태를 보여줌

이 여섯 가지를 하나의 연결된 문제로 보고 전수 점검하세요.

==================================================
1. 일지 삭제 영구 반영 문제
==================================================

실제 현상:

일지 삭제
→ 화면에서는 사라짐
→ 앱 완전 종료
→ 재실행
→ 동일 일지가 다시 나타남
→ 화면 DEV 표시가 del=false

이것은 단순 UI 동기화 문제가 아닙니다.

다음을 실제 production DB와 로그로 추적하세요.

A. 삭제 요청 직전
- diary_id
- class_group_id
- lesson_date
- is_deleted
- deleted_at
- updated_at

B. DELETE 처리 직후
- 응답 HTTP status
- 응답 body
- DB row의 is_deleted
- deleted_at
- 실제 commit 완료 여부
- 사용된 DB connection
- transaction 시작/종료 로그

C. 앱 재실행 후
- GET /diaries 응답 원본
- GET /diary 응답 원본
- GET /today-schedule 응답 원본
- 해당 diary_id가 어느 endpoint에서 다시 내려오는지
- 내려오는 객체의 is_deleted 값

D. 중복 ID 확인
같은 수업에 대해 서로 다른 diary row가 2개 이상 존재하는지 확인하세요.

조회 기준:
- center_id
- class_group_id
- lesson_date
- teacher_id

삭제한 row와 화면에 다시 나타난 row의 ID가 같은지 반드시 비교하세요.

E. 생성 경로 전수 확인
앱 시작 시 또는 화면 진입 시 자동으로 일지를 생성하는 코드가 있는지 검색하세요.

검색:
- POST /diaries
- POST /diaries/with-media
- createDiary
- ensureDiary
- restoreDraft
- autoSave
- upsertDiary
- diary 생성 effect
- 앱 hydration 시 생성 로직

사용자가 저장 버튼을 누르지 않았는데 일지가 자동 생성되는 경로가 있으면 제거하세요.

완료 조건:
- DELETE 직후 DB is_deleted=true
- 앱 종료 후 재실행해도 동일 diary_id가 어떤 API에도 나오지 않음
- 같은 수업 날짜에 새 row가 자동 생성되지 않음

==================================================
2. 사진 “사용 중” 상태 정확성
==================================================

실제 현상:

모든 일지를 삭제했는데
앨범 선택 화면의 사진에 “사용 중” 배지가 남아 있습니다.

“사용 중”은 실제로 유효한 일지에 연결된 경우에만 표시되어야 합니다.

먼저 프론트 코드에서 “사용 중” 판단식을 정확히 보고하세요.

확인 항목:
- journal_id != null 인가
- student_note_id != null 인가
- status == attached 인가
- is_attached 응답 필드인가
- relation table 존재 여부인가
- 캐시된 local state인가

해당 사진 한 장을 기준으로 실제 DB를 조회하세요.

필수 컬럼:
- photo id
- journal_id
- student_note_id
- student_id
- status
- is_deleted
- updated_at

그리고 연결 대상도 확인하세요.

- 연결된 journal_id가 실제 존재하는가
- 해당 journal의 is_deleted 값
- 연결된 student_note_id가 실제 존재하는가
- 해당 student note가 삭제된 일지 소속인가

“사용 중”의 올바른 서버 판정은 다음이어야 합니다.

유효한 사용 중:
- 연결된 journal이 존재
- journal.is_deleted=false
- 또는 유효한 student note가 존재하고 그 상위 journal.is_deleted=false

사용 중 아님:
- journal_id=NULL
- student_note_id=NULL
- 연결 대상 journal이 삭제됨
- 연결 대상 student note가 삭제된 일지 소속
- 연결 ID만 남은 orphan 관계

앨범 API에서 단순히 journal_id가 NULL이 아닌지만 보고
“사용 중”으로 내려주면 안 됩니다.

삭제 트랜잭션에서 다음을 모두 NULL 처리하세요.

photo_assets_meta:
- journal_id
- student_note_id
- student_id가 일지 전용 연결값이라면 정책에 맞게 초기화
- status를 detached/uploaded로 변경

video_assets_meta:
- journal_id
- student_note_id
- student_id가 일지 전용 연결값이라면 정책에 맞게 초기화
- status를 detached/uploaded로 변경

삭제된 일지에 연결된 기존 찌꺼기 데이터도 마이그레이션 또는 정리 쿼리로 복구하세요.

완료 조건:
- 모든 일지를 삭제한 뒤 “사용 중” 배지 0개
- 앱 종료 후 재실행해도 0개
- 새 일지에 사진을 붙이면 해당 사진에만 “사용 중”
- 그 일지를 삭제하면 즉시 “사용 중” 해제

==================================================
3. 앨범 사진 노출 문제
==================================================

앨범은 업로드 자산 보관함입니다.

사진이 일지에 사용됐더라도 앨범에서 사라지면 안 됩니다.

앨범 API와 프론트 필터를 확인하세요.

앨범에 보여야 하는 상태:
- uploaded
- attached
- detached
- failed

제외:
- is_deleted=true인 실제 삭제 자산만 제외

다음과 같은 필터가 있으면 제거 또는 수정하세요.

- attached 사진 제외
- journal_id가 있는 사진 제외
- student_note_id가 있는 사진 제외
- 사용 중인 사진 숨김

앨범에서는 모든 자산을 보여주고
상태만 배지로 구분하세요.

완료 조건:
- 업로드한 사진 전부 앨범에 표시
- 일지에 붙인 사진도 앨범에 계속 표시
- 삭제된 일지의 사진도 앨범에 다시 사용 가능 상태로 표시
- 사진 수가 API 응답 개수와 UI 개수가 일치

4. iPhone Safe Area 및 상단 겹침
==================================================

실제 현상:

“전체 앨범” 또는 “앨범에서 선택” 화면 상단 제목이
iPhone 상태바 시간·5G·배터리 영역과 겹칩니다.

해당 화면과 관련 modal/full-screen route 전부 확인하세요.

수정 기준:

- react-native-safe-area-context의 SafeAreaView 또는 useSafeAreaInsets 사용
- 상단 컨테이너 paddingTop을 임의 고정값으로 두지 않음
- insets.top을 실제 적용
- navigation header가 이미 safe area를 처리한다면 중복 padding 방지
- iPhone 노치/Dynamic Island 기종에서 모두 정상
- header height를 status bar 포함 기준으로 계산
- absolute top: 0 요소가 상태바를 침범하지 않도록 수정

확인 화면:
- 전체 앨범
- 앨범에서 선택
- 사진/영상 선택 modal
- 사진 전체 보기
- 영상 전체 보기
- 일지 상세
- 일지 작성
- 지난 일지

완료 조건:
- 제목·닫기 버튼·선택 카운트가 상태바와 겹치지 않음
- iPhone 세로 화면에서 상단 여백이 일정
- 불필요하게 두꺼운 이중 여백도 없음

5. 일지 저장 후 잘못된 화면 이동
==================================================

실제 현상:

스케줄러에서 수업 선택
→ 일지 작성
→ 저장
→ 홈 화면으로 이동

정상 동작:

스케줄러에서 진입했다면
→ 저장 후 원래 스케줄러 화면으로 복귀

보존해야 할 상태:
- 선택 날짜
- 선택 반
- 월/주/일 보기 모드
- 필요한 경우 DaySheet/바텀시트
- 해당 수업의 일지 완료 상태

진입 출처를 명시적으로 전달하세요.

예:
returnTo = "schedule"
returnDate = "2026-07-23"
returnClassGroupId = "..."
returnViewMode = "day"

저장 후 router.replace("/home") 같은 하드코딩을 제거하세요.

복귀 규칙:

- 스케줄러에서 진입 → 스케줄러로 복귀
- 홈에서 바로쓰기 진입 → 홈으로 복귀
- 지난 일지 수정에서 진입 → 지난 일지 상세/목록으로 복귀
- 어드민 화면에서 진입 → 해당 어드민 화면으로 복귀

가능하면 새 화면을 강제로 replace하지 말고
원래 navigation stack으로 router.back() 하되,
직접 deep link 진입 등 back stack이 없을 경우 returnTo fallback을 사용하세요.

저장 성공 후:
- emitDiaryChanged
- 복귀 대상 화면 데이터 즉시 갱신
- 중복 navigation 실행 방지
- 저장 Promise와 navigation이 두 번 실행되지 않도록 guard 적용

완료 조건:
- 스케줄러에서 작성하면 스케줄러로 복귀
- 선택 날짜와 반 유지
- 작성한 수업이 즉시 “일지 완료”
- 홈으로 튕기지 않음

6. 화면 간 상태 통합
==================================================

현재 각 화면이 서로 다른 상태를 표시하고 있습니다.

다음 화면을 하나의 기준으로 동기화하세요.

- 홈 오늘 수업
- 스케줄러 월/주/일
- 지난 일지
- 일지 상세
- 앨범
- 사진 선택기
- 미작성 일지 카운트

diaryEvents와 mediaEvents를 구분해 구현하세요.

예:
emitDiaryChanged({
  type: "created" | "deleted" | "updated",
  diaryId,
  classGroupId,
  lessonDate
})

emitMediaChanged({
  type: "attached" | "detached" | "uploaded" | "deleted",
  mediaIds,
  diaryId
})

각 화면은 이벤트를 받으면:
1. 즉시 로컬 상태 수정
2. 서버 재조회
3. 오래된 응답이 최신 상태를 덮어쓰지 못하도록 request generation 적용

7. 실제 테스트 시나리오
==================================================

코드 리뷰만 하지 말고 실제 production 앱에서 아래 순서대로 테스트하세요.

테스트 A — 삭제 영구성
1. 일지 작성
2. 앱 재실행
3. 일지 존재 확인
4. 일지 삭제
5. 앱 재실행
6. 일지 미표시 확인
7. 홈·스케줄러·지난 일지 모두 미작성 확인

테스트 B — 사진 사용 중 해제
1. 사진 2장 업로드
2. 일지에 첨부
3. 사진 2장 “사용 중” 확인
4. 일지 삭제
5. 사진 2장 “사용 중” 해제 확인
6. 앱 재실행
7. 계속 해제 상태 확인
8. 새 일지에 다시 선택 가능 확인

테스트 C — 앨범 노출
1. 업로드 사진 수 기록
2. 일지 첨부 전 앨범 수
3. 첨부 후 앨범 수
4. 삭제 후 앨범 수
5. 모든 단계에서 사진 누락이 없는지 확인

테스트 D — 복귀 경로
1. 스케줄러 7월 23일 목 19:00반 선택
2. 일지 작성
3. 저장
4. 같은 스케줄러 날짜/반으로 복귀 확인
5. 홈으로 이동하지 않는지 확인

테스트 E — Safe Area
실제 iPhone에서:
- 전체 앨범
- 앨범에서 선택
- 일지 작성
- 일지 상세

상단 제목과 상태바가 겹치지 않는 스크린샷 제출
