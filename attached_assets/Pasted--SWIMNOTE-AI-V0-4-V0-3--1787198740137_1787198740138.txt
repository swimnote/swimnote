# [SWIMNOTE 학부모 AI 커리큘럼 검색 — V0.4 수정 확정 설계서]

목적:
기존 V0.3 설계를 아래 정책으로 수정한다.

아직 구현하지 않는다.
현재 코드/DB 구조에서 아래 정책대로 구현 가능한지 최종 확인 후 WP 구현을 시작한다.

절대 금지:
- 코드 수정
- DB 수정
- migration
- Production 배포
- 전체 regression test
- 광범위 refactor

이번 단계는 설계 확정 및 구현 전 확인만 수행한다.

==================================================
1. 기능 정의
==================================================

AI 커리큘럼 검색은 학부모가 자연어로 자녀의 실제 수업 진행상황을 질문하면,

1) 학생 실제 수업/일지/진도 기록
2) 해당 수영장의 커리큘럼
3) SWIMNOTE AI 전문 수영 Knowledge

를 조합해

- 현재 어디까지 배웠는지
- 특정 영법/기술 진행 상태
- 최근 무엇을 배우고 있는지
- 다음 커리큘럼 단계
- 현재 단계의 의미
- 왜 현재 기술을 배우는지
- 현재 레벨에서 남은 과정

등을 근거 기반으로 설명하는 학부모용 대화형 AI 검색 시스템이다.

GPT가 학생 진도를 추측하지 않는다.

학생 진도:
학생 실제 기록 + 커리큘럼 구조로 판정

GPT:
판정된 결과와 전문 수영 정보를 자연어로 설명

3. 일반 SWIMNOTE 사용자 정책 — 수정 확정
==================================================

일반 SWIMNOTE 학부모에게
AI 커리큘럼 검색을 실제 사용 가능하게 열지 않는다.

즉:

Normal SWIMNOTE
→ AI curriculum search DISABLED

사용자가 기존
"커리큘럼 검색"
버튼을 누르면 AI 질문 화면으로 진입시키지 않고 안내한다.

안내 문구:

"현재 수영장에 AI 검색용 커리큘럼이 등록되어 있지 않아
커리큘럼 AI 검색을 이용할 수 없습니다."

또는 동일 의미의 자연스러운 문구 사용 가능.

중요:

이 상황에서는
AI Engine / GPT 호출이 절대 발생하지 않는다.

일반 사용자가 버튼을 여러 번 눌러도
AI 비용이 발생하면 안 된다.

==================================================
4. 커리큘럼 검색 활성화 조건
==================================================

AI 커리큘럼 검색은
해당 센터가 실제 검색 가능한 커리큘럼을 충분히 구축한 경우에만 활성화한다.

기본 조건:

SEARCHABLE CURRICULUM ITEMS >= 300

즉:

검색 가능 커리큘럼 300개 이상
AND
센터가 커리큘럼 검색 사용 대상 상태

→ AI 검색 허용

그 외:

→ AI 검색 차단
→ 커리큘럼 등록 필요 안내

중요:

단순히 X mode 여부만으로 search를 실행하지 않는다.

실제 검색 가능한 커리큘럼이 존재해야 한다.

단,
Normal SWIMNOTE는 제품 정책상 AI 검색 비활성화 상태로 유지한다.

6. 학부모 AI 검색 월 사용 횟수 — 10회 확정
==================================================

AI 커리큘럼 검색 사용이 활성화된 센터에서도
학부모는 무제한으로 GPT를 호출할 수 없다.

정책:

학부모 1명당
월 최대 AI 커리큘럼 검색 10회

기준:

parent_account_id
+
calendar month

기본 quota:

CURRICULUM_AI_MONTHLY_LIMIT = 10

==================================================
7. 횟수 차감 기준
==================================================

실제 AI 비용이 발생한 질문만 quota를 차감한다.

GROUNDED_GPT
→ 1회 차감

DIRECT_DB
→ 차감하지 않음

HUMAN_ONLY
→ GPT 호출이 없다면 차감하지 않음

CURRICULUM_NOT_AVAILABLE
→ 차감하지 않음

ERROR
→ 정상 AI 답변이 생성되지 않았다면 차감하지 않음

즉:

"질문 전송 횟수"가 아니라
"실제 유료 AI 응답 생성 횟수"를 기준으로 한다.

==================================================
8. quota 표시
==================================================

AI 검색이 사용 가능한 경우
학부모가 현재 사용량을 확인할 수 있게 한다.

예:

"이번 달 AI 커리큘럼 검색 3/10회"

또는:

"이번 달 남은 검색 7회"

UI 디자인은 기존 SWIMNOTE 스타일에 맞춘다.

너무 강조할 필요는 없지만
사용자가 남은 횟수를 확인할 수 있어야 한다.

9. 10회 소진 시
==================================================

월 10회의 AI 호출을 모두 사용하면
추가 GROUNDED_GPT 요청을 차단한다.

안내:

"이번 달 AI 커리큘럼 검색 이용 횟수를 모두 사용했습니다.
다음 달에 다시 이용할 수 있습니다."

이 상태에서는 GPT 호출 금지.

새 달이 되면 자동으로 다시 10회 사용 가능.

16. quota 데이터 구조 확인
==================================================

현재 curriculum-search API에
monthly quota check가 이미 존재한다고 보고됨.

따라서 새 quota 시스템을 중복 구현하지 않는다.

READ-ONLY 확인:

- 현재 quota table
- 현재 monthly limit 값
- quota key
- parent 기준인지 student 기준인지
- reset 방식
- usage 증가 시점
- 실패 요청도 차감되는지
- 현재 GPT 호출 전/후 어느 시점에 차감하는지

목표:

기존 quota 시스템을 최대한 재사용하고
limit만 10회 정책에 맞춘다.
