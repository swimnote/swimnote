[SWIMNOTE X PRODUCT POLICY CORRECTION]
[P0 — DIRECT PAYMENT → POOL-WIDE X ACTIVATION + X SETUP SEPARATION]

목적:

현재 X 상품 흐름을 다음 최종 구조로 수정한다.

1. 수영장 운영자가 X 정기결제를 직접 완료
2. 결제 성공 즉시 해당 수영장 mode = X
3. 해당 수영장 소속 관리자/선생님/학부모가 모두 X mode로 진입
4. 커리큘럼 업로드 및 X 세부 설정은
   X모드 내부의 별도 "X모드 세팅하기"에서 진행
5. 설정 미완료는 전체 X 진입을 막지 않고
   필요한 개별 기능만 준비중 상태로 제한

이번 작업은
X product/mode UX correction.

RevenueCat 상품/가격/slot/payment server contract는 변경하지 않는다.

==================================================
0. FINAL PRODUCT CONTRACT
==================================================

SWIMNOTE X는:

"신청 → 승인 → X모드"

구조가 아니다.

최종 구조:

정기결제
→ RevenueCat purchase success
→ APP SERVER sync success
→ x_paid_entitlement = true
→ 해당 swimming_pool 전체 X 활성화
→ 해당 수영장 소속 사용자 X mode 적용

즉:

결제 자체가 X 활성 조건.

별도 Super Admin 승인 대기 없음.

==================================================
1. POOL-WIDE MODE
==================================================

X entitlement의 owner는:

individual user가 아니라
swimming_pool.

따라서 해당 pool의 effective X entitlement가 true이면:

- pool_admin
- sub_admin
- teacher
- parent

해당 수영장에 속한 모든 role이
X mode를 사용한다.

각 사용자별로 별도 X 결제/승인 필요 없음.

==================================================
2. PAID MODE RULE
==================================================

paid X subscription:

x_paid_entitlement = true
AND x_force_disabled = false

이면:

mode = x

xmode_config_status가 READY인지 여부와 무관.

즉:

PAID + CONFIG NOT READY
→ x

PAID + CONFIG READY
→ x

paid 고객은 더 이상
전체 앱 mode에서 x_pending으로 보내지 않는다.

==================================================
3. MANUAL ENTITLEMENT
==================================================

Super Admin manual entitlement는
운영/지원/테스트 목적.

기존 manual-only 정책은 별도 유지 가능.

권장 resolver:

if x_force_disabled:
  mode = normal

else if x_paid_entitlement:
  mode = x

else if x_manual_entitlement:
  mode = x or x_pending
  according to current manual/config policy

else:
  mode = normal

중요:

paid customer가 config 미완료라는 이유로
x_pending이 되면 안 된다.

==================================================
4. CONFIG STATUS MEANING
==================================================

xmode_config_status는
"X를 사용할 수 있는가?"를 판단하는 값이 아니다.

의미:

- 수영장별 커리큘럼 업로드 상태
- 커리큘럼 연결 상태
- X 운영 초기 설정 상태
- 개별 X 기능 준비 상태

즉:

ENTITLEMENT
= X 이용권

CONFIG
= X 안에서 필요한 운영 세팅 상태

둘을 분리한다.

==================================================
5. NORMAL SWIMNOTE SETTINGS LABEL
==================================================

일반 SWIMNOTE 설정에서는:

메뉴:
SWIMNOTE X모드

하위 설명:
X모드 알아보기

로 사용.

이 영역의 역할:

- X모드 설명
- AI 설명
- 학부모 리포트 설명
- 선생님 AI 일지 설명
- 커리큘럼 검색 설명
- 선착순 할인
- 정기결제

즉 구매 전/상품 안내 허브.

==================================================
6. X MODE SETTINGS LABEL
==================================================

X가 활성화된 후
X모드 내부 설정에는:

X모드 세팅하기

메뉴를 별도로 제공.

이 메뉴는
"X를 알아보는 화면"이 아니라
실제 운영 설정 화면.

==================================================
7. X MODE SETUP CONTENT
==================================================

"X모드 세팅하기"에서
현재 실제 구현/정책 범위에 맞춰 다음을 관리할 수 있게 한다.

최소:

1. 우리 수영장 커리큘럼
   - 업로드
   - 등록/연결 상태
   - 준비 상태

2. AI 기능 관련 설정
   - 실제 존재하는 옵션만

3. 학부모 리포트 관련 설정
   - 실제 존재하는 옵션만

4. 선생님 AI 일지 관련 설정
   - 실제 존재하는 옵션만

5. 커리큘럼 검색 관련 상태

6. 기타 현재 구현된 X 설정

중요:

없는 기능을 임의로 만들지 않는다.

이번 P0에서 전체 설정센터를 완성할 필요가 없다면
기존 x-setup route를
"X모드 세팅하기"로 재정의/정리하고
향후 확장 가능한 구조로 만든다.

==================================================
14. PURCHASE AUTHORITY
==================================================

정기결제 자체는
수영장 전체 X entitlement를 발생시키지만

누가 결제를 실행할 수 있는지는 별도.

기존 Basic subscription의 실제 결제 권한 contract를 조사하여
그 권한 모델을 X에도 재사용.

현재 실제 권한이 pool_admin only라면
그 자체는 유지 가능.

하지만 사용자 문구에서:

"관리자에게 신청"

개념 제거.

권한 없는 계정에서는:

"이 계정에는 정기결제 권한이 없습니다.
수영장 소유자 또는 결제 권한이 있는 계정에서 진행해주세요."

정도로 표현.

중요:

결제 권한이 없는 것과
X 사용 권한이 없는 것을 혼동하지 않는다.

teacher/parent는
X를 구매할 수 없더라도
pool이 X라면 X 기능을 사용 가능.
