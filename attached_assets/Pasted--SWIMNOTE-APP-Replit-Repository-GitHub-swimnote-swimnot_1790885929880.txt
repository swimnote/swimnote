3. DATA_ACCUMULATING
━━━━━━━━━━━━━━━━━━━━━━

승인 정책:

APP final disposition =
INSUFFICIENT_EVIDENCE

ENGINE의
analysis_status = DATA_ACCUMULATING
은 그대로 보존합니다.

안내:

“이번 달은 성장 판단에 필요한 충분한 변화 근거가 아직 축적되지 않았습니다.”

집계:

resolved_total
= generated_total
+ insufficient_evidence_total
+ policy_excluded_total

generated_total에는 포함하지 않습니다.
failure에도 포함하지 않습니다.
denominator에서도 제거하지 않습니다.

동일 입력 재분석 금지.
성장 평가 내용 창작 금지.
가짜 grounding/AI 성공 처리 금지.

기존 관리자 확인·발송 대기 형태와 호환되게 구현합니다.

4. First Pass
━━━━━━━━━━━━━━━━━━━━━━

월초 fixed pool manifest를 확정합니다.

각 sealed target에 first-pass outcome을 지속적으로 기록합니다.

개별 실패:
→ 기록
→ 같은 drain에서 즉시 반복하지 않음
→ 다음 대상 계속

pool 실패:
→ 다른 pool 계속

성공:
→ 즉시 보존
→ 이후 recovery 대상에서 제외

batch COMPLETED를
전체 분석 완료로 사용하지 않습니다.

전체 first-pass 종료는
고정 manifest의 모든 pool과 sealed target의
실제 first-pass accounting을 기준으로 판정합니다.

5. 실패 집계·슈퍼관리자 PUSH
━━━━━━━━━━━━━━━━━━━━━━

first-pass 종료 후 미완료가 존재하면
슈퍼관리자에게 집계 PUSH를 발송합니다.

포함:

- 전체 처리 pool 수

- generated 수
- insufficient_evidence 수
- 미완료 pool 수
- 미완료 회원 수
- 오류 category별 건수
- 예외 조회 진입점

PII / AI 본문 / payload / token 금지.

month + FIRST_PASS_FINISHED 기준
논리적 중복 발송 방지.

SuperAI에서 월/pool/error category별
미완료 내역을 확인할 수 있게 합니다.

6. Recovery
━━━━━━━━━━━━━━━━━━━━━━

기존 batch-recovery를 최대한 재사용합니다.

대상:
실제 실패/미완료 중
현재 계약상 recovery가 허용되는 건만.

제외:

- 기존 성공
- PUBLISHED
- INSUFFICIENT_EVIDENCE
- 정당한 policy exclusion
- UNKNOWN

recovery 회차를 지속적으로 기록합니다.

retry_count 초기화로
무한 recovery가 가능해지지 않게 합니다.

기존 성공 report 재분석 금지.

UNKNOWN을 새 request_id로 우회하는 기능 금지.

━━━━━━━━━━━━━━━━━━━━━━
7. Pool READY
━━━━━━━━━━━━━━━━━━━━━━

각 pool은 독립적으로 판정합니다.

READY 조건:

resolved_total == eligible_total

그리고 다음 blocker가 모두 0:

- UNKNOWN
- FAILED
- MISSING
- DUPLICATE
- WRONG_POOL
- QUEUED
- PROCESSING
- RETRY_PENDING
- 기타 unresolved 상태

다른 pool 실패 때문에
완료 pool READY를 지연시키지 않습니다.

recovery로 마지막 미완료가 해결되면
해당 pool을 즉시 다시 reconciliation 합니다.

9. Circuit Breaker
━━━━━━━━━━━━━━━━━━━━━━

월간 growth-report worker 범위에서만 구현합니다.

전체 breaker를 작동시키지 않습니다.

비정상적인 연속/대량 실패만 pause 대상으로 합니다.

window
probe
cooldown

pause 시:

- 신규 provider dispatch 중단
- 성공 결과 보존
- lookup/reconciliation 허용
- 슈퍼관리자 장애 PUSH
- 원인 수정 후 기존 manifest에서 resume

미처리 target이 존재하면
first-pass 완료로 선언하지 않습니다.
