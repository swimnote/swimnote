2. 실제 앱 인증 토큰 연결 완성
==================================================

TeacherDiaryAIClient가 현재 로그인한 앱 사용자의 실제 JWT를 받아
Authorization Header에 정확히 넣도록 확인하고 수정하십시오.

Authorization:
Bearer <현재 앱 JWT>

확인할 것:

- AuthContext에서 실제 토큰 로드
- SecureStore 또는 기존 저장소에서 토큰 복원
- DiaryAIService까지 토큰 전달
- TeacherDiaryAIClient Header 반영
- 업데이트 또는 reload 후 토큰 유지
- 토큰 누락 시 요청 전 AUTH_TOKEN_MISSING으로 차단
- 401 응답은 NETWORK 오류로 표시하지 않음
- 실제 401일 때만 인증 오류로 분류

실제 앱 JWT 원문을 로그나 보고서에 노출하지 마십시오.

다음 값만 확인하십시오.

- token_present
- exp
- role
- token_version
- swimming_pool_id 또는 tenant claim
- 서버 서명 검증 성공 여부

3. Request Contract를 설계대로 고정
==================================================

앱이 전송할 Request:

{
  "contract_version": "1.0",
  "schema_version": "1.0",
  "feature": "teacher_diary",
  "request_id": "<UUID v4>",
  "locale": "ko-KR",
  "input": {
    "text": "<교사 텍스트 또는 STT 원문>"
  },
  "context": {
    "pool_id": "<실제 swimming_pool_id>",
    "class_id": "<실제 class_group_id>",
    "lesson_date": "YYYY-MM-DD",
    "student_refs": ["<실제 student.id>"],
    "students": [
      {
        "ref": "<실제 student.id>",
        "name": "<DB 정식 학생 이름>"
      }
    ]
  }
}

반드시 검증:

- request_id UUID v4
- student_refs와 students[].ref 집합 동일
- 학생 이름은 DB 정식 이름
- 교사 원문 임의 변형 금지
- 앱에서 공통·학생 내용을 다시 분류하지 않음
- 앱에서 Template, Knowledge, Curriculum 추정 금지

4. AI Engine 내부 파이프라인 실제 연결 확인 및 수정
==================================================

정식 V1 Route가 반드시 기존 GroundedPipelineRunner를 호출해야 합니다.

실제 경로:

POST /api/v1/teacher-diary/generate
→ 인증
→ Request Contract 검증
→ TeacherDiaryAdapter 또는 기존 Contract Adapter
→ GroundedPipelineRunner.run()
→ TeacherInputParser
→ parseDiaryState
→ StudentRepository / Student Matcher
→ DiaryTemplateModule
→ KnowledgeModule
→ GroundedDraftBuilder
→ Naturalizer
→ GroundingValidator 또는 PolishOnlyValidator
→ TeacherDiaryAdapter.toV1Response()

Route에서 OpenAI를 직접 호출하는 별도 legacy 생성기를 사용하지 마십시오.

기존 설계대로 다음 기능이 실제 호출 경로에 포함돼야 합니다.

- STT 정규화
- 의미 추출
- COMMON/STUDENT 규칙 기반 분리
- 등록 학생 이름 확정
- 템플릿 30% 후보 진입
- 최종 사용 점수 1.40
- 동의어 확장
- Center/Tenant 격리
- INPUT_ONLY
- TEMPLATE_ASSISTED
- KNOWLEDGE_GROUNDED
- CENTER_CUSTOMIZED
- 섹션 간 내용 이동 금지
- GPT 이름 변경 금지
- student_ref 유지

구현은 되어 있지만 정식 Route에 연결되지 않은 모듈이 있다면 이번 작업에서 연결하십시오.

- Teacher Diary 품질 FAIL/UNKNOWN은 HTTP 200 + meta 기록
- 시스템 실패만 오류 status 반환

==================================================
6. 앱 Response Normalizer 확정
==================================================

DiaryAIService.normalizeDiaryResponse()는 grounded 모드에서 신형 V1 Contract만 허용하십시오.

매핑:

resp.result.common
→ normalized.common

resp.result.students[].student_ref
→ normalized.students[].studentRef

resp.result.students[].content
→ normalized.students[].content

resp.request_id
→ normalized.requestId

resp.meta
→ normalized.meta

resp.usage
→ normalized.usage

grounded 모드에서 다음 구형 구조로 자동 fallback하지 마십시오.

- resp.common
- resp.students[].student_id
- resp.status
- resp.warnings

HTTP 상태 처리 순서:

1. fetch 완료
2. Content-Type 확인
3. JSON parse
4. HTTP status가 2xx인지 확인
5. 2xx가 아니면 서버 오류 분류
6. 2xx일 때만 V1 Contract 정규화
7. Contract 검증
8. 결과 반환

401·403·422·500을 Contract 오류나 NETWORK 오류로 위장하지 마십시오.

==================================================
7. 오류 분류 정상화
==================================================

실제 오류별 causeCode:

- fetch 자체 실패 → NETWORK_ERROR
- AbortController → ABORTED
- timeout → TIMEOUT
- 401 → AUTH_401
- 403 → AUTH_403
- 404 → HTTP_404
- 422 → HTTP_422 또는 서버 code
- 500 → HTTP_500
- 비 JSON → CONTENT_TYPE_ERROR
- JSON parse 실패 → PARSE_ERROR
- result 없음 → CONTRACT_RESULT_MISSING
- request_id 불일치 → CONTRACT_REQUEST_ID_MISMATCH
- unknown student_ref → CONTRACT_UNKNOWN_STUDENT_REF
- 중복 ref → CONTRACT_DUPLICATE_STUDENT_REF

“네트워크 연결을 확인해주세요”는 fetch 자체 실패일 때만 표시하십시오.
