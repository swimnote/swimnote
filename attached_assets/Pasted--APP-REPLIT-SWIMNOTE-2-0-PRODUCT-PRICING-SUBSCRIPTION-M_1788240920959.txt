14. 영상 서버 안전한도
==================================================

현재 서버 100MB hard limit이 있다면
상품 제한으로 사용하지 않는 방향.

하지만:

무제한 byte upload로 서버가 죽는 구조도 금지.

따라서:

원본 선택
→ client compression
→ 압축 완료파일 업로드

구조로 전환 후

서버에는
"기술적 최종 안전한도"
를 별도로 둘 수 있음.

중요:

사용자에게
"영상은 100MB까지만 가능"
같은 상품 제한으로 노출하지 않는다.

1.6.3 앱이 깨지면 안 됨.

- subscription endpoint
- plan response
- entitlement
- restore
- storage quota
- member limit
- video endpoint
- media response
- album
- diary feed

필요하면 서버는 backward-compatible response 유지.

2.0 때문에
기존 production 앱에 breaking contract 만들지 마십시오.

26. 누락/충돌 검출
==================================================

이번 검토에서 가장 중요한 부분.

아래를 반드시 찾아내십시오.

- 설계에는 있는데 현재 schema로 불가능한 것
- 현재 앱과 서버 계약이 충돌하는 것
- RevenueCat 구조상 바로 안 되는 것
- Store 정책상 별도 처리가 필요한 것
- 1.6.3 호환 깨질 가능성
- video compression 라이브러리/Expo native build 문제
- 데이터 migration 필요성
- media table 변경 필요성
- Trial abuse 가능성
- restore purchase 문제
- 기존 subscriber migration 문제
- DATA pack entitlement 문제
- X 플랜 upgrade/downgrade 문제
- storage downgrade 문제
- X downgrade 시 300GB→10GB 같은 quota 충돌
- X 해지 후 저장공간 초과 상태 처리
- Trial 종료 후 생성된 X 데이터 보존 문제

문제가 있으면 숨기지 말고 보고.
