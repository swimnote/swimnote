============================================================
1. 실제 수정 대상
============================================================

이번 WP는 회원 관리 화면에서 아래 2건만 수정한다.

[ISSUE 1]
상단 "어린이 직접 등록" 버튼이
네이비 헤더 바로 아래에 너무 붙어 있어서
버튼이 독립된 CTA처럼 안 보이고
상단 배경에 붙은 요소처럼 보여 UI가 어색함.

[ISSUE 2]
학생 목록 카드 내부에 있는 아래 4개 quick action 버튼:

- 반이동
- 연기
- 퇴원
- 삭제

이 4개를 카드 바깥에서 바로 누르는 구조를 제거하고,
이 기능들은 전부 "상세" 버튼 안의 상세 화면/상세 진입 경로로 이동시켜야 함.

즉,
회원목록 카드에는 "상세" 진입만 두고,
반이동/연기/퇴원/삭제는 상세 진입 후 그 안에서 처리되게 구조를 정리한다.

============================================================
2. ISSUE 1 — 어린이 직접 등록 CTA 수정
============================================================

현재 문제:
- "어린이 직접 등록" 버튼 상단이 네이비 헤더 하단에 거의 붙어 있음
- 버튼이 독립된 card/button 형태로 안 보임
- 실기기에서 "잘못 붙은 레이아웃"처럼 보임

기대 결과:
- 헤더와 버튼 사이에 명확한 세로 간격을 둘 것
- 버튼이 독립된 CTA 블록처럼 보여야 함
- 좌우 여백/상하 여백이 자연스러워야 함
- 버튼 모양이 또렷하게 살아 있어야 함

수정 방향:
- 헤더 아래 첫 CTA section의 top margin / padding 조정
- safe area / container spacing 확인
- 버튼 자체 높이/라운드/패딩은 기존 디자인 언어 유지
- 단순히 화면 전체를 아래로 밀지 말고 해당 CTA 영역 레이아웃을 최소 수정

중요:
- 검색창, 필터칩, 목록 카드 간격은 불필요하게 건드리지 말 것
- 이 CTA가 상단 배경과 시각적으로 분리되어 보여야 함

============================================================
3. ISSUE 2 — 회원목록 카드 액션 구조 정리
============================================================

현재 문제:
학생 카드마다 아래 버튼이 직접 노출됨:
- 반이동
- 연기
- 퇴원
- 삭제
- 상세

사용자 요구:
- 카드에서 반이동/연기/퇴원/삭제 직접 노출 제거
- "상세" 버튼을 눌러 상세로 들어간 뒤
  거기에서 반이동/연기/퇴원/삭제를 처리하도록 구조 변경

즉,
목록 카드는 "요약 + 상세 진입" 역할만 하고,
수정/상태변경/삭제 액션은 상세 화면에 집중시킬 것.

기대 결과:
회원목록 카드:
- 유지: 핵심 요약 정보
  (이름, 상태, 주횟수, 반, 선생님, 전화, 학부모미연결 등)
- 유지 가능: 상세 버튼
- 제거: 반이동, 연기, 퇴원, 삭제 버튼의 카드 직접 노출

상세 화면(member-detail 등 실제 active route 기준):
- 반이동 기능 사용 가능
- 연기 기능 사용 가능
- 퇴원 기능 사용 가능
- 삭제 기능 사용 가능
- 기존 저장/확인/모달/검증 로직은 유지

중요:
"없애라"는 뜻은 기능 삭제가 아니라
"목록 카드에서 꺼내고 상세 내부로 이동/집중"이다.

============================================================
4. 상세 화면 처리 원칙
============================================================

실제 현재 소스 기준으로
회원 상세 화면의 active component / route를 확인해서 작업할 것.

예상:
- /(admin)/member-detail
- member-detail.tsx
등 기존 상세 화면

그 상세 화면이 already supports:
- 반 변경
- 연기 / 퇴원 / 복귀 / 삭제
등을 갖고 있다면
목록 카드 액션을 제거하고 상세 쪽만 entry point로 남기면 된다.

만약 일부 액션이 상세 내부에 없으면
새 아키텍처를 만들지 말고
기존 상세 구조 안에 정리해서 넣을 것.

5. 공통 적용 범위
============================================================

이 회원 관리 화면과 회원 상세 화면이
Normal SWIMNOTE와 X mode에서 공통 파일이면
반드시 공통 컴포넌트 한 번만 수정해서 둘 다 반영할 것.

반드시 확인할 것:
- Normal members route
- X members route
- same file 여부
- same member-detail 여부

공통이면:
Normal + X 둘 다 동일하게 수정

중복 구현 금지.
