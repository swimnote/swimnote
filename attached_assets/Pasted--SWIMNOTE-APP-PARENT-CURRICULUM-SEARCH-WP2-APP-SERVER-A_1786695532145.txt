==================================================

코드 수정 전에 실제 Repository를 조사한다.

다음 항목을 실제 schema/route/service 기준으로 확인:

A. Parent 인증 middleware

B. Parent ↔ Student 승인 관계 테이블/함수

C. Student의 swimming_pool_id 확인 방법

D. Pool mode canonical resolver
   반드시 기존 resolvePoolMode() 재사용

현재 고정 canonical rule:

mode = x
iff:
xmode_entitlement = true
AND
xmode_config_status = 'READY'

그 외:
x_pending / normal

approval_status를 mode 계산에 넣지 않는다.

E. Pool-owned curriculum/template 저장 위치

F. X global curriculum/template 저장 위치

G. active/current template set 판정 방법

H. 학생 현재 curriculum/progress 저장 위치

I. 기존 Teacher Diary에서 사용하는
curriculum/template scope builder가 있다면 재사용 가능 여부

J. 기존 AI ENGINE server-to-server client/auth 방식

특히 기존 Growth Report:

growth-report-engine-client.ts

가 ENGINE을 어떻게 호출하고
어떤 JWT/service auth를 사용하는지 먼저 확인.

새 인증 체계를 임의로 만들지 않는다.

조사 후 실제 schema에 맞춰 구현한다.

==================================================

  "request_id": "curriculum_<uuid>",
  "query": "우리 아이는 지금 평영을 어디까지 배우고 있나요?"
}

원칙:

- studentId는 URL/path에서 받음
- pool_id를 client가 임의 전송하지 않음
- mode를 client가 임의 전송하지 않음
- curriculum IDs를 client가 임의 전송하지 않음
- Parent App은 질문만 전달

==================================================
5. NORMAL MODE ELIGIBILITY
==================================================

기존 WP12 설계 원칙:

NORMAL pool은
해당 수영장이 직접 보유한 curriculum/template 데이터가
최소 300개 이상일 때
Parent Curriculum Search 활성화.

중요:

“300개”의 실제 계산 대상을
Repository의 기존 curriculum/template 구조를 보고 확정.

임의로:

row 300개
template 300개
curriculum 300개

중 하나를 추측하지 마라.

기존 WP12 memory/design에서
정의된 canonical counting rule이 있으면 그대로 사용.

없으면 STOP 후 보고.

다른 pool의 데이터로 300개를 채우지 않는다.

조건 미충족 시 ENGINE 호출 금지.

typed error 예:

CURRICULUM_SEARCH_NOT_ELIGIBLE

6. X MODE ELIGIBILITY

- ACTIVE
- 현재 사용 가능한
- canonical X global template/curriculum set

만 선택.

반드시 기존:

global_template_sets
diary_templates
scope = x_global

구조와 기존 helper를 우선 재사용.

deprecated/inactive set 사용 금지.

다른 pool-owned set 혼합 금지.

12. RESPONSE VALIDATION
==================================================

ENGINE response를 무조건 신뢰하지 않는다.

검증:

- request_id 일치
- schema_version 지원
- feature 일치
- result.answer string
- grounding.validation === PASS
- grounding.curriculum_ids가
  APP이 전송한 allowed curriculum IDs의 subset인지
- 중복/unknown curriculum ID 없음

ENGINE이 허용하지 않은 curriculum ID를 반환하면:

정상 응답으로 Parent에게 전달 금지.

typed internal error 처리.

Knowledge IDs는 ENGINE Knowledge DB ID이므로
APP DB와 비교하지 않는다.
