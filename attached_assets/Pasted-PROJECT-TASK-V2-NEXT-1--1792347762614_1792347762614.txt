2. 실제 일정과 자동 배차 완성

다음을 기존 회원·수강·보강·출결 데이터와 연결하세요.
- 실제 수업 요일·시작/종료 시각
- 휴강·일정 변경·미래 수강·결석·보강
- 센터 출발·복귀·인계에 필요한 버퍼
- 차량 정원·가용 시간·기사/인솔자 배정
- 회원별 정기·임시 이용과 승하차 조건

기본 운행은 귀가 학생 하차 후 다음 수업 학생 승차로 구성하고,
예외적인 혼합 순서도 같은 정류장 구조로 처리하세요.

기존 배차·고정 순서·고정시각을 보존하면서
자동 초안과 변경 구간의 부분 재계산을 완성하세요.
필요한 제약 계산/Solver는 기존 기술과 가벼운 구성을 우선 사용하세요.

AI는 조건 해석과 배차 제안에 사용합니다.
정원·중복·시간·귀속 검사는 결정적인 코드로 수행하고,
사용자가 검수·확정한 뒤 게시하세요.

이동시간은 등록된 값이나 사용이 허용된 근거를 사용하세요.
주소·좌표·이동시간이 부족하면 보완 대상을 표시하고,
AI 추측을 실제 도로 시간이나 최적 경로 검증으로 표시하지 마세요.
미배정·충돌 학생을 누락한 채 전체 배차 완료로 표시하지 마세요.

실제 모델 호출 없이도 수동 편집과 제약 검수는 사용할 수 있어야 합니다.
무료 배차용 AI 권한으로 일반 유료 AI 작업창을 개방하지 마세요.

3. 기사 가입과 운행 업무 완성

기사 최초 가입은 기존 스윔노트 가입 흐름을 우선 재사용하고,
센터 초대 수락 후 DRIVER/ESCORT 권한을 부여하도록 연결하세요.
권한 부여 전에는 회원·보호자·운행 자료를 공개하지 마세요.
관리자·강사 권한을 기사 권한 대신 부여하지 마세요.

기존 운행 화면을 유지하며 다음 잔여 항목을 완성하세요.
- 운행 당시 인계조건 snapshot과 기사 표시
- 전원/일부 승하차와 미탑승
- 기본 전화 앱 연결 후 같은 운행으로 복귀
- 직전 오입력 정정과 원기록 보존
- 미하차·미처리·센터 인계·차내 최종 확인
- C를 먼저 처리해도 A/B 미처리 보존

이전/다음은 조회 대상만 바꾸며 실제 처리로 기록하지 않습니다.
조작은 정차 후 또는 인솔자가 수행하도록 구성하세요.

4. 백그라운드와 잠금화면 연결

기사의 매 정류장 앱 재진입을 줄이는 기능은 이번 핵심 범위입니다.

현재 모바일 프로젝트의 native 구성과 target/min OS를 확인한 뒤
공식 지원 방식으로 연결하세요.
- Android: 운행 알림·액션, 필요한 실행 유지 방식
- iPhone: 지원되는 Live Activity·알림 액션과 운행 카드
- 공통: 지원하지 않는 조작은 현재 운행으로 바로 진입하는 fallback

각 OS에서 실제 가능한 표시·조작·잠금 해제 조건을 구분하세요.
두 OS가 같은 방식으로 동작한다고 가정하지 마세요.

GPS 접근과 예정 시간 중 먼저 발생한 조건으로 안내하되,
동일 정류장 안내를 중복 생성하거나 창을 쌓지 마세요.
시간 도래를 실제 도착으로 표시하지 마세요.
GPS로 승하차를 자동 확정하지 마세요.

위치·알림 권한 거절, 신호 부족, 지연 상황에서도
직접 정류장을 선택해 처리할 수 있어야 합니다.
운행 종료 시 불필요한 위치 접근과 운행 표시를 종료하세요.

위치의 상시 서버 전송·부모 차량 위치 추적·다른 앱 위 오버레이는
이번 기본 범위에 추가하지 마세요.

native 변경이 필요한 기능은 소스와 통합 빌드에 반영하고,
기존 앱에 OTA만 보내면 된다고 안내하지 마세요.
실기기가 없다는 이유로 구현 가능한 native 연결까지 미루지 말고,
구현과 실기기 미확인을 구분하세요.

5. 오프라인 복구와 관리자 해결

기존 보호된 전송 대기와 동일 요청 ID를 재사용하세요.
다음 보류 상황을 PC에서 확인·대조·해결할 수 있게 완성하세요.
- 운행 버전 변경
- 기사 배정 또는 권한 회수
- 오프라인 기록과 서버 현재 상태 충돌
- 정정·중복 요청·응답 유실

관리자가 원기록·당시 배차·확인 시각·충돌 사유를 확인하고
권한 안에서 해결하도록 하세요.
관측 기록을 조용히 삭제하거나 새 승하차로 복제하지 마세요.

현장 확인 완료, 전송 대기, 서버 반영 완료를 구분하고
기존 영수증 복구 경로를 유지하세요.

6. PC와 학부모 실시간 상태 및 알림

같은 서버 승하차 기록을 기준으로
PC 현황과 승인된 자기 자녀의 학부모 화면을 갱신하세요.
기존 실시간 전달 방식을 재사용하고 재연결 시 상태를 재조회하세요.

기존 push dispatcher에 알림 intent를 연결하고,
중복 방지·실패 기록·재처리 방식을 완성하세요.
- 알림 OFF: 발송하지 않지만 앱 조회 가능
- 알림 ON: 승인된 수신자에게만 발송
- 발송 실패: 승하차 기록은 유지
- 동일 이벤트 재처리: 중복 알림 방지
- 유료 SMS 자동 전환 금지

실제 push 발송은 이번 소스 구현 지시로 승인된 것이 아닙니다.
설정 저장·서버 기록·푸시 발송 성공을 각각 구분하세요.

7. 차량관리와 문서 잔여 기능

기존 원 설계의 주유·정비·보험·검사 이력과 필요한 출력,
운행 기록 검수·확정·서명을 이번 차량 범위에서 완성하세요.
기존 지출·문서 기능이 있으면 재사용하세요.

공식 제출 양식은 적용 대상과 최신 원문을 확인해 작성하고,
확인되지 않은 출력은 비공식 업무용으로 표시하세요.
새 범용 회계·전자서명 플랫폼이나 자동 신고 기능으로 확대하지 마세요.

다만 새 SQL·트랜잭션·동시 처리·중복 방지는
기존 개발 DB 또는 사용이 허용된 검증 환경에서 직접 확인하세요.
순수/주입 단위검사만으로 실제 DB PASS를 선언하지 마세요.
운영 데이터를 검증용으로 변경하지 마세요.

별도 합성 인증·검증 전용 제품·반복 설치본을 만들지 마세요.
PC와 모바일은 각각 이번 차량 기능을 포함한 통합 산출물로 모으세요.
현재 가능한 빌드와 내부 확인을 수행하고,
서명·기기 접근 등 실제 차단 조건만 정확히 보고하세요.

사용자 확인은 기능별로 끊지 말고 최종 통합 체크리스트로 모으세요.
기존 업무 호환성과 인증·센터 격리·중복 처리 보호는 유지하세요.

9. 운영 적용과 비용

기존 운영 적용 승인으로 이번 V2를 자동 배포하지 마세요.
완성된 정확한 SHA와 migration 파일·순서·영향·복구 절차를
한 묶음으로 제출하세요.
기존 OFFICE schema를 중복 적용하지 마세요.

신규 유료 모델 호출·실발송·운영 migration·운영 배포·앱 공개 배포는
기존 승인 범위를 확인하고 새 범위만 묶어서 요청하세요.
이전 모델 시험 4회 승인을 추가 호출에 재사용하지 마세요.
가격·구독·기존 운영 설정은 일괄 변경하지 마세요.

권한이나 새 비용 결정이 필요한 항목만 분리하고,
그와 독립적인 구현은 계속 진행하세요.
