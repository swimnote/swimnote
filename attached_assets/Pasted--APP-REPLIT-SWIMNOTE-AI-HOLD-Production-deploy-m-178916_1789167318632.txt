2. 출석은 DATE가 아니라 실제 수업 SESSION 기준
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

현재:

COUNT(DISTINCT a.date)

방식은 수정하십시오.

같은 날 학생이 실제로

정규수업 1회
+
보강수업 1회

에 참여했다면
실제 수업 참여는 2회입니다.

date 하나만 DISTINCT 처리하면
1회로 잘못 계산됩니다.

현재 attendance schema의 실제 unique/session 식별 구조를 확인하십시오.

우선순위:

1. 실제 lesson/session id가 있으면 그것 사용
2. 없으면 attendance row의 canonical id 검토
3. 현재 구조가 class_group_id + student_id + date 단위라면
   최소 class_group_id + date 조합으로 distinct 처리

단순 DISTINCT date 사용 금지.

동일한 실제 수업이 DB 중복으로 2행 생겼을 때만
1회로 계산되어야 합니다.

3. late는 실제 참여라면 출석으로 인정
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

현재 status:

present
absent
late

중

present만 인정하도록 계획되어 있으나,
late가 실제 수업에 늦게 참석한 의미라면
성장리포트 발급정책상 실제 수업 참여입니다.

따라서 실제 운영 semantics를 확인하십시오.

present
+
late

보강도 실제 참여 status이면 포함.

만약 현재 시스템의 late가
실제 참여를 뜻하지 않는 특수 상태라면
그 근거를 보고하십시오.

실제로 분석 원천으로 포함될 수 있는

- pool 일치
- analysis period 일치

- 실제 분석 가능한 내용 존재
- 빈 note가 source로 세어지지 않음
- 동일 Diary 중복 note는 1회
- ENGINE에 실제 전달되지 않는 기록은 count하지 않음
