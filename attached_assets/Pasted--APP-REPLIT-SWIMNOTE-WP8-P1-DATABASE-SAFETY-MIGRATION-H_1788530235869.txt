============================================================
0. 목적
============================================================

WP8 기능 구현은 완료되었으나
Production Safety Incident 검증에서 다음이 확인됨.

1.
Replit development api-server가
Production Supabase DB와 동일한
SUPABASE_DATABASE_URL을 사용하고 있음.

2.
ensureWp8Schema()가 runtime boot 시 실행되어
Replit dev server restart만으로
Production DB DDL이 실행됨.

3.
WP8 preflight 테스트가
Production DB에 테스트 support_cases / notes를 삽입함.

기존 데이터 손상은 없지만
개발/테스트와 Production DB 격리가 깨져 있음.

이번 WP8-P1 목표:

A.
runtime boot DDL 제거

B.
WP8 schema를 explicit migration 방식으로 전환

C.
dev/test가 Production DB를 자동 mutate하지 못하게 fail-closed guard 추가

D.
기존 Production 테스트 데이터 정확히 inventory

E.
삭제는 하지 않고 cleanup plan만 작성

F.
WP8 기능 regression PASS

완료 후에만 WP9 시작 가능.
