[WP-CS23C — Expected Question Library, Direct Matcher Import & Runtime QA]

목적:

CS23B에서 확정한 Canonical Answer 72개를 기준으로
사용자가 실제 고객센터에 입력할 수 있는 자연어 질문 Variant를 대량 생성하고,
support_intent_utterances에 안전하게 등록한 뒤
Direct Matcher의 실제 적중률과 오답률을 검증한다.

이번 WP의 목표는:

Canonical Answer 72개
→ 자연어 예상질문 Library
→ DB Import
→ Direct Match Runtime 검증

이다.

1. 절대 원칙
    ━━━━━━━━━━━━━━━━━━━━━━
2. Canonical Answer 내용 변경 금지.
3. 기존 ACTIVE 26 Knowledge 임의 수정 금지.
4. 질문 Variant가 의미를 바꾸면 안 됨.
5. 한 질문이 여러 intent에 애매하게 걸리면 자동 Direct 등록 금지.
6. 짧은 질문은 무리하게 특정 intent로 매핑 금지.
7. 가격/환불 등 HUMAN_ONLY intent는 Direct Answer 반환 금지.
8. Production 자동 ACTIVE 금지.
9. Dataset 검증 후에만 active utterance 등록.
10. GPT를 Variant 생성 결과 검증 없이 그대로 신뢰 금지.
11. 틀린 Direct Answer보다 NO_MATCH 우선.

Direct Matcher 전체 시간.

현재 JS-side bounded candidate strategy가

LIMIT 500으로 인해
등록된 utterance 일부가 검색 후보에서 빠지는 구조인지 반드시 확인.

만약 단순히:

SELECT … LIMIT 500

후 JS fuzzy scan이라면
1,000개 이상에서
뒤쪽 row가 영구적으로 검색되지 않을 수 있음.

그 경우 반드시 수정안 제시.

Production에 데이터 대량 등록 전에 해결.

19. LIMIT 500 검증
━━━━━━━━━━━━━━━━━━━━━━

현재 보고된:

Full table scan behavior = LIMIT 500 bounded

를 실제 검증.

질문:

1. 정확히 어떤 WHERE/ORDER BY 뒤에 LIMIT 500인가?
2. exact match는 전체 DB index/query로 검색하는가?
3. fuzzy match 후보만 500개인가?
4. 500개보다 많은 utterance에서 특정 intent가 후보에서 누락될 수 있는가?

필수:

UTTERANCE_COUNT > 500에서도
모든 active intent가 검색 가능해야 함.

만약 불가능:

P0 blocker.
