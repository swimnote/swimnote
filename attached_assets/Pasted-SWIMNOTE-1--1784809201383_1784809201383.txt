SWIMNOTE 댓글·좋아요·감사합니다 기능 실제 미연동 수정

현재 완료 보고와 실제 앱 동작이 일치하지 않습니다.

실제 앱 테스트 결과:

1. 학부모 일지에 여전히 “쪽지달기”가 표시됨
2. 댓글 화면이 기존 쪽지 화면처럼 보임
3. 키보드를 열면 입력창이 가려짐
4. 좋아요를 눌러도 선택 상태가 표시되지 않음
5. 감사합니다 버튼은 동작하지 않음
6. 좋아요가 선생님 일지에 반영되지 않음
7. 선생님 화면에 좋아요·감사합니다·댓글 수가 표시되지 않음
8. 선생님이 댓글을 읽거나 답글을 작성할 UI가 없음

파일 생성이나 API 등록만으로 완료 처리하지 마세요.
실제 production 앱에서 학부모 → 서버 → 선생님까지 연결되는 것을 검증하세요.

==================================================
1. 실제 production 화면 파일 확인
==================================================

먼저 현재 production OTA에서 실제로 렌더링되는 파일을 확인하세요.

화면에 여전히 “쪽지달기”가 보이므로,
보고서에 수정했다고 적은 `(parent)/diary.tsx`가 실제 사용 화면이 아닐 가능성이 큽니다.

다음을 전체 검색하세요.

- "쪽지달기"
- "선생님께 쪽지"
- "messages"
- "diary-comments"
- "좋아요"
- "감사합니다"

같은 기능의 중복 화면과 컴포넌트를 모두 찾으세요.

각 항목에 대해 보고:

- 실제 route
- 실제 렌더링 파일
- 실제 버튼 컴포넌트
- 실제 onPress 함수
- production OTA bundle에 포함된 파일

“쪽지달기” 텍스트가 남아 있는 정확한 파일을 찾아 제거하세요.

2. 학부모 일지 반응 버튼 실제 연결
==================================================

학부모 일지 하단을 다음으로 변경합니다.

[👍 좋아요] [🙏 감사합니다] [💬 댓글]

각 버튼은 실제 API와 연결되어야 합니다.

필요한 상태:

myLike: boolean
myThanks: boolean
likeCount: number
thankCount: number

현재 `GET /diaries/:id/reactions/summary`가
전체 집계만 반환한다면 학부모 본인 반응 상태를 알 수 없습니다.

다음 중 하나로 수정하세요.

GET /api/diaries/:id/reactions

응답 예:

{
  "counts": {
    "like": 3,
    "thanks": 2
  },
  "myReactions": {
    "like": true,
    "thanks": false
  }
}

studentId를 기준으로 권한과 반응 상태를 판별하세요.

==================================================
3. 좋아요·감사합니다 토글 API
==================================================

두 반응은 독립적으로 동작해야 합니다.

좋아요 클릭:
- 미선택이면 추가
- 선택이면 취소

감사합니다 클릭:
- 미선택이면 추가
- 선택이면 취소

예:

POST /api/diaries/:id/reactions

{
  "studentId": "...",
  "reactionType": "like"
}

{
  "studentId": "...",
  "reactionType": "thanks"
}

응답:

{
  "active": true,
  "counts": {
    "like": 3,
    "thanks": 2
  }
}

반응 타입 이름을 전체 코드에서 통일하세요.

확인 대상:

- like
- thank
- thanks
- gratitude

현재 `thank_count`와 프론트의 reactionType 이름이 달라
감사합니다가 동작하지 않는지 확인하세요.

4. 반응 버튼 선택 상태 표시
==================================================

학부모가 반응을 눌렀는지 반드시 화면에서 알 수 있어야 합니다.

미선택:
- 기본 배경
- 기본 테두리

선택:
- 민트 배경 또는 강조 배경
- 진한 아이콘 및 텍스트
- “좋아요 완료”, “감사합니다 완료” 또는 명확한 선택 표시

좋아요와 감사합니다 모두 같은 규칙을 사용하세요.

앱 재실행 후 서버의 myReactions를 조회해 상태를 복원하세요.

Optimistic update를 사용하되 실패 시 롤백하고 오류를 표시하세요.

5. 감사합니다 버튼 미동작 원인 추적
==================================================

감사합니다 버튼이 눌리지 않는 원인을 실제 로그로 확인하세요.

점검:

- onPress가 존재하는지
- disabled 조건이 잘못됐는지
- 부모 View가 터치를 가리는지
- Pressable 위에 투명 overlay가 있는지
- reactionType이 서버 enum과 다른지
- diaryId 누락
- studentId 누락
- token 누락
- endpoint URL 불일치
- 오류를 catch에서 숨기는지

클릭 로그:

[PARENT REACTION PRESS]
diaryId=
studentId=
reactionType=

API 로그:

[DIARY REACTION REQUEST]
parentUserId=
diaryId=
studentId=
reactionType=

결과 로그:

[DIARY REACTION RESULT]
active=
likeCount=
thankCount=
error=

6. 댓글 화면을 기존 쪽지 구조에서 분리
==================================================

화면 제목만 “댓글”로 바꾸고 기존 쪽지 UI를 재사용한 상태로 보입니다.

댓글 화면은 반드시 해당 일지와 연결된 화면이어야 합니다.

상단:

댓글
학생명 · 날짜
해당 수업일지 정보

본문:

- 본인의 댓글 스레드
- 선생님 답글

하단:

- 댓글 입력창
- 전송 버튼

기존 쪽지함, 대화 상대, 일반 메시지 개념은 제거하세요.

diaryId와 studentId가 없는 경우 댓글 화면 진입을 허용하지 마세요.

7. 키보드 입력창 가림 수정
==================================================

현재 실제 iPhone에서 키보드가 입력창을 완전히 덮습니다.

단순히 KeyboardAwareScrollView를 넣었다고 완료 처리하지 마세요.

다음 구조로 정리하세요.

최상위:
KeyboardAvoidingView style={{ flex: 1 }}

iOS:
behavior="padding"

Android:
behavior="height"

내부:
- 고정 헤더
- 댓글 목록 flex: 1
- 입력 footer

입력 footer는 ScrollView의 content 안쪽 끝이 아니라
화면 하단의 별도 영역으로 두고 키보드와 함께 올라오게 하세요.

입력 footer:

paddingBottom: Math.max(insets.bottom, 8)

확인:

- 키보드 열림
- 입력창 전체 노출
- 전송 버튼 노출
- 입력 텍스트 노출
- 홈 인디케이터에 가리지 않음
- 긴 텍스트 입력 가능

실제 iPhone 스크린샷으로 검증하세요.

9. 선생님 일지 목록 실제 연결
==================================================

보고서에는 DiaryHistoryList.tsx에 필드를 추가했다고 하지만
실제 선생님 지난 일지 카드에는 집계가 보이지 않습니다.

다음을 확인하세요.

1. 실제 화면이 DiaryHistoryList.tsx를 사용하는지
2. API 응답에 값이 실제 존재하는지
3. 필드 이름이 일치하는지

서버:

like_count
thank_count
comment_count

프론트:

like_count
thank_count
comment_count

또는 camelCase mapper를 사용할 경우:

likeCount
thankCount
commentCount

혼용하지 마세요.

실제 일지 카드 하단에 항상 표시:

👍 0 · 🙏 0 · 💬 0

값이 0일 때도 초기 검증 단계에서는 숨기지 마세요.
그래야 연결 여부를 확인할 수 있습니다.

10. 선생님 일지 상세 화면 구축
==================================================

선생님이 자신이 작성한 일지를 열면
본문과 사진 아래에 다음을 표시하세요.

👍 좋아요 3
🙏 감사합니다 2
💬 댓글 4

반응 상세:

- 학생명
- 보호자 표시

예:

좋아요
- 서태웅 보호자
- 김민준 보호자

댓글:

서태웅 보호자
“오늘 사진 감사합니다.”

↳ 서경민 선생님
“오늘 아주 잘했습니다.”

선생님은 각 학부모 댓글 스레드에 답글을 작성할 수 있어야 합니다.

현재 선생님 화면에 이 UI가 없다면
작업이 완료된 것이 아닙니다.

11. 댓글 권한 분리
==================================================

같은 일지에 여러 학부모가 댓글을 남기는 경우:

학부모 A:
- A의 댓글만 조회
- A 댓글의 선생님 답글만 조회

학부모 B:
- B의 댓글만 조회
- B 댓글의 선생님 답글만 조회

선생님:
- 해당 일지의 모든 학부모 댓글 조회

이 권한은 서버에서 강제하세요.

학부모가 다른 사람의 commentId를 직접 요청하면
403 또는 404를 반환하세요.

12. diary_messages 재사용 구조 점검
==================================================

현재 기존 `diary_messages` 테이블에
parent_comment_id와 student_id만 추가했다고 보고했습니다.

다음을 확인하세요.

- 기존 쪽지 데이터와 댓글 데이터가 어떻게 구분되는지
- message_type 컬럼이 있는지
- 기존 쪽지가 댓글 API에 섞이지 않는지
- receiver/sender 구조가 댓글 스레드와 충돌하지 않는지

구분 필드가 없다면 추가하세요.

예:

message_type:
- legacy_message
- diary_comment

댓글 API는 diary_comment만 조회해야 합니다.
