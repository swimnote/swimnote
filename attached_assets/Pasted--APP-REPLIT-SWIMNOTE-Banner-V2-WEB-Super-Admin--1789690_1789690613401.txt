- 글자색

→ 진한 글자

글자색도 직접 변경 가능.

4. COLOR PICKER
━━━━━━━━━━━━━━━━━━━━━━

현재 프로젝트에 이미 안정적인
React Native color picker component/library가 있으면
재사용하십시오.

없다면 이 기능 하나 때문에
무거운 신규 dependency를 추가하지 마십시오.

그 경우:

- 기본 palette/swatches
- HEX 직접입력
- 실시간 preview

조합으로 구현하십시오.

핵심은
색상 선택 자유도이지
Photoshop 수준의 picker가 아닙니다.

━━━━━━━━━━━━━━━━━━━━━━
5. DB 구조는 최대한 유지
━━━━━━━━━━━━━━━━━━━━━━

우선 신규 DB column/table을 만들지 마십시오.

현재:

color_theme

필드가 string이면
기존 preset과 custom 값을
같이 표현할 수 있는지 먼저 검토하십시오.

권장 예:

기존:
teal

custom:
custom:#163A5F:#FFFFFF

또는 현재 API/schema convention에 맞는
안전한 string serialization.

중요:

- 기존 preset 값 정상 유지
- custom background
- custom text color

를 하나의 기존 field 안에서
안전하게 표현할 수 있으면
DB migration 하지 마십시오.

단 현재 validation/schema 때문에
이 방식이 위험하다면
임의 구현하지 말고
최소 변경안을 먼저 보고하십시오.

9. 가독성 보호
━━━━━━━━━━━━━━━━━━━━━━

사용자가 배경색과 글자색을
거의 같은 색으로 설정해도
앱이 crash하면 안 됩니다.

가능하면 preview에서
contrast가 너무 낮을 경우:

“글자가 잘 보이지 않을 수 있습니다.”

정도의 작은 경고만 표시.

강제로 색을 바꾸지는 마십시오.

사용자 선택 자유도 우선.
