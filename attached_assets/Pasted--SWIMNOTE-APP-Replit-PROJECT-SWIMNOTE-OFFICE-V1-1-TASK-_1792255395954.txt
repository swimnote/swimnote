2. 한 작업에서 마무리할 PC 이식

A. 영상
- 앱의 기존 영상 API·저장 계약 재사용.
- PC 파일 선택→필요한 기존 제한 확인→전송→첨부→재조회 연결.
- 앱의 압축 방식을 무조건 PC에 복제하지 않음.
- 서버가 원본 전송을 지원하면 기존 제한 안에서 우선 재사용.
- 새 변환 엔진·대형 native 의존성은 필요 근거 없이 추가하지 않음.
- 사진/영상의 성공·실패를 구분하고 일부 실패를 전체 완료로 표시하지 않음.
- 모바일 전용 경로가 막히면 필요한 최소 서버 변경만 별도 정리.

B. 강사 일지
- 기존 권한에 맞는 삭제 UI 연결.
- 삭제 대상 명시·사용자 확인 유지.
- 발행이력의 구분·필터 연결.
- 현재 담당 범위와 기존 서버 정책 유지.

C. 기존 이식 누락
docs/office/app-migration-status.md의 잔여 항목을 기준으로
센터 관리자·선생님의 기존 앱 업무 중 빠진 연결만 마무리.
이미 완료한 영역은 다시 조사하지 않음.

super_admin 전용 커리큘럼 최종 승인,
학부모 본인의 OTP 입력 등은 센터 권한에 임의 개방하지 않음.
정책상 제외와 구현 누락을 구분.

3. AI 업무 연결

새 범용 AI 엔진을 만들지 않는다.
기존 Action 등록 구조로 가능한 업무부터 연결한다.

- 화면 열기만 지원하는 것과 실제 업무 실행을 구분.
- 파일 전송은 사용자가 선택한 파일을 기준으로 처리.
- 모호한 대상·값은 확인하고 추측 저장 금지.
- 삭제·권한변경·발송 등 기존 확인 절차 유지.
- 미지원 자연어 실행은 미지원으로 표시.

AI 전체 일반화가 영상·일지 등 PC 이식을 막지 않게 한다.
남은 AI 실행 연결은 같은 목록에서 추적한다.

4. 관리자 보강 처리

현재 pool_admin 경로·권한 불일치를
기존 앱의 보강 업무와 서버 정책 기준으로 좁게 정리한다.

- 필요한 endpoint·역할·Pool/학생 범위.
- 기존 teacher/super_admin 동작에 미치는 영향.
- 최소 수정안과 직접 관련 검사.
- 서버 적용·복구 방법.

로컬 수정안과 검토 가능한 적용안까지 준비한다.
운영 적용은 기존 명시 승인 범위에서만 수행.
역할 위장·권한 검사 제거 금지.

이 항목의 승인 대기로 다른 PC 이식을 멈추지 않는다.

5. 최소 검사

필수 제품 빌드와 변경 부분의 직접 관련 검사만 수행.
기존 전체 suite·monorepo 타입검사 반복 금지.

기존 프런트엔드 오류 73건 전체를 고치는 작업으로 확대하지 않음.
이번 변경에서 새로 생기거나 실제 업무를 막는 오류는 수정.

업로드·삭제 등은 transport fixture 등 기존 방법으로 제한 확인.
운영 파일 업로드·실삭제·실발송·유료 AI 호출은
승인된 대상·범위 없이 실행하지 않음.

Windows 직접 실행하지 않았다면 NOT RUN으로 명시.
이 때문에 구현·패키징을 중단하지 않음.

6. 설치본 전달

영상·강사 일지·기타 잔여 이식을 모아 통합본 1회 전달.
각 항목마다 설치본·사용자 확인을 요구하지 않음.
실행 차단 또는 데이터·권한 관련 중대한 결함만
필요할 때 중간 수정본 전달.

사용자는 다운로드→설치→실행만 수행.
개발 도구·로컬 DB·소스 빌드·터미널 작업 요구 금지.

7. 범위·승인

이번에는 레거시 신규 CRM·Billing 개발로 범위를 넓히지 않음.
해당 기능은 다음 개발 묶음으로 유지.

모바일·AI ENGINE 불필요한 변경 금지.

기존 승인 경계 유지.
commit/push도 명시된 기존 승인 범위에서만 수행.
