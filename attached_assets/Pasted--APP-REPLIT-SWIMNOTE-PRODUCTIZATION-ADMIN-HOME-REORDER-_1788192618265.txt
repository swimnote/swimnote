반드시 포함:

- SWIMNOTE X 영역
- AI 학생리포트
- AI 일지피드
- AI 커리큘럼
- SWIMNOTE X 관리
- 이번 달 매출
- 전체 회원
- 보강 상태
- 인원관리

2. 현재 첫 화면 노출 범위 분석
==================================================

첨부된 실제 관리자 화면 기준으로
스크롤 없이 첫 화면에 보이는 영역과
스크롤해야 보이는 영역을 구분한다.

특히 다음을 확인:

- 회원등록이 몇 번째 위치인지
- 스케줄러가 몇 번째 위치인지
- 처리 필요가 몇 번째 위치인지
- 보강 상태가 몇 번째 위치인지
- 통합 사용량이 몇 번째 위치인지
- SWIMNOTE X 영역이 차지하는 세로 높이
- 첫 화면에서 실제 업무 버튼이 몇 개 보이는지

가능하면 현재 화면 기준
대략적인 viewport 내 노출 순서를 제시한다.

==================================================
3. 사용빈도 기준 분류
==================================================

기능을 새로 만들지 말고
현재 존재하는 항목만 아래 기준으로 분류한다.

A. HIGH FREQUENCY
관리자가 실제 운영 중 자주 누를 가능성이 높은 기능

예:
- 회원등록
- 스케줄러
- 보강 처리
- 인원관리
- 처리 필요

B. MEDIUM FREQUENCY
주기적으로 확인하지만
앱 실행 직후 매번 볼 필요는 없는 기능

예:
- 전체 회원
- 매출 확인
- 휴무일
- X 관리

C. LOW FREQUENCY / STATUS
주로 상태 확인용이며
홈 상단 우선순위가 낮은 기능

예:
- 통합 사용량
- 데이터 사용량
- 영상 사용량

실제 코드와 운영 목적을 보고
각 항목을 분류하고 근거를 제출한다.

4. 재배치 설계 원칙
==================================================

이번 변경의 핵심 원칙:

"앱을 켜자마자 일을 시작할 수 있어야 한다."

따라서:

- 사용빈도 높은 기능은 위로
- 상태 조회 성격은 아래로
- 현재 기능 자체는 그대로 유지
- 현재 디자인 그대로 유지
- 카드 크기 그대로 유지
- 색상 그대로 유지
- 버튼 개수 그대로 유지

즉:
UI redesign이 아니라
render order 재배치만 설계한다.

5. 1차 권장 순서 검토
==================================================

아래는 현재 제품회의에서 제안된 후보 순서다.

이 순서를 무조건 적용하지 말고
실제 코드 구조상 안전하게 가능한지 검토한다.

후보:

1. 상단 헤더
2. 빠른 실행
   - 회원등록
   - 매출 확인
   - 스케줄러
   - 휴무일
3. 처리 필요
   - 보강 미처리
   - 수업 미배정
   - 학부모 미연결
4. 보강 상태 / 인원관리
5. SWIMNOTE X 영역
   - AI 학생리포트
   - AI 일지피드
   - AI 커리큘럼
   - SWIMNOTE X 관리
6. 이번 달 매출 / 전체 회원
7. 통합 사용량

검토할 것:

- 이 순서가 현재 JSX/component 구조에서
  단순 reorder만으로 가능한지
- dependency 문제 없는지
- layout 깨짐 가능성
- conditional rendering 순서 문제
- X mode / Normal mode 차이
- scroll height 영향
- first viewport 노출 개선 정도

7. 최종 추천안
==================================================

Replit이 실제 코드 기준으로
가장 안전하고 효과적인 배치안을 하나 추천한다.

최종안에는 반드시:

- 위→아래 전체 순서
- 각 섹션 이름
- 현재 위치 → 변경 위치
- 변경 이유
- 코드 수정 파일 예상
- 단순 reorder인지
- regression risk
- Normal/X 차이

를 적는다.
