사전 조사 보고서는 확인했습니다.

아직 코드 수정이나 Publish는 하지 마세요.

현재 보고서에는 요청한 최종 방향과 다른 부분 및 구현상 문제가 있으므로 아래 내용을 반영해 수정 보고서를 다시 제출하세요.

[1. 학부모 홈 최종 순서 수정]

최종 화면 순서는 반드시 다음과 같습니다.

1. 슬림 헤더
2. 자녀 선택 + 추가
3. 슬림 자녀 정보
4. 얇은 고정 배너
5. 두꺼운 좌우 스크롤 배너
6. 사진 업데이트
7. 수업일지 피드

두꺼운 배너를 수업일지 아래로 배치하지 마세요.

배너는 수영장별 홍보, 장기 안내, 이벤트 및 중요 소식을 반복 노출하는 영역이므로 사진과 일지보다 위쪽에 있어야 합니다.

[2. 공지사항·현재 레벨 큰 카드 제거]

공지사항 카드와 현재 레벨 카드를 홈 하단에 유지하지 마세요.

- 공지사항은 헤더의 작은 Lucide 아이콘으로 이동
- 현재 레벨은 헤더 또는 슬림 자녀 정보 영역의 작은 상태 버튼으로 이동
- 기존 상세 화면, 라우팅, 데이터 연결은 유지
- 큰 기능 카드는 제거

이번 개편의 핵심은 큰 버튼과 기능 카드가 아니라 사진과 수업일지가 중심이 되는 것입니다.

[3. 컬러 이모지 전면 금지]

와이어프레임에도 컬러 이모지를 사용하지 마세요.

🔔, ⚙️, 📅, ⏰, 📣 등의 운영체제 이모지를 전부 Lucide 선형 아이콘 이름으로 표시하세요.

예:
- Bell
- Settings
- CalendarDays
- Clock
- Megaphone

학부모, 선생님, 관리자, 슈퍼관리자를 포함한 모든 모드에 동일한 아이콘 시스템을 적용합니다.

또한 branding.tsx의 수영장 로고 이모지 선택 기능도 단순 예외 처리하지 말고 아래 대안을 검토하세요.

- Lucide 아이콘 선택
- 로고 이미지 업로드
- 텍스트 이니셜
- 기존 이모지는 호환용으로만 유지하고 신규 선택 중단

현재 코드, 초기 데이터, seed, DB 값, 메뉴 배열, 빈 상태 문구에 포함된 컬러 이모지도 전부 조사하세요.

[4. Soft Snap 구현 방식 수정]

수업일지는 글자 수와 사진 수에 따라 카드 높이가 달라집니다.

따라서 아래 방식은 사용하지 마세요.

- pagingEnabled
- 고정 DIARY_CARD_H
- 고정 snapToInterval
- 모든 일지에 동일 높이를 강제하는 방식

각 일지의 실제 시작 위치를 onLayout으로 측정하여 offset 배열을 관리하세요.

스크롤이 종료되었을 때 가장 가까운 일지 시작점까지의 거리를 계산하고, 설정된 임계 거리 이내인 경우에만 부드럽게 scrollToOffset 하세요.

임계 거리 밖이면 사용자가 멈춘 위치를 그대로 유지해야 합니다.

목표:
- 자유 스크롤 유지
- 관성 유지
- 일지 경계 근처에서만 부드러운 정렬
- 강제 페이지 이동 금지
- 뒤로 튀는 현상 금지

decelerationRate="fast"는 무조건 적용하지 말고 기본값과 실제 기기 비교 후 제안하세요.

[5. 자녀 HeroCard 축소]

현재 HeroCard는 이름, 레벨, 반, 출석, 오늘 수업을 포함하여 상단을 과도하게 차지할 수 있습니다.

큰 HeroCard가 아니라 슬림 정보 행 또는 낮은 요약 패널로 재설계하세요.

예:

홍길동 · 브론즈 1
자유형반 · 화목 17:00        이번 달 8/12

오늘 수업이 있을 때만 작은 상태 라벨을 노출하세요.

자녀 선택 탭과 정보가 중복되지 않도록 설계하세요.

[6. 배너 글자 제한 적용 위치 수정]

maxLength 및 글자 수 카운터는 학부모 표시 컴포넌트가 아니라 실제 관리자 배너 생성·수정 TextInput에 적용해야 합니다.

조사 및 수정 대상:
- 관리자 얇은 배너 생성 화면
- 관리자 얇은 배너 수정 화면
- 관리자 두꺼운 배너 생성 화면
- 관리자 두꺼운 배너 수정 화면
- 생성 API
- 수정 API

학부모 표시 컴포넌트에는 표시 높이, 최대 줄 수, 기존 초과 데이터에 대한 안전 처리만 적용하세요.

[7. 배너 입력 규칙]

얇은 배너:
- 공백과 문장부호 포함 최대 15자
- 줄바꿈 입력 금지
- 한 줄 고정
- 실시간 글자 수 표시

두꺼운 배너:
- 공백과 문장부호 포함 최대 30자
- 최대 두 줄
- 직접 줄바꿈은 최대 1회 허용 여부를 검토
- 줄바꿈이 없어도 화면에서 최대 두 줄 자동 배치
- 실시간 글자 수 표시

클라이언트와 서버에서 동일한 기준으로 검증하세요.

[8. 기존 초과 배너 처리]

기존 15자 또는 30자 초과 데이터는 자동 삭제하거나 자동 잘라내지 마세요.

- 기존 배너는 현재 표시 유지
- 수정 화면에서 제한 초과 안내
- 다시 저장할 때 신규 제한 적용
- 초과 데이터 목록과 개수를 보고
