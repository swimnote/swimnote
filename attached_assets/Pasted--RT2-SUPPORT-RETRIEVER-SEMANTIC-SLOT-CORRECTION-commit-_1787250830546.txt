==================================================
2. ACTION OPPOSITION
==================================================

반대 행동은 강한 penalty.

예:

ENABLE ↔ DISABLE
CREATE ↔ DELETE
REGISTER ↔ REMOVE

query action과 KI action이
명확히 반대면:

- DB_DIRECT 금지
- top candidate 우선순위 크게 하락

예:

"알림 끄기"
vs
"알림 다시 켜기"

→ 동일 notification concept여도
반대 행동이므로 top-1 금지.

==================================================
3. OBJECT MATCH
==================================================

query object와 KI object가
명확히 다르면 penalty.

예:

MATERIAL_SUBMISSION
vs
APP_INSTALL

→ HOW_TO intent가 같아도
다른 문제.

Q6:

"자료 제출"
→ MATERIAL_SUBMISSION

"다른 앱 설치"
→ APP_INSTALL

따라서 app-install KI가
자료 제출 질문 top-1이 되면 안 됨.

==================================================
4. GENERIC SETTINGS 처리
==================================================

"푸시 알림 설정"
처럼 action/오류 표현이 없는 일반 설정 질문은:

concept=NOTIFICATION_SETTINGS
intent=DESCRIPTION/HOW_TO 또는 neutral
object=NOTIFICATION

으로 취급.

ERROR_TROUBLESHOOT KI는
query에:

- 안와
- 오류
- 안돼
- 작동 안함
- 실패

등이 없으면 penalty.

즉 Q4에서
"알림이 오지 않는 경우 해결"
KI top-1 금지.

==================================================
6. RANKING 우선순위
==================================================

최종 ranking에서 relevance 우선순위:

1. concept
2. object
3. action
4. intent
5. title/question lexical overlap
6. content overlap
7. usage_count

usage_count는 여전히 tiebreak only.

7. MULTI-EVIDENCE
==================================================
