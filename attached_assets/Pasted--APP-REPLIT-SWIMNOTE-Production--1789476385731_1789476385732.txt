A. MEDIA ORDER 조사
━━━━━━━━━━━━━━━━━━━━━━

현재 문제:

사진/영상을 여러 개 한 번에 선택하면
사용자가 선택한 순서와 다르게 뒤죽박죽 표시됩니다.

최종 요구:

picker에서 선택한 순서
=
저장 순서
=
재조회 순서
=
표시 순서

이어야 합니다.

사진과 현재 지원되는 영상 모두 동일합니다.

실제 전체 파이프라인을 조사하십시오.

1. 어떤 picker/library를 사용하는지
2. picker assets 배열이 선택 순서를 보존하는지
3. 선택 직후 local state 구조
4. upload 함수/helper
5. 병렬 업로드 여부
6. Promise.all / callback / 완료순 append 여부
7. API request payload 구조
8. DB 저장 구조
9. media table 또는 JSON array 여부
10. sort_order / position / sequence 등의 기존 필드 존재 여부
11. 조회 API의 ORDER BY
12. APP render 시 별도 sort 여부

Root Cause를 정확히 특정하십시오.

특히:

“업로드가 먼저 끝난 파일부터 state/DB에 들어가서
선택순서가 사라지는지”

확인하십시오.

조사 범위:

- Diary 사진
- Diary 영상
- 사진/영상 관련 공통 uploader

현재 동일 helper를 공유하는지 확인하십시오.

보고할 것:

- 순서가 최초로 깨지는 정확한 단계
- APP만 수정하면 되는지
- API 수정 필요한지
- DB 수정 필요한지
- 기존 ordering 필드 재사용 가능 여부
- 병렬 업로드를 유지하면서 해결 가능한지
- 예상 수정 파일

DB migration은 필요성을 확인만 하고 실행하지 마십시오.

B. 학생 개별일지 MEDIA-ONLY 조사
━━━━━━━━━━━━━━━━━━━━━━

현재 문제:

공통/전체 일지는 작성되어 있어도
학생 개별일지에 사진을 넣으려면

개별 text에 "." 등
최소 한 글자를 입력해야 합니다.

최종 요구:

공통일지 내용 존재
+
학생 개별 text = 빈값
+
해당 학생 사진 >= 1

이면 정상 저장 가능.

가짜 "." 문자는 필요 없어야 합니다.

실제 저장 flow를 조사하십시오.

확인:

1. 학생별 note 생성 조건
2. content.trim() 검증 위치
3. Save 버튼 활성화 조건
4. API validation
5. DB content nullable / NOT NULL 여부
6. student note ID가 media upload 전에 필요한지
7. media가 어느 record에 연결되는지
8. 사진 저장 후 student note 생성 흐름
9. 현재 영상도 학생별 첨부를 지원하는지
10. Parent/Teacher feed가 빈 student text를 어떻게 렌더하는지

특히:

개별 row 저장 조건이 현재

text.length > 0

로 되어 있는지,

아니면 다른 validation 때문에
빈 text + media가 차단되는지

정확히 확인하십시오.

목표 데이터 정책:

- text 있음 → 저장
- media 있음 → 저장
- text + media 둘 다 없음 → 빈 student row 생성 안 함

공통일지가 없는 완전 빈 Diary를
이번 요구 때문에 허용하라는 뜻은 아닙니다.

보고할 것:

- "."가 필요했던 실제 Root Cause
- APP validation 문제인지
- API 문제인지
- DB constraint 문제인지
- media-only student note를 현재 schema에서 지원 가능한지
- 가짜 text 없이 저장 가능한 최소 변경
- 예상 수정 파일
- migration 필요 여부

AI ENGINE은 조사 대상이 아닙니다.
