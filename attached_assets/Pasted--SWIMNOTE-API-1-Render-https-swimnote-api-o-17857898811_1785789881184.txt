[SWIMNOTE 운영 API 불일치 — 실제 프로덕션 서버 추적 및 배포 지시]

현재 확인된 상태:

1. Render 신규 서버
   https://swimnote-api.onrender.com
   → 커밋 088a6fa1 적용 완료
   → 검색어 없는 요청은 빈 배열
   → 전방일치 검색 정상
   → phone 미노출

2. 현재 운영 앱 API
   https://swimnote.kr/api
   → 구버전 동작
   → 검색어 없이 전체 수영장 반환
   → 포함 검색
   → phone 반환

3. 앱 API_BASE
   https://swimnote.kr/api

따라서 Render 배포만으로 현재 운영 앱 서버는 변경되지 않았다.

중요:
Google Frontend 헤더만 보고 별도 Google Cloud 서버라고 확정하지 않는다.
DNS 변경도 아직 금지한다.

이번 단계의 목적은 swimnote.kr/api의 실제 배포 원본을 찾아
동일 커밋 088a6fa1을 현재 운영 서버에 안전하게 배포하는 것이다.

STEP 2. 운영 서버 판정
━━━━━━━━━━━━━━━━━━━━━━

다음 중 하나로 명확히 판정한다.

A. Replit Production Deployment
B. Render 서비스
C. Google Cloud 직접 배포
D. 다른 프록시·호스팅
E. 판정 불가

A라면:
현재 Replit Production Deployment에 커밋 088a6fa1을 배포한다.

B라면:
Render Custom Domain 연결 상태와 DNS가 불일치한 원인을 보고한다.

C라면:
실제 Google Cloud 서비스명·프로젝트·리전·배포 방식을 확인하고
동일 코드 배포 계획만 제출한다.

D/E라면:
임의 변경하지 말고 확인된 연결 체인을 보고한다.

- 서버 로그 확인

STEP 4. swimnote.kr 직접 검증
━━━━━━━━━━━━━━━━━━━━━━

반드시 Render URL이 아니라 아래 운영 도메인으로 검증한다.

https://swimnote.kr/api/...

필수 결과:

1. query 없음
   → 전체 목록 금지
   → 빈 결과

2. 공백 query
   → 빈 결과

3. name=스윔
   → 이름이 스윔으로 시작하는 수영장만 반환

4. 토이키즈가 중간 포함만 되는 경우
   → 제외

5. phone
   → 응답 필드에 없어야 함

6. 비활성·삭제 수영장
   → 제외

7. 최대 결과 수
   → 설정된 LIMIT 적용

응답 body와 HTTP status를 제출한다.

━━━━━━━━━━━━━━━━━━━━━━
STEP 5. 서버 정상 후 앱 OTA
━━━━━━━━━━━━━━━━━━━━━━

swimnote.kr 운영 API가 새 정책으로 동작하는 것이 확인된 경우에만
학부모 회원가입 클라이언트 OTA를 진행한다.

실기기 확인:

- 최초 진입 시 수영장 목록 없음
- 한 글자 입력 후 결과 표시
- 글자를 추가할수록 결과 축소
- 빠른 입력 시 이전 응답이 덮어쓰지 않음
- 검색 결과를 선택해야 가입 가능
- 검색어 수정 시 기존 선택 해제
- 전화번호 등 불필요 정보 미노출

━━━━━━━━━━━━━━━━━━━━━━
STEP 6. DNS 변경 금지 원칙
━━━━━━━━━━━━━━━━━━━━━━

swimnote.kr을 바로 swimnote-api.onrender.com으로 변경하지 않는다.

DNS 변경 전 반드시 확인해야 할 항목:

- swimnote.kr이 웹 프론트도 함께 제공하는지
- /api 외의 웹 경로 영향
- SSL 인증서
- 쿠키 도메인
- OAuth redirect URI
- Apple·Kakao 로그인 callback
- 업로드 URL
- RevenueCat webhook
- 기존 학부모·선생님 앱 API
- CORS
- WebSocket
- R2 파일 URL
- health check

단순히 API 수정 하나를 반영하기 위해 루트 도메인의 DNS를 바꾸면
전체 서비스 장애가 발생할 수 있다.
