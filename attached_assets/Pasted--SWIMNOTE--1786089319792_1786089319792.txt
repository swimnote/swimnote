1. 사실 수준 표기

모든 보고는 아래 세 단계로 구분:

CONFIRMED
= 코드/DB/HTTP/log/실기기 직접 증거

INFERRED
= 확인된 코드 흐름에 따른 추론

UNKNOWN
= 현재 증거 없음

UNKNOWN을 CONFIRMED로 올리지 않는다.

현재 알려진 상태:

DB COUNT = 3건 CONFIRMED

Server Query Result = 3건 CONFIRMED

Server res.json 직전 = 3건 INFERRED

HTTP JSON = UNKNOWN

App received JSON = UNKNOWN

waitingList state = UNKNOWN

Rendered IDs = UNKNOWN

Device visible cards = 일부만 확인

따라서 최초 UNKNOWN은 HTTP JSON이다.

14. Pull-to-refresh 헌법
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Pull-to-refresh는 반드시:

사용자 refresh
→ 해당 endpoint cache 무효화/bypass
→ 실제 network fetch
→ 최신 response
→ state 갱신

이어야 한다.

현재 구조가 cache HIT로 과거 데이터를 그대로 반환한다면
UX 문제로 기록.

하지만 공용 cache를 바로 수정하지 않는다.

보강 endpoint 한정 최소 복구안을 우선 검토한다.
