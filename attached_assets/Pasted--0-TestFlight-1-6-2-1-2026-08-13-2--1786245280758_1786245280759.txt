--------------------------------------------------
4. 특히 확인할 조건
--------------------------------------------------

다음을 전부 확인:

1. diary가 classGroup.students를 직접 사용하는지
2. 별도 API로 학생을 다시 조회하는지
3. attendance가 있는 학생만 필터하는지
4. 날짜 비교에서 timezone 문제가 있는지
5. schedule ID와 classGroup ID를 혼동하는지
6. recurring class의 원본 ID / instance ID를 혼동하는지
7. teacher/pool_admin role에 따라 학생 API 응답이 달라지는지
8. student status(active/inactive) filter가 있는지
9. attendance 데이터 로딩 전에 students=[]를 확정하는지
10. 비동기 race/loading 문제인지
11. 이전에 발견된 사진 로딩 지연처럼 API 응답 전 empty state가 먼저 보이는 것인지
12. 화면을 오래 기다렸을 때 학생이 뒤늦게 나타나는 구조인지
