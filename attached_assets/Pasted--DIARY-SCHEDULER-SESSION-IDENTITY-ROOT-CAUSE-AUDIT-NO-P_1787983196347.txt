4. CHECK RENDER PRODUCTION VERSION
==================================================

중요.

최근 서버 코드에는:

GET /diaries/unwritten-slots

및
includeWritten=true

변경이 있었음.

현재 production Render
swimnote-api가
정말 그 코드를 실행 중인지 확인.

확인:

- deployed commit SHA
- current branch
- endpoint existence
- includeWritten=true support
- response contract

만약 앱 OTA는 최신인데
Render가 이전 SHA라면
두 selector가 동시에 실패할 수 있음.

이 경우:

FRONTEND BUG로 오판하지 말 것.

6. INVESTIGATE NAV PARAM REUSE / STALE SCREEN
==================================================

특히 확인:

- Expo Router가 diary screen을 reuse하는지
- same classGroupId로 다른 lessonDate 진입할 때
  effect가 재실행되는지
- lastNavKeyRef가
  classGroupId + editDiaryId만 보고
  lessonDate 변경을 무시하는지
- params.lessonDate가 바뀌어도
  targetDate가 stale state로 남는지

중요:

이전에 보고된:

lastNavKeyRef = classGroupId|editDiaryId

구조라면
같은 반의 8/13 → 8/27 이동에서
lessonDate가 key에 없어서
navigation change를 무시할 가능성을
반드시 확인.

이건 매우 중요.
