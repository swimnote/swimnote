STATUS = 기존 검수안 수정. 구현 착수 지시 아님.

[1. 제품 역할 정정]

스윔노트 오피스는 관리자 모드 + 수영장 운영 전산이다.
선생님 앱의 모든 화면·업무를 PC에 그대로 복제하는 제품이 아니다.

기존의 “앱 기능 100% 이식”은
관리자에게 필요한 앱 기능을 PC에서 빠짐없이 사용할 수 있게 한다는
기준으로 수정한다.

선생님 앱은 수업 현장의 기록 작성,
PC는 센터 운영·관리·검수·발급·수납·현황 파악에 집중한다.

기존 앱·API·데이터·권한·업무 규칙은 재사용한다.
사용 편의 → 업무 완결성 → 디자인의 우선순위를 유지한다.

[2. 사진·일지 관련 기존 검수안 정정]

사용자가 확인한 사실:
- 선생님 앱에서는 일지 작성 중 사진 업로드가 이미 가능하다.
- PC 오피스에는 일지 작성 기능이 필요하지 않다.

따라서 다음 제안을 작업 목록에서 제외한다:
- PC 일지 작성 화면의 신규 개발·확장
- PC 일지 작성 중 업로더 연결을 우선 과제로 삼는 것
- 앱의 일지 작성 기능이 부족하다는 전제

PC에 필요한 범위:
- 반·날짜·회원·작성자별 일지 조회와 검색
- 기존 사진·영상·개별 기록 열람
- 기존 정책상 관리자에게 허용된 관리 동작
- 관리자용 앨범·사진 업로드와 대상 연결

관리자 사진 업로드가 기존 앱에서 어떻게 활용되는지는
실제 API 계약을 확인하여 제안한다.
관리자 사진 등록을 일지 자동 작성·임의 발행으로 연결하지 않는다.

이미 구현된 PC 강사 화면·일지 작성 코드가 있다면
즉시 삭제하거나 크게 재작성하지 않는다.
관리자 제품에서 필요한 노출 범위와 정리안을 먼저 제시한다.
기존 앱의 강사 기능·권한은 변경하지 않는다.

[3. 성장리포트는 관리자 핵심 업무]

다음 흐름은 PC에서 완결되도록 설계한다:
목록 → 본문 상세 → 관련 기록 확인
→ 관리자 권한의 검수·허용 수정/재분석 요청
→ 승인·발급 → 발송 → 이력 재열람.

관리자 확인과 강사 검수는 실제 기존 정책에 맞게 구분한다.
검수 완료·발급 완료·발송 완료를 하나로 합치지 않는다.

이전 보고에서 확인한 다음을 우선 재사용한다:
- 발행 대기·이력의 본문 진입 누락
- 관리자 mark-reviewed와 강사 review 경로의 구분
- Native 허용 경로와 요청 메서드 불일치
- 기간·회원별 목록 탐색
- 실제 앱 보고서의 본문 렌더링 계약

새 리포트 엔진·별도 원장을 만들지 않는다.
소스 연결 확인을 실제 운영 성공으로 표현하지 않는다.

[4. 기본 요금과 AI 구분]

사용자가 제시한 앱 기본 요금은 월 9,900원이다.
이 기본 이용권을 바탕으로 PC 일반 업무를 추가 PC 이용료 없이
제공하는 방향을 반영한다.

기존 기본 이용권의 실제 회원수·저장공간·기능 제한이
현재 코드에서 어떻게 적용되는지 확인한다.
이전 검토에서 사용한 미확인 요금·제한 수치를 기준으로 삼지 않는다.

- 일반 PC 업무: 기본 이용권에 포함, 별도 PC 요금 없음
- 일상 AI 작업창: 기존 X 이용권 기준
- 무료 AI 데이터 이전: X 이용권 없이 사용 가능

회원수·저장공간의 새 제한이나 기존 앱 혜택 변경은
임의로 결정하지 말고 필요한 결정만 근거와 함께 제시한다.

외부 명칭:
- 스윔노트 오피스 / SWIMNOTE OFFICE
- 기존 X 서비스의 외부 명칭: 스윔노트 AI
- 내부 X 식별자·SKU·API·DB는 유지
- 모바일 표시명 변경은 추후 앱 빌드로 분리

[5. 전체 메뉴를 관리자 기준으로 재분류]

다음 업무 범위는 보존한다:
- 전체현황·오늘 처리할 일
- 회원·보호자·상담·체험·레벨테스트·대기·등록전환
- 일정·반·정원·강사·레인·출결·보강·휴강·대강
- 상품·수강권·할인·재등록·청구·수납·미납·환불·마감
- 일지·앨범 조회, 교육자료·레벨·성장리포트 관리
- 학부모 요청·공지·소통·직원 업무·인수인계
- 직원·권한·강사정산·운영 지출·시설·물품
- 기존 설계의 무료 배차·셔틀
- 마케팅·홍보
- 대회·업체·본사 안내·신청 등 운영지원
- 설정·가이드·Excel/CSV·필요한 PDF와 인쇄

각 기능은 다음으로 구분한다:
① 관리자 PC에 필요
② 앱에서 수행하고 PC에서는 조회·관리
③ 기존 권한상 제공 불가 또는 별도 정책 결정 필요
④ 외부 조건 때문에 해당 동작만 대기

화면이 이미 있다는 이유로 관리자 메뉴에 모두 노출하지 않는다.
반대로 교사용 기능이라는 이유로 관리자에게 필요한 조회·관리까지
함께 제거하지 않는다.

[6. 기존 보완 범위 유지]

무료 AI 데이터 이전:
- 여러 파일·시트 누적
- GPT 형태의 대화 + 미리보기
- 사용자 의견을 변환 규칙에 반영
- 중복·충돌·원본 추적·이어하기
- 미리보기와 실제 반영 구분
- 운영 시작 후 변경 덮어쓰기 방지
- 금액·잔여횟수 대조와 결과 출력
- 기존 일괄등록 재사용
- 일반 AI 이용권 우회 통로가 되지 않도록 서버 범위 제한

NFC:
- 센터 출결에만 활용
- 범용 리더·카드의 지원 규격 명시
- 카드 등록·해제·분실·재발급·기존 카드 재사용
- 기존 출결과 연결하고 보호자 푸시
- 중복·통신 실패·수동 출결 처리
- 장비 미확정 부분만 예정으로 구분
- 셔틀 NFC는 제외

마케팅:
- 당근·네이버 관리 주소와 자료 보관
- 게시 일정·담당자·게시 링크·수동 상태 기록
- 소개·공유 캠페인과 상담·등록 유입 연결
- 미연동 기능을 실제 자동 게시·성과로 표시하지 않음

[7. 개발 순서 수정]

첫 과제에서 PC 일지 작성 업로더 보완을 뺀다.

권장 순서:
1) 성장리포트 관리자 흐름·기존 관리자 연결 오류·AI 이용권 경계
2) 회원·상담·일정과 최소 상품·계약·수강권 연결
3) 청구·수기수납·환불·미납·재등록·마감 완결
4) 무료 이전·마케팅·NFC·운영지원의 준비된 부분 통합

위 순서는 엄격한 대기열이 아니다.
독립 업무는 준비된 기존 자산부터 진행하는 방안을 제안한다.

현황·Excel·필요한 출력·공통 Action·AI 연결은
각 업무 묶음에 함께 포함한다.
Smartro 등 외부 조건이 다른 업무를 막지 않도록 한다.

기존 Stage 5~8 안에서 배치하고 불필요한 새 단계를 만들지 않는다.

[8. 이번 제출물]

기존 검수안을 수정하여 다음을 제출한다:
1) 앞선 안에서 제외·수정·유지되는 항목
2) 관리자 중심 메뉴 구조와 업무 흐름
3) 현재 코드 재사용·연결 수정·신규 개발 구분
4) 관리자·강사·학부모의 역할 구분
5) 기본 9,900원 이용권과 PC 사용의 실제 제한 적용 지점
6) 큰 업무 묶음별 개발 순서와 통합 설치본 전달 시점
7) 아직 사용자 결정이 필요한 사항만 간결하게 정리

새로운 대형 검증 체계·별도 인증·로컬 업무 DB를 만들지 않는다.
기존 검사 증거는 재사용하고 필요한 연결부만 확인한다.
이번 설계 검수에서 제품 구현·빌드·운영 변경·실발송·
실거래·새 유료 모델 호출·commit/push는 하지 않는다.

더 간단하고 빠른 방안이 있으면 의견을 제시하고,
수정 검수안 제출 후 사용자 검토를 기다린다.
