A. HOME app-admin.jpeg 공개 데이터 문제

현재 HOME SWIMNOTE 대표 이미지에
실제 운영 데이터가 표시되어 있다면
외부 공개 홈페이지용으로 그대로 사용하지 않는다.

원칙:
- 실제 회원 이름/전화번호/개인정보 노출 절대 금지
- 실제 수영장 내부 운영수치도 불필요하면 공개하지 않음
- fake UI 새로 만들지 않음

현재 repo 안에 안전한 기존 asset이 있으면 교체한다.

안전한 asset이 없다면
민감정보가 전혀 없는 실제 데모/placeholder 수준으로만 처리하고
최종 공개용 새 screenshot 필요 여부를 보고한다.

이미지에 단순 CSS blur를 씌워 개인정보를 숨긴 척하는 방식은 금지.

13. 공용 PC 대시보드 진입점 확인
━━━━━━━━━━━━━━━━━━━━━━

P0 조사에서는:

/login
= 일반 login / super_admin/TOTP 가능

/login?pool=:poolId
= pool 전용 3-field flow

라고 확인됐다.

그러나 공식 홈페이지의
[PC 대시보드]는 특정 poolId를 미리 알지 못한다.

따라서 코드를 변경하기 전에 반드시 확인:

"공용 /login 화면에서
수영장 관리자가 ID + password 입력 후
기존 backend가 계정의 swimming_pool_id를 식별하고
PIN 단계까지 완료한 다음
/admin으로 이동하는 현재 경로가 실제 가능한가?"

가능:
→ 기존 구조 그대로 UI만 통합.

불가능:
→ 인증을 임의 수정하지 말고
원인과 최소 해결안을 보고.
그 부분만 구현 보류 가능.

super_admin/TOTP flow는 절대 깨뜨리지 않는다.

16. Device Guard 구현 기준
━━━━━━━━━━━━━━━━━━━━━━

현재 React/Vite 구조에서
최소 의존성으로 구현.

권장 판단 조합:

1. Mobile/Tablet User-Agent 판단
2. iPadOS 특수처리
   - navigator.platform === "MacIntel"
   - navigator.maxTouchPoints > 1
   등
3. viewport sanity check
4. pointer 정보 보조

중요:

touchscreen Windows laptop은
터치가 된다는 이유만으로 차단하지 않는다.

새 device-detection package 설치는
꼭 필요하지 않으면 금지.

공통 helper/hook으로 중앙화.

이 Guard는 보안수단이 아니다.
UX 사용환경 제한이다.

기존 Auth는 그대로 필요하다.
