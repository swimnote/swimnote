1. ROOT CAUSE TRACE
==================================================

정확히 다음 위치 조사:

WP1 Group 8
parent_ai_daily_usage_feature_unique

현재 SQL / helper / transaction 구조 확인.

특히:

EXCEPTION WHEN duplicate_object THEN NULL

이 있음에도 throw되는 이유를 확인.

가능성 예:

- duplicate_object가 아닌 다른 SQLSTATE
- constraint가 이미 존재하지만 다른 object conflict
- ALTER TABLE ADD CONSTRAINT가 transaction aborted 상태
- helper가 exception을 다시 throw
- constraint name vs index name collision
- DO block 범위 문제
- schema qualification 문제

추측으로 수정 금지.
실제 error code / message / stack 확인 후 수정.

==================================================
2. CORRECT IDEMPOTENT PATTERN
==================================================

가장 안전한 방식으로
"존재 여부를 먼저 검사하고 없을 때만 생성"하도록 수정.

PostgreSQL catalog 기준으로
해당 table의 constraint 존재 여부를 검사.

예시 방향:

SELECT 1
FROM pg_constraint
WHERE conname = 'parent_ai_daily_usage_feature_unique'
  AND conrelid = 'parent_ai_daily_usage'::regclass

존재:
→ SKIP

없음:
→ ALTER TABLE ... ADD CONSTRAINT ...

단 실제 schema-qualified table name과 repository migration helper 스타일을 사용.

Exception swallowing에 의존하는 방식보다
pre-check 방식 우선.
