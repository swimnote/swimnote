[SWIMNOTE X — Curriculum APP MASTER Word Import System 구현]

이번 작업은 실제 구현 작업이다.

목표:
사용자가 GPT에서 생성한
“SWIMNOTE X Curriculum APP MASTER” Word(.docx) 파일을
Superadmin에서 특정 X MODE 수영장에 업로드하면,

해당 문서의 Level / Curriculum Node / Drill / Relation / Test 정보를
정확히 파싱하여 APP/API DB에 저장하고,
해당 수영장 전용 Curriculum Version으로 즉시 사용할 수 있게 한다.

중요:
AI ENGINE으로 자동 전송하는 기능은 이번 작업에서 만들지 않는다.

사용자가 APP용 Word와 AI ENGINE용 Word를 각각 직접 업로드한다.

즉 APP은 APP 파일만 책임진다.

절대로 APP → AI 자동 migration/sync 구조를 만들지 말 것.

==================================================
0. 구현 전 절대 원칙
==================================================

현재 Repository를 먼저 조사하고
기존 데이터 모델/API/UI를 최대한 재사용한다.

기존 기능을 깨뜨리지 않는다.

기존 curriculum_items 및 과거 growth_events 참조 데이터 삭제 금지.

새 Curriculum은 Version 방식으로 추가한다.

현재 ACTIVE 버전은 새 파일 Import가 성공하기 전까지 유지한다.

APP Curriculum DB가
학생진도 / 학부모 Curriculum / Growth context 등
APP측 Curriculum 정본이다.

==================================================
1. 입력 파일
==================================================

입력은 .docx 파일이다.

GPT가 SWIMNOTE 표준 Curriculum APP MASTER 양식에 맞춰 생성한
구조화 Word 문서만 받는다.

파일 내용을 자유 텍스트로 대충 추론해서 넣지 말 것.

문서의 명시적 heading / field / table / numbering 기준으로
deterministic parser를 우선한다.

필수 지원 데이터:

DOCUMENT META
- pool reference
- curriculum release/version
- document schema version

LEVEL
- level_order
- level_name
- description
- badge/display metadata if present

CURRICULUM NODE
- sequence_in_level
- display number
- stroke
- domain
- skill_group
- atomic_skill
- title
- goal
- movement_sequence
- observable_success
- partial_success
- error_signals
- coaching_point
- test 여부
- completion 기준
- source trace

DRILL
- target curriculum node
- title
- target aspect
- movement sequence
- repetitions
- immediate feedback
- integration
- sprint validation
- failure return relation

RELATION
- prerequisite
- next skill
- related skill
- correction relation
- test relation

==================================================
2. Level 규칙
==================================================

수영장별 레벨 이름/개수는 모두 다를 수 있다.

WHITE / BLUE / BEGINNER 같은
전역 레벨 체계를 강제하지 않는다.

현재 APP 구조의:

pool_level_settings.level_order
pool_level_settings.level_name

을 우선 재사용한다.

진도순서는 반드시:

level_order INTEGER ASC

를 사용한다.

예:

수영장 A
1 흰색
2 파란색
3 빨간색

수영장 B
1 초급
2 중급
3 상급
4 마스터

UI에서는 항상
해당 pool의 level_name을 다시 표시한다.

AI용 난이도 코드와 섞지 않는다.

==================================================
3. Curriculum Identity
==================================================

매우 중요.

사람 표시번호와 DB 영구 식별자를 분리한다.

예:

display_no = L3-012
sequence_in_level = 12

이 값 자체를 DB PK로 사용하지 않는다.

DB PK/node id는 시스템이 생성하거나
기존 schema 방식에 맞춰 생성한다.

순서가 바뀌어도
과거 growth/event 참조가 깨지지 않아야 한다.

가능하면 문서의 stable node key와
DB node id mapping을 유지한다.

필요한 경우에만 최소 migration을 추가한다.

새 테이블을 무조건 만들지 않는다.

단,
Node / Drill / Relation 구조를 기존 schema가 제대로 표현하지 못하면
정규화 테이블을 최소 범위로 추가해도 된다.

그 경우 기존 curriculum_items와의
compatibility strategy를 반드시 같이 구현한다.

==================================================
5. Word Parser
==================================================

Parser 품질이 매우 중요하다.

요구사항:

- heading 순서 검증
- table/field name 검증
- level_order integer 검증
- sequence 검증
- 빈 atomic_skill 금지
- duplicate node 금지
- duplicate sequence 감지
- drill target 확인
- relation target 확인
- 잘못된 level reference 감지
- malformed Word 차단
- schema version 검증

파일 전체를 LLM에 보내서
매번 다르게 해석하는 방식 금지.

표준 Word 구조는 deterministic parser로 읽는다.

필요하면 fallback parser를 둘 수 있으나
fallback 발생 시 사용자에게 경고한다.

==================================================
7. Import Transaction
==================================================

Import는 transaction 기반으로 처리한다.

중간 실패 시
일부 Level만 들어가고
일부 Node만 들어가는 상태 절대 금지.

전체 성공 또는 전체 rollback.

새 version을 먼저 생성하고
검증/저장이 모두 성공한 뒤
IMPORT_COMPLETE 상태로 둔다.

기존 ACTIVE version을 바로 교체하지 않는다.

==================================================
8. Version 운영
==================================================

최소 상태:

DRAFT
VALIDATED
IMPORTED
ACTIVE
ARCHIVED
FAILED

과도한 상태머신 만들지 않는다.

사용자는 Import 완료 후
새 Curriculum을 직접 확인한다.

그리고 [활성화] 버튼으로 ACTIVE 전환한다.

새 버전 ACTIVE 시
기존 ACTIVE 버전은 ARCHIVED 처리하되
DB row 삭제 금지.

과거 성장기록/일지/리포트 참조 보존.

==================================================
10. Curriculum 활용도 100%
==================================================

Import된 Curriculum을 단순 보관만 하지 않는다.

현재 APP 기능에서 실제로 연결한다.

반드시 조사 후 연결:

1. Student Curriculum Progress
2. Curriculum Progress Gauge
3. 학부모 Curriculum 화면
4. 학생 현재 Level
5. 레벨별 Progress
6. 승급/테스트 정보
7. Growth Report용 Curriculum Snapshot
8. Diary 저장 시 curriculum node reference
9. 관리자/선생님 Curriculum 조회

기존 기능이 아직 전체 Node를 활용하지 못하면
필요한 selector/query/API를 추가한다.

중요:
Progress는 전체 문서 850개 단일 %만 보여주는 방식으로 고정하지 않는다.

pool의 level_order 기준으로
현재 Level 및 해당 Level 내 진행률을 계산할 수 있어야 한다.

학부모에게는 level_order 숫자가 아니라
해당 pool의 level_name을 표시한다.

==================================================
11. Drill과 Progress 분리
==================================================

Drill 수행 =
Curriculum Node 완료가 아니다.

Node 완료/확정은
기존 student progress/observation 정책에 연결한다.

Drill은 지도/교정 수단이다.

Progress Gauge를 Drill 횟수로 올리지 않는다.
