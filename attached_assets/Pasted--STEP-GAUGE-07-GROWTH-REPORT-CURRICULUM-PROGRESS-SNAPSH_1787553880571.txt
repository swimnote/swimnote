4. SCP row 없음
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

현재 Growth Report snapshot convention을 확인해서
더 자연스러운 값을 사용.

중요:
아직 3-session evidence가 없는 상태를
"0% 실력"처럼 해석하면 안 됨.

권장:

confirmed_progress_pct = null
active_confirmed_rank = 0
active_total_count = 0
active_version_id = null
observation_session_count = 0

단 기존 JSON contract가 nullable을 허용하지 않으면
0 사용 가능하되 의미는 "미확정"으로 유지.

보고서에 결정 명시.

5. Previous Report Snapshot
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

가장 중요.

period_start_pct는
현재 SCP를 과거 날짜 기준으로 재계산해서 만들면 안 된다.

반드시:

이 학생의 직전 완료 Growth Report
content JSONB에 저장된

curriculum_state.confirmed_progress_pct

를 직접 읽어서 사용.

즉:

previous report immutable JSONB
→ previous confirmed_progress_pct
→ current report period_start_pct

현재 SCP 재조회로
과거값을 복원하는 방식 금지.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
6. Previous Report 선택
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

동일:

student_id
swimming_pool_id

기준.

현재 생성 중 report 제외.

직전 finalized/completed report 1개 선택.

기존 Growth Report status/version convention 재사용.

ORDER BY report period/date descending
LIMIT 1.

초안/실패/취소 report가 있다면
previous snapshot source로 사용 금지.

실제 기존 status 값을 최소 확인하고
완료 리포트만 선택.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
7. Delta 계산
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

둘 다 값이 있을 경우:

progress_delta_pct =
ROUND(
  confirmed_progress_pct - period_start_pct,
  1
)

예:

지난 리포트:
42.4

현재:
48.7

→ progress_delta_pct = 6.3

표현 의미:
+6.3 %p

"6.3%"가 아니라
percentage point 차이임.

이 단계에서는 UI 문구 만들지 말고
숫자만 snapshot에 저장.

10. Version Transition
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

리포트 snapshot에는:

confirmed_progress_pct
= lifetime display gauge

active_version_id
= 생성 당시 현재 curriculum version

active_confirmed_rank
= 해당 active version factual rank

를 같이 저장.

따라서:

old display=70%
new version active=50%

이면 report에는:

confirmed_progress_pct: 70
active_confirmed_rank: new version rank
active_version_id: new version ID

가 들어갈 수 있음.

이건 정상.

두 의미를 섞지 않는다.
