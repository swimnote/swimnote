[SWIMNOTE 보강반 배정 정책 정정]

보강 배정은 사전 예약뿐 아니라 다음 상황을 모두 지원해야 한다.

1. 사전 보강 예약
- 오늘 이후 수업에 미리 배정

2. 당일 보강 배정
- 앱에서 미리 배정하지 않았지만 학생이 당일 갑자기 보강 수업에 참여
- 수업 시작 전·진행 중·종료 후 모두 배정 가능

3. 사후 보강 처리
- 학생이 실제 보강 수업에 참여한 후 교사나 관리자가 뒤늦게 앱에 기록
- 이미 종료된 오늘 수업에도 배정 가능

━━━━━━━━━━━━━━━━━━━━━━
후보 반 표시 기준
━━━━━━━━━━━━━━━━━━━━━━

- 결석일 이후부터 오늘까지 실제 존재했던 수업을 선택할 수 있어야 한다.
- 오늘 수업은 현재 시각이나 수업 종료 여부와 관계없이 전부 후보에 포함한다.
- 오늘 이미 종료된 반도 선택 가능해야 한다.
- 미래 수업도 기존처럼 선택 가능해야 한다.
- 과거 수업은 보강 유효기간 안에 있고 실제 수업이 존재한 날짜라면 사후 처리용으로 선택 가능해야 한다.
- 단순히 반의 반복 요일만 표시하지 말고 배정 대상 수업일을 함께 확정해야 한다.

━━━━━━━━━━━━━━━━━━━━━━
배정 데이터에 필요한 값
━━━━━━━━━━━━━━━━━━━━━━

보강 배정 시 최소한 아래 값을 저장하거나 기존 저장 구조에서 보존해야 한다.

- 학생 ID
- 원래 결석일
- 보강 대상 반 ID
- 실제 보강 수업일
- 보강 수업 시간
- 담당 교사 또는 인계 여부
- 처리 시각
- 처리 주체
- 사전 배정인지 사후 처리인지 구분 가능한 상태

사후 처리 여부는 처리 시각과 실제 수업일 비교로 계산하거나,
명시적인 assignment_type 값으로 저장할 수 있다.

예:
- scheduled: 수업 전에 배정
- same_day: 당일 배정
- retroactive: 수업 후 사후 처리

기존 DB에 이미 동일 의미의 상태가 있으면 신규 컬럼을 만들지 말고 재사용한다.

━━━━━━━━━━━━━━━━━━━━━━
정원 처리 정책
━━━━━━━━━━━━━━━━━━━━━━

- 사전 예약: 정원 초과 배정 차단
- 당일·사후 처리: 실제로 학생이 참여한 사실을 기록해야 하므로 정원 초과만으로 저장을 완전히 차단하면 안 된다.
- 정원 초과 시 경고를 표시하고 관리자 또는 권한 있는 교사가 확인 후 저장하도록 설계한다.
- 현재 시스템에 예외 승인 권한이 없다면 기존 권한 구조를 조사해 최소 변경안을 제출한다.

━━━━━━━━━━━━━━━━━━━━━━
중복 처리 정책
━━━━━━━━━━━━━━━━━━━━━━

- 동일 학생이 동일 결석 건으로 동일 수업에 두 번 배정되는 것은 차단
- 이미 보강 완료된 결석 건을 다른 수업에 다시 배정하는 것은 차단 또는 명확한 재배정 절차 필요
- 사후 처리라도 출결·보강 현황·잔여 횟수에 정확히 한 번만 반영
- API 재시도 시 중복 레코드가 생기지 않도록 멱등성 확인

━━━━━━━━━━━━━━━━━━━━━━
원인조사 시 확인할 핵심
━━━━━━━━━━━━━━━━━━━━━━

현재 코드에서 다음 조건이 있으면 정책 오류다.

- 수업일 > 오늘
- 수업 시작시간 > 현재시간
- 종료된 수업 제외
- 오늘 수업 제외
- 미래 occurrence만 생성
- 현재 시각 이전 수업 disabled
- 과거 날짜 저장 API 거부

서버 후보 API, 클라이언트 필터, 저장 API를 모두 확인해서
어느 단계에서 오늘·종료 수업을 제거하는지 확정한다.

━━━━━━━━━━━━━━━━━━━━━━
최종 테스트
━━━━━━━━━━━━━━━━━━━━━━

1. 오늘 시작 전 수업 → 배정 가능
2. 오늘 진행 중 수업 → 배정 가능
3. 오늘 종료된 수업 → 사후 배정 가능
4. 앱에 미등록 상태로 실제 수업 후 → 사후 처리 가능
5. 어제 수업 → 유효기간 내라면 사후 처리 가능
6. 미래 수업 → 사전 예약 가능
7. 정원 여유 있음 → 정상 배정
8. 정원 초과 + 사후 처리 → 경고 후 권한자 저장 가능
9. 동일 결석 건 중복 배정 → 차단
10. 출결·보강 현황·잔여 보강 횟수에 한 번만 반영

지금은 코드 수정하지 말고,
현재 DB와 API가 위 정책을 수용할 수 있는지 먼저 조사 보고한다.
신규 컬럼이나 테이블은 기존 구조로 구현할 수 없을 때만 제안한다.
