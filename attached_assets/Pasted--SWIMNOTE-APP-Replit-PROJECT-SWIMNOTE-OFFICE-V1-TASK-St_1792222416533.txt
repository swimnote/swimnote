2. 실제 모델 추가 호출 승인

합성 데이터만 사용.
추가 추론 SDK 시도 최대 8회, 자동 재시도 0.
입출력·timeout 제한은 기존 검증된 설정 유지.

공식 단가를 실행 직전에 확인하고,
8회 최대 계획비용이 US$0.01 이내일 때 진행.
초과 예상 시 호출 전에 보고.
계정 전체 강제 비용 상한이라고 표현하지 않는다.

호출 배분:
- 정확한 합성 이름 검색 2회.
- “○○ 회원 찾아줘/정보 보여줘” 등 표현 변형 2회.
- 동명이인 검색 1회.
- 존재하지 않는 회원 검색 1회.
- 검색과 정보 변경을 섞은 복합 요청 1회.
- 수정 필요 시 확인용 1회.

실패가 없으면 마지막 1회는 사용하지 않아도 된다.
사전 차단으로 SDK를 호출하지 않았다면 별도 구분한다.
한도 소진 후 반복 호출하지 않는다.

3. 검색 보정의 안전성

- 원문에 근거한 이름·전화번호 검색만 허용.
- 보정이 다른 회원을 선택하거나 검색 범위를 임의 확대하지 않음.
- 검색 결과 0명·1명·여러 명을 구분.
- 동명이인은 자동 변경 대상 확정 금지.
- 잘못된 모델 출력이 모호하면 질문/실패로 처리.
- 복합 요청에서 일부 변경만 실행하지 않음.
- 한두 문구에 맞춘 이름 하드코딩·과도한 문자열 치환 금지.

신규 모델 응답
→ 실제 interpretation handler
→ 공통 검색 Action
→ 합성 DB 조회
→ UI 결과까지 확인한다.

검색어 생성 성공만으로 PASS 선언하지 않는다.

4. 비용 없는 통합 잔여 검증

기록된 응답 또는 구조화 fixture를 재사용하여:
- 검색·필터·목록 스크롤 설정.
- 일반정보 수정 또는 반이동.
- 완료 카드→결과 보기→변경 후 조회.
- 뒤로→이전 조회 상태 복원.
- 앞으로→결과 화면 재진입.
- 현재 데이터는 변경 후 값 유지.
- AI 초안·첨부 유지.
- 실패한 결과 조회는 미열람 유지.
- 세션 교체 시 이전 결과 격리.

이 항목 때문에 모델을 추가 호출하지 않는다.

- 운영과 분리된 DB·API.
- 합성 계정·합성 회원만 사용.
- 기존 preload/IPC·Origin·host 제한 유지.
- 접근 방법·서버 인증·수명·종료 방법.
- 필요한 배포/네트워크/Secret와 비용 여부.

사용자 PC에서 접근할 수 없는 loopback 주소를
전달 가능한 환경으로 표현하지 않는다.
광범위 proxy·임의 host 허용·제품 인증 우회 금지.
환경이 준비되지 않았는데 설치본부터 만들지 않는다.
