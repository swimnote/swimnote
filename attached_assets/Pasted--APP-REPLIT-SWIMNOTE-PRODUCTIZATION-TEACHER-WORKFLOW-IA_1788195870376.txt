==================================================
2. TODAY-SCHEDULE WORK HUB
==================================================

현재 수업 카드의 기존 동작을 보존한다.

추가되는 빠른 action:

- 출석
- 일지
- 사진
- 보강
- 회원

현재 이미 존재하는 출석/일지 동작은
가능한 한 기존 handler를 그대로 재사용한다.

사진:
photos?classGroupId=<현재 반>

보강:
makeups?classGroupId=<현재 반>&backTo=today-schedule

회원:
students?classGroupId=<현재 반>

기존 카드 tap 동작이 있다면 변경하지 않는다.

expand/collapse UI를 추가하는 경우에도
기존 직접 버튼 동작과 route는 유지한다.

attendance 화면에서 동일 수업의 일지로

classGroupId
className

backTo=today-schedule

기존 출석 저장 로직 변경 금지.
기존 back 동작 변경 금지.

사용자가 일지 버튼을 누른 경우에만 이동.

자동 redirect 금지.

==================================================
4. PHOTOS OPTIONAL CONTEXT
==================================================

photos.tsx에 optional classGroupId를 지원한다.

classGroupId가 있을 때:
- 해당 반을 초기 선택
- 기존 사진/영상 기능 그대로 사용

classGroupId가 없을 때:
- 현재 Production 동작 그대로
- 기존 반 선택 UI 그대로
- 기존 default state 그대로

즉:

OLD:
/(teacher)/photos

NEW:
/(teacher)/photos?classGroupId=X

둘 다 반드시 정상.

기존 URL contract를 대체하지 않는다.

==================================================
5. MAKEUPS OPTIONAL CONTEXT
==================================================

makeups.tsx에 다음 optional param 지원:

classGroupId?
backTo?

classGroupId가 있으면:
가능한 범위에서 해당 반 관련 결과를
우선/필터 표시.

없으면:
현재 전체 보강 화면 그대로.

backTo가 있으면:
명시된 기존 route로 복귀.

없으면:
현재 기존 back behavior 그대로.

특히 params 없는 기존 makeups 접근의
navigation stack을 절대 바꾸지 않는다.

==================================================
6. STUDENTS OPTIONAL CLASS FILTER
==================================================

students.tsx:

classGroupId? optional.

없으면:
현재 전체 회원목록 100% 유지.

검색/기존 회원 상세 진입/기존 필터를 깨지 않는다.

10. BACKTO REGRESSION — 절대 중요
==================================================

→ save/back 후 my-schedule

→ save/back 후 diary-index

→ 기존 back

→ today

→ 기존 destination
