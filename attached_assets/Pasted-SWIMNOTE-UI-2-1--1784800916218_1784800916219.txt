SWIMNOTE 선생님 모드 앨범 선택 UI 및 전체 앨범 사진 미표시 수정

이번 작업 범위는 아래 2개만 처리합니다.

1. 선생님 모드 일지 작성 화면의 앨범 선택 영역 위치와 정렬 수정
2. 전체 앨범 보기에서 사진이 나오지 않는 문제 수정

다른 기능은 건드리지 마세요.

==================================================
1. 앨범 선택 영역 위치 수정
==================================================

선생님 모드에서 일지 작성 시 사용하는
사진/영상 앨범 선택 영역의 현재 레이아웃을 확인하세요.

점검 대상:

- 앨범 선택 버튼 위치
- 선택한 사진 미리보기 위치
- 공통 사진 / 학생별 사진 구분 영역
- 사진 추가 버튼
- 영상 추가 버튼
- 상단 제목 및 저장 버튼과의 간격
- 하단 safe area
- 키보드가 열렸을 때 위치 밀림
- 스크롤 안에서 버튼이 잘리거나 겹치는지
- iPhone과 Android 화면 차이

수정 원칙:

- 사진 선택 영역은 일지 내용 입력 영역 바로 아래에 배치
- 공통 사진 영역과 학생별 사진 영역이 시각적으로 명확히 구분
- 앨범 선택 버튼이 화면 좌우 중앙 또는 현재 디자인 기준선에 정확히 정렬
- 버튼과 미리보기 카드가 서로 겹치지 않음
- 하단 네비게이션 또는 safe area에 가리지 않음
- 작은 화면에서도 버튼이 잘리지 않음
- 사진을 여러 장 선택해도 레이아웃이 무너지지 않음
- 영상 미리보기 역시 사진과 동일한 정렬 기준 사용

임시 margin 값만 추가하지 말고
부모 컨테이너의 flex, width, padding, gap, safe area 구조를 확인해서 수정하세요.

필요하면 다음을 점검하세요.

- position: absolute 사용 여부
- fixed height 사용 여부
- ScrollView contentContainerStyle
- SafeAreaView
- KeyboardAvoidingView
- bottom padding
- flexShrink
- flexWrap
- width: "100%"
- alignItems / justifyContent

수정 전후 스크린샷을 보고서에 포함하세요.

==================================================
2. 전체 앨범 보기에서 사진 미표시 문제
==================================================

선생님 모드의 전체 앨범 화면에서
업로드한 사진이 나오지 않는 정확한 원인을 찾으세요.

추측으로 수정하지 말고 아래 흐름을 전부 확인하세요.

1. 전체 앨범 화면 진입
2. 어떤 API를 호출하는지
3. API 응답에 사진 row가 포함되는지
4. 프론트 상태에 사진이 저장되는지
5. 필터링 과정에서 빠지는지
6. FlatList 또는 SectionList에 전달되는지
7. 이미지 URL이 유효한지
8. Image 컴포넌트가 실제 URL을 렌더링하는지

==================================================
3. API와 DB 조건 점검
==================================================

전체 앨범 조회 API의 SQL 또는 ORM 조건을 확인하세요.

다음 조건 때문에 사진이 빠지는지 확인:

- status = "uploaded"만 조회
- status = "attached" 제외
- diary_id IS NULL 조건
- student_id IS NULL 조건
- is_deleted 조건 오류
- center_id 조건 오류
- uploader_id 조건 오류
- class_group_id 조건 오류
- media_type 조건 오류
- pagination 기본값 오류
- created_at 정렬 오류
- tenant/center 필터 불일치

전체 앨범에는 원칙적으로 다음 상태의 미디어가 보여야 합니다.

- uploaded
- attached
- detached
- failed

단:

- is_deleted=true는 제외
- 실제 파일이 없는 row는 실패 상태로 표시
- 다른 센터 자료는 제외

특히 attached 사진을 전체 앨범에서 제외하지 마세요.

전체 앨범은 "아직 일지에 안 붙인 사진만 보는 화면"이 아니라
선생님이 업로드한 전체 사진과 영상을 보는 보관함입니다.

==================================================
4. 프론트 필터 전수 확인
==================================================

전체 앨범 화면에서 다음 패턴을 검색하세요.

filter(item => !item.diaryId)
filter(item => item.status === "uploaded")
filter(item => !item.attached)
filter(item => item.studentId)
filter(item => item.mediaType === "image")
filter(item => item.isAvailable)
filter(Boolean)

이런 필터로 attached 사진이나 공통 사진이 빠지는지 확인하세요.

필터링이 필요하면 목적을 구분하세요.

전체 앨범:
- 삭제되지 않은 전체 사진/영상 표시

일지 첨부 선택기:
- 재첨부 가능한 미디어만 선택 가능

두 화면이 같은 배열과 같은 필터를 쓰면 안 됩니다.

==================================================
5. URL 문제 점검
==================================================

API 응답에 row는 있는데 사진이 안 보이는 경우
URL 문제를 확인하세요.

점검:

- thumbnail_url
- file_url
- public_url
- signed_url
- r2_key
- storage_key

프론트가 어떤 필드를 사용하는지 확인하세요.

예:

API는 thumbnailUrl을 반환하는데
프론트는 url을 읽는 경우

API는 file_url을 반환하는데
프론트는 imageUrl을 읽는 경우

signed URL 만료
http/https 문제
undefined URL
상대경로 문제

각 이미지 렌더링 직전에 개발 로그를 추가하세요.

[ALBUM IMAGE RENDER]
mediaId=
status=
fileUrl=
thumbnailUrl=
resolvedUrl=

Image onError에도 로그 추가:

[ALBUM IMAGE ERROR]
mediaId=
resolvedUrl=
error=

==================================================

전체 앨범 API 응답과 프론트 타입을 비교하세요.

예:

API:
file_url

frontend:

==================================================
7. 로딩과 빈 화면 처리
==================================================

현재 사진이 안 보일 때
실제 빈 앨범인지, 로딩 실패인지 구분되지 않을 수 있습니다.

상태를 분리하세요.

- loading
- loaded and empty
- loaded with items
- request failed

오류인데 "사진이 없습니다"로 표시하지 마세요.

API 실패 시:

"앨범을 불러오지 못했습니다"
재시도 버튼

실제 0개일 때만:

"아직 업로드된 사진과 영상이 없습니다"

==================================================
8. 캐시와 화면 복귀
==================================================

사진 업로드 후 전체 앨범으로 이동했을 때
바로 반영되는지 확인하세요.

다음 시점에 refetch 또는 cache invalidation:

- 사진 업로드 성공
- 영상 업로드 성공
- 일지 첨부 성공
- 일지 첨부 해제
- 일지 삭제
- 전체 앨범 화면 focus

React Query를 사용한다면 관련 query key를 전부 확인하세요.

예:

teacher-album
media
album
uploaded-media
class-media

화면마다 다른 query key를 써서
한 화면만 갱신되는 문제가 없는지 확인하세요.

9. 테스트
==================================================

아래를 실제로 검증하세요.

테스트 1
사진 3장 업로드
→ 전체 앨범에 3장 표시

테스트 2
사진 1장을 일지에 첨부
→ 전체 앨범에서 계속 표시
→ "일지 첨부됨" 배지 표시

테스트 3
공통 사진 1장
→ 전체 앨범 표시

테스트 4
학생별 사진 1장
→ 전체 앨범 표시

테스트 5
영상 1개 업로드
→ 전체 앨범 표시
→ 썸네일 또는 영상 표시

테스트 6
앱 종료 후 재실행
→ 전체 앨범 동일하게 표시

테스트 7
업로드 직후 전체 앨범 이동
→ 새 사진 즉시 표시

테스트 8
Image URL 오류 강제 발생
→ 오류 로그 표시
→ 화면 전체가 멈추지 않음
