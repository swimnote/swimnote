SWIMNOTE 추가 보호자 전화번호 등록 및 자동 연결 기능

목표:

기존에 학생과 연결된 학부모가
학부모 앱 설정에서 두 번째·세 번째 보호자 전화번호를 직접 등록합니다.

등록된 전화번호는 즉시 수영장 관리자 전산의
해당 학생 보호자 정보에도 표시합니다.

이후 등록된 전화번호로 학부모가 가입하거나
이미 가입된 계정이 로그인하면,
별도 관리자 승인 없이 해당 학생과 자동 연결합니다.

학생 이름으로 병합하지 않습니다.
인증된 전화번호가 등록 번호와 일치할 때만 자동 연결합니다.

==================================================
1. 학부모 설정 화면
==================================================

학부모 앱 설정 또는 자녀 관리에 다음 메뉴를 추가하세요.

[추가 보호자 관리]

학생별 표시 예:

홍길동

주 보호자
- 조승주
- 010-6538-0519
- 연결 완료

추가 보호자 1
- 전화번호 입력
- 관계 선택
- 저장

추가 보호자 2
- 전화번호 입력
- 관계 선택
- 저장

[추가 보호자 등록]

보호자 수는 2명으로 제한하지 말고
두 번째·세 번째 보호자를 계속 추가할 수 있게 합니다.

기본 권장 최대값은 학생당 4명으로 설정하되,
상수 또는 센터 설정으로 변경 가능하게 하세요.

입력 항목:

- 보호자 전화번호
- 관계
  - 어머니
  - 아버지
  - 조부모
  - 기타
- 보호자 이름은 선택 입력

==================================================
2. 저장 즉시 관리자 전산 반영
==================================================

기존 학부모가 추가 보호자 번호를 저장하면
수영장 관리자 화면의 해당 학생 보호자 정보에 즉시 추가하세요.

관리자 표시 예:

연결된 보호자

1. 조승주
   010-6538-0519
   주 보호자
   앱 가입 완료

2. 이름 미등록
   010-1234-5678
   추가 보호자
   가입 대기

3. 김○○
   010-9876-5432
   추가 보호자
   앱 가입 완료

현재 학부모 명단의 상세 화면에서도
추가 보호자 전화번호와 상태를 확인할 수 있어야 합니다.

상태:

- 가입 대기
- 자동 연결 완료
- 연결 해제
- 등록 취소

==================================================
3. 자동 승인·자동 연결
==================================================

학부모 회원가입 또는 로그인 시
본인 인증된 전화번호를 기준으로 추가 보호자 등록 정보를 조회하세요.

조건:

verified_phone
=
학생 보호자 정보에 저장된 추가 보호자 전화번호

일치하면 별도 관리자 승인 없이 자동으로:

- 해당 사용자 계정 연결
- 해당 학생 연결
- 보호자 상태를 연결 완료로 변경
- 관리자 전산에 이름과 가입 상태 반영

이미 가입한 계정인 경우에도
로그인 또는 앱 실행 시 등록 번호를 조회해 자동 연결하세요.

자동 연결 후 학부모 앱에 안내:

“홍길동 학생의 보호자로 연결되었습니다.”

==================================================
4. 전화번호 정규화
==================================================

다음 전화번호가 동일하게 비교되도록 정규화하세요.

010-1234-5678
01012345678
+82 10-1234-5678

가입 전화번호와 관리자 전산 전화번호,
추가 보호자 입력 번호 모두 같은 정규화 함수를 사용하세요.

DB에는 phone_normalized를 별도로 저장하세요.

==================================================
5. 데이터 구조
==================================================

기존 학생 보호자 연결 구조를 확인하고
추가 보호자는 동일 학생에 여러 명 연결할 수 있게 하세요.

권장 필드:

student_guardians

- id
- center_id
- student_id
- user_id nullable
- guardian_name nullable
- phone_normalized
- relationship nullable
- is_primary
- status
- registered_by_user_id
- registered_at
- connected_at
- created_at
- updated_at

status:

- pending
- connected
- cancelled
- disconnected

전화번호 저장 직후:

user_id = NULL
status = pending

해당 번호 가입 확인 후:

user_id = 가입 사용자 ID
status = connected
connected_at = 현재 시각

==================================================
6. 중복 방지
==================================================

다음 중복을 차단하세요.

- 같은 학생에 같은 번호 반복 등록
- 같은 사용자 계정이 같은 학생에 중복 연결
- 주 보호자 본인 번호를 추가 보호자로 다시 등록
- 삭제되지 않은 동일 pending 번호 중복 생성

권장 제약:

UNIQUE(student_id, phone_normalized)

UNIQUE(student_id, user_id)
WHERE user_id IS NOT NULL

이미 연결된 번호를 입력하면:

“이미 이 학생의 보호자로 등록된 전화번호입니다.”

표시.

==================================================
7. 자동 연결 트랜잭션
==================================================

자동 연결 시 동일 트랜잭션으로 처리하세요.

1. 인증된 전화번호 조회
2. pending 보호자 row 잠금
3. 해당 학생과 센터 확인
4. 중복 연결 확인
5. user_id 저장
6. status = connected
7. connected_at 저장
8. 사용자-학생 연결 생성 또는 활성화
9. 감사 로그 저장

중복 요청이 와도 보호자 연결이 두 번 생성되지 않아야 합니다.

==================================================
8. 등록 번호 수정·삭제
==================================================

기존 승인 보호자는 아직 가입하지 않은 pending 보호자에 대해:

- 전화번호 수정
- 관계 수정
- 등록 취소

가능하게 하세요.

이미 connected 상태인 보호자는
다른 학부모가 임의로 삭제하지 못하게 합니다.

연결 완료 보호자의 해제는:

- 본인 연결 해제 요청
- 또는 관리자 처리

방식으로 제한하세요.

==================================================
9. 관리자 화면
==================================================

현재 첨부된 학부모 상세 화면에
연결된 자녀뿐 아니라 해당 자녀의 보호자 정보를 확인할 수 있게 하세요.

학생 상세 또는 보호자 상세에서:

- 주 보호자
- 추가 보호자
- 전화번호
- 관계
- 앱 가입 여부
- 연결 상태

표시.

기존 승인 보호자가 번호를 저장하면
관리자 앱을 새로 실행하거나 화면을 다시 열었을 때 즉시 반영되어야 합니다.

==================================================
10. 권한
==================================================

추가 보호자 번호 등록 가능 사용자:

- 해당 학생에 이미 연결된 승인 보호자
- 센터 관리자

자동 연결 조건:

- 전화번호 인증 완료
- phone_normalized 정확히 일치
- 상태 pending
- 같은 학생 및 센터
- 연결 취소 상태가 아님

학생 이름만 같거나
보호자 이름만 같다는 이유로 연결하지 마세요.

==================================================
11. 연결 후 권한
==================================================

두 번째·세 번째 보호자도 연결 완료 후 동일 학생의:

- 수업 일지
- 사진·영상
- 출결
- 공지
- 일정
- 좋아요
- 감사합니다
- 댓글 작성
- 선생님 답글

을 사용할 수 있어야 합니다.

단, 보호자별 댓글 비공개 정책은 유지합니다.

보호자 1과 보호자 2는
서로 작성한 댓글을 볼 수 없습니다.

==================================================
12. 실제 테스트
==================================================

테스트 1

기존 보호자가 추가 번호 저장
→ 관리자 전산에 가입 대기 번호 표시

테스트 2

해당 번호로 신규 가입
→ 별도 관리자 승인 없이 학생 자동 연결
→ 관리자 전산 상태 연결 완료

테스트 3

이미 가입된 계정 번호 저장
→ 다음 로그인 또는 화면 갱신 시 자동 연결

테스트 4

세 번째 보호자 번호 등록
→ 동일 방식으로 자동 연결

테스트 5

다른 전화번호로 가입
→ 자동 연결 안 됨

테스트 6

학생 이름만 동일
→ 자동 연결 안 됨

테스트 7

동일 번호 중복 등록
→ 차단

테스트 8

가입 전 번호 수정
→ 이전 번호 연결 불가
→ 새 번호만 자동 연결

테스트 9

연결된 추가 보호자
→ 해당 학생 일지·사진 정상 조회

테스트 10

추가 보호자끼리 댓글 작성
→ 선생님은 모두 확인
→ 보호자끼리는 서로 댓글 미표시

==================================================
13. 작업 범위 제한
==================================================

이번 작업에서 새 학생 row를 생성하지 마세요.

‘어린이 직접 등록’ 기능을 호출하지 마세요.

반드시 기존 student_id에
추가 보호자만 연결해야 합니다.

사진·영상, 일지, 댓글 기능의 기존 로직은 변경하지 말고
보호자 연결 권한만 동일하게 적용하세요.
