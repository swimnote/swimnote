# SWIMNOTE 디자인 시스템 리뉴얼 — S7 보완 작업 지시

S7 완료 보고서를 검토했습니다.

현재 상태는 조건부 완료이며 아직 승인하지 않습니다.

S8로 진행하지 마세요.

======================================
보완이 필요한 이유
======================================

1.

필수였던 Android 및 iPhone 실기기 테스트가 실제로 수행되지 않았습니다.

“Expo Go에서 확인 가능”은 테스트 결과로 인정할 수 없습니다.

2.

현재 구현은 onScroll에서 계산한 최신 속도를
onMomentumScrollEnd에서 확인하는 구조입니다.

빠른 플링도 감속이 끝날 무렵에는 최신 속도가 낮아질 수 있으므로,
빠른 플링인데도 Soft Snap이 실행될 가능성이 있습니다.

이 부분을 반드시 실제 코드 기준으로 검증하세요.

======================================
S7 보완 목표
======================================

빠른 플링 여부를 스크롤 종료 순간의 낮아진 속도가 아니라
해당 스크롤 세션의 속도 정보로 판단하도록 보완합니다.

======================================
권장 구현 방식
======================================

다음과 같이 스크롤 세션 단위로 관리하세요.

- onScrollBeginDrag에서 세션 초기화
- onScroll 중 최대 절대 속도 또는 의미 있는 플링 속도 기록
- onScrollEndDrag에서 플링 여부 확정
- 빠른 플링으로 판단된 세션은 onMomentumScrollEnd에서 스냅 금지
- 처리가 끝난 뒤 플래그 초기화

예시 개념:

isFastFlingRef
maxVelocityRef
didDragRef

단, 실제 구현은 기존 코드 구조에 맞게 최소 변경으로 처리하세요.

중요:

마지막 onScroll 속도만 이용해 빠른 플링 여부를 판단하지 마세요.

======================================
추가 검증 사항
======================================

1.

아래 두 방향 모두 확인하세요.

- 아래 방향 빠른 플링
- 위 방향 빠른 플링

속도 비교는 절댓값 기준으로 처리해야 합니다.

2.

프로그램에 의해 실행된 scrollToOffset 때문에
추가 onMomentumScrollEnd가 발생하더라도 반복 스냅 또는 진동이 생기지 않아야 합니다.

필요하다면 isSnappingRef 같은 보호 장치를 사용하세요.

3.

headerHeight가 0이거나 아직 측정되지 않은 상태에서는
두 번째 스냅 포인트를 사용하지 마세요.

4.

동일한 스냅 포인트가 중복 등록되지 않도록 하세요.

5.

기존 Home UI, 데이터, API, Context, Navigation은 수정하지 마세요.

======================================
실기기 테스트 필수
======================================

Android와 iPhone에서 실제로 다음 항목을 수행하세요.

- 천천히 아래로 드래그 후 경계 근처 정지
- 천천히 위로 드래그 후 경계 근처 정지
- 아래 방향 빠른 플링
- 위 방향 빠른 플링
- 80px보다 먼 위치에서 정지
- 맨 위에서 짧게 드래그
- 사진 영역까지 긴 스크롤
- 당겨서 새로고침 후 스크롤
- 자녀 전환 후 스크롤
- Soft Snap 직후 다시 반대 방향으로 스크롤
- 연속으로 빠르게 두 번 플링

실기기 접근이 정말 불가능하다면
불가능하다고 보고하고 테스트 완료로 표시하지 마세요.
