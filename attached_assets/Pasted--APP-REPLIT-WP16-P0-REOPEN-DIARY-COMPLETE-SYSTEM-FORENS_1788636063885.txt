4. AI DIARY — 가장 중요
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

현재 사용자 의도:

선생님이 짧게 입력한 문장을
그대로 Diary에 넣는 기능이 아님.

정상:

Teacher short/raw input
→ AI ENGINE
→ Template Search
→ Knowledge Search
→ Grounded generation
→ 수영 전문 내용이 보강된 자연스러운 Diary
→ APP preview
→ 그 AI 결과를 저장

현재 실제 Production에서는
"내가 입력한 내용만 들어가는 것 같다"는 증상이 있음.

이것을 반드시 end-to-end 추적.

확인 단계:

1.
Teacher가 입력한 raw text

2.
APP가 Engine으로 보내는 request payload
민감정보는 마스킹

3.
Engine HTTP response
다음 정도만 기록:
- status
- pipeline_mode
- fallback_used
- common result 존재 여부
- student result 존재 여부
- generated text length
- template_ids count
- knowledge_ids count
- grounding_validation 존재 여부

실제 전문 텍스트 전체 로그 출력 금지.

4.
APP response mapper

5.
AI 결과가 어떤 state에 저장되는지

6.
UI에서 어떤 text를 보여주는지

7.
Save payload가 무엇을 보내는지

8.
DB에 최종 어떤 source text가 저장되는지

반드시 아래를 구분:

CASE A
Engine은 풍성한 결과를 반환하지만
APP가 raw input으로 덮어씀

CASE B
Engine 결과 mapping이 깨짐

CASE C
common/student mapping 중 일부가 누락

CASE D
save payload가 generated text가 아니라 raw teacher text 사용

CASE E
Engine response 자체가 실제로 빈약함

CASE F
AI 호출이 실패하고 fallback/local raw text path가 작동

CASE G
잘못된 다른 legacy AI route 사용

추측 금지.

APP에서 임의로 수영 지식 생성 금지.

Exact evidence:
request 정상
APP mapping 정상
Engine response 자체가 원인
