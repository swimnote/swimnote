3. 실기기 최종 검증
━━━━━━━━━━━━━━━━━━━━━━

CASE 1
보강대기 진입
→ 탭 바 아래 작은 학생 이름 검색창 표시

CASE 2
목록 스크롤
→ 검색창은 상단에 계속 유지

CASE 3
검색창 탭
→ 키보드 표시

CASE 4
학생 이름 한 글자 입력
→ 검색 버튼 없이 즉시 필터링

CASE 5
이름 중간 글자 입력
→ 부분검색 정상

CASE 6
검색된 학생 카드의 기존 액션 탭
→ 첫 탭에 바로 실행
→ 두 번 탭해야 하는 현상 없음

CASE 7
키보드가 열린 상태에서 목록 드래그
→ 첫 드래그에 키보드 내려감
→ 동시에 스크롤 정상

CASE 8
키보드가 열린 상태에서 목록의 빈 공간 터치
→ 키보드가 한 번에 내려가는지 실기기 확인

중요:
CASE 8은 keyboardShouldPersistTaps="handled"만으로
동작을 확정하지 말고 실제 iOS/Android 결과를 확인한다.

CASE 9
검색어 clear
→ 전체 waitingList 즉시 복원

CASE 10
없는 이름 검색
→ "검색 결과가 없습니다."

CASE 11
화면 이탈 후 재진입
→ 검색어 초기화

CASE 12
검색하지 않은 상태
→ 기존 보강대기 기능과 동작 동일
