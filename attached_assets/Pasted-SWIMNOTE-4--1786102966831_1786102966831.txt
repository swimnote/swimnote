현재 제출한 4개 수정안은 아직 승인하지 않는다.

목표는 정확히 이것이다.

"정원 찬 반에도 보강 학생은 배정 가능하게 한다."

중요:
정규 회원 등록, 반이동, 신규 등록 등의 정원 제한을 해제하는 작업이 아니다.

코드 수정 금지.
먼저 아래 조사 결과만 제출한다.

2. teachers.ts HAVING 원문 제출
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

현재 제안:

"HAVING 절 삭제"

이 방식은 승인하지 않는다.

HAVING 전체 원문을 제출한다.

확인:

HAVING이 단순히

current_count < max_students

조건 하나만 포함하는지,

아니면 다른 aggregate 조건도 포함하는지 확인한다.

정원 조건 외 다른 조건이 있다면
HAVING 전체 삭제 금지.

정원 비교식만 정확히 제거해야 한다.

3. CLASS_FULL 블록 전체 원문
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

teachers.ts의 CLASS_FULL 발생 코드 전체를 제출한다.

특히 확인:

- validateMakeupOccurrence 안에 있는지
- assign과 complete-direct가 공유하는지
- 다른 CLASS_FULL 검증이 추가로 존재하는지
- is_full만 계산하는 부분과 실제 차단 부분을 구분

최종 정책:

보강 assign / complete-direct에서는
정원이 차 있어도 허용.

그러나

- 반 존재 검증
- pool 일치
- 수업 요일
- 휴일
- 날짜 -14/+28
- expired 확인
- 상태 검증

은 그대로 유지해야 한다.

정원 검증 하나만 제거한다.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
4. admin is_eligible 의미 해체
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

현재 제안:

.filter(r => r.is_eligible) 전체 삭제

이것은 위험하므로 금지한다.

admin.ts에서 is_eligible 값이 정확히 어떻게 계산되는지 원문 제출.

예:

is_eligible =
  !is_full &&
  is_active &&
  ...

처럼 여러 조건이 합쳐져 있다면
filter 전체 삭제 금지.

정원 때문에 false가 되는 부분만 바꿔야 한다.

반드시 다음을 표로 제출:

조건 | 의미 | 유지/제거

정원 조건만 제거하고
나머지 eligibility 조건은 전부 유지한다.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
5. makeups.tsx UI 검수
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

현재 제안:

- disabled 삭제
- opacity 0.4 삭제
- onPress guard 삭제
- is_full 뱃지 유지

이 방향은 가능하다.

하지만 해당 disabled/onPress 조건이 정말 is_full 하나만 보는지 원문 제출.

예:

disabled={r.is_full || !r.is_eligible}

라면 통째 삭제 금지.

정원 부분만 제거해야 한다.
