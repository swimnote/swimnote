[SWIMNOTE 학부모 연결 FIX 추가요구 — 형제자매 자동 연결]

앞서 조사한 학부모 승인 FIX에 아래 요구사항을 추가합니다.

이번 수정에서 반드시 같이 구현하십시오.

━━━━━━━━━━━━━━━━━━━━
1. 학부모 승인 단위를 "신청 자녀 1명"에서 "보호자 계정"으로 확장
━━━━━━━━━━━━━━━━━━━━

수영장에서는 학생 등록 시 이미 각 학생에게

parent_phone
parent_phone2
parent_phone3
parent_phone4

형태로 보호자 전화번호를 등록하고 있습니다.

따라서 학부모가 정상적으로 본인 확인되어
학생 한 명과 연결되는 순간,

같은 수영장 안에서
동일한 보호자 전화번호가 등록된 다른 학생도 함께 검색하십시오.

예:

학생 A
parent_phone = 01012345678

학생 B
parent_phone2 = 01012345678

학부모 계정
phone = 01012345678

학부모가 A 또는 B 중 한 명을 기준으로 정상 승인되면

→ A 연결
→ B 연결

두 학생 모두 같은 학부모 계정에 자동 연결합니다.

학부모가 형제자매 각각에 대해
가입신청을 반복하거나
관리자가 각각 승인할 필요가 없게 합니다.

━━━━━━━━━━━━━━━━━━━━
2. 이름은 최초 학생 확인용, 형제자매 연결은 보호자 전화번호 기준
━━━━━━━━━━━━━━━━━━━━

형제자매 자동연결에서
학생 이름을 다시 비교하지 마십시오.

보호자가 한 학생에 대해 정상 승인된 이후에는

현재 parent의 normalized phone

과

같은 pool의 active students에 등록된

parent_phone1~4

를 비교합니다.

일치하는 모든 학생을
해당 parent 계정에 연결합니다.

즉:

보호자 정상 승인
→ 보호자 전화번호 확정
→ 같은 pool 검색
→ 동일 보호자 전화번호가 등록된 학생 전부 검색
→ parent_students 연결

구조입니다.

━━━━━━━━━━━━━━━━━━━━
3. 반드시 같은 pool 안에서만 실행
━━━━━━━━━━━━━━━━━━━━

형제자매 자동연결 검색 조건:

student.swimming_pool_id === approved pending.pool_id

필수.

다른 수영장의 동일 전화번호 학생은
절대 연결하지 않습니다.

━━━━━━━━━━━━━━━━━━━━
4. 미리 등록된 보호자 번호만 인정
━━━━━━━━━━━━━━━━━━━━

학부모가 가입하면서 입력한 전화번호가 있다고 해서
아무 학생이나 추가하지 않습니다.

학생 DB의

parent_phone
parent_phone2
parent_phone3
parent_phone4

중 하나에
해당 학부모 전화번호가 실제로 사전등록되어 있는 학생만 연결합니다.

즉 이 기능의 근거는:

"학부모가 형제라고 주장했다"

가 아니라

"수영장이 이미 해당 학생의 보호자 번호로 등록해두었다"

입니다.

━━━━━━━━━━━━━━━━━━━━
5. 여러 자녀가 발견되면 전부 연결
━━━━━━━━━━━━━━━━━━━━

예:

서태웅
parent_phone = 01011112222

서태희
parent_phone2 = 01011112222

서태민
parent_phone = 01011112222

보호자 01011112222 승인

결과:

parent → 서태웅 approved
parent → 서태희 approved
parent → 서태민 approved

3건 연결.

기존 설계의
학생당 최대 3명 보호자 정책은 그대로 유지합니다.

이 기능은

한 보호자 → 여러 자녀

연결이며,

학생 1명 → 최대 3명 보호자

정책과 충돌하지 않아야 합니다.

━━━━━━━━━━━━━━━━━━━━
6. 기존 parent_students 중복 방지
━━━━━━━━━━━━━━━━━━━━

형제자매 중 일부가 이미 연결되어 있을 수 있습니다.

예:

A = 이미 approved
B = 미연결
C = 미연결

승인 실행 시:

A → 그대로 유지
B → approved 생성
C → approved 생성

A duplicate 생성 금지.

idempotent하게 구현하십시오.

같은 승인 API를 여러 번 호출해도
parent_students 중복 row가 생기면 안 됩니다.

━━━━━━━━━━━━━━━━━━━━
7. 기존 sibling pending 정리
━━━━━━━━━━━━━━━━━━━━

형제자매가 각각 가입신청/pending으로 존재할 수 있습니다.

보호자 승인 후
동일 parent + 동일 pool + 동일 보호자 전화번호로 자동 연결된 학생에 대한
기존 pending 요청이 있다면 상태가 계속 "대기"로 남지 않게 정리하십시오.

안전하게 해당 학생이 실제 연결되었음이 확인되는 경우:

pending
→ matched

matched_student_id 설정

을 검토하여 적용하십시오.

단 다른 학생의 불확실한 pending을
전화번호만 비슷하다는 이유로 임의 처리하지 마십시오.

━━━━━━━━━━━━━━━━━━━━
8. 관리자 수동승인에도 동일 적용
━━━━━━━━━━━━━━━━━━━━

관리자가 name_mismatch 요청을 보고

[승인]
→ 학생 선택
→ 최종 승인

했을 때도

선택한 학생 한 명만 연결하고 끝내지 않습니다.

관리자가 승인한 parent의 전화번호를 기준으로
같은 pool에서 동일 보호자 전화번호가 등록된 학생을 추가 검색하여

형제자매를 함께 연결합니다.

즉:

자동승인
수동승인
rejected → approved

세 경로 모두
최종 성공 후 동일한 sibling-link helper를 사용하십시오.

별도 로직을 3군데 복제하지 마십시오.

권장:

linkApprovedParentToRegisteredChildren(
  parentId,
  poolId,
  normalizedParentPhone
)

같은 공통 helper로 분리합니다.

━━━━━━━━━━━━━━━━━━━━
9. 학부모 UX
━━━━━━━━━━━━━━━━━━━━

학부모가 첫 연결을 완료하면
다시 자녀 추가 신청을 하지 않아도

사전에 동일 보호자 번호가 등록되어 있던 자녀들이
학부모 계정에 함께 나타나야 합니다.

예:

박세아 신청
→ 승인

수영장 DB에 같은 학부모 전화번호로
박세연도 등록되어 있음

결과:

학부모 홈에서

박세아
박세연

둘 다 선택 가능.

추가 승인 요청 없음.

━━━━━━━━━━━━━━━━━━━━
10. 안전규칙
━━━━━━━━━━━━━━━━━━━━

자동 sibling 연결 조건은 반드시:

1. 동일 pool
2. 동일 normalized 보호자 전화번호
3. students.parent_phone1~4 중 실제 일치
4. active/유효 학생
5. 기존 연결 중복 없음

을 모두 만족해야 합니다.

자녀 성이 같다,
이름이 비슷하다,
신청자가 형제라고 입력했다

등은 sibling 자동연결 근거로 사용하지 않습니다.

━━━━━━━━━━━━━━━━━━━━
11. 추가 테스트
━━━━━━━━━━━━━━━━━━━━

CASE S1

한 학부모 전화번호가 학생 2명에게 등록
→ 한 명 승인
→ 2명 모두 parent_students approved

CASE S2

3명 형제자매
→ 한 명 승인
→ 3명 모두 연결

CASE S3

형제 중 1명 이미 approved
→ 나머지만 생성
→ duplicate 0

CASE S4

같은 전화번호지만 다른 pool 학생
→ 연결 금지

CASE S5

학생 DB에 보호자 번호 미등록
→ 자동 sibling 연결 금지

CASE S6

관리자 수동승인
→ 선택 학생 승인
→ 같은 번호의 형제자매도 자동연결

CASE S7

rejected → 관리자 승인
→ 형제자매 동시 연결

CASE S8

형제별 pending이 여러 건 존재
→ 승인 후 실제 연결된 학생 pending만 matched 정리
→ 대기 숫자가 잘못 남지 않음

CASE S9

동일 승인 API 재호출
→ parent_students duplicate = 0

CASE S10

학생 1명에 이미 다른 보호자 2명이 연결되어 있고
새 보호자가 세 번째로 승인
→ 최대 3명 정책 안에서 정상 연결

최대 보호자 수 제한을 초과할 경우
기존 정책에 따라 안전하게 차단하고
관리자에게 명확한 오류를 표시하십시오.

━━━━━━━━━━━━━━━━━━━━
12. 최종 원칙
━━━━━━━━━━━━━━━━━━━━

학부모에게 형제자매 각각을
다시 가입시키게 하지 마십시오.

수영장이 이미 보호자 전화번호를 등록해두었다면

# 보호자 한 번 확인
→ 등록된 자녀 전체 연결

이 SWIMNOTE의 기본 UX가 되어야 합니다.
