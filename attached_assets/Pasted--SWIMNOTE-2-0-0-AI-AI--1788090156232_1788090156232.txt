[SWIMNOTE 2.0.0 — AI 커리큘럼 검색 답변 가독성 개선]

목적:
현재 AI 커리큘럼 검색 답변이
내용은 맞지만 긴 문단 하나로 이어져 모바일에서 읽기 어렵다.

이번 작업은
1) AI 응답 생성 포맷
2) 서버 응답 보존
3) 앱 렌더링
을 함께 점검해서
문단과 강조가 실제 화면에서 살아나도록 개선한다.

중요:
프롬프트에 줄바꿈만 추가하는 식으로 끝내지 말 것.
앱 렌더링 과정에서 \n\n 또는 Markdown이 사라지는지까지 확인한다.

━━━━━━━━━━━━━━━━━━━━
1. 현재 증상
━━━━━━━━━━━━━━━━━━━━

실제 답변 예:

"현재 기록된 진도는 없어 정확한 현재 위치 판단은 어렵습니다.
토이키즈스윔클럽 교육과정에서는 배영을 익힐 때 ..."

현재 문제:
- 긴 문단 하나로 출력됨
- 문단 구분 없음
- 핵심 포인트 강조 없음
- 모바일에서 읽기 피곤함
- 내용 구조가 눈에 잘 안 들어옴

━━━━━━━━━━━━━━━━━━━━
2. 목표 답변 구조
━━━━━━━━━━━━━━━━━━━━

AI 커리큘럼 검색 답변은
기본적으로 2~4개의 짧은 섹션으로 나눈다.

예:

**현재 상태**

현재 기록된 진도가 없어 정확한 현재 위치를 판단하기는 어렵습니다.

**배영에서 먼저 익힐 부분**

배영은 귀가 물에 자연스럽게 잠기는 머리 위치와
천장을 일정하게 바라보는 시선,
그리고 저항이 적은 스트림라인을 먼저 안정시키는 것이 중요합니다.

**특히 중요한 포인트**

킥을 할 때는 다리 전체로 물을 누르는 감각을 유지하고
무릎이 수면 위로 과도하게 올라오지 않도록 하는 것이 중요합니다.

━━━━━━━━━━━━━━━━━━━━
3. 생성 포맷 규칙
━━━━━━━━━━━━━━━━━━━━

AI 응답 생성 규칙:

- 답변 전체 2~4개 섹션
- 섹션 제목은 짧게
- 제목 아래 한 줄 띄움
- 문단당 1~3문장
- 한 문단 4줄 이상 길어지지 않도록
- 같은 내용 반복 금지
- 핵심만 남기고 군더더기 문장 줄이기
- 지나치게 구어체 표현 줄이기
- 학부모가 이해하기 쉬운 표현 사용
- 교육과정 근거 범위 밖 지식 생성 금지

권장 섹션 예:
- 현재 상태
- 먼저 익힐 부분
- 중요한 포인트
- 다음에 확인할 부분

질문 유형에 따라 모든 섹션을 강제하지는 않는다.

━━━━━━━━━━━━━━━━━━━━
4. Markdown 여부 조사
━━━━━━━━━━━━━━━━━━━━

현재 curriculum chat 응답이
Markdown 렌더링을 지원하는지 실제 코드로 확인한다.

확인할 것:
- 서버가 plain text를 반환하는지
- Markdown 문자열을 반환하는지
- 앱에서 Text 컴포넌트로 그대로 출력하는지
- Markdown renderer가 이미 있는지
- \n\n 줄바꿈이 보존되는지
- bold 표시가 가능한지

추측하지 말 것.

━━━━━━━━━━━━━━━━━━━━
5. 렌더링 정책
━━━━━━━━━━━━━━━━━━━━

A. 기존 앱에 안정적인 Markdown renderer가 이미 있으면
→ 그대로 재사용 가능 여부 검토

B. Markdown renderer가 없다면
→ 이번 기능 하나 때문에 무거운 dependency를 새로 추가하지 말고
간단한 structured response 또는 line-break rendering 방식 우선 검토

예:
server response를
{
  sections: [
    { title: "현재 상태", body: "..." },
    { title: "먼저 익힐 부분", body: "..." }
  ]
}
형태로 구조화하는 방식도 검토할 것.

단,
현재 API contract와 1.6.3 호환성을 깨지 않는 범위에서 설계한다.

━━━━━━━━━━━━━━━━━━━━
6. 1.6.3 / 2.0.0 호환성
━━━━━━━━━━━━━━━━━━━━

공용 backend를 수정할 경우
1.6.3이 동일 endpoint를 사용하는지 확인한다.

기존 response contract를
갑자기 object로 바꿔 1.6.3이 깨지면 안 된다.

필요하면:
- 기존 text 필드는 유지
- 2.0.0용 optional structured field 추가
처럼 backward-compatible 방식 사용.

━━━━━━━━━━━━━━━━━━━━
7. 프롬프트 개선
━━━━━━━━━━━━━━━━━━━━

AI ENGINE / prompt builder에서
커리큘럼 검색 답변 formatting instruction을
명확하게 추가한다.

예시 방향:

- Return concise parent-facing answer.
- Use 2 to 4 short sections.
- Separate sections with blank lines.
- Keep each paragraph short.
- Avoid one long block of text.
- Do not invent swimming knowledge outside retrieved curriculum evidence.
- If current student progress is unknown, state that briefly once and continue with curriculum-based guidance.

중요:
"현재 기록된 진도는 없어..." 같은 한계 설명이
답변 전체를 지배하지 않게 한다.

한계 설명은 1~2문장으로 끝낼 것.

━━━━━━━━━━━━━━━━━━━━
8. 문장 톤
━━━━━━━━━━━━━━━━━━━━

지금보다 조금 더 정돈된 교육 안내 톤으로 변경.

지양:
- "마냥 어렵다기보다"
- 장황한 연결문
- 한 문장에 너무 많은 요소 나열
- 지나치게 설명적인 말투

권장:
- 짧고 명확
- 학부모 친화적
- 교육과정 근거 중심
- 핵심 포인트 우선

━━━━━━━━━━━━━━━━━━━━
9. 실제 답변 예시 테스트
━━━━━━━━━━━━━━━━━━━━

최소 아래 질문 테스트:

1. "배영 어려워?"
2. "자유형에서 중요한 게 뭐야?"
3. "평영 발차기 왜 어려워?"
4. "접영은 언제 배우나요?"
5. "우리 아이 지금 어느 단계야?"
6. "다음에 뭘 배우게 돼?"

각 답변에서 확인:

- 문단 실제 분리
- 제목 실제 표시
- 과도한 길이 없음
- 교육과정 근거 유지
- 학생 진도 없을 때 과장하지 않음
- 모바일에서 한눈에 읽힘

━━━━━━━━━━━━━━━━━━━━
