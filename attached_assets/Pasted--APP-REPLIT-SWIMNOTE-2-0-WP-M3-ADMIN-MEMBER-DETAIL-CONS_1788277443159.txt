0. 이번 WP의 핵심 목표
==================================================

현재 관리자 회원상세는
member-detail shell + 여러 탭 구조로 분산되어 있습니다.

이번 WP에서는:

회원 목록
→ 회원 선택
→ 회원정보 상세

한 화면에서 아래로 스크롤하면서

- 회원 기본정보
- 수강정보
- 교육정보
- 출결/보강 요약
- 보호자 정보
- 피드/미디어 shortcut
- 회원 상태/관리

를 대부분 조회하고 수정할 수 있는
단일 long-scroll Member Detail로 재설계합니다.

목표는:

"회원 한 명을 관리하기 위해
여러 탭과 여러 화면을 계속 이동하는 구조 제거"

입니다.

4. DELETE 기능 의미 절대 혼동 금지
==================================================

WP-M1에서 확인:

A.

/students/:id/purge

=
개인정보 익명화
row 유지
수업기록 유지

B.

/admin/students/:id/force-delete

=
즉시 HARD DELETE
status guard 없음
위험도 매우 높음

C.

/admin/students/:id/permanent

=
archived/deleted 상태에서
confirm gate 있는 HARD DELETE

이 3개는 같은 기능이 아님.

이번 WP에서:

통합 금지
endpoint 변경 금지
semantics 변경 금지

UI label은 사용자가 의미를 명확히 이해하도록
기존 서비스 용어를 기준으로 정리.

특히 force-delete를
일반적인 "회원 탈퇴"처럼 노출하면 FAIL.

==================================================
5. FORCE DELETE 이번 WP 처리
==================================================

WP-M1에서
active 회원도 force-delete 가능한 위험이 확인되었습니다.

그러나 실제 API guard 수정은
WP-M6 예정입니다.

이번 WP에서는:

API semantics 변경 금지.

다만 관리자 UI에서
기존 force-delete가 일반적으로 쉽게 노출되어 있다면

Danger Zone 내부로 이동하고
기존 confirm 절차를 절대 약화시키지 마십시오.

API guard 추가는 WP-M6.

11. KEYBOARD / SCROLL 기존 RULE 유지
==================================================

이번 Member Detail도
기존 global rule을 반드시 따릅니다.

- long-scroll 마지막 내용까지 완전히 scroll 가능
- Safe Area 확보
- keyboard가 입력필드/저장버튼을 가리지 않음
- keyboardShouldPersistTaps 적절히 적용
- 스크롤 시 keyboard dismiss
- 버튼 tap은 keyboard가 떠 있어도 1회 tap으로 실행
- 빈 배경 tap의 전역 keyboard dismiss는
  별도 예정된 Global Keyboard Audit에서 일괄 처리하므로
  이번 WP에서 독자적인 임시 전역 hack 금지
