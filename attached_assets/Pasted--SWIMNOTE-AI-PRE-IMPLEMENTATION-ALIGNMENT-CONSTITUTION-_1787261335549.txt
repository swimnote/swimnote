# 27. Replit이 반드시 의견을 내야 하는 항목

다음에 대해서는 단순 AGREE뿐 아니라 기술적 의견을 제출한다.

## A. APP ↔ AI ENGINE 경계

현재 역할 분리가 실제 구조와 맞는가?

맞지 않는 부분이 있다면 정확히 어디인가?

## B. Usage Recorder

기존 saveAiTrace와 provider-neutral UsageEvent를
중복 저장 없이 어떻게 하나의 contract로 맞출 것인가?

## C. Retrieval 공통 기반

Support / Curriculum / Diary / Professional Search가
서로 독립적인 과도한 검색 시스템을 만들지 않고
공통 runtime/interface를 어느 수준까지 재사용할 수 있는가?

단 대규모 리팩터링 제안 금지.

## D. Validator

AI가 반환한:

* source IDs
* student refs
* pool refs
* generation mode

등을 server가 검증하는 공통 패턴을 재사용할 수 있는가?

## E. Request ID

APP
→ API
→ AI Engine
→ Usage Log

전체를 동일 request_id로 추적하는 것이 현재 구조에서 가능한가?

## F. 실패/Timeout/Retry

AiGateway 또는 external client의 retry가
비용 Dashboard에서 실제 request_count / retry_count를 왜곡하지 않게 어떻게 기록할 것인가?
