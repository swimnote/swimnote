[WP-CS24 — Support Learning Loop & Knowledge Candidate Operations]

목적:

CS23에서 완성한 SWIMNOTE 고객지원 구조:

User
→ DIRECT_DB
→ deterministic resolver
→ Grounded GPT
→ Human

위에 실제 사용 데이터를 기반으로
Knowledge coverage가 계속 확장되는 운영 루프를 추가한다.

최종 목표:

실사용 질문
→ 분류/그룹핑
→ Candidate 생성
→ Super Admin 검토
→ 승인
→ 기존 intent/Knowledge DB 반영
→ 다음부터 DIRECT_DB 처리

단:

AUTO-CANDIDATE = 허용
AUTO-ACTIVATE = 절대 금지

최종 활성화는 반드시 Human Approval을 거친다.

7. Candidate Type — 반드시 분리
━━━━━━━━━━━━━━━━━━━━━━

Candidate는 최소 두 종류로 분리.

A. UTTERANCE_EXTENSION

정답은 이미 존재.

기존 intent_id / knowledge_id에
새 질문 표현만 추가하면 해결.

예:

기존 Intent:
PARENT_PHOTO_NOT_VISIBLE

신규 반복 질문:
“우리애 사진 왜 없어”

→ UTTERANCE_EXTENSION

B. NEW_CANONICAL

기존 Canonical Answer 어디에도
정답 자체가 존재하지 않음.

→ 새로운 Knowledge Candidate 필요.

두 타입을 절대 혼합하지 않는다.
