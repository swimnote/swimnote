일지 삭제 후 상태 표시 동기화 추가 수정 요청

현재 실제 증상:

- 지난 일지에서는 일지가 삭제됨
- 그러나 스케줄러 일정에는 계속 "일지 완료"
- 홈의 오늘 수업에도 계속 "일지 완료"

즉 삭제 데이터는 반영됐지만,
화면별 일지 작성 여부 상태가 서로 다릅니다.

다음 화면이 반드시 같은 기준을 사용하도록 수정하세요.

1. 지난 일지
2. 스케줄러 월/주/일
3. 스케줄러 날짜 상세 바텀시트
4. 홈 오늘 수업
5. 미작성 일지 카운트
6. 관리자/선생님 일지 작성 여부 표시

==================================================

1. 일지 존재 여부의 단일 기준

일지 완료 여부는 반드시 다음 조건으로만 판단하세요.

- 동일 class_group_id
- 동일 lesson_date
- is_deleted = false

삭제된 일지는 어떤 화면에서도 작성 완료로 계산하면 안 됩니다.

다음과 같은 별도 로컬 boolean을 기준으로 쓰지 마세요.

- schedule.hasDiary
- isDiaryCompleted
- diaryCompleted
- written
- completed
- local diarySet
- cached written status

이 값들이 필요하다면 활성 일지 목록에서 매번 파생되도록 하세요.

==================================================

2. 공통 키 정의

모든 화면에서 같은 키 생성 함수를 사용하세요.

예:

getDiaryKey(classGroupId, lessonDate)

반 ID와 날짜 형식이 화면마다 달라지지 않게 하세요.

확인 항목:

- class_group_id
- group_id
- schedule_id
- YYYY-MM-DD
- UTC 변환
- 현지 날짜 변환

같은 수업인데 서로 다른 키가 생성되지 않아야 합니다.

==================================================

3. 삭제 성공 후 전 화면 상태 동시 갱신

DELETE 성공 직후 다음 상태를 모두 갱신하세요.

- 지난 일지 목록에서 diary_id 제거
- active diary 목록에서 제거
- scheduler diarySet에서 해당 키 제거
- 홈 오늘 수업 상태에서 해당 키 제거
- 미작성 일지 목록 재계산
- 미작성 일지 카운트 재계산
- 관리자용 작성 상태 재계산

삭제 직후 이벤트 하나를 발행하는 방식도 가능합니다.

예:

emitDiaryChanged({
  type: "deleted",
  diaryId,
  classGroupId,
  lessonDate
})

관련 화면은 모두 이 이벤트를 받아 상태를 갱신하세요.

==================================================

4. 서버 응답 기준 전체 재조회

삭제 후 다음 API를 확인하세요.

- 지난 일지 조회
- 스케줄러 조회
- 홈 오늘 수업 조회
- 미작성 일지 조회

각 API가 자체적으로 일지 완료 여부를 계산한다면
SQL에서 반드시 삭제 조건을 적용하세요.

예:

WHERE class_diaries.is_deleted = false

LEFT JOIN을 사용하는 경우에도
삭제된 일지가 존재한다고 판단되지 않게 하세요.

특히 EXISTS, COUNT, JOIN 조건을 확인하세요.

잘못된 예:

EXISTS (
  SELECT 1
  FROM class_diaries
  WHERE class_group_id = ...
    AND lesson_date = ...
)

정상 예:

EXISTS (
  SELECT 1
  FROM class_diaries
  WHERE class_group_id = ...
    AND lesson_date = ...
    AND is_deleted = false
)

==================================================

5. 홈 화면 별도 조사

현재 홈 화면의 오늘 수업에
"일지 완료"가 계속 표시됩니다.

홈이 사용하는 실제 endpoint와 필드를 확인하세요.

보고 항목:

- endpoint
- 응답 필드명
- diaryCompleted 계산 위치
- is_deleted 조건 적용 여부
- 앱 캐시 여부
- 화면 focus 시 재조회 여부

홈 화면 진입 또는 focus 시
최신 활성 일지 상태를 다시 조회하세요.

==================================================

6. 스케줄러 별도 조사

현재 스케줄러 바텀시트에도
"일지 완료"가 계속 표시됩니다.

스케줄러가 사용하는 다음 값의 출처를 확인하세요.

- diarySet
- hasDiary
- diaryStatus
- completedDiaryIds
- writtenScheduleIds

삭제 후 해당 수업 키가 즉시 제거되어야 합니다.

그리고 앱 재실행 후 서버 조회 결과에서도
삭제 일지는 완료 상태로 계산되면 안 됩니다.

==================================================

7. 상태 문구 통일

활성 일지가 있으면:

"일지 완료"

활성 일지가 없으면:

"일지 미작성"

삭제 직후 모든 화면이 동시에
"일지 미작성"으로 변경되어야 합니다.

==================================================

8. 테스트 시나리오

같은 일지 1개로 다음을 검증하세요.

삭제 전:

- 지난 일지 카드 있음
- 스케줄러: 일지 완료
- 홈: 일지 완료
- 미작성 일지 수: 0

삭제 후:

- 지난 일지 카드 없음
- 스케줄러: 일지 미작성
- 홈: 일지 미작성
- 미작성 일지 수: 1

앱 완전 종료 후 재실행:

- 지난 일지 카드 없음
- 스케줄러: 일지 미작성
- 홈: 일지 미작성
- 미작성 일지 수: 1

새 일지 작성 후:

- 지난 일지 카드 있음
- 스케줄러: 일지 완료
- 홈: 일지 완료
- 미작성 일지 수: 0
