1. Story Diag 완전 제거

제거 대상:

- 📊 Story Diag Alert
- P0~P12 stage trace
- meta=true/false 진단 출력
- uriExists 진단 출력
- fileSize 진단 출력
- photos 진단 출력
- share=success 진단 출력
- 진단용 result object
- 진단 전용 state/ref
- 진단 전용 console log

단 실제 정상 오류 처리는 유지한다.

예:

→ 기존 안내

→ 기존 정상 사용자 Alert

capture 실패
→ "이미지 생성에 실패했습니다."

Instagram share 실패
→ 정상 사용자용 안내

진단 코드만 제거하고
실제 오류 처리 로직은 삭제하지 않는다.

4. 사진 10장 레이아웃 최종 검토
━━━━━━━━━━━━━━━━━━━━━━

현재 실기기 Story를 보면
사진 10장 + summary 이후에도
하단 여유 공간이 상당히 남는다.

사진 우선 정책이므로
9~10장 grid의 사진 높이를
현재 70px × 2행에서
조금 더 키울 수 있는지 계산한다.

단 임의 수정하지 말고 먼저 계산:

현재:
사진영역 높이
summary 실제 사용 높이
branding 안전영역
남는 vertical space

를 보고한다.

안전하게 사진을 키워도
summary 247자 최대조건에서
잘림이 없을 경우에만
최소 확대 제안.

예:
70 → 80/85/90 중
안전한 최대값 계산.

본문 공간을 침범하거나
요약 길이를 다시 줄여야 한다면
현재 70 유지.

사진 확대는 별도 승인 전 적용 금지.
