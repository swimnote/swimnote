다음 중 정확히 어디에서 끊기는지 확정한다.

① NoticePopup mount 안 됨

② fetchAndShow 실행 안 됨

③ /notices/pending 요청 안 나감

④ pending 요청은 나가지만 인증/role/pool 문제로 실패

⑤ pending 응답이 빈 배열

⑥ pending 응답에는 notice가 있음

⑦ setNotice까지 실행

⑧ setVisible(true)까지 실행

⑨ visible=true render까지 실행

⑩ RN Modal presentation 실패

⑪ Modal onShow까지 실행

현재 notice_dismissals=0이므로
⑪까지 실제 도달했다면 /seen 실패 가능성도 별도로 확인한다.

"코드를 읽어보면 정상이어야 한다"는 결론 금지.

━━━━━━━━━━━━━━━━━━━━━━
1. 실제 RootNav 구조 재확인
━━━━━━━━━━━━━━━━━━━━━━

NoticePopup JSX가 정확히 어느 return branch에 존재하는지 확인한다.

특히:

if (isLoading) return <AppLoadingScreen />;

이후 실제 navigator를 반환하는 JSX 안에
NoticePopup이 정말 존재하는지 확인한다.

다음 값 변화도 추적:

- token
- kind
- isLoading
- NoticePopup mount/unmount
- fetchAndShow callback 재생성
- fetchAndShow를 호출하는 effect 재실행

useCallback dependency에 isLoading이 있다는 것과
실제 useEffect가 다시 실행되는 것은 별개의 문제다.

fetchAndShow를 호출하는 실제 effect의 dependency를
그대로 확인해서 보고한다.

━━━━━━━━━━━━━━━━━━━━━━
2. pending API eligibility를 추정하지 말 것
━━━━━━━━━━━━━━━━━━━━━━

보고서에는

"/notices/pending 쿼리는 show_banner 조건이 없으므로
해당 공지를 정상 반환해야 함"

이라고 되어 있다.

이번에는 "해야 함"으로 끝내지 마라.

실제 테스트 대상 role/pool/user 조건으로
pending eligibility를 서버 로직/테스트에서 재현해서

실제 반환 결과를 확인한다.

확인:

- user role
- canonical role
- pool_id
- notice target_roles
- pool scope
- starts_at
- ends_at
- status
- dismissal NOT EXISTS

그리고 최종 결과:

또는

을 확정한다.

3. 런타임 진단 instrumentation
━━━━━━━━━━━━━━━━━━━━━━

현재처럼 silent failure가 반복되고 있으므로
NoticePopup lifecycle에 최소한의 진단 로그를 넣어라.

개인정보/토큰/공지 본문은 로그에 남기지 않는다.

구분 가능한 event만 기록:

NOTICE_POPUP_MOUNT
NOTICE_POPUP_READY
NOTICE_PENDING_REQUEST
NOTICE_PENDING_STATUS
NOTICE_PENDING_COUNT
NOTICE_PENDING_SELECTED
NOTICE_VISIBLE_SET
NOTICE_MODAL_RENDER
NOTICE_MODAL_ONSHOW
NOTICE_SEEN_REQUEST
NOTICE_SEEN_STATUS
NOTICE_POPUP_ERROR

필요한 경우 role 정도만 허용.
token, 이름, 전화번호, 공지 내용 등 PII 금지.

이 로그로 다음 실기기 실행에서
어디까지 실행됐는지 한 번에 판별 가능해야 한다.

기존 logging infrastructure가 있으면 그것을 사용하고,
새 대규모 시스템을 만들지 마라.

4. RN Modal presentation 경로 조사
━━━━━━━━━━━━━━━━━━━━━━

setVisible(true)까지 도달한다면
그 다음은 Modal 문제다.

확인:

- NoticePopup의 Modal JSX가 visible state를 실제 사용하고 있는지
- 조건부 return 때문에 Modal 자체가 render되지 않는지
- 동시에 열려 있는 다른 Modal 존재 여부
- RootNav/navigation transition과 충돌 여부
- onShow
- onDismiss
- visible state가 바로 false로 변경되는 코드
- cleanup effect
- AppState listener
- navigation listener

특히 visible을 false로 만드는 모든 코드 경로를 찾아라.
