7. Android 전용 확인
============================================================

현재 실제 장애 제보가 Android에도 있으므로
Android를 별도로 깊게 확인.

검사:

- API URL이 iOS와 동일한지
- https 사용 여부
- Android networkSecurityConfig
- cleartextTraffic 설정
- AndroidManifest 관련 네트워크 권한
- INTERNET permission
- Expo/RN fetch 차이
- AbortController
- TLS/SSL 호환
- IPv4/IPv6 관련 코드/설정
- platform conditional API base
- production/dev API 분기
- OTA runtime/channel 차이
- Android만 다른 environment variable을 읽는지
- Android bundle에 localhost/dev URL이 들어갈 가능성
- login fetch 예외가 network_error로 매핑되는 조건

특히:

"서버에 연결할 수 없습니다"

문구가 정확히 어떤 catch branch에서 발생하는지 확인하고

다음 중 무엇을 전부 같은 문구로 처리하는지 분리 보고:

- DNS failure
- TLS failure
- fetch reject
- timeout
- invalid JSON
- HTTP 5xx
- post-login error
- other exception

10. POST-LOGIN 오류 구분
============================================================

로그인 HTTP 요청 자체가 성공한 뒤
후속 처리에서 예외가 나면서

"서버에 연결할 수 없습니다"

로 잘못 보일 가능성이 있는지
세 클라이언트 각각 확인.

검사 대상 예:

- session/token 저장
- user parsing
- role parsing
- pool fetch
- subscription fetch
- RevenueCat init
- navigation
- AsyncStorage
- SecureStore
- profile fetch
- post-login background request

각 버전에서
HTTP login 성공 이후 발생한 오류가
network_error로 합쳐지는지 확인.

12. 장애 원인 분류
============================================================

각 클라이언트에 대해 다음 중 하나로 판정:

A.

B.
SERVER route/contract incompatibility

C.
SERVER 5xx/availability 문제

D.
SERVER는 정상 응답하지만 CLIENT parsing/error mapping 문제

E.
로그인 HTTP 성공 후 POST-LOGIN 문제

F.
현재 코드/서버 기준 문제 없음,
과거 transient availability 가능성

G.
증거 부족 / UNCONFIRMED

근거 없는 결론 금지.
