3. SAFE INSERT 방식 우선 검토
━━━━━━━━━━━━━━━━━━━━

가장 우선:

parameterized query / bound values

방식으로 바꿀 수 있는지 검토.

목표:

Production row 값을
JavaScript에서 직접 PostgreSQL literal 문자열로
조립하지 않고 DB driver가 serialize하도록 한다.

예:

INSERT INTO table (col1,col2,...)
VALUES ($1,$2,...)

또는 현재 Drizzle/sql API에서 지원하는
parameter binding 방식.

identifier(table/column)는
허용된 sync table 목록과 Production row keys를
검증한 뒤 identifier/raw 처리 가능.

값(value)은 반드시 parameter binding 우선.

━━━━━━━━━━━━━━━━━━━━

6. pool_credits graceful skip
━━━━━━━━━━━━━━━━━━━━

pool_credits 삭제 금지.

HOT_SYNC_TABLES에서도 제거 금지.

Production SELECT 시
undefined_table / relation does not exist이면:

LAZY_TABLE_NOT_CREATED

로 분류하고 정상 skip.

중요:

단순히 모든 relation does not exist를
무조건 성공 처리하면 안 됨.

해당 table이
명시적으로 lazy-init 허용 목록에 있을 때만
graceful skip.

현재 허용:

pool_credits

그 외 sync 대상 table missing은
정상 오류로 유지.

즉:

LAZY_SYNC_TABLES = new Set(["pool_credits"])

같은 명시적 구조 권장.

7. unsafe stub auto-create 처리
━━━━━━━━━━━━━━━━━━━━

CREATE TABLE IF NOT EXISTS ...

Production rows > 0이면:

AUTO_CREATE_STUB 금지.

임의 column1 stub 생성 금지.

단 현재 수리된 10개 테이블을
다시 변경하지 말 것.
