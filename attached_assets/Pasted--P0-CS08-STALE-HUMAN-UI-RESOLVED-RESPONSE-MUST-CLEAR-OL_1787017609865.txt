[P0-CS08-STALE-HUMAN-UI — RESOLVED RESPONSE MUST CLEAR OLD HUMAN_REQUIRED PRESENTATION]

실제 production iPhone / parent_account / normal mode 검증 결과:

첫 질문:
"스윔노트X에 대해 알려줘"
→ 당시 Knowledge 없음
→ NO_MATCH
→ HUMAN_REQUIRED

이후 ki_x_mode_intro ACTIVE 승인.

두 번째 같은 질문:
→ 승인된 X MODE FAQ 답변이 실제 앱에 정상 표시됨.

실제 화면:
- FAQ 답변 표시 = YES
- 그런데 이전 HUMAN_REQUIRED UI가 그대로 남음:
  1. "문의가 접수되었습니다. 운영팀이 확인 후 답변드립니다."
  2. "상담사에게 문의하기"
  3. "상담사가 확인 중입니다. 잠시 기다려주세요."

목적:

정상 deterministic/FAQ 답변으로 해결된 이후
이전 HUMAN_REQUIRED 상태/legacy presentation이
현재 conversation UI에 stale하게 남지 않도록 수정한다.

신규 AI 기능 개발 금지.
Knowledge 수정 금지.
X Mode Knowledge 변경 금지.

3. HUMAN ESCALATION SEMANTICS
==================================================

중요:

사용자가 실제로 상담사 연결을 요청해서
human ticket이 이미 활성 상태인 경우와

자동 NO_MATCH 때문에
HUMAN_REQUIRED가 된 경우를 구분.

사용자가 실제 상담사를 요청한 상태를
AI 답변 하나로 임의 취소하면 안 됨.

따라서 확인:

HUMAN_REQUESTED_BY_USER =
ACTIVE_HUMAN_TICKET =
AUTO_HUMAN_REQUIRED_ONLY =

자동 fallback만 있었고
human agent workflow가 실제 시작되지 않았다면
정상 FAQ 응답 후 AI_RESPONDED 복구 가능.

==================================================
5. LEGACY ACK
==================================================

현재 legacy 문구:

"문의가 접수되었습니다. 운영팀이 확인 후 답변드립니다."

가 단순히
system message 없음 → fallback

조건으로 표시되는지 확인.

정상 AI/FAQ response가 이미 존재하면
이 fallback을 표시하지 않는다.

추천 조건 concept:

showLegacyAck =
human escalation이 실제 active
AND
현재 conversation에 successful AI/deterministic response가
escalation 이후 존재하지 않음

실제 구조에 맞게 최소 수정.

==================================================
6. HUMAN CARD
==================================================

"상담사에게 문의하기"

카드는 다음 경우만 표시:

- 현재 answer가 LOW/no_evidence
- requires_human=true
- 실제 current case state가 HUMAN_REQUIRED

정상 FAQ RESOLVED 후에는 숨김.

과거 message 하나가 LOW였다는 이유만으로
영구 표시 금지.
