[WP-CS24 — Support Learning Loop & Knowledge Candidate Operations]

목적:

CS23에서 완성한 고객지원 시스템을 실제 운영하면서 발생하는:

NO_MATCH
AMBIGUOUS
GPT_FALLBACK
HUMAN 문의

를 자동 수집하고 분석하여,

새로운:

Canonical Answer Candidate
Utterance Candidate

로 승격할 수 있는 운영 루프를 구축한다.

핵심:

사용자가 고객센터를 많이 사용할수록

DIRECT DB 해결률 ↑
GPT 호출률 ↓
Human 문의율 ↓

가 되도록 만든다.

단:

AI 또는 시스템이 새로운 Knowledge를 자동 ACTIVE 해서는 안 된다.

최종 활성화는 반드시 Human Approval을 거친다.

0. 확정 운영 구조
━━━━━━━━━━━━━━━━━━━━━━

현재 Production:

User Question

→ DIRECT DB
→ 기존 deterministic resolver
→ Grounded GPT
→ Human

완성.

이제 다음 운영 Layer 추가:

실사용 Query Log

→ unresolved/low-confidence 분류

→ 반복성 분석

→ Knowledge Candidate

→ Super Admin Review

→ 승인

→ Canonical Answer / Utterance DB

→ 이후 Direct DB 처리

4. 후보 생성 조건
━━━━━━━━━━━━━━━━━━━━━━

무조건 모든 NO_MATCH를 Candidate로 만들지 않는다.

Candidate 가능 signal:

동일/유사 질문 반복
Human 문의 반복
GPT fallback 반복
기존 Answer에 새로운 표현이 반복
현재 Intent에 높은 유사도지만 Direct threshold 미달
Super Admin이 직접 Candidate 지정

예:

"사진이 없어졌어요"
"아이 사진 안떠요"
"사진이 안보여"

가 같은 실제 원인/정답으로 확인되면
하나의 intent candidate로 grouping 가능.

5. 기존 INTENT 확장 vs 신규 INTENT
━━━━━━━━━━━━━━━━━━━━━━

Candidate를 두 종류로 분류.

A. UTTERANCE_EXTENSION

기존 정답은 이미 존재.

새로운 질문 표현만 추가하면 해결.

예:

기존:
PARENT_PHOTO_NOT_VISIBLE

새 질문:
"우리애 사진 왜 없어"

→ 기존 Intent utterance 후보.

B. NEW_CANONICAL

기존 72개 Answer 어디에도 해당 정답이 없음.

→ 새로운 Canonical Answer Candidate 필요.

둘을 혼동하지 말 것.

━━━━━━━━━━━━━━━━━━━━━━
6. AMBIGUOUS
━━━━━━━━━━━━━━━━━━━━━━

다음과 같은 질문:

"가격"
"사진"
"보강"
"안돼요"

는 반복된다고 무조건 utterance로 승격 금지.

문맥 없이 여러 Intent로 갈 수 있으면:

AMBIGUOUS

유지.

필요하면 향후 clarification UX 후보로 기록.

예:

"사진이 어떤 문제인가요?"

* 사진이 안 보여요
* 사진 업로드가 안 돼요

이번 WP에서는 clarification UI를 새로 만들 필요 없음.

필요 여부만 분석.
