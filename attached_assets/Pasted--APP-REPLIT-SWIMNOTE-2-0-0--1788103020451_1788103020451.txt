[SWIMNOTE 2.0.0 — 학부모 홈 현재 모자레벨 표시 + 선생님 레벨 변경 즉시 연동]

목적:
현재 선생님 모드에서 학생 모자레벨(current level)을 변경하는 기능은 존재하지만,
학부모 X 홈에서는 현재 모자레벨을 직접 확인할 수 있는 UI가 없다.

따라서 학부모 홈의 기존

"교육과정 진행도"

영역에
현재 학생의 모자레벨을 세련된 색상 가로선으로 추가한다.

이 기능은 단순 UI 표시가 아니라

선생님 레벨 변경
→ 학생 current level 저장
→ 학부모 홈 현재 모자레벨 표시
→ 향후 성장리포트/AI 리포트/성장 데이터 참조

로 이어지는 공통 레벨 데이터 연결점으로 사용한다.

중요:
이번 작업은 새로운 레벨 시스템을 만드는 것이 아니다.
이미 존재하는 pool별 레벨 설정과 학생 current level을 그대로 사용한다.

━━━━━━━━━━━━━━━━━━━━
1. 먼저 기존 데이터 흐름 확인
━━━━━━━━━━━━━━━━━━━━

추측하지 말고 실제 코드 확인.

확인:

1. 선생님 학생 레벨 변경 API
2. 학생 current level 저장 필드
3. pool_level_settings 구조
4. 각 level의
   - order
   - name
   - color
   또는 대응 색상 필드
5. 학부모가 현재 레벨을 조회하는 기존 API
6. parent home에서 이미 받아오는 student 데이터
7. 교육과정 진행도 게이지의 실제 데이터 source
8. parent home focus/resume 시 데이터 refresh 구조

이미 확인된 관련 endpoint 후보:

Teacher:
GET /teacher/students/:id/level
PATCH /teacher/students/:id/level

Parent:
GET /parent/students/:id/level-info

하지만 실제 parent home에서 무엇을 사용 중인지는 코드 기준으로 확인한다.

━━━━━━━━━━━━━━━━━━━━
2. Source of Truth
━━━━━━━━━━━━━━━━━━━━

모자레벨의 source of truth는
선생님이 지정한 학생의 실제 current level이다.

절대 금지:

- 교육과정 진행률로 레벨 추정
- 출석 횟수로 자동 계산
- 수업일지로 자동 승급
- AI가 레벨 추정
- 학부모 화면에서 별도 level state 생성

반드시:

student current level
+
해당 pool의 pool_level_settings

를 기준으로 표시한다.

즉 수영장마다 레벨 이름/색상이 달라도
해당 수영장 설정을 그대로 사용해야 한다.

━━━━━━━━━━━━━━━━━━━━
3. 학부모 홈 UI 위치
━━━━━━━━━━━━━━━━━━━━

첨부된 현재 X Parent Home 기준.

현재 영역:

교육과정 진행도

[기존 progress gauge]

진행 정보가 쌓이는 중입니다

이 영역의 "교육과정 진행도" 제목 줄에
현재 모자레벨 표시를 추가한다.

대규모 카드 추가 금지.
현재 화면 구조를 깨지 않는다.

목표 디자인:

교육과정 진행도        ━━━━━━━
                         ↑
                  현재 모자레벨 색상

그리고 그 아래:

━━━━━━━━━━━━━━━━━━━━━━━━
기존 교육과정 진행도 게이지

즉:

상단 작은 색상선 = 현재 모자레벨
하단 긴 게이지 = 교육과정 진행도

두 개의 의미를 명확히 분리한다.

━━━━━━━━━━━━━━━━━━━━
4. 모자레벨 표시 디자인
━━━━━━━━━━━━━━━━━━━━

현재 모자레벨 표시선:

- 교육과정 진행도 제목과 같은 row
- 제목 오른쪽 여백 이후 배치
- 지나치게 길지 않음
- 기존 progress bar와 비슷한 두께
- 둥근 radius
- 현재 pool_level_settings의 실제 level color 사용
- 화면 전체 색상 체계를 해치지 않게 최소 표현

가능하면 색상선 옆 또는 위에
현재 레벨 이름을 작게 표시하는 방안도 검토.

예:

교육과정 진행도     빨간모자 ━━━━━

또는

교육과정 진행도          ━━━━━
                       빨간모자

단,
화면이 난잡해지면 level name은 생략 가능.

핵심은
"현재 모자 색상"이 한눈에 보이는 것.

기존 네이비/민트 디자인 시스템은 건드리지 않는다.

━━━━━━━━━━━━━━━━━━━━
5. 레벨 색상
━━━━━━━━━━━━━━━━━━━━

색상 하드코딩 금지.

WHITE / BLUE / RED 같은 전역 레벨 가정 금지.

반드시 해당 수영장의:

pool_level_settings

에서 현재 학생 current level에 대응되는
실제 configured color를 사용한다.

수영장마다:

- 레벨 이름
- 단계 수
- 색상
- 순서

가 다를 수 있다는 전제로 구현한다.

색상값이 없거나 잘못된 경우에는
앱 crash 금지.

fallback은 기존 neutral progress 색상 계열 사용.

━━━━━━━━━━━━━━━━━━━━
6. 실시간/즉시 반영 요구
━━━━━━━━━━━━━━━━━━━━

중요:

선생님이 학생 레벨을 변경하면
학부모 홈의 모자레벨 표시도 가능한 한 즉시 바뀌어야 한다.

현재 레벨 stale-cache 버그 수정:

- parent level-info GET _noCache: true
- teacher level GET _noCache: true

가 이미 2.0.0에 반영되어 있음.

관련 수정 commit:
3ca5d1df

따라서 parent home에서도
stale cache를 다시 사용하지 않도록 한다.

먼저 기존 앱에
level change realtime event / websocket / notification invalidation /
query invalidation 구조가 있는지 확인한다.

우선순위:

1. 기존 realtime/event invalidation 구조가 있다면 재사용
2. parent home focus/resume 시 no-cache refresh
3. 홈이 현재 열려 있는 상태에서도 기존 event mechanism으로 갱신

새로운 대형 realtime infrastructure는 이번 작업에서 만들지 않는다.

기존 구조로 현재 열린 화면의 즉시 반영이 불가능하다면
그 사실을 완료보고에 명확히 적고,
가장 가벼운 안전한 refresh 방식을 적용한다.

"즉시 반영됐다"고 허위 보고하지 않는다.

━━━━━━━━━━━━━━━━━━━━
7. Parent Home 데이터 연결
━━━━━━━━━━━━━━━━━━━━

현재 parent home이 level-info를 받지 않는다면
가장 작은 방식으로 연결한다.

우선 검토:

기존 parent home student summary response에
current level 정보가 이미 있는지 확인.

있으면 재사용.

없으면 기존:

GET /parent/students/:id/level-info

를 재사용하는 것을 우선 검토.

불필요하게 신규 endpoint 만들지 않는다.

필요 데이터:

- current level identifier/order
- current level name
- current level color
- pool level setting mapping

API breaking change 금지.

1.6.3 공용 contract 깨지지 않게 한다.

━━━━━━━━━━━━━━━━━━━━
8. 기존 교육과정 게이지는 건드리지 않는다
━━━━━━━━━━━━━━━━━━━━

현재 교육과정 진행도 게이지가
실제로 작동하는지에 대해서는 이번 작업에서 기능 수정하지 않는다.

사용자 요청상:
게이지 동작 검증은 별도 후속 작업으로 진행한다.

이번 작업에서는:

- 게이지 위치 유지
- 게이지 계산 로직 유지
- 게이지 데이터 source 변경 금지

모자레벨 표시만 위쪽에 독립적으로 추가한다.

단,
코드 조사 중 명백한 crash/잘못된 연결을 발견하면
수정하지 말고 완료보고에 별도 기록한다.

━━━━━━━━━━━━━━━━━━━━

━━━━━━━━━━━━━━━━━━━━

향후 리포트와 연결될 수 있도록

화면 전용 임시 데이터가 아니라
기존 canonical student level 데이터를 사용한다.

향후:

AI 성장리포트
AI 인사이트 전략 리포트
Growth Event
레벨업 기록
교육과정 해석

등에서 같은 student level을 참조할 수 있어야 한다.

이번 작업에서 리포트 기능 자체는 수정하지 않는다.

10. 테스트 시나리오
━━━━━━━━━━━━━━━━━━━━

최소 테스트:

CASE 1
현재 레벨 존재
→ 해당 색상선 정상 표시

CASE 2
현재 레벨 변경
→ teacher PATCH 성공
→ parent home refresh
→ 새 색상 반영

CASE 3
WHITE → RED 등 색상이 완전히 다른 레벨 변경
→ 잘못된 이전 색상 남지 않음

CASE 4
다른 pool
→ 해당 pool의 level settings 사용

CASE 5
current level 없음
→ crash 없이 neutral/미설정 처리

CASE 6
level color 없음
→ fallback 정상

CASE 7
학부모가 다른 자녀로 전환
→ 각 자녀의 current level 색상 정상 변경

CASE 8
앱 종료 없이 parent home 재진입
→ 최신 레벨 표시

CASE 9
기존 교육과정 progress gauge
→ 기존 동작 회귀 없음

CASE 10
1.6.3 API contract
→ 영향 없음
