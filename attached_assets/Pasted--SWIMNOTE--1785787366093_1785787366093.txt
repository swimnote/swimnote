[SWIMNOTE 회원가입 수영장 검색 — 최종 배포 승인]

현재 완료 보고서의 수정 내용을 승인한다.

승인 대상:

- 검색어 없는 전체 수영장 목록 비노출
- 이름 전방일치 검색
- 서버 최대 20개 제한
- 전화번호 제거
- 상세 주소를 최소 지역 정보로 축약
- 300ms debounce
- AbortController 요청 취소
- unmount 시 timer·request 정리
- 검색 결과에서 선택한 pool_id만 가입 요청에 사용
- 선택 없이 가입 진행 차단

수정 대상 파일:

- artifacts/api-server/src/routes/pools.ts
- artifacts/swim-app/app/(auth)/signup.tsx

다른 회원가입 단계는 수정하지 않는다.

━━━━━━━━━━━━━━━━━━━━━━
STEP 1. 배포 전 최종 확인
━━━━━━━━━━━━━━━━━━━━━━

1. 실제 swimming_pools 스키마에서 다음 컬럼 존재 여부만 확인한다.

- deleted_at
- is_deleted
- is_active
- status

실제 존재하는 비활성·삭제 컬럼이 있으면 public-search SQL에 필터를 추가한다.

예:

AND deleted_at IS NULL
AND is_active = true

존재하지 않는 컬럼은 임의로 추가하거나 SQL에서 사용하지 않는다.

2. 다음을 재확인한다.

- query 없음 → []
- 공백 query → []
- name ILIKE query || '%'
- 주소 검색 없음
- phone 응답 없음
- LIMIT 20
- 상세 주소가 응답에 포함되지 않음
- 가입 요청은 selectedPool.id만 사용

3. 첨부 이미지·지시문 파일은 Commit 대상에서 제외한다.

4. 현재 브랜치와 상태를 보고한다.

- branch
- HEAD
- origin SHA
- git status --short

충돌이나 예상하지 못한 변경이 있으면 배포하지 말고 중단한다.

━━━━━━━━━━━━━━━━━━━━━━
STEP 2. Commit 및 Push
━━━━━━━━━━━━━━━━━━━━━━

의도한 두 파일만 Commit한다.

Commit 메시지:

fix: restrict public pool search and minimize signup exposure

금지:

- force push
- rebase
- reset
- unrelated 파일 포함
- attached_assets 포함

정상 Push 후 다음을 확인한다.

- origin 브랜치에 새 Commit 반영
- 로컬 HEAD와 origin SHA 일치
- Push 충돌 없음

━━━━━━━━━━━━━━━━━━━━━━
STEP 3. Render 서버 배포
━━━━━━━━━━━━━━━━━━━━━━

서버 변경이 있으므로 Render 배포를 먼저 완료한다.

확인 항목:

1. 빌드 성공
2. 서버 시작 성공
3. Migration 실행 없음
4. pools.ts 라우트 등록 정상
5. health check 정상
6. 반복되는 5xx 오류 없음

서버 배포 실패 시 OTA 금지.

━━━━━━━━━━━━━━━━━━━━━━
STEP 4. 운영 서버 검색 API 검증
━━━━━━━━━━━━━━━━━━━━━━

GET /pools/public-search를 직접 검증한다.

필수 테스트:

1. query 없음

GET /pools/public-search

예상:

{
  "success": true,
  "data": []
}

2. 공백 검색

GET /pools/public-search?name=%20%20

예상: 빈 배열

3. 전방일치 검색

GET /pools/public-search?name=토

예상:

- ‘토’로 시작하는 수영장만 반환
- 중간에 ‘토’가 포함된 수영장은 제외

4. 더 긴 검색어

GET /pools/public-search?name=토이키즈

예상: 결과가 더 좁혀짐

5. 응답 필드 확인

허용:

- id
- name
- 축약된 address

금지:

- phone
- 상세주소
- 대표자 정보
- 회원 수
- 요금제
- X모드 정보

6. 결과 개수 20개 이하 확인

API 검증 결과가 정상일 때만 다음 단계로 진행한다.

━━━━━━━━━━━━━━━━━━━━━━
STEP 5. 앱 OTA 배포
━━━━━━━━━━━━━━━━━━━━━━

운영 앱이 실제 사용하는 Expo/EAS channel과 branch를 기존 배포 이력에서 확인한다.

잘못된 channel에 임의 배포하지 않는다.

OTA 메시지:

fix: hide full pool list and add prefix search on signup

배포 후 제출:

- update ID
- channel
- branch
- runtime version
- 배포 시각
- 포함 Commit SHA

새 네이티브 빌드는 생성하지 않는다.

━━━━━━━━━━━━━━━━━━━━━━
STEP 6. 운영 앱 확인
━━━━━━━━━━━━━━━━━━━━━━

앱을 완전히 종료한 뒤 다시 실행하여 OTA를 적용한다.

학부모 회원가입과 선생님 회원가입 양쪽에서 확인한다.

1. 추가정보 단계 최초 진입
   - 수영장 목록이 보이지 않음

2. 검색어 없음
   - “등록된 수영장 이름을 입력해 주세요” 표시
   - 전체 목록 없음

3. ‘토’ 입력
   - ‘토’로 시작하는 수영장만 표시

4. ‘토이’ 입력
   - 결과가 더 좁혀짐

5. ‘키즈’ 입력
   - ‘토이키즈…’는 표시되지 않음
   - ‘키즈…’로 시작하는 결과만 표시

6. 빠르게 여러 글자 입력
   - 이전 결과가 최신 결과를 덮어쓰지 않음

7. 검색 결과 없음
   - 정확한 빈 결과 안내

8. 수영장 선택
   - 선택 카드 정상 표시
   - 목록 닫힘

9. 선택 취소
   - 검색창으로 복귀

10. 수영장을 선택하지 않고 가입 시도
    - 가입 차단
    - “검색 결과에서 수영장을 선택해 주세요” 표시

11. 결과 카드
    - 전화번호 없음
    - 상세 도로명·번지 없음
    - 수영장 이름과 최소 지역만 표시

12. 실제 가입
    - 선택한 swimming_pool_id로 정상 처리

━━━━━━━━━━━━━━━━━━━━━━
STEP 7. 문제 발생 시 롤백
━━━━━━━━━━━━━━━━━━━━━━

서버 문제:

- 직전 정상 Commit을 대상으로 revert commit 생성
- force push 금지
- Render 재배포

앱 문제:

- 직전 정상 Commit 기준으로 동일 channel에 새 OTA 발행
- 기존 Update 삭제만으로 롤백 처리하지 않음

DB Migration이 없으므로 스키마 롤백은 필요 없다.

━━━━━━━━━━━━━━━━━━━━━━

━━━━━━━━━━━━━━━━━━━━━━
