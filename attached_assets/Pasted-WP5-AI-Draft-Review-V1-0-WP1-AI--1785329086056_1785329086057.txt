WP5 — AI 응답 Draft Review 화면 구현 및 검증

설계도 V1.0을 고정 기준으로 작업한다.

현재 상태

- WP1 완료: AI 모달 열기·닫기·백드롭·스와이프·재진입·하단 탭 정상
- WP2 코드 완료: Voice Recorder, 새 EAS 바이너리 검증 대기
- WP3 조건부 완료: Whisper STT 코드·Preview OTA 완료, 실기기 E2E는 새 바이너리 대기
- WP4 완료: Diary Generate Request/Response Contract 검증 완료, 기존 구현이 설계도와 일치

이번 WP에서는 AI Engine 응답이 Draft Review 화면에 정확하고 안전하게 표시되는지만 검증한다.

이번 WP에서 자동 Insert와 Save는 절대 수행하지 않는다.

──────────────────────────────────
1. 작업 시작 전 Git 확인
──────────────────────────────────

작업 시작 전 반드시 아래 결과를 출력한다.

- git status
- git rev-parse HEAD
- git branch --show-current
- git branch -vv
- git log --oneline -10

작업 브랜치가 production 브랜치가 아닌지 확인한다.

작업 트리에 untracked 파일이 있으면 무엇인지 먼저 보고하고 임의 삭제하지 않는다.

──────────────────────────────────

──────────────────────────────────

↓

Student Drafts

↓

↓

수정 가능 상태

이번 WP의 종료 지점은 “교사가 공통 Draft와 학생별 Draft를 화면에서 확인하고 수정할 수 있는 상태”다.

Insert와 Save는 다음 WP에서 다룬다.

──────────────────────────────────
4. Draft 데이터 구조 확인
──────────────────────────────────

다음 데이터가 어디에 저장되는지 확인한다.

- common Draft
- students Draft
- original response
- normalized response
- editable common value
- editable student values
- generatedStudentsRef
- resultText
- generatedStudents
- currentRequestId
- selected student context

다음 사항을 확인한다.

- Common Draft와 Student Draft가 서로 분리되어 있는가
- AI Engine 원본 응답을 직접 수정하지 않고 UI 상태를 별도로 갖는가
- 수정 후 다시 렌더링해도 값이 유지되는가
- 모달을 닫기 전까지 Draft가 유지되는가
- 새 Generate 요청 시 이전 Draft 처리 정책이 명확한가
- Retry 시 이전 Draft를 무조건 삭제하지 않는가
- 실패 응답이 기존 Draft를 덮어쓰지 않는가

──────────────────────────────────
5. Common Draft 검증
──────────────────────────────────

AI Engine 응답의

result.common

이 Draft Review 화면에 정상 표시되는지 확인한다.

반드시 확인

- string 타입 검증
- 빈 string 처리
- 공백만 있는 값 처리
- 너무 긴 텍스트 처리
- 줄바꿈 유지
- 한글 깨짐 없음
- 사용자가 직접 수정 가능
- 수정 중 Generate 재요청 차단 또는 정책 확인
- 기존 Teacher Diary 내용과 분리
- 자동 Insert 금지
- 자동 Save 금지

Common Draft가 빈 값이고 학생 Draft만 존재하는 경우에도 화면이 깨지지 않아야 한다.

──────────────────────────────────
6. Student Draft 검증
──────────────────────────────────

AI Engine 응답의

students[
  {
    student_ref,
    content
  }
]

가 학생별 Draft로 정확히 매칭되는지 확인한다.

반드시 확인

- student_ref 기준 매칭
- 학생 이름 문자열 기준 매칭 금지
- 배열 순서 기준 매칭 금지
- 중복 student_ref 처리
- unknown student_ref 처리
- 누락 student_ref 처리
- 빈 content 처리
- 공백 content 처리
- 일부 학생만 응답된 경우 처리
- 선택 학생 수와 응답 학생 수가 다른 경우 처리
- 동일 이름 학생이 있어도 ref로 구분
- 삭제되었거나 현재 목록에 없는 학생 처리
- 학생별 Draft 수정 가능
- 한 학생 수정이 다른 학생 Draft에 영향 없음
- 학생 순서가 원래 선택 순서를 유지하는지 확인

unknown student_ref가 하나라도 존재할 경우 현재 정책이 전체 응답 거부인지, unknown 항목만 제외인지 설계와 코드 기준으로 보고한다.

임의로 정책을 바꾸지 않는다.

──────────────────────────────────
7. Legacy 호환 확인
──────────────────────────────────

normalizeDiaryResponse()가 아래 legacy 응답을 허용하는지 확인한다.

- student_id
- feedback

허용한다면

- 우선순위
- 충돌 시 어떤 필드를 사용하는지
- 로그 또는 경고 여부
- UI에 동일하게 반영되는지

를 보고한다.

legacy 호환 코드를 삭제하지 않는다.

──────────────────────────────────
8. Teacher Review UI 검증
──────────────────────────────────

Teacher Review 화면에서 다음을 확인한다.

- Common Draft 영역이 명확히 구분됨
- Student Draft 영역이 학생별로 명확히 구분됨
- 학생 이름 표시
- student_ref는 사용자 화면에 직접 노출하지 않음
- TextInput 또는 편집 가능한 UI
- 키보드 정상
- 스크롤 정상
- 긴 학생 목록에서 스크롤 가능
- 작은 화면에서도 버튼이 가려지지 않음
- 키보드가 열려도 Draft 수정 가능
- 로딩 UI가 종료되고 RESULT 상태로 전환
- 오류 UI와 결과 UI가 동시에 보이지 않음
- Generate 버튼이 결과 화면에서 중복 동작하지 않음
- 닫기 버튼 정상
- 재진입 정책 확인

UI 전체 재설계는 금지한다.

현재 구조를 유지하며 깨지는 부분만 최소 수정한다.

──────────────────────────────────
9. 상태 전이 검증
──────────────────────────────────

기대 상태 전이

INPUT

↓

PROCESSING

↓

RESULT

또는

ERROR

확인 사항

- receiveResult() 호출 위치
- RESULT 진입 전에 Draft 상태 세팅 순서
- React state batch 처리 시 빈 화면 깜빡임 여부
- ERROR 후 Retry 가능
- RESULT 상태에서 Back/Edit 가능 여부
- RESULT 상태에서 다시 Generate 정책
- 모달 닫기 시 상태 초기화 정책
- 재진입 시 이전 Draft가 남는지 또는 초기화되는지
- request_id가 바뀐 응답은 표시하지 않음
- stale response가 RESULT 화면을 덮어쓰지 않음
