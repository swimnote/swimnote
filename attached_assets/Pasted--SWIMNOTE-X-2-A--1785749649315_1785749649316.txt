[SWIMNOTE 긴급 오류 조사 — 반이동 버튼 미작동 + 과거 수업명단 소급 삭제]

현재 X모드 작업은 계속 중단한다.

긴급 오류 2건을 분리해서 조사한다.

오류 A:
스케줄러 반 상세 모달에서 학생별 [반이동] 버튼을 눌러도 동작하지 않는다.

오류 B:
학생을 현재 월 기준으로 미배정 또는 연기 처리하면,
처리일 이전의 과거 수업일 학생 목록에서도 해당 학생 이름이 모두 사라진다.

실제 확인 사례:
- 8월에 학생 연기 처리
- 7월 25일 과거 수업 상세에서도 학생 이름 삭제됨
- 과거 수업일의 당시 학생명단이 유지되지 않음

지금은 코드 수정 금지.
먼저 Repository와 실제 데이터 조회 흐름을 조사해서 원인보고서를 제출한다.

- 부모 ScrollView와 터치 충돌

1. 반이동 버튼 JSX 위치
2. onPress에 연결된 실제 함수
3. 전달되는 studentId, classGroupId 값

2. 오류 B — 과거 학생명단 소급 삭제 조사
━━━━━━━━━━━━━━━━━━━━━━

핵심 정책:

학생이 8월부터 연기·미배정·반이동·퇴원 처리되더라도
7월 등 과거에 실제로 해당 반에 소속되어 수업한 날짜의 학생명단은 유지되어야 한다.

현재 상태를 과거 날짜 전체에 소급 적용하면 안 된다.

예:

7월 25일:
학생 A가 토 10:00반 소속
→ 과거 수업명단에 학생 A 표시

8월 3일:
학생 A 연기 처리
→ 8월 이후 수업명단에서는 제외 가능
→ 7월 25일 과거 수업명단에서는 계속 표시되어야 함

B. 연기·미배정 처리

확인:

C. 과거 날짜 조회

반드시 확인:

- 현재 students.class_group_id만 보고 있는가
- 현재 status만 보고 있는가
- assignment 시작일/종료일을 비교하는가
- 과거 diary/attendance snapshot을 사용하는가
- `deleted_at IS NULL`
- `status NOT IN (...)`
조건 때문에 과거 학생까지 제외되는가

4. 가장 가능성 높은 오류 가설
━━━━━━━━━━━━━━━━━━━━━━

아래는 가설일 뿐이므로 실제 코드로 확인한다.

가설 1:
과거 수업명단을 당시 배정 이력이 아니라
현재 students.class_group_id 또는 현재 assigned_class_ids로 조회하고 있음.

가설 2:
연기·미배정 시 기존 반 배정 레코드를 hard delete하거나
현재 관계만 제거하여 과거 조회 근거가 사라짐.

가설 3:
과거 학생명단 조회 SQL에
현재 status='active'
또는 deleted_at IS NULL
또는 class_group_id=currentGroup
조건이 들어가 과거 명단까지 필터링함.

가설 4:
과거 수업에 class_diary_student_notes 또는 attendance가 있는데도
현재 학생 배정 목록과 INNER JOIN하여 현재 미배정 학생이 누락됨.

━━━━━━━━━━━━━━━━━━━━━━
5. 반드시 확정할 정책
━━━━━━━━━━━━━━━━━━━━━━

학생명단은 날짜 기준으로 조회해야 한다.

정책:

1. 과거 날짜
- 해당 날짜에 유효했던 반 배정 이력 기준
- 또는 해당 날짜에 생성된 수업·출결·일지 snapshot 기준
- 이후 연기·미배정·반이동 상태가 과거 명단을 지우면 안 됨

2. 오늘과 미래 날짜
- 현재 유효한 배정 상태 기준

3. 반이동
- 이동일 이전: 이전 반에 표시
- 이동일부터: 새 반에 표시

4. 연기
- 연기 시작일 이전: 기존 반에 표시
- 연기 시작일부터: 제외 또는 연기 상태 표시

5. 미배정
- 미배정 적용일 이전: 기존 반에 표시
- 적용일부터: 반 명단에서 제외

6. 퇴원·삭제
- 과거 수업·출결·일지 이력은 보존
- 현재·미래 명단에서는 제외

6. 임의 수정 금지
━━━━━━━━━━━━━━━━━━━━━━

다음 방식으로 급하게 막지 않는다.

금지:

- 과거 날짜면 모든 학생을 강제로 표시
- status 필터만 제거
- deleted_at 필터만 제거
- 현재 class_group_id 조건만 제거
- 학생 전체 목록을 과거 화면에 표시
- UI에서 이름을 임시 복구
- 과거 일지 데이터를 새로 생성
- 기존 출결·일지 기록 변경
- 배정 이력 없이 날짜만 하드코딩
- 반이동 버튼을 별도 화면으로 우회

과거 명단의 기준 데이터가 무엇인지 먼저 확정해야 한다.
