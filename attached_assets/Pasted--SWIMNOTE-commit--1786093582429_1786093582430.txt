[SWIMNOTE 보강 기능 즉시 복원 — 최종 실행 지시서]

목적:

보강 기능은 이미 완성했던 기능이다.

더 이상 과거 commit 탐색,
정상본 후보 탐색,
추측성 분석,
진단 로그 추가,
새 architecture 설계

를 반복하지 않는다.

사용자가 실제 운영 정책을 다시 확정했다.

아래 정책과 현재 구현을 정확히 대조한 뒤,
불일치하는 부분만 최소 수정하여 즉시 복원한다.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
0. 절대 확정된 보강 정책
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

정책 1 — 지난달 미처리 보강

지난달에 발생한 보강 대상이
다음 달로 넘어가도 목록에서 사라지면 안 된다.

예:

7월 미처리 보강
→ 8월에도 선생님 보강 대기 화면에 존재

기간이 지난 경우:

"기간 지난 보강"

으로 명확하게 표시한다.

일반 보강과 기간 지난 보강을
화면에서 즉시 구분할 수 있어야 한다.

기간 지난 보강도:

- 보강반 배정
- 날짜 선택
- 직접 완료
- 인계
- 기존 허용 처리

가 가능해야 한다.

expired라는 이유로 화면에서 제거하지 않는다.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. 보강 가능 날짜 범위 — 절대 확정
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

기준은 항상 KST 오늘 날짜다.

보강 선택 가능 범위:

오늘 -14일
~
오늘 +28일

즉:

과거 2주
+
오늘
+
미래 4주

범위다.

공용 정책:

getMakeupDateRange()

validateMakeupDateRange()

를 사용한다.

teacher/admin/client마다
다른 날짜 정책을 만들지 않는다.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2. 예정 결석 선보강 허용
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

결석 예정일보다 먼저 보강하는 것도 허용한다.

예:

결석 예정일:
2026-08-20

보강:
2026-08-17

→ 정상 허용.

절대 금지 조건:

makeup_date >= absence_date

또는

occurrence_date >= absence_date

같은 제약.

보강 날짜는 결석일을 기준으로 제한하지 않는다.

오직:

KST 오늘 -14일 ~ 오늘 +28일

범위 안의 실제 수업 회차인지로 판단한다.

따라서 미래 결석 예정인 학생도
오늘 기준 허용 범위 안에서
결석일보다 먼저 보강할 수 있어야 한다.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
3. eligible-occurrences 정상 동작
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Endpoint:

GET /teacher/makeups/:makeupId/eligible-occurrences

선생님이 보강반을 선택하면
해당 반의 실제 수업 회차를 불러온다.

반드시:

rangeStart = KST today - 14 days
rangeEnd   = KST today + 28 days

범위의 회차를 조회한다.

결석일 또는 expire_at 때문에
조회 범위를 좁히지 않는다.

반환된 실제 회차 중:

- 과거 2주
- 오늘
- 미래 4주

모두 표시 가능해야 한다.

예정 결석보다 앞선 날짜도 표시한다.

현재 실기기에서:

"수업 회차를 불러오지 못했습니다"

가 표시되는 것은 FAIL이다.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
4. 기간 지난 보강 목록
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

GET:

/teacher/makeups?status=waiting

정책:

waiting + expired

모두 반환한다.

expired 제외 금지.

클라이언트에서도 expired 제거 금지.

일반 보강 뒤에:

────────────
기간 지난 보강 (N건)
────────────

을 표시하고 expired 카드를 이어서 표시한다.

expired 0건:
separator 없음.

expired N건:
separator 정확히 1개.

카드 자체도 반드시 실제 화면에 렌더되어야 한다.

separator만 있고 카드가 없으면 FAIL.

10. 날짜 API 실패도 이번에 끝낸다
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

현재 실기기에서:

가 실제 발생 중이다.

따라서 현재 selectClass()와
eligible-occurrences 서버 Contract를 직접 대조한다.

확인:

Request:

makeupId
class_group_id

Response:

range
occurrences

클라이언트가 기대하는 field와
서버 실제 response field가 정확히 일치해야 한다.

Contract mismatch가 있으면
현재 공용 정책을 유지하면서 최소 수정.

500ms retry를 반복해서 증상을 숨기지 않는다.

실패의 직접 코드 원인을 찾아 바로 수정한다.
