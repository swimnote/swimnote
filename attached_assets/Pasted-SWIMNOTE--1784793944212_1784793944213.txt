SWIMNOTE 사진·영상 시스템 전체 안정화 작업

사진과 영상은 이 앱의 핵심 기능입니다.

일지 저장만 성공하고 사진 연결이 실패하거나,
선생님에게는 보이지만 학부모에게 안 보이거나,
공통 사진과 개별 사진이 누락되는 상태를 허용하지 않습니다.

이번 작업은 특정 오류 한 건만 수정하지 말고
미디어의 전체 생명주기를 전수 점검하고 안정화하세요.

==================================================
A. 확정된 서비스 정책
==================================================

1. 공통 미디어

공통 사진·영상은:

student_id = NULL

로 저장합니다.

공통 미디어는 해당 수업 일지에 연결된 모든 학생의 보호자에게 표시합니다.

2. 개별 미디어

개별 사진·영상은:

student_id = 해당 학생 ID

로 저장합니다.

해당 학생의 보호자에게만 표시합니다.

3. 학부모 표시 공식

각 학부모에게 표시되는 미디어:

공통 미디어
+
자기 자녀에게 지정된 개별 미디어

예:

공통 사진 2장

A 학생 개별 사진 3장
B 학생 개별 사진 1장
C 학생 개별 사진 6장

결과:

A 보호자 = 5장
B 보호자 = 3장
C 보호자 = 8장

다른 학생의 개별 미디어는 절대 표시하지 않습니다.

4. 연결 정책

현재 정책:

미디어 1개는 일지 1개에만 연결합니다.

이미 다른 일지에 연결된 미디어는
새 일지 첨부 선택기에서 기본적으로 선택 불가 처리하세요.

단, 앨범에서는 attached 상태여도 계속 보여야 합니다.

==================================================
C. 일지 저장과 미디어 연결 순서
==================================================

일지 저장 과정은 반드시 순차적으로 처리하세요.

권장 순서:

1. class_diary 생성
2. 생성된 diary_id 확인
3. student_notes 생성
4. 생성된 student_note ID 확인
5. 공통 미디어 연결
6. 개별 미디어 연결
7. 연결 결과 검증
8. 전체 성공 후 저장 완료 표시

사진 연결 전에 diary_id가 실제 DB에 커밋되어 있어야 합니다.

다음은 금지합니다.

- 일지 생성 요청과 미디어 연결 요청을 동시에 실행
- diary 생성 Promise 완료 전 attach 실행
- 임시 diary_id로 attach
- 클라이언트가 만든 ID만 믿고 서버 row 확인 없이 attach
- `.catch(() => {})`로 오류 무시
- 일부 첨부 실패 후 전체 성공 표시

==================================================
D. 트랜잭션 전수 수정
==================================================

프로덕션 서버 전체에서 수동 트랜잭션을 검색하세요.

검색:

db.execute(sql`BEGIN`)
db.execute(sql`COMMIT`)
db.execute(sql`ROLLBACK`)
pool.query("BEGIN")
pool.query("COMMIT")
pool.query("ROLLBACK")

pg.Pool에서 각각 다른 연결을 사용할 수 있는 방식은 금지합니다.

다음 기능을 특히 확인하세요.

- 일지 생성
- 일지 수정
- 일지 삭제
- 학생별 note 생성
- 사진 연결
- 영상 연결
- 공통 미디어 연결
- 개별 미디어 연결
- 연결 해제
- 미디어 상태 변경

반드시:

db.transaction(async tx => { ... })

또는 동일한 단일 client connection을 사용하세요.

그리고 수정 코드는 Replit 작업 공간에만 두지 말고
https://swimnote.kr/api 를 처리하는 프로덕션 백엔드에 실제 배포하세요.

==================================================
E. 원자적 저장 정책
==================================================

사용자에게 “일지 저장 완료”가 표시되려면:

- 일지 본문 저장 성공
- 학생별 내용 저장 성공
- 선택한 모든 사진 연결 성공
- 선택한 모든 영상 연결 성공

이 전부 성공해야 합니다.

선택한 미디어 중 일부가 실패하면:

1. 어떤 파일이 실패했는지 표시
2. 실패한 미디어 수 표시
3. 재시도 버튼 제공
4. 성공하지 않은 상태를 저장 완료로 표시하지 않음

권장 정책:

일지 본문이 이미 저장됐다면
“일지는 저장됐지만 미디어 2개 연결 실패”로 정확히 표시하고
연결 재시도를 제공하세요.

전체 롤백 정책을 적용할 경우에는
일지와 미디어 연결이 함께 롤백되어야 합니다.

어느 정책을 사용할지 명확하게 결정하고 보고하세요.

==================================================
F. silent error 전수 제거
==================================================

전체 코드에서 다음 패턴을 검색하세요.

.catch(() => {})
.catch(() => null)
catch (e) {}
catch {}
console.log만 하고 성공 처리
Promise.allSettled 후 실패 무시

사진·영상 업로드 또는 연결 과정의 오류는
절대 조용히 무시하지 마세요.

오류 로그 필수 항목:

[MEDIA ATTACH ERROR]

mediaId=
mediaType=
diaryId=
studentId=
statusBefore=
endpoint=
httpStatus=
responseBody=
error=
stack=

G. 선택기 정책
==================================================

첨부 선택기에 표시되는 미디어 상태를 명확히 구분하세요.

draft/uploaded/detached:
- 선택 가능

attached:
- 어느 일지에 연결됐는지 배지 표시
- 현재 정책상 다른 일지에 재선택 불가

failed:
- 실패 배지
- 재업로드 또는 삭제 가능

선택기에서 이미 연결된 사진을 골랐다가
서버 attach가 실패하는 구조를 만들지 마세요.

==================================================
H. 앨범 표시 정책
==================================================

선생님 앨범에서는 다음 상태를 모두 보여주세요.

- uploaded
- attached
- detached
- failed

단, 삭제된 미디어는 제외합니다.

attached 미디어를 숨기지 마세요.

앨범은 업로드 자산 보관함이고,
일지 연결 여부와 별개로 사진·영상이 보여야 합니다.

배지 예:

- 미첨부
- 일지 첨부됨
- 연결 해제됨
- 업로드 실패

==================================================
I. 학부모 조회 쿼리
==================================================

학부모 미디어 조회 조건을 실제 SQL까지 확인하세요.

필수 조건:

- 해당 센터
- 해당 수업 일지
- 일지 is_deleted=false
- 미디어 is_deleted=false
- 공통: media.student_id IS NULL
- 개별: media.student_id = 보호자 자녀 ID

개념적으로:

WHERE diary_id = :diaryId
AND media.is_deleted = false
AND (
  media.student_id IS NULL
  OR media.student_id = :childStudentId
)

공통 미디어 조건을 임의로 완화하지 말고,
업로드·연결 단계에서 student_id가 정확히 NULL로 저장되는지 먼저 확인하세요.

==================================================

사진만 고치고 끝내지 마세요.

영상에 대해 다음을 별도 확인하세요.

- 업로드 중 앱 백그라운드 이동
- 대용량 업로드
- 업로드 진행률
- 업로드 취소
- 네트워크 끊김 후 재시도
- 중복 업로드 방지
- 썸네일 생성
- 재생 URL
- 권한 있는 보호자만 재생
- 만료 URL 갱신
- 다운로드
- 영상 길이 및 용량
- 원본 파일명 유지 여부
- 압축 정책
- 업로드 완료 전 일지 연결 방지

영상 업로드가 완료되지 않았는데
일지에 첨부 완료로 표시하면 안 됩니다.

==================================================
K. 중복과 재시도 안전성
==================================================

업로드와 연결 API는 재시도에 안전해야 합니다.

같은 요청이 두 번 전송돼도:

- 같은 미디어 row가 중복 생성되지 않음
- 같은 diary-media 연결이 중복 생성되지 않음
- 학부모 화면에 같은 사진이 두 번 보이지 않음

idempotency key 또는 unique constraint를 검토하세요.

예:

UNIQUE(diary_id, media_id)

==================================================
L. 일지 삭제 시 미디어 정책
==================================================

일지를 삭제할 때 사진·영상을 실제 파일까지 삭제하지 마세요.

기본 정책:

- 일지 연결 해제
- media_status = detached 또는 uploaded
- 앨범에는 유지
- 학부모 일지에서는 미표시
- 이후 다른 일지에 다시 연결 가능

단, 현재 서비스 정책과 다르면 보고 후 맞추세요.

삭제 트랜잭션 안에서:

1. diary is_deleted=true
2. diary-media relation 해제
3. media 상태 갱신

이 모두 동일 트랜잭션으로 처리되어야 합니다.

O. 실제 테스트 데이터
==================================================

최소 다음 테스트를 수행하세요.

테스트 1 — 공통 사진

공통 사진 2장
학생 A, B, C

결과:
A=2
B=2
C=2

테스트 2 — 공통+개별 사진

공통 2
A 개별 3
B 개별 1
C 개별 6

결과:
A=5
B=3
C=8

테스트 3 — 영상

공통 영상 1
A 개별 영상 1

결과:
A=영상 2
B/C=공통 영상 1

테스트 4 — 일부 실패

사진 5개 중 2개 연결 실패

결과:
- 저장 완료로 거짓 표시하지 않음
- 실패 파일 특정
- 재시도 가능
- 재시도 후 중복 없음

테스트 5 — 앱 종료

업로드 또는 연결 중 앱 종료 후 재실행

결과:
- 진행 중 상태 복구
- 중복 업로드 없음
- 완료된 파일 손실 없음
- 실패 항목 재시도 가능

테스트 6 — 일지 삭제

사진/영상 포함 일지 삭제

결과:
- 학부모 일지에서 미표시
- 선생님 앨범에는 유지
- 상태 detached/uploaded
- 재첨부 가능
