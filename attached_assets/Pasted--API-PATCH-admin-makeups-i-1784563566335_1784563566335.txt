현재 보강 배정 취소 기능이 실제 운영 화면에 노출되지 않고 있습니다.

기존 조사에서 다음 API가 존재한다고 확인되었습니다.

PATCH /admin/makeups/:id/revert

하지만 실제 사용 화면인

1. 배정된보강 목록
2. 스케줄 상세 안의 보강학생 표시 영역

에서 보강 배정을 취소하고
다시 보강대기로 보내는 버튼이 보이지 않습니다.

API가 존재하는 것만으로 완료 처리하지 마세요.
실제 사용자가 접근하는 모든 관련 화면에 기능을 연결하세요.

==================================================
1. 실제 화면 경로 추적
==================================================

먼저 다음 화면이 실제로 어떤 파일과 컴포넌트를 사용하는지 추적하세요.

- 보강관리 > 배정된보강
- 스케줄 상세
- 날짜별 스케줄 팝업 또는 DaySheet
- 스케줄 안의 보강학생 카드
- 출결 화면 안의 보강학생 표시

기존 보고서의 makeups.tsx만 확인하지 말고
실제 navigation 경로에서 사용하는 화면을 모두 확인하세요.

==================================================
2. 배정된보강 목록에 버튼 추가
==================================================

배정된보강 상태의 각 항목에 다음 버튼을 표시하세요.

[배정 취소]

또는

[보강대기로 되돌리기]

버튼은 사용자가 바로 이해할 수 있는 위치에 표시하세요.

버튼 클릭 시 확인창:

“이 보강 배정을 취소하고 보강대기로 되돌리시겠습니까?”

설명:

“결석 기록과 보강 권리는 유지되며,
현재 스케줄 배정만 취소됩니다.”

확인 후:

PATCH /admin/makeups/:id/revert

호출

성공 시:

- 배정된보강 목록에서 즉시 제거
- 보강대기 목록에 즉시 표시
- 해당 스케줄의 보강학생 목록에서도 제거
- 전체 화면 새로고침 없이 로컬 상태 갱신 또는 쿼리 재요청
- 성공 토스트 표시

“보강 배정이 취소되어 보강대기로 이동했습니다.”

==================================================
3. 스케줄 상세의 보강학생에도 취소 버튼 추가
==================================================

스케줄 안에서 보강학생으로 표시되는 카드에도
배정 취소 기능을 추가하세요.

보강학생 카드 예시:

김민수
[보강]
배정 상태

[배정 취소]

이 버튼도 동일하게

PATCH /admin/makeups/:id/revert

를 사용해야 합니다.

중요:

student_id만으로 API를 호출하지 마세요.
반드시 해당 보강 건의 makeup_session_id를 사용하세요.

makeup_session_id가 현재 스케줄 API 응답에 없다면
기존 API 응답 구조를 확인하고
필요한 필드만 추가하세요.

새 보강 레코드를 만들거나
학생 전체 기록을 삭제하면 안 됩니다.

==================================================
4. 완료 상태에서는 직접 되돌리기 금지
==================================================

상태별 버튼 표시 규칙:

waiting
- 배정 취소 버튼 없음

assigned
- 배정 취소 버튼 표시

completed
- 일반 배정 취소 버튼 표시 금지

cancelled
- 배정 취소 버튼 없음

expired
- 배정 취소 버튼 없음

completed 상태를 되돌리는 기능이 필요하다면
일반 revert와 분리된 별도 기능이어야 합니다.

현재 작업에서는 assigned 상태만 보강대기로 되돌리세요.

==================================================
5. 스케줄 표시 즉시 동기화
==================================================

배정 취소 성공 후 다음 화면이 모두 동일하게 갱신되어야 합니다.

- 배정된보강
- 보강대기
- 날짜별 스케줄
- 스케줄 상세
- 출결 화면
- 일지 작성 대상

배정 취소 후 기존 스케줄 화면에
보강학생이 계속 남아 있으면 안 됩니다.

캐시를 사용하는 경우 관련 query key를 모두 invalidate 하세요.

예상 대상:

- makeups waiting
- makeups assigned
- today schedule
- schedule detail
- attendance
- makeup students
- diary students

실제 프로젝트의 query key를 추적해서 적용하세요.

==================================================
6. 데이터 보존 규칙
==================================================

배정 취소 시 유지:

- 원래 결석 기록
- 보강 권리
- 학생 정보
- 최초 결석일
- 보강 생성 기록

배정 취소 시 제거 또는 초기화:

- assigned_class_group_id
- assigned_date
- 배정 스케줄 연결값
- assigned_at
- 배정 상태 관련 값

상태:

assigned → waiting

삭제 금지:

- makeup_sessions row 자체 삭제 금지
- 결석 기록 삭제 금지
- 출결 원본 삭제 금지

==================================================
7. 필수 테스트
==================================================

테스트 1:
보강대기 학생을 미래 스케줄에 배정
→ 배정된보강 표시
→ 스케줄에 보강학생 표시

테스트 2:
배정된보강 목록에서 배정 취소
→ 배정된보강에서 제거
→ 보강대기로 이동
→ 스케줄에서 제거

테스트 3:
다시 다른 스케줄에 재배정
→ 정상 배정

테스트 4:
스케줄 상세의 보강학생 카드에서 배정 취소
→ 보강대기로 이동
→ 배정된보강 목록에서도 제거

테스트 5:
completed 상태
→ 배정 취소 버튼 미표시

테스트 6:
정규학생 카드
→ 보강 배정 취소 버튼 미표시
