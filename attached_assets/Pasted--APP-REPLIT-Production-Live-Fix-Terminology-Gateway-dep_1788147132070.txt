1. 먼저 Production route live 확인
━━━━━━━━━━━━━━━━━━━━

실제:

https://swimnote-api.onrender.com

에서 terminology route가 이제 404가 아닌지 확인.

다음 각각 확인:

GET /api/terminology/status
GET /api/terminology/search?q=글라이드&limit=30

APP API 사용자 인증이 필요한 route이면
실제 정상 인증 context를 사용한다.

반드시 기록:

- HTTP status
- response body/error code
- route handler 진입 여부

404이면 아직 배포 문제.
404가 아니면 다음 단계 진행.

terminology-engine-client에서

3. 가장 중요한 Secret 검증
━━━━━━━━━━━━━━━━━━━━

현재 과거 조사에서:

Replit env의 PROFESSIONAL_ENGINE_API_SECRET
→ ENGINE 401

이 확인된 적이 있다.

따라서 이번에는
Render의 두 실제 Production 서비스:

A. swimnote-api
B. swimnote-professional-engine

에 설정된:

PROFESSIONAL_ENGINE_API_SECRET

이 실제 동일한 값인지 검증한다.

값 자체는 출력하지 않는다.

가능하면:

- SHA256 fingerprint
- length
- 실제 authenticated call

중 안전한 방식 사용.

최종적으로
swimnote-api runtime에서 사용하는 secret으로
ENGINE 직접 요청했을 때 반드시 200이 나와야 한다.

PROFESSIONAL_ENGINE_API_SECRET

5. Root Cause별 즉시 처리
━━━━━━━━━━━━━━━━━━━━

CASE A — ENGINE 401/403
→ PROFESSIONAL_ENGINE_API_SECRET 불일치 확정
→ swimnote-api Render env에 ENGINE과 동일한 secret 설정 필요

Replit에서 Render env 변경 권한이 있다면 수정.
권한이 없다면:
사용자가 Render에서 바꿔야 할 정확한 변수와 대상 서비스만 보고.

코드 우회 금지.
인증 완화 금지.

CASE B — 404
→ URL/path 오류
→ Gateway URL 최소 수정

CASE C — 502/503/timeout
→ ENGINE cold start/timeout/URL 문제 확인
→ 실제 원인에 맞게 최소 수정

CASE D — ENGINE 200인데 Gateway 5xx
→ response parsing/error mapping bug 확인 후 최소 수정
