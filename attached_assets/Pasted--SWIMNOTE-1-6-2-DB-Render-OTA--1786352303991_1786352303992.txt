[긴급 감리 — SWIMNOTE 1.6.2 강제 업데이트 모달 미표시 원인 조사]

중요:
지금은 코드 수정 금지.
DB 수정 금지.
Render 배포 금지.
OTA 배포 금지.
원인 조사만 한다.

현재 상황:

- 기존 Production 앱: 1.6.1
- 신규 앱 버전: 1.6.2
- 앱에는 새 버전 출시 시
  업데이트 모달 표시
  → App Store 이동
  → 이전 버전 사용 차단
  기능이 이미 구현되어 있음.
- 그런데 기존 1.6.1 앱에서 업데이트 모달이 나오지 않음.

직전 확인에서:

GET /api/app-version

응답에 iOS:
latest_version: "1.6.1"

이 확인된 적이 있음.

따라서 추측하지 말고
현재 Production의 실제 Version Gate 전체 경로를 추적한다.

━━━━━━━━━━━━━━━━━━━━━━

GET /api/app-version

iOS:

- 기타 관련 필드

Android:
동일 항목

현재 서버가 실제로
1.6.2를 알고 있는지 확인.

확인:

- hardcoded인지
- DB인지
- environment variable인지
- config 파일인지
- app.json을 읽는지

관련 파일/line 전부 보고.

특히:

1.6.1
1.6.2

repository 전체 검색.

latest_version / minimum_version 값이
어떻게 결정되는지 정확히 보고.

3. 앱 Version Check 진입점 추적
━━━━━━━━━━━━━━━━━━━━━━

앱 시작 시 Version Check가 실제 어디서 실행되는지 확인.

확인:

App root
SessionContext
_layout
Splash
Auth
Home

중 어디에서 호출되는지.

다음 흐름을 실제 코드로 보고:

→ appVersion 획득
→ /api/app-version 호출

→ Modal 표시
→ Store 이동
→ 구버전 차단

각 파일/함수/line 보고.

4. 현재 앱 버전 취득 방식
━━━━━━━━━━━━━━━━━━━━━━

예:

Application.nativeApplicationVersion
expo-application
기타

Production 1.6.1 설치본에서
실제로 비교되는 값이 무엇인지 코드 기준으로 확인.

━━━━━━━━━━━━━━━━━━━━━━
5. Version 비교 로직
━━━━━━━━━━━━━━━━━━━━━━

반드시 실제 비교 함수를 조사.

예:

currentVersion < latestVersion

같은 문자열 비교인지,

semver 비교인지,

major/minor/patch를 숫자로 분리하는지 확인.

다음 CASE를 코드로 검증:

1.6.1 vs 1.6.2
→ UPDATE REQUIRED

1.6.2 vs 1.6.2
→ PASS

1.6.10 vs 1.6.2
→ PASS

2.0.0 vs 1.6.2
→ PASS

문자열 단순 비교라면 버그 가능성 보고.

━━━━━━━━━━━━━━━━━━━━━━
6. 강제 업데이트 조건
━━━━━━━━━━━━━━━━━━━━━━

모달이 단순 latest_version 비교인지,
minimum_version 이하에서만 나오는지 확인.

예:

current < latest
current < minimum
force_update === true
mandatory === true

등 실제 조건 확인.

사용자가 원하는 정책은:

새 Production 버전이 강제 업데이트 대상으로 설정되면

기존 버전:
1.6.1

새 버전:
1.6.2

일 때

1.6.1 사용자는 앱 진입 차단
→ 업데이트 모달
→ App Store 이동

이어야 한다.

현재 코드가 이 정책과 일치하는지 판정.

━━━━━━━━━━━━━━━━━━━━━━

━━━━━━━━━━━━━━━━━━━━━━

SWIMNOTE 실제 App Store 앱으로 연결되는지 확인.

App Store Connect에 1.6.2가
실제로 사용자에게 배포 가능한 상태인지도
확인 가능한 범위에서 보고.

≠

이 둘을 구분해서 보고.
