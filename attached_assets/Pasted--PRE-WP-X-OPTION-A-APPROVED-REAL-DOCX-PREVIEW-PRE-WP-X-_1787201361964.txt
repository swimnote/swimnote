3. 중요 수정 — POOL 전체 DELETE 금지
==================================================

기존 보고서 제안:

DELETE FROM curriculum_items
WHERE swimming_pool_id = poolId

→ 사용 금지.

이 방식은 해당 pool이 직접 등록한 curriculum 또는
다른 version의 item까지 삭제할 위험이 있다.

최종 원칙:

X ingestion이 관리하는
특정 curriculum_version_id의 item만 교체한다.

개념:

DELETE FROM curriculum_items
WHERE swimming_pool_id = $poolId
AND curriculum_version_id = $xManagedVersionId

기존 사용자 작성/다른 version item:
절대 변경 금지.

297개
→ 297개

- 쉼표마다 무조건 split
- 동일 내용 표현만 바꿔 여러 item 생성
- 짧은 파편 생성
- 300개 맞추기 위한 artificial expansion

7. DEDUP
==================================================

같은 level 내:

detailed_skills 우선
→ skills 중복 제거
→ learning_contents 중복 제거

단순 exact string만 보지 말고
최소한 normalize 후 비교:

- 앞뒤 공백
- bullet 문자
- 반복 whitespace
- terminal punctuation

정도 제거.

의미 기반 GPT dedup은 이번 parser 단계에서 사용하지 않는다.

AI 호출 비용 없이 deterministic 처리.

9. 300 GATE 판정
==================================================

실제 sample 결과를 기준으로:

→ PASS

< 300
→ FAIL

FAIL이어도 parser가 실패한 것으로 간주하지 않는다.

해당 센터는 AI 커리큘럼 검색 eligibility 미충족.

억지 확장 금지.

10. X curriculum version 전략
==================================================

READ-ONLY 확인 결과를 바탕으로
X ingestion 전용 managed version을 어떻게 만들지 제안한다.

목표:

x_curriculum_levels
= 상위 level 구조

X-managed curriculum_version
= 해당 DOCX ingestion version

curriculum_items
= 실제 searchable item

새 ingestion 시:

BEGIN

1. X managed curriculum_version 확보/upsert
2. 해당 X managed version의 기존 curriculum_items만 제거
3. x_curriculum_levels 안전 교체
4. searchable_items → curriculum_items INSERT

COMMIT

단,
이번 단계에서는 실행하지 않는다.

transaction plan만 확정한다.
