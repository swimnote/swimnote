# SWIMNOTE 2.1.0 — WP5 TAB DESIGN NORMALIZATION

대상 화면:
관리자 → 선생님 관리 → 선생님 선택 → 운영현황

첨부한 최신 실기기 스크린샷 기준.

현재 WP5 상태:
- 글자 잘림 문제는 해결됨
- 4개 탭 높이 정렬도 해결됨
- 그러나 현재 버튼 디자인이 SWIMNOTE 기존 UI 철학과 맞지 않음

현재 문제:
1. 버튼 높이가 너무 큼
2. 텍스트 좌우 여백이 너무 큼
3. 버튼 하나하나가 과하게 커 보여서 상단 정보영역을 많이 차지함
4. 둥근 outline 버튼이 지나치게 두껍고 독립 CTA처럼 보임
5. 앱의 다른 화면에서 사용하는 소형 탭/필터 칩 디자인과 일관성이 없음

이번 WP5 작업은:
"운영현황 탭 4개를 SWIMNOTE 기존 공통 소형 필터/탭 디자인으로 정규화"
하는 작업이다.

새로운 임의 디자인을 만들지 말 것.

============================================================
1. 먼저 기존 앱의 동일 계열 버튼 디자인 찾기
============================================================

현재 코드베이스에서 실제 사용 중인:

- 소형 탭
- 필터 chip
- segmented filter
- 상태 선택 chip
- 카테고리 전환 버튼

중 SWIMNOTE 공통 디자인에 가장 가까운 정상 화면을 찾는다.

반드시 기존 구현을 기준으로 할 것.

확인할 항목:
- height
- minHeight
- paddingHorizontal
- paddingVertical
- borderRadius
- borderWidth
- fontSize
- lineHeight
- fontWeight
- selected background
- selected text color
- unselected border color
- unselected text color
- chip 간 gap

가능하면 이미 존재하는 공통 컴포넌트/style/token을 재사용한다.

동일 디자인을 복제해서 새로운 별도 스타일을 만드는 것보다
공통 스타일 재사용을 우선한다.

============================================================
2. 운영현황 탭 크기 축소
============================================================

대상:

담당 회원
출결
수업일지
보강

현재처럼 글자 양옆에 넓은 빈 공간이 남지 않게 한다.

원칙:
- 버튼 width 고정 금지
- flex:1로 4개를 억지로 동일 폭 배분 금지
- 텍스트 길이에 맞는 intrinsic width 사용
- paddingHorizontal은 기존 공통 chip 수준으로 축소
- paddingVertical도 기존 공통 chip 수준 사용
- 전체 높이는 현재보다 명확히 작게

즉:

[ 담당 회원 ] [ 출결 ] [ 수업일지 ] [ 보강 ]

처럼 내용에 맞는 컴팩트한 필터 탭이어야 한다.

"담당 회원" 때문에 다른 버튼까지 불필요하게 커지면 안 된다.

============================================================
3. 디자인 원칙
============================================================

이 탭들은 주요 CTA가 아니다.

따라서:
- 큰 버튼처럼 보이면 FAIL
- 과도하게 둥근 pill CTA처럼 보이면 FAIL
- 두꺼운 외곽선 금지
- 큰 내부 여백 금지
- 과도한 font size 금지

SWIMNOTE의 기존 정보 밀도에 맞게
작고 명확한 navigation/filter control로 보여야 한다.

selected 상태:
- 기존 SWIMNOTE 포인트 컬러 배경
- 기존 selected chip의 text color
- 불필요하게 크기 변화 없음

unselected 상태:
- 기존 앱의 공통 chip/tab 디자인과 동일
- selected와 동일한 height/padding
- 색상만 차이

selected/unselected 전환 시:
크기, 폭, 위치가 튀면 안 됨.

============================================================
4. 상단 레이아웃도 함께 확인
============================================================

통계 카드 아래와 탭 사이 간격,
탭 아래 목록 시작 간격도 기존 SWIMNOTE 화면과 비교.

현재보다 탭 영역이 더 컴팩트해져야 한다.

단:
- 통계 카드 수정 금지
- 목록 카드 수정 금지
- 하단 네비게이션 수정 금지
- 헤더 수정 금지

오직 탭 row와 그 주변 최소 spacing만 조정.

============================================================
5. 가장 중요 — 기존 디자인 재사용 증명
============================================================

완료 전에 반드시 보고:

어느 기존 화면/컴포넌트의 버튼 디자인을 기준으로 했는지
정확한 파일/컴포넌트명을 적을 것.

예:
Reference UI:
app/(admin)/xxxxx.tsx
Component/style:
xxxxxChip / filterChip / segmentedTab 등

기존 공통 컴포넌트가 있으면 그것을 재사용.

없다면 가장 가까운 기존 정상 스타일 값을 그대로 적용.

새로운 자의적 수치 설계는 최후 수단.

============================================================
6. 회귀 금지
============================================================

이전 WP5에서 해결한:

- 글자 1px처럼 찌그러지는 현상
- ScrollView cross-axis collapse
- text clipping
- selected/unselected 높이 불일치

절대 재발하면 안 됨.

ScrollView 구조를 다시 크게 바꾸지 말 것.

8. 완료 기준
============================================================

PASS 조건:

- 4개 탭 모두 현재보다 확실히 작음
