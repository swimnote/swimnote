4. 필수 날짜 규칙
==================================================

스케줄 날짜가 lessonDate라면 학생은 반드시 아래 조건을 모두 만족할 때만 표시되어야 합니다.

student_class_history.class_group_id = schedule.class_group_id

AND student_class_history.enrolled_at <= lessonDate

AND (
  student_class_history.left_at IS NULL
  OR student_class_history.left_at > lessonDate
)

AND student_class_history.deleted_at IS NULL

현재 students.status,
students.class_group_id,
students.created_at만으로 역사 표시를 결정하면 안 됩니다.

5. 월간 범위 조회 주의
==================================================

월간 스케줄 API가 한 달 전체 학생을 한 번에 조회한 뒤 모든 날짜에 재사용하는 구조인지 확인하세요.

다음 방식은 금지입니다.

- 6월 범위와 history가 한 번이라도 겹치면 6월 모든 날짜에 학생 표시
- 조회 시점 현재 활성 학생을 6월 모든 수업에 표시
- 반에 속한 학생 목록을 먼저 만들고 각 날짜에 그대로 재사용
- enrolled_at을 월 마지막 날짜와만 비교
- history 존재 여부만 확인하고 lessonDate별 필터를 생략

학생 포함 여부는 반드시 각 수업 날짜별로 계산해야 합니다.

예:

7월 20일 enrolled_at 학생

- 6월 수업: 제외
- 7월 19일 수업: 제외
- 7월 20일 수업: 포함
- 7월 21일 이후 수업: 포함

6. 캐시와 프론트 병합 확인
==================================================

다음을 확인하세요.

- React Query queryKey에 조회 날짜가 포함되어 있는지
- 월 변경 시 이전 달 캐시를 재사용하지 않는지
- class_group_id만 queryKey에 있고 month가 빠져 있지 않은지
- 현재 학생 목록을 스케줄 응답에 프론트에서 합치지 않는지
- Zustand/Context/Redux에 저장된 현재 학생 목록을 과거 일정에 사용하지 않는지
- FlatList/SectionList key 문제로 이전 학생 행이 재사용되지 않는지

날짜가 바뀌면 반드시 다른 캐시 키를 사용해야 합니다.
