==================================================
3. RESERVATION BEFORE ENGINE CALL
==================================================

질문 요청 흐름:

1. Parent auth
2. ownership 확인
3. quota 확인
4. 1회 reservation
5. ENGINE 호출
6. 성공 시 reservation finalize
7. 실패 시 reservation release/rollback

동시 요청에서도 10회를 초과하지 않도록
atomic reservation 필요.

단순:

SELECT count → INSERT

race condition 금지.

기존 parent_ai_usage_reservations가
이 목적이면 반드시 재사용.

==================================================
4. WHAT COUNTS AS SUCCESS
==================================================

다음 경우만 최종 1회 차감:

ENGINE response 정상
+
APP response validation 정상
+
grounding.validation === PASS
+
result.answer 정상

다음은 차감하지 않음:

ENGINE 401
ENGINE 429
ENGINE 5xx
timeout
network failure
request_id mismatch
grounding FAIL
unknown curriculum ID
malformed response
APP internal error

==================================================
10. MESSAGE WRITE ORDER
==================================================

질문 처리 흐름에서:

A. USER message

ENGINE 호출 전에 저장할지
성공 후 저장할지
현재 retry/idempotency 구조를 보고 결정.

중요:

같은 request_id retry로
USER message 중복 생성 금지.

B. ASSISTANT message

ENGINE 성공 + response validation PASS 후만 저장.

실패한 ENGINE 결과를
assistant message로 저장 금지.

==================================================
11. IDEMPOTENCY
==================================================

request_id 기준으로
동일 질문 retry 시:

- quota 이중 차감 금지
- USER message 중복 금지
- ASSISTANT message 중복 금지

가능하면 기존 reservation/request_id 구조 재사용.

Unique constraint 또는 transactional guard 필요.
