# SWIMNOTE 보호자 자동 연결 버그 수정
# parent_phone2 / parent_phone3 자동 연결 지원

## 작업 목적

현재 보호자 자동 연결 V2는 학생의 대표 보호자 전화번호인 parent_phone만 검사하고 있습니다.

기존 승인 학부모가 학생 정보에 추가 보호자 전화번호를 parent_phone2 또는 parent_phone3에 등록한 뒤,
해당 번호로 다른 보호자가 가입하면 기존 학생에 자동 연결되어야 하지만 현재는 연결되지 않습니다.

이번 작업에서는 이 누락만 수정합니다.

다른 가입 구조, 학생 생성 구조, 병합 구조, 관리자 UI는 변경하지 마십시오.

──────────────────────────────
1. 수정 대상
──────────────────────────────

실제 조사 결과 기준:

파일:
lib/auto-link-v2.ts

현재 조건:
parent_phone만 정규화하여 가입 보호자 전화번호와 비교

현재 예시:

AND REGEXP_REPLACE(COALESCE(parent_phone,''),'[^0-9]','','g') = ${phoneNorm}

수정 후에는 같은 tenant/swimming_pool_id 범위 안에서 아래 3개 컬럼을 모두 비교해야 합니다.

- parent_phone
- parent_phone2
- parent_phone3

셋 중 하나라도 가입자의 정규화된 전화번호와 정확히 일치하면 자동 연결 후보로 인정합니다.

──────────────────────────────
2. 필수 조건
──────────────────────────────

전화번호 비교 전 기존 방식과 동일하게 숫자만 남겨 정규화합니다.

예:

010-1234-5678
01012345678
+82 10-1234-5678

현재 시스템의 기존 정규화 규칙을 그대로 재사용하십시오.

새로운 정규화 함수를 중복 생성하지 마십시오.

──────────────────────────────
3. tenant 격리
──────────────────────────────

반드시 기존 swimming_pool_id 조건을 유지하십시오.

다른 수영장 또는 다른 tenant의 학생과는 절대 연결하면 안 됩니다.

──────────────────────────────
4. 자동 연결 결과
──────────────────────────────

parent_phone2 또는 parent_phone3이 일치하는 경우에도 기존 parent_phone 일치와 동일하게 처리합니다.

필수 결과:

- 신규 Student 생성 없음
- 기존 Student 재사용
- parent_students에 보호자 연결
- 이미 연결된 관계는 중복 생성하지 않음
- 기존 학생의 반, 레벨, 일지, 출결 정보 유지
- 추가 가입 보호자는 기존 학생을 즉시 조회 가능

──────────────────────────────
5. 다중 후보 처리
──────────────────────────────

같은 tenant 안에서 동일 전화번호가 여러 학생의 parent_phone / parent_phone2 / parent_phone3에 중복 등록되어 정확한 학생을 하나로 결정할 수 없는 경우:

- 임의 자동 연결 금지
- 기존 pending 상태 유지
- 로그에 다중 후보임을 기록
- 신규 Student 생성 금지

한 명의 학생만 정확히 일치하는 경우에만 자동 연결하십시오.

──────────────────────────────
6. 기존 자동 연결 트리거 유지
──────────────────────────────

아래 기존 트리거가 모두 parent_phone2/3에도 동일하게 적용되는지 확인하십시오.

1. 보호자 가입 후 POST /parent/onboard-pool
2. 관리자가 학생 정보 등록 또는 수정 시 triggerAutoLinkOnStudentV2
3. 보호자 홈 진입 시 getParentStatusV2 재매칭

한 경로만 수정하지 말고, 세 경로가 공통 매칭 함수를 사용하는지 확인하십시오.

공통 함수가 아니라 별도 조건을 사용하는 경로가 있다면 모두 동일 기준으로 맞추십시오.
