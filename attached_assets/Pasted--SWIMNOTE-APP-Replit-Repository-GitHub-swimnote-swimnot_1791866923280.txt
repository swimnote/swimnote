6. Attendance class isolation
━━━━━━━━━━━━━━━━━━━━━━

가장 주의해서 처리합니다.

현재 기존 row lookup/update가
student_id + date 중심인 문제를 수정하여
반 context를 포함시킵니다.

현재 schema에 실제 session identifier가 이미 있다면
그 기존 identifier를 우선 검토.

없다면 최소 기준:

student_id
+ class_group_id
+ date

로 동일 출석을 식별합니다.

중요:

migration/index 변경 전에
Production READ ONLY preflight 실행.

확인:

- 동일 student_id + class_group_id + date duplicate 수
- null/legacy class_group_id
- 기존 데이터가 새 unique contract와 충돌하는지

충돌 데이터가 존재하면
임의 delete/merge 금지.
HOLD 보고 후 정지.

충돌이 없다면
안전한 migration으로 unique contract를 맞춥니다.

출석 CREATE/UPDATE/조회/보강 완료 경로에서
같은 식별 계약을 사용해야 합니다.

목표:

학생 A가 같은 날짜에 다른 두 class에 있어도
출석 A/TUE와 A/THU가 서로 덮어쓰지 않음.
