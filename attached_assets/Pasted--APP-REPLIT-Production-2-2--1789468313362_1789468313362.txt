━━━━━━━━━━━━━━━━━━━━━━

실제 Production에서:

회원목록
→ 학생상세
→ 좌측 BACK

결과:
HOME으로 이동

목표:
회원목록으로 복귀

입니다.

이 문제는 아직 해결되지 않았습니다.

이번에는 router.canGoBack() 여부로 판단하지 마십시오.

반드시 실제 진입 source를 보존하십시오.

조사:

- 회원목록에서 student-detail로 들어가는 실제 route
- push / replace 여부
- student-detail의 좌측 Back handler
- student-detail이 어느 Stack/Tabs 아래에 있는지
- 왜 BACK destination이 HOME이 되는지

최종적으로:

회원목록
→ student-detail

진입 시 source 또는 returnTo를 명시적으로 전달하고,

student-detail BACK:

source=member-list
→ 회원목록 route로 명시적 복귀

하도록 처리하십시오.

예:

member-list
→ student-detail?id=...&source=member-list

student-detail BACK
→ source === member-list
   ? replace/push member-list
   : 기존 안전 fallback

단 실제 현재 route명에 맞춰 구현하십시오.

중요:

HOME으로 보내는 fallback을
학생상세의 정상 BACK 경로로 사용하지 마십시오.

HOME은 사용자가 HOME 버튼을 직접 누른 경우에만 이동합니다.

그리고 기존:

학생상세
→ 일지 / 사진영상 / 성장리포트

하위 화면에서 BACK
→ 학생상세

동작은 깨뜨리지 마십시오.
