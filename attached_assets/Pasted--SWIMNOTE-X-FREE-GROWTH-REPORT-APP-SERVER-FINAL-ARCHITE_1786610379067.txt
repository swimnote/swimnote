[SWIMNOTE X FREE GROWTH REPORT — APP/SERVER FINAL ARCHITECTURE FEASIBILITY & IMPLEMENTATION DESIGN AUDIT]

중요:
이번 작업은 구현이 아니다.

현재 SWIMNOTE APP Repository를 기준으로
SWIMNOTE X 무료 월간 성장리포트 완성형을
APP + APP SERVER에서 어떻게 수용할지 감리하라.

코드 수정 / DB 변경 / 배포 금지.
READ-ONLY AUDIT + IMPLEMENTATION DESIGN ONLY.

MVP나 축소판으로 임의 변경하지 마라.
최종 완성 형태를 기준으로 감리한다.

AI 평가·분석 자체는 AI ENGINE의 책임이다.
APP은 수영 전문 판단, 인간 행동 평가, Evidence 판단,
긍정 성장항목 선정 등을 자체 생성하면 안 된다.


==================================================
1. 전체 제품 흐름
==================================================

X모드 학생에게 월 1회 무료 성장리포트를 제공한다.

운영주기:

매월 25일
→ 해당 회차 성장리포트 생성 가능
→ Push Notification
→ 서버/엔진 사전분석
→ 추가 학부모 정보가 필요한 경우 질문 모달

25일 ~ 다음달 5일
→ Parent 질문 응답 가능
→ 분석/검토/발행 진행

다음달 5일
→ 해당 회차 입력/생성 기간 종료
→ 종료 알림

중요:
이미 PUBLISHED 된 리포트는 없어지지 않는다.
계속 피드에서 열람 가능하다.
구조화 결과는 다음 월의 분석자료로 재사용된다.


==================================================
2. APP의 절대 역할
==================================================

APP / APP SERVER는 다음 역할을 담당한다.

- X entitlement / 접근권한
- 학생/수영장/사용자 Context
- Report Window 상태 표시
- Push Notification
- AI ENGINE 호출 orchestration에 필요한 App-side API
- 질문 모달 표시
- 학부모 답변 수집
- 답변 저장/ENGINE 전달
- Report Job 상태 표시
- 교사 검토 UI
- Report 결과 저장 또는 ENGINE 결과 persistence orchestration
- 학부모 Feed 발행
- 상세 리포트 렌더링
- PDF download/share
- SNS용 AI 요약 결과 표시/공유
- 감사로그/권한/발행상태

APP이 하면 안 되는 것:

- Teacher Diary 의미분석
- Observation 생성 판단
- 70개 Metric Mapping
- Evidence Sufficiency 판단
- Positive Signal 선정
- Longitudinal 평가
- Question Priority 판단
- Growth Opportunity 판단
- GPT용 Fact 생성
- 수영 전문 판단

위 판단은 AI ENGINE 책임.

==================================================

==================================================
6. Parent Question Modal
==================================================

중요:
고정된 70문항 설문을 보여주는 기능이 아니다.

AI ENGINE이 해당 학생의 기존 데이터를 먼저 분석하고,

“현재 긍정 성장신호 후보 중
학부모 답변이 들어오면 Evidence 가치가 크게 증가하는 항목”

2~5개 정도를 선택해 APP으로 반환한다.

APP은 그 질문만 표시한다.

질문 Contract 후보:

question_id
report_id
metric_id

question_text

answer_type
options[]

reason_code
(optional, 내부용)

sequence
is_required

APP은 metric 판단을 하지 않는다.

답변 후보는 기본적으로 객관식/선택형이며
질문 문구는 긍정적 변화 가능성이 높은 항목에서 선정될 수 있으나
답변 선택지는 편향 없이 구성되어야 한다.

답변 저장:

answer_id
question_id
selected_option
answered_at
parent_account_id

필요한 경우 ENGINE에 재분석 요청.


==================================================
7. 교사 검토
==================================================

AI 분석 완료 후 바로 Parent Publish 여부를 감리하라.

현재 설계 원칙은:

ANALYZING
→ REVIEW_REQUIRED
→ teacher / pool_admin 검토
→ APPROVED
→ PUBLISHED

교사가 수정할 수 있는 범위도 제안하라.

중요:
교사가 Evidence/Metric 판정을 임의로 새로 만드는 것이 아니라,
문장 검토 / 근거 제외 요청 / 재분석 요청 등의 구조를 우선 검토한다.

기존 WP13 Growth Event Review,
Audit 구조를 어느 정도 재사용 가능한지 확인하라.


==================================================
8. Parent Feed 발행
==================================================

성장리포트는 별도 메뉴를 찾아가야만 보는 기능을 기본으로 하지 않는다.

기본 Parent UX:

기존 수업 Feed 안에
새 Feed Item Type 또는 기존 Feed 확장으로

GROWTH_REPORT

가 월 1회 게시된다.

예:

[8월 성장리포트]

이번 달 핵심 성장요약
짧은 Preview

[리포트 보기]

사용자가 Feed item을 누르면
앱 안의 상세 리포트 화면/모달로 진입한다.

현재 Parent Feed 구조에서
새 타입을 넣는 가장 안전한 방식을 실제 코드 기준으로 감리하라.

기존 Diary 저장/표시 Contract를 깨지 마라.

==================================================

PUBLISHED Report
↓
AI SNS Summary
↓
Share Card / Story Content
↓
Instagram Story 등 공유

중요:
APP이 성장내용을 자체 요약하지 않는다.

AI ENGINE이 제공한
SNS-safe summary / key growth points를 사용한다.

APP 역할:
렌더링
브랜딩
공유 Intent
필요한 워터마크/브랜드 카드

현재 기존 공유 기능과
어느 정도 재사용 가능한지 감리하라.

12. Longitudinal Persistence
==================================================

과거 리포트를 다음 달 분석자료로 쓰기 때문에
APP DB에는 단순 PDF URL만 저장하면 안 된다.

필요 구조 후보:

report_id
student_id
pool_id
period
status

selected_metrics
metric_states
metric_confidences

evidence_refs

positive_growth_signals
success_conditions
support_levers

parent_answers

next_growth_targets
next_observation_targets

engine_version
report_version

published_at
previous_report_id

다만 실제 DB 소유권을
APP DB에 둘지 ENGINE DB에 둘지는
현재 architecture를 확인해 제안하라.

Source of Truth는 반드시 하나여야 한다.

APP과 ENGINE에 서로 다른 리포트 상태가 중복 저장되어
drift가 생기는 구조를 만들지 마라.

==================================================
15. X Mode Access
==================================================

무료 성장리포트는 X entitlement가 활성화된 수영장 회원 대상이다.

현재 `XModeGuard`, entitlement,
pool X status 및 Parent 접근구조를 확인해서

어디서 server-side enforcement를 하고
어디서 UI guard를 할지 설계하라.

UI Guard만으로 접근제어하면 안 된다.
