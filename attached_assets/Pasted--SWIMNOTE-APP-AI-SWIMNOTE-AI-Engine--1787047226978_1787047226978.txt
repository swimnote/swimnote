[SWIMNOTE 핵심특허 작성용 APP ↔ AI 연결 기술자료 요청]

목적:
SWIMNOTE 앱 내부에서 AI Engine과 연결되는
독자적인 데이터 흐름과 자동화 구조를
특허 실시예 및 종속항 후보로 검토하기 위함.

일반적인 CRUD/UI 설명은 제외하고
AI/커리큘럼/학생진도/리포트/Context/자동화와
직접 연결되는 구조만 실제 Repository 기준으로 정리.

==================================================
1. APP → AI ENGINE REQUEST FLOW
==================================================

앱에서 AI 요청이 발생할 때
실제로 어떤 Context/Data가 Engine으로 전달되는지 정리.

예:

user_id
pool_id
user_role
teacher_id
student_id
class_id
curriculum_id
current_progress
lesson_context
request_id
feature_type

각 필드:
- 어디서 수집되는지
- 필수/선택
- AI Engine에서 어떤 용도로 쓰이는지

실제 구현만.


==================================================
2. AI TEACHER DIARY — APP SIDE
==================================================

선생님이 한 번 입력한 내용을
여러 학생에게 각각 생성하는 전체 앱 흐름.

확인:

- 입력 UI
- 음성/STT
- 현재 반/학생 자동 Context
- 학생 목록 전달
- Engine request 생성
- common/student-specific 결과 수신
- student_id 기반 결과 매칭
- 각 학생 일지 필드 삽입
- 선생님 검토
- 기존 저장 flow 사용

특히:

한 번의 입력
→ 복수 학생
→ 개별 AI 결과

구조를 상세히 정리.

→ result

- 없는 진도/없는 curriculum 처리

5. AI RESULT INSERTION / SAVE
==================================================

- 학생별 결과를 찾고
- 기존 일지 입력필드에 넣고
- 사용자가 검토하고
- 최종 저장하는지

앱이 기존 save flow를 사용하는지 구분.

AI Engine과 App의 책임 분리도 설명.
