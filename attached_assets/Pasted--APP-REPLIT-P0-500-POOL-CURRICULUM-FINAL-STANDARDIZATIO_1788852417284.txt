최종 canonical Local Curriculum Resolver:

1.
학생에게 active SCA가 있고
그 SCA가 is_global_reference=false Local version을 가리키면
→ 해당 version 사용

2.

→ pool의 active Local version 사용

조건:

is_global_reference=false
AND swimming_pool_id=poolId
AND is_active=true
AND import_status='ACTIVE'
AND archived_at IS NULL

- searchCurriculumCandidates

2. Structure와 Activation 역할 완전 분리
━━━━━━━━━━━━━━━━━━━━━━

현재 structure 단계에서
curriculum_version을 is_active=true로 만드는 구조 제거.

정상 상태:

UPLOAD
→ file 저장

STRUCTURE
→ 새 Local version 생성
→ is_active=false
→ import_status=DRAFT / VALIDATED 등 현재 허용상태 사용

APPROVE
→ APPROVED profile
→ 아직 is_active=false

ACTIVATE
→ 여기서만 is_active=true

즉:

structure/approve 단계에서는
현재 운영중 Local에 아무 영향 없음.

activate-local TX에서만:

1. 새 approved Local 확인
2. 기존 active Local deactivate/archive
3. 새 Local activate + import_status='ACTIVE'
4. xmode_config_status='READY'
5. 필요한 transition 작업
6. 전부 하나의 transaction

실패 시 전체 rollback.

부분 activation 금지.

3. version_name 고정 UPSERT 제거
━━━━━━━━━━━━━━━━━━━━━━

현재:

version_name='x-curriculum-v1'
+
ON CONFLICT UPDATE
+
items DELETE/INSERT

구조는 version history를 파괴한다.

신규 업로드는 반드시 새 Local curriculum_version을 생성.

각 import마다 안정적인 version identity 사용.

예시 방향:

x-curriculum-{sequence}
또는
source/canonical hash 기반 version id/name

실제 repository 스타일에 맞게 구현.

중요:

동일 파일 재업로드는
content_hash로 감지.

A. 동일 content_hash
→ 이미 구조화된 동일 import가 있으면
duplicate로 반환하거나 기존 결과 재사용

B. 다른 hash
→ 새 Local version 생성

기존 Local row overwrite 금지.

기존 curriculum_items DELETE 후 교체 금지.

과거 version/items 보존.

━━━━━━━━━━━━━━━━━━━━━━
4. content_hash / import idempotency
━━━━━━━━━━━━━━━━━━━━━━

x_setup_files 또는 적절한 import metadata에
content_hash 저장.

동일 pool + 동일 파일 hash:

→ 구조화 중복실행 금지
→ 동일 canonical 결과 재사용 가능

다른 hash:

→ 새 import batch
→ 새 curriculum version

Global version은 어떠한 Local import에서도
UPSERT target이 될 수 없음.
