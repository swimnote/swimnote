# SWIMNOTE Teacher Diary 앱 응답 매핑 및 입력 데이터 확인

현재 Teacher Diary의 공통 일지와 학생별 일지는
AI Engine이 상태 전환 규칙으로 분리하여 반환할 예정입니다.

이번 작업은 앱에서 문장을 새로 분리하거나 해석하는 작업이 아닙니다.

앱은 AI Engine Response의

result.common

result.students[]

를 정확한 입력칸에 매핑해야 합니다.

==================================================

1. AI Engine Response 실제 구조 확인

Teacher Diary 성공 응답의 실제 JSON을 로그로 확인하십시오.

반드시 다음을 보고하십시오.

- result.common 실제 값
- result.students[] 전체
- 각 student_ref
- 각 학생 이름
- 각 feedback
- 현재 선택된 학생 목록

민감정보는 마스킹하십시오.

==================================================

2. 공통 일지 매핑 규칙

반 공통 일지 입력칸에는 반드시

result.common

값만 넣으십시오.

금지:

- 원본 교사 입력 전체 삽입
- transcript 전체 삽입
- 학생별 feedback 병합
- students[] 내용을 common에 추가
- common이 비어 있을 때 원본 입력으로 fallback

result.common이 빈 문자열이면
공통 일지 입력칸도 빈 상태로 유지하십시오.

==================================================

3. 학생별 일지 매핑 규칙

각 학생별 입력칸에는 반드시

result.students[]에서 해당 학생과 매칭된 feedback만

넣으십시오.

매칭 우선순위:

1. student_ref 또는 student_id의 정확한 일치
2. 서버 계약에 실제로 존재하는 다른 고유 학생 ID
3. 이름 매칭은 고유 ID가 없을 때만 보조적으로 사용

금지:

- result.common을 학생별 칸에 복사
- 원본 교사 입력 전체를 학생별 칸에 삽입
- transcript를 모든 학생에게 복사
- 첫 번째 학생 feedback을 다른 학생에게 복사
- feedback이 없는 학생에게 common을 fallback으로 삽입
- 이름만 비슷한 학생에게 추측 매핑

학생별 feedback이 없거나 빈 문자열이면
그 학생의 추가 일지를 자동 생성하지 마십시오.

==================================================

4. 중복 학생 처리

AI Engine Response에 같은 student_ref가 여러 번 반환될 가능성을 확인하십시오.

같은 학생이 여러 번 등장하면
응답 순서대로 해당 학생의 feedback을 결합할 수 있습니다.

단, 다음 조건을 지키십시오.

- 같은 student_ref끼리만 결합
- 문장 중복 제거
- 다른 학생 내용과 혼합 금지
- result.common과 결합 금지

가능하면 AI Engine이 학생별 feedback을 하나로 합쳐 반환하므로
앱은 불필요한 재가공을 하지 마십시오.

==================================================

5. 학생 데이터 전달 확인

AI Engine이 성을 제외한 이름만으로도 학생을 인식하려면
앱이 요청에 학생 ID와 실제 학생 이름을 함께 전달해야 합니다.

현재 Teacher Diary Request에
student_refs만 존재하는지,
학생 이름 정보도 함께 존재하는지 실제 코드를 확인하십시오.

반드시 보고할 내용:

- AI Engine으로 보내는 학생 ID
- AI Engine으로 보내는 학생 전체 이름
- student_ref와 학생 이름의 대응 관계
- 현재 Request Contract에서 학생 이름을 전달할 수 있는 필드가 있는지
- 이름 정보가 없는 경우 AI Engine이 student_ref만으로 이름을 인식할 수 있는지

중요:

사용자가 음성이나 텍스트로

“태웅”
“태웅이”
“태웅이는”
“서태웅”

이라고 말했을 때 이를 실제 학생과 연결하려면
AI Engine에 학생 이름 목록이 전달되어야 합니다.

현재 계약에 학생 이름 전달 필드가 없다면
임의로 필드를 추가하지 말고 CONTRACT BLOCKED로 보고하십시오.

==================================================

6. 앱에서 분리 로직 구현 금지

다음과 같은 키워드 상태 전환 파싱을
앱 프론트엔드에 새로 구현하지 마십시오.

- 전체 감지
- 학생 이름 감지
- 현재 대상 학생 상태 유지
- 조사 제거
- 성 제거 이름 매칭

이 로직은 AI Engine의 Teacher Diary 해석 책임입니다.

앱은

교사 원문 + 수업 Context + 학생 목록

을 보내고,

AI Engine이 반환한 구조화 결과를 정확히 화면에 삽입하는 역할만 수행합니다.

==================================================

7. DiaryInsertResult 변환 확인

다음 변환 흐름을 실제 코드로 추적하십시오.

AI Engine Response
→ DiaryInsertResult
→ 반 공통 일지 입력값
→ 학생별 추가 일지 입력값

확인 대상:

- result.common 변환 코드
- result.students[] 변환 코드
- student_ref 매칭 코드
- common fallback 코드
- transcript fallback 코드
- 빈 feedback 처리 코드
- 기존 입력값과 병합하는 코드
- 같은 학생의 기존 추가 일지에 덮어쓰기 또는 추가하는 방식

특히 아래와 유사한 코드가 있는지 검색하십시오.

studentFeedback || common
feedback ?? common
common + feedback
transcript
rawText
input.text
students.map(() => common)

존재한다면 실제 목적을 확인하고
공통 내용이 학생별 일지로 복사되는 fallback은 제거하십시오.

==================================================

8. 기대되는 AI Engine 명령 해석 규칙

앱은 아래 규칙에 맞는 입력 원문을 그대로 AI Engine에 전달해야 합니다.

상태 전환 명령:

- “전체”가 나오면 이후 내용은 공통 일지
- 학생 이름이 나오면 이후 내용은 해당 학생 일지
- 다른 학생 이름이 나오면 해당 학생으로 대상 전환
- 학생 이름 이후 다음 이름이나 “전체”이 나오기 전까지 같은 학생 내용으로 유지
- 다시 “전체”가 나오면 기존 학생 구간을 종료하고 이후 내용을 공통 일지에 추가
- 같은 학생 이름이 나중에 다시 나오면 기존 해당 학생 내용 뒤에 추가
- 학생 이름은 성을 뺀 이름만 말해도 인식
- 이름 뒤 조사도 허용

예시 입력 순서:

전체
이름2
이름1
이름2
전체

기대 결과:

- 첫 번째 전체 구간과 마지막 전체 구간은 result.common에 순서대로 결합
- 이름2의 첫 구간과 두 번째 구간은 이름2 feedback에 순서대로 결합
- 이름1 구간은 이름1 feedback에 삽입
- 서로 다른 대상의 내용은 섞이지 않음

앱은 이 원문 순서를 변경하거나 문장을 미리 분할하지 마십시오.

==================================================

9. 필수 앱 테스트

AI Engine Mock Response가 아니라
실제 Production Response를 기준으로 확인하십시오.

입력:

“전체 자유형 열 바퀴 했습니다.
태웅 평영 발차기를 연습했습니다.
민수 자유형 호흡을 연습했고 조금 어려워했습니다.
태웅 마지막에는 평영 킥이 좋아졌습니다.
전체 마무리로 배영 한 바퀴 했습니다.”

기대 화면:

반 공통 일지:
“자유형 열 바퀴 했습니다. 마무리로 배영 한 바퀴 했습니다.”

태웅:
“평영 발차기를 연습했습니다. 마지막에는 평영 킥이 좋아졌습니다.”

민수:
“자유형 호흡을 연습했고 조금 어려워했습니다.”

확인 사항:

- 공통 내용이 학생별 칸에 없음
- 태웅 내용이 민수 칸에 없음
- 민수 내용이 태웅 칸에 없음
- 태웅의 두 구간이 순서대로 결합됨
- 마지막 전체 구간이 common 뒤에 추가됨
- 이름이 언급되지 않은 학생의 추가 일지가 생성되지 않음

중요

앱의 책임은 AI Engine 결과를 정확하게 화면에 넣는 것입니다.

공통 일지와 학생별 일지의 의미 분리,
“전체”와 학생 이름에 따른 상태 전환,
이름 조사 제거와 성 제외 이름 인식은
AI Engine에서 수행합니다.

앱에서는 공통 내용을 학생별 내용에 복사하지 마십시오.
