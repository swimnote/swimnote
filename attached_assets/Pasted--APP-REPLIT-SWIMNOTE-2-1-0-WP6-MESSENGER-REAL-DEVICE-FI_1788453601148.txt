# SWIMNOTE 2.1.0 — WP6 MESSENGER REAL-DEVICE FIX / VERIFICATION

대상:
관리자/선생님 메신저

현재 WP6은 이미 한 번 구현 완료된 작업이고,
이번 단계는 2.1.0 실기기 기준으로 기존 WP6 수정사항이 정확히 반영됐는지 재검증하고
실패 항목만 최소 수정하는 작업이다.

새 기능 추가 작업이 아니다.
기존 WP6 요구사항을 그대로 기준으로 검증할 것.

============================================================
WP6 원래 요구사항
============================================================

1. 멘션 UI 제거

기존 화면에 보이던:

- @@나 언급
- @@서경민투 언급
- 기타 mention chip / badge

등의 별도 멘션 표시 UI를 제거한다.

중요:
메시지 본문 자체의 텍스트를 임의 삭제하면 안 됨.

즉:
- 별도 mention badge/chip UI는 제거
- 실제 사용자가 입력한 message text는 그대로 표시

============================================================
2. 발신자 표시 방식 정리
============================================================

기존의:
- 성만 들어간 원형 avatar
- 이름 일부만 보이는 badge

형태 제거.

메시지 위/옆 발신자 표시는 역할에 따라 다음처럼 표시.

Teacher:
{name} 선생님

예:
서경민 선생님

Admin / Pool Admin / Sub Admin 등 비선생님 계정:
{name}

예:
서경민

절대 모든 사용자에게 "선생님"을 붙이지 말 것.

현재 서버/메시지 데이터에 존재하는 sender_role을 기준으로 판별.

Teacher role일 때만 "선생님" suffix 사용.

============================================================
3. 본인 메시지 삭제
============================================================

본인이 작성한 메시지는 삭제 가능해야 한다.

기존 WP6 구현 기준:
DELETE /messenger/messages/:id

조건:
- 로그인 인증 필수
- 해당 메시지 sender 본인만 삭제 가능
- 다른 사용자 메시지는 삭제 불가
- 관리자라고 해서 다른 사람 메시지까지 삭제 가능하게 만들지 말 것
- 삭제 후 목록에서 즉시 제거/재조회 반영
- 중복 삭제 요청/이미 삭제된 메시지는 앱 crash 없이 처리

UI:
본인 메시지 long press 등 기존 구현된 삭제 진입 방식 사용.

삭제 confirmation이 현재 구현되어 있다면 유지.
새로운 복잡한 UI 만들지 말 것.

============================================================
4. 첨부파일 + 버튼 수정
============================================================

기존 문제:
iOS에서 "+" / 첨부파일 버튼을 눌러도
DocumentPicker 또는 파일 선택 UI가 정상적으로 뜨지 않던 문제.

기존 WP6에서:
modal dismiss 직후 즉시 DocumentPicker를 열면서
iOS presentation timing 충돌이 발생하는 것으로 수정했음.

기존 수정:
modal dismiss 이후 약간의 delay 후 DocumentPicker 실행.

현재 2.1.0 실기기에서 반드시 재검증.

PASS 조건:
- + 버튼 터치됨
- 첨부 메뉴 열림
- 파일 선택 실행됨
- 취소 후 정상 복귀
- 다시 눌러도 정상 작동
- 앱 freeze/crash 없음

8. 서버 DELETE endpoint 검증
============================================================

중요:
UI만 존재한다고 PASS 처리하지 말 것.

DELETE /messenger/messages/:id 실제 서버 route 확인.

검증:

A. 본인 메시지
Expected:
삭제 성공

B. 다른 사용자 메시지
Expected:
403 또는 정책에 맞는 권한 거부

C. 없는 message id
Expected:
정상적인 404/실패 응답
서버 crash 없음

D. 인증 없는 요청
Expected:
401

E. pool/tenant 경계
다른 pool 메시지 삭제 불가

현재 production 서버 배포 여부를 이번 WP에서 임의로 변경하지 말 것.

서버 코드 수정이 필요한 경우:
코드만 수정 + commit 후 보고.

Render deploy:
NO

사용자 승인 없이 production deploy 금지.
