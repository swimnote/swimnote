============================================================
1. 공통 원칙
============================================================

Kakao → General 전환은
"신규 가입"이 아니라
"기존 계정 마이그레이션"이다.

따라서:

approval pending
approval required
manual admin approval

모두 금지.

단,
완전 신규 일반가입자는
기존 신규가입/승인 정책 그대로 유지.

============================================================
2. TEACHER — 기존 지시 그대로 적용
============================================================

기존 승인된 Kakao teacher가
동일 phone + pool 조건으로 일반가입 전환 시:

- 새 General teacher 생성
- 기존 승인 상태 승계
- is_activated/approved 상태 즉시 확정
- 동일 pool 유지
- 기존 담당 반 유지
- 기존 담당 학생 유지
- active refs 이전
- old Kakao teacher archive/disable
- approval queue 미노출
- admin approval 불필요
- 즉시 login 가능
- 즉시 teacher mode 사용 가능

완전 신규 general teacher는
기존 approval flow 유지.

============================================================
3. PARENT — 동일 정책 적용
============================================================

기존 Kakao parent가
동일 전화번호로 일반가입 전환 시:

신규 parent approval/pending flow로 보내지 말 것.

대신:

- 새 General parent account 생성
- 기존 Kakao parent의 소속/연결정보 이전
- 기존 자녀 연결 전부 이전
- 기존 pool 관계 이전
- 기존 approved relationship 유지
- 기존 parent_students 관계 이전
- 기존 parent_student_requests 상태 중
  실제 active/approved 관계는 새 계정 기준으로 정상화
- 알림/push 관련 active refs 이전
- old Kakao parent archive/disable
- 새 General parent 즉시 login 가능
- 자녀 바로 조회 가능
- 기존 승인 완료 상태 그대로 유지

============================================================
4. PARENT APPROVAL QUEUE 제거
============================================================

Kakao → General parent migration이 완료된 계정은
관리자 승인대기 목록에 나타나면 안 됨.

현재 approval/pending 목록이 어떤 조건으로 생성되는지 확인하고:

migration parent가
그 조건에 걸리지 않도록
서버 상태 자체를 정상 approved/active 상태로 확정.

UI에서 숨기기만 하는 방식:
NO

서버 상태를 올바르게 맞출 것.

5. 기존 PARENT 연결정보 이전
============================================================

현재 parent Kakao migration 코드가
이전하는 실제 reference table을 source에서 전수 확인.

반드시 기존 active 관계를 새 parent ID로 이전.

예시 범주:

- parent_students
- parent_pool 관계
- parent requests 중 ownership/reference
- push_settings
- push_tokens
- notification/read state
- 기타 현재 parent_user_id / parent_id를 FK로 사용하는 active table

중요:
실제 schema 기준으로 전수조사.
추측으로 table 추가 금지.

기존에 이미 migration coverage 목록이 있다면
그 목록을 source of truth로 사용.

10. 이미 잘못 승인대기에 들어간 PARENT 처리
============================================================

중요.

현재 이미:

Kakao parent
→ General signup
→ approval pending

상태로 잘못 생성된 계정이 있을 수 있음.

코드 기준으로 recovery 경로 마련.

조건:

- 동일 phone
- 기존 Kakao parent 존재
- 새 General parent가 migration attempt로 생성된 것이 확인됨

이면:

관리자 승인 버튼 없이
migration state를 정상 완료 상태로 복구 가능하게 할 것.

필요 시 migration endpoint 재호출로:

- child refs 이전
- approved state 복원
- pending state 제거
- new General parent 활성화
- old Kakao parent disable

가능하게.
