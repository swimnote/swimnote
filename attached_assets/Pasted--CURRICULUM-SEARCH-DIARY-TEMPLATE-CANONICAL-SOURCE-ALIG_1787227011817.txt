# [CURRICULUM SEARCH — DIARY TEMPLATE CANONICAL SOURCE ALIGNMENT]

중요 설계 확정.

커리큘럼 검색의 원본 데이터는
별도 DOCX가 아니다.

각 수영장에 코드로 생성/등록하는
"일지 템플릿 목록(diary_templates)"이
실제 커리큘럼 원본이다.

수영장마다 일지 템플릿이 수백 개 생성되고,
그 데이터를 기반으로
Parent Curriculum Search AI가 동작해야 한다.

최종 구조:

diary_templates
= authoring/source of truth

curriculum_items
= AI curriculum search용 normalized/searchable index

==================================================
1. 목표
==================================================

수영장별 활성 diary_templates를
curriculum_items로 자동 materialize / sync한다.

Parent Curriculum Search는
curriculum_items를 계속 authority로 사용한다.

즉 기존 WP-A/B 검색 구조는 유지.

DOCX ingestion dependency는
Parent Curriculum Search 경로에서 제거한다.

==================================================
2. SOURCE
==================================================

대상 source:

diary_templates

반드시 실제 일지작성 화면에서
사용되는 활성 template만 대상.

필수 scope:

- swimming_pool_id
- 실제 활성 status
- 실제 사용 가능한 template scope

테스트/archived/global legacy template 제외.

==================================================
3. POOL SCOPING
==================================================

각 수영장별로 분리.

다른 pool의 diary_templates 혼입 금지.

예:

pool A diary_templates
→ pool A curriculum_items

pool B diary_templates
→ pool B curriculum_items

==================================================
4. MATERIALIZATION
==================================================

각 diary_template를
검색 가능한 curriculum_items로 변환.

원칙:

- 실제 교육 의미 단위 유지
- artificial split 금지
- 300개 맞추기 위한 inflation 금지
- duplicate 생성 금지
- 빈 내용 생성 금지

가능하면:

1 diary_template
→ 1 curriculum_item

단,
실제 template 구조상 하나의 row에
복수 독립 교육 단위가 명확히 존재하는 경우에만
semantic split 허용.

==================================================
5. ID / LINK
==================================================

curriculum_items가
원본 diary_template를 추적할 수 있게 한다.

가능하면 기존 schema 범위에서:

source_template_id
또는 equivalent relation

사용.

새 migration이 필요하면
먼저 보고 후 승인받는다.

임의 컬럼 추가 금지.

==================================================
6. VERSION
==================================================

현재 curriculum_items가
curriculum_versions를 필수로 요구한다면,

수영장별 diary-template 기반
managed curriculum_version을 생성/유지.

예:

source_type = diary_templates

단,
실제 schema 확인 후 구현.

기존 X DOCX version과 충돌 금지.

==================================================
7. SYNC BEHAVIOR
==================================================

일지 템플릿 추가/수정/비활성화 시
검색 인덱스도 동기화되어야 한다.

필요 동작:

- template 신규 → item 신규
- template 수정 → item 업데이트
- template inactive → item inactive
- template 삭제 → hard delete보다 inactive 우선

기존 데이터 보호.

==================================================
8. ELIGIBILITY
==================================================

X mode 기준:

해당 pool의
active searchable curriculum_items >= 300
→ eligible=true

<300
→ CURRICULUM_NOT_READY

기준 변경 금지.

X entitlement만으로 허용 금지.

==================================================
9. NORMAL POLICY
==================================================

Normal SWIMNOTE는
일지 템플릿이 300개 이상 있어도
Parent AI Curriculum Search는 계속 차단.

이번 sync는 필요하다면 X pool만 수행.

Normal 정책 변경 금지.

==================================================
10. SEARCH ENGINE
==================================================

Parent Curriculum Search는 계속:

curriculum_items
→ intent
→ evidence
→ progress resolver
→ professional DB
→ DIRECT_DB / GROUNDED_GPT / HUMAN_ONLY

구조 유지.

diary_templates를 검색엔진이 직접 읽도록
WP-A/B 전체를 다시 만들지 않는다.
