[1. 최신 우선순위]

지금은 기능 추가·업무 연결·잔여 구현을 먼저 마무리한다.
디자인 변경·메뉴 재배치·클릭형 UX 시안 제작은 시작하지 않는다.

향후 홈 화면은 자주 쓰는 업무를 바로 시작하는 공간으로 정리한다.
이 방향만 설계에 기록하고, 지금 별도 홈 개편 작업으로 확대하지 않는다.

기존 화면에서 선택값 전달·입력 보존·불필요한 왕복 제거처럼
작은 연결 개선은 기능 구현과 함께 진행한다.

PC를 우선 완성하고 모바일 앱 개편은 이후에 모아서 진행한다.
공유 서버는 기존 앱 호환성을 유지한다.
Smartro는 외부 대기로 분리한다.

[2. 기존 작업 재사용]

직전 보고의 로컬 커밋:
d759260d3525003a6415785f5b803a1aa71c3798

현재 HEAD와 작업 트리를 확인하되 임의 reset·checkout하지 않는다.
기존 소스·첨부·문서·커밋·설치본·복구 자료를 보존한다.

이미 구현한 회원 생성 영수증 복구, 리포트 대상 전달,
관리자 보고서, 마케팅·대회 연결, 가져오기 미리보기,
카드 재발급 흐름을 다시 만들지 않는다.

[3. 검사 실패부터 제한적으로 정리]

직전 전체 Desktop 검사에서 실패한 30건을 기존 결과로 분류한다.
전체 검사를 다시 돌리는 것부터 시작하지 않는다.

- 이번 변경으로 발생한 오류
- 변경된 정책과 맞지 않는 기존 검사
- 기존부터 있던 독립 오류
로 구분한다.

이번 변경의 실제 오류와 현재 제품 동작을 막는 문제는 수정한다.
정책 변경으로 기대값이 달라졌다면 근거에 맞게 검사를 수정한다.
통과시키기 위해 권한·복구·금액 검사를 삭제하거나 약화하지 않는다.

관련 범위만 확인하고 나머지 기능 개발을 계속한다.

[4. AI 연결의 실제 잔여 구현 완료]

현재 상태를 아래처럼 구분한 뒤 미구현 코드를 완성한다:
① 화면 이동
② 조회
③ 초안·필드 입력
④ 사용자 확인 후 실제 Action 실행
⑤ 구현 완료지만 모델 실행 스위치 OFF
⑥ 실제 미구현

‘승인 대기’라는 표현으로 미구현 기능을 묶지 않는다.

무료 AI 데이터 이전:
- 대화창과 원본·변환 미리보기 연결
- 자연어 의견을 제한된 변환 규칙으로 해석
- 대상·영향 표시와 규칙 수정·취소
- 후속 파일에도 사용자 결정 유지
- 모호한 대상·충돌만 묶어서 확인
- 회원·금융·잔여횟수·보강 자료 연결
- 실제 반영·중복·재개·결과 대조 연결
- 정형 처리는 일반 코드, 필요한 의미 해석만 모델 사용

일상 AI 작업창:
- 합의한 관리자 업무를 기존 공통 Action/API에 연결
- 메뉴에서 가능한 업무와 AI 연결의 누락을 기존 상태표에서 확인
- 모호한 대상 추측·임의 SQL·범용 HTTP 실행 금지
- 금액·삭제·대량변경·발송은 대상과 영향을 확인
- 계산과 권한 판정은 기존 서버 로직 사용
- 기존 X 이용권을 서버 모델 진입점에서도 확인
- 무료 이전이 일반 AI 이용권 우회 경로가 되지 않도록 제한

새 유료 모델 호출은 이번에 승인하지 않는다.
호출 없이 가능한 구현·계약 확인은 진행하고,
실제 모델 확인에 필요한 입력·횟수·예산만 마지막에 묶어 제시한다.
응답 재생·mock 결과를 실제 모델 성공으로 보고하지 않는다.

[5. 합의한 PC 기능을 끝까지 연결]

기존 설계·상태표와 현재 코드의 차이만 확인한다.
이미 구현한 기능은 재사용하고 빠진 부분만 구현한다.

회원·운영:
- 상담·체험·레벨테스트·대기·자리 제안·등록전환
- 보호자·가족·담당자·후속 연락·인수인계
- 휴회·복귀·반이동·퇴원·재등록의 적용일과 이력

수업·수강:
- 상품·할인·계약·수강권·회차조정
- 날짜별 반·수업·정원·강사·레인·휴강·대강
- 출결·보강·사용량·잔여권리 연결

금융:
- 청구·대량청구·부분수납·배분·미납·미배분금
- 정정·취소·환불·마감·지출·자금수지
- 가족별 조회와 회원별 귀속
- 계약 당시 조건 보존
- 결과 불명·중복 요청·재시작 복구
- 수기 기록과 실제 PG 승인·취소 구분

교육:
- 관리자 일지·사진·영상 조회와 앨범 업로드
- 성장리포트 본문·검수·발급·발송·당시 이력
- 같은 회원·report_id·버전의 연속성
- PC 강사 일지 작성 확대는 제외

문서:
- 태블릿 신청·동의·직접 서명·확정 문서
- 회원 등록·계약 연결과 재열람
- Excel/CSV·필요 PDF·인쇄
- 화면·상세·요약·출력의 조건 및 합계 일치

마케팅·운영지원:
- 채널·콘텐츠·일정·담당자·게시 기록
- 캠페인·소개·참여·유입·홍보 동의 구분
- 시설·물품·대회·참가·업체·본사 안내와 신청
- 외부 접수·승인·게시가 없으면 수동 기록임을 명시

정책 미정 부분은 해당 동작만 분리한다.
독립 기능 전체를 중단하거나 새로운 업무 범위를 임의 추가하지 않는다.

[6. 배차·NFC 외부 조건 처리]

배차:
- 기존 합의 설계서를 첨부·프로젝트 문서에서 찾아 원문 확인
- 못 찾으면 필요한 문서명을 정확히 보고
- 임의 재설계·내비게이션·셔틀 NFC 추가 금지
- 원문이 있으면 PC 배차·관리 범위부터 구현
- 기사·학부모 앱 작업은 후속 앱 범위로 구분

NFC:
- 실제 지원 연결 방식과 동작 조건 명시
- 스캔 모드 수신과 다른 업무 중 수신 구분
- 카드 입력이 메모·금액 입력칸에 섞이지 않도록 처리
- 기존 카드·출결·분실·재발급·중복 방지 연결 재사용
- 실장비·SDK가 없으면 그 부분만 대기
- 장비 미확인을 이유로 전체 개발을 멈추지 않음
- UID 관리만으로 실제 NFC 출결 완료 선언 금지

[7. 개발 확인과 사용자 확인]

개발 중:
- 변경 범위의 컴파일·타입·필수 동작 확인
- 권한·Pool 귀속·금액·중복·동시 수정·복구의 필요한 직접 검사
- 기존 증거 재사용
- 로그인 화면 렌더링을 업무 동작 확인으로 계산하지 않음

사용자:
- 기능마다 설치·확인을 요청하지 않음
- 최종 통합본에서 체크리스트로 모아서 확인
- 개발 도구 설치·소스 빌드·터미널 진단 요구 금지

새 검증 전용 제품·로컬 업무 DB·합성 인증·대형 검사 시스템을 만들지 않는다.

[8. Git·운영 적용]

GitLab 인증 문제와 독립적인 구현은 계속한다.
실패한 동일 인증 push를 반복하지 않는다.
인증이 복구되면 기존 동일 feature 브랜치에 일반 push한다.
main 반영·강제 push·다른 원격 우회는 하지 않는다.

새 서버 소스는 기존 운영 승인 범위에 자동 포함하지 않는다.
필요한 새 SHA·migration 유무·앱 영향·복구 방법을 묶어 제출한다.
이미 적용한 schema 2를 재적용하지 않는다.

실발송·자동 알림 활성화·실결제·실환불·새 유료 모델 호출·
구독/가격/청구/용량 정책 전환은 실행하지 않는다.
기존 운영 기능 설정을 일괄 변경하지 않는다.

[9. 완료·전달]

합의한 PC 잔여 기능을 모아 최신 통합 설치본을 제작한다.
소스 변경이 기존 설치본에 포함됐는지 정확히 구분한다.
장비·Smartro·후속 앱 대기는 별도 표시하고 전달 전체를 막지 않는다.
