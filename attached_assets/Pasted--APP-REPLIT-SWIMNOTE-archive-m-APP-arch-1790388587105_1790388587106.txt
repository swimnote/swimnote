[보낼 곳: APP REPLIT]

[SWIMNOTE — 관리자 하단 archive-m... 불필요 탭 조사 후 안전 제거]

현재 관리자 APP 하단 탭바 오른쪽 끝에

archive-m...

처럼 표시되는 불필요한 탭이 노출되어 있습니다.

실기기에서 확인된 현상:

- 하단 탭에 `archive-m...` 항목이 추가되어 있음
- 탭을 누르면 “지난 회원” 화면으로 들어감
- 화면 자체는 지난 회원 Archive 화면으로 보임
- 현재 지난 회원이 없으면 “지난 회원이 없습니다.” 표시
- 이 화면에서 뒤로가기 동작도 정상적이지 않음
- 관리자 메인 하단 탭에 상시 노출될 이유가 없음

중요:

퇴원생 Archive 기능 자체를 삭제하면 안 됩니다.

이미 구현된:

- 지난 회원 목록
- Archive 상세
- 과거 일지 조회
- 관리자 Archive 연결/해제
- 학부모 지난 수강 기록
- 기존 정상 “지난 회원” 진입 경로

는 그대로 유지해야 합니다.

이번 목표는:

“개발 과정에서 Archive route가 하단 Tabs에 자동 노출된 것인지 조사하고,
불필요한 하단 탭 노출만 안전하게 제거”

입니다.

3. 삭제 판단 기준
━━━━━━━━━━━━━━━━━━━━━━

조사 후 다음 기준으로 처리하십시오.

CASE A.

하단 archive-m...가
정상 Archive screen 자체인데

Tabs group 아래에 있어서
자동 노출된 경우:

→ screen 파일 삭제 금지.

대신:

- 하단 Tab에서 숨김
- 정상 “지난 회원” 버튼으로만 진입 가능
- navigation route는 유지

Expo Router에서 현재 프로젝트 구조에 맞는
정상적인 hidden route 방식 사용.

예:
`href: null`

등.

현재 Expo Router 버전/구조에 맞는
기존 프로젝트 패턴을 우선 사용.

CASE B.

archive-m...가
정상 Archive screen과 별개의
개발용/중복 route이고

실제 참조가 0개인 것이 확인되면:

→ 해당 개발용 route만 제거 가능.

단 삭제 전 반드시:

- import 검색
- router.push/replace 검색
- href 검색
- route name 검색
- Tabs.Screen 검색

으로 참조 0 확인.

CASE C.

정상 Archive route와
하단 Tab route가 복잡하게 얽혀 있으면:

→ 파일 삭제하지 말고
Tab 노출만 숨기는 최소 수정.

6. 뒤로가기 수정
━━━━━━━━━━━━━━━━━━━━━━

현재 archive-m... 탭 직접 진입에서는
뒤로가기가 정상적이지 않습니다.

하단 탭 노출 제거 후
정상 경로:

회원관리
→ 지난 회원

으로 진입했을 때

상단 뒤로가기 버튼이
정상적으로 이전 회원관리 화면으로 돌아가는지 확인.

필요하면 해당 screen의 back handler/navigation만
최소 수정.

금지:

- 무조건 home replace
- navigation stack 전체 재설계
- 다른 화면 back behavior 변경

정상 stack history가 있으면
router.back() 또는 기존 canonical back 패턴 사용.

history가 없는 direct/deep-link 상황은
기존 프로젝트 fallback 패턴이 있다면 그 패턴 사용.
