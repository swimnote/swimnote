# 2. deterministic path 의미 확인

LLM이 실제 호출되지 않은 Support request에서:

```text
provider=openai
```

가 기록되는 현재 동작의 코드 원인을 확인한다.

실제 provider call이 0인데 OpenAI provider usage처럼 기록된다면
비용 observability 의미상 부정확하다.

원인만 먼저 보고한다.

수정이 필요하면 최소 수정:

* 실제 OpenAI 호출 발생 → provider=openai
* deterministic only → provider를 실제 contract에 맞는 null/internal 값으로 처리

단 기존 event schema를 재설계하지 않는다.

Production DB를 수정하지 않는다.

* broad retrieval candidate는 1개 이상 나오는

기존 unit test에서 사용한 표현 변형/동의어 사례 중
production DB에도 존재하는 KI 하나를 재사용하는 것을 우선한다.

목표 경로:

```text
DIRECT_DB miss
→ broad retrieval candidate > 0
→ nanoResolve

→ validator
→ grounded answer
```
