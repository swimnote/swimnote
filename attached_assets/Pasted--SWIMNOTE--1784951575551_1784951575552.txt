# SWIMNOTE 보호자 가입·자녀 연결 흐름 최종 정리

## 작업 목적

보호자 가입은 보안상 안전해야 하지만, 정상 가입자는 최대한 쉽고 빠르게 기존 학생과 연결되어야 합니다.

이번 작업에서는 아래 흐름을 완성합니다.

1. 가입 시 입력한 자녀 이름을 관리자 화면에 명확히 표시
2. 미연결 보호자를 기존 학생과 직접 연결
3. 신규 학생 중복 생성 방지
4. 자동 연결 실패 시 관리자가 쉽게 확인하고 처리
5. 기존 승인 보호자의 추가 전화번호 가입자는 기존 학생에 연결
6. 다른 수영장 또는 다른 학생으로 잘못 연결되지 않도록 보안 유지

학생 병합 기능 자체는 이번 작업 범위에 포함하지 않습니다.

──────────────────────────────
1. 관리자 미연결 보호자 상세 화면
──────────────────────────────

현재 미연결 보호자 상세 화면에서 아래 정보를 반드시 표시합니다.

- 보호자 이름
- 보호자 전화번호
- 가입일
- 가입 상태
- 가입 시 입력한 자녀 이름
- 현재 연결 상태
- 자동 연결 실패 여부

가입 시 입력한 자녀 이름이 존재하면 눈에 잘 띄게 표시합니다.

예시:

가입 시 입력한 자녀 이름
김민준

연결 상태
미연결

reg_request.child_names 또는 parent_v2_pending.child_name_raw 중 실제 가입 경로에서 저장된 값을 사용하십시오.

두 곳에 값이 모두 존재하면 최신 가입 요청 또는 현재 pending 데이터를 기준으로 일관되게 표시하십시오.

값이 없을 경우:

가입 시 입력한 자녀 이름
정보 없음

으로 표시하십시오.

섹션 자체를 숨기지 마십시오.

──────────────────────────────
2. 기존 버튼 제거 또는 변경
──────────────────────────────

미연결 보호자 화면에서 신규 Student 생성을 유도하는 버튼을 기본 동작으로 두지 마십시오.

기본 버튼은 다음으로 통일합니다.

기존 학생과 연결

기존 문구 중 아래와 같은 의미의 버튼이 있으면 교체합니다.

- 학생 등록 후 바로 연결
- 새 학생 등록
- 자녀 신규 등록
- 연결하기인데 실제로 Student를 생성하는 동작

기본 동작은 반드시 기존 Student 검색 및 연결이어야 합니다.

──────────────────────────────
3. 기존 학생 검색 화면
──────────────────────────────

관리자가 "기존 학생과 연결"을 누르면 기존 학생 검색 화면 또는 모달을 엽니다.

초기 검색어:

- 가입 시 입력한 자녀 이름을 자동 입력
- 자녀 이름이 없으면 빈 검색창 표시

검색 결과에 반드시 표시할 정보:

- 학생 이름
- 소속 반
- 현재 상태
- 현재 레벨
- 대표 보호자 이름
- 대표 보호자 전화번호 일부 마스킹
- 추가 보호자 전화번호 존재 여부
- 이미 연결된 보호자 수

전화번호 전체를 불필요하게 노출하지 마십시오.

예시:

김민준
돌고래반 · LEVEL_2
보호자: 김○○ / 010-****-1234
연결된 보호자 1명

──────────────────────────────
4. 학생 검색 API
──────────────────────────────

현재 GET /students가 전체 조회 후 클라이언트 필터링 방식이라면, 관리자 연결 전용 검색 API를 사용하거나 추가하십시오.

권장 형태:

GET /admin/students/search?q={검색어}&poolId={현재 pool}

검색 조건:

- 학생 이름
- 보호자 이름
- parent_phone
- parent_phone2
- 필요 시 학생 상태

필수 보안 조건:

- 현재 관리자의 swimming_pool_id 안에서만 검색
- 다른 tenant 학생 반환 금지
- 최소 2글자 이상 입력 후 검색
- 결과 수 제한
- 페이지네이션 또는 최대 결과 제한
- 일반 보호자 계정에서 호출 금지
- 관리자 권한 확인

기존 API를 안전하게 재사용할 수 있다면 새 API를 만들지 않아도 됩니다.

단, pool 전체 학생 데이터를 한 번에 클라이언트로 내려받는 방식은 사용하지 마십시오.

──────────────────────────────
5. 기존 Student에 보호자 연결
──────────────────────────────

기존에 존재하는 API:

POST /admin/parents/:parentId/link-student

를 우선 재사용하십시오.

관리자가 학생을 선택하면 연결 전 확인 모달을 표시합니다.

예시:

보호자 서정주님을
학생 문희택에게 연결하시겠습니까?

연결 후 서정주님은 문희택 학생의
수업일지, 출결, 진도 정보를 확인할 수 있습니다.

[취소] [연결]

연결 처리 결과:

- 기존 Student 재사용
- 신규 Student 생성 금지
- parent_students 관계 생성
- 이미 같은 관계가 존재하면 중복 생성하지 않음
- 기존 학생 데이터 변경 금지
- 반, 레벨, 출결, 일지 유지
- 보호자 앱에서 즉시 기존 학생 표시

──────────────────────────────
6. 연결 완료 후 상태 처리
──────────────────────────────

수동 연결 성공 후 아래 상태를 정리합니다.

- parent_v2_pending 상태를 linked 또는 완료 상태로 변경
- 재매칭 대상에서 제외
- 관리자 미연결 명단에서 제거
- 보호자 상세 화면에 연결된 학생 표시
- 보호자 홈에서 기존 학생 즉시 표시
- 기존 가입 요청 상태도 승인 완료 또는 연결 완료 상태로 갱신

pending 레코드를 무조건 삭제하지 말고 기존 시스템의 상태 관리 방식을 따르십시오.

가입 이력 추적이 가능해야 합니다.

──────────────────────────────
7. 신규 학생 등록은 보조 동작
──────────────────────────────

검색 결과에 실제 기존 학생이 없을 때만 다음 보조 동작을 제공합니다.

새 학생으로 등록

이 버튼은 기본 버튼보다 작게 표시하거나 검색 결과 없음 상태에서만 노출합니다.

신규 등록 전 반드시 중복 후보를 한 번 더 확인합니다.

확인 조건:

- 동일 이름 학생
- 유사 이름 학생
- 동일 보호자 전화번호
- 동일 추가 보호자 전화번호

중복 후보가 있으면 바로 신규 생성하지 말고 기존 학생 후보를 다시 보여주십시오.

──────────────────────────────
8. 자동 연결과 수동 연결 우선순위
──────────────────────────────

가입 흐름은 다음 순서로 동작해야 합니다.

1. 보호자 가입
2. 전화번호 정규화
3. 동일 pool 내 parent_phone 또는 parent_phone2 검색
4. 정확히 한 명의 학생과 일치하면 자동 연결
5. 여러 학생이 일치하면 자동 연결 금지
6. 전화번호 일치가 없으면 자녀 이름 기반 pending 생성
7. 관리자 화면에 가입 시 입력한 자녀 이름 표시
8. 관리자가 기존 학생 검색 후 수동 연결
9. 실제 기존 학생이 없는 경우에만 신규 학생 등록

이 순서를 변경하지 마십시오.

──────────────────────────────
9. 보안 요구사항
──────────────────────────────

필수 보안 조건:

- 모든 자동 및 수동 연결은 동일 swimming_pool_id 내부에서만 수행
- 관리자 권한 검증
- 보호자 본인이 임의의 student_id를 넣어 연결할 수 없도록 차단
- 서버에서 parentId, studentId, poolId 관계 재검증
- 클라이언트가 전달한 poolId만 신뢰하지 않음
- 이미 다른 tenant에 연결된 학생을 반환하지 않음
- 전화번호는 서버에서 정규화
- 로그에 전화번호 전체값 노출 금지
- 연결 요청 반복 호출 시 중복 관계 생성 금지
- 연결 성공 전 학생 정보 전체 반환 금지
- 다른 보호자의 개인정보 과다 노출 금지

──────────────────────────────
10. 이번 작업에서 변경 금지
──────────────────────────────

- 학생 데이터 병합 기능
- 출결/일지 데이터 이동
- Student 삭제
- parent_students 구조 변경
- 신규 레벨 구조 변경
- 가입 인증 방식 변경

- DB 대규모 리팩터링
- 다른 수영장 데이터 접근
- 기존 정상 자동 연결 로직 제거

──────────────────────────────
11. 실제 테스트 시나리오
──────────────────────────────

테스트 1
- 가입 시 자녀 이름 입력
- 자동 연결 실패 상태 생성
- 관리자 미연결 상세 화면에 자녀 이름이 표시되는지 확인

테스트 2
- 관리자 "기존 학생과 연결" 선택
- 가입 시 입력 이름이 검색창에 자동 입력되는지 확인
- 기존 학생 검색 후 연결
- 신규 Student가 생성되지 않았는지 확인

테스트 3
- 연결 완료 후 관리자 미연결 명단에서 제거되는지 확인
- 보호자 앱 홈에 기존 학생이 즉시 표시되는지 확인

테스트 4
- 기존 학생의 반, 레벨, 출결, 일지가 그대로 유지되는지 확인

테스트 5
- 같은 보호자와 학생을 다시 연결 요청해도 parent_students 중복이 생성되지 않는지 확인

테스트 6
- 다른 swimming_pool_id의 학생이 검색 결과에 나오지 않는지 확인

테스트 7
- 일반 보호자 계정으로 관리자 학생 검색 API 호출이 차단되는지 확인

테스트 8
- 동일 이름 학생이 여러 명일 때 반, 레벨, 마스킹된 보호자 정보로 구분 가능한지 확인

테스트 9
- 검색 결과가 없을 때만 "새 학생으로 등록" 흐름이 제공되는지 확인

테스트 10
- parent_phone2로 가입한 추가 보호자가 자동 연결되는 기존 수정 기능이 그대로 유지되는지 회귀 테스트

──────────────────────────────
12. 완료 조건
──────────────────────────────

코드 수정 또는 API 성공만으로 완료 처리하지 마십시오.

실제 Production 앱에서 아래 흐름을 끝까지 직접 조작하십시오.

보호자 가입
→ 자동 연결 실패
→ 관리자 미연결 상세 확인
→ 가입 시 입력 자녀 이름 확인
→ 기존 학생 검색
→ 기존 Student 연결
→ 보호자 앱 로그인
→ 기존 학생 표시 확인

완료 보고서에 아래를 포함하십시오.

1. 수정한 파일
2. 수정한 API
3. 수정한 화면
4. 가입 시 자녀 이름 데이터 출처
5. 기존 학생 검색 방식
6. tenant 격리 방식
7. 신규 Student 생성 여부
8. parent_students 중복 여부
9. pending 상태 변경 방식
10. 모든 테스트 결과
11. 실제 DB 검증 결과
12. 관리자 앱 스크린샷
13. 보호자 앱 스크린샷

실제 앱에서 전체 흐름이 확인되지 않았거나 스크린샷이 없으면 완료로 처리하지 마십시오.
