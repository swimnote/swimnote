현재는 코드를 수정하지 마세요.

학부모 일지와 사진 기능을 부분적으로 계속 수정하면서
홈, 상세, 앨범의 데이터 연결이 서로 달라진 것으로 보입니다.

먼저 현재 production 서버, DB, 클라이언트의 실제 구조를
증거 기반으로 전부 분석해서 보고하세요.

추측이나 개선안 없이 현재 구조만 제출하세요.

1. 일지 저장 구조
────────────────────

선생님이 일지를 저장할 때 실행되는 전체 흐름을 작성하세요.

저장 버튼
→ 호출 함수
→ API endpoint
→ 서버 route
→ service/query
→ INSERT 또는 UPDATE
→ 관련 테이블
→ 응답 JSON
→ 저장 후 이동 화면

각 단계마다 다음을 포함하세요.

- 파일명
- 함수명
- 라인 번호
- 전달되는 주요 데이터
- 반환되는 데이터

다음 항목도 명확히 확인하세요.

- 저장할 때 매번 새 diary row를 INSERT하는지
- 기존 학생 일지를 UPDATE하는지
- 수업별 diary 식별자가 무엇인지
- diary가 lesson_session 또는 attendance와 연결되는지
- 공통일지와 학생별일지가 각각 어디에 저장되는지
- 하나의 수업에서 학생마다 diary row가 따로 생기는지
- 한 diary 안에 여러 학생 내용이 저장되는지
