6. 중복 Notification 정책
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

시간 기반:

"1시간 내 동일 ref_id 알림 차단"

을 핵심 idempotency 규칙으로 사용하지 않는다.

정상 기준:

실제 request 상태가 변했을 때만 알림 생성.

예:

pending → done
= 1회 알림

pending → rejected
= 1회 알림

같은 상태를 다시 PATCH:

done → done
rejected → rejected

= 새 알림 생성 금지.

가능하면 기존 status를 UPDATE 전에 읽어서:

previousStatus !== requestedStatus

일 때만 notification + push를 실행한다.

현재 서버 정책상 done/rejected → pending 재전환을 허용하고 있다면
그 구조를 이번에 임의 변경하지 않는다.

단 동일 상태 no-op에서 중복 결과 알림이 발생하면 안 된다.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
