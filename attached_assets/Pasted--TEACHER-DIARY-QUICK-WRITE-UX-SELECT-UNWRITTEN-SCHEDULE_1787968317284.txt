[앱]

TEACHER DIARY QUICK WRITE UX
SELECT UNWRITTEN SCHEDULE FIRST

목표:
현재 "일지 바로쓰기" 버튼이
임의/기존 날짜로 diary 화면에 바로 진입하는 방식을 제거한다.

새 동작:

일지 바로쓰기
→ 내 수업 스케줄 중 일지 미작성 회차 목록 표시
→ 정확한 회차 선택
→ 해당 날짜/시간/반 기준 diary 작성 시작

==================================================
1. CURRENT BUG
==================================================

현재 "일지 바로쓰기"를 누르면
특정 schedule occurrence를 선택하지 않았는데도
diary.tsx가 fallback 날짜를 사용하면서
예: 8/6이 이미 선택된 상태로 진입함.

이 방식 제거.

Quick Write에서는
lessonDate를 임의 생성하거나 today fallback으로 정하지 않는다.

==================================================
2. NEW QUICK WRITE FLOW
==================================================

"일지 바로쓰기" 탭:

STEP 1
미작성 수업 선택 화면 또는 modal/bottom sheet 표시

STEP 2
현재 로그인 선생님의 실제 schedule occurrence 목록 조회

STEP 3
각 회차별로 diary 작성 여부 확인

STEP 4
미작성 회차만 기본 표시

STEP 5
사용자가 하나 선택

STEP 6
선택한 schedule occurrence의 실제 값을
diary 화면으로 전달

반드시 전달:

- lessonDate
- classGroupId
- schedule/slot identifier가 기존에 있으면 그것도
- startTime
- class name/display name

==================================================
3. LIST CONTENT
==================================================

각 row 예:

8/13 (목)
19:00 · 목 19:00반
일지 미작성

또는:

8/13 목 · 19:00
목 19:00반

정렬:
최근 날짜 우선 또는 현재 날짜에 가까운 순서.

과거 미작성 회차도 선택 가능.

미래 수업은
실제 운영 정책상 일지를 미리 쓸 수 없다면 제외.
현재 앱 정책 확인 후 기존 기준 유지.

==================================================
4. SESSION IDENTITY
==================================================

목록에서 "미작성" 판정은
반드시 기존 수정 기준과 동일하게:

최소:
class_group_id + lesson_date

기존 schema에 schedule/session/slot id가 있으면
그 값까지 포함.

중요:
Quick Write 목록의 미작성 판정,
diary 화면의 기존 일지 판정,
저장 귀속

세 곳이 동일한 session identity를 사용해야 한다.

==================================================
5. ALREADY WRITTEN SESSION
==================================================

기본 Quick Write 목록에서는
이미 작성된 회차는 제외.

단,
사용자가 "지난 일지" 또는 기존 schedule 화면에서
이미 작성된 회차로 진입하면
기존 replacement confirmation UX를 사용:

"이 수업의 일지가 이미 작성되어 있습니다.
새로 작성한 일지로 기존 일지를 바꾸시겠습니까?"

Quick Write에서는
굳이 작성 완료 회차를 기본 노출하지 않는다.

==================================================
6. EMPTY STATE
==================================================

미작성 수업이 없으면:

"작성할 수업 일지가 없습니다."

보조 문구:

"모든 수업 일지가 작성되었습니다."

확인 버튼만.

==================================================
7. DATE SOURCE OF TRUTH
==================================================

Quick Write에서 diary 진입 후
diary 화면 상단 날짜는 반드시
사용자가 목록에서 선택한 schedule occurrence의 lessonDate.

todayStr()
todayDateStr()
latest diary date
fallback diary date

사용 금지.

예:

8/13 회차 선택
→ diary header = 2026-08-13
→ save lesson_date = 2026-08-13

==================================================
8. UI
==================================================

현재 "일지 바로쓰기" 버튼 자체 디자인은 유지 가능.

버튼 클릭 후
새 full screen을 만들기보다
기존 앱 패턴에 맞는 modal / bottom sheet / selector 우선.

필요하면 제목:

"작성할 수업 선택"

설명:

"일지를 작성할 수업을 선택해주세요."

==================================================
9. PRESERVE EXISTING PATHS
==================================================

기존:

스케줄 화면
→ 특정 회차
→ 일지작성

경로는 유지.

이 경로는 이미 선택한 날짜를 그대로 diary로 전달.

이번 작업은
"일지 바로쓰기" 진입 UX만 개선.
