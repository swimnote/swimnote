# 수업일지 뒤로가기 내비게이션 수정

현재 잘못된 동선:

스케줄러
→ 반 상세 모달
→ 수업일지
→ 뒤로가기
→ 홈 화면

이 동선은 잘못되었습니다.

사용자가 수업일지 화면으로 들어온 경로는
스케줄러의 특정 반 상세 모달입니다.

따라서 뒤로가기를 누르면
직전 화면과 상태로 돌아가야 합니다.

정상 동선:

스케줄러
→ 특정 반 상세 모달
→ 수업일지
→ 뒤로가기
→ 스케줄러
→ 방금 열었던 특정 반 상세 모달이 다시 열린 상태

==================================================
1. 핵심 수정
==================================================

수업일지 화면의 뒤로가기 로직에서
Home으로 보내는 모든 코드를 제거하세요.

다음 사용 여부를 확인하세요.

- router.replace('/home')
- router.push('/home')
- navigation.navigate('Home')
- navigation.replace('Home')
- navigation.reset(...)
- tabs/home 강제 이동
- fallback으로 홈 이동
- 저장 후 홈 이동 상태가 뒤로가기에도 재사용되는지

직전 화면으로 돌아갈 때는
navigation.goBack()
또는 router.back()
또는 현재 내비게이션 구조에 맞는 pop()
을 사용하세요.

==================================================
2. 반 상세 모달 상태 복원
==================================================

단순히 스케줄러 화면만 보여주는 것으로 끝내지 마세요.

사용자가 수업일지 진입 전에 열었던
반 상세 모달도 다시 열린 상태여야 합니다.

보존해야 할 값:

- 선택한 날짜
- 선택한 반
- classGroupId
- lessonDate
- lessonTime
- 선택한 스케줄 항목
- 반 상세 모달 open 상태
- 현재 월/주/일 보기 상태
- 스케줄러 스크롤 및 선택 상태가 있다면 그대로 유지

수업일지 진입 전에
반 상세 모달을 완전히 초기화하거나 삭제하지 마세요.

==================================================
3. 권장 구현 방식
==================================================

가능하면 가장 안전한 방식으로 수정하세요.

권장 방식 A:

스케줄러 화면의 navigation stack 위에
수업일지 화면을 push

뒤로가기 시 pop/goBack

기존 스케줄러 화면과 모달 state가 그대로 남아 있도록 유지

권장 방식 B:

반 상세 모달을 닫아야 수업일지 진입이 가능한 구조라면

수업일지 진입 시 route params에 다음 정보 전달:

- returnTo: 'scheduler'
- reopenClassModal: true
- classGroupId
- lessonDate
- lessonTime

수업일지에서 뒤로가기 시
스케줄러로 복귀한 뒤
해당 반 상세 모달을 자동 재오픈

단, Home을 중간에 거치지 마세요.

==================================================
4. 뒤로가기 진입 경로별 처리
==================================================

수업일지 화면은 여러 경로에서 진입할 수 있으므로
진입 경로를 구분하세요.

A. 스케줄러 반 상세 모달에서 진입

뒤로가기:
→ 스케줄러
→ 동일 반 상세 모달 재오픈

B. 홈의 ‘일지 바로쓰기’에서 진입

뒤로가기:
→ 홈

C. 지난 일지 목록에서 수정 화면 진입

뒤로가기:
→ 지난 일지 상세 또는 목록

모든 경우를 무조건 홈으로 보내면 안 됩니다.

진입 경로에 따라 직전 화면으로 복귀해야 합니다.

==================================================
5. 수정해야 할 실제 원인 찾기
==================================================

표면적으로 뒤로가기 버튼만 고치지 말고
왜 Home으로 튕기는지 정확한 원인을 찾으세요.

확인 항목:

- 수업일지 화면 header back handler
- Android hardwareBackPress
- iOS 상단 뒤로가기 버튼
- useFocusEffect
- beforeRemove listener
- 저장 완료 후 route replace
- 화면 unmount 시 홈 redirect
- route params 누락 시 fallback
- 스케줄러에서 수업일지 열 때 replace 사용 여부
- 모달 close 후 home route가 stack 최상단이 되는 구조인지
