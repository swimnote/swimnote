==================================================
1. WP-C 목적
==================================================

기존:

artifacts/swim-app/app/(parent)/home.tsx
artifacts/swim-app/app/(parent)/curriculum-chat.tsx

를 확장하여

학부모가 ChatGPT와 유사한 방식으로
AI 커리큘럼 검색을 사용할 수 있는 UI를 만든다.

신규 홈 버튼 생성 금지.

기존 "커리큘럼 검색" 버튼을 그대로 사용.

==================================================
2. NORMAL SWIMNOTE BUTTON — 중요
==================================================

현재 home.tsx:

selectedStudent
&&
(mode === "x" || mode === "x_pending")

일 때만 버튼 표시.

이 조건을 수정하여
Normal 학부모에게도 기존 커리큘럼 검색 버튼을 표시한다.

최소 조건:

selectedStudent 존재

버튼 디자인/위치/아이콘은
기존 것을 최대한 그대로 유지.

==================================================
3. NORMAL USER UX
==================================================

Normal 학부모가 버튼을 누르면
기능 자체를 숨기거나 disabled 처리하지 않는다.

curriculum-chat 화면으로 진입 후
서버 eligibility 결과에 따라 안내 상태 표시.

안내:

"현재 수영장에 AI 검색용 커리큘럼이 등록되어 있지 않아
커리큘럼 AI 검색을 이용할 수 없습니다."

이 상태에서는:

- 질문 입력창 숨김
- 추천 질문 숨김
- 전송 버튼 숨김
- AI 호출 없음
- quota 차감 없음

기존 뒤로가기/navigation은 정상 유지.

==================================================
4. CURRICULUM NOT READY
==================================================

X/허용 센터라도
검색 가능한 curriculum_items < 300이면
동일한 unavailable UI 사용.

서버 reason 예:

CURRICULUM_NOT_AVAILABLE
CURRICULUM_NOT_READY

둘 모두 안전하게 처리.

개발자용 code는 화면에 노출하지 않는다.

==================================================
5. ELIGIBLE USER UI
==================================================

검색 가능한 사용자는
기존 curriculum-chat.tsx를 확장.

목표 UX:

ChatGPT와 유사한 익숙한 대화 방식
+
SWIMNOTE 기존 디자인 유지.

필수:

- 사용자 질문 표시
- AI 답변 표시
- 대화 아래로 누적
- 하단 고정 입력창
- 전송 버튼
- keyboard 처리
- 자동 scroll
- loading/typing indicator
- retry 기존 기능 유지

==================================================
6. 첫 화면 추천 질문
==================================================

현재 message가 없는 첫 진입 상태에서
추천 질문 표시.

예:

"지금 어디까지 배웠나요?"
"최근에는 무엇을 배우고 있나요?"
"자유형은 어디까지 했나요?"
"다음 단계는 무엇인가요?"

추천 질문 탭:

일반 텍스트 질문 전송과
동일한 send flow 사용.

별도 API 만들지 않는다.

==================================================
7. 답변 COPY — V1 필수
==================================================

각 ASSISTANT 답변 하단에:

[복사]

추가.

복사 대상:

사용자에게 보이는 답변 text 전체.

복사 제외:

- metadata
- intent
- answer_mode
- knowledge_ids
- validation
- 내부 JSON
- source id

복사 성공:

"복사되었습니다"

짧은 toast/snackbar.

Expo/RN 현재 프로젝트에서 이미 사용하는
clipboard 패키지가 있으면 재사용.

없으면 최소 의존성 방식 검토 후
불필요한 package 추가는 피한다.

==================================================
8. QUOTA 표시
==================================================

기존 API response:

usage {
  limit,
  used,
  remaining,
  period,
  resets_at
}

및 기존 UsageInfo state 재사용.

검색 가능 화면에서 작게 표시.

권장 표현:

"이번 달 AI 검색 3/10회"

또는:

"이번 달 남은 검색 7회"

기존 SWIMNOTE UI에 자연스럽게 배치.

과도하게 큰 경고 UI 금지.

==================================================
9. QUOTA EXHAUSTED UI
==================================================

서버:

429
PARENT_CURRICULUM_MONTHLY_LIMIT_REACHED

수신 시:

"이번 달 AI 커리큘럼 검색 이용 횟수를 모두 사용했습니다.
다음 달에 다시 이용할 수 있습니다."

표시.

입력창은 disabled 또는 전송 차단.

사용자가 계속 눌러 API를 반복 호출하지 않도록 처리.

==================================================
10. ANSWER MODE UI
==================================================

서버가 additive response로:

answer_mode
intent

를 반환해도
사용자 화면에 내부 enum을 그대로 노출하지 않는다.

DIRECT_DB
GROUNDED_GPT
HUMAN_ONLY

모두 사용자에게는
일반 AI 답변처럼 표시.

HUMAN_ONLY라고
"HUMAN_ONLY" badge 노출 금지.
