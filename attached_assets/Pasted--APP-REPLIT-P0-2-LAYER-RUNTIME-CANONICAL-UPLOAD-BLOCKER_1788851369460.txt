1. Global scope 규칙 확정
━━━━━━━━━━━━━━━━━━━━━━

scope 기준은:

GLOBAL:
is_global_reference = true

LOCAL:
is_global_reference = false
AND swimming_pool_id = current pool

로 고정.

import_status에
GLOBAL_REFERENCE라는 신규 상태 추가 금지.

scope와 lifecycle 상태를 섞지 않는다.

Global version은:

is_global_reference=true
import_status='ACTIVE'

로 검색 가능하게 한다.

is_active는 기존
"pool당 active local version 1개"
제약 때문에 Local activation 이후 false가 될 수 있다.

따라서 Global 검색은
is_active=true에 의존하지 말고:

is_global_reference=true
AND import_status='ACTIVE'

기준으로 한다.

━━━━━━━━━━━━━━━━━━━━━━
2. swimming_pool_id 건드리지 말 것

현재 global version의:

swimming_pool_id =
pool_1780849364252_l9k44rbk3

는 이번 작업에서 변경하지 않는다.

'SYSTEM' sentinel 삽입 금지.
가짜 system pool 생성 금지.

runtime scope 판정은
is_global_reference를 source of truth로 사용.

장기 schema cleanup은 별도 작업.

4. Local 우선 규칙
━━━━━━━━━━━━━━━━━━━━━━

동일/유사 기술이 Local + Global에 동시에 있으면:

1. Local candidate가 정상 threshold 충족
   → Local을 progress target

2. Global도 같이 적합
   → Global은 grounding/support only

3. Global만 적합
   → AI grounding에는 사용 가능
   → Local curriculum progress에는 반영 금지

단순 score가 Global이 더 높다는 이유로
Local progress target을 Global item으로 교체하지 않는다.

Local은 해당 수영장의 공식 교육과정이다.
