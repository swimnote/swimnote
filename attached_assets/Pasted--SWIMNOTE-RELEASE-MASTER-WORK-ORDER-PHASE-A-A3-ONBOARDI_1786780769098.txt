==================================================
2. ONBOARDING UX PRINCIPLE
==================================================

전체 앱 공통:

1. 지금 사용자가 해야 할 행동만 안내
2. 한 화면에서 여러 행동을 동시에 요구하지 않음
3. 긴 설명 금지
4. 완료한 작업을 다시 안내하지 않음
5. 닫은 가이드가 매 실행마다 반복되지 않음
6. 내부 개발 용어 노출 금지
7. 기능명보다 행동 중심 문구 사용
8. Empty state와 Tutorial을 구분
9. 안내 때문에 실제 업무를 막지 않음
10. Admin / Teacher / Parent 모두 동일한 UI 문법 사용

==================================================
3. COPY STYLE
==================================================

문장은 짧고 직접적으로 작성.

예:

BAD:
"아직 등록된 회원 데이터가 존재하지 않습니다. 회원 관리 기능을 이용하기 위해 먼저 회원을 등록해주세요."

GOOD:
"등록된 회원이 없습니다."
[회원 등록]

BAD:
"AI 기반 수영 전문 분석 서비스를 이용해보세요."

GOOD:
"수업 내용을 입력하면 AI가 일지 초안을 작성합니다."
[AI 일지 작성]

개발 용어 금지:

API
ENGINE
DB
config_status
READY
entitlement
request_id
trace_id

등.

==================================================
4. FIRST-RUN vs EMPTY STATE
==================================================

FIRST-RUN:

처음 사용하는 사람에게
기능 사용법을 알려주는 상태.

EMPTY STATE:

현재 데이터가 없는 상태.

둘을 혼동하지 않는다.

예:

회원 없음
→ Empty State

회원 등록 방법 3단계 안내
→ First-use Guide

가능하면 Empty State 자체에
다음 행동 CTA를 제공해
별도 Modal 사용을 줄인다.

5. ADMIN / OWNER
==================================================

최초 사용자가
앱에 들어온 뒤 무엇부터 해야 하는지 확인한다.

실제 기존 구조 기준으로
필요한 contextual guide만 제공.

권장 흐름 후보:

운영처 확인
→ 반/수업 생성
→ 선생님 초대
→ 학생/회원 등록
→ 학부모 연결

단:

새로운 대형 Wizard를 만들지 않는다.

현재 화면에서
Empty State + CTA로 해결 가능하면
그 방식을 우선한다.

==================================================

X_PENDING:

8. PARENT
==================================================

상태를 분리:

A. 자녀 미연결
B. 자녀 연결됨 + 데이터 없음

==================================================
11. X SETUP
==================================================

X setup은 특히 중요.

사용자가 봤을 때:

- 현재 상태
- 완료된 것
- 아직 필요한 것
- 다음 행동

이 명확해야 한다.

완료된 항목을
계속 미완료처럼 표시하지 않는다.

READY가 되면
setup을 계속 강제로 안내하지 않는다.

내부 상태명 대신 사용자 언어 사용.

예:

config_status = READY

를 화면에 그대로 노출 금지.

대신:

"설정 완료"

처럼 표시.

==================================================
12. X_PENDING
==================================================

x_pending은:

"X를 사용할 수 없는 오류 상태"

처럼 보이면 안 된다.

정확히:

설정 중
심사 중
승인 대기

등 실제 원인을 사용자에게 보여준다.

실행 불가능한 AI CTA는 제거.

필요한 setup entry만 유지.

14. EMPTY STATE CTA RULE
==================================================

예:
회원
반
공지

→ CTA 가능.

사용자가 직접 만들 수 없는 데이터:

예:

Teacher에게 아직 배정되지 않은 수업

→ 잘못된 생성 CTA 금지.

설명만 제공하거나
올바른 담당자를 안내.

==================================================
17. LOGIN / SIGNUP
==================================================

첫인상 영역.

확인:

- 회원가입 단계가 명확한가
- 같은 설명이 반복되는가
- CTA 이름이 일관적인가
- 완료 후 다음 화면이 예상 가능한가
- 역할 선택이 이해 가능한가
- back 동작이 자연스러운가
- 실패 시 오류 안내가 이해 가능한가

현재 디자인 시스템 유지.

19. MODAL MINIMIZATION
==================================================

온보딩을 무조건 Modal로 만들지 않는다.

우선순위:

1. Empty State
2. Inline Guide
3. Small Banner
4. Modal

Modal은 사용자가 반드시 알아야 하는 경우만.

A4에서 Modal system을 별도 정리할 예정이므로
이번에는 onboarding 목적의 불필요 Modal을 줄이는 데 집중.
