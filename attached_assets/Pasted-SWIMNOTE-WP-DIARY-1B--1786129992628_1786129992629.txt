SWIMNOTE — WP-DIARY-1B 정정 지시

실기기 결과:
개별일지는 여전히 높이가 늘어나지 않는다.

새로운 자동 높이 방식을 설계하지 마라.

사용자 요구는 단순하다:

"현재 전체일지에서 이미 정상 작동하고 있는
텍스트 길이에 따른 입력창 확장 방식을
개별일지에도 똑같이 적용한다."

━━━━━━━━━━━━━━━━━━━━
1. 전체일지 구현을 Source of Truth로 사용
━━━━━━━━━━━━━━━━━━━━

DiaryWriteView.tsx에서
현재 전체일지 TextInput의 실제 구조를 전부 추적한다.

확인:

- JSX 전체
- style 전체
- value
- onChangeText
- multiline
- numberOfLines
- scrollEnabled
- height / minHeight / maxHeight
- 부모 View
- KeyboardAwareScrollView와의 관계
- 별도 state
- onContentSizeChange 사용 여부

"왜 늘어나는지" 추측하지 말고
현재 정상 전체일지 코드를 그대로 Source of Truth로 한다.

━━━━━━━━━━━━━━━━━━━━
2. 개별일지에 동일 방식 적용
━━━━━━━━━━━━━━━━━━━━

개별일지 TextInput의 동작을
전체일지 TextInput과 동일하게 만든다.

차이가 필요한 것은:

전체일지:
commonContent

개별일지:
해당 student_id의 note_content

라는 데이터 연결뿐이다.

레이아웃/텍스트 확장 방식은 동일하게 맞춘다.

새로운 noteHeights state,
onContentSizeChange 기반 별도 시스템 등은
전체일지에 없는 방식이라면 추가하지 않는다.

전체일지에 이미 검증된 방법을 그대로 쓴다.

━━━━━━━━━━━━━━━━━━━━
3. 학생별 독립성 유지
━━━━━━━━━━━━━━━━━━━━

학생 A의 개별일지가 길면
A 카드만 그 내용만큼 늘어난다.

학생 B/C는 영향받지 않는다.

학생이 20명이면:

학생1 카드
학생2 카드
학생3 카드
...
학생20 카드

가 아래로 이어지고
기존 바깥 화면 스크롤로 끝까지 볼 수 있어야 한다.

각 학생 TextInput 내부에 별도 스크롤을 만들지 않는다.

━━━━━━━━━━━━━━━━━━━━
4. 미리보기 전체 표시 유지
━━━━━━━━━━━━━━━━━━━━

이전 WP에서 제거한:

numberOfLines={2}

는 다시 넣지 않는다.

학생 카드의 개별일지 내용은
전체 문장이 보이도록 유지한다.

━━━━━━━━━━━━━━━━━━━━
5. DiaryEditView도 동일
━━━━━━━━━━━━━━━━━━━━

일지 작성뿐 아니라
기존 일지 수정 화면에서도

전체일지와 같은 확장 방식을
개별일지 TextInput에 적용한다.

Write/Edit 동작을 맞춘다.

━━━━━━━━━━━━━━━━━━━━
