# SWIMNOTE AUTH EMERGENCY
# PHASE 1 — KAKAO LOGIN RECOVERY IMPLEMENTATION
# PLAN A HYBRID — MINIMAL PATCH ONLY

가격/RevenueCat/WP5 작업은 계속 HOLD입니다.

PHASE 0 AUTH AUDIT는 검수 완료되었습니다.

이번 PHASE 1은
카카오 로그인 장애 + 로그인/회원가입 UX + 카카오 계정 복구 경로를
최소변경으로 실제 구현하는 단계입니다.

Apple 대규모 auth rewrite는 이번 범위에서 금지합니다.

==================================================
0. 구현 원칙
==================================================

최종 Kakao UX:

[카카오 아이콘] 카카오로 로그인/회원가입

하나의 버튼으로:

기존 Kakao-linked SWIMNOTE user
→ LOGIN

기존 SWIMNOTE user지만 Kakao 미연결
→ 안전한 ACCOUNT LINKING

완전 신규 사용자
→ SIGNUP

를 처리합니다.

별도의:

카카오 로그인 버튼
+
카카오 회원가입 버튼

을 따로 만들지 마십시오.

==================================================
1. 카카오 버튼 UI 수정
==================================================

현재 index.tsx의 아이콘-only Kakao 버튼을:

"카카오로 로그인/회원가입"

텍스트가 포함된 버튼으로 변경.

기존 UI 디자인/색상/레이아웃을 최대한 유지.

새로운 별도 카카오 버튼 추가 금지.

Apple 버튼도 같은 원칙으로:

"Apple로 로그인/회원가입"

으로 레이블만 명확화.

Apple 기능 로직은 이번 단계에서 재설계하지 않음.

==================================================
2. 기존 Kakao login flow 유지
==================================================

현재 flow:

kakaoLogin()
→ accessToken
→ POST /auth/kakao-social-login
→ Kakao /v2/user/me
→ kakao_id 조회
→ 기존 SWIMNOTE user login

유지.

새로운 OAuth stack으로 교체 금지.

SDK 교체 금지.

==================================================
3. Kakao identity lookup 우선순위
==================================================

최종 lookup 우선순위:

1.
kakao_id exact match

2.
Kakao verified phone이 존재하는 경우
기존 SWIMNOTE account phone match

3.
매칭 실패 시
즉시 신규가입시키지 않고
ACCOUNT LINKING 선택 제공

4.
사용자가 기존 계정이 없다고 선택한 경우만
신규가입

중요:

phone_number를 로그인 성공의 필수조건으로 만들지 마십시오.

Kakao에서 phone을 제공하지 않는 사용자가 존재할 수 있습니다.

==================================================
4. 전화번호 정규화 보정
==================================================

현재:

+82 10-1234-5678
→ 01012345678

형식만 단순 equals 비교하는 문제 수정.

기존 DB phone이:

01012345678
010-1234-5678
+821012345678

등 가능한 기존 저장형식인 경우
동일인을 찾을 수 있도록
현재 find-identifier-by-phone의 정규화 패턴을 재사용.

새로운 대규모 phone utility rewrite 금지.

기존 helper가 있으면 재사용.

==================================================
5. kakao_no_account 처리 변경
==================================================

현재:

kakao_no_account
→ 바로 signup

금지.

변경:

kakao_no_account
→ 사용자에게 다음 선택 제공

"이미 SWIMNOTE 또는 수영장에 등록된 계정이 있으신가요?"

[기존 계정 연결]
[새로 가입하기]

기존 계정 연결:
→ 기존 kakao-link flow 재사용

새로 가입하기:
→ 현재 signup flow

기존 kakao-link.tsx를 최대한 재사용.

==================================================
6. Account linking 안전성
==================================================

기존 계정 연결 시:

사용자가 본인 계정임을 검증하지 않은 상태에서
임의의 account에 kakao_id를 붙이면 안 됩니다.

현재 kakao-link.tsx의 인증 방식을 감사하고
기존:

전화번호 인증
기존 login credential
센터 등록 정보 확인

등 실제 본인 확인 절차가 있다면 재사용.

단순히 전화번호 입력만으로
다른 account에 kakao_id 저장 가능한 구조라면
구현 중단 후 보고.

자동 merge 신규 구현 금지.

==================================================
7. sub_admin / role lookup 수정
==================================================

PHASE 0에서 발견된:

role IN ('teacher','pool_admin')

때문에 sub_admin 등 정상 운영 role이
Kakao login에서 누락되는 문제 수정.

단 다음처럼 과도한 NOT IN 추측을 바로 넣지 마십시오.

먼저 실제 users.role enum / 사용 role 전체를 코드에서 확인.

정상 앱 로그인 허용 role만 명시적으로 포함하는 방향 우선.

예:

teacher
pool_admin
sub_admin

등 실제 role 목록 확인 후 적용.

super_admin / platform_admin 등
관리자 전용 계정을 Kakao 일반 로그인에 실수로 포함하지 마십시오.

완료보고에 최종 허용 role 목록 제출.

8. Kakao password / account recovery UX
==================================================

SWIMNOTE가 Kakao password를 reset하지 않습니다.

현재 forgot-password / find-id flow에서
social_provider = kakao가 확인되면:

"카카오로 가입한 계정입니다."

안내 후

[카카오로 로그인/계정 복구]

CTA를 제공.

현재 텍스트 안내만 있고 CTA가 없다면 추가.

CTA:
→ 로그인 화면의 Kakao login flow를 실행하거나
→ Kakao 인증 entry point로 연결

사용자가 다시 일반 SWIMNOTE 비밀번호 재설정 화면으로
돌아가게 하면 안 됨.
