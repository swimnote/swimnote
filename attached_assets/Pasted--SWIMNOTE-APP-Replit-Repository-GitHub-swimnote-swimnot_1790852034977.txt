그중:

- 9건은 이미 approved 관계가 존재
- 2건은 전화번호 불일치 가능
- 1건은 학생 특정 불가

기존 approved 9건은

현재 성공 상태와 정합하게 정리한다.

중요:

이 9건은 “새 자동승인”이 아니다.
이미 승인된 관계의 stale pending cleanup이다.

정리 전/후 건수를 기록한다.

전화번호 불일치 2건과
학생 특정 불가 1건은

- matched = 정상 승인/연결 완료 상태
- 승인됨 탭에서 정상 표시
- pending 탭에서는 제외

되도록 상태 매핑을 바로잡는다.

기존 approved 관계와 혼동하지 말 것.

DB migration은 만들지 않는다.

4. 관리자 PUSH
━━━━━━━━━━━━━━━━━━━━━━

학부모가:

[관리자에게 승인 요청하기]

를 누르면

해당 pool의 관리자에게 PUSH를 보낸다.

기존 알림/PUSH 인프라를 최대한 재사용한다.

새 대규모 notification 시스템 만들지 않는다.

알림 예시:

제목:
학부모 연결 승인 요청

내용:
학부모 연결 승인을 기다리는 요청이 있습니다.

PUSH 선택
→ 승인관리 > 학부모 연결 > 해당 pending 요청
으로 이동 가능하면 기존 navigation 구조를 이용한다.

pool isolation 필수.

다른 수영장 관리자에게 보내면 안 된다.

동일 pending에 대해 버튼을 반복해서 눌러
PUSH spam이 발생하지 않도록
기존 구조로 가능한 최소 dedupe/cooldown을 둔다.

과도한 복잡한 시스템은 만들지 않는다.

→ 해당 학생 개인정보 확인창

빠르게 보고 처리할 수 있어야 한다.

7. 확인 버튼 하나로 처리

관리자가 정보를 확인/수정한 뒤

[확인]

버튼 하나로 처리한다.

불필요하게:

저장
→ 뒤로가기
→ 다시 승인
→ 학생선택
→ 승인

같은 절차를 만들지 않는다.

[확인] 한 번으로 서버에서:

1. pending 재조회
2. parent/pool 재검증
3. 학부모 계정에 결합된 SMS 인증 전화번호 확인
4. 대상 student 및 pool 확인
5. 입력된 허용 학생정보 저장
6. 저장된 parent_phone 슬롯과 인증 전화번호 재비교
7. 일치하면 관계 승인
8. 동일 pool/동일 인증번호 정상 형제도 기존 정책대로 연결
9. pending → matched
10. commit

까지 수행한다.

가능한 한 하나의 transaction으로 처리한다.

중간 실패 시 부분 승인 상태를 남기지 않는다.

15. 필수 테스트
━━━━━━━━━━━━━━━━━━━━━━

CASE A
정상 신규 학부모
SMS 인증번호 = 등록 보호자 번호
→ 기존대로 자동승인
→ 관리자 pending 없음

CASE B
SMS 인증번호 ≠ 등록 보호자 번호
→ pending
→ 학부모에게 관리자 승인 요청 버튼 표시

CASE C
학부모가 관리자 승인 요청 버튼 클릭
→ 해당 pool 관리자 PUSH
→ 다른 pool PUSH 0

CASE D
같은 pending에서 버튼 반복 클릭
→ 과도한 중복 PUSH 방지

CASE E
관리자가 승인 클릭
학생 안전하게 특정 가능
→ 학생 선택목록 없음
→ 해당 학생 개인정보 확인창 바로 표시

CASE F
관리자가 등록 전화번호를
학부모 인증번호와 동일하게 수정 후 확인
→ 서버 재검증
→ 즉시 승인
→ pending matched

CASE G
확인 후에도 번호 불일치
→ 승인 금지
→ pending 유지
→ 관리자에게 전화 확인 안내

CASE H
동일 번호 형제 2명
→ 정상 형제 모두 연결
→ 중복 없음

CASE I
다른 pool 동일 번호 학생
→ 연결 0

CASE J
이미 approved 관계
→ 관계 변경 없음
→ 중복 없음

CASE K
학생 withdrawn/deleted
→ 승인 대상 제외

CASE L
학생 특정 불가
→ 임의 학생 선택/승인 없음
→ 신규회원/회원정보 확인 안내

CASE M
기존 approved + stale pending
→ 새 관계 생성 없이 stale pending만 정합성 정리

CASE N
승인됨 탭
→ matched 완료 요청 정상 표시
→ pending 탭에서는 제거

CASE O
학부모가 입력한 학생 이름 오타/복수이름
→ 전화번호 기반 정상 신규 자동승인에 영향 없음
