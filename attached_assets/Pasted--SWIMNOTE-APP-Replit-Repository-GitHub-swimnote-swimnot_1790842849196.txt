[학부모 연결 — 전화번호 기반 자동승인 최소 수정]

목적:
학부모 ↔ 학생 연결의 자동승인 조건만 수정한다.

성장리포트 작업은 HOLD 상태 유지.
AI ENGINE 작업 금지.
관리자 승인관리 UI/PC/다른 기능 변경 금지.

확정 정책:

1. 학부모가 SMS/OTP로 실제 소유 인증한 전화번호와
2. 선택한 수영장의 students.parent_phone1~4 중 하나가 일치하면

학생 이름 입력값과 관계없이 자동승인한다.

동일 수영장에 같은 보호자 전화번호로 등록된 학생이 여러 명이면
해당 학생들을 모두 같은 학부모에게 연결한다.

학부모에게 표시되는 학생 이름은
가입자가 입력한 child_name이 아니라
기존 students.name을 그대로 사용한다.

1. 보안 전제부터 수정
━━━━━━━━━━━━━━━━━━━━━━

현재 조사에서 확인된 문제:

POST /api/auth/v2/parent-register가
제출된 phone이 실제 SMS 인증을 완료한 번호인지
서버에서 강제하지 않는다.

따라서 이름 조건을 제거하기 전에
반드시 서버에서 전화번호 소유 인증을 강제한다.

기존:

POST /api/auth/send-sms-code
POST /api/auth/verify-sms-code

및 기존 phone_verifications 구조를 최대한 재사용한다.

요구사항:

SMS 인증 성공
→ 서버가 검증 가능한 짧은 수명의 proof 발급
→ proof는 인증된 전화번호에 귀속
→ parent-register에서 proof 검증
→ proof 전화번호와 가입 phone이 동일한지 검증
→ 성공한 경우에만 phone-only auto-link 허용

클라이언트의 smsState === verified만 신뢰하면 안 된다.

임의의 phone을 parent-register body에 넣는 직접 API 요청으로
자동연결할 수 없어야 한다.

새로운 대규모 인증 시스템을 만들지 않는다.
현재 OTP 구조를 이용한 최소 변경으로 구현한다.

필요한 경우 signup.tsx는
인증 proof를 최종 가입 요청에 전달하는 최소 변경만 허용한다.

━━━━━━━━━━━━━━━━━━━━━━
2. V2 자동승인 matching 변경
━━━━━━━━━━━━━━━━━━━━━━

핵심 대상:

artifacts/api-server/src/lib/auto-link-v2.ts

현재 tryMatchStudentV2():

학생 이름 exact match
→ 전화번호 match

순서를 자동승인 기준에서 제거한다.

새 기준:

선택된 pool
+
서버에서 인증 완료된 학부모 전화번호
+
students.parent_phone / parent_phone2 / parent_phone3 / parent_phone4

일치.

childName은 자동승인 matching key로 사용하지 않는다.

이름:
정확
오타
여러 자녀 이름을 한 문자열로 입력
완전히 다른 문자열

어느 경우든 전화번호가 일치하면
이름 때문에 pending으로 보내지 않는다.

전화번호가 일치하지 않으면
이름이 정확해도 자동승인 금지.

━━━━━━━━━━━━━━━━━━━━━━
3. 형제/자매 자동연결
━━━━━━━━━━━━━━━━━━━━━━

같은 pool에서 동일한 인증 전화번호가 등록된
모든 해당 학생을 찾는다.

예:

박하윤 / 01011112222
박유하 / 01011112222

학부모 인증번호:
01011112222

→ 박하윤 연결
→ 박유하 연결

두 학생 모두 자동승인.

기존:

linkApprovedParentToRegisteredChildren()
linkParentToStudentV2()

구조를 재사용하되 중요한 제한:

기존 helper가
unregistered / pending_approval 학생을 active로 변경하는
부수효과가 조사에서 확인됐다.

이번 수정에서는
“학부모 연결 조건 변경” 이외의
학생 등록/승인 상태를 임의로 변경하면 안 된다.

필요하다면 helper 전체를 그대로 호출하지 말고
기존 approved/정상 학생에 대한 관계 생성 부분만
최소 재사용/분리한다.

학생 status 변경은 이번 작업 범위 밖이다.

이미 같은 parent/student 관계가 approved라면 유지한다.
중복 관계를 만들지 않는다.

아직 연결되지 않은 동일 전화번호 학생만 추가한다.

━━━━━━━━━━━━━━━━━━━━━━
4. POOL 경계 유지
━━━━━━━━━━━━━━━━━━━━━━

전화번호 검색은 반드시 현재 선택한:

swimming_pool_id

내에서만 수행한다.

같은 전화번호가 다른 수영장에도 존재한다고 해서
다른 pool 학생까지 연결하면 안 된다.

구형:

autoLinkParentToStudents()
parent-link-scheduler

등의 pool 제한 없는 검색 로직을
이번 phone-only 연결에 재사용하지 않는다.

이번 작업에서 legacy 시스템 전체를 개편하지 않는다.

새 V2 자동승인 경로에서만
명확한 pool boundary를 보장한다.
