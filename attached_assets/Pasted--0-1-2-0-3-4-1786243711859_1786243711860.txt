[긴급 수정 — 출석학생 0명 일지 작성 후 임시상태가 남는 문제]

현재 재현:

1. 선생님이 일지 작성 화면 진입
2. 출석 학생이 0명인 상태
3. 공통 일지 내용 입력
4. 사진 여러 장 첨부
5. 저장 시:
   "출석한 학생이 없어 일지를 저장할 수 없습니다. 출결을 먼저 확인해주세요."
   메시지로 저장 차단
6. 이후 뒤로가기/나가기
7. 다시 일지 작성 화면에 들어오면 이전에 작성한 텍스트/사진 등의 임시상태가 남아 있음

이 상태는 잘못된 동작이다.

━━━━━━━━━━━━━━━━━━━━━━
1. 기존 정책 유지
━━━━━━━━━━━━━━━━━━━━━━

출석 학생 0명일 때 일지 저장 금지는 그대로 유지한다.

출결 판정 로직,
출석 API,
일지 저장 API,
기존 정상 저장 흐름은 변경하지 않는다.

이번 수정은 Draft/작성세션 정리에 한정한다.

━━━━━━━━━━━━━━━━━━━━━━
2. 먼저 실제 상태 보관 위치 조사
━━━━━━━━━━━━━━━━━━━━━━

코드 수정 전 다음을 확인한다.

- 공통 일지 state 위치
- 학생별 일지 state 위치
- 첨부 사진 state 위치
- 첨부 영상 state 위치
- 선택 템플릿 state 위치
- AI 생성 결과 임시 state 위치
- 현재 draft/session state가 Context인지 local state인지
- 화면 unmount 시 cleanup이 존재하는지
- 뒤로가기 handler
- 하단 "나가기" 버튼 handler
- 저장 성공 후 reset 함수
- 저장 실패 후 reset 여부

실제 함수명/파일명 기준으로 보고 후 수정한다.

━━━━━━━━━━━━━━━━━━━━━━
3. 나가기 동작
━━━━━━━━━━━━━━━━━━━━━━

작성 중인 내용이 하나라도 있으면:

- 공통 일지 text
- 학생별 text
- 사진
- 영상
- AI 생성 draft
- 기타 작성 session 데이터

뒤로가기 또는 "나가기" 버튼 탭 시 확인 Alert:

제목:
일지 작성을 종료할까요?

내용:
작성 중인 내용은 저장되지 않습니다.

버튼:
취소
나가기

취소:
현재 작성 화면 유지
state 변경 없음

나가기:
작성 session 전체 reset
→ 화면 종료

━━━━━━━━━━━━━━━━━━━━━━
4. 반드시 reset할 항목
━━━━━━━━━━━━━━━━━━━━━━

나가기 확정 시 최소:

- common diary text
- student diary text
- selected photos
- selected video
- photo upload temp state
- selected template
- AI draft/generated result
- loading/progress state
- edit/create mode에서 생성한 temporary state
- 기타 이 작성 화면에서만 유지되는 draft

전부 초기화.

단 기존 서버에 저장된 실제 일지,
기존 사진,
기존 출결 데이터는 삭제 금지.

━━━━━━━━━━━━━━━━━━━━━━
5. 저장 실패와 draft 삭제를 혼동하지 말 것
━━━━━━━━━━━━━━━━━━━━━━

출석 학생 0명으로 저장 버튼을 눌렀을 때는:

- 저장 실패 Alert 표시
- 작성 내용은 그 자리에서는 유지

이 시점에 자동 삭제하지 않는다.

사용자가 출결을 수정하고 다시 돌아와 저장할 수도 있기 때문이다.

단 그 상태에서 사용자가
뒤로가기/나가기를 확정하면
draft를 완전히 폐기한다.

━━━━━━━━━━━━━━━━━━━━━━
6. 저장 성공 시 기존 reset 유지
━━━━━━━━━━━━━━━━━━━━━━

정상 저장 성공 후 기존에 draft reset이 있다면 그대로 유지.

새 reset 로직을 중복으로 만들어
정상 저장 후 화면에 영향을 주지 않도록 한다.

가능하면 기존 reset 함수가 있다면 재사용한다.

━━━━━━━━━━━━━━━━━━━━━━
7. 하드웨어/제스처 Back 포함
━━━━━━━━━━━━━━━━━━━━━━

가능한 범위에서 확인:

- 화면 상단 뒤로가기 버튼
- 하단 나가기 버튼
- iOS swipe back
- Android hardware back

작성 중 draft가 있을 때
서로 다른 경로로 빠져나가면서 cleanup이 누락되지 않도록 한다.

현재 router 구조상 전부 가로챌 수 없는 경우
지원 가능한 경로와 제한사항을 보고한다.

━━━━━━━━━━━━━━━━━━━━━━
8. 테스트 CASE
━━━━━━━━━━━━━━━━━━━━━━

CASE 1
출석 0명 + 텍스트 작성 + 저장
→ 저장 차단
→ 내용 화면에 유지

CASE 2
CASE 1 상태 → 나가기
→ 확인 Alert
→ 취소
→ 내용 유지

CASE 3
CASE 1 상태 → 나가기 → 확정
→ 화면 종료
→ 재진입
→ 빈 작성화면

CASE 4
출석 0명 + 사진 9장 + 텍스트
→ 나가기 확정
→ 재진입
→ 사진 0장 / text 빈값

CASE 5
AI 작성 결과 존재
→ 나가기 확정
→ 재진입
→ AI draft 없음

CASE 6
정상 출석 학생 존재
→ 정상 저장
→ 기존 저장 흐름 정상

CASE 7
기존 저장된 일지 편집 화면
→ 나가기
→ 서버 저장 데이터 삭제되지 않음

CASE 8
일반 일지 작성/사진/영상/AI 기능 회귀 없음
