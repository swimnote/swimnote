5. 수정 목표
━━━━━━━━━━━━━━━━━━━━

API contract는 유지:

result.answer: string

Markdown 강제하지 않는다.

최종 answer는 plain text + 실제 \n\n 형식.

예:

현재 상태

현재 기록만으로 정확한 진도를 판단하기는 어렵습니다.

먼저 익힐 부분

배영에서는 머리 위치와 몸의 정렬을 먼저 안정시키는 것이 중요합니다.

중요한 포인트

킥을 할 때 무릎이 과도하게 올라오지 않도록 리듬을 유지하는 것이 중요합니다.

규칙:

- 2~4개 짧은 섹션
- 섹션 제목 plain text
- 제목 뒤 빈 줄
- 문단당 1~3문장
- 지나치게 긴 한 문단 금지
- 같은 내용 반복 최소화
- 학부모 친화적 문장
- 학생 진도 미확인 안내는 1~2문장 이내
- retrieved curriculum evidence 밖 지식 생성 금지
- Markdown bold 강제 금지

8. 실제 ENGINE 테스트
━━━━━━━━━━━━━━━━━━━━

가능하면 실제 개발/테스트 환경에서
아래 질문 6개를 호출한다.

1. 배영 어려워?
2. 자유형에서 중요한 게 뭐야?
3. 평영 발차기 왜 어려워?
4. 접영은 언제 배우나요?
5. 우리 아이 지금 어느 단계야?
6. 다음에 뭘 배우게 돼?

각 질문에 대해 확인:

- final answer가 2~4개 섹션인지
- 실제 \n\n 포함 여부
- Markdown marker 없는지
- 한 문단으로 뭉치지 않는지
- 근거 밖 지식 생성 없는지
- 기존 의미가 바뀌지 않았는지

가능하면 수정 전/후 비교.

Production 사용자 데이터 변경 금지.

필요하면 test fixture / test tenant 사용.

━━━━━━━━━━━━━━━━━━━━

- API contract 동일

- crash 가능성 없음
