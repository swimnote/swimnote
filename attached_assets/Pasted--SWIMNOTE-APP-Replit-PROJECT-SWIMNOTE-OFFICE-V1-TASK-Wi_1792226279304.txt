2. 이번 목표

다음 두 차단을 해결한다.

A. 실제 제품 인증 경로를 합성 DB에 연결.
B. Windows 체크리스트 수행에 필요한 격리 오류 주입 도구 완성.

Linux에서 정상 인증 기반 최소 통합 검증까지 수행하고,
Windows에서 실행할 새 고정 후보·전달 자료를 준비한다.

Windows 접근이 없으면 Windows 실행은 NOT RUN으로 남긴다.
준비 완료와 Windows 통합 수용을 구분한다.

3. 실제 인증 의존성 확인

저장소 source·schema·migration을 기준으로 확인:

- routes/auth.ts의 실제 로그인·PIN/TOTP 분기.
- JWT 발급·검증과 제품의 세션 종료·무효화 동작.
- middlewares/auth.ts의 현재 사용자·역할·탈퇴 상태 검증.
- @workspace/db의 db·superAdminDb 연결과 초기화 부작용.
- users·swimming_pools 및 필요한 인증 관계·제약.
- auth/me, pools/my-pools, pools/x-mode.
- Desktop 업무 화면이 실제 요구하는 조회 경로.
- limiter·event logger·SMS/parent hook 등의 외부 의존성.

운영 DB·metadata에 접속하지 않는다.
필요한 분기만 조사하고 전체 시스템 개편으로 확대하지 않는다.

제품이 실제 요구하는 PIN/TOTP 정책을 유지한다.
현재 없는 토큰 갱신·회수 기능을 구현된 것으로 가정하지 않는다.

4. 격리 DB·정상 인증 연결

기존 연결 주입 구조를 우선 사용.
불가능한 부분만 최소한으로 분리한다.

- 실제 제품 로그인 handler·JWT·권한 미들웨어 재사용.
- 합성 사용자·Pool·주 계정·제한 계정 구성.
- 실제 필요한 인증 schema·제약·관계 유지.
- 전용 loopback DB만 허용.
- 운영 DSN·Secret 접근 및 fallback 금지.
- 연결·schema·격리 확인 실패 시 시작 차단.
- 운영 app/index startup으로 의존성을 채우지 않음.
- fixture Bearer·가짜 성공 JWT·미들웨어 skip 금지.
- AuthContext alias·별도 모방 로그인 handler 금지.

기존 office_acceptance 업무 schema와 정상 인증 schema 사이의
사용자·Pool ID 및 권한 귀속을 명시적으로 연결한다.
서로 다른 Pool을 같은 것으로 취급하는 우회 매핑 금지.

실제 외부 발송 없이 필요한 인증 경로가 가능한지 확인.
필수 외부 의존성 때문에 불가능하면 차단 지점과 최소 조건 보고.
독립적으로 가능한 준비는 계속 완료한다.

5. 합성 자격증명·문자 인코딩

DB 비밀번호와 로그인 비밀번호·PIN·JWT 키를 구분한다.
필요한 로컬 비밀은 실행 시 새로 생성한다.

- Windows에서는 제한 ACL 설정 성공 후 비밀 파일 작성.
- ACL 실패 시 비밀 작성·시작 중단.
- 로그·명령줄·ZIP·manifest에 비밀 포함 금지.
- 사용자에게 합성 로그인 정보를 확인하는 로컬 방법 제공.
- private.json·DB data·토큰·세션 파일 업로드 금지.
- 필요한 UTF-8 SQL client encoding 고정 유지.
- 한글 합성 이름·메모의 seed→조회→수정 왕복 확인.

기존 후보의 명시적 UTF-8 보완을 잃지 않는다.

6. 정상 인증 기반 최소 통합 검증

Linux 전용 DB·API에서 실제 로그인으로 토큰을 발급받아 검증:

- 정상 로그인→현재 사용자·Pool 조회.
- 잘못된 자격증명 거부.
- 인증 누락·변조·만료 거부.
- 타 Pool·제한 역할 접근 거부.
- 비활성·탈퇴 사용자 및 비활성 Pool 처리.
- 실제 제품에서 요구하는 PIN/TOTP 분기.
- 제품이 실제 지원하는 로그아웃·세션 무효화 동작.

업무 검증용 토큰을 직접 만들어 넣지 않는다.
오류 검증용 토큰은 음성 테스트로 별도 구분.

이후 기록된 응답을 이용해:
- 검색.
- 일반정보 수정.
- 지정 소속 반이동.
- 다른 소속·주당 횟수 보존.
- receipt 결과 재조회.
- 실행 OFF에서 기존 결과 조회.
- 사용자·Pool 변경 후 이전 결과 접근 차단.

신규 유료 모델 호출 0회.
HTTP 성공과 실제 DB 변경을 각각 확인한다.

7. 격리 오류 주입 도구 완성

첨부 체크리스트에서 미구현으로 남긴 다음을 준비:

A. 응답 유실
- 합성 명령이 실제 완료된 후 실행 응답 전달만 유실.
- 쓰기 1회와 receipt 저장 확인.
- UI 결과 불명 처리와 자동 재발급·재실행 없음 확인.
- 같은 요청 ID의 결과 조회로 복구.

B. 실행 OFF
- 완료 receipt를 유지한 채 신규 실행만 차단.
- 기존 receipt 조회는 현재 인증·권한 검증 후 허용.
- 인증 미준비 503과 실행 gate OFF를 구분.

C. 세션 교체
- 정상 로그아웃·다른 합성 계정/Pool 로그인으로 수행.
- 이전 카드·초안·첨부 및 receipt 접근 격리 확인.

D. stale revision·결과 조회 실패
- 승인된 합성 writer로 충돌 생성.
- 결과 조회만 실패시켜 미열람 유지 확인.

오류 주입은 격리 runner/transport에서만 제공.
제품 API에 테스트 endpoint·보안 우회 분기 추가 금지.
OS 방화벽·운영 API·임의 proxy로 오류를 만들지 않는다.
Windows 사용자가 실행할 정확한 조작·복구 명령을 작성한다.

8. 기존 실행 도구와 연결

기존 VerifyCandidate/BuildDesktop/Prepare/Start/Check/
LaunchDesktop/Stop/DeleteData 흐름을 갱신한다.

- 정상 인증·schema 준비 증거가 있을 때만 barrier 해소.
- 플래그만 바꿔 ISOLATED_AUTH_NOT_READY 제거 금지.
- app://office renderer와 단일 loopback API origin 유지.
- preload·IPC·DPAPI·sandbox·contextIsolation·webSecurity 유지.
- 기존 제품 userData·세션과 격리 유지.
- 부모 운영 환경변수 전달 금지.
- 기존 포트 점유자·다른 프로세스 종료 금지.
- 이번 도구가 만든 자원만 종료.
- 합성 데이터 삭제는 별도 명시적 명령 유지.

강제 종료 후 stale lock에 대한 진단 방법도 명시.
소유권 확인 없이 lock 삭제·PID 종료·재시작하지 않는다.

9. 의존성·빌드 검증 경계

기존 standalone lock과 provenance를 보존한다.
원본 workspace lockfile을 임의 변경하지 않는다.

보고된 런타임 버전은:
- 실제 package/lockfile 고정값.
- engines 요구사항.
- 기존 설치 metadata.
- 실제 검증 환경.
으로 구분한다.

Linux 기존 의존성 재사용 컴파일을
새 lockfile 설치 성공으로 표현하지 않는다.

가능하면 깨끗한 임시 Linux 폴더에서
standalone frozen-lockfile 설치·빌드를 제한 검증한다.
이는 Windows 네이티브 설치 증거가 아님을 명시한다.
다운로드가 불가능하면 그 항목만 미검증으로 남긴다.

호스트 Node와 Electron embedded Node를 구분.
호스트 버전 불일치 경고를 기록하고 요구 버전에서 검증.

Windows용 의존성·Electron binary 준비 방법은 안내하되
사용자 PC 자동 설치·관리자 권한·실행 정책 변경 금지.

새 후보로 다음을 함께 식별:

- 합성 schema·seed.
- 격리 runner·재생·오류 주입 도구.
- standalone manifest·lockfile·실행 안내.

기존 서버 후보와 달라진 파일·이유 기록.
기존 후보·ZIP은 보존하고 새 ID·새 ZIP 생성.
파일 목록·기준 source·patch/manifest/ZIP 해시 기록.

BuildDesktop의 기존 출력 덮어쓰기 금지 정책 유지.
새 후보에서 새 build-evidence 생성.
추적 dist/index.mjs는 임의 삭제·복원하지 않는다.

전달본에 비밀·node_modules·Linux 임시 출력 제외.
실제 handler와 재생/오류 주입 코드의 빌드 경계 검사.

실행 안내와 WINDOWS-CHECKLIST를 실제 도구에 맞춰 갱신.
미구현 기능을 실행 가능하다고 기재하지 않는다.
