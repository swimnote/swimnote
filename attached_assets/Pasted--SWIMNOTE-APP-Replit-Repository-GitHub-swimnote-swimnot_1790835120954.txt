2. 토이키즈스윔클럽 기준 Dry-run
━━━━━━━━━━━━━━━━━━━━━━

Production DB를 수정하지 않는다.

가능하면 기존 코드의 read-only/dry-run 경로 또는
격리된 mock/test DB를 이용해 실제 함수들을 실행한다.

가짜로 결과 문자열을 만들어 보고하지 말고
실제 production code path를 호출한다.

발급월:
2026-10

분석월:
2026-09

pool:
토이키즈스윔클럽

2026-10-01
→ 2026-09 cycle 준비

→ 토이키즈 회원 발급대상 판정

→ KST:
2026-09-01 00:00 이상
2026-10-01 00:00 미만

→ 인정수업:
예정 - 결석 + 완료 보강

→ 휴일/휴강 제외

→ 동일 class/date 중복 제외

→ 인정수업 >= 3

→ 학생 개인 일지 >= 1

→ continuing/active/nondeleted 조건

→ 분석 대상 생성

각 단계의 실제 실행 결과를 보여준다.

3. ENGINE 요청 직전까지 실제 실행
━━━━━━━━━━━━━━━━━━━━━━

APP/API가 실제로 사용하는 기존 경로로
ENGINE request payload가 만들어지는 것을 보여준다.

반드시 확인:

APP/API
→ snapshot builder
→ ENGINE client
→ POST /api/v1/growth-report/analyze

실제 생성되는 요청에서 개인정보를 제거하고 다음을 출력:

- report_period
- timezone
- analysis_from
- cutoff
- snapshot_version
- request_id 존재 여부
- snapshot/canonical hash 존재 여부
- lessons/diaries가 payload에 포함되는 구조
- 대상 pool context 존재

ENGINE endpoint를 mock으로 바꾼 별도 구현을 만들지 않는다.
현재 production code가 사용하는 client/path를 증명한다.

4. ENGINE 성공 응답 이후 APP 동작 실행 증거
━━━━━━━━━━━━━━━━━━━━━━

실제 GPT 비용을 발생시키지 않도록
ENGINE response 부분만 기존 검증 fixture를 사용해도 된다.

단 이후 처리는 실제 production code path를 실행한다.

확인:

ENGINE 성공 응답
→ response validation
→ 결과 저장 경로
→ report 상태 전환
→ 성공 결과 보존
→ 동일 성공 결과 재분석 방지

그리고 실패 fixture로:

retryable failure
→ retry

retry limit
→ FAILED

restart/stale
→ recovery

가 실제 실행되는 것을 보여준다.
