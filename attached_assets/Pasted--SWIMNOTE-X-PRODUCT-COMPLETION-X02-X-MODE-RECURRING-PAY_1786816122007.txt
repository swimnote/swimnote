==================================================
15. DISCOUNT ARCHITECTURE
==================================================

RevenueCat/App Store/Google Play에서
가입 순번별 서로 다른 가격을
어떻게 안전하게 구현할 수 있을지 조사한다.

가능한 구조를 실제 Store/RevenueCat 제약 기준으로 비교:

- 별도 Product/Package
- Promotional Offer
- Offer code
- Introductory Offer
- RevenueCat targeting/offering
- 기타 현재 지원 가능한 구조

중요:

아직 구현하지 않는다.

"앱 DB에서 50% 계산하고
Store에는 임의 금액 청구"

같은 구조 금지.

실제 Store transaction 가격과
표시 가격이 일치해야 한다.

17. DISCOUNT PERSISTENCE
==================================================

한 번 확보한 할인 tier가
향후 전체 가입자 수 증가 때문에
자동으로 바뀌면 안 되는 구조가 필요한지 검토.

예:

가입 당시 50% 대상
→ 이후 500개 운영처가 생겨도
해당 고객의 tier 유지

현재 Product Policy와
구현 가능한 Store 구조를 연결해서 보고.

임의 확정하지 말 것.
