1. 작은 iPhone에서 ‘전체 저장’ 버튼 UI 깨짐
━━━━━━━━━━━━━━━━━━━━

실기기:

작은 iPhone 화면에서
선생님 → 지난 일지보기 화면의

“수업 미디어 사진 4장”
우측에 있는
[전체 저장]

버튼이 카드/화면 우측 밖으로 밀려나가며 UI가 깨집니다.

첨부 이미지 참고.

확인할 것:

- 해당 화면 파일 경로
- 해당 컴포넌트명
- 사진목록 header row 구조
- “수업 미디어 사진 N장” 영역
- “전체 저장” 버튼 style
- width / minWidth / padding / gap / flexDirection / flexShrink / flexWrap 여부
- SafeArea / screen width 고려 여부
- iPhone SE급 작은 화면에서 왜 overflow 되는지
- 큰 화면에서는 왜 정상인지

목표 수정방향은:

- 작은 화면에서도 화면 밖으로 절대 나가지 않음
- “수업 미디어 사진 N장”과 “전체 저장” 둘 다 유지
- 버튼 기능 유지
- 사진 다운로드 기능 변경 금지
- 필요하면 텍스트 크기/패딩/아이콘 크기 소폭 축소
- 필요하면 flexShrink / wrap / layout 재배치
- 큰 화면 레이아웃도 깨지지 않게 유지

원인 먼저 보고하십시오.

2. 좋아요/감사 리액션 UI가 학부모 화면과 불일치
━━━━━━━━━━━━━━━━━━━━

현재 선생님이 지난 일지를 보는 화면 하단에는

👍 좋아요
🙏 감사합니다
💬 댓글

형태로 표시됩니다.

하지만 학부모 화면은 이미 정책을 변경하여:

- 좋아요 = 하트 아이콘
- 감사합니다 기능 제거
- 댓글 유지

로 정리되어 있습니다.

선생님 일지보기 화면도
학부모 화면과 동일한 정책으로 통일해야 합니다.

최종 목표:

❤️ 좋아요
💬 댓글

만 표시.

삭제:

- 👍 따봉 아이콘
- 🙏 감사합니다 아이콘
- 감사합니다 카운트 UI

중요:

단순히 아이콘만 숨기는 것이 아니라
현재 “감사합니다” 기능이 실제로 더 이상 사용되지 않는 정책이라면

선생님 화면에서
관련 onPress / 표시 / 카운트 / 조건부 렌더링이
어디까지 남아 있는지 조사하십시오.

단,
DB 컬럼이나 기존 과거 reaction 데이터를
이번 작업에서 삭제하지 마십시오.

이번 범위는 UI 및 현재 사용경로 정리입니다.

좋아요 하트의:

- 아이콘 종류
- 활성/비활성 상태
- 색상
- 카운트 표시방식

은 현재 학부모 일지 화면 구현을 실제로 찾아서
그 UI를 그대로 재사용하거나 동일 규칙으로 맞추십시오.

추측해서 새 디자인 만들지 마십시오.

3. 지난 일지 사진 크게보기 — 2번째 사진부터 오류
━━━━━━━━━━━━━━━━━━━━

재현:

선생님 → 지난 일지
→ 사진 썸네일 클릭
→ 크게보기

첫 번째 사진:
정상 표시

옆으로 swipe하여 두 번째 사진부터:
“Something went wrong”
오류 화면 발생

이것은 반드시 원인을 정확히 찾으십시오.

확인할 것:

- 사진 썸네일 onPress
- 크게보기 modal/viewer 컴포넌트
- viewer에 전달되는 image list
- initialIndex
- currentIndex
- keyExtractor
- image URI 배열
- R2 URL
- encodeURI / decodeURI
- query string
- signed/public URL 여부
- expo-image / React Native Image 여부
- preload/prefetch 여부
- swipe 후 index 변경 시 URI 재생성 여부
- 첫 이미지와 2번째 이후 데이터 구조 차이
- ErrorBoundary가 잡는 실제 exception
- “Something went wrong” 생성 주체
- iOS에서만 발생하는지 Android도 동일한지
- 다른 사진 viewer와 공통 component를 사용하는지

특히:

첫 번째 이미지가 정상인데
두 번째부터만 오류라는 점을 기준으로

단순 네트워크 오류라고 추정하지 말고

index 변경
→ 다음 이미지 선택
→ URI 전달
→ render

전체 경로를 추적하십시오.

가능하면 실기기 로그 또는
재현 가능한 최소 테스트로
실제 exception message를 확보하십시오.
