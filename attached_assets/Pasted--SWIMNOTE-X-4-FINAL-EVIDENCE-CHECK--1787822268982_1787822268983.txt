0. X모드 구현 헌법 — 반드시 준수
━━━━━━━━━━━━━━━━━━━━━━

SWIMNOTE X의 핵심은
"관리 화면을 하나 더 만드는 것"이 아니다.

실제 Parent / Teacher / Admin 기능과
AI Diary / Growth / Curriculum / Report / X Setup 데이터가
동일한 실제 운영 데이터로 연결되어야 한다.

따라서 앞으로 4개 허브를 구현할 때:

- 화면용 임시 fixture 금지
- 실제 기능과 분리된 독립 데이터 생성 금지
- 기존 기능이 있는데 별도 유사 기능 재구현 금지
- 실제 Parent/Teacher에서 사용하는 데이터와 다른 기준 사용 금지
- 실제 AI ENGINE/X 기능 상태와 무관한 가짜 상태표시 금지

모든 KPI / 상태 / 목록 / 상세는
"현재 실제 SWIMNOTE 기능이 사용하는 source of truth"
에서 가져와야 한다.

3. 공통 Entity 탐색 구조

학생뿐 아니라 아래 대상도 같은 원칙 적용:

학생:
가나다 인덱스 + 검색 + 반 + 선생님 + 상태

반:
요일 / 시간 / 담당선생님 / 레벨 기준 index

선생님:
이름 index + 담당반 + 상태

커리큘럼:
레벨 / 영법 / 단계 / 활성상태 index

리포트:
월 / 상태 / 반 / 선생님 index

일지:
날짜 / 반 / 선생님 / 작성상태 index

운영자가 "찾는 시간"이 최소가 되도록 설계.

- Normal Parent

중 해당 기능이 실제 어느 mode/role에 존재하는지 확인.

확인.

Admin 리포트 상태
↔ Parent가 실제 보는 리포트

↔ Parent가 실제 보는 일지

Admin Curriculum
↔ Parent AI 검색에 실제 사용되는 curriculum

이 세 연결은 반드시 E2E로 추적.

18. MODE 분기 회귀 방지
━━━━━━━━━━━━━━━━━━━━━━

X모드 기능을 구현하면서
일반 SWIMNOTE 모드의 기존 기능에
영향을 주면 안 됨.

구현계획서에 반드시:

- 공용 파일 여부
- mode-aware component 여부
- X-only route 여부
- shared API 여부
- Normal mode regression risk

명시.

공유 컴포넌트를 수정하면
Normal / X 양쪽 영향범위 작성.
