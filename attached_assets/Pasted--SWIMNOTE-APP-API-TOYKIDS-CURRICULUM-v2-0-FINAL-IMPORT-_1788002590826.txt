[SWIMNOTE APP/API — TOYKIDS CURRICULUM v2.0 FINAL IMPORT / ONE-SHOT PRODUCTION REPLACEMENT]

첨부파일:

TOYKIDS_SWIMNOTE_X_APP_FINAL_IMPORT_v2.0.docx

이번 작업의 목적:

첨부한 FINAL IMPORT 파일을 교육적으로 재해석하지 않고
파일에 확정된 Canonical Curriculum을 그대로 APP/API DB에 Import한다.

그 후:

- 새 Curriculum Version 생성
- 전체 Validation
- 일지 템플릿 [교육과정] Preview
- Normal AI Diary APP-side curriculum lookup 확인
- PASS 시 ACTIVE 원자적 교체
- 잘못 생성된 이전 Curriculum 정리
- 최종 E2E

까지 한 번에 완료한다.

이번 작업은 APP/API만 수행한다.
AI Engine은 수정하지 않는다.

==================================================
0. 사고 재발 방지 — 절대 규칙
==================================================

가장 먼저 첨부파일이 실제 workspace에 존재하는지 확인한다.

파일이 없으면:

FAIL: FINAL_IMPORT_FILE_NOT_FOUND

로 즉시 STOP.

절대 임의 데이터 생성 금지.

절대 기존 기억/세션 요약/이전 DB 데이터를 사용해
첨부파일 내용을 추정하거나 재구성하지 않는다.

첨부파일의 선언을 확인:

FILE_TYPE = FINAL_IMPORT
NO_REINTERPRETATION = TRUE
NO_RECLASSIFICATION = TRUE

위 선언 중 하나라도 없으면 STOP.

이번 파일이 유일한 Import source of truth다.

파일/Parser 불일치이므로 Import하지 않고 STOP.

6. FINAL IMPORT Parser
==================================================

FINAL IMPORT 전용 Parser를 사용한다.

기존 생성입력용 AI/parser가
교육 의미를 추론하도록 되어 있다면 사용하지 않는다.

필요하면 FINAL_IMPORT 전용 deterministic parser를 추가한다.

Parser 역할은 오직:

DOCX table/field 읽기
→ schema validation
→ canonical record 변환

이다.

교육 판단 기능은 없어야 한다.

18. ACTIVE 교체 — 원자적 수행
==================================================

PASS 시 단일 transaction 또는
안전한 atomic switching 방식으로:

1. 새 Final version ACTIVE
2. 기존 ACTIVE is_active=false
3. ACTIVE version count=1 확인

전환 도중 실패하면 rollback하여
기존 ACTIVE를 유지한다.

서비스에 ACTIVE=0 상태가 생기지 않게 한다.
