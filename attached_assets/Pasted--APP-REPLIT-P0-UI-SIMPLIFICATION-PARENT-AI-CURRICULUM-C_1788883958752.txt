[보낼 곳: APP REPLIT]

[P0 UI SIMPLIFICATION — PARENT AI CURRICULUM CHAT 단일 대화 구조로 통합]

현재 학부모 모드의
"AI 커리큘럼 검색" 화면에

- 연필 아이콘
- 대화 목록
- 새 대화 생성
- 여러 "새 대화" row

가 존재한다.

이 기능은 일반 멀티채팅 서비스가 아니라
"특정 자녀의 수영 커리큘럼을 검색/질문하는 기능"이다.

제품 정책을 아래처럼 단순화한다.

━━━━━━━━━━━━━━━━━━━━━━
1. 먼저 실제 기능 확인
━━━━━━━━━━━━━━━━━━━━━━

현재 헤더의 연필 아이콘과
대화 목록 아이콘의 실제 onPress를 코드에서 확인.

추정으로 수정하지 말 것.

확인 항목:

- 연필 아이콘 = 새 대화 생성인지
- 목록 아이콘 = conversation list인지
- conversation/thread DB/API가 실제 존재하는지
- 현재 질문/응답이 어떤 conversation id에 저장되는지

확인 후 아래 단일 대화 구조로 바로 수정.

━━━━━━━━━━━━━━━━━━━━━━
2. 최종 UX
━━━━━━━━━━━━━━━━━━━━━━

AI 커리큘럼 검색은:

학생 1명
→ 단일 conversation
→ 계속 질문

구조로 사용.

일반 사용자 UI에서:

- 새 대화 생성 기능 제거
- 대화 목록 기능 제거
- conversation picker 제거
- "새 대화" row 목록 제거

사용자가 여러 thread를 관리하게 하지 않는다.

━━━━━━━━━━━━━━━━━━━━━━
3. 화면 진입
━━━━━━━━━━━━━━━━━━━━━━

학부모가:

AI 커리큘럼 검색
→ 자녀 선택 또는 현재 선택된 자녀
→ 바로 해당 자녀의 AI 커리큘럼 대화창

으로 진입.

중간 "대화 목록" 화면 금지.

━━━━━━━━━━━━━━━━━━━━━━
4. 기존 대화 유지
━━━━━━━━━━━━━━━━━━━━━━

같은 student_id로 다시 들어오면
해당 학생의 기존 canonical conversation/history를 그대로 이어서 표시.

매번 새 conversation 생성 금지.

학생 A와 학생 B가 있으면
student_id 기준으로 각각 별도 단일 history를 가질 수 있음.

즉:

학생당 conversation 1개.

━━━━━━━━━━━━━━━━━━━━━━
5. 새 대화 기능 대체
━━━━━━━━━━━━━━━━━━━━━━

기존 연필 아이콘이 "새 대화" 기능이라면
일반 UI에서 제거.

대신 정말 필요한 경우에만
헤더 메뉴 또는 설정성 액션으로:

"대화 초기화"

1개만 둘 수 있음.

초기화는:
- 실제 기존 API/데이터 정책 확인 후 구현
- 잘못 눌러 즉시 삭제되지 않게 확인 UI 사용
- 구현이 불필요하면 이번 작업에서는 아예 넣지 않아도 됨

중요:
대화 목록 관리 기능을 다시 만들지 말 것.

━━━━━━━━━━━━━━━━━━━━━━

8. 기존 여러 conversation 데이터
━━━━━━━━━━━━━━━━━━━━━━

기존 Production에 이미 conversation/thread가 여러 개 존재한다면
데이터 삭제 금지.

사용자 UI에서만 단일 canonical conversation을 선택하도록 처리.

어떤 thread를 canonical로 사용할지는
실제 데이터/schema 기준으로 결정.

예:
- 가장 최근 active thread
- student별 canonical thread
- 기존 지정 primary thread

임의 데이터 삭제/merge 금지.

필요하면 legacy conversation은 비노출 상태로 보존.
