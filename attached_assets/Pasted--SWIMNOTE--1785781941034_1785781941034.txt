[SWIMNOTE 긴급 오류 — 일지 작성 화면 하단 ‘나가기’ 버튼 원인조사]

문제 화면이 정확히 확인됐다.

문제 화면:
- 선생님 수업 일지 작성 화면
- 상단 제목: 반명과 수업일시 표시
- 반 공통 일지
- AI 작성 버튼
- 학생별 추가 일지
- 화면 하단 고정 버튼:
  - 왼쪽: 나가기
  - 오른쪽: 저장

실제 오류:
- 화면 하단 왼쪽 ‘나가기’ 버튼을 눌러도 아무 반응 없음
- 화면 상단 왼쪽 뒤로가기 버튼은 정상 작동
- 현재 사용자는 상단 뒤로가기로만 일지 작성 화면을 닫고 있음
- 따라서 AI 작성 모달 X 버튼 문제가 아니라 일지 작성 화면 자체의 하단 나가기 버튼 문제다

이번 단계에서는 수정하지 말고 실제 코드 경로와 직접 원인을 조사해 보고한다.

Commit / Push / Render 배포 / OTA 금지.

4. 직접 원인 후보 조사
━━━━━━━━━━━━━━━━━━━━━━

아래 후보를 실제 코드로 판정한다.

1. onPress가 비어 있음
2. 잘못된 함수 연결
3. 함수명은 있으나 return만 하고 종료
4. 저장 중 상태 때문에 disabled
5. 이미 작성된 일지 상태에서 disabled
6. 하단 고정 영역 위에 투명 View가 겹침
7. 하단 탭바 또는 SafeArea View가 터치 가로챔
8. ScrollView contentContainer가 버튼 위까지 겹침
9. KeyboardAvoidingView가 터치 가로챔
10. pointerEvents 문제
11. zIndex/elevation 문제
12. 버튼 Pressable 내부에 다른 Pressable 충돌
13. 뒤로가기 확인 Alert가 열리지만 화면 뒤에 가려짐
14. 함수 실행 중 예외 발생
15. router.replace 또는 저장 effect가 즉시 화면을 다시 열음

5. 터치 영역 구조 조사
━━━━━━━━━━━━━━━━━━━━━━

스크린샷상 하단 구조는 다음처럼 보인다.

- ScrollView 본문
- 구분선
- 하단 나가기 / 저장 버튼
- 앱 하단 탭바

실제 레이아웃 트리를 제출한다.

확인할 항목:

- 하단 버튼 영역이 ScrollView 내부인지 외부인지
- position: absolute 여부
- bottom 값
- SafeArea inset
- 탭바 높이
- pointerEvents
- zIndex
- elevation
- 버튼 위를 덮는 투명 View
- 저장 버튼과 나가기 버튼의 부모가 같은지
- 저장 버튼은 실제 터치되는지

중요 판정:

- 저장 버튼은 작동하고 나가기만 안 되는지
- 두 버튼 모두 안 되는지
- 나가기 버튼 영역 중 일부만 안 되는지

정적 코드로 확인 가능한 범위와 실기기 로그가 필요한 범위를 구분한다.

6. 로그 삽입 위치 제시
━━━━━━━━━━━━━━━━━━━━━━

정적 분석으로 직접 원인을 확정하지 못하면 다음 로그 위치를 제시한다.

하단 버튼 onPress 첫 줄:

console.log("[DIARY-EXIT-A] bottom exit pressed", {
  isSaving,
  isGenerating,
  hasUnsavedChanges,
  diaryExists,
});

종료 함수 첫 줄:

console.log("[DIARY-EXIT-B] handleExit entered");

navigation 직전:

console.log("[DIARY-EXIT-C] calling router.back");

상단 뒤로가기에도 비교 로그:

console.log("[DIARY-BACK] top back pressed");

로그로 구분:

- 하단 터치 자체 미진입
- onPress 진입 후 함수 미진입
- 함수 진입 후 조건 return
- router.back 호출 후 화면 유지
- 예외 발생

7. AI 일지 상태와의 관계 확인
━━━━━━━━━━━━━━━━━━━━━━

이 화면은 일반 일지 작성 화면 안에 AI 작성 기능이 포함돼 있다.

다음을 확인한다.

- AI 작성 모달이 열린 상태에서만 나가기 버튼이 안 되는지
- AI 작성 후 결과가 삽입된 뒤 안 되는지
- AI를 전혀 사용하지 않아도 안 되는지
- 이미 작성된 일지를 수정하는 화면에서만 안 되는지
- 신규 일지 화면에서도 안 되는지

관련 상태:

- isAiModalVisible
- isGenerating
- isProcessing
- isSaving
- hasUnsavedChanges
- existingDiary
- isEditMode
- showExitConfirm

실제 state 이름으로 제출한다.

8. 최소 수정 원칙
━━━━━━━━━━━━━━━━━━━━━━

직접 원인이 확정되면 가장 작은 수정안을 제시한다.

우선 원칙:

- 상단 뒤로가기와 하단 나가기가 동일한 종료 함수 사용
- 하단 나가기 버튼을 저장 상태와 무관하게 누를 수 있어야 함
- 저장 중이라면 이중 저장만 차단하고 화면 종료 정책은 별도 판단
- AI 요청 중이면 abort 후 종료
- 키보드 dismiss
- 입력 중인 내용이 있으면 기존 확인 Alert 정책 재사용
- 저장 로직 변경 금지
- AI 생성 로직 변경 금지
- 학생별 일지 매핑 변경 금지

권장 구조:

const handleExitDiary = () => {
  Keyboard.dismiss();
  aiAbortRef.current?.abort();

  if (hasUnsavedChanges) {
    setShowExitConfirm(true);
    return;
  }

  router.back();
};

상단 뒤로가기:

onPress={handleExitDiary}

하단 나가기:

onPress={handleExitDiary}

실제 코드 구조에 맞춰 제안한다.
