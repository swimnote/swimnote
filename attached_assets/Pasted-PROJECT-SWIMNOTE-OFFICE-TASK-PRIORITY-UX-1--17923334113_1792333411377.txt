PRIORITY = 기능 완결 우선 / UX·디자인 개편 후속

[1. 진행 기준]

현재 사용자에게 보이는 수정 사항은 주로 UX 영역이다.
지금 메뉴·홈·레이아웃 전면 개편을 시작하지 않는다.

UX 개선 사항은 기존 문서에 누적하고,
다음 문제만 기능 구현과 함께 즉시 수정한다:
- 업무 진행 불가
- 잘못된 대상·금액·상태 표시
- 입력 유실·중복 실행
- 권한·개인정보 문제
- 완료된 작업을 다시 시작해야 하는 연결 단절

나머지 배치·색상·정보 밀도·버튼 위치·편의 개선은
기능 완성 후 한 묶음으로 진행한다.

[2. 최신 구현을 재사용]

기준 소스:
d4d1e699da58d32e6387ec478e2f0117160671e2

기존 작업과 이후 변경을 보존한다.
무료 이전 대화·모델 제안·양식 초안·회원 생성 복구·
리포트 ID/version·보고서 연결을 재구현하지 않는다.

같은 검토·패키징·전체 검사를 반복하지 않는다.

[3. 남은 기능을 끝까지 연결]

기존 합의 기능 목록과 현재 코드를 대조하여
실제 미구현·부분 연결만 계속 구현한다.

우선 범위:
- 공지·학부모 요청 답장 등 남은 관리자 양식의 AI 초안 연결
- 기존 공통 Action을 통한 조회·미리보기·확인 후 실행
- 성장리포트 검수·발급·발송 상태·당시 이력의 누락
- 회원·수강·청구·수납·환불·마감의 끊긴 처리
- 관리자 보고서·문서·출력·운영지원의 잔여 기능
- 무료 이전의 회원·금융·잔여권리 처리와 복구

AI가 입력한 초안과 실제 저장·발송은 구분한다.
늦은 AI 응답이 수동 입력이나 다른 대상에 덮어쓰지 않도록
기존 보호를 재사용한다.

‘실행 승인 대기’와 ‘코드 미구현’을 구분한다.
외부 조건이 필요한 동작만 대기하고 나머지는 계속한다.

[4. 모델 분담]

- 정해진 버튼·메뉴 처리는 모델 없이 실행
- 간단한 조건 해석·필드 변경은 작은 모델 우선
- 복잡한 문서·모호한 자료·복합 계획만 큰 모델 사용
- 처리 인원이 많다는 이유만으로 큰 모델을 선택하지 않음
- 대상 조회·금액 계산·권한·일괄 저장은 기존 서버 수행
- 모델 선택을 위해 매번 별도 모델을 호출하지 않음
- 자동 무제한 승급·재시도 금지

새 유료 호출은 이번 지시에서 승인하지 않는다.
제안한 최대 4회 시험은 정확한 모델·입출력 토큰 상한·
공식 단가·합산 최대 비용을 정리해 별도 승인 요청한다.
호출 승인을 기다리는 동안 연결 코드는 계속 완성한다.

[5. 외부 대기]

Smartro:
영업일 상담·공식 문서·계정 조건이 필요한 부분만 대기.
실결제·실환불은 실행하지 않는다.

배차:
기존 합의 설계 원문을 프로젝트 첨부·문서에서 확인한다.
없으면 정확한 필요 문서를 한 번에 요청한다.
원문 없이 임의 재설계하지 않고 다른 개발은 계속한다.

NFC:
지원 리더 공식 사양·SDK·실장비 의존 부분만 대기.
장비 없이 상시 병행 수신이 검증됐다고 표시하지 않는다.
센터 출결에만 사용하고 셔틀 NFC는 추가하지 않는다.

[6. Git·운영]

GitLab 인증 문제는 독립적으로 처리한다.
동일 실패 push 반복·다른 원격 우회·강제 push·main 반영 금지.
로컬 소스·커밋·복구 bundle 보존.

새 서버 적용은 확정 SHA·영향·복구 방법을 묶어 승인 요청한다.
기존 schema 2 재적용 금지.
이번 지시만으로 운영 배포·새 migration을 실행하지 않는다.

실발송·자동 알림 활성화·실거래·새 유료 호출·
구독/가격/용량 정책 전환은 기존 제한을 유지한다.

[7. 확인·전달]

개발 중 변경 범위의 필수 확인은 수행한다.
사용자 기능 확인은 최종 통합 체크리스트에 모은다.
기능 하나마다 설치본을 제작하지 않는다.

다음 보고는 아래 중심으로 간결하게 제출한다:
1. 추가 완성한 기능
2. 실제 남은 PC 미구현 기능
3. 외부 조건으로만 대기하는 기능
4. 후속 UX 개선 목록
5. 필요한 서버 적용·모델 시험 승인 묶음

같은 완료보고를 반복하고 정지하지 말고,
현재 승인 범위의 독립적인 잔여 구현을 계속 진행한다.
