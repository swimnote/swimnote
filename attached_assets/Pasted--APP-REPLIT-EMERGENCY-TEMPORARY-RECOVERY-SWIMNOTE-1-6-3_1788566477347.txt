# EMERGENCY TEMPORARY RECOVERY — SWIMNOTE 1.6.3
# 목적:
# 현재 기존 배포 앱 1.6.3에서 로그인 후
# "수영장 정보 불러오는 중..." 화면에 계속 머물며 접속이 되지 않는다.
#
# 2.0.1 정식 업데이트는 주말 이후 진행 예정.
# 지금 목표는 1.6.3을 주말 동안 기존 운영자가 사용할 수 있을 정도로만
# 최소 복구하는 것이다.
#
# 중요:
# 1.6.3을 다시 개발하거나 현대화하지 않는다.
# 기존 2.0/X 기능을 1.6.3에 맞추기 위해 되돌리지 않는다.
# 원인 확인 → 최소 backward-compatible fix → 검증 → STOP.

============================================================
현재 증상
============================================================

실제 iPhone의 기존 1.6.3 앱에서:

앱 실행
→ 하단 navigation 표시됨
→ 중앙 spinner
→ "수영장 정보 불러오는 중..."
→ 계속 대기
→ 정상 화면 진입 불가

즉 우선 조사 대상은:

login/session restore
→ authenticated API
→ current pool / swimming pool info fetch
→ app bootstrap

구간이다.

- 새로운 native build 생성

============================================================
STEP 3 — 최근 변경과 비교
============================================================

1.6.3이 과거 정상 동작하던 API contract와
현재 Production API contract를 비교.

특히 확인:

1. 기존 pool/current-pool endpoint가 삭제/rename 되었는가
2. response field가 바뀌었는가
3. nullable → required 변화가 있었는가
4. auth middleware가 추가되어 1.6.3 token을 거부하는가
5. token_version/session validation 변화가 있는가
6. role/pool membership resolver 변화가 있는가
7. endpoint prefix가 바뀌었는가
8. old client가 보내는 query/body field를 현재 server가 거부하는가
9. X/subscription/catalog 변경 중 기존 bootstrap response contract가 깨졌는가
10. 최근 WP0/X 작업이 이 startup endpoint에 간접 영향을 줬는가

특히:
"건드리지 말라고 했던 1.6.3 compatibility가 최근 backend 변경으로 깨졌는지"
commit history/blame로 확인.
