[SWIMNOTE 보강 시스템 전체 증거자료 추출 — 분석·수정 금지]

목적:

외부 검수자가 SWIMNOTE 보강 시스템의 전체 실행 경로를 직접 분석한다.

이번 작업에서 Replit은 원인 판정이나 해결책을 작성하지 않는다.
관련 코드·스키마·라우트·배포 기준만 원문 그대로 추출한다.

- 코드 수정
- 자동 수정
- 리팩터링
- Commit
- Push
- Render 배포
- OTA
- 운영 DB INSERT/UPDATE/DELETE
- reset/revert
- 구독 코드 변경
- X모드 작업
- “정상”, “원인 확정” 등의 자체 판정

10. 문제 재현 대상 DB SELECT 자료
━━━━━━━━━━━━━━━━━━━━━━

운영 DB 수정 금지.
SELECT만 수행한다.

실패한 보강 세션 ID와 선택한 class_group_id가 확보돼 있다면:

A. makeup_sessions

SELECT *
FROM makeup_sessions
WHERE id = :makeupId;

B. class_groups

SELECT *
FROM class_groups
WHERE id = :classGroupId;

C. 로그인 user

SELECT id, role, swimming_pool_id
FROM users
WHERE id = :userId;

D. holidays

SELECT *
FROM pool_holidays
WHERE swimming_pool_id = :poolId
ORDER BY holiday_date;

E. 학생 정원 대상

SELECT id, status, class_group_id, assigned_class_ids, deleted_at
FROM students
WHERE swimming_pool_id = :poolId
  AND (
    class_group_id = :classGroupId
    OR assigned_class_ids @> to_jsonb(:classGroupId::text)
  );

F. 삭제 학생 잔존 보강

SELECT
  ms.*,
  s.status AS student_status,
  s.deleted_at AS student_deleted_at
FROM makeup_sessions ms
LEFT JOIN students s ON s.id = ms.student_id
WHERE ms.status IN ('waiting','expired','assigned')
ORDER BY ms.created_at DESC;

이름·이메일·전화번호는 출력 자료에서 마스킹한다.

DB 접속 불가 시 임의 결과를 작성하지 말고
“미수집”으로 표시한다.
