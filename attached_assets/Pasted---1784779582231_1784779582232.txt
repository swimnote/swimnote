긴급 점검: 사진앨범 전체 미노출 및 일지 사진 시스템 상태 꼬임

현재 현상

사진을 정상적으로 업로드해 두었는데
선생님 사진앨범에서 “사진 없음”으로 표시됩니다.

최근 다음 수정 이후 발생했을 가능성이 큽니다.

- /photos/picker
- /photos/teacher-all

조회 조건에

AND media_status != 'attached'

필터를 추가함

현재는 단순히 필터를 또 수정하지 말고,
사진 업로드 → 앨범 보관 → 일지 연결 → 일지 삭제까지
전체 데이터 생명주기를 조사하세요.

==================================================

핵심 서비스 정책

사진앨범은 선생님이 업로드한 사진 원본을 보관하고 확인하는 공간입니다.

사진을 일지에 사용했다고 해서
사진앨범에서 사라지면 안 됩니다.

즉:

사진 업로드
→ 사진앨범에 표시

사진을 일지에 연결
→ 해당 일지에도 표시
→ 사진앨범에도 계속 표시

일지를 삭제
→ 해당 일지와의 연결만 해제
→ 사진 원본은 사진앨범에 계속 표시

사진앨범에서 사용자가 직접 사진 삭제
→ 그때만 사진앨범에서 제거

“일지 연결 상태”와 “앨범 노출 여부”를 같은 media_status 하나로 판단하지 마세요.

==================================================

1. 현재 DB 상태 진단

최근 업로드한 사진들을 DB에서 조회하세요.

각 사진별로 다음 값을 출력하세요.

- id
- pool_id
- uploader_id / teacher_id
- album_type
- media_status
- journal_id
- student_id
- student_note_id
- deleted_at 또는 is_deleted
- storage key / file URL
- created_at

특히 사진앨범에서 사라진 사진들이:

- media_status='attached'라서 숨겨졌는지
- journal_id가 남아 있는지
- student_note_id가 남아 있는지
- 일지 삭제 과정에서 상태가 변경됐는지
- 실제 파일은 저장소에 존재하는지

확인하세요.

진단 결과를 먼저 보고하세요.

==================================================

2. picker와 사진앨범의 목적 분리

다음 API를 각각 구분해서 점검하세요.

A. 내 사진앨범 /photos/teacher-all

목적:
선생님이 업로드했고 삭제하지 않은 사진 원본 전체 표시

기본 조회 기준:

- 같은 수영장
- 현재 선생님에게 접근 권한 있음
- 사진 유형
- 실제 삭제되지 않음

일지에 attached 상태인지 여부만으로 숨기면 안 됩니다.

따라서 teacher-all에서

AND media_status != 'attached'

조건은 제거하는 방향을 우선 검토하세요.

B. 일지용 사진 선택기 /photos/picker

여기도 사진 재사용 정책을 먼저 확정하세요.

현재 스윔노트의 정상 UX는:

- 앨범에 있는 사진은 계속 보여야 함
- 이미 다른 일지에 사용된 사진도 원본은 앨범에 남아야 함

동일 사진의 여러 일지 재사용을 금지할 필요가 있다면
사진 자체를 picker에서 무조건 숨기지 말고:

- “사용 중” 표시
- 선택 비활성화
- 연결된 일지 안내

등 명확한 UX를 사용하세요.

다만 현재 요구사항상 사진을 다시 선택해 사용할 수 있어야 한다면,
사진 하나에 journal_id 하나만 저장하는 현재 구조가 잘못된 것입니다.

3. 데이터 구조 점검

현재 photo_assets_meta에

- journal_id
- student_id
- student_note_id

를 직접 저장하여 사진 원본과 일지 연결을 한 행에서 관리하는지 확인하세요.

이 구조라면 사진 한 장은 사실상 하나의 일지 또는 학생 노트에만 연결할 수 있습니다.

사진앨범 원본과 여러 일지 연결을 안정적으로 운영하려면
관계 테이블 구조를 검토하세요.

예:

photo_assets
- id
- owner / pool
- storage_key
- album_type
- deleted_at
- created_at

diary_photo_links
- id
- photo_id
- diary_id
- student_note_id nullable
- student_id nullable
- link_type ('common' | 'individual')
- created_at
- unique constraint

이 경우:

- 사진 원본은 앨범에 계속 존재
- 일지 삭제는 link만 삭제
- 같은 사진을 여러 일지에 연결 가능
- common과 individual 구분 명확
- attached 상태 때문에 앨범 전체가 사라지는 문제 방지

이번 긴급 수정에서 스키마 변경이 너무 크다면,
우선 현재 구조를 안전하게 복구하되
임시 수정인지 구조적 수정인지 명확하게 보고하세요.

==================================================

4. 일지 삭제 로직 점검

최근 DELETE /diaries/:id에서

photo_assets_meta를 detach하는 로직이 추가됐습니다.

이 로직이 사진앨범 노출에 영향을 주는지 확인하세요.

일지 삭제 시 정상 동작:

- class_diary 논리 삭제
- 해당 일지와 사진 연결 해제
- 사진 파일 삭제 금지
- 사진 앨범 원본 삭제 금지
- 사진이 teacher-all에서 계속 표시
- 다른 일지와의 연결이 있다면 절대 훼손하지 않음

일지 삭제가 media_status를 잘못 변경하거나
journal_id/student_note_id를 NULL 처리하면서
앨범 조회 조건에서 빠지게 하는지 조사하세요.

5. 에러 삼키기 전면 점검

다음 패턴을 사진·일지 관련 코드 전체에서 검색하세요.

.catch(() => {})
.catch(() => null)
catch {}
void someAsyncFunction()

사진 업로드, attach, detach, 앨범 조회 실패를
조용히 무시하면 안 됩니다.

각 실패는 로그와 사용자 오류로 확인 가능해야 합니다.

==================================================

6. 즉시 복구 목표

현재 업로드된 사진을 삭제하거나 재업로드시키지 말고 복구하세요.

정상 목표:

- 기존 업로드 사진이 내 사진앨범에 다시 표시됨
- 새로 업로드한 사진도 즉시 표시됨
- 일지에 사용한 사진도 앨범에서 사라지지 않음
- 전체일지 사진과 개별일지 사진이 학부모에게 합쳐서 전달됨
- 일지 삭제 후 사진 원본은 앨범에 남음

==================================================

7. 필수 테스트

A. 사진 3장 업로드
→ 내 사진앨범에 즉시 3장 표시

B. 사진 2장을 전체일지에 연결
→ 일지에 2장 표시
→ 내 사진앨범에도 계속 3장 표시

C. 사진 1장을 학생 개별일지에 연결
→ 해당 학부모에게 전체 2장 + 개별 1장 표시
→ 다른 학생에게는 전체 2장만 표시

D. 일지 삭제
→ 해당 일지 미노출
→ 사진 원본 3장은 사진앨범에 계속 표시

E. 앱 종료 후 재접속
→ 사진앨범 동일하게 표시

F. 이미 일지에 사용한 사진의 picker 동작
→ 서비스 정책에 맞게 표시 및 선택 가능 여부 확인
→ 아무 설명 없이 앨범 전체에서 사라지면 실패

G. 기존에 사라진 사진
→ 재업로드 없이 다시 앨범에 표시
