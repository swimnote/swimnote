1. analysis_from 명시
━━━━━━━━━━━━━━━━━━━━━━

현재 확인된 문제:

cycle.analysis_from이 null인 경우
ENGINE wire request에도 null이 전달된다.

이를 수정한다.

무료 월간 성장리포트 contract v1.0에서는
report_period로부터 분석 시작/종료 시각을
Asia/Seoul 기준으로 명확히 계산한다.

2026-09:

report_period = "2026-09"

analysis_from =
2026-09-01 00:00:00 Asia/Seoul
=
2026-08-31T15:00:00.000Z

analysis_cutoff_at =
2026-10-01 00:00:00 Asia/Seoul
=
2026-09-30T15:00:00.000Z

하드코딩하지 않는다.

report_period + timezone으로 계산한다.

cycle.analysis_from이 null이라고 해서
wire contract까지 null로 만들지 않는다.

3. parent_answers 위치 교정
━━━━━━━━━━━━━━━━━━━━━━

현재 APP builder:
snapshot 내부에 parent_answers 저장

현재 ENGINE contract:
request 최상위 parent_answers 소비

이 불일치를 수정한다.

실제 ENGINE wire request 최상위에
parent_answers를 전달한다.

ENGINE에서 [] fallback으로
실제 학부모 답변이 사라지지 않아야 한다.

기존 snapshot 내부 값을
즉시 제거할 필요가 있는지는
payload hash/기존 코드 영향도를 확인하여
최소 변경한다.

중요한 것은 최종 wire request에서
ENGINE이 실제 데이터를 소비할 수 있는 것이다.

━━━━━━━━━━━━━━━━━━━━━━
4. longitudinal 위치 교정
━━━━━━━━━━━━━━━━━━━━━━

현재 APP:
snapshot 내부 longitudinal

ENGINE:
request 최상위 longitudinal

불일치를 수정한다.

실제 wire request 최상위에
longitudinal을 전달한다.

ENGINE에서 null fallback으로
정보가 사라지지 않아야 한다.

5. teacher_review 계약 확인/교정
━━━━━━━━━━━━━━━━━━━━━━

현재 조사에서:

APP는 teacher_review 객체를 보낼 가능성이 있고
ENGINE contract는 string|null을 기대한다.

실제 APP 데이터 타입과 사용처를 다시 확인한다.

실제로 ENGINE에 전달해야 하는 값이라면
ENGINE contract에 맞는 string|null wire representation을 사용한다.

객체 전체를 임의 JSON.stringify해서 보내는 식으로
의미를 바꾸지 않는다.

현재 실제 기능에서 사용하지 않는 값이라면
그 사실을 보고하고 불필요한 contract 확장을 하지 않는다.

6. snapshot_version 타입
━━━━━━━━━━━━━━━━━━━━━━

실제 wire:

snapshot_version = "1.0"

ENGINE contract도 string "1.0"을 요구한다.

APP TypeScript 선언이 number라면
실제 wire contract에 맞게 string 타입으로 교정한다.

영향 범위를 확인하고 최소 수정한다.

7. payload hash 보존
━━━━━━━━━━━━━━━━━━━━━━

APP/ENGINE에서 확인된 canonical hash 방식:

payload_hash 자체 제외
객체 key 재귀 정렬
배열 순서 유지
JSON 직렬화
SHA-256

을 그대로 유지한다.

최상위 parent_answers/longitudinal 등의
wire contract 교정 후에도
APP 생성 hash와 ENGINE 재계산 hash가
동일해야 한다.

Golden에서 확인한다.

8. ENGINE 응답 저장 경로 보존
━━━━━━━━━━━━━━━━━━━━━━

ENGINE response
→ APP ID/status/object validation
→ trace.payload_hash 검증

→ request-ID CAS
→ DB 저장

9. timeout 안전 여유
━━━━━━━━━━━━━━━━━━━━━━

현재:

APP HTTP timeout = 기본 120초
ENGINE 내부 timeout = 기본 120초

이므로 APP가 인증/registry/network 시간을 먼저 소비하여
ENGINE 정상 종료 전에 연결을 끊을 위험이 있다.

APP timeout은 설정 가능 구조를 유지한다.

이번 WP에서 실제 ENGINE 운영 timeout이 120초임을
계약 기준으로 테스트할 수 있다면,
APP timeout에 충분한 상위 여유를 두는
최소 안전값을 제안한다.

단,
임의 수치로 Production 설정을 변경하지 않는다.

완료보고에서:

현재값
권장값
근거

를 제시한다.
