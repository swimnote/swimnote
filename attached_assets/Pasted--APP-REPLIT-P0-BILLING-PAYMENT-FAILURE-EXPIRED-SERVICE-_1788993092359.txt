[P0 BILLING — PAYMENT FAILURE / EXPIRED SERVICE SUSPENSION]

목표:
X 구독 갱신 결제가 실패했을 때
데이터를 삭제하지 않고,
유예기간 이후 완전 만료 시 pool 단위로 SWIMNOTE 서비스 이용을 일시중지한다.

중요:
결제 실패 ≠ 즉시 BASE 전환
결제 실패 ≠ 회원 데이터 삭제
결제 완전 만료 후에는 관리자/선생님/학부모 앱 사용을 제한한다.

1. 상태 정의
━━━━━━━━━━━━━━━━━━━━━━

최소 상태:

ACTIVE
GRACE
PAYMENT_SUSPENDED
RECOVERED

정책:

ACTIVE
→ 정상 사용

갱신 결제 실패 + Store grace period 유효
→ GRACE
→ 기존 X 기능 유지
→ 관리자에게 결제수단 확인 안내

grace period 종료 + entitlement 비활성/만료
→ PAYMENT_SUSPENDED

결제 복구
→ RECOVERED
→ 즉시 기존 정상 플랜/권한 복구

자동 BASE downgrade 금지.

3. APP ENTRY GATE
━━━━━━━━━━━━━━━━━━━━━━

관리자 문구:

구독을 갱신하면 기존 상태 그대로 다시 이용할 수 있습니다."

CTA:
"구독 갱신하기"

관리자만 결제/구독 관리 화면 접근 허용.

"SWIMNOTE 서비스 이용이 일시 중지되었습니다"

"수영장의 구독 상태를 확인해주세요."

학부모 문구:

"SWIMNOTE 서비스 이용이 일시 중지되었습니다"

"수영장의 서비스 이용이 재개되면 기존 기록을 다시 확인할 수 있습니다."

4. API SERVER GUARD
━━━━━━━━━━━━━━━━━━━━━━

클라이언트 화면만 막는 방식 금지.

PAYMENT_SUSPENDED pool은
결제 복구/인증/필수 billing endpoint 제외하고
운영 write API를 서버에서도 차단.

표준 응답 예:

HTTP 402 또는 기존 정책에 맞는 상태코드

{
  "code": "POOL_SUBSCRIPTION_SUSPENDED"
}

read API도 비용 절감을 위해
선생님/학부모 일반 기능은 차단 가능.

관리자는 billing recovery에 필요한 최소 read만 허용.

5. GRACE PERIOD
━━━━━━━━━━━━━━━━━━━━━━

BILLING_ISSUE 발생 즉시 서비스 정지 금지.

→ GRACE

결제수단을 확인해주세요."

6. REVENUECAT WEBHOOK
━━━━━━━━━━━━━━━━━━━━━━

현재 webhook 이벤트 기준으로 상태 전환 확인.

예상:

BILLING_ISSUE
→ grace/entitlement 상태 확인
→ GRACE

RENEWAL / recovery
→ ACTIVE
→ suspension 해제

EXPIRATION / entitlement inactive after grace
→ PAYMENT_SUSPENDED

CANCELLATION은 즉시 suspension 아님.
현재 paid-through date까지 ACTIVE 유지.

PRODUCT_CHANGE도 즉시 suspension 아님.

Store event 이름/필드는
현재 실제 RevenueCat webhook schema 기준으로 확인 후 구현.

7. MEMBER LIMIT 문제
━━━━━━━━━━━━━━━━━━━━━━

X500 사용 중 회원 500명인데 결제 만료됐다고
SWIMNOTE 기본플랜으로 자동 전환 금지.

500명 데이터 그대로 보존.

PAYMENT_SUSPENDED 상태 유지.

사용자가 나중에 직접 SWIMNOTE 기본플랜으로 변경하려면
target plan member limit 검증.

현재 회원 수가 target plan limit 초과면
downgrade 거부.

예:

"SWIMNOTE 기본플랜은 최대 N명까지 이용할 수 있습니다.
현재 등록 회원 수가 N명을 초과하여 변경할 수 없습니다."

8. RECOVERY
━━━━━━━━━━━━━━━━━━━━━━

데이터 복구 migration 필요 없어야 함.
애초에 삭제하지 않음.
