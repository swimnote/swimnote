2. 1,000명 COMMIT 실제 테스트
━━━━━━━━━━━━━━━━━━━━━━

Production DB 사용 금지.

test/local/격리 DB 또는
테스트 종료 후 전체 삭제 가능한 환경에서
synthetic 1,000명으로 실제 canonical:

/admin/members/bulk/commit

동등 로직을 실행하십시오.

중요:
validation 함수만 호출하는 테스트는 인정하지 않습니다.

실제로:

transaction 시작
→ 250명 chunk × 4
→ 총 1,000 INSERT
→ commit

까지 실행해야 합니다.

확인:

- 1,000명 전체 INSERT 성공
- 실제 저장 row = 1,000
- partial success 없음
- transaction 정상 종료
- timeout 없음
- DB connection 오류 없음
- 실제 commit 소요시간

3. ROLLBACK 실제 테스트
━━━━━━━━━━━━━━━━━━━━━━

같은 격리 환경에서
transaction 중간 실패 상황을 1회 만들어

예:

1~500 정상 처리 후
의도적인 test exception 발생

시키십시오.

확인:

최종 INSERT row = 0

이어야 합니다.

즉 ALL-OR-NOTHING을
코드 판독이 아니라 실제 transaction으로 증명하십시오.

테스트 전용 방식만 사용하고
Production 코드에 failure hook을 남기지 마십시오.
