==================================================
1. SESSION_SWITCH / STUDENT_RELOAD
==================================================

현재 문제:

setTargetDate(newDate)
후 즉시 openGroup()가 실행되면서
loadClassStudents()가 closure의 OLD targetDate를 사용함.

수정:

loadClassStudents에 explicit date parameter 추가.

예:

loadClassStudents(classId, lessonDate)

내부의 날짜 의존 API:

/today-schedule?date=
/attendance/makeup-students?date=
/attendance?...&date=

전부 state targetDate가 아니라
전달받은 lessonDate 사용.

openGroup(group, overrideDate)에서:

const effectiveDate = overrideDate ?? targetDate

를 정하고,
loadClassStudents(group.id, effectiveDate)

형태로 전달.

세션 전환 시:
session.lessonDate가 끝까지 사용되어야 함.

==================================================
2. WRITTEN_REPLACE RACE CONDITION
==================================================

현재:

myDiaryExists = diarySet.has(...)

는 session switch 직후 load() 완료 전
false가 될 수 있음.

수정:

현재 선택된 group + targetDate에 대해
이미 로드된 diaries를 source of truth로 사용.

예:

diaries.some(
  d =>
    d.class_group_id === group.id &&
    normalizeLessonDate(d.lesson_date) === targetDate &&
    !d.is_deleted
)

중요:
Date/string 형식 차이 있으면
기존 normalizeLessonDate() 재사용.

replace 대상 diaryId도
동일한 helper/key 기준으로 찾는다.

즉:

EXISTS CHECK
REPLACE TARGET LOOKUP

둘이 반드시 동일한 기준 사용.
