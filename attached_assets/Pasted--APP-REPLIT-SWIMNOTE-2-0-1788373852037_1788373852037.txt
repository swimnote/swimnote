G. 학부모 연결 자동승인
============================================================

현재 승인관리 > 학부모 연결에
대기 요청이 많이 남음.

기존 제품 정책:
회원정보가 이미 등록되어 있고
학부모 정보와 매칭되면 자동승인.

사용자가 원하는 최종 정책:

CASE 1.
회원정보가 먼저 등록되어 있음
+
학부모 가입/연결 요청
+
전화번호가 회원정보와 일치
→ 즉시 자동승인 / 자동연결
→ 대기 목록에 남지 않음

CASE 2.
학부모가 먼저 가입해서 pending 상태
→ 이후 운영자가 회원정보 등록
→ 전화번호가 pending parent와 일치
→ 회원 등록 순간 자동 재매칭/자동승인
→ 관리자 수동 승인 필요 없음

CASE 3.
잘못 가입
아무 관련 없는 전화번호
수영장에 해당 회원정보 없음
자동 매칭 근거 없음
→ 이 경우만 pending 목록에 남음

중요:
불편하게 만들지 말 것.
정상 사용자에게 수동승인을 요구하지 않는 것이 핵심.

반드시 조사:

- 현재 auto-approval exact condition
- phone normalization
  01012345678
  010-1234-5678
- 보호자1 / 보호자2 전화번호 모두 비교하는지
- 학생 이름 match가 필수인지
- 현재 "학생 이름 확인 필요"가 왜 발생하는지
- 현재 "전화번호 확인 필요"가 왜 발생하는지
- parent가 먼저 가입한 후 member 생성 시
  pending request re-check hook 존재 여부
- same phone + multiple children 처리
- duplicate link 방지
- cross-pool protection

계획서에서:
현재 pending 8건이 왜 남았는지
가능하면 READ ONLY 데이터/코드 기준으로 원인 유형 분류.
PII는 masked.

그 안의 모든 1차/2차/3차 하위 화면,
그리고 modal/bottom sheet까지 조사.

현재 문제:
하위 화면에서 back 또는 X를 누르면
홈 화면으로 점프.

최종 navigation 규칙:

Settings
→ X mode
→ sub menu
→ detail
→ modal

modal X
→ detail

detail back
→ sub menu

sub menu back
→ X mode / X mode settings

X mode root back
→ Settings

단순 back:
HOME으로 이동 금지

HOME icon:
홈으로 이동 가능

반드시 조사:

- 모든 X 관련 route
- 각 route의 current back handler
- router.back
- router.replace
- router.push("/")
- router.replace("/(admin)")
- backTo
- fallback home
- modal close handlers
- hardware/gesture back

완료 계획에
"route → expected previous route"
표를 반드시 포함.

예:

| Current Route | Expected Back Target | Current Behavior | Fix |
| ... |

중요:
한 화면만 고치지 말고
X 설정 flow 전체 전수조사.
