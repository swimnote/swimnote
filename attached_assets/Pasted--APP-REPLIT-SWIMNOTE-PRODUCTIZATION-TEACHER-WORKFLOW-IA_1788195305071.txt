4. 핵심 후보 — Schedule Work Hub
==================================================

다음 개념이 실제 구조에 맞는지 검토한다.

선생님 스케줄/오늘수업의 각 수업 카드에서:

출석
일지
사진
회원
보강

으로 바로 이동.

중요:

이 버튼들이 새로운 기능을 만드는 게 아니다.

현재 기존 destination으로 바로 보내되:

- class_id
- lesson/session id
- date

같은 기존 context를 전달해
재선택을 줄이는 방식이다.

실제 기존 route contract가
이 params를 받을 수 있는지 조사한다.

새로운 params가 필요하면
기존 route와 backward compatibility를 유지할 수 있는지 분석한다.

==================================================
5. 기존 경로 유지 원칙
==================================================

Schedule Hub를 도입하더라도:

기존:
하단탭
기존 메뉴
기존 상세화면
기존 deeplink

를 즉시 제거하지 않는다.

신규 빠른 경로를 추가한 뒤
기존 경로도 계속 작동하도록 설계한다.

즉:

OLD PATH = 유지
FAST PATH = 추가

원칙.

향후 실제 사용성 검증 후에만
중복 진입점 정리를 별도 결정한다.

6. Context 전달 안전성
==================================================

특히 조사:

- class_id
- class_group_id
- lesson/session id
- selectedDate
- lesson_date
- students[]
- teacher id

현재 각 화면이 어떤 값을 source of truth로 사용하는지.

절대 임의로
새 global state store를 만들지 않는다.

가능하면 기존:
route params
현재 hook/store/context
를 사용한다.

다른 반으로 이동했는데
이전 반 정보가 남는 stale context 위험도 평가한다.
