SWIMNOTE 날짜 시스템 통합 작업 범위 최종 확인

이번 작업은 기존 코드에 날짜 조건을 몇 개 추가하는 작업이 아닙니다.

현재 앱에서 스케줄, 출결, 일지, 사진, 학부모 화면이 서로 다른 날짜 기준을 사용하고 있기 때문에 발생하는 구조적인 문제를 해결하는 것이 목적입니다.

이번 작업에서는 관련 없는 기능은 절대 수정하지 않고,
SWIMNOTE가 하나의 날짜 기준으로 동작하도록 통일합니다.

현재 코드에 이미 구현되어 있다고 표시되어 있는 부분도 실제 동작을 기준으로 다시 확인합니다.

"이미 구현되어 있음"

"배포만 하면 됨"

"현재 구조로 충분함"

이라는 판단으로 작업을 종료하지 않습니다.

실제 앱에서 동일한 날짜 기준으로 정상 동작하는 것을 완료 기준으로 합니다.

==================================================

1. 회원 날짜 기준

회원은 등록한 날짜가 아니라

실제 첫 수업일부터 반에 참여한 것으로 처리합니다.

예)

7/18 등록

7/20 첫 수업

등록일

2026-07-18

첫 수업일

2026-07-20

스케줄

출결

일지

학부모 기록

모두 첫 수업일부터 적용합니다.

등록일은 회원관리 기록으로만 유지합니다.

==================================================

2. 회원 상태 적용 기준

다음 상태는 모두 적용 시작일을 기준으로 처리합니다.

- 반 등록
- 반 이동
- 미배정
- 퇴원
- 연기
- 복귀

예)

8/1부터 미배정

→ 7월 마지막 수업까지 기존 반 표시

→ 8/1부터 기존 반 미표시

과거 기록은 변경하지 않습니다.

==================================================

3. 반 이동

예)

A반 마지막 수업

7/27

B반 첫 수업

8/3

→ 7/27까지 A반

→ 8/3부터 B반

→ 중간 기간은 어느 반에도 소속되지 않은 정상 상태입니다.

과거 A반 기록은 유지합니다.

==================================================

4. 연기

연기 기간에는

- 정규 스케줄
- 출결
- 일지 대상

모두 제외합니다.

복귀일부터 다시 정상 표시합니다.

과거 기록은 유지합니다.

==================================================

5. 보강

보강은 현재 구조를 유지합니다.

보강 회원은

해당 보강 수업 날짜에만 표시합니다.

정규 반 이력은 변경하지 않습니다.

==================================================

6. 일간·주간·월간 스케줄

일간

주간

월간

세 화면은 서로 다른 날짜 계산을 하지 않습니다.

동일한 날짜 기준

동일한 회원 조회

동일한 날짜 판정 로직을 사용합니다.

==================================================

7. 출결

출결 대상 회원은

해당 수업 날짜에

실제로 그 반에 참여 중인 회원만 포함합니다.

==================================================

8. 일지

일지는 반에 속하는 데이터가 아닙니다.

수업 날짜에 속하는 데이터입니다.

예)

7/20 일지

7/27 일지

두 일지는 완전히 독립됩니다.

다음 항목은 날짜별로 모두 분리됩니다.

- 일지
- 완료 상태
- 출결
- 개인 메모
- 사진
- 영상
- 학부모 전송

다른 날짜 데이터가 자동으로 따라오면 안 됩니다.

==================================================

9. 사진

사진과 영상은

해당 날짜 수업의 일지에만 연결합니다.

이전 수업 사진이

다음 수업 일지에 자동으로 나타나면 안 됩니다.

==================================================

10. 관리자 / 선생님 / 학부모

관리자

선생님

학부모

세 화면 모두

같은 날짜

같은 반

같은 수업

을 조회하면

동일한 원본 데이터를 사용해야 합니다.

권한 차이만 존재하고

날짜 기준은 동일해야 합니다.

==================================================

11. 공통 날짜 기준

기능마다 날짜 조건을 따로 구현하지 않습니다.

공통 날짜 조회 로직을 만들고

다음 기능이 모두 같은 로직을 사용합니다.

- 스케줄
- 출결
- 일지
- 사진
- 학부모 조회

이후 새로운 기능도 반드시 이 공통 날짜 기준을 사용합니다.

==================================================

12. 기존 데이터 처리 원칙

신규 회원만 새로운 날짜 기준을 적용하는 방식은 사용하지 않습니다.

SWIMNOTE는 하나의 날짜 기준만 사용해야 합니다.

기존 회원도 실제 첫 수업일을 확인할 수 있는 경우에는 동일한 기준으로 맞춥니다.

실제 첫 수업일을 확인할 수 없는 데이터는 임의로 추측하여 변경하지 않습니다.

먼저 데이터 분석과 영향 범위를 보고한 후 진행합니다.

==================================================

13. 연기 및 퇴원 데이터

현재 suspended 또는 withdrawn 상태인 회원의 데이터를

무조건 오늘 날짜로 일괄 수정하지 않습니다.

먼저

- 실제 연기 시작일
- 실제 퇴원일

복원이 가능한지 확인합니다.

복원이 불가능한 경우에는

안전한 처리 방법을 먼저 보고한 뒤 진행합니다.

==================================================

14. 이번 작업에서 변경하지 않는 기능

- 로그인
- 회원가입

- 기타 날짜 시스템과 관계없는 기능

==================================================

16. 완료 기준

다음 조건을 모두 만족해야 완료입니다.

- 등록 이전 스케줄에 회원이 표시되지 않는다.
- 첫 수업일부터 정상 표시된다.
- 미배정, 퇴원, 연기, 반 이동이 적용 날짜부터 정확하게 반영된다.
- 일간, 주간, 월간 스케줄 결과가 동일하다.
- 출결 대상 회원이 스케줄과 동일하다.
- 날짜가 다른 일지는 완전히 독립된다.
- 이전 수업 사진이 다음 수업으로 따라오지 않는다.
- 다른 반 데이터가 섞이지 않는다.
- 관리자, 선생님, 학부모가 동일한 날짜 기준을 사용한다.
- 기존 데이터가 임의로 변경되지 않는다.
- 관련 없는 기능은 변경하지 않는다.

==================================================

현재 단계에서는 코드 수정을 시작하지 않습니다.

먼저 위 작업 범위를 기준으로

1. 수정 대상 파일

2. 수정 방법

3. 데이터 영향 범위

4. 기존 데이터 처리 방법

5. 테스트 계획

을 최종 확인한 후 작업을 시작합니다.
