3. TYPOGRAPHY 과대화 금지

기존 계획의 최대 96px Display는 사용하지 않는다.

이번 사이트는 기존 홈페이지의
"지나치게 큰 글씨 + 긴 빈 공간 + keynote형 scrolling"
문제를 없애는 것이 목적이다.

기본 권장 기준:

HOME Product Title
Desktop: 약 56px
Mobile: 약 40px

Product Detail Hero
Desktop: 약 48px
Mobile: 약 36px

Section Title
Desktop: 약 36px
Mobile: 약 28px

Subheading
Desktop: 약 24px
Mobile: 약 20~21px

Body Large:
17~18px

Body:
15~16px

Caption:
12~13px

필요한 경우 clamp()는 사용할 수 있지만
위 시각적 규모를 크게 넘지 마라.

Apple 스타일의 핵심은
"큰 글씨"가 아니라
비율 / 여백 / 타이포그래피 / 절제 / 일관성이다.

6. PC DASHBOARD DESKTOP GUARD 수정

기존 제안:

window.innerWidth >= 1024
&& !('ontouchstart' in window)
&& pointer:fine

처럼 touch 지원 자체를 차단 조건으로 사용하면
터치스크린 Windows 노트북까지 오차단될 수 있다.

목표는:

ALLOW:
- 일반 Windows desktop/laptop
- Mac desktop/laptop
- mouse/trackpad 기반 PC 환경
- 터치 기능이 추가된 Windows laptop도 정상 PC라면 허용

BLOCK:
- Smartphone
- iPhone
- Android phone
- iPad
- Android tablet

이다.

viewport / pointer capability / device detection을 조합해
false positive를 최소화하는 방식을 WP9 전에 다시 설계한다.

이 기능은 보안 인증 대체가 아니라 UX 사용환경 제한이다.

WP1에서는 구현하지 마라.

7. PC DASHBOARD PUBLIC LOGIN 진입경로 추가 확인 필요

P0 보고에 따르면:

/login
= 일반 로그인 / super_admin / TOTP

/login?pool=:poolId
= pool 전용 ID + PW + PIN

구조가 존재한다.

그런데 공식 홈페이지 Header의
"PC 대시보드" 버튼은 특정 poolId를 미리 알 수 없는
공용 진입점이다.

따라서 WP8 구현 전에 반드시 추가 조사해서:

"공용 홈페이지에서 사용자가
ID + Password + PIN만 입력하면
기존 backend/auth 구조 그대로
자기 swimming_pool_id로 들어갈 수 있는지"

확인한다.

불가능하다면 임의로 인증체계를 바꾸지 말고
원인을 보고한 후 대표 승인을 받아라.

super_admin/TOTP 로그인도 깨뜨리지 마라.

이번 WP1에서는 인증코드 수정 금지.

1. GLOBAL DESIGN TOKENS

현재 repo 구조에 가장 자연스러운 위치에
중앙화된 Design Token을 구축한다.

반드시 다음을 중앙화:

- typography
- font weight
- line height
- neutral colors
- SWIMNOTE accent colors
- SWIMNOTE X accent colors
- spacing
- radius
- border
- shadow
- transition
- content max width
- responsive breakpoint

페이지에서 arbitrary value를 반복 작성하지 않도록 한다.

단,
현재 TailwindCSS v4 구조와 충돌하지 않게
CSS variables 중심 또는 가장 자연스러운 기존 방식을 사용한다.

쓸데없이 JS tokens + CSS variables를
동시에 중복 관리하지 마라.

Single Source of Truth를 우선한다.
