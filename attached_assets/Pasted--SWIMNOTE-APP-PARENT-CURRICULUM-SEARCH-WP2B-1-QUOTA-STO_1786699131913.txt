2. COLLISION CHECK
==================================================

현재 Curriculum Search monthly quota가:

usage_date = 해당 월 1일

을 사용하는 구조에서

기존 Parent AI의
2026-08-01 daily usage row와
같은 DB key를 사용할 가능성이 있는지 확인.

반드시 실제 UNIQUE/PK 기준으로 판정.

다음 중 하나:

A.
(parent_account_id, feature, usage_date)
등 feature가 key에 포함
→ 충돌 없음

B.
(parent_account_id, usage_date)
등 feature 구분 없음
→ 충돌 있음 / BLOCK

C.
다른 canonical 구조
→ 정확히 설명

"논리적으로 다르다"가 아니라
DB constraint로 증명.

==================================================
5. FAILED REQUEST RETRY
==================================================

현재 보고:

FAILED/없음 → fresh attempt

이라고 했는데,

동일 request_id가 이미
FAILED row로 존재하는 상태에서

다시 요청하면 실제 SQL이:

1. quota reservation을 다시 +1 하는지
2. 기존 FAILED reservation을 RESERVED로 전환하는지
3. INSERT ... ON CONFLICT DO NOTHING 때문에
   FAILED 상태 그대로 남는 문제는 없는지
4. 성공 후 COMPLETED로 정상 전환되는지

실제 query/transaction 흐름으로 확인.

그 이유와 영향 보고.

이번 audit에서 임의 수정 금지.

확인만 한다.
