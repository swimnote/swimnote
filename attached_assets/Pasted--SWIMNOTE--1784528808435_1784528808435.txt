====================================================================
SWIMNOTE 통합 날짜 시스템 정의 및 적용 계획 수립 지시문
EFFECTIVE-DATED MEMBER SCHEDULE & LESSON JOURNAL SYSTEM
====================================================================

중요

이번 작업의 목적은 기존 앱 기능을 새로 만드는 것이 아니다.

현재 존재하는

- 회원 관리
- 반 관리
- 주간 스케줄
- 일간 스케줄
- 월간 스케줄
- 출결
- 수업일지
- 사진과 영상
- 선생님 모드
- 관리자 모드
- 학부모 모드

기능은 최대한 그대로 유지한다.

이번 작업에서는 앱 전체가 사용하는 날짜 기준을 하나로 정의하고,
모든 기존 기능이 동일한 날짜 기준을 사용하도록 통일한다.

지금은 코드를 수정하지 마라.

먼저 현재 프로젝트를 분석하고,
본 지시문을 기준으로 작업계획과 영향 범위를 보고하라.

내가 분석 결과와 작업계획을 승인한 이후에만
실제 코드를 수정한다.

====================================================================
1. 현재 발생 중인 핵심 오류
====================================================================

현재 회원을 특정 날짜에 스케줄에 등록하면
등록한 날짜 이전의 과거 스케줄에도 회원이 표시되고 있다.

예

회원의 실제 수업 시작일

2026-07-20

정상 결과

2026-07-06 스케줄
→ 회원 미표시

2026-07-13 스케줄
→ 회원 미표시

2026-07-20 스케줄
→ 회원 표시

2026-07-27 스케줄
→ 회원 표시

현재 오류

회원이 반에 등록되면
해당 반의 과거·현재·미래 스케줄 전체에 표시됨

이 문제는 화면에서 과거 회원을 숨기는 방식으로 해결하지 않는다.

회원이 해당 반에 참여한 실제 유효기간을 기준으로 해결한다.

====================================================================
2. 날짜 시스템의 최종 원칙
====================================================================

SWIMNOTE의 모든 날짜 시스템은
다음 원칙을 따른다.

1. 회원은 반에 영구적으로 붙어 있는 것이 아니다.

2. 회원은 특정 날짜부터 반에 소속된다.

3. 직접적인 상태 변경이 없다면
   이후 같은 반의 반복 스케줄에 계속 표시된다.

4. 미래 날짜에 상태 변경을 예약할 수 있다.

5. 미래 상태 변경은 지정한 날짜부터 적용된다.

6. 과거 스케줄과 과거 기록은
   미래 상태 변경으로 수정되거나 삭제되지 않는다.

7. 주간·일간·월간 스케줄은
   모두 동일한 회원 유효기간 판정 함수를 사용한다.

8. 출결과 일지는
   각각의 실제 수업 날짜를 기준으로 독립적으로 생성된다.

9. 한 수업의 일지와 사진은
   다른 날짜의 수업으로 이어지거나 복사되지 않는다.

10. 관리자·선생님·학부모 화면은
    동일한 서버 기준과 동일한 날짜 결과를 사용한다.

====================================================================
3. 회원의 반 소속 날짜 구조
====================================================================

회원의 현재 반만 저장하는 방식으로 처리하지 않는다.

회원이 언제부터 언제까지
어떤 반에 소속됐는지를 저장해야 한다.

권장 개념

MEMBER CLASS ASSIGNMENT
또는
CLASS ENROLLMENT PERIOD

필수 데이터

assignmentId

tenantId

branchId

studentId

classId

effectiveFrom

effectiveTo nullable

assignmentStatus

changeReason

createdAt

updatedAt

createdBy

effectiveFrom

해당 회원이 반 스케줄에 표시되기 시작하는 날짜

effectiveTo

해당 회원이 반 스케줄에 표시되는 마지막 날짜

effectiveTo가 null이면

직접적인 변경이 생길 때까지
이후 스케줄에 계속 표시된다.

====================================================================
4. 스케줄 회원 표시 공식
====================================================================

특정 수업 날짜에 회원을 표시하는 조건은 다음과 같다.

수업 날짜 >= 회원 반 등록 시작일

그리고

회원 반 종료일이 없거나
수업 날짜 <= 회원 반 종료일

즉

lessonDate >= effectiveFrom

AND

effectiveTo IS NULL
OR lessonDate <= effectiveTo

괄호를 정확하게 적용한다.

정상 조건 예시

lessonDate >= effectiveFrom
AND
(
  effectiveTo IS NULL
  OR lessonDate <= effectiveTo
)

반드시 실제 스케줄 날짜와 비교한다.

오늘 날짜와 비교하지 않는다.

현재 회원 상태만 보고 결정하지 않는다.

현재 classId만 보고
과거 스케줄 전체에 표시하지 않는다.

5. 최초 등록 동작
====================================================================

예

오늘 날짜

2026-07-20

회원의 실제 첫 수업일

2026-07-20

회원 등록 결과

effectiveFrom = 2026-07-20

effectiveTo = null

정상 표시

7/6 미표시

7/13 미표시

7/20 표시

7/27 표시

8/3 표시

직접 변경이 없으면
이후 매주 계속 표시된다.

6. 미래 날짜 상태 변경
====================================================================

관리자는 미래 날짜의 스케줄 화면으로 이동하여
그 날짜부터 적용할 상태를 지정할 수 있다.

예

현재 날짜

2026-07-20

관리자가 2026-08-01 날짜를 기준으로
회원을 미배정 처리함

정상 결과

기존 반 배정

effectiveFrom = 기존 시작일
effectiveTo = 2026-07-31

새 상태

UNASSIGNED
effectiveFrom = 2026-08-01

스케줄 결과

7/20 기존 반 표시

7/27 기존 반 표시

8/1부터 기존 반 미표시

8월 이후 미배정 상태 표시

중요

미배정을 누른 실제 클릭 날짜가 아니라
관리자가 적용 대상으로 선택한 날짜부터 반영한다.

====================================================================
7. 퇴원 처리
====================================================================

예

퇴원 적용일

2026-08-01

정상 결과

기존 반 소속 종료일

2026-07-31

퇴원 상태 시작일

2026-08-01

7월 31일까지의 과거 스케줄과 기록은 유지한다.

8월 1일부터는 정규 스케줄에 표시하지 않는다.

퇴원 처리 때문에

- 과거 출결
- 과거 일지
- 과거 사진
- 과거 선생님 피드백

을 삭제하거나 이동하지 않는다.

====================================================================
8. 미배정 처리
====================================================================

미배정은 회원 삭제가 아니다.

미배정은 지정 날짜부터
어떤 정규 반에도 소속되지 않은 상태이다.

예

A반 소속

7/1~7/31

미배정

8/1~

정상 결과

7월 스케줄
→ A반 표시

8월 스케줄
→ A반 미표시

회원관리
→ 미배정 회원으로 표시

과거 A반 기록
→ 그대로 보존

====================================================================
9. 반 이동 처리
====================================================================

반 이동 시 기존 반 정보를 덮어쓰지 않는다.

예

A반 마지막 참여일

2026-07-27

B반 첫 참여일

2026-08-03

정상 데이터

A반

effectiveFrom = 기존 시작일
effectiveTo = 2026-07-27

B반

effectiveFrom = 2026-08-03
effectiveTo = null

정상 스케줄 결과

7/27까지 A반 표시

8/3부터 B반 표시

A반의 과거 일지와 사진은
B반으로 이동하지 않는다.

====================================================================
10. 상태 변경일 의미 통일
====================================================================

모든 상태 변경 화면에서
날짜의 의미를 명확히 통일한다.

반 등록일

해당 반 스케줄에 처음 표시되는 날짜

미배정 시작일

기존 반 스케줄에서 더 이상 표시되지 않고
미배정 상태가 시작되는 날짜

퇴원 시작일

회원이 퇴원 상태로 전환되는 날짜

연기 시작일

정규 수업 대상에서 제외되기 시작하는 날짜

복귀일

정규 수업 대상에 다시 표시되기 시작하는 날짜

반 이동일

새 반에 처음 표시되는 날짜

화면에 모호한 표현을 사용하지 않는다.

예

나쁜 표현

변경 날짜

좋은 표현

이 반에 표시되기 시작하는 날짜

미배정이 시작되는 날짜

새 반 첫 수업일

퇴원이 적용되는 날짜

====================================================================
11. 주간·일간·월간 스케줄 통일
====================================================================

주간 스케줄

일간 스케줄

월간 스케줄

세 화면은 반드시 동일한 서버 데이터와
동일한 회원 날짜 판정 함수를 사용한다.

금지

- 주간 화면에서 별도 필터
- 일간 화면에서 별도 필터
- 월간 화면에서 별도 필터
- 프론트 화면마다 서로 다른 날짜 계산
- 한 화면은 등록일을 사용하고 다른 화면은 현재 상태 사용
- 월간에서는 전체 반 회원을 표시하고 주간에서만 필터링

하나의 공통 함수 또는 공통 서비스로 판정한다.

예

isStudentActiveForClassOnDate(
  studentId,
  classId,
  lessonDate
)

또는

getActiveStudentsForClassOnDate(
  classId,
  lessonDate
)

모든 스케줄 화면은 이 공통 결과를 사용한다.

====================================================================
12. 스케줄 날짜와 수업 회차
====================================================================

반복 스케줄과 실제 수업 날짜를 구분한다.

예

매주 일요일 오후 3시

이것은 반복 스케줄 규칙이다.

2026-07-20 오후 3시 수업

이것은 실제 수업 회차이다.

2026-07-27 오후 3시 수업

이것은 전혀 다른 실제 수업 회차이다.

같은 반
같은 선생님
같은 시간이어도

수업 날짜가 다르면
서로 독립된 수업이다.

각 실제 수업 회차에는
고유한 lessonOccurrenceId 또는 동등한 고유 ID가 있어야 한다.

====================================================================
13. 일지 시스템 날짜 원칙
====================================================================

일지는 반 전체에 영구적으로 붙는 데이터가 아니다.

일지는 특정 날짜의 실제 수업 회차에 속한다.

예

2026-07-20 수업일지

2026-07-27 수업일지

두 일지는 같은 반이어도 완전히 독립된 데이터이다.

반드시 다음을 구분한다.

- 서로 다른 lessonOccurrenceId
- 서로 다른 journalId
- 서로 다른 완료 상태
- 서로 다른 사진 목록
- 서로 다른 영상 목록
- 서로 다른 회원 선택 상태
- 서로 다른 개인 피드백
- 서로 다른 학부모 전송 상태
- 서로 다른 읽음 상태

====================================================================
14. 일지 작성 가능 시점
====================================================================

회원은 등록 시작일부터
실제 수업에 참여한다.

수업이 실제로 종료된 후
해당 수업 회차의 일지 작성이 가능해진다.

예

회원 등록 시작일

2026-07-20

수업

2026-07-20 15:00~16:00

정상 동작

15:00 이전
→ 아직 수업 전

15:00~16:00
→ 수업 진행 중

16:00 이후
→ 해당 7/20 수업일지 작성 가능

7/27 수업일지는
7/20 수업일지와 별도로 존재한다.

7/20 일지를 완료해도
7/27 일지는 완료되지 않는다.

7/20 일지에 사진을 첨부해도
7/27 일지에는 사진이 없어야 한다.

====================================================================
15. 일지 대상 회원
====================================================================

특정 수업일의 일지 대상 회원은
그 수업 날짜에 해당 반에 유효하게 등록된 회원만 포함한다.

예

회원 시작일

7/20

7/13 수업일지 대상

미포함

7/20 수업일지 대상

포함

7/27 수업일지 대상

포함

회원이 8/1부터 미배정이면

7/27 수업일지 대상

포함

8월 첫 수업일지 대상

미포함

현재 회원 목록을 그대로 모든 과거 수업일지에 사용하지 않는다.

====================================================================
16. 사진과 영상 날짜 독립
====================================================================

첨부파일은 반드시 특정 수업 회차 또는
특정 일지에 속해야 한다.

필수 연결 기준

lessonOccurrenceId

journalId

필요한 경우

studentJournalId

금지

- classId만으로 최근 사진 불러오기
- 최근 작성한 일지 사진을 다음 일지에 기본 표시
- 같은 반이라는 이유로 이전 사진 재사용
- 선생님의 마지막 업로드 사진 자동 연결
- 프론트 입력 상태를 다음 수업에서 그대로 유지
- 7/20의 attachmentId를 7/27 일지에 복사

새로운 수업일지를 열면
첨부파일 상태는 빈 상태로 시작한다.

기존 첨부파일을 다시 사용하려면
사용자가 명시적으로 선택하는 별도 기능이어야 한다.

기본 동작으로 자동 상속하지 않는다.

====================================================================
17. 일지 완료 상태 독립
====================================================================

수업별 일지 상태를 독립적으로 관리한다.

예

7/20 수업

COMPLETED

7/27 수업

NOT_STARTED

정상 결과

7/20 완료

7/27 미작성

금지

반 단위 journalCompleted 사용

마지막 일지 완료 상태 재사용

같은 주차 또는 같은 반이라는 이유로 상태 상속

====================================================================
18. 관리자 모드 날짜 기준
====================================================================

관리자 모드에서는
선택한 날짜를 기준으로 회원과 상태를 보여준다.

오늘 현재 상태만 보여주는 것이 아니다.

예

관리자가 7/27 스케줄을 열면
7/27 당시 유효한 회원 표시

관리자가 8/3 스케줄을 열면
8/3 당시 유효한 회원 표시

관리자가 7월 과거 날짜로 돌아가면
현재 미배정 또는 퇴원 상태여도
그 당시 반에 소속됐던 회원은 과거 기록에 표시한다.

====================================================================
19. 선생님 모드 날짜 기준
====================================================================

선생님은 선택한 실제 수업 회차를 기준으로 본다.

선생님 화면에서

- 회원 목록
- 출결
- 공통 일지
- 개인 일지
- 사진
- 영상
- 완료 여부

는 모두 같은 lessonOccurrenceId를 사용해야 한다.

7/20 수업을 열었을 때
7/27 데이터가 섞이면 안 된다.

다른 반의 같은 날짜 데이터도 섞이면 안 된다.

과거 일지를 재구성하지 않는다.

과거 기록은 당시 수업 회차와 당시 반 기준으로 유지한다.

status

effectiveFrom

effectiveTo

classId nullable

reason

그러나 과거·미래 스케줄 판정은
반드시 날짜 이력 데이터를 기준으로 한다.

24. 임시 패치 금지
====================================================================

다음 방식으로 수정하지 않는다.

- 등록일 이전 회원을 프론트에서 숨기기
- 주간 화면에만 if문 추가
- 월간 화면은 기존 방식 유지
- 일지 작성 화면을 열 때마다 전체 사진 배열 초기화만 수행
- 오늘 날짜 이전 스케줄을 모두 제외
- 현재 미배정 회원을 과거 기록에서도 제거
- 현재 반 ID를 과거 모든 수업에 적용
- 기존 데이터를 삭제하고 새로 시작
- 날짜 비교 오류를 하루 더하거나 빼서 해결
- 동일 반이라는 이유로 일지나 첨부파일 공유
- 원인 확인 없이 캐시 전체 삭제

이번 수정은 모든 화면에서 사용하는
하나의 날짜 구조로 해결해야 한다.

28. 분석 답변 시 필수 질문

현재 프로젝트 구조상 결정이 필요한 부분이 있다면
코드 수정 전에 질문하라.

1. 회원 등록일과 실제 첫 수업일이 다를 수 있는가

2. 미배정 시작일은
   그 날짜부터 미표시인지
   전날까지만 표시인지

기본 규칙은

미배정 시작일 당일부터 미표시
전날까지 기존 반 표시

3. 퇴원 시작일도 동일한 규칙인지

기본 규칙은

퇴원 시작일 당일부터 미표시
전날까지 기존 반 표시

4. 반 이동 시 공백 기간이 허용되는가

5. 연기 기간 중 정규 스케줄에는 표시하지 않을 것인지

6. 보강 회원은 정규 반 배정과 별도로

29. 완료 기준
====================================================================

아래 항목이 모두 충족되어야 완료이다.

- 회원이 등록 시작일 이전 스케줄에 표시되지 않는다.
- 직접 변경이 없으면 등록 이후 스케줄에 계속 표시된다.
- 미래 날짜의 미배정이 해당 날짜부터 적용된다.
- 미래 날짜의 퇴원이 해당 날짜부터 적용된다.
- 과거 스케줄은 미래 상태 변경으로 바뀌지 않는다.
- 주간·일간·월간 스케줄 결과가 동일하다.
- 일지 대상 회원도 같은 날짜 기준을 사용한다.
- 날짜가 다른 수업일지는 완전히 독립적이다.
- 이전 수업 사진이 다음 수업에 따라오지 않는다.
- 다른 반의 일지와 사진이 섞이지 않는다.
- 관리자·선생님·학부모가 같은 수업 원본을 사용한다.
- 기존 앱의 관련 없는 기능은 변경되지 않는다.
- 모든 필수 테스트가 통과한다.
