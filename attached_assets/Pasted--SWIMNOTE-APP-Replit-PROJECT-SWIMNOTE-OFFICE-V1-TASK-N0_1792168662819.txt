1. 범위
현재 사용 가능한 Dashboard·회원목록·회원 상세를 대상으로
공통 Navigation을 구현한다.

- Breadcrumb
- 앱 내 뒤로/앞으로 이동
- 회원 검색·필터·목록 스크롤 복원
- 선택 회원·상세 Drawer 상태 복원
- 기존 Dashboard 회원목록 바로가기 연결
- 향후 AI OPEN도 재사용할 typed navigation 진입점

AI 채팅·모델 호출·업무 실행·새 업무 화면은 구현하지 않는다.
Side Workspace의 별도 레이아웃·전체 모드 전환은 후속 작업.

2. 기존 구현 재사용
- 기존 router·Sidebar·DashboardLayout·QueryClient 우선 재사용.
- 기존 Navigation 유틸이 있으면 확장하고 중복 체계 금지.
- 메뉴·Dashboard 링크·공통 OPEN 호출이 같은 이동 함수를 사용.
- 인증·Pool·역할·X 정책은 기존 검증 경로 유지.
- query cache를 별도 회원 데이터 저장소로 복제하지 않는다.

3. 동작 규칙
- 회원목록→상세→뒤로 이동 시 먼저 상세를 닫고
  기존 검색·필터·스크롤로 돌아온다.
- 홈 등 다른 지원 화면으로 이동 후 돌아와도
  같은 세션의 목록 상태를 복원한다.
- 앞으로 이동도 해당 이력과 일관되게 동작.
- 메뉴 접기/펼치기는 현재 작업과 조회 상태를 초기화하지 않는다.
- 같은 목적지 재선택은 불필요한 이력 중복·상태 초기화를 막는다.
- 목록 갱신 시 선택 회원은 ID 기준으로 유지.
- 삭제·권한 상실 등으로 대상이 없어지면
  잘못된 상세 대신 안내하고 유효한 목록으로 복귀.
- 로그아웃·계정/Pool 교체 시 이전 이력·상태 제거.
- 회원정보·검색어·개인정보를 디스크에 새로 저장하지 않는다.
- 프로세스 재시작 후 업무 상태 복원은 이번 범위 제외.

4. 공통 OPEN 경계
- 지원 목적지와 필요한 ID만 받는 typed 계약 사용.
- 임의 URL·임의 API·쓰기 실행을 받지 않는다.
- 회원 ID는 UUID와 기존 서버 생성 text ID를 모두 고려.
- 지원하지 않는 목적지는 명확히 거부.
- 화면 OPEN 성공을 업무 처리 완료로 표현하지 않는다.
- 실제 AI 연결 없이 코드·fixture로 공통 진입점 검증.

5. 완료 조건
- Breadcrumb와 뒤로/앞으로가 실제 지원 화면에서 일관되게 동작.
- 검색·상태/반 필터·스크롤·Drawer 복원 검증.
- 메뉴 접기와 같은 목적지 재선택 시 상태 보존.
- Dashboard 링크와 공통 OPEN이 동일 이동 경로 사용.
- 로그아웃·계정/Pool 전환·늦은 응답 격리 유지.
- 대상 없음·비허용 목적지 처리 검증.
- 기존 Web Navigation 회귀 없음.
- 현재 편집 기능은 비활성 상태 유지.
  조회 상태 보존을 저장 충돌 안전성으로 확대하지 않는다.
