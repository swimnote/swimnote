[SWIMNOTE 학부모 회원가입 — 수영장 전체 목록 비노출 및 전방일치 검색 변경 지시]

문제 화면:

학부모 회원가입 4단계 ‘추가정보’
→ 수영장 선택 영역

현재 문제:

- 검색어를 입력하지 않아도 가입 가능한 수영장 전체 목록이 노출됨
- 가입 전 사용자에게 SWIMNOTE 이용 수영장 전체 규모와 명칭이 불필요하게 공개됨
- 수영장을 찾는 기능에는 전체 목록 노출이 필요하지 않음

확정 변경 정책:

1. 검색어가 비어 있으면 수영장 목록을 표시하지 않는다.
2. 사용자가 한글 또는 영문을 한 글자 이상 입력한 경우에만 검색한다.
3. 검색 결과는 수영장 이름의 앞부분이 검색어와 일치하는 전방일치 방식으로 제한한다.
4. 검색어를 한 글자씩 추가할 때마다 결과가 점점 좁혀져야 한다.
5. 전체 수영장 목록을 가져온 뒤 클라이언트에서 숨기는 방식은 금지한다.
6. 서버 API도 검색어가 없으면 전체 목록을 반환하지 않아야 한다.

1. 목표 동작
━━━━━━━━━━━━━━━━━━━━━━

검색어 없음:
- 수영장 목록 숨김
- 안내문만 표시

안내문 예시:
“등록된 수영장 이름을 입력해 주세요.”

검색어 입력 예시:

‘토’
→ 이름이 ‘토’로 시작하는 수영장만 표시

‘토이’
→ 이름이 ‘토이’로 시작하는 수영장만 표시

‘토이키즈’
→ 이름이 ‘토이키즈’로 시작하는 수영장만 표시

다른 예시:

‘가’
→ ‘가’로 시작하는 수영장

‘나’
→ ‘나’로 시작하는 수영장

‘스윔’
→ ‘스윔’으로 시작하는 수영장

중간 글자 포함 검색은 기본적으로 하지 않는다.

예:
검색어 ‘키즈’
→ ‘토이키즈스윔클럽’은 결과에서 제외
→ 이름이 ‘키즈’로 시작하는 수영장만 표시

2. 클라이언트 정책
━━━━━━━━━━━━━━━━━━━━━━

검색어 trim 결과가 빈 문자열이면:

- API 호출 금지
- 기존 결과 즉시 초기화
- 목록 렌더 금지
- 로딩 표시 금지

검색어가 1글자 이상이면:

- 250~350ms debounce 적용
- 검색 API 호출
- 새로운 글자를 입력하면 이전 요청 결과가 현재 결과를 덮어쓰지 않도록 request sequence 또는 AbortController 적용
- 검색어가 변경되는 즉시 이전 결과를 초기화하거나 로딩 상태로 전환

필수 상태 구분:

- idle: 검색어 없음
- loading: 검색 중
- loaded: 결과 있음
- empty: 검색 결과 없음
- error: 검색 실패

에러를 빈 결과로 처리하지 않는다.

━━━━━━━━━━━━━━━━━━━━━━
3. 서버 검색 정책
━━━━━━━━━━━━━━━━━━━━━━

수영장 검색 API의 실제 경로와 구현 파일을 먼저 확인한다.

서버는 query가 없거나 trim 후 빈 문자열이면 전체 목록을 반환하지 않는다.

권장 응답:

HTTP 200
{
  "results": []
}

또는 기존 Contract가 배열이면:

[]

검색 조건:

WHERE normalized_name LIKE normalized_query || '%'

즉 전방일치 검색만 허용한다.

금지:

- query 없이 전체 swimming_pools 반환
- `%검색어%` 포함 검색
- 클라이언트에 전체 목록을 내려준 뒤 필터링
- 검색어 한 글자 입력 시 전체 목록에 가까운 과도한 결과 반환

결과 개수 제한:

- 최대 10개 또는 20개
- 동일 이름 중복 제거
- 삭제·비활성·가입 불가 수영장 제외
- 학부모 가입을 허용한 수영장만 반환

정렬:

1. 이름 정확히 일치
2. 이름 길이가 짧은 순
3. 수영장 이름 가나다순

━━━━━━━━━━━━━━━━━━━━━━
4. 한글 검색 처리
━━━━━━━━━━━━━━━━━━━━━━

사용자가 입력한 완성형 한글 문자열을 기준으로 전방일치한다.

예:

토
토이
토이키
토이키즈

각 입력 단계마다 해당 문자열로 시작하는 결과만 반환한다.

이번 범위에서는 초성 검색을 추가하지 않는다.

예:
‘ㅌㅇㅋㅈ’ 검색 지원은 이번 수정 범위 밖이다.

공백과 앞뒤 공백은 정규화한다.

예:
‘  토이키즈  ’
→ ‘토이키즈’

영문은 대소문자를 구분하지 않는다.

━━━━━━━━━━━━━━━━━━━━━━
5. 개인정보·사업정보 노출 제한
━━━━━━━━━━━━━━━━━━━━━━

검색 결과에는 가입에 필요한 최소 정보만 노출한다.

허용:

- 수영장 이름
- 가입 식별에 필요한 최소 지역명 또는 주소 일부

금지 또는 최소화:

- 전체 상세 주소
- 대표자명
- 회원 수
- 선생님 수
- 전화번호
- 가입자 수
- 요금제
- X모드 여부
- 내부 ID 직접 표시
- 운영 상태 상세 정보

수영장 ID는 선택 요청에 필요하면 내부 값으로만 사용하고 화면에 표시하지 않는다.

━━━━━━━━━━━━━━━━━━━━━━
6. 선택 후 동작
━━━━━━━━━━━━━━━━━━━━━━

검색 결과에서 수영장을 선택하면:

- 선택한 수영장 이름 표시
- 검색 결과 목록 닫기
- 검색어는 선택한 수영장 이름으로 유지하거나 별도 선택 카드로 표시
- 이후 사용자가 검색어를 수정하면 기존 선택값 해제
- 가입 제출 시 선택된 swimming_pool_id가 반드시 검색 결과에서 선택된 값인지 서버에서 재검증

사용자가 텍스트만 입력하고 결과를 선택하지 않았다면 가입 진행을 허용하지 않는다.

오류 문구:

“검색 결과에서 수영장을 선택해 주세요.”

━━━━━━━━━━━━━━━━━━━━━━
7. 조사 및 수정 대상

실제 Repository 기준으로 다음을 확인한다.

1. 학부모 회원가입 화면 파일
2. 수영장 검색 입력 state
3. 현재 전체 목록을 가져오는 API
4. 검색 결과 렌더 JSX
5. 수영장 선택 state
6. 가입 제출 시 swimming_pool_id 전달 경로
7. 서버 검색 라우트
8. 현재 SQL 검색 방식
9. inactive/deleted 필터 여부
10. 결과 제한 여부

기존 파일명으로 추정하지 말고 실제 호출 경로를 확인한다.

8. 테스트
━━━━━━━━━━━━━━━━━━━━━━

1. 화면 최초 진입
   - 수영장 목록 0개
   - API 전체 목록 호출 없음

2. 검색어 빈 문자열
   - 목록 숨김

3. 공백만 입력
   - 목록 숨김
   - API 호출 없음

4. ‘토’ 입력
   - ‘토’로 시작하는 수영장만 표시

5. ‘토이’ 입력
   - 결과가 더 좁혀짐

6. ‘토이키즈’ 입력
   - 정확한 수영장 표시

7. 검색어 ‘키즈’
   - ‘토이키즈…’는 표시되지 않음
   - ‘키즈…’로 시작하는 수영장만 표시

8. 빠르게 여러 글자 입력
   - 이전 검색 응답이 최신 검색 결과를 덮어쓰지 않음

9. 결과 없음
   - “일치하는 수영장이 없습니다” 표시

10. 검색 결과를 선택하지 않고 가입 진행
   - 진행 차단

11. 결과 선택 후 검색어 수정
   - 기존 선택 해제

12. 삭제·비활성 수영장
   - 검색 결과에서 제외

13. 동일 이름 수영장
   - 지역 정보로 구분 가능
   - 내부 ID는 노출하지 않음

14. 네트워크 오류
   - 오류 문구와 재시도 표시
   - 전체 목록 fallback 금지
