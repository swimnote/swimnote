2. CORS 최소 수정
- 기존 서버 CORS·Origin 검증 구조를 재사용.
- OFFICE packaged Origin인 app://office만 정확히 허용.
- null Origin·전체 app://·와일드카드 허용 금지.
- Origin 문자열 부분 일치로 허용하지 않는다.
- 기존 웹·모바일의 허용 정책을 보존.
- 필요한 method·header·credentials 정책은
  실제 기존 인증/API 계약에 맞춰 최소 적용.
- CORS 실패가 500이 되는 경로도 확인하고,
  기존 오류 처리 구조 안에서 최소 정정.
- Origin 허용은 인증·권한 검증의 대체가 아니다.
- 인증 middleware·Pool 격리·역할·X 정책 완화 금지.

3. F03 연결 및 제한 검증
- 수정된 로컬/격리 서버에서 Desktop Origin의
  preflight와 실제 인증 요청 경로를 확인.
- 기존 Web Origin 허용과 비허용 Origin 거부 확인.
- 로그인→필요한 PIN/TOTP→최종 token→
  사용자/Pool/역할/X 재검증 흐름 유지.
- 실제 운영 계정의 UNKNOWN 항목은
  응답 증거 확보 전까지 UNKNOWN으로 둔다.
- 운영 서버가 아직 수정 전이면 운영 로그인 실패를
  반복 재현하지 않는다.
- 인증정보·token·개인정보를 로그나 문서에 남기지 않는다.

4. API·SSE
- 기존 OFFICE 계획에 포함된 API·SSE 계약만 확인.
- 기존 canonical client·인증·권한 체계 재사용.
- SSE의 연결·해제·인증 만료·재연결·중복 연결 방지를
  현재 구현 방식에 맞춰 제한 검증.
- 서버 이벤트 수신만으로 편집 중 입력을 덮어쓰지 않는다.
- 미구현 업무 기능이나 새로운 이벤트 체계를 확장하지 않는다.
- F04 범위 밖 항목은 backlog로 기록.
