2. PHASE 2-G CLOSURE #1
Worker Realtime 초기화
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

현재 보고에서:

API index.ts:
setRealtimeDb(db)
startListener()

는 확인됨.

그러나 Worker에서도 notifyPoolEvent를 사용합니다.

반드시 확인:

growth-report-analysis-worker
growth-report-batch-worker
기타 notifyPoolEvent 호출 Worker

각 별도 프로세스가
notifyPoolEvent를 실제 실행할 수 있도록
realtime DB/notifier가 초기화되는지 확인.

원칙:

API process:
- notifier DB 초기화
- LISTEN listener 시작

Worker process:
- notifier DB 초기화
- LISTEN listener는 시작할 필요 없음
- pg_notify는 실제 동작해야 함

Worker가 API index.ts 초기화에 의존하면 FAIL.

필요하면 Worker entrypoint에서
setRealtimeDb(db) 또는 동일 책임의 초기화를
최소 추가.
