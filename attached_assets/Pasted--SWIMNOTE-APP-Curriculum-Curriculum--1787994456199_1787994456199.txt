[SWIMNOTE APP — Curriculum 전체 교체 + 일지 템플릿 목록 재생성]

목표:

기존에 테스트/구버전으로 들어가 있는 Curriculum 데이터를 전부 제거하고,
새로 제공하는

TOYKIDS_SWIMNOTE_X_APP_커리큘럼_생성입력_MASTER_v2.0.docx

를 기준으로
새 APP/API Canonical Curriculum을 처음부터 생성한다.

그리고 새 ACTIVE Curriculum metadata를 사용하여
관리자 > 일지 템플릿 > [교육과정]
목록까지 정상 생성/표시되는 상태로 완성한다.

이번 작업은 APP/API 쪽만 수행한다.
AI Engine 수정/배포는 하지 않는다.

==================================================
0. 최우선 원칙
==================================================

이번 파일은 단순 850행 import 파일이 아니다.

파일 앞부분의:

SWIMNOTE X 커리큘럼 APP MASTER 양식 v2.0

규칙을 먼저 읽고,
뒤의 기존 850개 자료를 "원본 재료"로 사용하여
새 Canonical Curriculum을 생성해야 한다.

절대 금지:

- 기존 850개를 그대로 850 Node로 import
- 351~850의 기초확장/중급확장/심화1/심화2/마스터즈를
  학생 level_order로 변환
- atomic_skill 문자열만 보고 다른 영법 Node를 merge
- APP 전용 별도 카테고리 taxonomy 생성
- 550개를 diary_templates에 복제

핵심:

학생 Level ≠ Drill Progression

APP Template 표시분류 =
AI 검색분류와 동일한 Curriculum metadata

6. 새 Canonical Curriculum 생성
==================================================

APP MASTER v2.0 규칙에 따라
850 source를 정규화한다.

Canonical 구조:

Level
→ Stroke
→ Domain
→ Skill Group
→ Atomic Skill Node
→ Drill
→ Relation

Node는 실제 서로 다른 학습기술 단위로 생성한다.

개수를 350/500/550/850 등에 맞추지 않는다.

실제 Canonical 결과 개수가 최종 count다.

==================================================
7. Level 배정 원칙
==================================================

토이키즈 실제 Level Master를 사용한다.

level_order / level_name은
현재 pool_level_settings 기준으로 확인하여 사용.

APP 코드에 모자명을 하드코딩하지 않는다.

교육적으로 학생이 배우는 실제 단계에 배치한다.

절대:

기초확장 = 검정
심화1 = 금
심화2 = 챔피언
마스터즈 = 슈퍼챔피언

같은 변환을 하지 않는다.

기초확장/중급확장/심화/마스터즈는
Drill.progression_stage로만 사용한다.

==================================================
8. Node Canonicalization
==================================================

Node 판정은 최소:

- stroke
- domain
- skill_group
- atomic_skill
- goal
- movement_sequence

를 함께 사용한다.

다른 stroke이면 기본적으로 별도 Node.

예:

backstroke + pull + 배영 풀 동작
freestyle + pull + 자유형 풀 동작

→ 반드시 서로 다른 Node.

금지:

atomic_skill = "풀 동작"

하나 아래에
배영/자유형 Drill 혼합.

==================================================
9. 기존 기본 350 처리
==================================================

001~350의 기존 일지형 문장은
source_text/source_key로 추적 보존.

그러나 한 문장 = 한 Node로 강제하지 않는다.

각 행의 실제 학습 의미를 분석하여:

- Atomic Node
- Drill
- Assessment
- Progress/record
- Review

성격을 구분한다.

실제 독립 기술이면 Node,
같은 기술의 반복/연습방법이면 Drill,
레벨 테스트 항목이면 is_test_item/assessment metadata로 구조화한다.

를 기록한다.

13. Import 후 DRAFT 검증
==================================================

반드시 아래 검사:

A. Level
- 모든 Node의 level_order 유효

B. Progression
- progression_stage가 level_order로 사용된 행 = 0

C. Mixed Stroke
- 서로 다른 stroke Drill이 generic Node 하나에 섞인 사례 = 0
- general 공통기술 예외는 근거 명시

D. Drill
- orphan = 0

E. Count
- level별 합계 = 전체 Node count

F. Sequence
- 각 level sequence_in_level = 1..N

G. Relation
- broken reference = 0

H. Duplicate
- 동일 의미의 불필요한 Canonical Node 중복 검사
