현재 뒤로가기 관련 버그는 대부분 수정 완료.

============================================================
문제
============================================================

경로:

설정 / X모드
→ 구독관리
→ 구독내용을 보는 상세 화면
→ Back

현재:
Home으로 이동함

정상:
바로 이전 논리적 상위 화면인
"구독관리" 화면으로 돌아가야 함.

이 1개 케이스만 수정.

============================================================
1. 실제 route 먼저 확인
============================================================

사용자가 말한:

"구독관리 눌러서 구독내용 보는 화면"

의 실제 현재 route/component를 코드에서 확인.

추측해서 다른 화면 수정 금지.

확인할 것:

- 구독관리 목록/메인 route
- 구독내용 상세 route
- 상세 화면 진입 코드
- 상세 화면 Back handler
- 현재 backTo 전달 여부
- router.back / router.replace / fallback 구조

============================================================
2. 최종 Back 동작
============================================================

상세 화면 Back:

explicit backTo가 있으면
→ 구독관리 route로 이동

우선순위는 기존 WP 기준 그대로:

1. backTo
2. canGoBack()
3. logical fallback

즉:

backTo > navigation stack > fallback

============================================================
3. 진입 시 backTo 명시
============================================================

구독관리 화면에서
구독내용 상세 화면으로 진입할 때

반드시:

backTo = 구독관리 화면

을 명시적으로 전달.

예:

구독관리
→ 구독내용 상세
   ?backTo=x-subscription

실제 route명은 현재 코드 기준 사용.

하드코딩된 예시 route를 그대로 쓰지 말고
실제 존재하는 route 확인 후 적용.

============================================================
4. 상세 화면 Back handler
============================================================

상세 화면에서:

잘못된 형태:

if (router.canGoBack()) {
  router.back();
}

또는:

router.replace("/home")

금지.

반드시:

if (backTo) {
  router.replace(resolvedBackTo);
  return;
}

if (router.canGoBack()) {
  router.back();
  return;
}

router.replace(LOGICAL_SUBSCRIPTION_PARENT);

형태.

실제 현재 프로젝트 navigation helper가 있으면
그 패턴을 재사용.
