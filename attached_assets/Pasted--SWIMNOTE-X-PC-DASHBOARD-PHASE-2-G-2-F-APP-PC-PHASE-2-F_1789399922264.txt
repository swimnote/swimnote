2. 2-F 잔여 #2
Bulk Import 기본 정책 = ALL OR NOTHING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

현재:

invalid row가 있어도 valid rows만 commit

구조는 폐기합니다.

기본 정책:

파일 전체 Parse
→ 전체 Validation
→ 한 행이라도 ERROR
→ Import 버튼 비활성
→ 사용자가 파일 수정 후 다시 업로드

모든 row PASS
→ Import 가능

Commit 단계도 가능하면 하나의 DB transaction.

중간 실패:
→ 전체 rollback

을 우선.

즉:

100명 중 1명 오류
→ 99명 일부 등록 금지.

부분 성공이 운영 기본동작이 되어서는 안 됩니다.

기존 구조상 transaction이 정말 불가능하면
왜 불가능한지 BLOCKER 보고 후 임의 진행 금지.

11. PostgreSQL NOTIFY Transaction 원칙
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

매우 중요.

Mutation이 DB transaction 안에서 수행될 경우:

가능하면 동일 transaction client로:

SELECT pg_notify(...)

를 COMMIT 이전에 실행하십시오.

PostgreSQL NOTIFY는
transaction commit 후 실제 전달되므로

Browser가 event 받고
API refetch 했는데
아직 commit 전 데이터가 나오는 race를 방지할 수 있습니다.

기존 transaction 구조를
억지로 뜯지 마십시오.

Transaction이 없는 단순 mutation은
DB 성공 후 notify.

DB 실패했는데 event 보내면 FAIL.
