==================================================

→ HUMAN_REQUIRED

5. KOREAN NORMALIZATION
==================================================

한국어 자연어 variation 대응.

최소:

- punctuation 제거
- 공백 정규화
- 조사 영향 완화
- 복합어 normalization
- common conversational suffix 영향 완화

예:

학부모리포트는
→ 학부모리포트

어떤기능이야
→ 어떤 기능

알림끄는거
→ 알림 + 끄기 의미 추출 가능

단 무리한 형태소 분석 라이브러리 추가 금지.

가벼운 deterministic normalization 우선.

==================================================
7. CANONICAL KNOWLEDGE SEARCH
==================================================

active support_knowledge_items 대상으로:

- title
- question
- content/answer

실제 존재 컬럼 확인 후 검색.

검색 방식:

A. concept exact/alias hit
B. normalized keyword overlap
C. title/question stronger weight
D. content weaker weight

가능하면 SQL ILIKE로 candidate를 좁히고
JS ranking 수행.

active KI 전체 무조건 로드 금지
(필요한 경우 제한된 fallback만).

==================================================
8. RANKING
==================================================

단일 token-overlap threshold 하나로
hard fail시키지 않는다.

score 구성 예:

- exact concept match
- alias match
- title token match
- question token match
- content token match
- utterance match weight

최고 score candidate와
2위 candidate 차이도 고려.

기존처럼:
"동점이면 무조건 null"
금지.

동점일 경우:

- same canonical KI면 merge
- 다른 KI면 confidence 낮춤
- 충분한 Evidence가 있으면 GROUNDED_AI
- 정책상 위험하면 HUMAN_REQUIRED

==================================================
9. ANSWER POLICY
==================================================

RetrievalResult 이후:

DIRECT_DB KI + HIGH confidence
→ DB_DIRECT

GROUNDED_GPT KI
또는 여러 active KI 조합 필요
→ GROUNDED_AI

HUMAN_ONLY KI
→ HUMAN_REQUIRED

실질적인 active match 없음
→ INSUFFICIENT_EVIDENCE

"utterance exact miss"
자체는 INSUFFICIENT_EVIDENCE 아님.
