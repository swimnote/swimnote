현재 보충수업과 일지 시스템을 함께 수정합니다.

이번 작업은 단순 UI 수정이 아니라
보강 상태 전환, 과거 스케줄 배정, 보강 완료 후 일지 작성,
스케줄별 독립 일지, 공통일지와 개인일지 병합 규칙까지
하나의 흐름으로 정확하게 연결하는 작업입니다.

기존 기능을 임의로 삭제하거나 구조를 단순화하지 마세요.

==================================================
1. 현재 보충수업 상태 정의
==================================================

보충수업은 다음 3단계로 운영됩니다.

1) 보강대기
- 결석 처리는 되었지만
- 아직 어느 스케줄에도 보강이 배정되지 않은 상태

2) 배정된보강
- 특정 스케줄에 보강학생으로 배정된 상태
- 아직 해당 보강수업이 완료되지 않은 상태

3) 보강현황
- 배정된 보강수업이 실제로 완료된 상태
- 해당 보강 건이 완료 이력으로 남아 있는 상태

이 세 상태를 명확하게 구분하세요.

==================================================
2. 배정된보강 취소 기능 추가
==================================================

현재 문제:

배정된보강 상태에서 한 번 스케줄에 배정하면
잘못 배정했거나 일정이 변경되어도
다시 보강대기로 되돌릴 수 없습니다.

수정 요구사항:

배정된보강 항목에
“배정 취소” 기능을 추가하세요.

배정 취소 시:

- 해당 스케줄의 보강학생 목록에서 제거
- 보강 배정 정보 제거
- 보강 완료 정보가 있다면 취소 불가 처리 또는 별도 확인 필요
- 원래 결석 기록은 유지
- 해당 보강 건은 다시 보강대기 상태로 이동
- 새로운 보강 스케줄에 다시 배정 가능

중요:

배정 취소는 보강 건 자체를 삭제하는 기능이 아닙니다.
결석으로 발생한 보강 권리는 유지되어야 합니다.

상태 전환:

보강대기
→ 스케줄 배정
→ 배정된보강

배정된보강
→ 배정 취소
→ 보강대기

배정된보강
→ 실제 수업 완료
→ 보강현황

==================================================
3. 과거 스케줄에도 보강 배정 가능
==================================================

현재 보강대기에서는
앞으로 예정된 스케줄에만 보강을 배정할 수 있는 구조로 보입니다.

하지만 실제 운영에서는
이미 지난 수업에서 보강을 진행했는데
당시에 시스템 입력을 놓친 경우가 있습니다.

따라서 보강 배정 시:

- 미래 스케줄 선택 가능
- 오늘 스케줄 선택 가능
- 과거 스케줄 선택 가능

모두 허용하세요.

과거 스케줄에 배정할 때는
경고만 표시하고 배정은 가능해야 합니다.

예시 경고:

“이미 지난 수업입니다.
실제로 보강을 진행한 기록을 등록하는 경우에만 배정하세요.”

확인 후 배정 가능하게 하세요.

과거 스케줄 배정 시에도
정상적으로 해당 스케줄의 보강학생으로 추가되어야 합니다.

==================================================
4. 보강 완료 조건
==================================================

보강학생이 특정 스케줄에 배정되었다고 해서
자동으로 완료 처리하면 안 됩니다.

배정과 완료를 분리하세요.

배정된보강:
- 스케줄에 들어가 있음
- 아직 완료되지 않음

보강완료:
- 해당 스케줄에서 실제 보강 완료 처리가 됨

완료 방식은 기존 출결 또는 보강 완료 처리 방식과 연결하세요.

보강학생에 대해 다음 상태를 구분할 수 있어야 합니다.

- 예정
- 완료
- 미진행
- 취소

최소한 내부 데이터에서는
배정 여부와 완료 여부가 별도 필드 또는 별도 상태로 구분되어야 합니다.

==================================================
5. 보강 완료 학생의 일지 작성 허용
==================================================

보강학생이 해당 스케줄에서 실제로 보강을 완료하면
그 학생도 해당 스케줄의 일지 작성 대상이 되어야 합니다.

조건:

- 보강학생이 해당 스케줄에 배정되어 있음
- 해당 보강이 완료 처리되어 있음

위 조건을 만족하면:

- 해당 스케줄 일지 작성 화면에 학생 표시
- 개인일지 작성 가능
- 공통일지 적용 가능
- 개인사진 선택 가능
- 학부모에게 해당 스케줄 기준으로 일지 전달 가능

반대로:

보강이 배정만 되고 완료되지 않은 상태에서는
일지 작성 대상에 포함하지 마세요.

즉:

배정된보강 + 미완료
→ 일지 대상 아님

배정된보강 + 완료
→ 일지 대상 포함

이 부분은 보강 데이터와 일지 데이터를 크로스체크해서 처리하세요.

==================================================
6. 일지는 스케줄별로 완전히 독립
==================================================

일지 시스템의 가장 중요한 규칙입니다.

각 일지는 반드시 특정 스케줄에 종속되어야 합니다.

같은 반, 같은 학생, 같은 날짜가 비슷하더라도
다른 스케줄이면 완전히 다른 일지입니다.

일지의 기본 식별 기준은 최소한 다음을 포함해야 합니다.

- schedule_id
- student_id
- diary_type
- lesson_date

가능하면 schedule_id를 최우선 기준으로 사용하세요.

다른 스케줄의 공통일지, 개인일지, 사진이
절대 섞이면 안 됩니다.

==================================================
7. 스케줄 공통일지 규칙
==================================================

각 스케줄에는 공통일지 1개를 작성할 수 있습니다.

공통일지는
해당 스케줄의 전체 수업내용을 설명하는 내용입니다.

공통일지에 포함되는 항목:

- 공통 텍스트
- 공통 사진
- 공통 영상이 있다면 공통 영상
- 공통 템플릿 내용

공통일지는 해당 스케줄에서
일지 수신 대상이 되는 모든 학생에게 기본으로 적용됩니다.

대상:

- 정규수업 완료 학생
- 해당 스케줄에서 보강 완료된 학생

결석, 미수업, 보강 미완료 학생에게는 발송하지 마세요.

==================================================
8. 개인일지 규칙
==================================================

개인일지는
해당 스케줄 안에서 특정 학생에게만 작성되는 내용입니다.

개인일지에는 다음이 들어갈 수 있습니다.

- 개인 텍스트
- 개인 사진
- 개인 영상이 있다면 개인 영상
- 개인 피드백
- 개인 템플릿 선택 내용

개인일지는 해당 학생에게만 보여야 합니다.

다른 학생에게 절대 노출되면 안 됩니다.

==================================================
9. 공통일지와 개인일지 병합 규칙
==================================================

학부모에게 보이는 최종 일지는
각 학생별로 아래 규칙에 따라 만들어야 합니다.

A. 공통일지 있음 + 개인일지 있음

해당 학생에게:

- 공통일지 내용
- 공통일지 사진
- 개인일지 내용
- 개인일지 사진

모두 보여줍니다.

최종 구조:

공통내용
+
공통사진
+
개인내용
+
개인사진

B. 공통일지 있음 + 개인일지 없음

해당 학생에게:

- 공통일지 내용
- 공통일지 사진

만 보여줍니다.

개인일지가 없다고 해서 발송을 막으면 안 됩니다.

C. 공통일지 없음 + 개인일지 있음

해당 학생에게:

- 개인일지 내용
- 개인일지 사진

만 보여줍니다.

공통일지가 없다고 해서 개인일지 발송을 막으면 안 됩니다.

D. 공통일지 없음 + 개인일지 없음

해당 학생에게 일지를 발송하지 않습니다.

==================================================
10. 공통사진 규칙
==================================================

공통일지 작성 화면에서 등록한 사진은
해당 스케줄의 공통사진입니다.

공통사진은
해당 스케줄의 일지 수신 대상 전체에게 보여야 합니다.

단:

- 다른 스케줄에는 보여지면 안 됨
- 다른 날짜 스케줄에는 보여지면 안 됨
- 다른 반 스케줄에는 보여지면 안 됨

공통사진은 반드시 schedule_id 기준으로 연결하세요.

==================================================
11. 개인사진 규칙
==================================================

개인일지 레이아웃에서
앨범 선택을 통해 특정 학생에게 사진을 추가한 경우
그 사진은 해당 학생에게만 보여야 합니다.

개인사진 식별 기준:

- schedule_id
- student_id

개인사진은 다음 대상에게만 노출:

- 해당 schedule_id
- 해당 student_id

같은 스케줄의 다른 학생에게도 보여지면 안 됩니다.

공통 앨범 사진과 개인 선택 사진을 섞지 마세요.

==================================================
12. 스케줄별 학생 일지 완성 구조
==================================================

각 학생의 최종 일지는 서버 또는 앱에서
다음 구조로 조합하세요.

예시:

{
  schedule_id,
  student_id,
  lesson_date,
  common_diary: {
    content,
    photos,
    videos
  },
  personal_diary: {
    content,
    photos,
    videos
  },
  final_diary: {
    common_content,
    common_photos,
    personal_content,
    personal_photos
  }
}

단, 실제 DB 구조는 현재 구조를 확인한 뒤
중복 저장을 최소화하는 방향으로 설계하세요.

공통일지를 학생마다 복제 저장하는 방식보다:

- 스케줄 공통일지 1개
- 학생별 개인일지 개별 저장
- 조회 시 조합

방식을 우선 검토하세요.

==================================================
13. 일지 작성 대상 결정 규칙
==================================================

해당 스케줄에서 일지 작성 가능한 학생은
다음 중 하나입니다.

1. 해당 스케줄의 정규 학생이며 실제 수업 완료
2. 해당 스케줄에 배정된 보강학생이며 보강 완료

다음은 제외:

- 결석
- 미출석
- 보강 배정만 되고 미완료
- 보강 취소
- 해당 스케줄과 관계없는 학생
- 다른 날짜 수업 학생
- 현재 반에는 있지만 당시 스케줄에는 없던 학생

학생 대상 판단 시
현재 전체 학생 목록을 그대로 사용하지 마세요.

반드시 해당 schedule_id와 실제 출결 또는 보강 완료 기록으로 판단하세요.

==================================================
14. 학부모 화면 규칙
==================================================

학부모 화면에서는
수업마다 일지가 각각 독립적으로 보여야 합니다.

같은 학생의 일지라도
다른 스케줄의 일지가 합쳐지면 안 됩니다.

목록 기준:

- lesson_date
- schedule_id
- class_group_id
- teacher_id 또는 수업정보

학부모가 특정 수업 일지를 열면
그 수업의 공통일지와 그 자녀의 개인일지만 조합해서 보여주세요.

다른 학생의 개인일지는 절대 조회되면 안 됩니다.

다른 스케줄의 공통사진이나 개인사진도 섞이면 안 됩니다.

17. 필수 테스트 시나리오
==================================================

다음 테스트를 모두 수행하세요.

테스트 1
- 학생 결석 처리
- 보강대기 생성
- 미래 스케줄 배정
- 배정된보강 표시 확인

테스트 2
- 배정된보강 취소
- 스케줄에서 학생 제거 확인
- 다시 보강대기로 복귀 확인

테스트 3
- 보강대기 학생을 과거 스케줄에 배정
- 경고 표시
- 확인 후 정상 배정

테스트 4
- 보강 배정만 하고 완료하지 않음
- 일지 작성 대상에서 제외 확인

테스트 5
- 보강 완료 처리
- 해당 스케줄 일지 작성 대상에 포함 확인

테스트 6
- 공통일지만 작성
- 스케줄 완료 학생 전체에게 공통일지만 표시

테스트 7
- 개인일지만 작성
- 해당 학생에게만 개인일지 표시

테스트 8
- 공통일지와 개인일지 모두 작성
- 해당 학생에게 공통 + 개인 모두 표시

테스트 9
- 개인사진을 학생 A에게만 선택
- 학생 A에게만 사진 표시
- 학생 B에게는 미표시

테스트 10
