2. LOCKED BACK RULE
==================================================

뒤로가기의 의미:

"직전 화면으로 복귀"

입니다.

절대 원칙:

A → B
뒤로가기
→ A

A → B → C
C 뒤로가기
→ B
B 뒤로가기
→ A

금지:

뒤로가기
→ Home 강제 이동

뒤로가기
→ Dashboard 강제 이동

뒤로가기
→ 임의의 상위 Tab 강제 이동

뒤로가기
→ logical parent라고 임의 추측하여
실제 history를 무시

기본:

router.back()
navigation.goBack()

우선.

history가 실제로 없는 특수 경우에만
명확한 fallback 허용.

10. LOCKED KEYBOARD RULE
==================================================

키보드 기본 규칙:

TextInput focus
→ keyboard visible

입력 focus가 없으면
→ keyboard hidden

다만 중요한 interaction rule:

--------------------------------
A. 버튼 TAP
--------------------------------

키보드가 올라와 있어도
사용자가 버튼을 누르면:

첫 tap으로
버튼 action이 실행되어야 함.

"첫 tap = keyboard dismiss만"
"두 번째 tap = button 실행"

구조 금지.

--------------------------------
B. 빈 배경 TAP
--------------------------------

키보드가 올라온 상태에서
버튼/입력/선택 UI가 아닌

"빈 화면 / 배경"

을 tap하면:

Keyboard.dismiss()

되어야 함.

--------------------------------
C. SCROLL
--------------------------------

scroll 시작:

keyboard 자연스럽게 dismiss.

현재 curriculum search에서 적용한
on-drag 동작 유지.

15. keyboardShouldPersistTaps 감사
==================================================

ScrollView / FlatList / SectionList에서:

keyboardShouldPersistTaps

현재 값 조사.

목표:

키보드가 떠 있어도
버튼/목록 item을 한 번 tap하면
action 실행.

보통:

handled

패턴이 적절하지만
현재 component 구조를 실제로 조사해서 보고.

잘못된:

never

등으로 인해
첫 tap이 keyboard dismiss에 소비되는 곳 찾기.
