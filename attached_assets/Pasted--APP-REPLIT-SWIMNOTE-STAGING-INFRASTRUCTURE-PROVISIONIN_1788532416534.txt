============================================================
0. 목적
============================================================

현재 확인된 구조:

- Replit DEV API가 Production Supabase DB를 사용 중
- 별도 TEST DB 없음
- 일부 integration/preflight가 과거 Production DB에 fixture를 삽입한 적 있음
- Production R2와 test object도 동일 bucket + prefix만 분리되어 있음

따라서 기능개발을 계속하기 전에
Production과 완전히 격리된 STAGING/TEST 환경부터 구축한다.

최종 목표:

REPLIT DEV / TEST
→ STAGING SUPABASE

RENDER PRODUCTION
→ PRODUCTION SUPABASE

를 완전히 분리.

이번 작업은 인프라 분리만 수행한다.

9. SCHEMA 복제 방식
============================================================

Production DATA를 복사하는 것이 아니라
repository의 explicit migrations/schema를 이용하여
Staging schema를 구축한다.

먼저 현재 repository에서
schema/migration source-of-truth를 조사.

사용:

existing migrations
Drizzle schema
explicit migration scripts
known init scripts

금지:

Production pg_dump --data

가능하면 schema-only도
repository migration이 정확하다면 사용하지 않음.

목표:
"새 환경을 코드만으로 재현 가능"하게.
