[SWIMNOTE AI 성장리포트 — 발급조건 헌법 고정 전 최종 대조 조사]

이번 작업에서는 코드를 수정하지 마라.
Production 변경도 하지 마라.

목적은 SWIMNOTE 무료 "AI 성장리포트"의
발급조건을 이번에 최종 고정하여
앞으로 코드 수정 때마다 조건이 바뀌는 일을 막는 것이다.

중요:
현재 코드에 구현되어 있다는 이유만으로
그 조건을 제품 정책이라고 판단하지 마라.

"확정된 제품 정책"
"현재 코드 구현"
을 반드시 분리해서 보고한다.

━━━━━━━━━━━━━━━━━━━━━━
1. 현재 확정된 상위 제품 정책
━━━━━━━━━━━━━━━━━━━━━━

현재 제품 정책의 상위 원칙은 다음과 같다.

1) 리포트 명칭
무료 월간 리포트의 공식 명칭:
"AI 성장리포트"

2) 대상 기간
매월 발급되는 리포트는
직전 달의 수업/성장 데이터를 대상으로 한다.

예:
2026-10-05 발급
→ 2026년 9월분 AI 성장리포트

3) 발급일
매월 5일 자동 발급.

4) 재등록 원칙
전월 수업에 대한 무료 AI 성장리포트는
다음 달에도 재등록이 완료되어
계속 수강하는 대상 회원에게 제공한다.

예:
9월 수업
→ 10월 재등록 회원
→ 10월 5일 9월분 무료 AI 성장리포트 발급

5) 발급 방식
관리자가 발송 버튼을 눌러야 발급되는 구조가 아니다.

조건을 충족하고
AI 성장리포트 생성이 정상 완료되면

PUBLISHED
→ 학부모 앱 피드 노출
→ 학부모 PUSH

까지 자동으로 진행되는 것이
"자동 발급 완료"다.

6) PDF
PDF는 5일에 서버가 일괄 생성하는 발급물이 아니다.
학부모가 발급된 리포트를 앱에서 확인하고
PDF로 저장할 수 있는 기능이다.

━━━━━━━━━━━━━━━━━━━━━━
2. 이번 조사에서 반드시 분리할 조건
━━━━━━━━━━━━━━━━━━━━━━

현재 코드에는 조사 결과 다음 조건이 존재한다고 보고됐다.

- active 학생
- enrollment 기준
- 출석 3회 이상
- 유효 학생별 일지 1건 이상
- X 이용 자격 수영장
- 승인된 수영장
- 기타 EXCLUDED 조건

하지만 이것들이 모두
확정된 "무료 성장리포트 발급 자격"이라고 가정하지 마라.

각 조건마다 아래 표로 보고한다.

조건
현재 코드 위치
현재 실제 동작
왜 존재하는지 코드상 근거
제품 정책 문서/주석상 근거
없으면 "정책 근거 확인 불가"
이 조건이 없으면 기술적으로 리포트 생성 가능한지

특히 아래 두 조건을 집중 조사:

A. 출석 3회 이상
B. 유효 일지 1건 이상

이 두 조건이
사용자가 확정했던 제품 발급 정책인지,
과거 구현 과정에서 추가된 기술적/품질 필터인지
명확하게 구분한다.

━━━━━━━━━━━━━━━━━━━━━━
3. 재등록의 정확한 코드 정의
━━━━━━━━━━━━━━━━━━━━━━

"다음 달 재등록 완료 회원"이
현재 시스템 데이터에서 무엇을 의미하는지 조사한다.

예를 들어 단순히:

student.active = true

인지,

10월 enrollment 존재

인지,

9월 enrollment의 left_at이 10월까지 이어지는 것

인지,

결제/수강 등록 데이터

인지 정확히 확인한다.

우리가 필요한 것은:

"9월에 실제 수강했고,
10월에도 재등록되어 계속 수강하는 회원"

이라는 제품 개념이다.

현재 DB에서 이 개념을
가장 정확하게 판정할 수 있는 source of truth를 찾아라.

임의로 새 정의를 만들지 않는다.

━━━━━━━━━━━━━━━━━━━━━━
4. 전월 수강 조건
━━━━━━━━━━━━━━━━━━━━━━

10월에 active라는 이유만으로
9월에 수업하지 않은 신규 회원에게
9월 성장리포트가 생성되면 안 된다.

따라서 현재 코드가:

- 전월 실제 수강 회원
AND
- 다음 달 재등록 회원

교집합을 제대로 만드는지 확인한다.

예:

9월 수강 O / 10월 재등록 O
→ 9월 리포트 대상 후보

9월 수강 O / 10월 재등록 X
→ 무료 자동발급 대상 아님

9월 수강 X / 10월 신규등록 O
→ 9월 리포트 대상 아님

이 세 경우를 반드시 확인한다.

━━━━━━━━━━━━━━━━━━━━━━
5. 데이터 부족과 발급 자격을 분리
━━━━━━━━━━━━━━━━━━━━━━

매우 중요하다.

"회원이 리포트를 받을 자격이 있는가"

와

"리포트를 만들 수 있을 만큼 데이터가 있는가"

를 같은 조건으로 취급하지 마라.

예를 들어:

재등록 여부
= 발급 자격

일지/출석/관찰 데이터
= 리포트 생성 입력 데이터

일 수 있다.

현재 구현에서 이 두 개념이
EXCLUDED 하나로 섞여 있는지 조사한다.

특히:

출석 3회 미만이면
무료 리포트 자격 자체가 사라지는 것인지,

아니면 데이터가 적은 상태에서도
존재하는 사실만으로 제한된 리포트를 생성해야 하는 것인지

현재 코드와 기존 정책 근거를 분리해서 보고한다.

정책 근거가 없으면 임의로 결정하지 않는다.

━━━━━━━━━━━━━━━━━━━━━━
6. 퇴원생
━━━━━━━━━━━━━━━━━━━━━━

9월에 수업했지만
10월에 재등록하지 않은 회원의
무료 9월 성장리포트 처리 정책이
현재 코드에서 어떻게 되어 있는지 확인한다.

기존 리포트가 이미 발급되어 있는 경우와
아직 발급 전인 경우도 구분한다.

━━━━━━━━━━━━━━━━━━━━━━
7. 월 경계
━━━━━━━━━━━━━━━━━━━━━━

전월 데이터 기간은 KST 기준으로 고정한다.

9월분이라면:

2026-09-01 00:00:00 KST 이상
2026-10-01 00:00:00 KST 미만

현재 모든 관련 쿼리가
이 의미와 일치하는지 목록화한다.

이번에는 수정하지 않는다.

━━━━━━━━━━━━━━━━━━━━━━
8. 무료 AI 성장리포트와 다른 리포트 분리
━━━━━━━━━━━━━━━━━━━━━━

다음 기능과 혼동하지 마라.

- AI 인사이트 전략 리포트
- 유료 리포트
- 관리자 수동 발송 리포트
- 기타 분석 리포트

이번 정책 고정 대상은 오직:

"매월 5일 자동 발급되는 무료 AI 성장리포트"

다.

다른 리포트의 조건을 가져오지 않는다.

━━━━━━━━━━━━━━━━━━━━━━
9. 최종 보고 형식
━━━━━━━━━━━━━━━━━━━━━━

코드 수정 없이 다음을 보고한다.

1. 현재 무료 AI 성장리포트의 실제 eligibility 조건 전체
2. 각 조건의 코드 위치
3. 각 조건의 정책 근거 유무
4. 전월 수강 판정 방식
5. 다음 달 재등록 판정 방식
6. 신규 회원 처리
7. 퇴원 회원 처리
8. 휴회/중도퇴원 등 상태 처리
9. 출석 3회 조건의 출처와 목적
10. 유효 일지 1건 조건의 출처와 목적
11. 데이터 부족과 eligibility가 현재 분리되어 있는지
12. EXCLUDED가 되는 모든 이유
13. 9월→10월 사례별 현재 결과
14. 현재 구현과 상위 제품 정책의 불일치 목록
15. 제품 정책으로 확정이 필요한 항목만 별도 목록

중요:
마지막에 코드를 고치지 마라.
"권장 정책"도 임의로 만들지 마라.

이번 결과를 사용자가 검토한 뒤
최종 SWIMNOTE AI 성장리포트 발급조건을 확정하고,
그 확정본을 기준으로 다음 수정 WP를 진행한다.

Production 변경 없음 확인.
