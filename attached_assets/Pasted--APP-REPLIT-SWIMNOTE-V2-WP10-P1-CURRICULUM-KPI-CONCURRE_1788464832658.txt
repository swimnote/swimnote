============================================================
7. fire-and-forget 정책
============================================================

사용자 검색 API 응답 자체를
KPI 갱신 때문에 오래 block하지 않는 방향은 유지 가능.

하지만:

void promise
+ unhandled rejection
+ stale write

구조는 금지.

fire-and-forget을 유지한다면:

- rejection catch 필수
- structured server log 필수
- pool/month 식별 가능
- lock 기반 recount 필수

KPI 집계 실패 때문에
학부모 검색 결과 자체를 실패시키지는 말 것.

즉:

business action success
KPI refresh failure

를 분리.
