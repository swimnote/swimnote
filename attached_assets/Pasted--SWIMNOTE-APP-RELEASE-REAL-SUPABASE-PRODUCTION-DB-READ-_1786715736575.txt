[SWIMNOTE APP RELEASE]
[REAL SUPABASE PRODUCTION DB READ-ONLY PRECHECK]

현재 확정:

- Replit executeSql(environment:"production")
  → Replit 내장 NeonDB
  → 실제 SWIMNOTE 운영 DB 아님

- 실제 SWIMNOTE Production APP DB
  → Render의 SUPABASE_DATABASE_URL
  → Supabase

따라서 기존 NeonDB 기준 migration precheck 결과는 폐기한다.

이번 단계 목적:

실제 SUPABASE_DATABASE_URL을 사용하는
SWIMNOTE Production DB에
read-only로 직접 연결해서
migration 상태를 다시 확인한다.

중요:

Production write 금지.
Migration 실행 금지.
Render deploy 금지.
코드 영구 수정 금지.

==================================================
1. CONNECTION METHOD
==================================================

executeSql 사용 금지.

반드시 기존 APP 코드가 실제 사용하는:

process.env.SUPABASE_DATABASE_URL

을 읽어 PostgreSQL client로 직접 연결.

가능한 방법:

- 현재 @workspace/db의 superAdminPool 재사용
- 또는 임시 read-only tsx script

APP Repository 내에서만 실행.
