2. 예외 승인 목적 재확정
━━━━━━━━━━━━━━━━━━━━━━

이 경로의 목적은:

정상 자동연결에 실패하여 pending에 남은 학부모를
관리자가 실제 회원정보를 확인한 뒤
올바른 학생에게 수동으로 연결하는 것이다.

대표 사례:

수영장에 저장된 보호자 전화번호가 잘못되어
학부모의 SMS 인증 전화번호와 일치하지 않는 경우.

따라서 전화번호 불일치는
자동승인은 막아야 하지만
관리자의 명시적 수동 승인까지 막아서는 안 된다.

━━━━━━━━━━━━━━━━━━━━━━
3. 관리자 학생 선택 기능 복구
━━━━━━━━━━━━━━━━━━━━━━

검색창은 다시 만들지 않는다.

검색 TextInput 없음
검색 state 없음
검색 filter 없음
자동 keyboard 없음

대신 관리자 승인 화면에서
현재 pool의 승인 가능한 학생 목록을
즉시 표시한다.

관리자가 목록을 스크롤하여
올바른 학생을 직접 선택할 수 있어야 한다.

필요 시 기존 학생 선택 UI를 재사용한다.

중요:

검색 기능 제거 ≠ 학생 선택 기능 제거

반드시:

정보 확인
→ 학생 목록 확인
→ 학생 직접 선택
→ 최종 승인

이 가능해야 한다.

다른 pool 학생은 목록에 노출하지 않는다.

━━━━━━━━━━━━━━━━━━━━━━
4. 전화번호 불일치 수동 승인 허용
━━━━━━━━━━━━━━━━━━━━━━

자동승인과 관리자 수동승인의 조건을 분리한다.

[AUTO]

SMS 인증 전화번호
=
등록 보호자 전화번호

일 때만 기존 자동연결.

[MANUAL EXCEPTION]

자동연결 실패/pending 상태에서
관리자가 자신의 pool 학생을 직접 확인·선택하고
명시적으로 승인한 경우:

등록 보호자 전화번호와
학부모 전화번호가 불일치해도
guardian/student 관계 연결을 허용한다.

전화번호 불일치는 관리자 화면에 명확히 표시한다.

그러나 불일치를 이유로
관리자 승인 자체를 서버에서 차단하지 않는다.

━━━━━━━━━━━━━━━━━━━━━━
5. 개인정보 자동수정 금지
━━━━━━━━━━━━━━━━━━━━━━

- 학생명 수정
- 보호자명 수정
- 보호자 전화번호 수정

등의 회원정보 저장은 제거한다.

이번 관리자 승인 기능의 책임은:

pending 학부모
+
관리자가 선택한 학생

사이의 유효한 관계를 승인/생성하는 것뿐이다.

관리자 승인 과정에서
students의 회원정보를 자동 교정하지 않는다.

전화번호가 잘못 등록되어 있더라도
이번 승인 API가 자동으로 전화번호를 고치지 않는다.

회원정보 수정은 기존 회원정보 수정 기능의 책임이다.

6. 서버 최종 승인 검증
━━━━━━━━━━━━━━━━━━━━━━

관리자가 승인할 때 서버에서 반드시 재검증:

- 관리자 인증
- 관리자 pool
- pending request 존재
- 선택 student 존재

반드시 거절.

학생 status:
변경 금지.

기존 보호자 pointer:
덮어쓰기 금지.

훼손 금지.

인증 근거 없음:

이 변경으로 정상 자동승인의 SMS 보안 조건을
