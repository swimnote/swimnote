# SWIMNOTE X — WP4 설계서 수정 요청

제출한 WP4 외형 분기 설계서는 승인하지 않습니다.

이유는 기존 확정 WP4 범위를 임의로 축소했기 때문입니다.

이번 수정은 설계 범위를 새로 확장하는 것이 아니라, 최초 확정된 WP4 범위로 되돌리는 작업입니다.

코드는 수정하지 말고 WP4 설계서만 다시 제출하십시오.

━━━━━━━━━━━━━━━━━━━━━━

1. 기존 WP4 확정 범위
   ━━━━━━━━━━━━━━━━━━━━━━

WP4의 확정 목표는 다음입니다.

* X 로고
* X 색상
* X 명칭
* X 전용 메뉴
* 관리자 화면 분기
* 선생님 화면 분기
* 학부모 화면 분기
* 일반모드에서 X 전용 Route 차단

이 단계에서는 다음 실제 기능을 연결하지 않습니다.

* 커리큘럼
* 성장판
* Growth Event
* X 글로벌 템플릿
* 학부모 AI 검색
* 성장리포트

즉 WP4는 기능 구현 단계가 아니라, 같은 앱 안에서 일반모드와 X모드의 외형·메뉴·진입 구조를 완성하는 단계입니다.

━━━━━━━━━━━━━━━━━━━━━━
2. 현재 제출안의 문제
━━━━━━━━━━━━━━━━━━━━━━

현재 설계는 다음만 포함합니다.

* XModeBadge 신규
* 관리자 대시보드 뱃지
* 교사 오늘 스케줄 뱃지
* 학부모 홈 뱃지

그리고 다음을 WP5 이후로 미뤘습니다.

* X 전용 메뉴
* X 전용 화면 분기
* X 외형
* X Route 처리

이는 기존 WP4 범위를 변경하는 것입니다.

WP 번호와 작업순서를 임의로 바꾸지 마십시오.

━━━━━━━━━━━━━━━━━━━━━━
3. XModeBadge 처리
━━━━━━━━━━━━━━━━━━━━━━

`XModeBadge` 자체는 WP4 구성요소로 사용할 수 있습니다.

다만 이것만으로 WP4가 완료되지는 않습니다.

설계서에는 다음을 구분하십시오.

```text
XModeBadge
→ 현재 Mode 상태를 표시하는 보조 요소

X 외형·메뉴·화면 분기
→ WP4의 본체
```

뱃지 색상도 임의 보라색으로 확정하지 마십시오.

현재 SWIMNOTE X의 확정 색상 규칙과 기존 앱 디자인 시스템을 Repository에서 먼저 확인하십시오.

확정되지 않은 신규 브랜드 색상을 만들지 마십시오.

━━━━━━━━━━━━━━━━━━━━━━
4. Repository에서 조사할 실제 항목
━━━━━━━━━━━━━━━━━━━━━━

## 앱 로고·브랜드

확인:

* 현재 SWIMNOTE 로고 파일
* 로그인 화면 로고
* 관리자 헤더 로고
* 교사 헤더 로고
* 학부모 헤더 로고
* 앱 내 브랜드명 문자열 위치
* 현재 네이비·민트 색상 상수 위치
* Theme 또는 Colors 파일
* 이미지 asset 경로
* 역할별 공통 Header 컴포넌트 존재 여부

## 관리자 메뉴 구조

확인:

* 관리자 홈
* 관리자 탭
* Drawer 또는 메뉴
* 현재 메뉴 목록
* 메뉴 구성 파일
* 메뉴가 하드코딩인지 배열 기반인지
* 관리자 X 전용 메뉴를 추가할 안전한 위치

## 교사 메뉴 구조

확인:

* 교사 홈
* 교사 탭
* 오늘 스케줄
* 일지 화면
* 교사 메뉴 구성
* X 전용 메뉴 분기 위치

## 학부모 메뉴 구조

확인:

* 학부모 홈
* 학부모 탭
* 현재 존재하는 `AI 커리큘럼 검색`
* 현재 존재하는 `AI 성장 리포트`
* 두 버튼의 출시 예정 모달 연결
* X모드에서만 보여야 할 항목
* 일반모드에서도 유지해야 할 항목

## Route 구조

확인:

* 관리자 Route 그룹
* 교사 Route 그룹
* 학부모 Route 그룹
* X 전용 placeholder Route 필요 여부
* 일반모드에서 직접 URL로 X Route 접근 시 차단 위치
* expo-router Redirect 또는 guard 기존 패턴
* Route를 만들지 않고 기존 화면 내부 분기만으로 가능한 범위

5. 상태별 확정 UI 원칙
━━━━━━━━━━━━━━━━━━━━━━

## mode = normal

* 기존 SWIMNOTE 외형 그대로
* 기존 메뉴 그대로
* X 로고 없음
* X 전용 메뉴 없음
* X Route 접근 차단
* 일반기능 변화 없음

## mode = x_pending

* 일반 SWIMNOTE 기능은 유지
* X 준비 중 상태가 명확히 표시
* X 기능이 활성화된 것처럼 보이면 안 됨
* X 전용 기능 진입 시 준비 중 안내
* 커리큘럼·성장판 실제 기능 연결 금지

## mode = x

* X 로고 또는 X 명칭 적용
* 확정된 X 색상 규칙 적용
* X 전용 메뉴 노출
* 역할별 X 화면 구조 노출
* 아직 구현되지 않은 기능은 출시 예정 또는 준비 중 상태 유지
* 실제 Backend 기능은 해당 WP 전까지 연결 금지

## status = loading / error / mode = null

* 기존 일반모드 화면을 깨지 않음
* 이전 X 상태를 재사용하지 않음
* X 전용 메뉴를 노출하지 않음
* 오류를 X 활성 상태로 처리하지 않음

━━━━━━━━━━━━━━━━━━━━━━
6. 역할별 WP4 설계 범위
━━━━━━━━━━━━━━━━━━━━━━

## 관리자

설계:

* X 브랜드 표시 위치
* X 전용 메뉴 항목
* 커리큘럼 의뢰 메뉴의 placeholder
* 커리큘럼 관리 placeholder
* 성장판 관리 placeholder
* 일반모드에서 비노출
* x_pending에서 준비 중 처리

## 교사

설계:

* X 브랜드 표시 위치
* X 전용 일지 진입 표시
* 커리큘럼 관련 placeholder
* 성장 확인 관련 placeholder
* 일반 AI 일지와 X AI 일지를 아직 실제로 분기하지 않음
* WP12 이후 실제 검색 분기 전까지 기능 연결 금지

## 학부모

설계:

* X 브랜드 표시 위치
* `AI 커리큘럼 검색` 버튼 유지
* `AI 성장 리포트` 버튼 유지
* 두 버튼은 기존 출시 예정 모달만 표시
* 실제 Parent AI·리포트 연결 금지
* X 성장판 메뉴 또는 영역의 placeholder 필요 여부 조사
* 일반모드 노출 정책을 기존 확정안과 비교

━━━━━━━━━━━━━━━━━━━━━━
7. Route 차단 설계
━━━━━━━━━━━━━━━━━━━━━━

일반모드에서 X 전용 Route를 직접 입력해 접근할 수 없어야 합니다.

설계서에 다음을 제출하십시오.

* Route 차단 컴포넌트 위치
* `useMode()` 사용 위치
* loading 중 처리
* error 중 처리
* normal 접근 처리
* x_pending 접근 처리
* x 접근 처리
* Redirect 목적지
* 뒤로가기 루프 방지
* Deep Link 접근 차단
* 일반 Route에는 Guard를 적용하지 않는 방식

아직 실제 커리큘럼·성장판 Route가 없다면, 어떤 placeholder Route만 WP4에서 생성할지 최소 범위로 제안하십시오.

불필요한 Route는 만들지 마십시오.

━━━━━━━━━━━━━━━━━━━━━━
8. 색상·디자인 원칙
━━━━━━━━━━━━━━━━━━━━━━

새로운 보라색 테마를 임의로 만들지 마십시오.

Repository에서 현재 확정된 디자인 규칙을 확인하십시오.

현재 앱 디자인 기준:

* 기본 배경과 주요 박스: 네이비 계열
* 강조 테두리: 민트
* 주요 박스 글자: 흰색
* 기존 화면 레이아웃과 크기 변경 금지
* 기존 디자인 구조를 유지한 채 색상과 X 표시만 분기

WP4에서 전체 화면을 새로 디자인하지 마십시오.

제출:

* 재사용할 기존 색상 상수
* 신규 색상 상수가 필요한지
* X 로고 asset 필요 여부
* 기존 SWIMNOTE 로고에 X 표시를 붙이는 방식
* 텍스트 `SWIMNOTE X`만 사용하는 더 단순한 방식

━━━━━━━━━━━━━━━━━━━━━━
9. 더 단순한 구현 우선
━━━━━━━━━━━━━━━━━━━━━━

WP4는 비용을 줄이기 위해 새 화면을 대량 생성하지 않습니다.

우선순위:

```text
기존 공통 Header·메뉴 재사용
→ ModeContext 값으로 조건부 표시
→ 최소 placeholder
→ 기존 출시 예정 모달 재사용
```

금지:

* 관리자·교사·학부모 화면 전체 복제
* 일반모드 화면과 X모드 화면을 별도 파일로 대량 복제
* 새 Navigation 시스템
* 새 Theme Provider
* 새 상태관리 라이브러리
* 새 공통 Modal 시스템
* WP5 이후 기능 선행 구현

━━━━━━━━━━━━━━━━━━━━━━

* 기존 출시 예정 모달 재사용
* 화면 복제 최소화
