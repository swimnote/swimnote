7. 기존 상단 분류 체계 감사
==================================================

현재 일지 템플릿 화면 상단 분류가 다음과 같이 되어 있음:

- 흰색: 물적응·호흡
- 흰색: 배영
- 흰색: 자유형
- 평영킥·파란...
- 평영스트로크
- 접영스트로크
- 수영질서·빨...
- 풀·글라이드
- 롤링·스트림...
- 스프린트·레...

이 분류는 기존 레거시 문장 템플릿용 분류이며,
현재 SWIMNOTE X Curriculum / AI Engine의 정규화 구조와 맞지 않는다.

현재 새 Curriculum 기준 핵심 축:

- pool_id
- curriculum_version_id
- level_order
- level_name
- sequence_in_level
- stroke
- domain
- skill_group
- atomic_skill

중요:
앞으로 일지 템플릿 화면의 분류는
AI가 동일하게 해석 가능한 구조여야 한다.

즉, 사람이 보는 UI 분류와
AI가 사용하는 Curriculum 분류가 서로 다른 별도 체계가 되면 안 된다.

==================================================
8. 새 템플릿 분류 설계안
==================================================

현재 ACTIVE Curriculum 550 Node를 기준으로
일지 템플릿 화면을 어떻게 목록화해야 하는지 설계한다.

우선순위:

1차 분류:
수영장 Level Master 기준
- 흰색
- 파란색
- 빨간색
- 검정
- 금
- 챔피언
- 슈퍼챔피언

단,
다른 수영장은 level_name이 다를 수 있으므로
하드코딩 금지.
반드시 해당 pool의 level_order / level_name을 사용.

2차 분류:
해당 레벨 내부에서 Curriculum Node의 실제 구조를 사용.

후보:
- stroke
- domain
- skill_group

어떤 조합이 가장 적절한지 실제 550 Node 분포를 집계해서 제안.

예:
흰색
 ├ 물적응
 ├ 호흡
 ├ 배영
 ├ 자유형
 └ 기타

검정
 ├ 공통기초
 ├ 배영
 ├ 자유형
 ├ 평영
 ├ 접영
 └ IM/훈련

단, 위 예시를 하드코딩하지 말고
실제 DB의 stroke/domain/skill_group 분포를 기준으로 자동 생성 가능한 구조를 설계.

==================================================
9. AI 사용 가능 분류 조건
==================================================

새 UI 분류는 반드시 아래 조건을 충족해야 한다.

- level_name은 표시용
- level_order는 실제 진도 기준
- stroke/domain/skill_group는 AI 검색 필터와 동일한 값 사용
- atomic_skill은 최종 선택 가능한 기술 항목
- 별도 사람이 만든 임의 category 문자열을 새로 만들지 않는다
- UI category와 AI search metadata가 동일 source에서 나온다
- 같은 Node가 APP/AI에서 다른 분류로 해석되지 않는다

즉:

APP 템플릿 목록
= Curriculum Master projection

AI Diary 검색
= 동일 Curriculum Master search

Growth Report
= 동일 Curriculum Master grounding

Parent Curriculum Search
= 동일 Curriculum Master

모두 같은 분류축을 사용해야 한다.

==================================================
10. 기존 일지 작성 분류와의 연결
==================================================

현재 실제 일지 작성 flow에서
교사가 어떤 방식으로 템플릿을 선택하는지 추적.

확인:
- Level 선택
- 영법 선택
- 기술 선택
- 템플릿 선택
- 학생별/공통 기록
- AI Diary 전달

현재 일지 작성 시 이미 사용 중인
레벨/영법/기술 분류가 있다면
새 Curriculum의 level_order/stroke/domain/skill_group와
1:1 또는 명확한 mapping이 가능한지 확인.

기존 UI 분류를 그대로 유지하지 말고,
새 Curriculum 정본으로 통합 가능한 구조를 제안.

==================================================
11. 목표 UI 구조
==================================================

목표는:

기존:
사람이 임의로 만든 10개 category
→ 362 legacy template

신규:
수영장 Level Master
→ Curriculum 분류(stroke/domain/skill_group)
→ Atomic Node
→ 필요 시 연결된 template/drill

즉,
"레벨 → 수영기술 분류 → 실제 Curriculum Node"
구조로 전환하는 방향을 우선 검토.

템플릿 개수도 기존 category별 고정 숫자가 아니라
현재 ACTIVE Curriculum에서 실시간 집계되어야 함.

예:
흰색 (150)
파란색 (100)
빨간색 (100)
검정 (50)
금 (50)
챔피언 (50)
슈퍼챔피언 (50)

그 아래 세부 분류는 실제 Node metadata 기준.
