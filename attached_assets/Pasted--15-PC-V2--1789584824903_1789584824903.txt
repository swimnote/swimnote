15. 향후 PC 운영프로그램 기반 구조 — 필수 원칙
━━━━━━━━━━━━━━━━━━━━━━

이번 정산 V2는
현재 모바일 APP 전용 기능으로 설계하면 안 됩니다.

향후 SWIMNOTE PC 운영프로그램에서
회원관리 / 매출관리 / 정산관리의
공통 기반으로 그대로 사용할 구조여야 합니다.

따라서 계산의 Source of Truth와
계산식은 반드시 SERVER/API 계층에 위치해야 합니다.

금지:

APP에서 독자적으로 매출 계산
PC Dashboard에서 별도의 매출 계산
각 화면에서 weekly_count × 가격을 따로 계산
APP/PC마다 다른 rounding
APP/PC마다 다른 teacher allocation 규칙

최종 구조:

Production DB
↓
공통 Settlement Calculation Layer
↓
공통 API Result
↓
APP Teacher
APP Admin
PC Admin
향후 SWIMNOTE PC 운영프로그램

모두 동일 결과 사용.

[I. SHARED CALCULATION ARCHITECTURE]

- 현재 settlement calculator를
  APP/PC 공용 API 계산 엔진으로 사용할 수 있는지
- 계산식을 어떤 server 함수/service로 분리하는 것이
  현재 repository 구조상 가장 적절한지
- calculator / reports / save가
  같은 계산 함수를 재사용할 수 있는지
- APP/PC frontend에서 계산식을 제거하고
  서버 결과만 표시할 수 있는지

이번 단계에서는
이를 이유로 대규모 refactor하지 마십시오.

구현 가능 구조만 제안하십시오.
