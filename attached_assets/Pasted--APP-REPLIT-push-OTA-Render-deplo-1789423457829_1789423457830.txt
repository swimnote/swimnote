1. MAKEUP — pool_admin + teacher 겸직 계정 처리
━━━━━━━━━━━━━━━━━━━━━━

최종 제품 원칙:

ADMIN MODE
= 전체 현황 감독 / read-only

TEACHER MODE
= 자기 담당 범위 실제 보강 운영

입니다.

같은 user가:

pool_admin
+
실제 수업을 담당하는 teacher

역할을 동시에 가질 수 있습니다.

이 경우에도:

[관리자 화면]

- 자기 pool 전체 보강 현황 조회
- 밀린 보강
- 미배정
- 만료 임박
- 소멸 예정

확인만 가능.

관리자 화면에서는:

- 배정
- 일정변경
- cancel
- complete
- transfer
- teacher 지정

등 실제 mutation은 하지 않습니다.

반대로 같은 사용자가
Teacher APP/Teacher Mode로 들어간 경우에는

자기 현재 담당 학생/반의 보강에 대해서:

- 일정 결정
- 배정
- 변경
- 취소
- 완료

를 기존처럼 직접 수행할 수 있어야 합니다.

즉:

pool_admin이라는 이유로
Teacher Mode의 자기 담당 보강 mutation까지 막히면 안 됩니다.

반대로:

pool_admin + teacher 겸직이라는 이유로
Admin Mode에서 전체 pool 보강을 mutation할 수 있어도 안 됩니다.

확인할 것:

1. 현재 auth/JWT에서
   pool_admin + teacher 겸직 사용자를 어떻게 표현하는지

2. APP에서
   Admin Mode / Teacher Mode 진입이 실제로 어떻게 분리되는지

3. `/teacher/makeups` 및 teacher mutation endpoint가
   pool_admin이면서 실제 담당 teacher인 사용자도
   Teacher Mode에서는 정상 사용 가능한지

4. admin mutation endpoint가 존재한다면
   pool_admin에게 실제 서버 권한이 열려 있는지

5. 최종적으로 가장 작은 수정으로:

   Admin Mode = read-only
   Teacher Mode = 담당범위 mutation 가능

   을 보장하는 방법

중요:

단순히 UI 버튼 숨김만으로
Admin Mode read-only를 보장하는 것이 충분한지
아니면 API 권한도 정리해야 하는지 실제 코드 기준으로 판단하십시오.

새 권한 시스템 만들지 마십시오.
