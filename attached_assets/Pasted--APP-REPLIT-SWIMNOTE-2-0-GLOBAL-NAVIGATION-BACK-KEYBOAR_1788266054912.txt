# SWIMNOTE 2.0
# GLOBAL NAVIGATION / BACK / KEYBOARD / SCROLL RULE RE-ENFORCEMENT
# BEFORE STORE CONNECTION

현재 SWIMNOTE 2.0에서
기존에 확정했던 전역 UI 규칙이
일부 신규 기능에 적용되지 않은 문제가 발견되었습니다.

이번 작업은 개별 화면 1~2개 수정이 아니라

1. 뒤로가기 규칙
2. 키보드 표시/해제 규칙
3. Keyboard Avoiding 규칙
4. Scroll 하단 여유 규칙
5. 신규 기능 전체의 규칙 누락 감사

를 다시 전역 기준으로 적용하는 작업입니다.

가격/RevenueCat/Store 연결 작업은
이번 UI 전역 규칙 보정 완료 후 진행합니다.

==================================================
0. LOCKED GLOBAL UI RULES
==================================================

아래 규칙은 SWIMNOTE 2.0 전역 고정 규칙입니다.

--------------------------------
A. BACK RULE
--------------------------------

뒤로가기는 항상:

"직전 화면"

으로만 복귀합니다.

금지:

뒤로가기
→ 홈 강제 이동

뒤로가기
→ 임의의 상위 탭 이동

뒤로가기
→ router.replace("/home")

뒤로가기
→ 특정 홈 route 하드코딩

홈은:

홈 버튼 / 홈 탭

으로만 이동합니다.

--------------------------------
B. WORKFLOW RETURN RULE
--------------------------------

사용자가 어떤 화면에서
다른 화면으로 들어갔다면:

A → B

뒤로가기:

B → A

가 되어야 합니다.

예:

설정
→ SWIMNOTE X모드
→ 뒤로가기

Expected:

설정

홈:
NO

--------------------------------
C. SHEET / MODAL RULE
--------------------------------

실무 작업:

- 출결
- 결석
- 반 이동
- 일지 작성
- 기타 간단 입력/처리

는 가능하면
page navigation보다 sheet/popup 우선.

Modal nesting 금지.

동시에 modal 1개만.

Modal/Sheet 닫을 때:

Keyboard.dismiss()

필요한 local state 초기화.

--------------------------------
D. KEYBOARD RULE
--------------------------------

키보드는:

사용자가 실제 text input을
focus했을 때만 표시.

다음 상황에서 키보드가 자동으로 떠 있으면 안 됨:

- 화면 진입 직후
- 목록 탐색 중
- 검색 결과 스크롤 중
- 상세 내용 보는 중
- 버튼 누른 후 결과 화면
- modal 닫힌 후
- 화면 복귀 후

TextInput focus가 없으면
키보드가 보이지 않는 상태가 기본.

--------------------------------
E. KEYBOARD DISMISS RULE
--------------------------------

다음 동작 시 Keyboard.dismiss 적용 검토:

- 목록 영역 tap
- scroll 시작
- 검색 실행
- 결과 선택
- modal/sheet 닫기
- 뒤로가기
- route 이동
- 완료/저장
- 검색 결과 표시

단 사용자가 실제로
입력 중인 경우 불필요하게 dismiss하지 않음.

--------------------------------
F. KEYBOARD AVOIDING RULE
--------------------------------

모든 입력 화면은
keyboard avoiding 적용.

키보드가 올라왔을 때:

- TextInput
- 전송 버튼
- 저장 버튼
- 검색 결과
- 목록 마지막 item
- 하단 CTA

가 가려지면 안 됨.

iOS Safe Area 포함.

--------------------------------
G. SCROLL BOTTOM SPACE RULE
--------------------------------

ScrollView / FlatList / SectionList 등
스크롤 가능한 화면은

마지막 콘텐츠가
키보드/하단 탭/Safe Area/CTA에
가려지지 않도록 충분한 bottom space 확보.

특히:

contentContainerStyle
paddingBottom
keyboardVerticalOffset
safeAreaInsets.bottom

등 현재 공통 구현 방식 사용.

임의 숫자 하드코딩을 화면마다 제각각 넣지 말고
기존 공통 규칙/helper가 있으면 재사용.

7. CURRICULUM SEARCH KEYBOARD RULE
==================================================

커리큘럼 검색 화면에서:

화면 진입:
키보드 자동 표시 금지

검색어 입력창 tap:
키보드 표시

검색 실행:
Keyboard.dismiss()

결과 목록 표시:
키보드 기본 숨김

결과 목록 scroll:
Keyboard.dismiss()

결과 item 선택:
Keyboard.dismiss()

화면 뒤로가기:
Keyboard.dismiss()

즉:

"채팅창/검색창에 실제 글을 입력할 때"

외에는
키보드가 계속 떠 있지 않도록 수정.

==================================================
8. CURRICULUM SEARCH SCROLL RULE
==================================================

검색 결과 목록은
keyboard + safe area + bottom navigation을 고려.

반드시:

- 마지막 item까지 스크롤 가능
- 마지막 item이 keyboard 위에 숨지 않음
- keyboard open 상태에서도 scroll 가능
- keyboard dismiss 후 layout 정상 복구
- 결과가 많아도 scroll 끝까지 이동 가능

FlatList 사용 시:

contentContainerStyle bottom padding

keyboardDismissMode
keyboardShouldPersistTaps

적절히 설정.

ScrollView 사용 시 동일 의미 보장.

13. keyboardShouldPersistTaps
==================================================

목록 item을 누르기 위해
첫 tap이 keyboard dismiss에만 소비되어
두 번 눌러야 하는 UX 금지.

적절한:

keyboardShouldPersistTaps="handled"

또는 현재 공통 규칙 사용.

사용자 tap 1회로
결과 item 선택 가능해야 함.
