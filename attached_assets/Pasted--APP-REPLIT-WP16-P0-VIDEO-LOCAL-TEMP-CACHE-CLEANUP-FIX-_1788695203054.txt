4. 직접 R2 업로드 원칙
━━━━━━━━━━━━━━━━━━━━━━

사용자 정책:

영상은 앱 내부 저장용으로 복사하지 말 것.

가능하면:

picker local uri
→ 바로 upload request
→ R2
→ remote id/url state 저장
→ local temp 정리

만 사용.

불필요한:

Documents 폴더 복사
persistent cache 복사
duplicate compression copy

금지.

단 iOS picker가 주는 임시 local file 자체는
업로드를 위해 잠깐 존재할 수 있음.

핵심:
업로드 성공 후 남기지 않기.

━━━━━━━━━━━━━━━━━━━━━━
5. 기존 cleanup 회귀 주의
━━━━━━━━━━━━━━━━━━━━━━

이전에 photo preview bug가
upload 직후 compressedUri를 너무 빨리 삭제해서 발생했음.

따라서 이번 cleanup은:

영상 preview가 local uri에 의존하는 동안
즉시 삭제해서 UI를 깨뜨리면 안 됨.

정상:

upload success
→ remote video id/url 확보
→ preview source를 remote 또는 video card state로 전환
→ 그 다음 local temp 삭제

즉:
LOCAL DELETE BEFORE STATE SWITCH = 금지

LOCAL DELETE AFTER REMOTE STATE READY = 허용

사진 path는 수정 금지.

━━━━━━━━━━━━━━━━━━━━━━

7. 실패 시 cleanup
━━━━━━━━━━━━━━━━━━━━━━

upload 실패 시에도
무한 local temp 누적 금지.

정상 정책:

upload fail
→ 사용자에게 실패 표시
→ retry가 필요하면 해당 session 동안 temp 유지 가능
→ 화면 이탈/취소/새 선택 시 cleanup
→ app restart 시 stale temp cleanup

대규모 queue system 금지.
