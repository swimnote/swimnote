현재 commit:
4f4890a9

현재 구현 중 다음은 승인:

- 사진 최대 10장 실제 표시
- +N 제거
- 사진 수에 따른 동적 grid
- Story 1장 완결
- shareSingle 1회
- 원본 일지/사진 무변경

그러나 아래는 승인하지 않는다:

bodyWrap: { flex: 1, overflow: "hidden" }

긴 일지를 화면 밖에서 잘라버리는 것은
확정 정책과 다르다.

최종 정책:

사진이 최우선.
사진은 최대 10장 모두 표시.
본문은 짧으면 원문 그대로.
본문이 Story 영역을 초과하면 실제 요약문을 생성하여 표시한다.

━━━━━━━━━━━━━━━━━━━━━━
1. 기존 clipping 제거
━━━━━━━━━━━━━━━━━━━━━━

overflow:hidden을
긴 일지 최종 처리 방식으로 사용하지 않는다.

텍스트가 잘린 상태로 Instagram에 공유되는 것을 금지한다.

"..." 단순 truncation도 금지.

━━━━━━━━━━━━━━━━━━━━━━
2. Story용 전용 요약 API 설계
━━━━━━━━━━━━━━━━━━━━━━

조사 결과 기존 Teacher Diary AI endpoint는
요약 용도가 아니므로 억지로 재사용하지 않는다.

SWIMNOTE API Server의 기존 OpenAI 호출 인프라를 조사하여
Story Summary 전용 endpoint를 최소 범위로 추가한다.

예:

POST /api/diaries/:diaryId/story-summary

정확한 route 이름은 현재 서버 routing convention에 맞춰 결정.

이 endpoint의 목적은 하나뿐이다:

기존 저장 일지 원문
→ Instagram Story 표시용 짧은 요약문

새로운 수영 지식 생성 기능이 아니다.

━━━━━━━━━━━━━━━━━━━━━━
3. 요약 입력
━━━━━━━━━━━━━━━━━━━━━━

클라이언트가 임의의 다른 텍스트를 보내는 구조보다
가능하면 diaryId 기준으로 서버가 실제 저장된 일지 내용을 조회한다.

요약 대상:

- 공통 일지
- 해당 학부모/학생에게 실제 표시되는 학생별 일지

학부모가 볼 수 없는 다른 학생 내용이
절대 summary에 섞이지 않도록 기존 diary visibility를 재사용한다.

중요:
다른 학생 개인정보 혼입 금지.

━━━━━━━━━━━━━━━━━━━━━━
4. 요약 규칙
━━━━━━━━━━━━━━━━━━━━━━

AI에게 다음 규칙을 강제한다.

- 원문에 존재하는 사실만 사용
- 새로운 수영 지식 추가 금지
- 원문에 없는 평가 추가 금지
- 원문에 없는 칭찬 추가 금지
- 원문에 없는 다음 계획 추가 금지
- 학생 이름/개인 피드백은 현재 학부모 자녀 범위만
- 의미 왜곡 금지
- 핵심 수업 내용 우선
- 개인 피드백이 있으면 핵심 1~2개 유지

결과는 Story에서 빠르게 읽을 수 있는
짧은 문단 형태.

광고 문구 생성 금지.

━━━━━━━━━━━━━━━━━━━━━━
5. 길이 목표
━━━━━━━━━━━━━━━━━━━━━━

StoryPageRenderer의 실제 text 영역을 기준으로
summary 최대 길이를 정한다.

고정 "몇 글자"를 먼저 임의로 정하지 않는다.

현재 Pretendard-Medium,
fontSize,
lineHeight,
사진 수별 남은 text 영역을 기준으로:

사진 1장일 때 허용 line 수
사진 4장일 때 허용 line 수
사진 6장일 때 허용 line 수
사진 10장일 때 허용 line 수

를 먼저 계산한다.

요약 endpoint에는 필요한 목표 길이 또는 max_lines를 전달할 수 있다.

최종 summary는 해당 영역 안에 전부 보여야 한다.

━━━━━━━━━━━━━━━━━━━━━━
6. 요약 호출 조건
━━━━━━━━━━━━━━━━━━━━━━

Story 버튼 탭:

원문이 현재 Story text 영역에 전부 들어감
→ AI 호출 없음
→ 원문 그대로 사용

원문이 Story text 영역 초과
→ Story Summary API 호출
→ summary 수신
→ Story 렌더
→ capture
→ Instagram

즉 모든 공유에서 AI 호출하지 않는다.

긴 일지에서만 호출한다.

9. 캐시
━━━━━━━━━━━━━━━━━━━━━━

같은 일지를 반복 공유할 때마다
AI 비용을 다시 발생시키지 않도록 검토한다.

DB schema 변경은 우선 하지 않는다.

가능하면 클라이언트 AsyncStorage에:

diaryId
+ content hash
+ summary

형태로 캐시.

원문이 변경되어 hash가 달라지면
기존 summary 무효화.

이 방식이 현재 구조에 적합한지 조사 후 적용.

12. 테스트
━━━━━━━━━━━━━━━━━━━━━━

반드시 현재 등록해둔 극단 테스트 데이터를 그대로 사용한다.

CASE 1
사진 1 + 짧은 원문
→ AI 호출 0
→ 원문 전체 표시

CASE 2
사진 4 + 일반 원문
→ 들어가면 AI 호출 0

CASE 3
사진 10 + 짧은 원문
→ 10장 모두 표시
→ 원문 전체

CASE 4
사진 10 + 긴 원문
→ AI summary 호출
→ 10장 모두 표시
→ summary 전체 표시
→ 잘림 없음

CASE 5
사진 10 + 100줄 이상
→ AI summary
→ 1장 Story 완결
→ 검은 화면 없음

CASE 6
summary API 실패
→ Instagram 미실행
→ 오류 안내
→ 원본 변경 없음

CASE 7
동일 일지 두 번째 공유
→ cache 적용 시 AI 재호출 없음
