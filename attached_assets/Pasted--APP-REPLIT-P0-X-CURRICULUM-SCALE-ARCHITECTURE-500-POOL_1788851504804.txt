1. 운영자가 보는 흐름은 3단계만
━━━━━━━━━━━━━━━━━━━━━━

신규 X 수영장:

1. Curriculum DOCX 업로드
2. 구조화 결과 검토/승인
3. 적용

끝.

운영자에게 아래 작업 요구 금지:

- curriculum_version ID 선택
- SCA 직접 생성
- READY 직접 변경
- global curriculum 연결
- global/local duplicate 정리
- SQL 실행
- management override
- manual entitlement로 setup 우회

이 모든 것은 서버 내부 자동화.

━━━━━━━━━━━━━━━━━━━━━━
2. Global Reference는 시스템 단일 자산
━━━━━━━━━━━━━━━━━━━━━━

Global Reference Curriculum은
수영장별로 생성/복사하지 않는다.

시스템에 공통 1세트 또는 versioned global set으로 존재.

모든 pool은 자동으로 검색에 접근.

Global 사용에:

- SCA 불필요
- pool별 assignment 불필요
- pool별 activation 불필요

검색 기준:

is_global_reference=true
AND import_status='ACTIVE'

Global은:

- AI grounding
- 의미 보강
- 부실 Local 보완

에만 사용.

Global item이 직접
CPO/SCP progress target이 되는 것 금지.

━━━━━━━━━━━━━━━━━━━━━━

━━━━━━━━━━━━━━━━━━━━━━

각 pool:

0 또는 1개의 active Local Curriculum.

is_global_reference=false

→ active

를 서버가 자동 처리.

4. SCA 자동화
━━━━━━━━━━━━━━━━━━━━━━

student_curriculum_assignments가
실제 runtime에 필요하다면
절대 수동 생성 구조로 두지 않는다.

Local Curriculum activate 시 서버가 자동:

현재 재원학생
→ active Local version assignment 생성

신규 학생 등록 시 자동:

student created/enrolled
→ 현재 active Local version assignment 생성

퇴원/비활성 처리 시
기존 history는 유지하되 active assignment 정책 자동 적용.

Local version 변경 시:

기존 active SCA deactivate
→ 새 Local version assignment 생성

모든 작업 idempotent.

ON CONFLICT 또는 equivalent로
중복 0 보장.

5. SCA가 정말 필요하지 않다면 제거 방향 검토
━━━━━━━━━━━━━━━━━━━━━━

중요.

현재 코드에서 SCA가:

A. 학생별 서로 다른 curriculum을 지원하기 위해 실제 필요
또는
B. 모든 학생이 동일 pool active version을 쓰는데도
중간 lookup으로만 존재

중 어느 것인지 확인.

만약 B라면
500개 pool 운영을 단순화하기 위해

student
→ pool active Local version

직접 fallback을 canonical source로 삼는 것이
더 단순한지 검토.

단 기존 기능 깨지지 않는 범위에서 판단.

즉:
불필요한 assignment table 의존을
운영 필수조건으로 만들지 말 것.

최종 보고에서:

명확히 판정.

6. READY 상태 자동화

→ upload
→ CURRICULUM_PENDING

pool마다 별도 prerequisite처럼 취급하지 않는다.

global_template_sets ACTIVE=0 때문에
특정 pool READY가 막히는 구조라면
그 dependency가 정말 필요한지 재검토.

500 pool onboarding에서
전역 상태 하나 때문에 모든 신규 pool이 막히는
fragile 구조 금지.

━━━━━━━━━━━━━━━━━━━━━━

같은 파일을 두 번 올려도

필수:

- source hash
- canonical hash
- pool_id
- version
- import batch id

기준으로 중복 처리.

- duplicate detection
또는
- safe new version

중 현재 제품정책에 맞게 하나로 고정.

절대 기존 Global row overwrite 금지.
