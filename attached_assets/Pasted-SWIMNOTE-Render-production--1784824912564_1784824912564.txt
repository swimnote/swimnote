SWIMNOTE 학부모 설정 화면에 추가 보호자 관리 진입 버튼 미노출 수정

현재 Render 배포 후 실제 production 앱의
학부모 ‘내 정보 수정’ 화면을 확인했지만

- 두 번째 보호자 이름
- 두 번째 보호자 전화번호
- 세 번째 보호자 이름
- 세 번째 보호자 전화번호

입력 기능이 전혀 보이지 않습니다.

보고서에는 more.tsx에 “추가 보호자 관리” 메뉴를 추가하고
additional-guardians.tsx 화면을 만들었다고 했지만,
실제 production 앱에는 진입 경로가 없습니다.

이번 작업은 새 기능을 다시 만드는 것이 아니라
실제 사용 중인 학부모 설정 화면에
추가 보호자 관리 기능을 확실히 노출하고 연결하는 작업입니다.

==================================================
1. 실제 production 설정 화면 파일 확인
==================================================

현재 첨부 화면은 학부모의 “내 정보 수정” 화면입니다.

먼저 이 화면을 실제로 렌더링하는 파일을 찾으세요.

전체 검색:

- "내 정보 수정"
- "비밀번호 변경"
- "스윔노트에 문의하기"
- "계정 탈퇴"
- "추가 보호자 관리"

보고서에 수정한 more.tsx가
실제 production 화면인지 확인하세요.

같은 역할의 중복 파일이 있다면
실제 route와 실제 렌더링 파일을 명확히 보고하세요.

==================================================
2. 추가 보호자 관리 메뉴를 실제 화면에 노출
==================================================

학부모 설정 화면에 다음 메뉴를 추가하세요.

[추가 보호자 관리]

배치 위치:

기본 정보
비밀번호 변경
추가 보호자 관리
문의하기
계정 탈퇴

또는 자녀 관리 메뉴가 별도로 있다면
자녀 관리 안에 배치해도 됩니다.

단, 실제 production 앱에서
사용자가 바로 찾을 수 있어야 합니다.

버튼을 누르면:

/(parent)/additional-guardians

화면으로 이동해야 합니다.

==================================================
3. 추가 보호자 관리 화면 요구사항
==================================================

현재 연결된 자녀별로
추가 보호자를 등록할 수 있어야 합니다.

예:

서태웅

주 보호자
- 서경민
- 010-7787-1507
- 연결 완료

두 번째 보호자
- 이름 입력
- 전화번호 입력
- 관계 선택
- 저장

세 번째 보호자
- 이름 입력
- 전화번호 입력
- 관계 선택
- 저장

네 번째 보호자
- 이름 입력
- 전화번호 입력
- 관계 선택
- 저장

이름은 선택 입력으로 두되
전화번호는 필수입니다.

==================================================
4. 저장 위치
==================================================

기존 students 테이블 구조를 사용합니다.

저장 기준:

주 보호자:
parent_phone

두 번째 보호자:
parent_phone2

세 번째 보호자:
parent_phone3

네 번째 보호자:
parent_phone4

이름 필드가 기존에 없다면
다음을 추가하거나 기존 필드를 재사용하세요.

parent_name2
parent_name3
parent_name4

관계까지 저장할 경우:

parent_relation2
parent_relation3
parent_relation4

이번 작업에서 새 student row를 만들면 안 됩니다.

반드시 기존 student_id에 추가 보호자 정보만 저장하세요.

==================================================
5. 관리자 전산 반영
==================================================

학부모가 추가 보호자 정보를 저장하면
수영장 관리자 화면의 기존 학생 상세에 즉시 표시하세요.

예:

보호자 1
서경민
010-7787-1507
주 보호자

보호자 2
조승주
010-6538-0519
가입 대기 또는 연결 완료

보호자 3
김○○
010-1234-5678
가입 대기 또는 연결 완료

현재 관리자 화면에 phone2/3/4만 표시하고 이름은 안 보인다면
이름도 같이 표시되도록 수정하세요.

==================================================
6. 자동 승인 연결
==================================================

추가 보호자 번호로 가입한 학부모는
별도 관리자 승인 없이 기존 학생과 자동 연결합니다.

조건:

가입 인증 전화번호
=
parent_phone2 또는 parent_phone3 또는 parent_phone4

일치 시:

- 기존 student_id에 parent_students 연결 추가
- 새 student row 생성 금지
- 관리자 전산 상태를 연결 완료로 변경
- 학부모 앱에서 기존 자녀 즉시 표시

==================================================
7. 기존 가입자 즉시 연결
==================================================

추가 보호자 번호를 저장할 때
그 번호로 이미 가입한 parent account가 존재하면
즉시 기존 student_id에 연결하세요.

저장 응답에 다음을 반환하세요.

{
  "saved": true,
  "autoLinked": true,
  "linkedParentId": "..."
}

가입 계정이 없으면:

{
  "saved": true,
  "autoLinked": false,
  "status": "pending"
}

==================================================
8. 실제 진입 경로 검증
==================================================

테스트:

1. 학부모 로그인
2. 설정 진입
3. 내 정보 수정 또는 추가 보호자 관리 메뉴 확인
4. 추가 보호자 관리 진입
5. 두 번째 보호자 이름과 번호 입력
6. 저장
7. 화면 재진입 후 값 유지
8. 관리자 학생 상세에 값 표시
9. 해당 번호 가입 계정 자동 연결

현재처럼 화면 파일만 만들고
실제 진입 버튼이 없는 상태는 실패입니다.

==================================================
9. OTA 배포 확인
==================================================

이 작업은 프론트 화면 연결이므로 OTA 배포가 필요합니다.

완료 보고에 반드시 포함:

- 실제 production에서 사용되는 설정 화면 파일
- 추가 보호자 관리 버튼 코드 위치
- additional-guardians route
- iOS production OTA update ID
- Android production OTA update ID
- 실제 기기에서 메뉴가 보이는 스크린샷
- 추가 보호자 입력 화면 스크린샷
- 저장 후 관리자 화면 스크린샷

완료 기준:

- 학부모 설정에서 “추가 보호자 관리”가 실제로 보임
- 두 번째·세 번째 보호자 이름과 전화번호 입력 가능
- 저장 후 다시 들어가도 값 유지
- 관리자 전산에 이름과 번호 반영
- 해당 번호 가입자는 기존 학생에 자동 연결
- 새 학생 중복 생성 없음
