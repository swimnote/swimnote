2. eligible-occurrences 실제 장애
━━━━━━━━━━━━━━━━━━━━

실기기:

finalType = NETWORK

Error:

SyntaxError
JSON Parse error: Unexpected character: <

즉 JSON parsing 전에 받은 실제 response body가
JSON이 아닌 것으로 확인된다.

가장 먼저 해야 할 일:

Production의 정확한 URL에 대해
실제 HTTP 응답을 조사한다.

대상:

GET
https://swimnote.kr/api/teacher/makeups/{makeupId}/eligible-occurrences?class_group_id={classGroupId}

현재 진단 화면의 실제 makeupId/classGroupId를 사용한다.

반드시 확인:

HTTP status
content-type
response headers
response body 첫 500자
redirect 여부
최종 URL
서버 route 도달 여부

중요:

response.json()부터 호출하지 마라.

먼저 response.text()로 원문을 확보해서
왜 "<"로 시작하는지 확인한다.

HTML이면 HTML의 정체를 확인한다.

404 HTML인지
502/503 proxy HTML인지
Google Frontend 오류인지
redirect 결과인지
Express error page인지

증거로 확정한다.

3. 서버 로그 대조
━━━━━━━━━━━━━━━━━━━━

동일 시각의 Production 서버 로그에서

eligible-occurrences 요청이

A. Express route까지 도달했는지
B. route 내부에서 exception이 발생했는지
C. route에 아예 도달하지 않았는지

확인한다.

route에 도달했다면
발생한 실제 exception/stack을 제출한다.

도달하지 않았다면
swimnote.kr/api proxy/routing 경계를 조사한다.
