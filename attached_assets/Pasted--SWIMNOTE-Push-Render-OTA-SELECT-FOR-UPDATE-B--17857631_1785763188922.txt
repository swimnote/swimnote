[SWIMNOTE 긴급 오류 수정 — 최종 배포 전 차단사항 보완]

현재 Push·Render 배포·OTA는 승인하지 않는다.

SELECT FOR UPDATE 안 B는
고정된 상태값으로 전체 반 이탈시키는 경로에는 허용 가능하지만,
현재 반 목록을 읽어 일부만 제거하는 경로에는 적용할 수 없다.

━━━━━━━━━━━━━━━━━━━━━━
1. 반드시 수정할 경로
━━━━━━━━━━━━━━━━━━━━━━

POST /students/:id/remove-from-class
- new_status 없음
- 특정 반 하나만 즉시 제거하는 경로

현재 문제:

assigned_class_ids, newIds, class_group_id, schedule_labels 등을
transaction 시작 전 existing 값으로 계산하고 있다.

이 상태에서는 동시 요청이 직렬화돼도
잠금 전 계산한 오래된 값으로 UPDATE하여 lost update가 발생할 수 있다.

━━━━━━━━━━━━━━━━━━━━━━
2. 해당 경로는 안 A로 변경
━━━━━━━━━━━━━━━━━━━━━━

transaction 내부에서:

1. SELECT students ... FOR UPDATE
2. locked.assigned_class_ids 파싱
3. locked.class_group_id 확인
4. 제거 대상 class_group_id를 기준으로 newIds 계산
5. 새 primary class_group_id 계산
6. schedule_labels 재계산에 필요한 최신 데이터 확정
7. closeClassHistory()
8. students UPDATE
9. commit

즉, 다음 값은 반드시 locked row 기준으로 transaction 안에서 계산한다.

- currentIds
- newIds
- newPrimaryClassId
- schedule_labels
- remaining_classes

transaction 밖 existing 값은 권한 확인이나 응답 보조 용도로만 사용한다.

━━━━━━━━━━━━━━━━━━━━━━
3. 전체 반 이탈 경로는 현 구조 유지 가능
━━━━━━━━━━━━━━━━━━━━━━

아래 경로는 UPDATE 결과가 현재 반 배열의 내용과 무관하게
항상 NULL / []로 고정되므로 잠금 목적 안 B를 유지할 수 있다.

- change-status suspended/withdrawn/unassigned
- remove-from-class + new_status
- admin PATCH suspended/withdrawn/archived
- admin POST withdraw

단, 잠금 후 학생 존재 여부 확인은 유지한다.

━━━━━━━━━━━━━━━━━━━━━━
4. 응답값도 잠금 후 결과 기준
━━━━━━━━━━━━━━━━━━━━━━

remove-from-class 응답의:

- remaining_classes
- class_group_id
- assigned_class_ids

관련 값이 있다면 잠금 후 계산한 newIds 기준으로 반환한다.

잠금 전 계산값 반환 금지.

━━━━━━━━━━━━━━━━━━━━━━
5. Rollback 문서 정정
━━━━━━━━━━━━━━━━━━━━━━

전체 롤백 설명에서 기준선은 정확히 다음과 같이 표기한다.

현재 HEAD:
2bc214bc

전체 수정 전 기준선:
9185e164

`git reset 9185e164`은 커밋 이력을 이동시키는 작업이므로
사용자 실행용 기본 Rollback 명령으로 권장하지 않는다.

아직 원격 Push 전이므로 실제 롤백이 필요할 때만 별도 승인 후 실행한다.

현재는 reset·restore·rm 모두 실행 금지.

━━━━━━━━━━━━━━━━━━━━━━
6. 보완 후 제출
━━━━━━━━━━━━━━━━━━━━━━

1. remove-from-class 특정 반 이탈 경로 실제 diff
2. locked row에서 계산되는 값 목록
3. 동시 요청 시나리오 테스트
4. 서버 타입체크 결과
5. git status
6. 자동 checkpoint 추가 발생 여부

금지:

- Push
- Render 배포
- OTA
- 운영 DB 수정
- reset
- revert
- force push
- X모드 작업 재개

이 보완만 수행하고 보고 후 멈춘다.
