SWIMNOTE AI UI Framework V1.0
Phase 2 — Motion System 구현 및 독립 프리뷰 검증

Stage Gate 1 통과를 확인했습니다.

이번 작업은 Phase 2입니다.

목표는 AI UI Framework의 공통 Motion System을 구현하고,
기존 앱 기능과 연결하지 않은 독립 프리뷰 화면에서
실제 애니메이션 품질을 검증하는 것입니다.

중요 제한

- 기존 AI 일지 화면을 수정하지 마십시오.
- 기존 일지 작성 흐름을 수정하지 마십시오.
- 기존 API를 호출하지 마십시오.
- 크레딧 로직을 연결하지 마십시오.
- 실제 음성 녹음을 구현하지 마십시오.
- 사진·영상 기능을 추가하지 마십시오.
- 새 라이브러리를 설치하지 마십시오.
- 기존 앱의 라우팅 구조를 불필요하게 변경하지 마십시오.
- 현재 설치된 Reanimated, Gesture Handler, Blur, LinearGradient,
  Haptics, Keyboard Controller만 사용하십시오.

2. State별 레이아웃 전환 구현
==================================================

아래 상태 전환에서 UI가 자연스럽게 변형되도록 구현합니다.

CLOSED
→ OPENING
→ INPUT
→ RECORDING
→ PROCESSING
→ RESULT
→ EDITING
→ COMPLETE
→ CLOSED

오류 흐름

현재 State
→ ERROR
→ retryTargetState

retryTargetState 예시

- 입력 오류 → INPUT
- 네트워크 오류 → INPUT
- 권한 오류 → PERMISSION
- 녹음 실패 → RECORDING
- 업로드 실패 → UPLOADING
- AI 타임아웃 → PROCESSING
- 크레딧 부족 → CLOSED
- 복구 불가 오류 → CLOSED

ERROR는 고정 복귀 State를 사용하면 안 됩니다.

AIErrorInfo의 retryTargetState를 기준으로 복귀해야 합니다.

==================================================
3. 레이아웃 구현 원칙
==================================================

고정된 40% / 40% 영역으로 만들지 마십시오.

상태에 따라 레이아웃이 반응형으로 변해야 합니다.

INPUT

- 입력 영역이 화면의 중심
- 결과 영역 숨김
- 음성 버튼 강조
- ActionBar 최소 구성

RECORDING

- 입력 영역 축소
- 음성 파형 영역 확장
- 녹음 시간 표시
- 취소와 완료 버튼 노출

PROCESSING

- 입력 내용은 요약된 형태로 축소
- 처리 영역이 중심으로 확장
- Shimmer 또는 Skeleton 표시
- 중복 제출 방지

RESULT

- 결과 카드가 자연스럽게 펼쳐짐
- 입력 영역은 상단 요약 형태로 축소
- 결과 영역 스크롤 가능
- 수정·재생성·삽입 버튼 표시

EDITING

- 결과 카드가 편집 가능한 입력 영역으로 전환
- 키보드 등장 시 ActionBar가 가려지지 않아야 함

COMPLETE

- 성공 Motion 후 닫기
- 결과 데이터는 Feature 쪽 콜백으로 전달

4. Swipe Down 닫기
==================================================

BaseAIModal에 아래 제스처를 구현합니다.

- 상단 또는 콘텐츠 전체에서 아래 방향 Drag
- 일정 거리 또는 속도 이상이면 닫기
- 기준 미달이면 Spring으로 원위치
- 내부 ScrollView가 최상단일 때만 Swipe Down 활성화
- 결과 내용을 아래로 스크롤하는 동작과 충돌하지 않아야 함
- 키보드가 열려 있으면 첫 Drag에서 키보드를 닫고,
  모달 종료는 다음 명확한 Drag에서 처리하는 방안을 검토

닫기 기준값은 Theme 또는 Motion Token으로 관리합니다.

하드코딩하지 마십시오.

==================================================
5. Reduce Motion 구현
==================================================

useAIReducedMotion을 실제 Motion System과 연결합니다.

Reduce Motion 활성화 시

- 큰 scale 변화 제거
- 과도한 Spring 제거
- errorShake 제거
- successBounce 제거
- 타이핑 효과 생략
- 반복 Pulse 최소화
- height 기반 과도한 Morphing 축소
- opacity 중심 전환 사용

Reduce Motion 여부 때문에 기능 동작이나 State 전이가 달라지면 안 됩니다.

Motion 표현만 달라져야 합니다.

==================================================
6. Shimmer 구현
==================================================

현재 설치된 expo-linear-gradient를 사용합니다.

조건

- 무한 애니메이션은 화면이 PROCESSING일 때만 실행
- 다른 State로 이동하면 즉시 중단
- 컴포넌트 언마운트 후 애니메이션이 남지 않아야 함
- Reduce Motion에서는 단순 Pulse 또는 정적 Skeleton 사용
- JS setInterval을 사용하지 말고 Reanimated 반복 애니메이션 사용

==================================================
7. 음성 파형 프리뷰
==================================================

이번 Phase에서는 실제 녹음 데이터를 연결하지 않습니다.

프리뷰용 가상 amplitude 값으로만 파형을 구현합니다.

조건

- SVG 또는 일반 Animated View 사용
- Skia 설치 금지
- 막대 수를 과도하게 늘리지 않기
- RECORDING State에서만 실행
- State 종료 시 애니메이션 정리
- 실제 expo-av metering 값으로 나중에 교체 가능한 props 구조 유지

예시

<AIVoiceWaveform amplitudes={...} active={state === 'RECORDING'} />

공통 컴포넌트가 필요하면 생성할 수 있습니다.

단, 생성한 파일과 이유를 보고하십시오.

==================================================
8. 독립 프리뷰 화면
==================================================

기존 AI 일지 화면에 연결하지 말고
개발 검증용 독립 프리뷰 화면을 만듭니다.

프리뷰 목적

- 모든 State를 수동으로 이동
- Motion을 실제 기기에서 확인
- ERROR 복구 흐름 확인
- Reduce Motion 모드 확인
- 키보드 대응 확인
- Swipe Down 확인

프리뷰 화면에 필요한 조작

- Open Modal
- Next State
- Previous 또는 Reset
- INPUT
- RECORDING
- UPLOADING
- PROCESSING
- RESULT
- EDITING
- COMPLETE
- PERMISSION ERROR
- NETWORK ERROR
- CREDIT ERROR
- Toggle Reduce Motion Simulation

프리뷰용 데이터만 사용합니다.

실제 API 호출은 금지합니다.

프리뷰 화면은 프로덕션 사용자에게 노출되지 않도록
개발 환경 전용 또는 명시적인 내부 테스트 경로로 구성합니다.

9. 성능 기준
==================================================

- 주요 애니메이션은 UI Thread에서 실행
- 애니메이션 제어를 위한 빈번한 React setState 금지
- 글자 단위 setState 타이핑 금지
- 불필요한 전체 트리 리렌더링 방지
- Modal 내부에서 무거운 Blur 중첩 금지
- 동시에 실행되는 무한 애니메이션 최소화
- Android 저사양 환경 고려
- useNativeDriver에 해당하는 Reanimated UI Thread 구조 유지
