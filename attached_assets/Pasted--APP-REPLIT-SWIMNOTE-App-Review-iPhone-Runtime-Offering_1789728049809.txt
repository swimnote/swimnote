[보낼 곳: APP REPLIT]

[SWIMNOTE — 신규 구독상품 App Review 제출 실행]

실제 iPhone Runtime 재진단 결과:

Offerings:
- solo_monthly
- center_monthly

MISSING:
- swimnote_monthly
- x_monthly

Direct getProducts:
- com.swimnote.swimnote.monthly = NOT FOUND
- com.swimnote.x300.monthly = NOT FOUND

그리고 ASC 신규 6개 상품은 현재:

MISSING_METADATA
→ READY_TO_SUBMIT

상태까지 정상화되었습니다.

이제 중요한 정책을 수정합니다.

READY_TO_SUBMIT은
“심사 제출 가능한 상태”이지
“이미 판매 가능한 상태”가 아닙니다.

따라서 단순 propagation 대기만 하지 말고
신규 구독상품을 App Review에 제출하는 단계로 진행합니다.

APP 코드 / RevenueCat / OTA는 건드리지 마십시오.

━━━━━━━━━━━━━━━━━━━━━━
1. 기존 승인 이력 확인
━━━━━━━━━━━━━━━━━━━━━━

현재 동일 앱:

com.swimnote.app

에는 기존 auto-renewable subscription:

solo_30
solo_50
solo_100
center_200
center_300
center_500
center_1000

등이 이미 APPROVED 상태입니다.

따라서 Apple 정책상
“첫 auto-renewable subscription” 제출이 아닙니다.

먼저 ASC API 기준으로:

- 앱에 approved app version 존재 여부
- 기존 auto-renewable subscription approved 존재 여부

를 확인하십시오.

둘 다 YES라면
신규 구독상품을 새 app version 없이
독립적으로 review submission 가능한지
현재 ASC API/상태 기준으로 확정하십시오.

━━━━━━━━━━━━━━━━━━━━━━
2. SUBSCRIPTION GROUP 상태 확인
━━━━━━━━━━━━━━━━━━━━━━

신규 상품이 속한 group:

SWIMNOTE Membership
SWIMNOTE Data

두 subscription group의 현재 상태를 확인하십시오.

특히:

- group localization 존재 여부
- group 자체가 이미 review 가능한 상태인지
- 아직 승인되지 않은 신규 group인지

확인.

Apple 정책상 group이 아직 승인되지 않아
submission에 group 포함이 필요하면
해당 group도 같이 포함하십시오.

임의로 새 group 만들지 마십시오.

━━━━━━━━━━━━━━━━━━━━━━
3. 제출 대상
━━━━━━━━━━━━━━━━━━━━━━

다음 6개만 대상:

com.swimnote.swimnote.monthly
com.swimnote.x300.monthly
com.swimnote.x500.monthly
com.swimnote.x1000.monthly
com.swimnote.data100.monthly
com.swimnote.data300.monthly

구 legacy:

com.swimnote.x.monthly.tier1
tier2
tier3
standard

등은 이번 submission에 포함 금지.

현재 앱/RevenueCat에서 사용하지 않는 상품입니다.

━━━━━━━━━━━━━━━━━━━━━━
4. 제출 전 최종 검증
━━━━━━━━━━━━━━━━━━━━━━

각 6개에 대해:

- state = READY_TO_SUBMIT
- localization 존재
- monthly duration
- price 정상
- Korea availability 포함
- 올바른 subscription group
- product ID 정확
- review 제출 blocker 없음

확인.

값을 다시 수정하지 마십시오.

문제가 발견되면
제출 전에 중단 후 보고.

━━━━━━━━━━━━━━━━━━━━━━
5. APP VERSION 필요 여부
━━━━━━━━━━━━━━━━━━━━━━

기존 auto-renewable subscription이 이미 APPROVED이므로
원칙적으로 additional subscription은
독립 submission 가능해야 합니다.

실제 ASC가:

“app version 필요”

를 요구하지 않는다면
새 앱 버전을 만들지 마십시오.

현재 Production 앱 build/version을
구독 심사를 위해 임의 증가시키지 마십시오.

ASC가 실제로 app version을 요구할 때만
중단 후 해당 이유를 보고하십시오.

━━━━━━━━━━━━━━━━━━━━━━
6. APP REVIEW SUBMISSION
━━━━━━━━━━━━━━━━━━━━━━

ASC API 또는 현재 정상 접근 가능한 방법으로
6개 신규 상품을 review submission에 추가하십시오.

필요한 미승인 subscription group도
ASC 요구사항에 따라 함께 포함.

그리고:

Submit for Review

까지 진행하십시오.

이번 작업에서는 실제 구독 구매는 하지 않습니다.

━━━━━━━━━━━━━━━━━━━━━━
7. REVIEW NOTE
━━━━━━━━━━━━━━━━━━━━━━

review note가 이미 존재하고
실제 기능 설명이 정확하면 유지.

새로 필요한 경우
과장하지 말고 간단하게:

SWIMNOTE 관리자 앱의
구독 관리 화면에서 선택 가능한
월간 자동갱신 구독 상품이라는 사실만 설명.

상품별 기능/가격은
현재 앱 표시와 일치해야 합니다.

임의 marketing 문구 추가 금지.

━━━━━━━━━━━━━━━━━━━━━━
8. 제출 후 실제 상태 확인
━━━━━━━━━━━━━━━━━━━━━━

제출 완료 후 6개 각각 실제 ASC state를 재조회.

예:

WAITING_FOR_REVIEW
IN_REVIEW
등 실제 Apple API 상태.

READY_TO_SUBMIT 그대로인데
submission만 생성된 경우도
정확한 상태를 보고.

“제출 요청했다”만으로 완료 금지.

━━━━━━━━━━━━━━━━━━━━━━
9. 이번 단계에서 금지
━━━━━━━━━━━━━━━━━━━━━━

- APP code 수정
- OTA
- native build
- RevenueCat offering 변경
- product ID 변경
- 가격 변경
- group 이동
- DB/API 수정
- 실제 결제
- 진단 버튼 제거

현재 구독 진단 버튼은
승인 후 재검증까지 유지.

━━━━━━━━━━━━━━━━━━━━━━
10. 승인 이후 검증 계획
━━━━━━━━━━━━━━━━━━━━━━

App Review에서 신규 상품 승인 후
동일 실제 iPhone에서:

구독 상품 진단

을 다시 실행.

최종 성공 기준:

Offerings:
- swimnote_monthly FOUND
- x_monthly FOUND

Direct getProducts:
- SWIMNOTE FOUND
- X300 FOUND

그리고 실제 화면:

SWIMNOTE
“구독 신청 준비 중”
→
“구독 시작”

자동 전환 확인.

승인 전에는
앱 버튼을 강제로 활성화하지 마십시오.

━━━━━━━━━━━━━━━━━━━━━━
11. 완료보고
━━━━━━━━━━━━━━━━━━━━━━

[A. ELIGIBILITY]

- approved app version 존재 여부
- 기존 approved auto-renewable subscription 존재 여부
- 새 app version 없이 독립 submission 가능 여부

[B. GROUPS]

SWIMNOTE Membership:
- 상태
- submission 포함 필요 여부

SWIMNOTE Data:
- 상태
- submission 포함 필요 여부

[C. PRODUCTS]

6개 각각:
- 제출 전 state
- submission 포함 여부

[D. SUBMISSION]

- App Review Submission ID
- 제출 시각
- 실제 submission status

[E. AFTER]

6개 각각 실제 ASC state

[F. APP]

- 코드 변경 없음
- OTA 없음
- RevenueCat 변경 없음
- 진단 버튼 유지
