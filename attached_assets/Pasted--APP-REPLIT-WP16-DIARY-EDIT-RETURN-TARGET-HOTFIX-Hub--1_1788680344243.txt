# WP16 — DIARY EDIT RETURN TARGET HOTFIX
# 범위 극소화
# 수업일지 Hub의 뒤로가기는 정상 — 절대 수정 금지
# 오직 DiaryEditView의 저장/뒤로가기 return target만 수정
# 수정 완료 후 release/v2.0.0 반영 + iOS production-v2 OTA까지 자동 완료
# Render deploy 금지

현재 실기기 실제 증상:

수업일지 Hub
→ 기존 Diary 선택
→ 일지 수정 화면

여기까지는 정상.

문제:

1.
일지 수정 화면에서 "저장"
→ Teacher Home으로 이동함

2.
일지 수정 화면에서 상단 "뒤로가기"
→ Teacher Home으로 이동함

정상 동작:

수업일지 Hub
→ 일지 수정
→ 저장
→ 수업일지 Hub

수업일지 Hub
→ 일지 수정
→ 뒤로가기
→ 수업일지 Hub

그리고:

수업일지 Hub 자체에서 뒤로가기
→ 스케줄러

이 동작은 현재 정상이며 절대 변경하지 마십시오.

3. 상단 뒤로가기 exact 코드 찾기

4. canonical return rule
━━━━━━━━━━━━━━━━━━━━━━

Teacher Home으로 이동 금지.

5. Hub 자체 back 동작 보존
━━━━━━━━━━━━━━━━━━━━━━

수업일지 Hub:

상단 뒤로가기
→ 스케줄러

현재 정상.

절대 변경 금지.

이번 수정으로:

Edit → Hub → Back → Scheduler

2단계 navigation이 정상이어야 함.

Edit → Back → Scheduler
로 한 번에 빠지면 FAIL.

6. return target fallback
━━━━━━━━━━━━━━━━━━━━━━

Hub가 아닌 다른 정상 entry에서
DiaryEditView를 열 수 있다면
기존 정상 return semantics는 유지.

단:

Hub에서 들어왔는데
fallback 때문에 Home으로 가는 상태 금지.

우선순위:

1. explicit backTo/returnTo
2. valid previous Diary context
3. safe Diary Hub

Home은 Diary edit의 기본 fallback으로 사용하지 말 것.
