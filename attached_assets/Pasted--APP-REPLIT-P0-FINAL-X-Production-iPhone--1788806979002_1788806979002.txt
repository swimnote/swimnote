현재 화면에 보이는 주요 문제:

- 시작일 NaN.NaN.NaN
- 만료일 NaN.NaN.NaN
- SWIMNOTE X Standard / 활성 표시가 실제 entitlement 종류와 맞는지 불명확
- 커리큘럼 미배정 210명

- AI 일지 0건
- 커리큘럼 검색 0건/0명

- AI 성장 이벤트 0건

- 일부 값이 server error인데 0으로 fallback될 가능성

이 화면은 X모드 핵심 대시보드다.

각 metric별로 반드시 아래 mapping을 만든다:

metric
→ frontend field
→ API endpoint
→ server query/service
→ DB/source
→ actual Production value
→ UI value

각 metric은 아래 3상태를 반드시 구분:

SUCCESS_VALUE
SUCCESS_ZERO
ERROR/UNAVAILABLE

ERROR인데 0 표시 금지.

예:
`value ?? 0`
`count || 0`

로 서버 오류를 숨기지 말 것.

B. X 활성 방식 / 시작일 / 만료일
━━━━━━━━━━━━━━━━━━━━━━

현재 수영장은 강제/수동 X모드 활성 상태일 수 있다.

canonical semantics 유지:

feature access = canonical mode resolver
paid = x_paid_entitlement
manual = x_manual_entitlement
HQ = x_management_override
forced off = x_force_disabled

`mode === 'x'`
를 유료 구독으로 간주 금지.

현재 pool의 실제 활성화 source를 판정:

- paid entitlement
- manual entitlement
- management override
- 기타 canonical source

그리고 실제 activation timestamp를 찾아 표시.

우선 기존 데이터에서:

- entitlement created_at
- override created_at
- xmode activation timestamp
- subscription started_at
- activation log/history

등 "실제 X 활성 시작" 의미가 있는 값을 사용.

updated_at을 임의 시작일로 쓰지 말 것.

최종 UI:

활성 방식
예:
관리자 수동 활성
본사 관리 활성
X300 구독

시작일:
실제 날짜

만료일:
유료 구독이면 실제 만료일
수동/관리 override에 만료가 없으면
"만료 없음"

DB 어디에도 과거 activation timestamp가 없으면:
"시작일 기록 없음"

으로 정확히 표시.

NaN/Invalid Date 금지.

강제 활성인데
`SWIMNOTE X Standard`
라고 유료 플랜처럼 오인시키면
실제 활성 방식에 맞게 수정.
