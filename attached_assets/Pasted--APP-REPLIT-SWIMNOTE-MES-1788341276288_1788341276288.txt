1. CLIENT FIX #1 — 화면 자동 갱신
============================================================

대상:

artifacts/swim-app/components/common/MessengerScreen.tsx

현재 문제:

MessengerScreen은
초기 loadMessages()
+
useFocusEffect()

만 사용.

화면을 계속 보고 있는 동안
상대방이 새 메시지를 보내면 자동으로 나타나지 않음.

최소 수정:

MessengerScreen이 focus 상태일 때만
5~10초 간격 HTTP polling 수행.

권장:
5초 또는 7초.

원칙:

- 화면 focus일 때만 polling
- blur/unmount 시 interval 즉시 cleanup
- 중복 interval 금지
- 기존 loadMessages() 재사용
- 새 인프라 추가 금지
- WebSocket/SSE 금지

중요:

사용자가 메시지를 입력 중이어도
keyboard/focus를 건드리지 말 것.

polling 때문에:
- scroll 튐
- 입력값 초기화
- 화면 전체 loading spinner 반복
- optimistic message 중복

발생하지 않도록 한다.

background polling 시
전체 screen loading state를 다시 켜지 말 것.

2. 중복 메시지 방지
============================================================

polling과 optimistic send가 같이 동작하므로

동일 message id가 두 번 렌더링되지 않는지 확인.

서버 authoritative message가 도착하면
optimistic item과 안전하게 reconcile되는
기존 구조를 보존.

필요한 경우에만 최소 dedupe 추가.

3. CLIENT FIX #2 — KST 날짜 separator
============================================================

현재 잘못된 코드:

sameDay(a,b)
→ a.slice(0,10) === b.slice(0,10)

UTC ISO 문자열 날짜를 직접 비교하고 있어서
KST 기준 날짜가 다르게 표시됨.

수정:

기존 parseDateSafe()를 사용해
각 timestamp를 Date로 변환한 뒤

local:
year
month
date

를 비교.

예:

KST
2026-09-02 08:00
2026-09-02 10:00

→ same day = true

UTC 날짜 문자열 slice 비교 금지.

fmtTime / fmtDateFull 기존 구현은
정상이라면 건드리지 말 것.
