[SWIMNOTE — 사진 전체앨범 iOS 선택순서 확정 / orderedSelection 적용]

조사 결과 승인합니다.

확정 ROOT CAUSE:

현재 expo-image-picker ~55.0.22는
iOS 15+에서 orderedSelection 옵션을 지원하지만,

사진 전체앨범의 실제
launchImageLibraryAsync 호출 2곳에

orderedSelection: true

가 없어서 기본 false로 동작하고 있습니다.

따라서 iOS picker 단계에서
사용자가 사진을 누른 순서와
result.assets 배열 순서가 항상 같다는 보장이 없었습니다.

이후:

- compression
- upload_sort_order
- upload_batch_id
- API payload
- DB
- teacher-all ORDER BY
- FlatList

는 result.assets의 배열 순서를 그대로 보존하므로

picker 단계에서 잘못된 순서가 들어오면
그 잘못된 순서를 정상적으로 영구 저장하는 구조였습니다.

이번 작업은 iOS selection order 계약을
확실하게 만드는 최소 수정만 합니다.

1. 수정 대상
━━━━━━━━━━━━━━━━━━━━━━

파일:

artifacts/swim-app/app/(teacher)/photos.tsx

사진 전체앨범 업로드에 사용되는
launchImageLibraryAsync 호출 2곳:

- handleTileUpload 경로
- pickAndUpload 경로

둘 다 확인하십시오.

2. PICKER 옵션 수정
━━━━━━━━━━━━━━━━━━━━━━

현재 의미:

launchImageLibraryAsync({
  mediaTypes: ["images"],
  allowsMultipleSelection: true,
  quality: 0.85,
  selectionLimit: 100,
})

수정:

launchImageLibraryAsync({
  mediaTypes: ["images"],
  allowsMultipleSelection: true,
  orderedSelection: true,
  quality: 0.85,
  selectionLimit: 100,
})

두 실제 업로드 picker 모두 동일하게 적용하십시오.

3. 제품 계약
━━━━━━━━━━━━━━━━━━━━━━

iOS에서 앞으로 사진 업로드 순서는:

사용자가 picker에서 선택한 순서

1
2
3
4
...

를 canonical order로 사용합니다.

result.assets[0]
= 선택 1번

result.assets[1]
= 선택 2번

...

이 순서를:

compression
→ upload task
→ upload_sort_order
→ DB
→ 전체앨범

까지 그대로 유지합니다.

업로드 완료 속도는 표시 순서에
어떠한 영향도 주면 안 됩니다.
