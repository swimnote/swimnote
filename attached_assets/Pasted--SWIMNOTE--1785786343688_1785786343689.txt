[SWIMNOTE 학부모 회원가입 수영장 검색 — 최종 보완 및 배포 지시]

현재 구현 방향은 승인한다.

확정 완료 항목:

- 검색어가 없으면 수영장 전체 목록 비노출
- 서버도 검색어 없으면 빈 배열 반환
- 수영장 이름 전방일치 검색
- 300ms debounce
- AbortController를 통한 이전 요청 취소
- 최대 20개 결과 제한
- 전화번호 응답 제거
- 검색 결과에서 실제 수영장을 선택해야 가입 가능
- 텍스트만 입력한 상태에서는 가입 진행 차단

다만 배포 전에 아래 항목을 최종 보완한다.

━━━━━━━━━━━━━━━━━━━━━━
1. 주소 노출 최소화
━━━━━━━━━━━━━━━━━━━━━━

현재 서버 응답:

SELECT id, name, address

현재 화면에는 상세 주소가 그대로 표시될 가능성이 있다.

학부모 회원가입 화면에서는 수영장 구분에 필요한 최소 지역 정보만 표시한다.

목표 예시:

토이키즈스윔클럽
고양시 덕양구

스윔노트 데모 수영장
서울시 강남구

금지:

- 번지 전체 노출
- 상세 도로명 주소 전체 노출
- 건물명·층수 노출
- 전화번호 노출
- 대표자명 노출
- 회원 수·요금제·X모드 여부 노출

먼저 Repository에서 swimming_pools 테이블에 다음과 같은 지역 컬럼이 있는지 확인한다.

- city
- district
- region
- sido
- sigungu
- address_short

지역 컬럼이 존재하면 해당 컬럼만 반환한다.

예:

SELECT id, name, city, district

지역 컬럼이 없고 address만 존재하면 DB 구조를 변경하지 말고,
서버 또는 클라이언트에서 화면 표시용 주소를 최소 지역 단위로 축약한다.

예:

서울특별시 강남구 테헤란로 123
→ 서울특별시 강남구

경기도 고양시 덕양구 화정로 10
→ 경기도 고양시 덕양구

주소 축약은 화면 표시용으로만 사용한다.
가입 처리에 필요한 기존 swimming_pool_id는 그대로 유지한다.

주소 파싱이 불확실한 경우 임의로 잘못 자르지 말고,
수영장 이름만 표시하는 방식이 더 안전하다.

최종 선택 우선순위:

1. 기존 시·군·구 컬럼 사용
2. 안전한 축약이 가능한 경우 최소 지역 표시
3. 불확실하면 이름만 표시

━━━━━━━━━━━━━━━━━━━━━━
2. 검색 결과 표시 구조
━━━━━━━━━━━━━━━━━━━━━━

검색 결과 한 행에는 다음만 표시한다.

- 수영장 이름
- 최소 지역 정보

예:

토이키즈스윔클럽
경기도 고양시 덕양구

화면에 표시하지 않는 값:

- swimming_pool_id
- phone
- 상세 주소
- 내부 승인 상태
- 생성일
- 구독 상태
- X모드 상태

ID는 내부 선택값으로만 유지한다.

━━━━━━━━━━━━━━━━━━━━━━
3. 검색 결과 선택 후 상태
━━━━━━━━━━━━━━━━━━━━━━

수영장 선택 시:

1. selectedPool 설정
2. 선택된 수영장 카드 표시
3. 검색 결과 목록 닫기
4. 검색 로딩·오류 상태 초기화

선택 후 검색어를 수정하면:

- 기존 selectedPool 즉시 해제
- 새 검색 결과에서 다시 선택하게 한다

가입 제출 시:

- selectedPool이 없으면 차단
- 서버에 selectedPool.id만 전달
- 사용자가 입력한 문자열을 pool_id 대신 사용하지 않는다

오류 문구:

검색 결과에서 수영장을 선택해 주세요.

━━━━━━━━━━━━━━━━━━━━━━
4. 서버 API 최종 확인
━━━━━━━━━━━━━━━━━━━━━━

대상:

GET /pools/public-search?name=검색어

필수 정책:

1. name 없음 → []
2. name="" → []
3. 공백만 입력 → []
4. 이름 전방일치만 허용
5. 주소 포함 검색 금지
6. 승인된 수영장만 반환
7. 삭제·비활성 수영장 필터가 실제 스키마에 있으면 함께 적용
8. 최대 20개
9. 전화번호 반환 금지
10. 상세 주소 최소화

최종 SQL은 실제 스키마에 맞춰 제출한다.

예:

SELECT id, name, city, district
FROM swimming_pools
WHERE approval_status = 'approved'
  AND name ILIKE ${q + '%'}
ORDER BY
  CASE WHEN LOWER(name) = LOWER(${q}) THEN 0 ELSE 1 END,
  LENGTH(name),
  name
LIMIT 20

삭제·비활성 컬럼이 실제로 존재하지 않으면 임의 컬럼을 사용하지 않는다.

━━━━━━━━━━━━━━━━━━━━━━
5. 클라이언트 검색 상태
━━━━━━━━━━━━━━━━━━━━━━

signup.tsx에서 다음 상태를 명확히 유지한다.

- idle
- loading
- loaded
- empty
- error

정책:

검색어 없음:
- idle
- API 호출 없음
- 결과 목록 없음

검색 중:
- loading
- 이전 결과 즉시 숨김

성공 + 결과 있음:
- loaded

성공 + 결과 없음:
- empty
- “일치하는 수영장이 없습니다”

실패:
- error
- “수영장 검색에 실패했습니다”
- 재시도 제공 가능
- 전체 목록 fallback 금지

━━━━━━━━━━━━━━━━━━━━━━
6. 한글 입력 및 요청 경쟁
━━━━━━━━━━━━━━━━━━━━━━

기존 300ms debounce와 AbortController 구조를 유지한다.

확인:

1. 조합 중인 한글 입력에서 불필요한 전체 목록 노출 없음
2. ‘토’ → ‘토이’ → ‘토이키즈’로 빠르게 입력해도
   이전 ‘토’ 응답이 최신 결과를 덮어쓰지 않음
3. 검색어를 지우면 진행 중 요청 취소
4. 화면 unmount 시 timer clear + abort
5. AbortError는 사용자 오류로 표시하지 않음

━━━━━━━━━━━━━━━━━━━━━━
7. 타입체크 및 테스트
━━━━━━━━━━━━━━━━━━━━━━

필수 테스트:

1. 최초 진입 시 목록 0개
2. API 호출 없음
3. 공백만 입력 시 목록 없음
4. ‘토’ → ‘토’로 시작하는 수영장만 표시
5. ‘토이’ → 결과 축소
6. ‘키즈’ → ‘토이키즈’ 제외
7. 영문 대소문자 무시
8. 결과 없음 UI
9. 네트워크 오류 UI
10. 빠른 입력 race condition 없음
11. 선택 없이 다음 단계 진행 차단
12. 선택 후 검색어 수정 시 기존 선택 해제
13. 전화번호 미노출
14. 상세 주소 미노출
15. 수영장 ID 화면 미노출
16. 학부모 가입 정상 완료
17. 선생님 가입도 동일 검색 컴포넌트를 사용한다면 회귀 없음

타입체크:

- artifacts/api-server/src/routes/pools.ts
- artifacts/swim-app/app/(auth)/signup.tsx

신규 오류 0건 확인.

앱:
- 직전 정상 commit 기준으로 동일 channel에 새 OTA 발행
- update 삭제만으로 롤백 처리하지 않음
