배정 취소 버튼은 표시되지만 실행하면
“권한이 없습니다” 오류가 발생합니다.

현재 teacher 화면에서 관리자 전용 엔드포인트인

PATCH /admin/makeups/:id/revert

를 호출하고 있을 가능성이 높습니다.

버튼이나 Alert를 다시 수정하지 말고,
실제 서버 권한 구조와 라우트를 추적해서 바로잡으세요.

==================================================
1. 오류 원인 확인
==================================================

다음 내용을 실제 코드로 확인하세요.

- PATCH /admin/makeups/:id/revert 라우트 파일
- 해당 라우트의 인증 미들웨어
- 허용 role
- teacher 화면에서 전달되는 JWT role
- tenant_id 또는 center_id 검사
- 해당 보강 건의 담당 선생님 정보
- 실제 서버 응답 status와 response body

“권한 문제 같습니다”라고 추측하지 말고,
어느 조건에서 403이 발생하는지 정확한 코드 줄을 보고하세요.

==================================================
2. 권한 정책
==================================================

보강 배정 취소 권한은 다음과 같이 적용하세요.

관리자:
- 자기 센터의 모든 assigned 보강 취소 가능

선생님:
- 자기 센터 소속이어야 함
- 자신에게 배정된 수업의 보강 건만 취소 가능
- 다른 선생님의 수업은 취소 불가
- completed 상태는 취소 불가
- assigned 상태만 waiting으로 복귀 가능

슈퍼관리자:
- 기존 정책 유지

단순히 teacher 역할 전체에 관리자 API를 개방하지 마세요.
tenant와 담당 수업 소유권을 모두 검사해야 합니다.

==================================================
3. API 구조 결정
==================================================

다음 두 방식 중 현재 프로젝트 구조에 맞는 안전한 방식을 사용하세요.

권장 방식 A:

PATCH /teacher/makeups/:id/revert

선생님 전용 라우트를 만들고,
teacher 인증과 담당 수업 소유권을 검사합니다.

또는 방식 B:

기존 공통 서비스 함수를 분리한 뒤

PATCH /admin/makeups/:id/revert
PATCH /teacher/makeups/:id/revert

두 라우트가 같은 revert 서비스 함수를 사용하게 합니다.

관리자 라우트의 권한 미들웨어를 무작정
admin + teacher로 변경하지 마세요.

==================================================
4. 선생님 소유권 검증
==================================================

선생님이 취소 가능한 조건을 DB에서 확인하세요.

makeup_session:
- id 일치
- tenant_id 또는 center_id 일치
- status = assigned

배정된 수업:
- assigned_class_group_id 또는 실제 연결 필드 확인
- 해당 class_group의 teacher_id가 로그인 teacher id와 일치

프로젝트에서 수업 담당자를 별도 schedule 테이블로 관리한다면
실제 수업 날짜의 담당 선생님을 기준으로 검사하세요.

클라이언트에서 전달한 teacher_id를 신뢰하지 말고
JWT 사용자 정보와 DB 데이터로 확인하세요.

==================================================
5. teacher 화면 API 수정
==================================================

(teacher)/makeups.tsx와
ClassDetailSheet.tsx에서 선생님이 실행하는 배정 취소는
선생님 권한이 허용된 정확한 엔드포인트를 호출하게 수정하세요.

관리자 화면은 기존 admin 엔드포인트를 유지하세요.

사용자 역할에 따라
잘못된 API가 호출되지 않도록 공통 API 함수를 구분하세요.

예:

adminRevertMakeup(id)
teacherRevertMakeup(id)

또는 현재 프로젝트의 API 구조에 맞는 명확한 함수명 사용.

==================================================
6. 오류 메시지 처리
==================================================

403 응답을 모두 단순히
“권한이 없습니다”로만 표시하지 말고
서버 사유에 따라 구분하세요.

- 다른 선생님 수업:
  “담당 수업의 보강만 취소할 수 있습니다.”

- 이미 완료된 보강:
  “완료된 보강은 배정 취소할 수 없습니다.”

- 이미 대기 상태:
  “이미 보강대기 상태입니다.”

- 다른 센터 데이터:
  일반적인 권한 오류 처리

다만 서버 내부 정보나 다른 센터 정보는 노출하지 마세요.

8. 필수 테스트
==================================================

테스트 1:
관리자 계정
→ 자기 센터 assigned 보강 취소 성공

테스트 2:
담당 선생님 계정
→ 자기 수업 assigned 보강 취소 성공

테스트 3:
다른 선생님 계정
→ 타 선생님 수업 취소 실패

테스트 4:
completed 보강
→ 관리자와 선생님 모두 일반 배정 취소 불가

테스트 5:
다른 센터 보강 ID
→ 접근 불가

테스트 6:
선생님 화면에서 취소 성공 후
→ 스케줄에서 제거
→ 배정된 보강에서 제거
→ 보강대기에 표시
