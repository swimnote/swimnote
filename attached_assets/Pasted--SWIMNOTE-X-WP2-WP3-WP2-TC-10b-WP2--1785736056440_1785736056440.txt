* 앱 로그인 후 현재 수영장의 X모드 상태 조회

9. 학부모 자녀 선택 흐름 조사
━━━━━━━━━━━━━━━━━━━━━━

확인:

1. 학부모 홈에서 선택된 자녀 상태를 저장하는 파일

10. Mode 상태 타입 설계
━━━━━━━━━━━━━━━━━━━━━━

WP2 Contract 기준으로 앱 타입을 설계하십시오.

서버 응답:

```typescript
type XModeStatus =
  | "NOT_CONFIGURED"
  | "CURRICULUM_PENDING"
  | "READY";

type PoolMode =
  | "normal"
  | "x_pending"
  | "x";

interface PoolModeResult {
  pool_id: string;
  mode: PoolMode;
  xmode_entitlement: boolean;
  xmode_config_status: XModeStatus;
}
```

앱 전역 상태에는 최소 다음 상태가 필요할 수 있습니다.

```text
idle
loading
ready
error
```

하지만 실제 Repository의 상태 관리 방식에 맞춰 설계하십시오.

임의 상태값을 추가하지 마십시오.

11. Mode Context 책임
━━━━━━━━━━━━━━━━━━━━━━

Mode Context의 책임 후보:

* 현재 pool의 Mode 조회
* mode 결과 저장
* loading/error 관리
* `refreshMode()` 제공
* 로그인 완료 후 최초 조회

* RevenueCat 호출

* Route 이동
* 커리큘럼 조회
* 성장판 조회

12. 서버 상태 조회 실패 정책

* 401
* 403
* 404
* 500
* 네트워크 오류
* 타임아웃

```text

```

일반모드 fallback 여부는 자동 확정하지 말고 다음을 구분하십시오.

* UI 안전 기본값
* 실제 서버 판정값
* 오류 상태

`error`를 숨기고 무조건 `normal`로 저장하는 설계는 금지합니다.

14. API 호출 방식
━━━━━━━━━━━━━━━━━━━━━━

`GET /pools/x-mode` 호출 방식:

```text

```

super_admin:

```text
GET /pools/x-mode?pool_id=<poolId>
```

앱 super_admin 화면에서 어떤 poolId를 사용할지는 현재 선택된 관리 대상 수영장 구조를 조사한 뒤 설계하십시오.

WP3에서 super_admin Mode Context가 실제로 필요한지 구분하십시오.

필요 없다면 일반 앱 사용자 역할만 먼저 처리하는 더 단순한 구조를 제안할 수 있습니다.

구현은 아직 하지 마십시오.

15. 초기 조회 시점
━━━━━━━━━━━━━━━━━━━━━━

다음 후보를 실제 로그인 흐름과 비교하십시오.

* JWT 복원 직후
* 사용자 정보 조회 후
* `/pools/my` 완료 후
* 현재 pool_id 확인 후
* 앱 Navigation 진입 전
* 홈 화면 진입 후

Mode 조회가 pool 확정 전에 실행되면 안 됩니다.

다음 순서를 기본으로 검토하십시오.

```text
인증 복원
→ 사용자·현재 pool 확정
→ Mode 조회
→ 앱 전역 ready
```

다만 기존 앱 초기화 구조를 우선하십시오.

* Pool Context 업데이트

* Navigation reset


이전 pool의 `mode="x"`가 새 일반 pool에 잠시 노출되지 않도록 설계하십시오.

foreground 복귀 시 요구사항:

* 서버 X 상태 재조회
* 30초 캐시 우회 여부
* 중복 호출 방지
* 로그인하지 않은 상태에서는 호출 금지
* 현재 pool 미확정 상태에서는 호출 금지
* 앱이 background에서 짧게 복귀한 경우 과도한 호출 방지 여부

서버 상태 변경은 슈퍼어드민에 의해 언제든 일어날 수 있으므로, foreground 복귀 시 오래된 Mode를 그대로 쓰면 안 됩니다.

다만 호출 빈도를 임의로 추가하지 마십시오.

19. 일반모드 보호
━━━━━━━━━━━━━━━━━━━━━━

WP3 설계에서 반드시 확인:

* Mode Context 추가로 기존 로그인 지연이 생기는지
* Mode 조회 실패로 일반 앱 전체가 차단되는지
* 기존 `/pools/my` 응답 처리 영향
* 기존 Navigation 영향
* 기존 역할 분기 영향
* 기존 부모 자녀 선택 영향
* 기존 앱 캐시 영향
* 일반모드에서 불필요한 X API 반복 호출 여부

WP3는 앱 전역 상태 기반만 만들며, 실제 화면 변경은 WP4까지 하지 않습니다.

20. 테스트 설계
━━━━━━━━━━━━━━━━━━━━━━

최소 테스트:

1. 일반 pool 로그인 → mode=normal
2. entitlement=true + NOT_CONFIGURED → x_pending
3. entitlement=true + CURRICULUM_PENDING → x_pending
4. entitlement=true + READY → x
5. 로그아웃 → mode 초기화
6. pool 전환 → 이전 mode 제거
7. foreground 복귀 → 재조회
8. 401 → 인증 흐름 유지
9. 404 → pool 오류 상태
10. 500 → 이전 X 상태 재사용 금지
11. 네트워크 오류 → error 상태
12. 여러 계정 로그인 전환
13. 여러 수영장 전환
14. parent 자녀 전환
15. parent 다중 pool 가능성
16. React Query cache 제거
17. `_apiCache` 제거
18. WP4가 Context 값만 읽을 수 있는지

실제 pool 상태 변경이나 샘플 생성은 아직 금지합니다.

테스트 fixture 설계만 제출하십시오.
