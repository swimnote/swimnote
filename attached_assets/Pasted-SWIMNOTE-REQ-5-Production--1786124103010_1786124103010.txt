REQ-5 Production 완료.
선생님별 보강 대상 분리 기능은 더 이상 수정하지 않는다.

현재 남은 작업은 정확히 하나다.

"이미 보강 배정/확정된 건에서 날짜 다시 선택 버튼이 다시 정상 작동하도록 복구"

아직 구현하지 말고 Git history + 현재 코드 기준 설계서만 제출한다.

1. 마지막 정상 동작 버전 찾기
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Git history에서 다음 기능이 마지막으로 정상 동작했던 commit을 찾는다.

- 이미 배정된 보강 카드/상세 화면
- "날짜 다시 선택" 버튼 표시
- 버튼 클릭
- 기존 선택 반 유지 또는 기존 정책대로 처리
- 날짜/회차 선택 화면 다시 진입
- 새 날짜 선택
- 보강 일정 업데이트

정확한 commit SHA와 diff를 제출한다.

추측 금지.

6. 기대 UX
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

보강일: 8/20

사용자가 "날짜 다시 선택" 클릭

→ 현재 보강 대상 유지
→ 가능한 회차 목록 다시 표시
→ 현재 정책 -14/+28 범위 사용

→ 목록의 assigned_date 갱신

기존에 반도 다시 선택하게 되어 있던 구조라면
그 기존 정상 UX를 확인해서 보고한다.
임의로 UX 새로 설계하지 않는다.

7. 데이터 무결성 조사
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

날짜 변경 시 서버가 기존 assigned record를:

- UPDATE하는지
- 기존 assignment 취소 후 재assign하는지
- attendance가 이미 생성됐으면 어떻게 처리하는지
- 미래 assigned 상태에서만 가능한지
- completed 상태에서도 버튼이 존재하는지

현재 Repository 실제 코드로 확인한다.

이미 완료된 보강 attendance를 임의로 변경하는 기능이면
별도 위험으로 보고하고 구현 전에 중단한다.
