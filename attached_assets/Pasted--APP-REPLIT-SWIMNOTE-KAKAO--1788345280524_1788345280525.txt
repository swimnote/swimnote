1. 최종 카카오 정책 LOCK
============================================================

카카오 로그인 자체는 정상 복구가 최우선.

기존 연결 사용자:

- teacher 기존 Kakao 연결 계정 → 로그인 허용
- parent 기존 Kakao 연결 계정 → 로그인 허용
- pool_admin 기존 Kakao 연결 계정 → 로그인 허용

절대 기존 연결 사용자를 막지 말 것.

신규 가입 정책만:

ADMIN / pool_admin:
신규 Kakao 가입 및 신규 Kakao 연결 금지.

표시 문구:

"관리자 계정은 PC 모드 연동으로 인해 소셜계정 가입이 불가합니다. 일반 계정으로 가입해 주세요."

TEACHER:
1 Kakao account = 1 SWIMNOTE account.

이미 다른 SWIMNOTE 계정에 연결된 Kakao:
신규 연결 금지.

PARENT:
동일 정책.

중복 Kakao 문구:

"이미 SWIMNOTE 계정에 연결된 카카오 계정입니다. 다른 수영장에 추가 가입하려면 일반가입을 이용해 주세요."

중요:

관리자 차단은
"신규 가입/신규 연결"만 차단.

기존 Kakao 관리자 로그인:
반드시 유지.

vs

vs
"현재 2.0"

목적:

============================================================
3. 1.6.3 / 2.0 CLIENT FLOW를 하나의 정상 계약으로 맞춘다
============================================================

정상 기본 계약:

Kakao button
→ Kakao SDK login()
→ accessToken
→ POST /api/auth/kakao-social-login
→ server validates Kakao user
→ existing account lookup
→ SWIMNOTE JWT/session
→ finishLogin
→ role home

1.6.3과 2.0 모두
이 핵심 로그인 계약이 동일해야 한다.

2.0에서 추가된 정책/UI가
기본 Kakao 로그인 contract를 깨면 안 된다.

12. ERROR HANDLING 개선
============================================================

현재 SDK 예외가 전부:

"카카오 로그인에 실패했습니다."

로 뭉개지는 문제 확인.

이번에는 최소한 내부 진단용으로:

KAKAO_CALLBACK_ERROR
KAKAO_TOKEN_MISSING
KAKAO_NETWORK_ERROR
KAKAO_SERVER_4XX
KAKAO_SERVER_5XX

정도는 구분 가능하게 할 것.

사용자 PII/token은 로그에 출력 금지.

사용자 화면은 지나치게 기술적인 메시지 금지.
