SWIMNOTE — WP-DIARY-1C 긴급 정정
실제 문제 화면을 잘못 수정한 가능성 조사

실기기 증거가 확보됐다.

현재 문제가 발생하는 화면은 일반 DiaryWriteView가 아니다.

화면 제목:
"AI 일지 작성"

하단 버튼:
"수정하기"
"다시 생성"
"일지에 삽입"

즉 AI 생성 결과를 검토/수정하는 모달이다.

실기기 증상:

- 학생별 일지에서 계속 타이핑은 됨
- 입력한 뒷부분은 화면에 보이지 않음
- 커서가 아래로 내려가면서 사라짐
- 학생 카드/TextInput 높이는 늘어나지 않음
- 전체일지는 긴 내용이 정상적으로 보임

중요:
WP-DIARY-1 / 1B에서 수정했던

DiaryWriteView.tsx
DiaryEditView.tsx

가 실제 문제 화면인지 먼저 재검증한다.

현재 캡처의 AI 일지 작성 모달과 직접 연결되지 않는다면
이전 두 수정은 문제 지점을 잘못 잡은 것이다.

추측 금지.

3. 전체일지와 학생별일지 비교
━━━━━━━━━━━━━━━━━━━━

같은 "AI 일지 작성" 모달 안에서

전체일지 표시/편집 영역

vs

학생별 일지 표시/편집 영역

을 직접 비교한다.

사용자 요구:

전체일지가 긴 내용에서 정상적으로 늘어나는 것과
완전히 동일한 사용자 경험을
학생별 일지에도 적용.

다른 화면의 전체일지와 비교하지 않는다.

반드시 같은 AI 결과 모달 내부의
전체/개별 구현을 비교한다.

━━━━━━━━━━━━━━━━━━━━
4. 현재 실기기 증상으로 판별
━━━━━━━━━━━━━━━━━━━━

현재 확인된 사실:

텍스트 입력 자체는 계속 된다.

따라서 AI content truncation 문제가 아님.

문제는:

입력 내용 높이 > 실제 보이는 TextInput/card 높이

상태에서 발생하는 것으로 보인다.

다만 정확한 원인은 코드 증거로 확정.

확인:

A. TextInput 자체 높이가 고정
B. TextInput은 늘지만 parent가 잘라냄
C. 내부 scroll이 발생하지만 cursor 추적이 안 됨
D. 다른 layout 제한

중 하나를 확정.

━━━━━━━━━━━━━━━━━━━━
