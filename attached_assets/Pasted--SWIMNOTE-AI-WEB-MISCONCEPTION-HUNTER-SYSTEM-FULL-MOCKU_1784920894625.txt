==================================================
0. 작업 목적
==================================================

현재 SWIMNOTE AI 웹 관리자 시스템에
‘비근거·미신 수영 데이터 수집장치’를 신규 핵심 메뉴로 추가한다.

현재 단계에서는 자동 크롤링, 완전 자동 검증, DTA 계산,
영상분석 연동이 실제로 모두 동작할 필요는 없다.

그러나 향후 구현할 전체 기능 구조가 사라지지 않도록
실제 제품 화면 수준의 풀세팅 목업을 구현한다.

단순한 설명 페이지나 빈 Placeholder를 만들지 않는다.

각 메뉴마다:

- 기능 설명
- 데이터 흐름
- 상태 카드
- 검색·필터
- 목록
- 상세 패널
- 검증 단계
- 실행 버튼
- 향후 기능 버튼
- 준비중 상태
- 예시 데이터
- 관리자 승인 흐름

을 실제 서비스처럼 구성한다.

현재 구현 가능한 기능은 실제 동작시키고,
아직 구현하지 않는 기능은 명확한 ‘준비 중’ 상태로 표시한다.

이 시스템은 향후 다음 엔진으로 발전한다.

사용자 질문 수집
→ 외부 확장검색
→ 비근거 주장 발견
→ 자동 크롤링
→ 출처 추적
→ DTA·물리·수학 검증
→ 관리자 승인
→ Knowledge DB 반영
→ 영상분석 및 교정 결과 연결
→ 스스로 성장하는 자동사냥 시스템

- 상태 변경
- 메모 입력
- 태그 입력
- 예시 데이터 조회

목록 컬럼:

- 주장 ID

필터:

- 영법
- 기술

- 외부 검색 사용 여부

예시 데이터:

접영은 큰 웨이브를 만들어야 한다.
자유형은 팔로 물을 뒤로 세게 밀수록 빨라진다.
평영은 무릎을 최대한 벌려야 추진력이 커진다.
배영은 귀에 물이 들어가면 머리를 더 들어야 한다.
접영 입수킥과 출수킥은 공식 기술 용어다.
캐치는 물을 강하게 움켜쥐는 동작이다.
호흡 때 머리를 높이 들수록 공기를 많이 마신다.
스트로크 수가 적을수록 무조건 효율적이다.

행 클릭 시 우측 상세 패널 또는 상세 페이지를 연다.

6. 검증 워크벤치
==================================================

하나의 주장을 단계별로 검증하는 화면을 만든다.

좌측:

검증 대상 주장 목록

중앙:

현재 검증 단계

우측:

판정 요약 및 최종 결정

검증 단계:

STEP 1
주장 분해

STEP 2
내부 DB 비교

STEP 3
공식 자료 확인

STEP 4
연구·전문서적 확인

STEP 5
출처 독립성 확인

STEP 6
용어 검증

STEP 7
물리·생체역학 검증

STEP 8
DTA 검증

STEP 9
적용 범위 검증

STEP 10
최종 판정

각 단계에 체크박스와 입력란을 제공한다.

예:

공식 자료에서 확인됨
연구자료에서 확인됨
전문서적에서 확인됨
일반 웹에서만 반복됨
독립된 원출처 확인
용어 혼동 있음
결과와 원인 혼동
물리법칙 충돌
DTA 손실 가능
특정 대상에만 적용 가능

최종 판정 선택:

VERIFIED
SUPPORTED
CONDITIONAL
TERMINOLOGY_ONLY
UNSUPPORTED
DISPUTED
REJECTED
HARMFUL
PENDING
REVIEW_REQUIRED

검증 요약 자동생성 버튼을 배치한다.

현재 실제 GPT 연결이 가능하면 생성 기능을 연결하고,
불가능하면 목업 텍스트를 생성한다.

8. DTA 검증실
==================================================

DTA를 별도 탭으로 명확히 보여준다.

페이지 제목:

DTA Claim Verification Lab

상단 설명:

주장의 효율성을 Direction, Timing, Advance와
기본 물리법칙으로 검증합니다.

검증 카드:

Direction

- 힘의 방향
- 전진 방향 정렬
- 상하 손실
- 좌우 손실
- 정면 면적 변화
- 자세 정렬

Timing

- 추진 발생 시점
- 팔·킥 연결
- 호흡 개입
- 추진 공백
- 추진 중첩
- 속도변동

Advance

- 스트로크당 거리
- 주기당 순전진
- 평균속도
- 감속 구간
- 저항 대비 이득
- 에너지 대비 이동거리

물리 검증 카드:

- F = ma
- 작용·반작용
- 운동량
- 충격량
- 저항
- 부력
- 중력
- 신체 중심
- 주기 내 속도변동
- 에너지 효율

각 항목에 다음 입력을 제공한다.

- 판정
- 근거
- 측정 가능 여부
- 직접 측정 / 계산 / 추정 / 추론
- 신뢰도
- 메모

판정:

PASS
CONDITIONAL
FAIL
NOT_ENOUGH_DATA

하단:

DTA 종합 판정
과학적 반증 요약
SWIMNOTE 대체 설명

현재 자동 계산은 목업으로 두되,
사용자가 수동으로 값을 입력하고 저장할 수 있게 한다.

14. 예시 데이터
==================================================

시스템이 빈 화면으로 보이지 않게
최소 12개의 예시 주장을 등록한다.

예시:

1. 접영은 큰 웨이브를 만들어야 한다.
2. 접영의 핵심은 머리부터 발끝까지 파동을 전달하는 것이다.
3. 자유형은 팔로 물을 세게 밀수록 빨라진다.
4. 캐치는 물을 움켜쥐는 동작이다.
5. 평영킥은 무릎을 최대한 벌려야 한다.
6. 배영은 머리를 들면 물이 덜 들어온다.
7. 호흡할 때 머리를 높이 들수록 공기를 많이 마신다.
8. 스트로크 수가 적을수록 무조건 효율적이다.
9. 물을 오래 미는 것이 항상 좋다.
10. 입수킥과 출수킥은 국제 공식 기술용어다.
11. 어린이는 무조건 발차기부터 많이 시켜야 한다.
12. 선수 자세를 그대로 따라 하면 가장 빠르게 배운다.

각 예시에는:

- 유형
- 임시 상태
- 영법
- 반복 횟수
- 검증 요약
- SWIMNOTE 입장
- 예상 오류
- DTA 손실

을 넣는다.

- 기존 SWIMNOTE 판정을 자동 변경하지 않는다.

18. 완료 조건
==================================================

다음이 실제 Production 웹에서 확인되어야 완료다.

1. 사이드바에 Misconception Hunter 메뉴가 보인다.
2. 모든 하위 메뉴에 정상 진입된다.
3. 예시 데이터가 표시된다.
4. 주장 목록 검색과 필터가 동작한다.
5. 주장 상세 화면이 열린다.
6. 상태와 메모를 수정할 수 있다.
7. 검증 워크벤치 화면이 구현된다.
8. DTA 검증실이 구현된다.
9. 자동사냥 설정 화면이 구현된다.
10. 오류·원인 연결 화면이 구현된다.
11. 영상분석 연결 화면이 구현된다.
12. 준비중 버튼이 설명 모달을 연다.
13. 시스템 설계도에 전체 장기 구조가 기록되어 있다.
14. 기존 웹 기능이 그대로 정상 작동한다.
15. 실제 앱을 직접 실행하고 전체 메뉴를 클릭해 검증한다.
16. 실제 웹 화면 스크린샷을 제출한다.
17. API 응답만으로 완료 처리하지 않는다.
18. 실제 화면과 저장 결과를 증거로 제출한다.
