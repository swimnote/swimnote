SWIMNOTE 보강 날짜 범위 수정 — Production 최종 배포

현재 검수 완료.

다음 순서대로 진행한다.

1. GitHub Push
2. Render 서버 자동 배포 완료까지 대기
3. GET /api/health 정상 확인
4. Production OTA 배포
5. OTA Update Group ID 제출
6. runtimeVersion 제출
7. updateId 제출
8. bundle SHA 제출
9. git status 제출
10. 변경 파일 목록 제출

그 후 중단한다.

실기기에서 내가 아래 항목을 직접 검증한다.

- 이월 보강
- 당월 보강
- 선보강(결석 전 보강)
- 오늘 날짜 보강
- 관리자 오류 Alert
- 날짜 선택 범위(오늘 기준 -14일 ~ +28일)

추가 코드 수정은 하지 않는다.

이후 OTA를 받은 앱으로 직접 테스트해 보면 이번 수정이 의도대로 동작하는지 바로 확인할 수 있습니다.

그러면 안전하게 니가 말하는대로가자

좋습니다. 그 순서가 가장 안전합니다.
