[Instagram Story Pipeline 실기기 진단 OTA — 실패 Stage 직접 확정]

현재 상황:

- Summary API 정상화 완료
- Story Summary fit 정상
- "이미지 생성 중..." Modal까지 진입
- 잠시 후 Modal 종료
- Instagram Story Composer 미진입

직전 감리에서는 META_APP_ID 빈값 가능성을 제기했으나
Expo SDK 55 공식 동작상
eas update --environment preview 사용 시
EAS preview environment 변수가 번들에 사용된다.

현재 EAS preview에는:

EXPO_PUBLIC_META_APP_ID=2093655621362240

정상 등록되어 있음.

따라서 .env 수정 금지.

이번 단계에서는 StoryCapturePipeline 내부에
실기기 진단 Stage만 추가하고
instagram-test에 진단 OTA를 배포한다.

2. StoryCapturePipeline Stage 추가
━━━━━━━━━━━━━━━━━━━━━━

다음 Stage를 실제 코드에 기록한다.

P0 = Pipeline mount

P1 = Renderer ref 확인 성공

P2 = captureRef 시작

P3 = captureRef 성공

P4 = capture URI 존재

P5 = finalize 진입

P6 = META_APP_ID 검사

P7 = META_APP_ID 존재 확인

P8 = Share.shareSingle 직전

P9 = Share.shareSingle 호출

P10 = Share Promise resolve

P11 = cleanup

P12 = onDone

PX = catch

각 Stage는 ref/state 변수 하나로 추적.

공유 로직 자체는 변경하지 않는다.

━━━━━━━━━━━━━━━━━━━━━━
3. META_APP_ID 실제 런타임 값 검증
━━━━━━━━━━━━━━━━━━━━━━

P6에서 실제:

const hasMetaAppId =
  typeof META_APP_ID === "string" &&
  META_APP_ID.length > 0;

만 확인.

Alert에는 App ID 실제 숫자를 노출하지 않는다.

표시:

meta=true

또는

meta=false

만 사용.

━━━━━━━━━━━━━━━━━━━━━━
4. capture 결과 검증
━━━━━━━━━━━━━━━━━━━━━━

captureRef 성공 후 다음만 확인:

uriExists=true/false

가능하면 expo-file-system 현재 API를 이용해
파일 존재 여부와 size를 READ-ONLY 확인.

단 이 확인 때문에 공유 동작이 실패하게 만들지 않는다.

파일 검사 API 사용이 현재 설치 버전과 충돌할 가능성이 있으면
새 라이브러리 추가 금지하고 URI 존재만 확인.

개인 파일 전체 경로는 Alert에 표시하지 않는다.

━━━━━━━━━━━━━━━━━━━━━━
5. Share 결과 진단
━━━━━━━━━━━━━━━━━━━━━━

Share.shareSingle 직전에:

stage=P8

호출 직후:

stage=P9

Promise resolve:

stage=P10

catch:

stage=PX
error=<sanitized message>

Share cancel과 error가 구분 가능한 현재
react-native-share 반환값이 있다면 결과 타입도 기록.

공유 API behavior 자체는 변경하지 않는다.

━━━━━━━━━━━━━━━━━━━━━━
6. 진단 Alert 표시 방식
━━━━━━━━━━━━━━━━━━━━━━

현재처럼 Modal unmount와 Alert가 경쟁해서
Alert가 사라질 수 있으므로
Pipeline 종료 후 Parent 화면에서 진단값을 표시할 수 있게 한다.

권장:

StoryCapturePipeline
→ onDone(result)

result 예:

{
  stage: "P7",
  meta: true,
  uriExists: true,
  shareResult: "unknown",
  error: null
}

Parent home.tsx가 Pipeline unmount 후
진단 Alert를 표시한다.

중요:
진단 Alert를 Pipeline Modal 내부에서 띄운 직후
onDone 하지 않는다.

그래야 iOS Modal dismiss와 Alert가 같이 사라지는 문제를 피할 수 있다.

이번 진단 버전에서만 사용.

━━━━━━━━━━━━━━━━━━━━━━
7. 기존 !META_APP_ID 분기
━━━━━━━━━━━━━━━━━━━━━━

기존 동작은 변경하지 않는다.

단 해당 분기를 타면 결과로:

stage=P6
meta=false
reason=missing_meta_app_id

를 parent에 전달하고 종료.

Alert는 parent 화면에서 Modal unmount 후 표시.

8. Photo load 관련 기록
━━━━━━━━━━━━━━━━━━━━━━

현재 photo onLoad 대기가 없다는 부가 문제가 있으므로
이번에는 수정하지 않고 값만 기록한다.

가능하다면 StoryPageRenderer에서:

12. 최종 성공/실패 판정
━━━━━━━━━━━━━━━━━━━━━━

CASE A:

stage=P6
meta=false

→ OTA bundle META_APP_ID 문제 확정.

CASE B:

stage=P7/P8
meta=true
uriExists=false

→ capture URI/file 문제.

CASE C:

stage=P9/PX
meta=true
uriExists=true

→ react-native-share 호출 단계 실패.

CASE D:

stage=P10
meta=true
uriExists=true
Instagram 미진입

→ Share Promise는 resolve하지만
Instagram handoff 문제.

CASE E:

Instagram 진입 + 이미지 일부 없음

→ photo loading/capture timing 문제 별도 조사.
