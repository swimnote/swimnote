4. FILE LOSS 관점
━━━━━━━━━━━━━━━━━━━━━━

특히 찾을 것:

A.
DB row는 있는데 R2 object 없음

B.
R2 object는 있는데 DB reference 없음

C.
재업로드가 overwrite

D.
delete/update에서 과거 원본 삭제

E.
parse 실패 시 원본까지 사라짐

F.
processing 실패 시 upload 자체 rollback

G.
pool 탈퇴/비활성화 시 원본 삭제

H.
Super Admin에서 source 추적 불가능

I.
파일 key가 pool 간 충돌 가능

J.
version race condition

5. 현재 R2 BACKUP 한계
━━━━━━━━━━━━━━━━━━━━━━

중요.

현재 전체 시스템에서
DB daily backup은 존재하지만
R2 originals는 별도 backup/recovery guarantee가 없는 것으로 알고 있다.

이번 감사에서 정확히 확인:

- R2 bucket versioning 여부
- object lifecycle rule
- delete protection
- accidental overwrite protection
- provider redundancy
- 별도 backup bucket 존재 여부
- restore 방법
- 현재 "원본 절대 유실 방지" 수준을 실제로 만족하는지

추측 금지.

현재 구조가 단순히
"R2에 저장돼 있으니 안전"
수준이면 PASS 금지.
