# Replit 검토 요청 (구현 가능성 평가)

현재 SWIMNOTE 앱의 AI 기능 방향을 확정하기 전에, 아래 구조가 현재 코드베이스에서 안정적으로 구현 가능한지 먼저 기술 검토를 부탁드립니다.

※ 이번 작업은 절대 코드 수정이나 구현을 하지 말고, 구조 검토 및 구현 가능성 평가만 진행해주세요.

--------------------------------------------------
[AI 설계 목표]
--------------------------------------------------

AI는 기존 앱을 대체하지 않습니다.

기존 기능은 그대로 유지하고,

기존 화면 위에 AI 레이어만 추가하는 구조입니다.

즉,

AI를 사용하지 않는 경우에는 현재 앱과 완전히 동일하게 동작해야 합니다.

AI 관련 코드가 기존 기능에 영향을 주면 안 됩니다.

--------------------------------------------------
[공통 AI 구조]
--------------------------------------------------

모든 AI 기능은 동일한 Base AI Modal을 사용합니다.

예)

- 선생님 AI 일지
- 학부모 AI 상담
- 영상분석 AI
- 기타 AI 기능

모두 동일한 AI 레이어를 사용합니다.

기능마다 다른 것은 Context Builder뿐입니다.

--------------------------------------------------
[AI 처리 흐름]
--------------------------------------------------

사용자

↓

AI 모달 실행

↓

질문 또는 음성 입력

↓

Context Builder

↓

AI

↓

결과 생성

↓

기존 화면(state)에 자동 적용

↓

기존 저장 버튼

AI는 저장하지 않습니다.

AI는 기존 state만 자동으로 채웁니다.

--------------------------------------------------
[선생님 AI]
--------------------------------------------------

AI는

- 공통 일지
- 학생별 일지

를 자동 작성합니다.

학생 개인정보는 AI에 전달하지 않습니다.

AI에는

student_id

(예)

100
101
102

같은 내부 ID만 전달합니다.

AI도 student_id 기준으로 결과를 반환합니다.

앱에서

student_id

↓

학생 이름

으로 매핑합니다.

--------------------------------------------------
[학부모 AI]
--------------------------------------------------

학부모 AI는 일반 챗봇이 아닙니다.

질문을 받으면 먼저 학생 정보를 자동 수집합니다.

예)

- 학생 기본정보
- 현재 진도
- 교재 진행도
- 최근 수업
- 최근 일지
- 반복 피드백
- AI Memory

등

질문의 목적에 필요한 정보만 선택적으로 수집합니다.

그 후

학생 Context

+

학부모 질문

을 합쳐 AI에 전달합니다.

--------------------------------------------------
[정보 부족 시 처리]
--------------------------------------------------

정보가 없는 경우

없는 정보를 절대 추측하면 안 됩니다.

예)

가입 직후

↓

이름만 있음

↓

이름만 이용

↓

일반적인 답변

정보가 있는 경우

↓

있는 정보만 사용

↓

질문 목적에 맞는 Context 생성

↓

답변

--------------------------------------------------
[자동화]
--------------------------------------------------

모든 AI는

모달이 떠있는 동안

Context를 생성하고

AI가 동작합니다.

AI 완료 후

기존 화면(state)에 자동 적용됩니다.

즉

AI가 화면을 대체하는 것이 아니라

기존 화면을 자동 작성해주는 구조입니다.

--------------------------------------------------
[기존 시스템 유지 원칙]
--------------------------------------------------

반드시 아래 원칙을 유지할 수 있는지 검토해주세요.

1.
AI를 사용하지 않으면
현재 앱과 100% 동일하게 동작하는가?

2.
기존 저장 로직
(handleSave / handleEditSave)
수정 없이 가능한가?

3.
기존 API 수정 없이 가능한가?

4.
기존 state를 그대로 사용할 수 있는가?

5.
AI 관련 코드 제거 시
기존 기능이 그대로 동작하는가?

6.
AI 기능이 기존 기능에 영향을 주지 않는 구조가 가능한가?

--------------------------------------------------
[검토 요청]
--------------------------------------------------

구현하지 말고 기술 검토만 진행해주세요.

다음 항목을 각각 평가해주세요.

① 현재 구조에서 구현 가능 여부

② 필요한 구조 변경

③ 구조상 어려운 부분

④ 더 좋은 설계 제안

⑤ 장기 유지보수 관점 추천 구조

⑥ 성능 및 확장성 문제

⑦ 예상 위험 요소

⑧ 현재 코드 기준으로 추천하는 아키텍처

※ 코드 수정은 하지 않습니다.
※ 구현도 하지 않습니다.
※ 현재 SWIMNOTE 코드베이스에서 이 AI 아키텍처를 안정적으로 구현할 수 있는지 기술 검토 및 설계 평가만 진행해주세요.
