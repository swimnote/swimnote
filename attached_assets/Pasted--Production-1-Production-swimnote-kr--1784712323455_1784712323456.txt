# 보호자 전화번호 기능 Production 반영 및 안전 검증 지시문

현재 확인된 핵심 원인은 다음과 같습니다.

1. Production 서버(swimnote.kr)에
   PATCH /students/:id/parent-phones
   엔드포인트가 배포되지 않음

2. 앱이 HTML SPA fallback 응답을 JSON으로 파싱하면서
   네트워크 오류로 잘못 표시함

3. 앱 오류 처리와 rollback 코드는 수정 완료

4. DB에는 parent_phone2 기준 8자리 전화번호가 20건 이상 존재

이번 작업은 다음 순서로 진행하세요.

==================================================
1. Production 서버 재배포
==================================================

Replit Production 서버를 재배포하세요.

목적:

- PATCH /students/:id/parent-phones 활성화
- GET /admin/students/:id/detail의 parents 배열 반영
- 보호자 전화번호 추가·수정·삭제 API 반영
- 자동 연결·해제 로직 반영

재배포 후 반드시 실제 Production URL로 확인하세요.

테스트:

PATCH https://swimnote.kr/api/students/{유효한학생ID}/parent-phones

인증 없이 호출한 경우 기대 결과:

- HTML 200이 나오면 실패
- JSON 형식의 401 또는 403이 나오면 라우트 활성화 성공

반드시 Content-Type도 확인하세요.

기대값:

application/json

text/html이 나오면 아직 Production 라우트가 반영되지 않은 것입니다.

3. Production API 배포 후 코드 검증
==================================================

Production 재배포 후 다음을 확인하세요.

1.
PATCH 엔드포인트가 JSON 응답을 반환하는지

2.
인증된 요청에서 보호자 2 전화번호 저장이 가능한지

3.
저장 후 students.parent_phone2 값이 정상적으로 갱신되는지

4.
보호자 1 parent_phone 값은 변경되지 않는지

5.
같은 학생 안에서 동일 번호 중복 저장이 차단되는지

6.
전화번호가 하이픈 없이 숫자 문자열로 저장되는지

7.
저장 후 상세 조회에서 새 번호가 반환되는지

8.
연결된 학부모 계정이 있으면 연결됨 상태로 표시되는지

9.
가입 계정이 없으면 가입 대기 상태로 표시되는지

실제 계정 인증이 불가능한 항목은
'실기기 검증 필요'로 명시하세요.

==================================================
4. 8자리 전화번호 DB 일괄 수정 금지
==================================================

현재 8자리 전화번호에 바로 '010'을 붙이는 UPDATE는 실행하지 마세요.

다음 SQL과 같은 일괄 수정은 아직 금지합니다.

UPDATE students
SET parent_phone2 = '010' || parent_phone2
WHERE length(parent_phone2) = 8;

8자리 값이 모두 실제 휴대전화 뒷자리라는 보장이 없기 때문입니다.

먼저 읽기 전용 조회만 수행하세요.

조회 대상:

- student id
- 학생 이름
- center 또는 tenant
- parent_phone
- parent_phone2
- parent_phone3
- 각 보호자 연결 상태
- 연결된 parent 계정 전화번호
- 등록일 또는 수정일

8자리 번호 전체 목록을 보고하세요.

==================================================
5. 8자리 번호 자동 검증
==================================================

각 8자리 번호에 대해 다음을 비교하세요.

예:

parent_phone2 = 62102386

후보 번호:

01062102386

확인 기준:

1.
해당 번호와 일치하는 학부모 계정이 존재하는지

2.
같은 학생에 이미 연결된 parent 계정의 전화번호와 일치하는지

3.
동일 센터 내 다른 학생의 보호자 번호와 일치하는지

4.
형제자매 학생에서 같은 후보 번호가 반복되는지

5.
후보 번호를 추가했을 때 다른 보호자 번호와 중복되는지

6.
다른 센터 데이터와 잘못 연결될 가능성이 없는지

분류 결과를 다음처럼 보고하세요.

- 자동 수정 안전
- 수동 확인 필요
- 중복 위험
- 계정 매칭 확인
- 판단 불가

==================================================
6. DB 수정 정책
==================================================

다음 조건을 모두 만족하는 번호만 자동 수정 후보로 분류하세요.

- 정확히 숫자 8자리
- 앞에 010을 붙인 11자리 번호가 유효한 형식
- 같은 학생의 다른 보호자 번호와 중복되지 않음
- 연결된 학부모 계정 전화번호와 일치하거나
  동일 가족 관계를 코드상 확인할 수 있음
- 다른 센터의 무관한 계정과 충돌하지 않음

계정 매칭이나 가족 관계 근거가 없는 경우
자동 수정하지 마세요.

그 경우 학생별 수동 확인 목록으로 남기세요.
