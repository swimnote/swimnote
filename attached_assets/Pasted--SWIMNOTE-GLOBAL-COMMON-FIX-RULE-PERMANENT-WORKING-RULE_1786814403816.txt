[SWIMNOTE GLOBAL COMMON-FIX RULE — PERMANENT WORKING RULE]

앞으로 SWIMNOTE 앱 수정 작업은
특별히 "X모드 전용 수정"이라고 명시된 경우를 제외하면
기본적으로 Normal SWIMNOTE + SWIMNOTE X 공통 기능 수정으로 처리한다.

==================================================
1. 기본 원칙
==================================================

먼저 해당 기능이 Normal SWIMNOTE와 SWIMNOTE X에서

- 동일 screen
- 동일 component
- 동일 route
- 동일 API
- 동일 shared primitive
- 동일 source of truth

를 공유하는지 확인한다.

==================================================
2. 공통 구조인 경우
==================================================

Normal/X가 동일 source를 공유하면:

- source of truth 한 곳만 수정
- 같은 코드를 양쪽에 중복 수정하지 않음
- 수정 후 Normal/X 양쪽에서 회귀검증

즉:

ONE SOURCE FIX
+
BOTH MODE VERIFICATION

원칙.

==================================================
3. 분기 구현인 경우
==================================================

mode === "x"
mode === "normal"
XModeGuard
별도 X component
별도 X route

등으로 구현이 분리되어 있으면:

1. Normal에서 동일 버그 존재 여부 확인
2. X에서 동일 버그 존재 여부 확인
3. 실제 문제가 있는 분기만 수정
4. 불필요하게 양쪽 코드를 동시에 변경하지 않음

==================================================
4. 특별히 X 전용으로 처리할 경우
==================================================

다음과 같이 명확히 X 전용인 작업만
X 범위로 제한한다.

예:

- X 전용 AI 기능
- X entitlement
- X config
- X setup
- X Growth
- X Steel Blue identity
- X 결제/가맹
- X 전용 커리큘럼
- X 전용 권한

그 외 공통 화면/기능 버그는
Normal/X 공통으로 본다.

==================================================
5. 공통 기능 예시
==================================================

다음과 같은 기능은 기본적으로 공통 여부를 먼저 확인한다.

- 공통 텍스트

==================================================
6. UI / BUG FIX
==================================================

공통 UI 버그 수정 시:

Normal만 고치고 X 확인을 생략하거나,
X만 고치고 Normal 확인을 생략하지 않는다.

반드시 보고:

NORMAL RESULT
X RESULT

둘 다 확인.

==================================================
7. API / SERVER
==================================================

동일 서버 route/API를 Normal/X가 공유하면
API 한 곳만 수정.

단 수정 전:

Normal 호출 경로
X 호출 경로

둘 다 같은 contract를 사용하는지 확인.

==================================================
8. 중복 구현 금지
==================================================

공통 문제를 해결하기 위해:

Normal용 새 component
X용 새 component

를 각각 만드는 방식 금지.

기존 shared component를 수정할 수 있으면
shared source를 우선한다.

==================================================
9. 회귀검증
==================================================

특별히 X 전용 작업이 아닌 경우
최종 검증에 항상 포함:

1. NORMAL SWIMNOTE
2. SWIMNOTE X
3. mode 분기에 따른 차이 없는지
4. 기존 기능 contract 유지
5. X 때문에 Normal regression 없음
6. Normal 수정 때문에 X regression 없음

==================================================
10. 지시문 작성 규칙
==================================================

앞으로 모든 작업 지시문에는
특별히 X 전용이 아닌 경우 다음 원칙을 자동 적용한다:

"본 작업은 Normal SWIMNOTE와 SWIMNOTE X 공통 기능으로 간주한다.
먼저 양쪽이 동일 source/component/route를 공유하는지 확인한다.
공통 구조라면 source of truth 한 곳만 수정하고 Normal/X 양쪽을 검증한다.
분기 구현이면 양쪽에서 동일 문제가 존재하는지 확인하고 필요한 범위만 각각 수정한다.
불필요한 중복 수정은 금지한다."

==================================================
11. REPORT
==================================================

공통 수정 완료 보고에는 가능하면 다음 포함:

1. SHARED SOURCE?
2. NORMAL PATH
3. X PATH
4. MODIFIED SOURCE
5. NORMAL RESULT
6. X RESULT
7. DUPLICATE CHANGE?
8. BUSINESS LOGIC CHANGE?
9. DB/API CHANGE?
10. TEST RESULT

이 규칙을 앞으로 SWIMNOTE 개발의 기본 수정 원칙으로 사용한다.
