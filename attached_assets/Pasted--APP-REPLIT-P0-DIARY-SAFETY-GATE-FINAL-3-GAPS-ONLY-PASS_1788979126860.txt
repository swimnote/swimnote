1. LEGACY TRACE SCOPE BYPASS 제거
━━━━━━━━━━━━━━━━━━━━━━

현재:

ai_request_id 존재
+
event_logs trace 존재
+
trace metadata에 class_id / lesson_date / student_ids 없음

→ warning 후 scope binding skip

이 동작 금지.

앞으로 새로운 POST /diaries 요청에서는:

AI request_id가 존재하는데
필수 scope를 검증할 수 없으면

409 AI_TRACE_SCOPE_UNVERIFIED

로 저장 거부.

이미 DB에 저장된 과거 diary는 영향 없음.
기존 row migration 필요 없음.

manual diary(ai_request_id 없음)는 기존대로 정상 저장.

필수 AI trace scope:

- pool_id
- teacher_id
- class_id
- lesson_date
- student_ids[]

2. TEACHER SCOPE LOCK
━━━━━━━━━━━━━━━━━━━━━━

AI trace durable scope에 teacher_id를 확실히 저장.

generate 당시 authenticated teacher id 사용.

POST /diaries 저장 시:

authenticated user.id
===
trace.teacher_id

검증.

다르면:

409 DIARY_TEACHER_SCOPE_MISMATCH

저장 금지.

반드시 실제 테스트:

Teacher A
→ same pool에서 AI generate
→ request_id 생성

Teacher B
→ SAME POOL
→ Teacher A request_id로 diary save 시도

기대:
409 DIARY_TEACHER_SCOPE_MISMATCH

pool mismatch로 대신 테스트하지 말 것.
