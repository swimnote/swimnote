[긴급 수정 — Teacher Diary 응답 Contract 불일치]

원인이 확정되었습니다.

AI Engine 생성은 정상이며 HTTP 200 JSON을 반환합니다.
앱이 응답 구조를 잘못 읽어서 “응답 형식 오류”가 발생합니다.

현재 앱 호출 경로:
POST /api/ai/diary/generate

현재 실제 응답:
{
  "schema_version": "1.0",
  "request_id": "...",
  "feature": "teacher_diary",
  "result": {
    "common": "...",
    "students": [
      {
        "student_ref": "...",
        "content": "..."
      }
    ]
  },
  "usage": {}
}

하지만 diary.tsx 또는 관련 타입은 다음 구형 구조를 기대하고 있습니다.

- response.common
- response.students
- students[].student_id
- response.status
- response.warnings

그 결과 undefined.trim(), undefined.length 오류가 발생합니다.

━━━━━━━━━━━━━━━━━━━━
1. 정식 Endpoint로 복구
━━━━━━━━━━━━━━━━━━━━

Teacher Diary grounded 모드는 반드시 다음 정식 V1 API를 호출하십시오.

POST /api/v1/teacher-diary/generate

환경변수 확인:

EXPO_PUBLIC_SWIMNOTE_AI_MODE=grounded
EXPO_PUBLIC_SWIMNOTE_AI_DIARY_PATH=/api/v1/teacher-diary/generate

앱이 실제 실행 시 /api/ai/diary/generate를 호출하는 원인을 추적하십시오.

확인 대상:

- TeacherDiaryAIClient
- DiaryAIService
- GROUNDED_PATH
- EXPO_PUBLIC_SWIMNOTE_AI_DIARY_PATH
- Production OTA에 baked-in 된 환경변수
- legacy/grounded feature flag 분기

grounded 모드에서 legacy 경로로 자동 우회하지 마십시오.

━━━━━━━━━━━━━━━━━━━━
2. 응답은 Service에서 정규화
━━━━━━━━━━━━━━━━━━━━

diary.tsx 화면에서 서버 원문을 직접 읽지 마십시오.

DiaryAIService.normalizeDiaryResponse()에서 아래처럼 변환하십시오.

서버:

{
  "result": {
    "common": "...",
    "students": [
      {
        "student_ref": "s001",
        "content": "..."
      }
    ]
  }
}

앱 내부 표준형:

{
  "commonContent": "...",
  "studentNotes": [
    {
      "studentId": "s001",
      "content": "..."
    }
  ]
}

매핑:

response.result.common
→ commonContent

response.result.students[].student_ref
→ studentId

response.result.students[].content
→ content

화면 컴포넌트는 정규화된 앱 내부 구조만 사용하게 하십시오.

━━━━━━━━━━━━━━━━━━━━
3. 구형 필드 의존 제거
━━━━━━━━━━━━━━━━━━━━

다음 직접 접근을 제거하십시오.

response.common
response.students
student.student_id
response.status
response.warnings

V1 Contract에 없는 status와 warnings를 필수값으로 취급하지 마십시오.

warnings가 필요하면 기본값 []로 정규화하십시오.

status가 필요하면 HTTP status 또는 앱 내부 상태로 관리하십시오.

절대 다음처럼 undefined 필드를 바로 사용하지 마십시오.

response.common.trim()
response.warnings.length
response.students.length

정규화와 타입 검증 후에만 렌더링하십시오.

━━━━━━━━━━━━━━━━━━━━
4. 임시 호환 범위
━━━━━━━━━━━━━━━━━━━━

운영 복구를 위해 normalizeDiaryResponse에서 아래 두 구조를 잠시 모두 읽을 수 있습니다.

신형 우선:
response.result.common
response.result.students[].student_ref

구형 보조:
response.common
response.students[].student_id

단:

- grounded V1 성공 응답은 신형 Contract로만 처리
- legacy 호환은 명시적 legacy 모드에서만 허용
- 신형 응답 실패 시 조용히 구형으로 위장하지 않음
- 실제 사용된 pipeline_mode를 로그에 기록

━━━━━━━━━━━━━━━━━━━━
5. 필수 테스트
━━━━━━━━━━━━━━━━━━━━

A. /api/v1/teacher-diary/generate 실제 호출 확인

B. HTTP 200 응답에서
result.common 정상 추출

C. result.students[].student_ref 정상 매핑

D. common이 빈 문자열이어도 TypeError 없음

E. students가 빈 배열이어도 TypeError 없음

F. status/warnings가 없어도 정상 렌더링

G. 학생 1명

H. 학생 여러 명

I. 공통일지 + 개별일지

J. 이름 매칭

K. 일지 삽입 및 저장

L. request_id echo 검증
