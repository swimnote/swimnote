4. 담당 선생님 canonical source 확인

5. FIRST BREAK 분리
━━━━━━━━━━━━━━━━━━━━━━

아래 중 하나로 정확히 판정:

CASE A
API 자체가 선생님에게 pool 전체 오늘 수업을 반환
→ server scope/role 문제

CASE B
API는 담당반만 반환하지만
client가 다른 endpoint/data와 합쳐 타 반을 표시
→ client 문제

CASE C
API와 client 모두 현재 teacher identity로 필터하지만
teacher assignment 데이터 자체가 잘못됨
→ DB assignment/data 문제

CASE D
관리자+선생님 겸임 계정에서만
effective role/mode가 잘못 전달됨
→ role-switch contract 문제

CASE E
스케줄의 담당 teacher source와
반의 담당 teacher source가 서로 달라
잘못된 canonical source를 사용
→ assignment source mismatch
