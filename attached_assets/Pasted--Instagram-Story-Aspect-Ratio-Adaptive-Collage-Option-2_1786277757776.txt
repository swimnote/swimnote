[수정 승인 — Instagram Story 다중사진 Aspect Ratio 기반 Adaptive Collage]

사전 조사 결과 확인.

Option 2(사진 수만으로 고정 Template 선택)는 승인하지 않습니다.

이유:

이번 수정의 핵심 요구사항은

"사진 10장을 모두 보여주되,
각 사진의 원본 종횡비를 최대한 유지하고
사진이 알아보기 어려울 정도로 crop되는 문제를 해결하는 것"

입니다.

Option 2는 실제 aspectRatio를 사용하지 않으므로
5×2보다 나아질 수는 있어도
원본 사진 비율 유지라는 핵심 요구를 충족하지 못합니다.

따라서 Option 1 방향으로 진행합니다.

━━━━━━━━━━━━━━━━━━━━━━
1. 구현 원칙
━━━━━━━━━━━━━━━━━━━━━━

각 Story 사진의 실제 width / height를 확보하여

aspectRatio = width / height

를 계산하십시오.

이 값을 기준으로:

- landscape
- portrait
- square

를 분류하고

사진 5~10장에서는
aspectRatio 조합에 맞는 Adaptive Collage Template을 선택합니다.

단 무제한 Masonry 알고리즘을 만들지 않습니다.

안전하게:

"실제 aspectRatio 조사
→ 3~5개의 검증 가능한 Layout Template
→ 가장 crop이 적은 Template 선택"

방식으로 구현합니다.

━━━━━━━━━━━━━━━━━━━━━━
2. 1~4장 보호
━━━━━━━━━━━━━━━━━━━━━━

현재 1~4장 V3 결과는 정상이며 보기 좋습니다.

따라서 1~4장 layout은 변경 금지.

aspectRatio 기반 Adaptive Collage는
5~10장에만 적용합니다.

━━━━━━━━━━━━━━━━━━━━━━
3. 사진 크기 정보 확보
━━━━━━━━━━━━━━━━━━━━━━

현재 StoryPhoto:

{
  id: string;
  uri: string;
}

를 다음처럼 확장:

{
  id: string;
  uri: string;
  width?: number;
  height?: number;
  aspectRatio?: number;
}

Story 생성 전에 사진 5~10장에 대해
React Native Image.getSize() 또는
현재 Expo/RN 환경에서 안전한 동일 기능으로
width / height를 조회합니다.

주의:

- 이미지 원본을 별도로 다운로드하지 말 것
- DB 수정 금지
- API schema 수정 금지
- 사진 파일 자체 수정 금지
- 실패한 한 장 때문에 전체 Story 실패시키지 말 것

size 조회 실패 시:

aspectRatio = 1

또는 안전한 fallback을 사용하고
Story 공유는 계속 가능해야 합니다.

━━━━━━━━━━━━━━━━━━━━━━
4. 비율 분류
━━━━━━━━━━━━━━━━━━━━━━

기본 기준:

landscape:
aspectRatio > 1.15

portrait:
aspectRatio < 0.87

square:
0.87 ~ 1.15

threshold는 실제 화면 테스트 후
소폭 조정 가능.

━━━━━━━━━━━━━━━━━━━━━━
5. Adaptive Template 구조
━━━━━━━━━━━━━━━━━━━━━━

5~10장에 사용할 Template을
3~5개 정도로 제한합니다.

예:

Template A — Landscape dominant

가로사진을 넓은 셀에 우선 배치.

Template B — Portrait dominant

세로사진을 높이가 충분한 셀에 우선 배치.

Template C — Mixed

가로/세로/정사각 혼합용 비대칭 collage.

Template D — Mostly square

3×3 또는 3행 기반 안정적 구성.

10장에서도
5×2 균등 grid는 절대 사용하지 않습니다.

━━━━━━━━━━━━━━━━━━━━━━
6. Template 선택 알고리즘
━━━━━━━━━━━━━━━━━━━━━━

각 Template의 셀에도
expectedAspectRatio를 정의합니다.

예:

wide cell   ≈ 1.5~2.0
square cell ≈ 0.9~1.1
tall cell   ≈ 0.6~0.85

각 사진의 actualAspectRatio와
각 셀 expectedAspectRatio의 차이를 계산하여

crop penalty가 가장 작은 Template을 선택합니다.

예시 개념:

penalty =
abs(log(actualAspectRatio / cellAspectRatio))

전체 사진 penalty 합이 가장 작은 Template 선택.

복잡한 최적화 라이브러리 금지.
순수 JS 계산으로 충분합니다.

━━━━━━━━━━━━━━━━━━━━━━
7. 사진 순서
━━━━━━━━━━━━━━━━━━━━━━

기본 원칙:

원래 사진 업로드 순서 유지.

하지만 aspectRatio에 맞는 셀에 넣기 위해
순서를 조금 바꾸는 것이 crop 감소에 결정적으로 필요하다면
자동 재정렬은 허용할 수 있습니다.

단 다음 조건:

- 사진 누락 금지
- 사진 중복 금지
- 10장은 10장 모두 표시
- 동일 사진 두 번 배치 금지

우선 구현은:

원본 순서를 최대한 유지하면서
같은 Template 내에서만 최소 재배치

방식으로 합니다.

완전 랜덤 재정렬 금지.

━━━━━━━━━━━━━━━━━━━━━━
8. crop 정책
━━━━━━━━━━━━━━━━━━━━━━

contentFit="cover" 자체는 유지할 수 있습니다.

단 cover를 하기 전에
사진 비율과 비슷한 셀을 배정하는 것이 우선입니다.

성공 기준:

- 얼굴이 반 이상 잘리지 않음
- 사람 전신/동작이 식별 가능
- 가로사진이 좁은 세로 띠가 되지 않음
- 세로사진이 납작한 가로 띠가 되지 않음

가능하면 crop 최소화.

완전 contain으로 흰 여백이 많이 생기는 것도 피합니다.

━━━━━━━━━━━━━━━━━━━━━━
9. 10장 기준 성공 예시
━━━━━━━━━━━━━━━━━━━━━━

현재:

5 × 2 균등
각 셀 약 72px
→ 실패

목표:

3행 또는 비대칭 4행 구조.

예:

[ wide ][ square ][ portrait ]

[ portrait ][ wide ][ square ][ portrait ]

[ wide ][ portrait ][ wide ]

처럼
사진 비율에 맞는 셀 크기를 배정.

정확한 구조는 실제 10장 aspectRatio 조합을 보고 결정.

━━━━━━━━━━━━━━━━━━━━━━
10. 성능 및 로딩
━━━━━━━━━━━━━━━━━━━━━━

Image.getSize를 10장 호출하더라도
Story 생성 시 한 번만 수행.

Promise.allSettled 사용 권장.

한 장 실패했다고 전체 reject 금지.

결과는 StoryInput 생성 시점에만 사용.

추가 서버 호출 금지.

필요하다면 같은 일지 공유 재시도 시
메모리 수준 cache를 검토할 수 있으나
이번 작업에서 복잡한 영구 cache는 만들지 않습니다.
