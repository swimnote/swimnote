사용자 실기기 기준:

- 사진 업로드는 정상
- 영상 관련 수정이 여러 번 있었지만 아직 안정되지 않음
- 공통 일지:
  영상 업로드 UI는 일부 보이나 실제 저장/재조회 신뢰 불가
- 학생별 개별 일지:
  영상 기능이 공통과 동일하게 작동하지 않음
- 영상 작업 후 iPhone 앱 Documents & Data가 약 5GB까지 증가
- 사용자 정책은 영상 파일을 앱 로컬에 장기 보관하는 구조가 아님
- 영상은 선택 후 가능한 즉시 R2로 보내고,
  로컬에는 업로드에 필요한 최소 임시파일만 존재해야 함
- 기존 패치:
  업로드 배너
  video.id 저장
  save payload 연결
  temp cleanup
  등을 따로 수정했지만 전체 line이 아직 불안정

따라서 이번에는
개별 버그를 하나 더 붙이는 방식 금지.

VIDEO PIPELINE 자체를
하나의 canonical flow로 재정리합니다.

현재 TypeScript 구조 안에서 하나로 통일.

개념적으로:

{
  id?: string,          // server video.id
  localUri?: string,    // upload 전/중 임시

  studentId?: string,

  uploaded: boolean,

12. "바로 R2" 정책 정확히 구현
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

사용자 정책:

영상은 앱에 저장하는 기능이 아님.

정상:

Photo Library picker
→ iOS가 제공하는 임시/local URI
→ 즉시 R2 upload
→ video.id + remoteUrl
→ remote state 전환
→ 앱이 만든 temp/copy cleanup

금지:

picker video
→ app Documents에 permanent copy
→ 나중에 upload

불필요한 persistent duplicate 금지.

iOS picker 자체가 임시 local URI를 생성하는 것은 정상.

중요:
"로컬파일이 순간적으로 존재함"과
"앱이 5GB 영구 저장함"을 혼동하지 말 것.
