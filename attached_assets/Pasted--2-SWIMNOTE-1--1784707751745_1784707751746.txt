# 학생별 학부모 전화번호 2명 등록·수정 및 다중 보호자 연결 검증

현재 SWIMNOTE에는 학생 1명에 여러 학부모 계정을 연결할 수 있는 구조가 있는 것으로 알고 있습니다.

하지만 관리자 또는 선생님이 회원을 처음 등록할 때 입력한 학부모 전화번호를
학생 상세 화면에서 추가하거나 수정할 수 없습니다.

현재 학생 상세 화면에는 연락처가 1개만 표시되고,
이미 입력된 전화번호를 수정하거나 두 번째 보호자 전화번호를 추가할 수 없습니다.

이 문제를 수정하세요.

이번 작업의 핵심은 단순한 연락처 표시가 아니라 다음 구조를 완성하는 것입니다.

학생 1명
→ 보호자 전화번호 최대 2개 등록
→ 보호자 2명이 각각 본인 전화번호로 가입
→ 동일 학생에게 각각 연결
→ 두 보호자 모두 동일한 학부모 서비스를 사용

==================================================
1. 작업 전 기존 구조 분석
==================================================

코드 수정 전에 반드시 현재 데이터 구조를 먼저 확인하세요.

확인 대상:

- 학생 테이블
- 학생 연락처 저장 필드
- 보호자 전화번호 저장 구조
- parent/student 연결 테이블
- guardian 또는 parent 관계 테이블
- 학부모 가입 승인 로직
- 전화번호 자동 연결 로직
- 학생 상세 API
- 학생 수정 API
- 학부모 Home 데이터 조회 조건
- 일지 수신 대상 조회 조건
- 공지·앨범·출결·일정 조회 조건

특히 현재 구조가 아래 중 무엇인지 정확히 확인하세요.

A.
학생 테이블에 parent_phone_1, parent_phone_2 형태로 저장

B.
학생 테이블에는 대표 연락처만 있고
별도 guardian 테이블에 여러 보호자를 저장

C.
학생-학부모 연결 테이블만 있고
가입 전 전화번호를 별도로 보관하는 구조

D.
기타 구조

기존에 다중 보호자 연결 기능이 이미 존재한다면
새로운 중복 구조를 만들지 말고 현재 구조를 확장하세요.

작업 완료 보고에 현재 구조를 정확히 설명하세요.

==================================================
2. 학생 상세 화면 수정
==================================================

현재 학생 상세 화면의 기본 정보 영역에 있는 연락처를
'학부모 연락처' 관리 영역으로 변경하세요.

표시 예시:

학부모 연락처

보호자 1
010-1234-5678
연결됨

보호자 2
010-5678-1234
미가입 또는 연결됨

필요 기능:

- 보호자 전화번호 추가
- 기존 전화번호 수정
- 두 번째 보호자 전화번호 추가
- 보호자 전화번호 삭제
- 전화번호별 연결 상태 표시
- 전화번호 최대 2개
- 전화번호 형식 자동 정리
- 중복 전화번호 방지

버튼 예시:

- 연락처 추가
- 수정
- 삭제

현재 화면 디자인과 색상 체계를 유지하세요.

학생 상세 화면 전체를 새로 디자인하지 마세요.

==================================================
3. 보호자 전화번호 개수
==================================================

학생 1명당 보호자 전화번호는 기본적으로 최대 2개로 지원하세요.

예:

- 어머니
- 아버지

다만 명칭을 반드시 어머니·아버지로 고정하지 말고,
가능하면 다음과 같이 처리하세요.

- 보호자 1
- 보호자 2

또는 기존 시스템에 보호자 관계 필드가 있다면:

- 어머니
- 아버지
- 기타 보호자

기존 DB와 UI 구조에 가장 안전한 방식을 사용하세요.

이번 작업에서 보호자 3명 이상 확장 기능은 만들지 마세요.
최대 2명까지만 지원하세요.

==================================================
4. 전화번호 추가
==================================================

첫 번째 보호자만 등록된 학생에게
두 번째 보호자 전화번호를 추가할 수 있어야 합니다.

추가 흐름:

1. 학생 상세 진입
2. 학부모 연락처 영역 확인
3. 연락처 추가 선택
4. 두 번째 보호자 전화번호 입력
5. 저장
6. 학생 상세에 두 번째 전화번호 표시
7. 연결 상태는 가입 전이면 '미가입' 또는 '연결 대기'
8. 해당 전화번호로 학부모가 가입하면 자동 연결

전화번호는 저장 전에 정규화하세요.

예:

010-1234-5678
01012345678

두 값은 동일한 번호로 처리해야 합니다.

==================================================
5. 전화번호 수정
==================================================

기존 보호자 전화번호를 수정할 수 있어야 합니다.

단, 이미 학부모 계정과 연결된 전화번호를 수정할 때는
연결 데이터가 잘못 끊기거나 다른 사람에게 이전되지 않도록 주의하세요.

수정 시 다음 경우를 구분하세요.

A. 아직 가입하지 않은 전화번호

- 전화번호만 수정
- 기존 대기 연결 정보 갱신
- 새로운 전화번호로 가입 시 자동 연결

B. 이미 학부모 계정과 연결된 전화번호

- 단순히 번호 문자열만 덮어쓰지 마세요.
- 연결된 학부모 계정과 학생 연결 관계를 확인하세요.
- 전화번호 변경이 기존 연결을 유지해야 하는지,
  기존 보호자 연결을 해제하고 새 번호를 대기 상태로 만들지
  현재 시스템 정책에 맞게 처리하세요.

안전한 기본 정책:

이미 연결된 보호자 번호를 변경하면
기존 학부모-학생 연결은 자동으로 다른 전화번호에 이전하지 않습니다.

다음과 같이 처리하세요.

- 사용자에게 연결된 보호자 번호라는 경고 표시
- 번호 변경 확인
- 기존 보호자 연결 해제 여부를 명확히 처리
- 새 번호는 미가입 또는 연결 대기 상태로 등록
- 기존 보호자 계정이 계속 학생을 볼 수 있는 상태로 남지 않도록 정책 일관성 유지

현재 시스템에 기존 정책이 있다면 그 정책을 우선 적용하세요.

임의로 개인정보 연결을 이전하지 마세요.

==================================================
6. 전화번호 삭제
==================================================

두 번째 보호자 전화번호를 삭제할 수 있어야 합니다.

삭제 전 확인창을 표시하세요.

예:

"이 보호자 연락처를 삭제하시겠습니까?"

이미 연결된 보호자라면 추가 안내:

"연락처를 삭제하면 해당 보호자의 학생 연결도 해제됩니다."

삭제 후:

- 해당 전화번호 제거
- 연결 대기 정보 제거
- 연결된 보호자라면 학생-학부모 연결 해제
- 다른 보호자 연결은 유지
- 학생 자체 정보는 삭제하지 않음
- 일지나 기존 교육 기록은 삭제하지 않음

==================================================
7. 보호자 2명 가입 및 연결
==================================================

다음 흐름이 정상이어야 합니다.

예:

학생: 전하빈

보호자 1:
010-1111-1111

보호자 2:
010-2222-2222

보호자 1이 010-1111-1111로 가입
→ 전하빈 자동 연결 또는 승인 절차 정상 진행

보호자 2가 010-2222-2222로 가입
→ 동일한 전하빈에게 추가 연결

결과:

- 학생은 1명
- 학부모 계정은 2명
- 두 학부모 모두 전하빈을 자신의 자녀로 확인
- 한쪽 가입 때문에 다른 쪽 연결이 덮어써지지 않음
- parent_id 하나만 저장하여 기존 보호자를 교체하는 구조 금지
- 두 개의 독립된 학생-학부모 연결 관계 유지

==================================================
8. 두 보호자에게 동일한 서비스 제공
==================================================

두 보호자가 연결된 뒤
다음 항목을 모두 동일하게 이용할 수 있는지 확인하세요.

- 학부모 Home
- 수업일지
- 공통 일지
- 학생 개별 일지
- 사진
- 영상
- 앨범
- 공지
- 출결
- 일정
- 교육 프로그램
- 레벨 및 진도 정보
- 수영정보
- 알림이 있다면 알림 수신 대상

첫 번째 보호자만 데이터를 볼 수 있고
두 번째 보호자는 일부 정보가 누락되는 구조가 없어야 합니다.

모든 학부모 데이터 조회는
대표 전화번호 또는 첫 번째 parent_id만 기준으로 하지 말고,
학생-학부모 연결 관계를 기준으로 조회해야 합니다.

==================================================
9. 일지 노출 및 알림 대상 확인
==================================================

학생에게 일지가 작성되면
연결된 보호자 2명 모두가 같은 일지를 확인할 수 있어야 합니다.

확인할 것:

- 일지 데이터 자체를 보호자별로 복제하지 않음
- 동일 diary를 두 보호자가 각자 조회
- 보호자 1 연결만 조회 조건에 포함되는 버그 없음
- 첫 번째 전화번호만 수신 대상으로 선택하는 코드 없음
- 알림 대상 생성 시 연결된 모든 보호자 계정 조회
- 한 보호자의 읽음 상태가 다른 보호자의 읽음 상태에 영향을 주는지 확인

읽음 상태가 보호자별이어야 하는 구조라면
각 보호자별로 독립 처리하세요.

==================================================
10. 기존 학생과 기존 보호자 호환
==================================================

현재 등록된 모든 학생은 기존처럼 정상 표시되어야 합니다.

기존 데이터가 연락처 1개만 있는 경우:

- 보호자 1로 표시
- 보호자 2는 빈 상태
- 연락처 추가 버튼 제공
- 기존 연결 유지

기존에 이미 보호자 2명이 연결된 학생이 있다면:

- 두 보호자가 모두 학생 상세에 표시되는지 확인
- 하나의 번호만 표시되는 문제가 있다면 수정
- 기존 연결을 새로 생성하여 중복시키지 않음

기존 학생 데이터를 일괄 삭제하거나 재생성하지 마세요.

==================================================
11. 전화번호 중복 및 개인정보 안전
==================================================

다음 예외를 처리하세요.

- 같은 학생에게 동일 번호 2번 등록 금지
- 서로 다른 형식의 동일 번호 중복 금지
- 이미 다른 학생의 보호자로 연결된 번호 처리
- 형제자매는 같은 보호자 번호로 연결 가능
- 다른 센터 또는 테넌트 데이터가 섞이지 않음
- 한 보호자가 여러 자녀를 갖는 구조 유지
- 다른 수영장의 학생이 잘못 연결되지 않음
- 멀티테넌트 조건 유지

중요:

같은 보호자 번호가 형제자매에게 등록되는 것은 허용해야 합니다.

그러나 다른 센터의 데이터가 전화번호만으로 무단 연결되면 안 됩니다.

현재 센터 및 승인 정책을 반드시 유지하세요.

==================================================
12. API 및 DB 변경 원칙
==================================================

먼저 기존 구조로 구현 가능한지 확인하세요.

기존 guardian 또는 student-parent 연결 구조가 이미 다중 연결을 지원한다면
불필요한 DB 스키마 변경은 하지 마세요.

DB 변경이 반드시 필요할 경우에만:

- 멱등 마이그레이션
- 기존 데이터 보존
- rollback 가능성 검토
- unique constraint 범위 검토
- tenant_id 포함
- 학생 1명당 최대 2명 제한 처리
- 형제자매 공통 보호자 허용

DB 변경이 필요하다고 판단되면
바로 적용하지 말고 먼저 구조와 변경 이유를 보고하세요.

가능하면 기존 API와 스키마를 활용하여 구현하세요.

==================================================
13. 학생 상세 UI 상태 표시
==================================================

각 보호자 전화번호 옆에 연결 상태를 표시하세요.

예:

- 연결됨
- 가입 대기
- 미연결

상태 정의는 현재 가입·승인 구조와 일치해야 합니다.

연결됨:
실제 parent 계정과 student 연결 관계가 존재

가입 대기:
전화번호는 등록됐지만 해당 번호의 학부모 계정 또는 연결 관계가 없음

미연결:
현재 시스템에서 별도 의미가 필요할 경우만 사용

상태를 전화번호 존재 여부만으로 추정하지 마세요.
실제 연결 테이블을 기준으로 표시하세요.

==================================================
14. 실제 검증 시나리오
==================================================

가능한 범위에서 API 또는 통합 테스트를 작성하세요.

실기기 테스트가 불가능하다면
실제 테스트 완료라고 보고하지 말고
코드상 검증과 실기기 검증 필요 항목을 구분하세요.

필수 시나리오:

시나리오 A: 두 번째 보호자 추가

1. 기존 학생에 보호자 1만 존재
2. 보호자 2 전화번호 추가
3. 학생 상세에서 두 번호 표시
4. 보호자 1 연결 유지

시나리오 B: 두 번째 보호자 가입

1. 보호자 2 전화번호로 학부모 가입

2. 보호자 1에서 일지 확인
3. 보호자 2에서 동일 일지 확인
4. 사진·개별내용·공통내용 모두 동일 확인

시나리오 D: 전화번호 수정

1. 미가입 보호자 2 번호 수정
2. 기존 번호로 가입해도 연결되지 않음
3. 새 번호로 가입하면 연결
4. 보호자 1 영향 없음

시나리오 E: 연결된 보호자 삭제

1. 보호자 2 연락처 삭제
2. 보호자 2 학생 연결 해제
3. 보호자 1은 계속 학생 확인
4. 학생 일지 및 기록 유지

시나리오 F: 형제자매

1. 동일 보호자 번호를 학생 2명에게 등록
2. 보호자 계정에서 두 자녀 모두 확인
