SWIMNOTE X — WP4 구현 승인 지시

WP4 수정 설계서를 검수했습니다.

WP4 구현을 승인합니다.

추가 설계서를 다시 작성하지 말고, 아래 확정사항을 반영하여 WP4 외형·메뉴 분기만 구현하십시오.

━━━━━━━━━━━━━━━━━━━━━━

1. WP4 구현 목표
    ━━━━━━━━━━━━━━━━━━━━━━

같은 SWIMNOTE 앱 안에서 ModeContext의 상태에 따라 다음을 구분합니다.

* normal: 기존 SWIMNOTE 외형과 기능 유지
* x_pending: X 준비 중 상태 표시
* x: SWIMNOTE X 명칭·표시·메뉴 노출

이번 WP에서는 실제 기능을 연결하지 않습니다.

금지:

* 커리큘럼 API 연결
* Growth Event 연결
* 성장판 API 연결
* X 글로벌 템플릿 연결
* 학부모 AI 검색 실제 연결
* 성장리포트 실제 연결
* RevenueCat 연결

━━━━━━━━━━━━━━━━━━━━━━
2. 일반모드 학부모 버튼 유지
━━━━━━━━━━━━━━━━━━━━━━

설계서의 다음 내용은 적용하지 마십시오.

normal 학부모
→ AI 커리큘럼 검색 버튼 숨김
→ AI 성장 리포트 버튼 숨김
→ Powered by SWIMNOTE AI 문구 숨김

이유:

* 현재 일반모드 앱에 이미 존재하는 UI임
* 기존 확정안에서 두 버튼을 유지하도록 정해짐
* 버튼은 실제 기능이 아니라 기존 출시 예정 안내 모달만 표시함
* 일반모드 변화 0 원칙을 지켜야 함

최종 확정:

normal
→ AI 커리큘럼 검색 버튼 기존 그대로 유지
→ AI 성장 리포트 버튼 기존 그대로 유지
→ 기존 AIFeatureModal 연결 유지
→ Powered by SWIMNOTE AI 기존 노출 유지
x_pending
→ 두 버튼 유지
→ 기존 AIFeatureModal 연결 유지
→ X 준비 중 표시 추가 가능
x
→ 두 버튼 유지
→ 기존 AIFeatureModal 연결 유지
→ XModeBadge 또는 SWIMNOTE X 표시 추가

학부모 home.tsx에서는 기존 버튼을 제거하거나 조건부로 숨기지 마십시오.

허용 변경은 XModeBadge와 X 준비 상태 표시뿐입니다.

4. XModeGuard 이번 WP 제외
━━━━━━━━━━━━━━━━━━━━━━

다음 파일은 이번 WP에서 만들지 마십시오.

components/mode/XModeGuard.tsx

이유:

* WP4에서는 X 전용 신규 Route를 생성하지 않음
* Guard를 실제 적용할 화면이 없음
* 미사용 컴포넌트는 테스트할 수 없는 Dead Code가 됨

처리 원칙:

첫 X 전용 Route가 실제 생성되는 WP
→ 해당 Route와 XModeGuard를 동시에 구현
→ normal / x_pending / error / Deep Link 차단 검증

기존 일반 Route에는 X Guard를 연결하지 마십시오.

* 수영장 이름 옆 준비 상태 Badge

* X 항목은 disabled 또는 준비 중 표시
* onPress로 실제 기능 진입 금지

mode가 normal, null 또는 Mode 오류일 때:

* 기존 dashboard와 완전히 동일
* X 섹션 없음
* X Badge 없음

mode가 normal 또는 null이면 기존 배열 결과와 완전히 같아야 합니다.
