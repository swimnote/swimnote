3. 이제 Android 강제 업데이트 정책 목표

Google Play에서 1.6.2가 실제 공개된 것이 확인되었으므로
최종 목표는:

AOS_MIN_VERSION = "1.6.2"
AOS_LATEST_VERSION = "1.6.2"

가 되어야 한다.

그러나 지금은 수정하지 말고
현재 값이 무엇인지부터 보고.

current = 1.6.1
min = 1.6.2

이면:

cmp(current, min) < 0

→ 강제 업데이트
→ cancelable:false
→ Play Store 이동

이어야 한다.

실제 코드로 CASE 실행 결과 보고.

→ Store Version Gate
→ 1.6.2 미만
→ 강제 Store Update

여기서는 OTA check를 먼저 실행하여

→ OTA check

→ download

16. Native Build 필요성 판정

중요.

현재 1.6.2 binary에 expo-updates 모듈과
production channel/runtime가 정상 포함되어 있다면

OTA updater UI 로직 자체는
OTA로 추가 가능할 가능성이 높다.

반대로 native config가 잘못된 경우에만
Native Build 필요.

증거 없이 재빌드하지 않는다.

17. 다음 수정 설계 조건

조사 후 필요하면 최소 수정안을 설계하되
아직 구현 금지.

최종적으로 하나의 Update Coordinator 구조를 권장:

APP START
   ↓
Native Version Gate
   ↓
if FORCE STORE UPDATE
   → blocking modal
   → store
   → STOP
else
   ↓
EAS OTA check
   ↓
if update available
   → fetch
   ↓
if downloaded
   → "업데이트 적용" modal
   ↓
Updates.reloadAsync()

중복 modal 방지.

앱 시작할 때 여러 useEffect가 경쟁하지 않게 한다.

19. OTA modal 정책

OTA는 Native 강제 Update와 다르게
앱 자체 update이므로:

"업데이트가 준비되었습니다."

[재실행]

정도로 단순하게.

원한다면 재실행 전 사용 중인 draft가 있는지
고려 필요.

현재 작성 중 일지를 갑자기 reload하여
draft를 날릴 가능성이 있는지도 조사.

따라서 앱 최초 실행/홈 진입 시 적용하는 구조 우선 검토.
