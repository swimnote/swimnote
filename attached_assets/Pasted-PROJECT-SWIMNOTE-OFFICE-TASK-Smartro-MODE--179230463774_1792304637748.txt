[1. 진행 원칙]

직전 관리자 핵심 통합본을 이어서 개발한다.
단계마다 설계 검토·설치본 전달·사용자 확인을 반복하지 않는다.

남은 기능을 큰 업무 묶음으로 연속 구현하고,
최종 통합본에서 사용자가 체크리스트로 확인하도록 한다.

단, 사용자 확인을 나중에 한다는 것이
개발 중 컴파일·필수 오류 확인까지 생략한다는 뜻은 아니다.
권한·금액·중복 저장·데이터 변경에 필요한 최소 확인은
개발자가 수행하고 결과를 누적한다.

[3. 이번 핵심 — 수강료·수납 업무 완결]

기존 학생·보호자·상담·상품·계약·수강 배정과 연결하여 구현한다.

A. 상품·수강권
- 기간권·횟수권·주당 횟수와 복합 상품
- 가격·할인·무료 제공 횟수·회차 조정
- 시작일·만료일·휴회·복귀·중도변경
- 재등록과 기존 수강의 연속성
- 계약 당시 가격·조건 보존
- 수업·출결·보강과 권리 사용 연결
- 과거 기록을 현재 상품 조건으로 덮어쓰지 않음

B. 청구·수납
- 회원별 청구·납부기한·미납
- 현금·계좌이체·외부 단말기 결제의 수동 기록
- 부분수납·청구별 배분·과납·미배분금
- 가족별 합산 조회와 회원별 귀속
- 재등록 대상·청구·수납 상태 연결
- 수기 기록을 실제 PG 승인으로 표시하지 않음

C. 정정·환불·마감
- 청구 감액·취소·오입력 정정·실제 환불 기록 구분
- 부분환불·원거래 연결·중복환불 방지
- 잔여 수강권과 금액 영향 표시
- 일별/기간별 수납·미납·환불·마감
- 마감 후 수정 권한과 변경 이력
- 같은 납부를 두 번 배분하거나 원금 초과 환불하지 않음

D. 경영 자료
- 운영 지출·분류·거래처·지급예정·증빙
- 수납·환불·지출에 따른 자금수지
- 강사정산과 학생 청구·수납 구분
- 청구액·수납액·미납액·현금흐름의 집계 기준 명시
- 필요한 Excel/CSV·PDF·인쇄

센터별 정책은 필요한 설정으로 분리한다.
환불·할인 등 중요한 미정 정책은 임의 확정하지 말고,
해당 결정이 필요한 부분만 보류하여 다른 구현을 계속한다.
법정 기준·자동 계산 규칙을 근거 없이 하드코딩하지 않는다.

[4. 기존에 남은 기능도 이어서 완성]

무료 AI 데이터 이전:
- 기존 다중 파일·시트·매핑·이어하기 재사용
- GPT 형태 대화창과 미리보기 연결
- 사용자 의견을 변환 규칙에 반영
- 규칙 수정·취소·영향 미리보기
- 회원뿐 아니라 금융·잔여횟수·보강 자료 연결
- 원본·기준일·과거 납부·시작 잔액 구분
- 운영 시작 후 변경 덮어쓰기 방지
- 정상/보류/실패와 금액·횟수 대조
- 실제 모델 호출이 미승인이면 해당 실행만 비활성으로 유지
- 단순 매핑 UI를 AI 이전 완성으로 표시하지 않음

성장리포트:
- 기존 본문·검수 보완을 이어 발급·발송·이력까지 연결
- 당시 버전 열람과 상태 구분
- 유료 AI 자격과 기존 발급 자료 접근 정책 분리
- 실발송은 실행하지 않음

전자 신청·계약:
- 태블릿용 제한된 입력·직접 동의/서명 흐름
- 관리자 확인과 회원 등록 연결
- 확정 양식·버전·문서 보존·PDF
- 관리자 계정 전체를 회원에게 노출하지 않음
- 실제 앱 입력이 필요한 부분은 앱 후속 변경으로 명시

NFC:
- 기존 UID 관리와 출결·중복 방지·보호자 알림 연결
- 준비된 범용 리더 방식이면 실제 제품에 연동
- 장비가 없으면 리더 동작만 미확인으로 유지
- 수동 카드 관리만으로 NFC 출결 완료 선언 금지
- 셔틀 NFC는 추가하지 않음

마케팅·운영지원:
- 기존 수동 마케팅을 상담·캠페인·소개 유입과 연결
- 필요한 홍보 자료·사용 동의·게시 기록
- 시설·물품·대회·업체·본사 안내/신청
- 이미 합의한 범위에서 구현하며 새 기능을 임의로 확장하지 않음
- 배차는 기존 원문 설계를 대조한 범위만 구현
- 원문이 없다면 해당 기능만 보류

[5. 공통 UX·AI]

각 업무에서 다음을 함께 완성한다:
- 일관된 메뉴·목록·상세·탭·짧은 입력 모달
- 검색·필터·스크롤·초안 유지
- 실제 현황과 상세 목록 연결
- 공통 Action/Service/API 사용
- 일반 메뉴와 AI가 같은 업무 처리 사용
- AI 없이도 일반 업무 사용 가능
- 모호한 대상은 확인하고 대량·금액·삭제·발송은 영향 요약
- 일부 성공·실패·결과 불명 구분
- 결과 불명인 요청을 무조건 재실행하지 않음

범용 AI 엔진 완성을 다른 기능의 선행 조건으로 삼지 않는다.
AI 연결 상태는 화면 이동/조회/초안/실행으로 구분한다.

[6. 확정 요금 정책 유지]

- 스윔노트 기본 앱·PC 전산·초기 세팅 무료
- 카드·모바일 결제 기능의 별도 스윔노트 이용료 없음
- 유료: AI·성장리포트·AI 작업창·인원별 저장용량
- 유료 상품의 기존 가격·할인·약정 유지
- 무료 AI 데이터 이전은 예외적으로 누구나 이용 가능
- 내부 X 식별자 유지, 외부 명칭은 스윔노트 AI

무료 저장용량·추가 가격·기존 구독 전환은 임의 확정하지 않는다.
가격 설계 미정이 일반 전산 구현을 막지 않도록 분리한다.

[7. 개발 확인·사용자 확인 분리]

개발 중:
- 변경 범위의 컴파일·타입·필수 동작 확인
- 금액·권한·중복·귀속·합계에 필요한 직접 검사
- 기존 검사 증거 재사용
- 기존 개발환경 활용
- 새 검증용 제품·합성 인증·로컬 업무 DB 제작 금지
- 변경 없는 전체 suite·monorepo 검사 반복 금지

사용자 확인:
- 개발을 모아 최종 통합본에서 체크리스트로 일괄 진행
- 기능별 설치본·중간 확인을 요구하지 않음
- 사용자에게 개발 도구·소스 빌드·터미널 진단 요구 금지

기존 문서에 기능별 확인 항목과 미확인 상태만 누적한다.
별도 대형 coverage·증거 관리 시스템은 만들지 않는다.

[8. 운영 적용 경계]

계속 진행:
- PC 구현
- 필요한 기존 서버 호환 확장 코드
- DB migration 작성
- 앱 후속 통합에 필요한 공유 계약 정리
- 최소 개발 확인

별도 승인 필요:
- 운영 DB migration·실데이터 일괄 변경
- 운영 서버 배포·활성화
- 실제 구독·가격·청구 전환
- 실발송·실거래·실환불
- 새 유료 모델 호출

승인이 필요한 항목은 적용 대상·영향·복구 방법을
구체적으로 준비해 한 번에 요청한다.
운영 승인이 없다는 이유로 독립 소스 구현을 중단하지 않는다.

[9. 전달·완료보고]

Smartro 전 운영 기능을 모은 뒤 하나의 통합 설치본을 전달한다.
서버 미적용이면 가능한 기능과 불가능한 기능을 명확히 표시한다.

3) 앱·서버·DB 변경 범위

그동안 독립 작업을 이어간다.
