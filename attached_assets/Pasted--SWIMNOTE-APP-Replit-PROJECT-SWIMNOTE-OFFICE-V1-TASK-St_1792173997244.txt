TASK = Stage 2 통합 업무 레이아웃 완성·검증본 전달

이 지시는 앞선 N02 배치 정정 지시들을 대체한다.
작업을 작은 수정·보고·재승인으로 반복 분할하지 말고,
아래 범위를 구현·검증·패키징까지 한 번에 완료한다.

확정 레이아웃 =
- 왼쪽: 기존 Sidebar·메뉴, 접기/펼치기.
- 중앙 상부의 나머지 공간: 기존 Dashboard·회원목록·상세.
- 중앙 하단: GPT 스타일 업무 입력창.
- 입력창 바로 위: 약 10줄이 보이는 AI 업무 처리 영역.
- 별도 업무집중/AI 중심 전환 없음.
- 오른쪽 상시 AI 패널 없음.
- 대시보드 UI를 새로 만들지 말고 기존 화면을 재배치한다.

1. 통합 배치
- 기존 DashboardLayout·N01 Navigation·업무 화면 재사용.
- AI 처리 영역은 결과가 길어지면 내부 스크롤.
- 입력창은 업무 화면 스크롤과 독립적으로 하단에 유지.
- 업무 화면·처리 영역·입력창이 서로 덮이지 않게 한다.
- “약 10줄”은 기본 높이 기준이며 작은 창에서는
  업무와 입력창을 사용할 수 있도록 유연하게 조정.
- 기존 두 모드 분기·전환 버튼·불필요한 패널 구조 정리.
- 인증·QueryClient·SSE·업무 subtree 중복 생성 금지.

2. 입력창과 처리 영역
- 입력 문구와 포커스는 메뉴 이동·접기 등으로 소실되지 않게 한다.
- 입력 내용은 세션 메모리만 사용.
- 현재 AI 미연결 상태를 명확하게 표시.
- 입력은 가능하게 하되 미연결 전송은 차단하고 이유 표시.
- 가짜 답변·모델 호출·업무 실행·성공 연출 없음.
- 향후 공통 Action 연결에 사용할 최소 컴포넌트 경계만 마련.
- 실제 AI와 쓰기 기능은 후속 단계에서 구현.
- 연결 전 상태를 제품의 최종 기능 완료로 보고하지 않는다.

3. 진행 중인 가독성 문제 함께 해결
- 홈 현황 카드는 실제 업무 영역 폭에 따라 4/2/1열 등으로 배치.
- 회원 제목·버튼은 좁으면 줄을 바꾸되 글자가 세로로 찢어지지 않게 한다.
- 회원표는 열별 최소 폭·줄바꿈 정책·내부 가로 스크롤 유지.
- 보기 버튼까지 접근 가능하게 한다.
- 앱 전체 가로 넘침·하단 입력창 가림 방지.
- 일반 Web에는 불필요한 Desktop 배치 변경을 적용하지 않는다.

4. 상태·권한 보존
- 검색·필터·가로/세로 스크롤·선택 회원·Drawer 유지.
- N01 뒤로/앞으로·Breadcrumb·Dashboard 이동 유지.
- 로그아웃·계정/Pool 전환 시 업무 Context·입력·cache 정리.
- 기존 Desktop 쓰기 차단 유지.
- 운영 회원정보·권한·PIN·TOTP 변경 금지.

5. 묶음 검증
- 실제 CSS 렌더링으로 홈·회원목록·Drawer를
  넓은 창/좁은 창/낮은 창에서 확인.
- 하단 입력창·처리 영역·업무 스크롤을 함께 확인.
- Navigation·입력 보존·세션 격리·중복 SSE 회귀 확인.
- 기존 통과 증거는 재사용하고 변경 영향만 검사.
- Desktop 타입검사·필요 build·기존 Web 회귀 확인.
- 관련 수정은 패키징 전에 모두 마무리.
- Windows에서 확인하지 않은 배율은 미검증으로 명시.

6. 통합 설치본 제작·전달
- 위 검증 완료 후 Windows x64 unsigned 내부 설치본 1회 제작 승인.
- 기존 설치·전달 도구 재사용.
- 새 PACKAGE ID·HEAD+미커밋 diff 식별값 기록.
- payload·민감 파일 제외·해시·전달 ZIP 무결성 확인.
- 기존 source·첨부·설치본 보존.
- 사용자에게는 이번 통합본 하나만 전달.
- 제작 도중 실제 blocker가 없으면 중간 승인 요청 없이 완료한다.

사용자 확인은 세 묶음으로 안내:
① 전체 배치와 좁은 창 가독성.

③ 하단 입력 유지·업무 영역과 독립된 스크롤.
