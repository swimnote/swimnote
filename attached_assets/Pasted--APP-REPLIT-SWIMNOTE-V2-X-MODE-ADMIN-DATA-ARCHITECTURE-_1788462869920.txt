============================================================

최소 500개 수영장 운영 전제.

모든 데이터는:

authenticated user
→ server auth
→ swimming_pool_id 확정
→ SQL query 단계에서 pool scope 적용

이어야 한다.

절대 금지:

- APP에서만 pool 필터
- client가 전달한 pool_id를 source of truth로 사용
- pool scope 없는 aggregate
- 전체 pool 데이터를 조회 후 client에서 필터
- cross-pool join
- tenant 조건 없는 background job

모든 KPI / monthly snapshot / report / event aggregation에
swimming_pool_id가 반드시 포함되어야 한다.
