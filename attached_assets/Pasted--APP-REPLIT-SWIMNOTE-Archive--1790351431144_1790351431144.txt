0. TARGET 기능
━━━━━━━━━━━━━━━━━━━━━━

최종적으로 원하는 동작:

ACTIVE MEMBER

→ 관리자/선생님이 명시적으로 퇴원 처리

→ canonical withdraw purge 실행 전

퇴원생 Archive에:

1. 최소 회원정보
2. 해당 학생의 과거 일지 데이터

→ 활성 회원수에서 제외
→ 기존 교육데이터 삭제
→ parent/student 연결 해제

하지만 Archive 데이터는 별도 보존.

관리자/선생님:

지난 회원 목록
→ 퇴원생 선택
→ 과거 일지 열람 가능

기본적으로 Archive 접근 불가.

동일 이름/전화번호로 재가입해도
자동 연결 금지.

관리자가 명시적으로:

[현재 회원과 지난 기록 연결]

을 누른 경우에만
해당 현재 학생/학부모에게
지난 퇴원 일지 조회 권한을 연결.

과거 diary row를
현재 active diary 테이블로 복원하는 기능이 아닙니다.

Archive는 Archive로 유지하고
조회 권한만 연결하는 구조를 우선 검토하십시오.

16. Archive snapshot atomicity
━━━━━━━━━━━━━━━━━━━━━━

DB 범위에서:

Archive member 생성
Archive diaries 생성

이 성공한 경우에만
canonical purge가 진행되도록 설계하십시오.

가능하면 동일 transaction.

검토:

Archive INSERT
→ DELETE education data
→ withdraw final state
→ COMMIT

중 오류 발생 시
DB 전체 rollback 가능한지.

R2 삭제는 별도 문제이므로
현재 canonical withdraw의
확정된 R2 failure 정책은 변경하지 마십시오.
