실기기 테스트 결과, 현재 문제의 핵심은 개별 버튼이나 높이값이 아니라
DiaryAIModalV2의 전체 UX 레이아웃 구조입니다.

AI 기능, API, 상태관리, 결과 삽입 구조는 현재 구현을 유지하십시오.

이제부터는 기능 수정이 아니라
모달 UX 레이아웃을 현대적인 모바일 앱 방식으로 전면 재구성하십시오.

이번 작업의 목표는 다음과 같습니다.

- 화면 크기와 관계없이 사용 가능
- 키보드가 올라와도 버튼과 입력창이 가려지지 않음
- 긴 입력과 긴 결과를 자유롭게 스크롤 가능
- 학생별 결과가 많아져도 레이아웃이 깨지지 않음
- iPhone의 Safe Area와 키보드 높이에 정상 대응
- 향후 Android에서도 동일한 구조로 적용 가능
- 고정 높이와 임의의 화면 계산에 의존하지 않음

━━━━━━━━━━━━━━━━━━━━━━
1. 모달 전체 레이아웃 구조를 변경하십시오.
━━━━━━━━━━━━━━━━━━━━━━

최종 구조는 아래와 같이 구성하십시오.

Modal
└─ Root Container
   └─ Keyboard-aware Sheet
      ├─ Drag Handle
      ├─ Header                    고정
      ├─ Scrollable Content        유일한 세로 스크롤 영역
      └─ Bottom Action Area        고정

구조 원칙:

- Header는 스크롤되지 않습니다.
- 콘텐츠 영역만 세로로 스크롤됩니다.
- ActionBar는 콘텐츠 ScrollView 밖에 둡니다.
- ActionBar는 항상 화면에서 접근 가능해야 합니다.
- 키보드가 올라오면 콘텐츠의 사용 가능한 높이만 줄어듭니다.
- 키보드 위에 ActionBar가 유지되어야 합니다.
- 콘텐츠는 ActionBar 아래로 가려지지 않아야 합니다.

━━━━━━━━━━━━━━━━━━━━━━
2. 고정 모달 높이를 제거하십시오.
━━━━━━━━━━━━━━━━━━━━━━

현재와 같은 고정 height, 임의 maxHeight 또는
화면 높이에서 키보드 높이를 직접 빼는 방식에 의존하지 마십시오.

금지 대상 예시:

- height: 특정 숫자
- height: screenHeight * 임의 비율을 상태별로 다르게 적용
- 키보드 높이를 직접 계산하여 모달 높이 변경
- 입력 상태마다 모달 높이 재설정
- absolute 좌표로 ActionBar 배치
- 키보드 표시 시 모달 전체 translateY 이동

대신 다음 원칙을 사용하십시오.

- 모달 시트는 사용 가능한 화면 안에서 flex로 배치
- 최대 높이는 Safe Area를 제외한 화면 범위
- 콘텐츠는 flex: 1
- 스크롤 영역은 minHeight: 0 적용
- ActionBar는 자연스러운 flex 레이아웃의 마지막 고정 영역
- 입력 내용이 짧으면 불필요하게 전체 화면을 채우지 않도록 하되,
  키보드와 긴 결과 상황에서는 충분히 확장 가능하게 구성

━━━━━━━━━━━━━━━━━━━━━━
3. 키보드 대응 방식을 하나로 통일하십시오.
━━━━━━━━━━━━━━━━━━━━━━

KeyboardAvoidingView, SafeArea padding, 수동 키보드 높이 계산을
중복으로 적용하지 마십시오.

현재 프로젝트 환경에서 가장 안정적인 방식 하나를 선택하고
그 방식만 사용하십시오.

우선 검토 순서:

1.
프로젝트에 이미 설치되어 있고 안정적으로 사용 중인
keyboard-aware scroll 또는 keyboard controller 라이브러리가 있는지 확인

2.
없다면 React Native 기본 구조로 구현

iOS:
KeyboardAvoidingView behavior="padding"

Android:
adjustResize 기반 또는 검증된 keyboard-aware 방식

중요 원칙:

- 키보드 이벤트로 모달 높이를 직접 계산하지 않음
- KeyboardAvoidingView를 여러 계층에 중복 사용하지 않음
- Safe Area bottom과 키보드 offset을 이중 적용하지 않음
- 키보드가 닫혔을 때 불필요한 빈 공간이 남지 않음
- 키보드가 열렸을 때 현재 포커스된 TextInput이 보이도록 자동 스크롤

━━━━━━━━━━━━━━━━━━━━━━
4. 콘텐츠 영역은 반드시 자유 스크롤 구조로 만드십시오.
━━━━━━━━━━━━━━━━━━━━━━

입력 화면과 결과 화면 모두 동일한 Scroll Container를 사용하십시오.

필수 속성 및 동작:

- contentContainerStyle에 충분한 하단 여백
- keyboardShouldPersistTaps="handled" 또는 필요한 수준으로 설정
- keyboardDismissMode는 iOS에서 interactive 검토
- 중첩된 세로 ScrollView를 만들지 않음
- 학생별 TextInput 내부와 외부 ScrollView가 터치 충돌하지 않도록 구성
- 긴 공통 일지와 다수의 학생별 일지가 모두 끝까지 스크롤 가능
- 마지막 학생의 입력란이 ActionBar 위까지 올라올 수 있어야 함
- 키보드가 표시된 상태에서도 마지막 줄을 볼 수 있어야 함

세로 스크롤의 소유자는 하나여야 합니다.

AIInputArea, AIResultArea 또는 StudentNoteCard 내부에
별도의 세로 ScrollView가 있다면 구조를 점검하고
가능하면 최상위 콘텐츠 ScrollView로 통합하십시오.

━━━━━━━━━━━━━━━━━━━━━━
5. ActionBar는 키보드 위에 고정하십시오.
━━━━━━━━━━━━━━━━━━━━━━

ActionBar는 다음 조건을 충족해야 합니다.

- 입력창 내용과 함께 스크롤되지 않음
- 키보드 뒤에 숨지 않음
- 홈 인디케이터와 겹치지 않음
- Safe Area bottom 적용
- 버튼의 최소 터치 높이 확보
- 작은 화면에서도 버튼 전체가 노출
- 긴 결과에서도 항상 접근 가능
- 로딩 상태에서는 버튼 대신 진행 상태를 명확하게 표시
- 비활성 버튼도 터치 영역과 시각 상태가 명확함

ActionBar를 absolute로 덮어씌우지 말고
Header / Content / Footer의 정상적인 flex 구조로 배치하십시오.

━━━━━━━━━━━━━━━━━━━━━━
6. 입력 포커스 정책을 명확히 하십시오.
━━━━━━━━━━━━━━━━━━━━━━

모달을 처음 열었을 때는 키보드를 자동으로 띄우지 마십시오.

사용자가 입력창을 직접 탭했을 때만 키보드가 열려야 합니다.
