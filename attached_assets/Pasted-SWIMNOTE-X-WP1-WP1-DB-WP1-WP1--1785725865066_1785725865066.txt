1. 최종 확정 사항

방식 C 채택

WP1에서는 운영 DB의 PART 1 Migration 구조만 정리합니다.

백업 DB에는 initXModeSchema()를 실행하지 않습니다.

백업 DB 스키마 드리프트와 standby sync 실패는 현재 문제로 기록만 유지합니다.

이번 WP에서 백업 DB 복구 기능, 전용 Migration, 신규 WP를 만들지 마십시오.

운영 DB 실패 정책

필수 운영 DB Migration 실패 시:

오류 기록
→ 서버 준비 상태 전환 금지
→ 프로세스 종료

백업 DB 실패 정책

현재 기존 정책을 유지합니다.

백업 DB 초기화 실패
→ 경고 기록
→ 운영 서버 계속 기동

이번 WP에서 백업 DB 정책을 추가 변경하지 마십시오.

2. 중요 정정 — DB 파라미터화 금지
━━━━━━━━━━━━━━━━━━━━━━

조사 보고서에서는 다음 변경을 제안했습니다.

initXModeSchema(db: Db)

그러나 방식 C에서는 백업 DB에 X Migration을 실행하지 않습니다.

따라서 DB 파라미터화는 불필요합니다.

기존 구조를 유지하십시오.

export async function initXModeSchema(): Promise<void> {
  const db = superAdminDb;
  // PART 1 Migration
}

금지:

* initXModeSchema(db)로 시그니처 변경
* backupDb 전달
* getBackupDb import 추가
* 백업 DB X 스키마 적용
* 백업 DB 일반 스키마 수정

변경 범위를 최소화하십시오.

8. index.ts 실패 처리

현재 개별 Promise 오류를 삼키는 구조를 제거하십시오.

목표 동작:

Promise.all([
  initPoolDb(),
  initSuperDb(),
])
  .then(() => {
    setServerReady();
    console.log("[server] DB 초기화 완료 — 헬스체크 200 응답 시작");
  })
  .catch((error) => {
    console.error("[FATAL] DB 초기화 실패 — 서버 기동 중단:", error);
    process.exit(1);
  });

Repository의 기존 코드 형식에 맞춰 작성하되, 의미는 변경하지 마십시오.
