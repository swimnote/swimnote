0. LOCKED X TRIAL POLICY
==================================================

X Trial 정책:

- 센터당 최초 1회
- 기간 3일
- 자동결제 없음
- 결제수단 사전등록 없음
- RevenueCat 표준 Trial 사용 안 함
- 서버 grant 방식
- Trial 종료 후 자동 유료전환 없음
- Trial 종료 후 X 전용 기능만 잠금
- 기존 일반 SWIMNOTE 데이터 삭제 금지
- 센터 맞춤 X 세팅은 결제 후에만 시작
- Trial 중에는 즉시 사용 가능한 AI 기능만 허용

==================================================
2. X Trial DB 컬럼
==================================================

`swimming_pools`에 최소 다음 컬럼을 추가하십시오.

필수:

x_trial_started_at TIMESTAMPTZ NULL

x_trial_ends_at TIMESTAMPTZ NULL

x_trial_used_at TIMESTAMPTZ NULL

`x_trial_used_at`은
센터가 Trial을 이미 한 번 사용했는지 영구적으로 판별하는 용도입니다.

정책:

Trial 최초 활성화 시:

x_trial_started_at = NOW()
x_trial_ends_at = NOW() + 3 days
x_trial_used_at = NOW()

Trial 종료 후:

x_trial_used_at는 절대 NULL로 되돌리지 않음.

Trial 재사용 방지.

==================================================
3. 센터당 최초 1회 제한
==================================================

서버에서 반드시 강제하십시오.

APP UI만으로 제한하면 안 됩니다.

Trial activate 요청 시:

IF x_trial_used_at IS NOT NULL
→ 거부

권장 에러코드:

X_TRIAL_ALREADY_USED

HTTP status는 현재 API convention에 맞게 사용.

Trial 시작 후 같은 요청을 반복 호출해도
Trial 시간이 연장되면 안 됩니다.

예:

첫 호출:
09/01 10:00

ends:
09/04 10:00

두 번째 호출:
09/01 11:00

절대:
09/04 11:00

으로 연장되면 안 됨.

==================================================
5. Paid X 사용자는 Trial 금지
==================================================

이미 X를 구매한 센터가 Trial을 눌러서는 안 됩니다.

다음 중 실제 entitlement 판단 함수를 재사용:

x_paid_entitlement
x_manual_entitlement
resolveEffectiveXEntitlement
또는 현재 authoritative helper

이미 유효한 X entitlement이면:

X_TRIAL_NOT_ELIGIBLE

등 현재 convention에 맞는 에러 반환.

Trial은 신규 X 체험용입니다.

==================================================

`x_force_disabled = true`이면
Trial보다 우선합니다.

즉:

force_disabled
→ x_trial 모드 진입 금지

기존 강제비활성 정책을 Trial이 우회하면 안 됩니다.

==================================================
7. Trial mode 계산
==================================================

Mode 계산 우선순위는 기존 X 상태를 깨지 않는 선에서 추가하십시오.

권장 의미:

IF force_disabled
→ normal 또는 기존 disabled 처리

ELSE IF valid paid/manual X entitlement
→ 기존 x / x_pending 로직

ELSE IF trial active
→ x_trial

ELSE
→ normal

Trial active 정의:

x_trial_started_at IS NOT NULL
AND
x_trial_ends_at > NOW()
AND
x_trial_used_at IS NOT NULL

중요:

paid entitlement가 생기면 Trial보다 paid X가 우선.

예:

Trial 중 X 결제 완료
→ 즉시 x_active/x_pending 흐름
→ x_trial UI 계속 보이면 안 됨

==================================================
8. Trial 만료 처리
==================================================

Trial은 3일이 지나면 자동으로 비활성으로 판정되어야 합니다.

중요:

반드시 background worker가 실행되어야만
Trial이 끝나는 구조로 만들지 마십시오.

최소한 모든 mode 계산/API에서:

x_trial_ends_at <= NOW()
→ expired

로 즉시 판정해야 합니다.

즉 worker 장애가 나도
3일 Trial이 무한 연장되면 안 됩니다.

worker는 cleanup/정리용으로 추가 가능하지만
authorization source of truth가 되어서는 안 됩니다.

24. 1.6.3 backward compatibility
==================================================

1.6.3 앱은 x_trial 상태를 모릅니다.

따라서 기존 1.6.3이 사용하는 API response에
breaking enum을 강제로 넣어 앱이 죽는 구조가 없는지 확인하십시오.

필요하면:

- 신규 2.0 전용 additive field
- 기존 field는 legacy fallback

방식으로 처리.

특히 기존 mode consumer가
unknown `"x_trial"`에서 crash하는지 확인.

만약 1.6.3이 동일 mode endpoint의 string을 직접 소비하며
unknown mode가 위험하다면:

2.0 client에서만 additive field를 조합해 x_trial을 만드는
backward-compatible 방식 사용 가능.

단 추측하지 말고 실제 코드 근거로 결정.

완료보고에 반드시:

1.6.3 MODE COMPAT STRATEGY

제출.
