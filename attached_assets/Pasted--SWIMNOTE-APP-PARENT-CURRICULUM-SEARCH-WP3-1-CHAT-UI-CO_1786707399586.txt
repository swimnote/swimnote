==================================================
1. RETRY REQUEST_ID
==================================================

실패한 질문의 "다시 시도"는 반드시:

동일 query
+
동일 request_id

를 재사용해야 한다.

새 request_id 생성 금지.

이유:

서버 WP2B.2에서
FAILED request_id:

FAILED
→ RESERVED
→ ENGINE retry
→ COMPLETED

idempotency flow가 구현되어 있음.

확인:

- 최초 질문 request_id 생성 위치
- optimistic message에 request_id 보존 여부
- retry handler가 같은 request_id를 사용하는지

새 ID를 생성하고 있다면 수정.

==================================================
2. COMPLETED DUPLICATE SAFETY
==================================================

네트워크 지연 등으로 사용자가
동일 성공 요청을 다시 보내도

동일 request_id라면 서버에서
persisted result replay가 동작해야 한다.

UI가 retry 과정에서 request_id를 바꾸지 않아야 함.

==================================================
8. ASSISTANT MESSAGE
==================================================

성공 시 Assistant bubble 1개만.

retry 성공 후에도 1개만.

COMPLETED replay에서도
새 Assistant bubble을 추가해서 중복시키지 않는다.

request_id 기준 reconciliation 확인.

==================================================
9. LOADING / DOUBLE TAP
==================================================

ENGINE 요청 진행 중:

동일 질문 전송 버튼 연타 차단.

동시에 같은 optimistic message에 대해
복수 request 발생 금지.

단 다른 질문을 동시에 허용하는 구조라면
quota concurrency가 서버에서 보호되더라도
현재 UI 정책을 명확히 보고.

출시 기준 권장:
한 번에 1개 질문 처리.
