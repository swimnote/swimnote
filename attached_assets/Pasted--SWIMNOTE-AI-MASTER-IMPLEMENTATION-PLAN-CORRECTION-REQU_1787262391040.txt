## 2. logical request와 actual provider calls 구분

현재 retry_count만으로는 비용 추적이 충분하지 않을 수 있습니다.

다음 두 개념을 분리하십시오.

### logical_request_count

사용자 또는 시스템이 요청한 기능 단위.

예:

Growth Report 생성 1건

→ logical request = 1

### actual_provider_call_count

provider에 실제 전송된 호출 수.

예:

최초 호출 1
+
retry 2

→ actual provider calls = 3

→ retry_count = 2

Dashboard 비용은 실제 provider calls와 실제 usage 기준으로 계산되어야 합니다.

Common Usage Contract 및 Implementation Plan에 이를 반영하십시오.

기존 `request_count` 필드를 어느 의미로 사용할지 명확히 고정하십시오.

필요하다면:

logical_request_count
actual_call_count

처럼 의미를 분리하는 안을 제안하십시오.

Migration 없이 JSONB 확장으로 처리합니다.
