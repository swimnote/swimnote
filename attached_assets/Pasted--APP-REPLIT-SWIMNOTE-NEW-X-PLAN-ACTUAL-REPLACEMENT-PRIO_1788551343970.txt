============================================================

구조:

[기본 플랜]
- 신규 공식 BASE plan 목록

UI component에 가격을 직접 하드코딩하지 않는다.

============================================================
5. Super Admin 직접 부여
============================================================

Super Admin은 결제 없이 특정 수영장에
신규 X 플랜을 직접 부여할 수 있어야 한다.

예:

Super Admin
→ 수영장
→ 구독·결제
→ X 플랜 선택
→ 저장

이 경우:

RevenueCat 결제:
필요 없음

x_manual_entitlement:
true

x_paid_entitlement:
변경하지 않음

x_force_disabled:
false

x_plan_key:
선택한 신규 X plan key

x_plan_member_limit:
선택한 신규 X plan의 공식 회원 한도

effective X:
true

Source:
MANUAL

즉:

"결제 플랜을 가짜 paid로 만드는 방식" 금지.

Super Admin 직접 부여는 반드시 MANUAL entitlement로 처리.

============================================================
6. 직접 부여와 유료 결제 분리
============================================================

Paid X:

RevenueCat / 실제 결제
→ x_paid_entitlement

Manual X:

Super Admin 직접부여
→ x_manual_entitlement

둘은 독립.

Effective X:

(x_paid_entitlement OR x_manual_entitlement)
AND NOT x_force_disabled

현재 resolver 유지.
