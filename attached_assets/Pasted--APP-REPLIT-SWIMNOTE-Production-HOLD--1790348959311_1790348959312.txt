1. education_started_at 타입 확인
━━━━━━━━━━━━━━━━━━━━━━

원래 설계:

education_started_at DATE NULL

이었으나 완료보고에는:

education_started_at TEXT

로 생성했다고 보고했습니다.

먼저 실제 Production schema를 확인하십시오.

보고:

- 실제 PostgreSQL data type
- TEXT로 만든 이유
- 저장되는 실제 값 형식
- 모든 query에서 date cast를 하고 있는지

특별한 호환 이유가 없다면
education_started_at은 DATE가 더 정확한 의미입니다.

현재 신규 컬럼에 실데이터가 거의 없거나
안전하게 변환 가능한 상태라면

TEXT → DATE

비파괴 migration을 검토하십시오.

단 데이터 손실 가능성이 있으면
임의 ALTER 금지하고 HOLD 보고.

2. “1개월 이상” 판정 정확성
━━━━━━━━━━━━━━━━━━━━━━

정책은:

suspended_at + calendar 1 month
<= 재등록 시점

이면 장기연기입니다.

즉 “1개월 초과”가 아니라
정확히 1개월이 되는 순간부터 적용입니다.

실제 코드 operator를 확인하십시오.

필수:

>= threshold 또는
reactivation >= suspended_at + interval '1 month'

의 의미여야 합니다.

KST 날짜 기준도 확인하십시오.

TEST:

A.
2026-01-15 연기
2026-02-14 복귀
→ 일반 연기

B.
2026-01-15 연기
2026-02-15 복귀
→ 장기연기

C.
2026-01-31 연기
calendar month 계산 결과 확인

D.
윤년/2월 월말

각 결과를 보고하십시오.

30일 고정 계산 금지.
