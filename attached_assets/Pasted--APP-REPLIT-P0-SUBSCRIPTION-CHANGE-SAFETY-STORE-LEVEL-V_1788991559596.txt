1. iOS SUBSCRIPTION GROUP 확인
━━━━━━━━━━━━━━━━━━━━━━

App Store Connect 설정을 코드만으로 추정하지 말 것.

현재 RevenueCat/App Store Connect 구성에서
다음 4개가 동일 subscription group인지 실제 확인:

- com.swimnote.swimnote.monthly
- com.swimnote.x300.monthly
- com.swimnote.x500.monthly
- com.swimnote.x1000.monthly

같은 group이어야 함.

또한 subscription level/rank 확인:

SWIMNOTE < X300 < X500 < X1000

의도한 upgrade/downgrade 관계가 되도록 Store 설정 확인.

결과:
- SAME_GROUP_CONFIRMED
또는
- DIFFERENT_GROUP / UNKNOWN

UNKNOWN이면 PASS 금지.

4. ANDROID PRODUCT CHANGE
━━━━━━━━━━━━━━━━━━━━━━

중요.

Google Play custom purchase flow에서
다른 subscription product 변경 시
단순 Purchases.purchasePackage(targetPackage)만 호출하면
별도 구독이 동시에 생성될 위험이 있음.

현재 react-native-purchases SDK 버전/지원 API 확인.

기존 paid subscription이 있으면 Android에서는:

- old product identifier
- replacement mode

를 명시하는 product-change purchase flow 사용.

정책:

UPGRADE:
SWIMNOTE → X
X300 → X500/X1000
X500 → X1000

→ 현재 제품 정책에 맞는 upgrade replacement mode 사용.

DOWNGRADE:
X1000 → X500/X300/SWIMNOTE
X500 → X300/SWIMNOTE
X300 → SWIMNOTE

→ DEFERRED
즉 현재 결제기간 종료 후 target plan 시작.

RevenueCat/Google Play 현재 SDK에서
DEFERRED 지원 방식 정확히 확인 후 구현.

지원되지 않으면 임의 purchasePackage 금지.
그 경우 Android downgrade CTA는 안전한 management flow로 전환하고 보고.
