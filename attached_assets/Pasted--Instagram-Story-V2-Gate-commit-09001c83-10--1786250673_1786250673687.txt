1. AI summary 결과 최종 fit 검증 필수
━━━━━━━━━━━━━━━━━━━━━━

현재:

max_lines를 Prompt에 지시
→ 반환된 summary를 그대로 Story에 사용

은 불충분하다.

LLM은 max_lines 지시를 초과할 수 있다.

따라서 summary 응답을 받은 후
클라이언트에서 반드시 다시:

storyTextFits(summary, photoCount)

를 실행한다.

결과:

PASS
→ Story 생성 진행

FAIL
→ 절대 overflow:hidden으로 잘라서 공유하지 않는다.

우선 가장 안전한 최소 방식:

한 번 더 더 짧게 요약 요청할 수 있도록
서버 endpoint가 target max_lines를 더 줄여 재요약하거나,

최종적으로도 fit 실패하면:

Alert:
"스토리 요약을 만들지 못했습니다.
잠시 후 다시 시도해주세요."

→ Instagram 미실행

무음 clipping 금지.

━━━━━━━━━━━━━━━━━━━━━━
2. overflow:hidden을 안전장치로 사용 금지
━━━━━━━━━━━━━━━━━━━━━━

StoryPageRenderer의:

overflow: "hidden"

이 레이아웃 보호 목적으로 존재하는 것은 허용하더라도

"텍스트가 넘쳐도 그냥 잘려도 된다"

는 로직으로 사용하지 않는다.

StoryCapturePipeline 진입 전에:

원문 또는 summary가
storyTextFits === true

임을 보장해야 한다.

즉 Renderer는 이미 fit 검증된 text만 받는 구조로 만든다.

본문 일부가 조용히 사라지는 CASE = 0이어야 한다.

━━━━━━━━━━━━━━━━━━━━━━
3. Summary cache key 수정
━━━━━━━━━━━━━━━━━━━━━━

현재:

key:
@sn:story_summary_<diaryId>

value:
{
  hash: simpleHash(bodyText),
  summary
}

문제:

같은 diary 본문이어도
사진 수가 바뀌면 Story text 허용 줄 수가 달라진다.

또 Story layout 규칙이 바뀌어도
기존 summary를 잘못 재사용할 수 있다.

따라서 cache validity에 최소:

- bodyText hash
- maxLines

를 포함한다.

예:

{
  hash: simpleHash(bodyText),
  maxLines,
  summary
}

cache hit 조건:

cached.hash === currentHash
AND
cached.maxLines === currentMaxLines
AND
storyTextFits(cached.summary, photoCount) === true

셋 다 만족할 때만 재사용.

하나라도 불일치:
→ summary 재생성.

━━━━━━━━━━━━━━━━━━━━━━
4. 25자/줄 계산의 역할 명확화
━━━━━━━━━━━━━━━━━━━━━━

25 chars/line 계산은
AI 호출 여부를 결정하는 빠른 사전 추정치로 사용 가능.

하지만 최종 출력 안전성은:

storyTextFits(finalText, photoCount)

재검증을 거쳐야 한다.

영문/숫자/긴 문자열/줄바꿈 조합에서도
본문이 잘리지 않는지 CASE 추가.

대규모 text measurement engine 도입은 이번 작업에서 금지.
최소 수정으로 처리한다.

━━━━━━━━━━━━━━━━━━━━━━
5. Summary API 인증 재확인
━━━━━━━━━━━━━━━━━━━━━━

POST /diaries/:diaryId/story-summary는
반드시 기존 parent 인증 middleware를 거쳐야 한다.

확인:

- 인증되지 않은 사용자 → 401
- 다른 학부모 diary → 403/404
- 현재 학부모 자녀에게 보이는 diary만 허용
- 다른 학생 student note가 prompt에 절대 포함되지 않음

OpenAI 호출 전에 visibility 검증 완료.

API_KEY 및 Prompt 원문은 앱에 노출하지 않는다.

6. 테스트 CASE 추가
━━━━━━━━━━━━━━━━━━━━━━

기존 CASE 1~7 + 다음 추가:

CASE 8
AI가 max_lines보다 긴 summary 반환
→ client fit FAIL 감지
→ 잘린 Story 공유 금지

CASE 9
동일 diary 본문 + 사진 수 변경
예: 1장 → 10장
→ 기존 cache 무조건 재사용 금지
→ maxLines 기준 재판정

CASE 10
cache summary가 현재 layout에 안 들어감
→ cache miss 처리

CASE 11
한글 + 영어 + 숫자 + 강제 줄바꿈 혼합
→ 최종 Story text 잘림 없음

CASE 12
다른 학부모가 diaryId를 임의로 호출
→ 접근 차단
→ OpenAI 호출도 발생하지 않음
