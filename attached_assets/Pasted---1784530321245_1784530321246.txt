최종 확인 보고서 보완 요청

현재 보고서는 전체 방향은 맞지만, 아래 문제를 수정하지 않은 상태에서는 작업을 승인하지 않습니다.

이번 작업은 현재 상태만 기준으로 회원을 숨기는 작업이 아니라,
각 수업 날짜 당시의 회원 소속과 상태를 정확히 복원하는 날짜 시스템 구축입니다.

==================================================

1. 현재 status 조건을 날짜 조회에 직접 사용하면 안 됩니다

현재 제안된 조건:

AND s.status NOT IN ('withdrawn', 'deleted', 'suspended')

이 조건을 과거 날짜 조회에 그대로 사용하면 문제가 발생합니다.

예)

7월에는 정상 수업
8월부터 연기

현재 status = suspended

이 상태에서 7월 스케줄을 조회하면
현재 status가 suspended라는 이유로 7월 과거 수업에서도 회원이 사라질 수 있습니다.

퇴원도 동일합니다.

예)

7월까지 정상 수업
8월부터 퇴원

현재 status = withdrawn

현재 상태값으로 필터링하면
정상적으로 수업했던 7월 과거 기록에서도 회원이 사라질 수 있습니다.

이것은 과거 기록 유지 원칙에 위배됩니다.

따라서 스케줄, 출결, 일지의 날짜별 회원 판정은
현재 students.status만으로 제외하지 말고
student_class_history의 해당 날짜 유효 구간을 기준으로 판단해야 합니다.

현재 status는 현재 회원관리 화면의 상태 표시에는 사용할 수 있지만,
과거 수업 날짜의 회원 포함 여부를 결정하는 절대 조건으로 사용하면 안 됩니다.

deleted처럼 실제 삭제 처리된 데이터만 별도 제외할 수 있습니다.

suspended와 withdrawn은 적용 날짜를 기준으로 판단해야 합니다.

==================================================

2. left_at의 의미를 하나로 확정해야 합니다

현재 조건:

h.enrolled_at <= 수업날짜
AND (h.left_at IS NULL OR h.left_at > 수업날짜)

그런데 기존 설명에서는

연기 또는 퇴원 시작일 - 1일을 left_at으로 저장한다고 했습니다.

이 두 방식은 서로 맞지 않습니다.

예)

8/1부터 연기

left_at = 7/31로 저장

조건이 left_at > 수업날짜라면

7/31 조회 시

7/31 > 7/31이 false가 되어
7/31에도 회원이 제외됩니다.

따라서 다음 두 방식 중 하나로 전체 시스템을 통일해야 합니다.

방식 A. left_at을 마지막 참여일로 저장

예)

8/1부터 연기
left_at = 7/31

조회 조건:

h.enrolled_at <= 수업날짜
AND (h.left_at IS NULL OR h.left_at >= 수업날짜)

방식 B. left_at을 제외 시작일로 저장

예)

8/1부터 연기
left_at = 8/1

조회 조건:

h.enrolled_at <= 수업날짜
AND (h.left_at IS NULL OR h.left_at > 수업날짜)

어느 방식을 사용할지 먼저 확정하고,

- today-schedule
- attendance
- diary
- parent
- photos
- students
- 반 이동
- 연기
- 퇴원
- 미배정

전체에서 같은 의미와 같은 비교식을 사용해야 합니다.

파일마다 left_at을 다르게 해석하면 안 됩니다.

==================================================

3. 연기 처리는 반 이력 종료만으로 충분한지 확인해야 합니다

연기 시작 시 기존 반 이력을 종료하고,
복귀 시 새 student_class_history row를 추가해야 합니다.

반드시 다음 흐름이 연결되어야 합니다.

연기 시작일 지정
→ 기존 반 이력 종료

연기 기간
→ 어느 정규 수업에도 미표시

복귀일 지정
→ 기존 반 또는 선택한 반으로 새 이력 생성

복귀 시 새 이력이 자동 생성되지 않으면
연기 종료 후에도 회원이 스케줄에 다시 나타나지 않습니다.

현재 시스템에서 복귀 처리가 새 history row 생성까지 연결되는지 확인해 주세요.

==================================================

4. 기존 suspended 회원을 현재 status 조건으로 숨기는 것은 해결이 아닙니다

보고서에는 기존 suspended 회원의 left_at이 없어도
status 조건으로 제외되므로 문제가 없다고 되어 있습니다.

하지만 이것은 현재 화면에서는 숨길 수 있어도
과거 날짜 기록까지 함께 사라질 수 있으므로 올바른 해결이 아닙니다.

기존 suspended 회원은 다음 기준으로 처리해야 합니다.

- 실제 연기 시작일을 복원할 수 있으면 해당 날짜로 이력 종료
- 복원할 수 없으면 임의로 오늘 날짜를 넣지 않음
- 데이터 영향 범위를 먼저 확인
- 과거 기록을 파괴하지 않는 방식으로 처리

withdrawn도 동일한 원칙을 적용합니다.

withdrawn_at이 있다면 해당 날짜를 기준으로 이력을 종료하되,
left_at의 의미와 비교 조건을 먼저 통일해야 합니다.

==================================================

5. 기존 회원의 첫 수업일 수동 보정 화면 확인

보고서에는 기존 데이터를 관리자가 직접 수정할 수 있는 화면을 통해
수동 보정한다고 되어 있습니다.

현재 실제로 다음 기능이 존재하는지 확인해 주세요.

- 기존 반 이력 조회
- enrolled_at 수정
- 수정 전 기존 일지·출결·사진 영향 확인
- 잘못 수정했을 때 복구 가능 여부

현재 수정 화면이 없다면
존재하는 것처럼 보고하지 말고
추가 작업이 필요한지 명확히 작성해 주세요.

이번 작업에서 별도 관리 화면을 추가하지 않는다면
기존 데이터는 자동 추측 수정 없이 유지합니다.

==================================================

6. 부분 배포로 날짜 기준이 일시적으로 달라지면 안 됩니다

현재 작업 순서는

1. today-schedule, parent, photos 먼저 배포
2. attendance 수정 배포
3. diary 수정 배포
4. students 수정 배포
5. 앱 OTA

로 되어 있습니다.

이 방식은 작업 중간에

- 스케줄은 새 날짜 기준
- 출결은 구 날짜 기준
- 일지는 구 날짜 기준

으로 서로 다른 결과가 나오는 시간이 생깁니다.

이번 작업의 목적은 날짜 시스템 통일이므로
가능하면 서버 수정 사항을 모두 완료하고 함께 배포해야 합니다.

최소한 외부 사용자가 사용하는 운영 환경에서는
기능별 날짜 기준이 서로 다른 중간 상태가 오래 유지되면 안 됩니다.

권장 순서:

1. 서버 관련 코드 전체 수정
2. 서버 통합 테스트
3. 서버 한 번에 배포
4. 앱 첫 수업일 UI 수정
5. OTA 배포
6. 실제 앱 전체 검증

==================================================

7. 사진 테스트 범위를 날짜별 독립성까지 확대해야 합니다

현재 사진 테스트는

'나한테 보낸 사진만 표시'

만 확인하고 있습니다.

이번 날짜 시스템 작업에서 필요한 핵심 테스트는 다음입니다.

- 7/20 일지에 올린 사진이 7/27 일지에 나타나지 않음
- 같은 반의 다른 수업 날짜 사진이 섞이지 않음
- 다른 반 사진이 섞이지 않음
- 다른 학생 사진이 섞이지 않음
- 학부모에게 전송하지 않은 사진은 학부모 화면에 나타나지 않음
- 기존 사진 데이터가 삭제되지 않음

사진 조회는 최소한 다음 식별자를 기준으로 분리되어야 합니다.

- 수영장 또는 tenant
- 반
- 수업 날짜 또는 수업 고유 식별자
- 일지
- 학생
- 학부모 전송 대상

==================================================

8. 테스트에 과거 상태 복원 검증을 추가해야 합니다

다음 테스트를 반드시 추가합니다.

TEST 10.

7월 정상 수업 후 8월 연기된 회원

→ 7월 스케줄에는 표시

→ 8월 연기 기간에는 미표시

TEST 11.

7월 정상 수업 후 8월 퇴원한 회원

→ 7월 과거 스케줄과 일지에는 표시

→ 퇴원 적용일부터 미표시

TEST 12.

8/1부터 미배정 회원

→ 7/31까지 기존 반 표시

→ 8/1부터 미표시

TEST 13.

A반 마지막 참여일과 B반 첫 참여일 사이에 공백이 있는 회원

→ A반 종료일까지 A반 표시

→ 공백 기간 어느 반에도 미표시

→ B반 시작일부터 B반 표시

TEST 14.

연기 후 복귀 회원

→ 연기 전 과거 수업 표시

→ 연기 기간 미표시

→ 복귀일부터 다시 표시

TEST 15.

현재 withdrawn 또는 suspended 상태인 회원의 과거 날짜 조회

→ 과거 정상 참여 기간 기록이 사라지지 않음

==================================================

9. 기존 UI와 기능 보호 원칙

이번 작업은 날짜 시스템을 갖추는 작업이며
기존 화면을 다시 만드는 작업이 아닙니다.

다음 항목은 절대 임의로 수정하지 않습니다.

- 기존 기능
- 모달 크기
- 모달 위치
- 모달 내부 레이아웃
- 스크롤 방식
- 스크롤 영역 높이
- 탭 구조
- 탭 글자
- 글자 줄바꿈
- 글자 깨짐
- 폰트 크기
- 버튼 위치
- 아이콘
- 색상
- 여백
- 화면 전환
- 기존 컴포넌트 구조
- 기존 권한
- 기존 UX

코드 정리, 리팩토링, 컴포넌트 교체를 이유로
작업 범위 밖의 화면이나 기능을 수정하지 않습니다.

허용되는 UI 수정은
반 배정 모달에 첫 수업일 선택 기능을 추가하기 위해 필요한
최소 범위만 허용합니다.

첫 수업일 UI 추가 시에도 기존 모달의

- 크기
- 스크롤
- 버튼 위치
- 탭
- 글자 표시
- 레이아웃

을 최대한 그대로 유지해야 합니다.

기존 화면 변경이 불가피하다면
임의로 수정하지 말고 변경 대상과 이유를 먼저 보고해야 합니다.

==================================================

10. 코드 수정 전 다시 보고할 내용

아직 작업을 시작하지 마세요.

다음 항목만 보완하여 다시 보고해 주세요.

1. suspended와 withdrawn을 현재 status로 제외하지 않고 과거 기록을 유지하는 방법

2. left_at을 마지막 참여일로 사용할지, 제외 시작일로 사용할지

3. 선택한 left_at 기준을 모든 파일에 어떻게 통일할지

4. 연기 후 복귀 시 새 class history row 생성 여부

5. 기존 회원 enrolled_at 수동 수정 화면의 실제 존재 여부

6. 서버 변경 사항을 한 번에 배포할 수 있는지

7. 날짜별 사진 독립성을 어떤 식별자로 보장하는지

8. 기존 UI와 기존 기능을 변경하지 않는 보호 방법

위 항목이 확인되면 최종 승인하겠습니다.
