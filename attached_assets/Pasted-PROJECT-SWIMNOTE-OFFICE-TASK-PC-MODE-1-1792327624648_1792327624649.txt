[1. 직전 구현을 이어간다]

직전 로컬 커밋 dff142a0의 작업을 보존한다.
현재 HEAD·작업 트리가 달라도 임의 reset·checkout하지 않는다.

이미 구현한 다음은 재사용한다:
- 상담→회원→계약→반 배정→청구
- 재등록 조건의 반 배정 전달
- 회원 상세→미납→부분수납→배분
- 요청 ID 저장의 재시작 후 영수증 확인
- 가져오기 규칙 일괄 적용
- NFC 스캔 모드 입력 보호
- 검색·스크롤·리포트 조건 보존

같은 조사·검사·설치본 제작을 반복하지 말고 아래를 계속 구현한다.

[2. 우선 완료할 세 가지]

A. 회원 생성 결과 불명 복구
- 저장 후 응답이 끊겨도 회원 생성 성공 여부를 확인 가능하게 한다.
- 결과 확인 전 같은 생성 요청을 재전송하지 않는다.
- 이름·전화번호가 같다는 이유만으로 기존 회원이라고 확정하지 않는다.
- 기존 요청 ID·영수증 구조를 재사용하고 필요한 서버 보완만 한다.
- 재시작 후에도 복구가 이어지게 한다.
- 해결을 위해 별도 대형 저널 시스템을 만들지 않는다.

B. 성장리포트 관리자 흐름 완결
- 선택 회원·report_id·버전을 유지한다.
- 목록/회원 상세→본문→검수→발급→이력을 연결한다.
- 관리자 확인과 강사 검수, 발급과 발송을 구분한다.
- 완료 후 해당 보고서와 상태를 재조회한다.
- 뒤로 이동해도 검색·기간·선택 상태를 보존한다.
- 권한에 맞는 수정·재분석 요청만 제공한다.
- 당시 발행본을 현재 초안으로 덮어쓰지 않는다.
- 실제 발송·새 유료 모델 호출은 실행하지 않는다.

C. 관리자 현황·보고서·출력
- 회원·등록·재등록·출결·보강·수납·미납·환불·지출을
  기존 합의 범위에서 연결한다.
- 사람 수·계약 수·청구 건수·거래 건수를 구분한다.
- 기간 거래와 누적 잔액을 구분한다.
- 현황 숫자를 누르면 같은 조건의 상세 목록으로 이동한다.
- 가족 배분과 회원별 금액 귀속을 유지한다.
- Excel/CSV·인쇄·필요 PDF가 화면 조건 및 합계와 일치하게 한다.
- 현재 페이지만 출력하는지 검색 결과 전체인지 명확히 표시한다.
- 새 분석 엔진이나 별도 통계 원장을 만들지 않는다.

[3. 합의된 잔여 기능을 빠짐없이 마무리]

기존 설계·상태표와 코드의 차이만 확인하여 구현한다.

마케팅·홍보:
- 채널 관리 주소·자료·게시 일정·담당자·게시 링크
- 소개·공유 캠페인·참여·유입경로
- 홍보 동의와 단순 참여 구분
- 자동 연동이 없으면 수동 기록임을 표시

운영지원:
- 시설·물품·대회·참가·업체·본사 안내/신청
- 준비된 기존 자료와 관리 기능 재사용
- 미구현 화면을 예시 숫자로 실제 운영처럼 표시하지 않음

무료 AI 이전:
- 대화창에서 사용자 의견을 변환 규칙에 반영하는 연결
- 규칙 변경·취소·영향 미리보기
- 여러 파일 추가와 이전 결정 유지
- 회원·금융·잔여권리의 처리 상태 구분
- 단순 규칙 입력을 자연어 AI 해석 완료로 표시하지 않음
- 새 모델 호출 승인이 없으면 실행만 비활성으로 유지

태블릿·문서:
- 기존 신청·동의·서명·확정 문서 연결의 누락 보완
- 관리자 세션과 회원 입력 범위 분리
- 실제 태블릿·인쇄 미확인은 체크리스트에 유지

NFC:
- 스캔 모드 전용 수신인지 다른 업무 중 수신인지 명확히 구분
- 일반 입력칸 혼입 방지와 빠른 연속 출결 유지
- 다른 업무 중 수신은 지원 장치의 실제 연결 방식으로 구현
- 불가능한 장비까지 지원한다고 표시하지 않음
- 카드 등록·분실·재발급·중복 출결·알림 경계 연결
- 실장비가 없으면 해당 항목만 미확인
- 셔틀 NFC는 추가하지 않음

배차:
- 기존 설계 원문이 있으면 대조 후 합의 범위 구현
- 없으면 정확한 필요 문서만 표시하고 다른 구현 계속
- 원문 없이 임의로 재설계하지 않음

[4. PC 동선 개선 기준]

‘다음 행동을 찾느라 마우스가 멈추지 않는 전산’을 기준으로 한다.

- 관련 업무를 현재 상세·탭·짧은 모달에서 이어가기
- 회원·반·기간·금액 등 기존 선택을 다음 동작에 전달
- 저장·취소·다음·목록 복귀 규칙 통일
- 검색·필터·스크롤·선택·초안 보존
- 실패 항목만 수정·재처리 가능
- 단순 작업마다 확인창을 추가하지 않음
- 금액·삭제·대량변경·발송은 필요한 영향 요약 유지
- 키보드 이동·다중 선택·반복 입력 재사용
- AI 없이도 일반 업무 완결

동선 개선을 이유로 전체 레이아웃을 다시 만들지 않는다.
현재 공통 컴포넌트와 Action을 보완한다.

[5. 진행·검사·적용 경계]

PC 우선 개발을 유지한다.
앱 업데이트와 Smartro는 후속으로 분리한다.
공유 서버 변경은 기존 앱 호환성을 유지한다.

변경 범위의 컴파일·타입과
권한·금액·중복·복구에 필요한 직접 확인만 수행한다.
기존에 통과한 변경 없는 검사는 반복하지 않는다.

새 서버 코드·migration은 작성 가능하다.
운영 반영은 확정 SHA·영향·복구 방법을 묶어 별도 승인 요청한다.
이전 운영 승인으로 새 소스까지 자동 배포하지 않는다.

실발송·자동 알림 활성화·실결제·실환불·새 유료 호출·
실제 구독/가격/용량 정책 전환은 실행하지 않는다.

GitLab 인증 문제와 독립적인 개발은 계속한다.
실패하는 동일 인증 push를 반복하거나 다른 원격으로 우회하지 않는다.
로컬 소스·커밋·복구 자료는 보존한다.

[6. 전달 기준]

기능 하나 끝날 때마다 멈추거나 설치본을 만들지 않는다.
위 PC 잔여 기능을 모아 의미 있는 통합본으로 전달한다.
