SWIMNOTE Teacher Diary AI
WP10 — 실제 AI API 연동 및 End-to-End 통합 검증

이번 작업은 WP10만 수행한다.

이번 단계부터는 코드만 읽고 PASS를 주지 않는다.

목표

1. Teacher Diary AI가 실제 앱 환경에서 실제 API를 호출하는지 검증한다.
2. 텍스트 입력 → AI 생성 → 결과 편집 → Insert → Save까지 실제로 실행한다.
3. 가능하면 음성 녹음 → Whisper → AI 생성 경로도 실제로 실행한다.
4. 실행하지 못한 항목은 반드시 UNVERIFIED로 보고한다.
5. 발견된 실제 결함만 최소 수정한다.
6. WP1~WP9 구조는 변경하지 않는다.

절대 규칙

- 실행하지 않은 테스트를 실행했다고 보고하지 않는다.
- 코드 분석만으로 E2E PASS를 주지 않는다.
- 콘솔 출력만 보고 성공으로 판단하지 않는다.
- Mock 응답을 실제 API 응답이라고 보고하지 않는다.
- 실제 서버 요청·응답 증거 없이 API 성공이라고 보고하지 않는다.
- Production 직접 수정·배포 금지.
- 사용자 승인 없는 OTA 금지.
- 이번 작업 완료 후 멈춘다.

Mock 또는 placeholder이면 실제 연동 PASS를 주지 않는다.

3. 테스트용 안전 데이터 준비
──────────────────────────────────

실제 회원 개인정보를 사용하지 않는다.

가능하면 개발용 테스트 반·테스트 학생을 사용한다.

테스트 데이터 조건:

- 테스트 반 1개
- 테스트 학생 최소 2명
- 식별 가능한 실명 사용 금지
- 테스트 문구 사용
- 실제 사진·영상 사용 금지
- 저장된 테스트 일지는 테스트 후 식별 가능하게 기록

예시 테스트 입력:

“오늘은 자유형 발차기와 호흡 연결을 연습했습니다.
첫 번째 학생은 호흡 타이밍을 연습했고,
두 번째 학생은 발차기 리듬을 연습했습니다.”

보고서에는 입력 원문을 반복해서 노출하지 말고 테스트 데이터 사용 여부만 적는다.

──────────────────────────────────
7. 네트워크 증거 제출
──────────────────────────────────

실제 실행한 요청마다 개인정보를 제거한 증거를 제출한다.

필수:

- endpoint
- method
- status
- request_id
- 시작 시각
- 종료 시각 또는 duration
- response schema key 목록
- 실제 서버 host
- Mock 여부

예시:

POST /api/ai/diary/generate
status: 200
request_id: 존재
duration: 2.4s
response keys: request_id, schema_version, result
server: staging host
mock: false

본문, 학생 ID, 토큰은 제출하지 않는다.

스크린샷이 가능하면 다음을 제출한다.

- AI 입력 화면
- Processing 상태
- Result 화면
- Insert 후 일지 화면
- Save 완료 후 History 화면

스크린샷에 실제 회원 개인정보가 있으면 마스킹한다.
