결정 A — ai_status
━━━━━━━━━━━━━━━━━━━━━━

선택:

AI KPI 제외.

class_diaries에 ai_status migration 하지 않는다.

이번 PHASE에서 구현 금지:

- AI 생성 KPI
- AI 실패 KPI
- AI/직접작성 filter
- AI 생성 상태 chip
- AI 실패 warning
- growth_events를 AI 생성 여부 대리값으로 사용

이유:

현재 DB에는
"이 일지가 AI로 생성되었는지"
정확하게 영속 저장되는 source of truth가 없음.

클라이언트 useDiaryAIV2 state는
저장 후 서버 데이터가 아니므로
관리자 현황 근거로 사용 금지.

growth_events도
AI 생성 사실과 동일하지 않으므로
대리 판정 금지.

정확하지 않은 AI 현황을 만들어내지 말 것.

DB migration / Teacher write flow 변경은
이번 PHASE 범위 밖.

완료보고의 MISSING 항목에:

"AI 생성 출처/상태 영속 데이터 없음"

으로 명시.

━━━━━━━━━━━━━━━━━━━━━━
결정 B — 미작성/작성완료 KPI
━━━━━━━━━━━━━━━━━━━━━━

class_diaries는 일지 저장 시에만 row가 생성되고
common_content NOT NULL이므로:

- 작성완료 = total
- 미작성 = 계산 불가

따라서 중복/허위 KPI를 만들지 않는다.

PHASE 3 KPI는 정확한 실제 데이터 2개만 사용:

1. 오늘 일지
= 선택 날짜의 실제 class_diaries row 수

2. 학생 노트
= 해당 일지 범위의 class_diary_student_notes 실제 count

4칸 KPI 숫자를 맞추려고
중복 카드나 추정 수치를 추가하지 말 것.

"작성 완료"
"미작성"
문구는 이번 V1 KPI에서 제외.

viewOnly=true

- 수정 기능 숨김

- AI 생성/재생성 기능 숨김

현재 write 기능 그대로 유지.

새 Admin diary detail 화면 생성 금지.

수정 범위가 단순 viewOnly 처리보다 커지면
임의 확장하지 말고 STOP 후 보고.
