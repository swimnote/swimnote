SWIMNOTE 보강 — 실기기와 동일한 선생님 인증 경로 재검증

현재 보고서의 "코드 수정 불필요 / 문제 없음" 판정은 승인하지 않는다.

이유는 2개다.

1. DB/API 조사에서 배서준의 7월 expired 보강 2건이 실제 존재한다고 확인했는데,
   실기기 화면에는 해당 2건과 "기간 지난 보강 (N건)" 구분선이 보이지 않는다.

2. eligible-occurrences 검증에 pool_admin JWT를 사용했다.
   실제 오류가 발생한 화면은 teacher 앱이므로 동일 검증이 아니다.

코드 수정 금지.
Commit / Push / Render / OTA / DB 변경 금지.

pool_admin JWT 금지.

실기기와 동일한 teacher 공식 JWT로 다음 요청을 실행:

GET /api/teacher/makeups/<실제 makeup_id>/eligible-occurrences
?class_group_id=<실기기에서 실제 선택한 class_group_id>

제출:

- HTTP status
- response body
- teacher userId tail
- pool_id
- makeup_id
- class_group_id

HTTP 200이면
서버 teacher 인증 경로는 정상.

실패하면 실제 error code/body로 원인 확정.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
7. 앱에서 선택한 class_group_id 검증
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

실기기에서 선택한 반의 id와
실제 eligible-occurrences 요청 query의 class_group_id가
정확히 동일한지 확인한다.

반 이름만 같고 id가 다르면 실패다.

반드시 비교:

eligible-classes response id
↓
앱 selected class id
↓
eligible-occurrences query class_group_id

세 값 동일 여부.
