2. multi-pool parent + Kakao 구조 반드시 수정
==================================================

현재 보고서에 남은 위험:

동일 phone이 여러 pool의 parent_account에 존재하는 경우
phone fallback lookup이 LIMIT 1로 첫 계정을 고르고
그 계정에 kakao_id를 연결할 가능성이 있다.

이 구조는 제거한다.

먼저 실제 schema와 현재 Kakao login request contract를 확인한다.

목표 정책:

A. kakao_user_id가 이미 연결되어 있으면
→ 해당 exact external identity account 사용

B. kakao_user_id가 아직 없고 phone fallback이 필요한 경우
→ 현재 로그인하려는 pool_id가 제공되면
   반드시 phone + pool_id로 정확한 parent_account 조회

C. pool_id가 없는 구형 1.6.3 요청에서
동일 phone parent가 정확히 1개일 때만 자동 연결 가능

D. pool_id가 없고 동일 phone parent가 여러 개이면
LIMIT 1 임의 선택 금지

이 경우:
- 명확한 ambiguous 상태 반환
- 잘못된 account에 kakao_id UPDATE 금지

예:
KAKAO_PARENT_AMBIGUOUS

E. kakao_id를 한 parent에 연결할 때
이미 다른 parent에 같은 kakao_id가 연결돼 있으면 충돌 방지

unique/external identity 정책도 확인한다.

==================================================
3. 1.6.3 backward compatibility
==================================================

1.6.3은 현재 pool_id를 Kakao login에 보내는지 확인한다.

보내지 않는다면:

- single matched parent → 기존처럼 정상 로그인
- zero match → 기존 신규가입/phone_missing 흐름
- multiple match → 임의 연결 금지

multi-pool ambiguous 상태가 발생했을 때
1.6.3이 generic error로 안전하게라도 처리 가능한지 확인한다.

1.6.3 앱 수정 없이는 사용자에게 세밀한 안내가 불가능하더라도
서버가 잘못된 parent에 연결하는 것보다 실패하는 것이 우선이다.

5. phone_missing flow 최종 확인
==================================================

Kakao profile에서 phone scope 미동의:

- kakao_user_id 확보
- phone 없음
- 기존 계정 자동 오인 연결 금지
- phone_missing=true
- 가입/추가정보 화면으로 정상 이동

사용자가 직접 전화번호를 입력한 이후에는
기존 parent와 매칭할 수 있으면 중복 계정을 만들지 않고
기존 계정에 Kakao identity를 연결한다.

이 과정에서:
- same pool
- sibling child
- existing membership
모두 정상이어야 한다.
