[앱]

PHASE 1 — GROWTH REPORT FEED CARD
PREMIUM VISUAL SYSTEM DESIGN

목표:
성장리포트의 학부모 피드 노출 디자인을
SWIMNOTE의 대표적인 프리미엄 UI로 새로 설계한다.

이번 Step은
기능 연결/DB/서버/Instagram/PDF 다운로드 구현이 아니라

"성장리포트가 학부모 피드에서 어떤 모습으로 보여야 하는지"

최종 디자인 시스템과 실제 카드 UI를 만드는 작업이다.

임시 디자인 금지.
기존 카드에 색상만 조금 바꾸는 수준 금지.

==================================================
0. DESIGN QUALITY BAR
==================================================

이번 디자인은 반드시 다음 느낌을 목표로 한다.

- 세련됨
- 고급스러움
- 현대적
- 전문적
- 감성적이지만 유치하지 않음
- AI 서비스지만 기술 냄새 과하지 않음
- 학부모에게 신뢰감을 줌
- 어린이 교육 서비스지만 키즈카페 스타일 금지
- 병원 검사표/성적표 스타일 금지
- 흔한 SaaS dashboard 카드 스타일 금지

"무료 앱 화면"처럼 보이면 FAIL.

Apple의 정돈된 UI,
고급 교육 서비스,
프리미엄 리포트 제품을 참고한 밀도감을 목표로 한다.

단,
다른 서비스의 UI를 복제하지 말 것.

==================================================
1. FEED 안에서 바로 완성되어 보여야 함
==================================================

성장리포트는
"자세히 보기"를 눌러야 가치가 보이는 카드가 아니다.

피드에 나타난 순간
부모가 바로 다음을 느껴야 한다.

"이번 달 우리 아이 성장리포트가 왔구나."

따라서 피드 자체에
리포트의 시각적 정체성이 충분히 보여야 한다.

==================================================
2. 카드 기본 구조
==================================================

GrowthReportFeedCard 전용 UI를 만든다.

구조:

[상단 메타 영역]

- MONTHLY 성장 리포트
- 2026년 8월
- 학생 이름
- 필요하면 수영장명은 작은 secondary 정보

[리포트 비주얼 영역]

- 우리가 확정한 리포트 디자인 언어를 적용한
  전용 preview image / report visual

- 일반 텍스트 카드처럼 보이면 안 됨.

[한 줄 핵심 성장 요약]

예:
"자유형·IM·킥과 접영 글라이딩을 차례로 연습한 수업"

또는 실제 report summary에서
짧고 자연스러운 문장만 사용.

[하단 interaction 영역]

향후:
좋아요 / 댓글 / Instagram / PDF

이번 Step에서는 위치와 디자인만 구현.
실제 action logic은 다음 Step.

==================================================
3. VISUAL HIERARCHY
==================================================

카드에서 시선 순서:

1. 리포트라는 사실
2. 해당 월
3. 아이의 성장 리포트 이미지
4. 핵심 성장 한 줄
5. 하단 액션

학생 이름이나 시스템 정보가
리포트 제목보다 먼저 튀면 안 됨.

==================================================
4. COLOR SYSTEM
==================================================

기존 SWIMNOTE 색상 계열 유지:

- deep navy
- aqua / turquoise
- white
- very light blue/gray

단,
현재 앱의 평범한 파란 카드 느낌보다
한 단계 고급스럽게 정리.

원칙:

- 배경색 과다 금지
- gradient 남발 금지
- teal 과포화 금지
- 그림자 과다 금지
- border 과다 금지

포인트 색상은
1~2개만 사용.

==================================================
5. CARD SHAPE
==================================================

카드는 기존 일지 피드와
완전히 동떨어진 컴포넌트처럼 보이면 안 된다.

하지만
"성장리포트는 특별한 콘텐츠"
라는 느낌은 분명해야 한다.

권장:

- 충분한 white space
- 큰 radius
- 아주 미세한 border 또는 shadow
- section 내부 padding 충분
- 카드 전체 폭은 기존 feed width와 정렬

과도한 floating card 스타일 금지.

==================================================
6. REPORT PREVIEW VISUAL
==================================================

가장 중요.

피드 안에 들어가는 report preview는
PDF 페이지 전체를 그냥 축소한 썸네일처럼
작게 넣지 말 것.

모바일 피드에 맞는
전용 composition으로 만들어야 한다.

포함 가능 요소:

- SwimNote AI REPORT 로고
- MONTHLY 성장 리포트
- 2026년 8월
- 서태웅
- 현재 커리큘럼 진도율
- 이번 달 핵심 성장 1~2개
- 얇은 progress visualization
- 성장 내용 일부

단,
정보를 너무 많이 넣지 말 것.

사용자가 스크롤하면서도
한눈에 읽을 수 있어야 한다.

==================================================
7. CURRICULUM PROGRESS
==================================================

진도 완료율은
숫자만 딱 보여주는 성적표 방식 금지.

예:

현재 커리큘럼
────────────── 48.7%

또는 세련된 progress bar.

색상/두께 최소화.

점수나 성적처럼 보이지 않게
"현재 교육과정 위치" 느낌으로 표현.

==================================================
8. TYPOGRAPHY
==================================================

한글 기준으로 정교하게 조절.

Title:
강하지만 무겁지 않게.

Metadata:
작고 명확하게.

Body:
읽기 쉬운 line-height.

숫자:
본문보다 조금 또렷하게.

font weight 남발 금지.

한 카드 안에서
font size 종류 4개 이하 권장.

==================================================
9. ICONOGRAPHY
==================================================

임시 emoji 금지.

기존 app icon set 또는
일관된 vector icon 사용.

성장리포트의 icon은
기존 "AI 성장 리포트" 작은 그림 아이콘을
그대로 무조건 재사용하지 말고
전체 디자인과 맞는지 검토.

아이콘이 디자인을 싸 보이게 하면
텍스트 중심으로 정리.

==================================================
10. ACTION BAR PLACEHOLDER
==================================================

카드 하단에 다음 4개 액션 위치를 디자인한다.

- 좋아요
- 댓글
- Instagram
- PDF

이번 Step에서는
touch action 실제 연결하지 않는다.

단,
Instagram은 일반 share icon과 구분되는
Instagram 의미가 명확해야 한다.

PDF는 다운로드 의미가 명확해야 한다.

버튼 4개가 너무 커서
toolbar처럼 보이지 않게.

Instagram 피드의 가벼운 interaction bar처럼
콘텐츠의 일부로 자연스럽게 위치.

==================================================
11. "자세히 보기" 정책
==================================================

기존처럼 큰
"자세히 보기 >"
CTA는 제거하거나 매우 약하게 처리.

리포트 자체를 tap하면
상세화면으로 이동하는 구조는 유지 가능.

하지만
사용자가 상세로 들어가지 않아도
피드에서 충분히 내용을 소비할 수 있어야 한다.

16. PASS 기준
==================================================
