SWIMNOTE 댓글·반응 실제 연동 오류 및 개발용 하단 탭 노출 수정

현재 production 앱 실제 테스트 결과:

1. 학부모 댓글 작성 시 “전송에 실패했습니다” 서버 오류 발생
2. 좋아요는 학부모 화면에서 눌린 상태로 보임
3. 감사합니다는 여전히 눌리지 않음
4. 학부모가 누른 좋아요가 선생님 지난 일지 카운트에 반영되지 않음
5. 학부모 댓글이 선생님 화면으로 넘어오지 않음
6. 하단 탭바에 `diary-rea...` 개발용/내부 라우트 탭이 갑자기 노출됨
7. 사진·영상 화면은 현재 정상으로 보이므로 건드리지 말 것

이번 작업은 UI 생성이 아니라
학부모 → API → DB → 선생님 화면 연결을 실제로 완성하는 작업입니다.

- 목록 API가 오래된 캐시 반환
- 실제 화면이 다른 API를 사용
- production backend 미배포

실제 reaction row를 production DB에서 확인하세요.

필수 보고:

reactionId=
diaryId=
studentId=
parentUserId=
reactionType=
createdAt=

그 diaryId가 선생님 지난 일지 카드의 diaryId와 정확히 같은지 비교하세요.

7. 선생님 일지 목록 집계 SQL 수정
==================================================

선생님 지난 일지 API에서 각 diary별로 정확히 집계하세요.

개념:

SELECT
  cd.id,
  ...
  COUNT(DISTINCT dr.id)
    FILTER (WHERE dr.reaction_type = 'like') AS like_count,
  COUNT(DISTINCT dr.id)
    FILTER (WHERE dr.reaction_type = 'thanks') AS thank_count,
  COUNT(DISTINCT dm.id)
    FILTER (
      WHERE dm.message_type = 'diary_comment'
      AND dm.parent_comment_id IS NULL
      AND dm.is_deleted = false
    ) AS comment_count

주의:

반응 JOIN과 댓글 JOIN을 동시에 하면 row가 곱집합으로 늘어날 수 있습니다.

예:

reaction 2개 × comment 3개 = 6 rows

따라서 다음 중 하나를 사용:

- correlated subquery
- LATERAL subquery
- 집계 CTE
- COUNT(DISTINCT ...)

집계값이 정확한지 DB 원본 row와 비교하세요.

8. 학부모 댓글이 선생님에게 안 넘어오는 문제
==================================================

댓글 전송 자체가 실패하고 있으므로 우선 INSERT를 정상화하세요.

그 후 선생님 반응·댓글 화면의 조회 API를 확인하세요.

GET /api/diaries/:id/comments

선생님 권한일 때:

- 해당 diary의 모든 학부모 원댓글
- 각 원댓글의 답글
- studentId
- studentName
- parent 표시명
- createdAt

을 반환해야 합니다.

학부모 권한일 때:

- 본인 parentUserId
- 본인 studentId

스레드만 반환합니다.

서버가 역할에 따라 응답 범위를 다르게 처리해야 합니다.
