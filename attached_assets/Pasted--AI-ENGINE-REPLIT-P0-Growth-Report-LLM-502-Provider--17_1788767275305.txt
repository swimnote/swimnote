[P0 — Growth Report LLM 502 종료: Provider 경로 단일 원인 수정]

현재 작업을 즉시 정리한다.

지금까지 확정된 사실:

1.
"snapshot students: 0"은 오진.
debug script가 잘못된 key를 참조한 것이며
실제 diary source는 존재함.

2.
실제 차단 원인은 Growth Report Engine:

POST /api/v1/growth-report/analyze

에서 반복 발생하는:

HTTP 502
LLM Provider Connection error

3.
원인 후보가 이미 확인됨:

AI_INTEGRATIONS_OPENAI_BASE_URL
= localhost 기반 Replit proxy

Render Production에서는 localhost:1106 접근 불가.

4.
Teacher Diary에서는 이미 같은 문제를 해결함:

OPENAI_API_KEY가 존재하면
direct OpenAI 사용
(baseURL undefined)

OPENAI_API_KEY가 없을 때만
AI_INTEGRATIONS_OPENAI_* fallback 사용.

이번 목표:
Growth Report Engine의 LLM client도
Teacher Diary와 동일한 Production-safe provider 정책으로 통일한다.

4. 최소 수정
━━━━━━━━━━━━━━━━━━━━━━

Growth Report에서도 Teacher Diary와 동일한 정책 사용:

const openai = new OpenAI({
  apiKey:
    process.env.OPENAI_API_KEY ??
    process.env.AI_INTEGRATIONS_OPENAI_API_KEY,

  baseURL:
    process.env.OPENAI_API_KEY
      ? undefined
      : process.env.AI_INTEGRATIONS_OPENAI_BASE_URL,
});

단 위 코드를 그대로 복붙하라는 뜻이 아님.

공통 factory가 이미 있으면 재사용.
중복 구현보다 기존 Production-safe helper 우선.

중요:

- model 변경 금지
- prompt 변경 금지
- growth logic 변경 금지
- snapshot 변경 금지
- contract 변경 금지
- DB 변경 금지

오직 provider connection policy만 수정.
