SWIMNOTE SUPABASE SECURITY — PHASE 3
BACKUP DB DATA API BLOCK VERIFY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

사용자가 POOL_DB Supabase 프로젝트에서도
Data API Exposed schemas에서 public을 제거했다.

이번 단계는 검증만 한다.

DB WRITE 금지.
RLS 변경 금지.
코드 변경 금지.
Render/OTA 금지.

━━━━━━━━━━━━━━━━━━━━
1. BACKUP DB SOURCE 확인
━━━━━━━━━━━━━━━━━━━━

반드시 POOL_DATABASE_URL 기준.

제출:

current_user
session_user
rolsuper
rolbypassrls

DB host는 masked.

━━━━━━━━━━━━━━━━━━━━
2. Backup direct postgres smoke
━━━━━━━━━━━━━━━━━━━━

POOL_DATABASE_URL direct postgres로
민감하지 않은 테이블 READ ONLY 확인.

예:

swimming_pools count
subscription_plans count

개인정보 내용 출력 금지.

목표:
Data API 설정 변경 후에도
getBackupDb() direct postgres 연결 정상 확인.

━━━━━━━━━━━━━━━━━━━━
3. Backup/restore 코드 영향
━━━━━━━━━━━━━━━━━━━━

현재:

getBackupDb()
→ drizzle/node-postgres direct connection

경로가 정상인지 확인.

PostgREST / Data API 호출이 새로 발생하지 않는지 재확인.

━━━━━━━━━━━━━━━━━━━━
4. anon Data API runtime verification
━━━━━━━━━━━━━━━━━━━━

POOL_DB anon/publishable key를
안전하게 사용할 수 있으면:

public schema의 비민감 테이블 대상으로
Data API HTTP smoke.

row 내용 출력 금지.

기대:
public schema 접근 실패.

키가 Replit에 없으면:

MANUAL_HTTP_CHECK_REQUIRED

로 명시.

"BLOCKED"라고 확정하지 않는다.

━━━━━━━━━━━━━━━━━━━━
5. Production 상태도 정확히 기록
━━━━━━━━━━━━━━━━━━━━

Production SUPABASE:

Dashboard public removal = APPLIED
direct postgres = VERIFIED
service regression = NONE
anon HTTP runtime = NOT_VERIFIED

따라서:

DATA_API_BLOCK_APPLIED
RUNTIME_ANON_BLOCK_NOT_VERIFIED

로 기록.

증거 없는 EXTERNAL_ACCESS_BLOCKED 확정 표현 금지.

━━━━━━━━━━━━━━━━━━━━
6. 기존 standby-sync 오류
━━━━━━━━━━━━━━━━━━━━

이번 보안 작업과 섞지 않는다.

현재 기존 오류:

subscription_plans
backup_settings
platform_banners
pool_credits

관련 schema mismatch는
별도 DB maintenance issue로 기록만 한다.

이번 단계 수정 금지.

━━━━━━━━━━━━━━━━━━━━
7. RLS 다음 단계 준비
━━━━━━━━━━━━━━━━━━━━

두 Supabase 프로젝트 Data API 차단 후에도
Security Advisor의 RLS warning이 남는 것은 정상.

다음 RLS 작업에서는
100개 전체를 한 번에 변경하지 않는다.

먼저 HIGH-RISK 소수 테이블 대상으로
pilot 적용 → API regression → 확대하는
단계적 계획을 제안.

아직 RLS 적용 금지.
