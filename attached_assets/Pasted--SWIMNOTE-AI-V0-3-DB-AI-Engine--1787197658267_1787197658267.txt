# [SWIMNOTE 학부모 AI 커리큘럼 검색 — V0.3 구현 전 최종 설계기획서]

목적:
아직 구현하지 않는다.
현재 코드/DB/AI Engine 구조에서 아래 설계대로 구현 가능한지 READ-ONLY로 확인한다.
확인 후 실제 구현 WP를 시작한다.

절대 금지:
- 코드 수정
- DB 수정
- migration
- 신규 table 생성
- resolver 변경
- 전체 regression test
- 광범위 refactor
- Production 배포

이번 단계는 설계 확정용 확인만 수행한다.

==================================================
1. 기능 정의
==================================================

AI 커리큘럼 검색은 학부모가 자연어로
자녀의 실제 수업 진행상황을 질문하면,

1) 학생 실제 수업/일지/진도 기록
2) 해당 수영장의 SWIMNOTE 커리큘럼
3) SWIMNOTE AI의 수영 전문 DB

를 조합하여

- 현재 어떤 영법/기술을 배우고 있는지
- 어디까지 진행됐는지
- 특정 기술을 했는지
- 최근 무엇을 배우고 있는지
- 다음 커리큘럼 단계가 무엇인지
- 왜 현재 단계를 연습하는지
- 현재 레벨에서 무엇이 남았는지

등을 근거 기반으로 설명하는
학부모용 대화형 AI 검색 시스템이다.

중요:

GPT가 학생 진도를 추측하지 않는다.

Progress 판정:
학생 실제 데이터 + 커리큘럼 구조

GPT 역할:
판정된 결과와 전문 수영정보를 자연어로 설명

3. 커리큘럼 검색 이용 조건 — 중요 수정
==================================================

AI 커리큘럼 검색은 X 모드 전용 기능으로 막지 않는다.

일반 SWIMNOTE 학부모도 기존
"커리큘럼 검색" 버튼을 볼 수 있어야 한다.

다만 실제 AI 검색 실행 가능 여부는
현재 수영장에 충분한 커리큘럼이 구축되어 있는지로 판단한다.

기본 기준:

CURRICULUM_AI_MIN_ITEMS = 300

조건:

해당 swimming_pool_id의
검색 가능한 활성 커리큘럼 item >= 300

이면:
→ AI 커리큘럼 검색 사용 가능

300 미만이면:
→ AI 검색 화면을 정상 사용시키지 않고 이용 불가 안내

안내 문구:

"현재 수영장에 커리큘럼이 아직 충분히 등록되지 않아
AI 커리큘럼 검색을 이용할 수 없습니다."

중요:

300이라는 숫자를 앱 UI에 직접 하드코딩하지 않는다.

가능하면 서버 기준값으로 관리한다.

확인 필요:

- 현재 일반 SWIMNOTE의 커리큘럼 저장 구조
- X 수영장의 커리큘럼 저장 구조
- 두 구조에서 '검색 가능한 커리큘럼 item 수'를 어떤 기준으로 계산할지
- active/status 등의 유효성 필터가 존재하는지

4. X 모드의 역할
==================================================

SWIMNOTE X는 커리큘럼 검색 기능을 독점적으로 잠그는 조건이 아니다.

X의 역할:

- 구조화된 커리큘럼 제공
- 대량 커리큘럼 구축
- 영법/기술/단계 구조화
- AI 검색에 충분한 데이터 확보

즉 일반 SWIMNOTE도
센터가 자체적으로 커리큘럼을 충분히 등록하면
AI 커리큘럼 검색을 사용할 수 있다.

다만 현실적으로 300개 이상의 구조화 커리큘럼 구축은
일반 사용자가 직접 만들기 어렵고,
X 모드는 이를 쉽게 충족시키는 상위 시스템이다.

10. 대화 연속성
==================================================

사용자는 다음과 같이 연속 질문할 수 있다.

Q:
"자유형 어디까지 했어요?"

"그럼 다음에는 뭐 배워?"

두 번째 질문에서
"그럼"이 기존 대화의 자유형 진행상태를 의미하는 것을
이어갈 수 있어야 한다.

기존:

buildRecentConversationContext

재사용 가능 여부 확인.

과거 전체 대화를 무제한 GPT에 보내지 않는다.

권장:

- 최근 N turn
- 필요 시 conversation summary
- 현재 student progress context

==================================================
15. Evidence Type
==================================================

Evidence 종류와 날짜를 분리한다.

DIRECT
= 실제 학생 일지/수업 기록에서
해당 영법/기술이 직접 확인됨

TRACKED
= 복수 실제 기록을 종합하여
현재 계속 진행 중임을 추적할 수 있음

INFERRED
= 현재 실제 진행 위치와
센터 커리큘럼의 순서를 통해 계산된 정보

UNKNOWN
= 확인 가능한 실제 근거 부족

날짜는 Evidence type이 아니다.

별도로:

date
age_days
recency

등으로 관리.

예:

{
  type: "DIRECT",
  skill: "자유형 호흡",
  date: "...",
  age_days: 8
}

최근 기록은 높은 가중치를 주되
"30일 이내이므로 DIRECT"와 같은 판정은 하지 않는다.

17. 커리큘럼 데이터 역할
==================================================

커리큘럼은
"우리 아이가 어디까지 왔는가"를 판단하는 기준 구조다.

확인 필요:

일반 SWIMNOTE:
어떤 table/structure가 실제 curriculum source인지

X:
x_curriculum_levels가 실제 curriculum source인지

X curriculum 예:

- level_name
- strokes
- skills
- learning_contents
- objectives
- promotion_criteria

일반 SWIMNOTE와 X가
같은 canonical curriculum item 구조로 검색 가능한지 확인.

필요하면 application layer에서 normalization할 수 있지만
이번 audit에서는 구현하지 않는다.

==================================================

diary_templates를

- student level
- conversation

AI ENGINE / AI DB 역할:

- 기술 설명
- 수영 원리

- 가능한 원인
- 교정
- 드릴
- 감각
- 타이밍
- 전문 수영 Knowledge

즉:

APP DB
= 이 아이가 무엇을 했는가

AI DB
= 그 기술이 수영에서 무엇을 의미하는가

전문 DB는 학생 진도 판정용이 아니라
답변 설명 보강용.

현재 별도 AI Engine에서
전문 DB 검색 endpoint/function이 실제 무엇인지 확인한다.

21. 답변 모드
==================================================

DIRECT_DB

명확한 DB 사실.

예:

- 현재 level
- 최근 수업 날짜
- 명확하게 완료된 기술

예:

- 어디까지 왔어요?
- 다음 단계는 무엇인가요?
- 왜 이걸 배우나요?
- 최근 어떤 변화가 있나요?


HUMAN_ONLY

교사/센터의 미래 판단 또는 평가가 필요한 질문.

예:

- 다음주 진급할 수 있나요?
- 왜 우리 아이 진급 안 시켜줘요?
- 정확히 언제 다음 단계로 넘어가나요?

AI가 확정 답변하지 않는다.

"현재 진행상태를 기준으로 SWIMNOTE 커리큘럼상 다음 단계는
자유형 연결 과정입니다."


UNKNOWN:

확정 금지.

예:
"현재 확인 가능한 기록에서는 해당 과정의 완료 여부가 확인되지 않습니다."


교사의 미래 수업:

확정 금지.

금지:
"다음 수업부터 평영을 시작합니다."

허용:
"현재 진행상태와 커리큘럼을 기준으로 다음 과정은 평영으로 이어집니다.
실제 전환 시점은 수업 진행상황과 담당 선생님의 판단에 따라 달라질 수 있습니다."

==================================================
23. 수영 전문 설명
==================================================

답변이 지나치게 단순해지지 않도록
현재 영법/기술과 관련된 SWIMNOTE AI 전문 Knowledge를 검색한다.

예:

학생 현재 단계:
자유형 호흡

AI 전문 DB 검색:

- 자유형 호흡 원리
- 롤링
- 머리 위치
- 타이밍
- 흔한 오류
- 다음 단계와 관계

그중 필요한 내용을 제한적으로 가져와
GPT가 자연스럽게 설명하도록 한다.

수영 전문 DB 정보가
학생이 실제 수행했다는 Evidence로 변환되어서는 안 된다.

24. 답변 UX
==================================================

답변은 보고서 형태보다
ChatGPT처럼 자연스러운 설명형을 기본으로 한다.

예:

"현재 자유형에서는 팔동작과 호흡 연결을 중심으로 연습하고 있습니다.
최근 수업 기록에서는 자유형 킥과 팔동작이 반복적으로 확인됐고,
호흡 타이밍을 연결하는 과정도 진행 중인 것으로 확인됩니다.

자유형 호흡에서는 고개를 단순히 옆으로 돌리는 것보다
몸통 회전과 팔동작의 타이밍을 함께 맞추는 것이 중요합니다.

현재 과정이 안정되면 SWIMNOTE 커리큘럼상
자유형 전체 동작을 자연스럽게 연결하는 단계로 이어집니다."
