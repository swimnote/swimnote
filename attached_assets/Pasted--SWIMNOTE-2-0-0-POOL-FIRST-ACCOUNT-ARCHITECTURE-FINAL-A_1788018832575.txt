==================================================
0. 최상위 계정 철학
==================================================

SWIMNOTE 계정의 시작점은 전화번호가 아니다.

항상:

등록된 수영장 선택
→ immutable pool_id 확정
→ 해당 pool 내부 계정 가입/로그인

순서다.

같은 사람이 같은 전화번호를 사용하더라도
수영장이 다르면 서로 완전히 독립된 신규 계정이다.

예:

ToyKids:
phone = 010-1111-1111
account_A
student_A

Swimnote2:
phone = 010-1111-1111
account_B
student_B

Pool C:
phone = 010-1111-1111
account_C
student_C

반드시:

account_A != account_B != account_C

student_A != student_B != student_C

전화번호가 같다는 이유로
계정/학생/데이터를 연결하지 않는다.

==================================================
1. PHONE의 정확한 역할
==================================================

전화번호는:

- 실명인증
- 본인확인
- 아이디 찾기
- 비밀번호 찾기

용도로만 사용한다.

전화번호는 다음 용도로 사용 금지:

- global account identity
- 일반 로그인 계정 결정
- 기존 account 자동 재사용
- 다른 pool membership 자동 추가
- 다른 pool student 자동 연결
- 다른 pool report 연결
- 다른 pool notification 연결
- 다른 pool AI data 연결
- account merge 기준

즉:

PHONE = VERIFICATION / RECOVERY KEY

ACCOUNT IDENTITY = POOL-SCOPED ACCOUNT

==================================================
2. 신규가입 — 반드시 Pool First
==================================================

가입 플로우:

STEP 1
등록된 수영장 검색/선택

STEP 2
선택된 수영장의 pool_id 확정

STEP 3
가입 session/context에 pool_id 고정

STEP 4
전화번호 본인인증

STEP 5
해당 pool 내부에서만 기존 가입 여부 확인

STEP 6
해당 pool에 계정이 없으면 신규 account 생성

다른 pool에 같은 전화번호가 존재해도:

무시
→ 현재 pool용 완전 신규 account 생성

금지:

phone global lookup
→ existing account 발견
→ membership 추가

이 기존 방식은 신규가입 흐름에서 제거한다.

6. LOGIN_ID 구조 Audit
==================================================

현재 login_id가 global UNIQUE인지 실제 DB/schema/auth 코드를 조사.

중요:

Pool-First 계정 독립 구조를
global login_id constraint가 방해하는지 확인한다.

현재 제품에서 수영장 선택 후 로그인하는 구조라면
login lookup은 최소:

pool_id + login_id

기준으로 동작해야 한다.

단:

기존 데이터를 파괴하는 migration 금지.

필요하면 안전한 additive migration 및
pool-scoped unique 구조를 적용.

실제 repository/schema를 확인하고 결정하며
추측으로 constraint를 DROP하지 않는다.

7. 아이디 찾기 / 비밀번호 찾기 — 예외 정책
==================================================

여기서는 일반 로그인과 다르다.

사용자가 전화번호 본인인증에 성공하면
그 전화번호로 등록된 계정들을
전체 수영장 범위에서 검색할 수 있다.

예:

010-1234-5678 인증 성공

결과:

토이키즈스윔클럽
- parent01

스윔노트2
- parent77

비타스위밍
- abc123

이처럼 동일 전화번호로 등록된
모든 독립 계정을 목록으로 표시한다.

중요:

이것은 계정을 연결하는 기능이 아니다.

단순히 본인이 가진 독립 계정들을
찾아주는 recovery 기능이다.
