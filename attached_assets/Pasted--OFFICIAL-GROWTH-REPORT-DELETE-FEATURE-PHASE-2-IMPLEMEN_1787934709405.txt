==================================================
3. TRANSACTION
==================================================

하나의 DB transaction에서 처리.

순서:

1.
SELECT report
FOR UPDATE

확인:
- 존재 여부
- swimming_pool_id
- deleted_at

2.
권한/pool ownership 확인

3.
DELETE notifications
WHERE ref_id = reportId
AND ref_type = 'growth_report'
AND type IN (
  'GROWTH_REPORT_PUBLISHED',
  'growth_report_like',
  'growth_report_comment'
)

4.
DELETE growth_report_comments
WHERE growth_report_id = reportId

root/reply/is_deleted 여부 관계없이
해당 report 댓글 전부 제거.

5.
DELETE growth_report_reactions
WHERE growth_report_id = reportId

6.
UPDATE growth_reports
SET
  deleted_at = now(),
  updated_at = now()
WHERE id = reportId
AND deleted_at IS NULL

중간 실패:
전체 rollback.

6. REISSUE SAFETY
==================================================

현재:

uq_growth_reports_student_cycle

WHERE cycle_id IS NOT NULL
AND deleted_at IS NULL

구조를 그대로 사용.

soft delete 후
동일 student_id + cycle_id 새 report INSERT 가능해야 함.

migration 금지.

추가로 딱 한 가지 확인:

새 report 생성 시 previous_report_id를 선택하는
기존 query/service가

deleted_at IS NULL

조건을 이미 사용하는지 확인.

이미 사용:
수정 없음.

사용하지 않음:
previous report 선택 query에만
deleted_at IS NULL 최소 조건 추가.

삭제된 report를 새 report의 previous_report_id로
다시 선택하면 안 됨.

그 외 generation algorithm 변경 금지.
