[WP-CS25 추가 지시 — CANONICAL ANSWER 상담사 완성문장 규칙]

기존 WP-CS25에 아래 규칙을 추가 적용한다.

━━━━━━━━━━━━━━━━━━━━━━
A. CANONICAL ANSWER는 완성형 상담 문장
━━━━━━━━━━━━━━━━━━━━━━

Canonical Answer를:

keyword
phrase
memo
검색용 fragment

형태로 작성하지 않는다.

잘못된 예:

"교사 담당 학생 출결 수정 가능"

"학부모 사진 학생 연결 필요"

"X 설정 관리자만 가능"

"보강 2주 전 4주 후"

이 형태는 금지.

Direct DB Answer는 GPT를 호출하지 않고
그대로 사용자에게 표시되기 때문에
canonical_answer 자체가 실제 상담사가 보내는
완성형 한국어 문장이어야 한다.

━━━━━━━━━━━━━━━━━━━━━━
B. 기본 문체
━━━━━━━━━━━━━━━━━━━━━━

모든 사용자 노출 답변은 기본적으로:

존댓말
친절하지만 짧은 상담사 말투
명확한 서술형

사용.

기본 종결:

~할 수 있습니다.
~해 주세요.
~확인할 수 있습니다.
~표시됩니다.
~필요합니다.
~이용할 수 없습니다.

반말/메모체 금지.

━━━━━━━━━━━━━━━━━━━━━━
C. 불필요한 인사말 금지
━━━━━━━━━━━━━━━━━━━━━━

다음처럼 매 답변마다:

"안녕하세요."
"문의해 주셔서 감사합니다."
"도움이 필요하셨군요."

등의 상투적인 서론을 붙이지 않는다.

Direct Answer는 바로 본론부터 답한다.

좋음:

"교사는 담당 학생의 출결을 기록하고 수정할 수 있습니다."

나쁨:

"안녕하세요. 문의해 주셔서 감사합니다. 교사의 출결 기능에 대해 안내드리겠습니다."

━━━━━━━━━━━━━━━━━━━━━━
D. Answer 구조
━━━━━━━━━━━━━━━━━━━━━━

단순 사실:

1~2문장.

절차:

첫 문장 = 결론
이후 = 실제 조작 순서

예:

"학부모는 연결된 자녀의 수업 일지를 확인할 수 있습니다.
앱에서 해당 자녀의 일지 화면으로 이동해 확인해 주세요."

오류:

첫 문장 = 현재 상황
둘째 = 확인/해결 방법
필요 시 셋째 = 직접 문의 조건

예:

"사진이 보이지 않는 경우 먼저 자녀 연결 상태와 네트워크 상태를 확인해 주세요.
계속 표시되지 않으면 [직접 문의하기]를 통해 담당자에게 확인을 요청할 수 있습니다."

단 실제 verified 원인/행동만 사용.

━━━━━━━━━━━━━━━━━━━━━━
E. 질문을 반복하지 않는다
━━━━━━━━━━━━━━━━━━━━━━

사용자:

"선생님이 출결 수정할 수 있어요?"

답변:

"네, 교사는 담당 학생의 출결을 수정할 수 있습니다."

가능.

하지만 모든 답변을:

"선생님이 출결을 수정할 수 있는지 문의하셨습니다."

처럼 질문을 다시 풀어쓰지 않는다.

━━━━━━━━━━━━━━━━━━━━━━
F. 단답형
━━━━━━━━━━━━━━━━━━━━━━

YES/NO 성격 질문은
가능하면 첫 단어에서 답을 준다.

예:

"네. 교사는 담당 학생의 출결을 수정할 수 있습니다."

"아니요. 학부모 계정에서는 해당 기능을 사용할 수 없습니다."

단 role/mode/source가 검증된 경우만.

━━━━━━━━━━━━━━━━━━━━━━
G. UI 안내
━━━━━━━━━━━━━━━━━━━━━━

UI 경로가 실제 검증된 경우:

"○○ 화면에서 △△ 버튼을 눌러 주세요."

형태 사용 가능.

존재하지 않는 UI 명칭 창작 금지.

불확실한 경우:

구체적인 메뉴 경로를 임의 작성하지 않는다.

━━━━━━━━━━━━━━━━━━━━━━
H. 오류 답변
━━━━━━━━━━━━━━━━━━━━━━

오류 답변도 메모체 금지.

잘못된 예:

"네트워크 확인 후 재시도"

좋은 예:

"네트워크 연결 상태를 확인한 뒤 다시 시도해 주세요."

━━━━━━━━━━━━━━━━━━━━━━
I. HUMAN_ONLY
━━━━━━━━━━━━━━━━━━━━━━

가격/환불 등 공식 정책이 없는 HUMAN_ONLY 답변은:

"담당자 확인이 필요한 문의입니다.
[직접 문의하기]를 눌러 문의를 남겨 주세요."

같은 완성형 상담 문장으로 작성.

다음 표현 금지:

"고객센터 문의"
"고객지원 문의"

현재 화면 자체가 고객지원이기 때문.

━━━━━━━━━━━━━━━━━━━━━━
J. GROUNDED_GPT용 Knowledge도 문장 품질 유지
━━━━━━━━━━━━━━━━━━━━━━

GROUNDED_GPT에 사용되는 Knowledge라고 해서
메모형 fragment로 저장하지 않는다.

GPT가 해석하기 쉬운
명확한 완성형 사실 문장으로 작성.

단 여러 답변 조합이 필요한 경우에도
각 Knowledge 자체는 독립적으로 의미가 완결되어야 한다.

━━━━━━━━━━━━━━━━━━━━━━
K. Answer Style QA
━━━━━━━━━━━━━━━━━━━━━━

전체 Canonical Answer에 대해 검사:

FRAGMENT_ANSWER
BANMAL_ENDING
INCOMPLETE_SENTENCE
UNNECESSARY_GREETING
UNVERIFIED_UI_INSTRUCTION
CIRCULAR_SUPPORT_LANGUAGE

목표:

전부 0.

추가 검사 예:

문장이 명사형으로 끝나는지
"가능", "필요", "불가", "확인" 등 메모형으로 끝나는지
종결어미 없는 답변이 있는지

자동 탐지 후 수동 검토.
