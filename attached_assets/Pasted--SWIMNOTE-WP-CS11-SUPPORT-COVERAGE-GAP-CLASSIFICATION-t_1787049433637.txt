4. Classification 상태
━━━━━━━━━━━━━━━━━━━━━━

각 Coverage Record는 최종적으로 정확히 하나의
coverage readiness 상태를 가져야 한다.

Canonical status:

COVERED_ACTIVE
COVERED_PENDING
PARTIAL
MISSING

정의:

COVERED_ACTIVE
= 현재 production Support에서 실제 사용 가능한 ACTIVE 근거가 있어
해당 support intent를 해결할 수 있음.

예:

ACTIVE FAQ/Knowledge
ACTIVE Solution
Rule
DB State
Frontend Map
현재 active Known Issue

등.

주의:
단순 code reference만으로 production ACTIVE라고 판정 금지.

COVERED_PENDING
= 해결에 필요한 candidate/data/knowledge가 존재하지만
PENDING 또는 미승인 상태라 production Support가 아직 사용할 수 없음.

PARTIAL
= 해당 coverage의 일부 intent/category만 현재 해결 가능.

예:

WHERE_IS는 Frontend Map으로 해결되지만
FAILURE/SOLUTION은 없음.

MISSING
= 현재 production Support가 해당 coverage에 필요한
검증된 근거를 사실상 제공하지 못함.

━━━━━━━━━━━━━━━━━━━━━━
5. Intent별 세부 Gap을 유지
━━━━━━━━━━━━━━━━━━━━━━

* PERMISSION

* ERROR / FAILURE
* NOT_VISIBLE
* NOT_SAVED
* NOT_RECEIVED
* UPLOAD
* LOGIN_AUTH
* PAYMENT
* SUBSCRIPTION
* X_MODE
* AI_FAILURE
* COMPLAINT
* KNOWN_ISSUE
* POLICY

해당 record에 적용되지 않는 category는:

NOT_APPLICABLE

로 명시 가능.

중요:

HOW_TO가 ACTIVE라고 해서
ERROR/SOLUTION까지 COVERED_ACTIVE로 올리지 않는다.
