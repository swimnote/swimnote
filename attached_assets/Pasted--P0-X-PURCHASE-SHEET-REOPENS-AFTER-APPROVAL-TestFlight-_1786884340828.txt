[P0 — X PURCHASE SHEET REOPENS AFTER APPROVAL]

실기기 TestFlight에서 실제 X 결제 테스트 중 다음 현상 발생.

흐름:

1. X-0001 / 50% 예약 정상
2. [결제 계속하기]
3. Apple TestFlight purchase sheet 표시
4. ₩75,000/개월 정상 표시
5. Apple 계정 비밀번호 입력
6. 구매 승인/인증 완료
7. 그런데 앱이 X 활성화/sync 화면으로 가지 않고
   동일한 SWIMNOTE X Apple purchase sheet가 다시 표시됨

중요:

사용자가 두 번째 구매를 진행하지 않은 상태.

이번 작업은 PURCHASE FLOW TRACE ONLY 우선.
추측 수정 금지.

==================================================
1. FIRST — PURCHASE ACTUALLY SUCCEEDED?
==================================================

현재 테스트 Apple/RevenueCat 상태에서
첫 번째 purchase가 실제 성공했는지 확인.

가능한 안전한 방법으로:

RevenueCat customer / event / transaction 확인.

반드시 보고:

FIRST_PURCHASE_RESULT =
RC_TRANSACTION_CREATED = YES / NO
RC_X_MODE_ACTIVE = YES / NO
PRODUCT_ID =
ENVIRONMENT = sandbox / production
INITIAL_PURCHASE_EVENT_RECEIVED = YES / NO

secret / user token 출력 금지.

==================================================
2. CLIENT PURCHASE CALL COUNT
==================================================

x-subscription.tsx에서
purchasePackage() 호출 위치 전수 확인.

실기기 한 번의 [결제 계속하기] 탭에 대해:

PURCHASE_PACKAGE_CALL_COUNT =

반드시 추적.

다음 가능성 확인:

- onPress double invocation
- state effect에 의한 재호출
- purchase success callback 재진입
- useEffect dependency
- retry handler 자동 실행
- button event bubbling
- inFlight ref reset timing
- component remount 후 READY_TO_PURCHASE 재실행

purchasePackage는
사용자 명시적 탭 1회당 정확히 1회만 호출되어야 한다.

==================================================
3. TRACE EXACT STATE TRANSITIONS
==================================================

한 purchase attempt에 대해
PII 없이 상태 전이만 임시 로그/테스트로 확인:

READY_TO_PURCHASE
→ PURCHASING
→ purchasePackage result
→ SYNCING
→ sync result
→ refreshMode
→ X_ACTIVE

또는 실제 실패 위치.

반드시 보고:

STATE_BEFORE_PURCHASE =
PURCHASE_RETURNED =
STATE_AFTER_PURCHASE =
SYNC_CALLED =
SYNC_RESULT =
REFRESH_MODE_CALLED =
FINAL_STATE =

==================================================
4. REVENUECAT PURCHASE RESULT
==================================================

purchasePackage(package)의 실제 반환/throw 분류.

확인:

A. success + CustomerInfo
B. userCancelled
C. error
D. pending
E. unknown

raw error를 사용자에게 표시하지 말 것.

Apple 인증창이 닫힌 직후
purchasePackage가 성공 resolve했다면
절대 purchasePackage를 다시 호출하면 안 된다.

즉시 sync-x-subscription으로 가야 한다.

==================================================
5. SECOND SHEET TRIGGER
==================================================

두 번째 Apple purchase sheet를 발생시킨
정확한 코드 path를 특정.

보고:

SECOND_PURCHASE_TRIGGER =
CALL_SITE =
WHY_INFLIGHT_GUARD_DID_NOT_BLOCK =

이 세 항목이 확인되지 않으면
원인 확정 금지.

==================================================
6. SERVER SYNC CHECK
==================================================

첫 purchase가 성공했다면:

POST /api/billing/sync-x-subscription

이 실제 호출됐는지 확인.

호출됐다면:

HTTP_STATUS =
RESPONSE =

확인.

다음 오류 가능성 분리:

- RevenueCat V2 customer lookup 실패
- product mismatch
- reserved slot mismatch
- entitlement propagation delay
- transaction binding 실패
- cross-pool block

중요:

sync 실패가 발생해도
purchasePackage를 자동 재호출하면 안 된다.

sync 실패 시 기존 정책대로:

"결제는 완료되었지만 X모드 활성화 확인이 지연되고 있습니다."

+
[활성화 다시 확인]

만 제공.

==================================================
7. ALREADY PURCHASED PROTECTION
==================================================

첫 purchase 성공 후
같은 화면에서 어떠한 이유로 state가 복구되더라도

CustomerInfo / local purchase success state / server sync state 중
현재 안전한 source를 이용해

purchasePackage 재진입을 막는다.

단 client만으로 entitlement를 최종 확정하지 않는다.

원칙:

PURCHASE SUCCESS ONCE
→ NEVER AUTO-PURCHASE AGAIN
→ ONLY SYNC/REFRESH RETRY

==================================================
8. DO NOT CREATE NEW SLOT
==================================================

현재 X-0001 reservation 유지.

이번 디버깅 중:

새 x-reserve-slot 호출 금지
새 sequence 발급 금지
새 franchise number 발급 금지

이미 RESERVED/PURCHASED 상태를 먼저 확인.

==================================================
9. PRICE NOTE
==================================================

Apple purchase sheet 자체에서는:

₩75,000/개월

정상 표시 확인됨.

따라서 실제 Store product 가격은 정상.

앱 예약 카드의 US$49.99 표시는
별도 localized metadata/display 이슈로 분리.

이번 P0의 핵심:
중복 purchase sheet.

가격 문제 때문에 purchase contract를 변경하지 않는다.

==================================================
10. SAFE FIX REQUIREMENTS
==================================================

Root cause 확인 후 최소 수정.

반드시 보장:

- 한 탭 = purchasePackage 1회
- purchase 성공 후 state=SYNCING
- 자동 재구매 없음
- sync 실패 → sync retry only
- component rerender/remount → purchase 자동 호출 없음
- user가 명시적으로 다시 구매 버튼을 누르지 않는 한
  Apple sheet 재표시 없음
