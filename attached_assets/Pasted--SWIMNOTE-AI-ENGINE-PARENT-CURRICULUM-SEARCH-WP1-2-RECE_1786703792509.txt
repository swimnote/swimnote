==================================================
1. CANONICAL COST RULE
==================================================

전체 conversation history를 ENGINE에 보내지 않는다.

ENGINE이 받을 수 있는 context는
최근 최대 6개 message.

권장:
최근 3 turn
= USER 3 + ASSISTANT 3
= 최대 6 messages

그 이전 history는 APP에 저장만 하고
이번 요청에는 전송하지 않는다.

==================================================
2. REQUEST CONTRACT EXTENSION
==================================================

기존 request에 optional 추가:

"context": {
  ...
  "recent_conversation": [
    {
      "role": "USER | ASSISTANT",
      "content": "..."
    }
  ]
}

규칙:

- optional
- 최대 6개
- 오래된 순 → 최신 순
- 현재 query는 recent_conversation에 중복 포함하지 않음
- role은 USER / ASSISTANT만 허용
- 빈 content 차단
- message ID, DB ID 필요 없음

==================================================
3. CONVERSATION CONTEXT ROLE
==================================================

recent_conversation은:

질문의 지시 대상
대명사
후속 질문
직전 설명 맥락

을 이해하기 위한 보조 context다.

예:

이전:
USER: 지금 평영 발차기를 배우고 있나요?
ASSISTANT: 현재 평영 발차기 단계...

현재:
USER: 그 다음은 뭐예요?

→ "그 다음"이 평영 발차기 다음 단계를 의미한다고
해석하는 데 사용할 수 있음.

==================================================
4. ABSOLUTE GROUNDING RULE
==================================================

중요:

이전 ASSISTANT 대화 자체를
새로운 사실 근거로 승격하지 않는다.

Grounded 사실 source는 기존과 동일:

A. APP Curriculum Scope
B. Student Progress
C. ENGINE Knowledge Search

recent_conversation은
"질문 이해용 context"일 뿐.

과거 답변에 오류가 있어도
그 내용을 근거로 새로운 사실을 확장하면 안 됨.

==================================================
5. QUESTION CLASSIFICATION
==================================================

QuestionClassifier가 필요하면
최근 conversation을 참고해
후속 질문 의미를 해석할 수 있도록 수정.

다만 기존 명시적 질문은
기존 classifier behavior 유지.

예:

"그 다음은?"
→ recent context 있으면 NEXT_STEP

recent context 없으면
무리하게 추정 금지.

==================================================
6. PROMPT BUILDER
==================================================

Prompt에 recent_conversation을
별도 구역으로 제한해서 넣는다.

예:

[RECENT CONVERSATION — CONTEXT ONLY]

명시:

- 이 대화는 질문의 문맥 해석에만 사용
- 사실 근거로 사용하지 말 것
- 사실은 Curriculum / Student Progress / Knowledge Evidence만 사용

==================================================
7. TOKEN CONTROL
==================================================

ENGINE에서도 방어:

- 최대 6 messages
- 각 message content 최대 길이 제한
- 전체 recent conversation 길이 제한

현재 코드 convention에 맞춰
합리적 제한 설정.

과도하게 긴 history를 그대로 Prompt에 넣지 않는다.
