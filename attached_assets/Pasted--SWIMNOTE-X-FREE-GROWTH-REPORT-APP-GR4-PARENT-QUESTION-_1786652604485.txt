==================================================
1. 핵심 원칙
==================================================

APP은 질문을 만들지 않는다.

ENGINE이 반환한 질문만 표시한다.

APP은 답변 의미를 해석하지 않는다.

APP이:

AGREEMENT
CONTRADICTION
CONTEXT_DIFFERENCE

등을 판정하지 않는다.

APP 역할:

질문 표시
→ 선택값 저장
→ parent_input_status 갱신
→ 재분석 trigger

까지만.

==================================================
2. QUESTIONS ARE OPTIONAL
==================================================

질문이 0개인 Report 정상.

is_required = false

QUESTION_REQUIRED 상태 생성 금지.

==================================================
7. ANSWER VALIDATION
==================================================

반드시 서버 검증:

- report exists
- parent owns child
- parent input window open
- question belongs to report
- is_required=false 여부와 관계없이 optional
- selected_values array
- answer_type 규칙 준수
- SINGLE_CHOICE → 정확히 1개 또는 정책상 0개 허용 여부 명확
- MULTI_CHOICE → allowed options 내 값만
- option value 존재 확인
- duplicate selected value 금지
- 다른 report question 제출 금지

==================================================
10. PARENT INPUT STATUS
==================================================

답변 저장 후:

NONE / AVAILABLE
→ ANSWERED

가능.

그러나 일부 질문만 답했다고 해서
무조건 “모든 답변 완료” 의미로 해석하지 마라.

parent_input_status=ANSWERED의 의미를:

“최소 한 개 이상 parent answer 존재”

로 명확히 정의 가능.

별도로 answered_count / total_question_count 계산.

PARENT_INPUT_CLOSED

==================================================
12. 5일 이전에도 재분석 가능한가
==================================================

정책:

학부모가 답변 제출했다고
매번 즉시 ENGINE 재분석을 여러 번 호출하지 마라.

비용/중복분석 방지 필요.

권장:

answer 저장
→ parent_input_status=ANSWERED

그리고:

A. 명시적 "답변 완료" 버튼
또는
B. 5일 close 이후 Worker

에서 second-pass 분석.

현재 UX는 가능한 단순하게 구현.

==================================================
13. SUBMIT COMPLETE ACTION
==================================================

부모 UI에
질문 선택 후:

"답변 저장"

또는
"답변 완료"

동작을 명확히 둔다.

답변 완료 시:

report가 QUESTION_AVAILABLE이면

READY_FOR_ANALYSIS

로 전환 가능.

그러면 GR3 worker가
second-pass Engine call 수행.

중요:

질문 일부만 선택되어도
질문은 optional이므로 완료 가능.

==================================================
14. AUTO CLOSE SECOND PASS
==================================================

QUESTION_AVAILABLE
→ READY_FOR_ANALYSIS

되므로
저장된 answer가 있든 없든
GR3 worker가 second-pass 분석 가능.

즉:

manual complete
OR
5일 auto close

둘 다 지원.

==================================================
15. SECOND-PASS SNAPSHOT
==================================================

GR3 SnapshotBuilder가
growth_report_answers에서
current report answers를 읽도록 이미 구현되어 있음.

GR4에서 이 path를 실제 flow로 연결.

answer 저장
→ READY_FOR_ANALYSIS
→ GR3 worker
→ new request_id
→ parent_answers 포함 Snapshot
→ ENGINE
→ REVIEW_REQUIRED

==================================================
18. ANSWER AFTER REANALYSIS
==================================================

second-pass ANALYZING 또는 REVIEW_REQUIRED 이후에는
해당 cycle Parent Input이 아직 열려 있더라도
답변 수정 정책을 명확히 해야 한다.

추천:

ANALYZING
REVIEW_REQUIRED
APPROVED
PUBLISHED

상태에서는 answer 수정 금지.

이유:
이미 분석 snapshot이 고정된 뒤
answer만 바뀌면 Product result와 불일치.

다시 수정 허용하려면
새 분석까지 trigger해야 해서 복잡해짐.

현재 FREE V1에서는
READY_FOR_ANALYSIS 진입 전까지만 수정 허용.
