==================================================

반드시 구분:

A. 사용자가 구독 취소 버튼을 누른 시점
B. 실제 entitlement 만료 시점

정상 정책:

구독 취소 버튼을 눌러도
이미 결제된 이용기간이 남아 있으면
기간 종료 전까지 X 사용 가능할 수 있음.

하지만 실제 entitlement가 만료된 시점에는
반드시 X 접근권한이 제거되어야 한다.

반드시 검증:

1. cancel 직후 entitlement 상태
2. expiration 시 entitlement false 여부
3. false 상태 server DB 반영 여부
4. swimming_pools X 상태 비활성화 여부
5. app restart 후 X 접근 차단
6. server-side X API 차단

UI만 숨기고 API가 살아 있으면 FAIL.

4. MANUAL GRANT / PAID ENTITLEMENT 분리
==================================================

슈퍼관리자 수동 grant와
실제 paid entitlement를 명확히 구분한다.

다음 네 상태를 표현할 수 있어야 한다:

- manual ON / paid OFF
- manual OFF / paid ON
- manual ON / paid ON
- manual OFF / paid OFF

최종 X 접근 원칙:

X_ACCESS =
VALID_PAID_X_ENTITLEMENT
OR
ACTIVE_SUPERADMIN_MANUAL_GRANT

둘 다 false면
반드시 X INACTIVE.

중요:

- manual revoke가 paid entitlement를 삭제하면 안 됨
- paid expiry가 manual grant를 삭제하면 안 됨
- RevenueCat sync가 manual grant를 덮어쓰면 안 됨
- 과거 xmode_enabled=true 값 하나 때문에
  영구적으로 X가 유지되는 구조 금지
