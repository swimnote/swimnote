━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

각 TASK마다 아래 형식을 정확히 작성하십시오.

TASK ID =

TASK NAME =

GOAL =
이 작업 완료 후 무엇이 실제로 가능해지는가.

CURRENT REUSE =
현재 어떤 파일/컴포넌트/API를 재사용하는가.

EXPECTED FILE SCOPE =
수정 예상 기존 파일.

EXPECTED NEW FILES =
신규 생성 예상 파일/모듈.
아직 만들지 말 것.

BACKEND CHANGE =
YES/NO
필요 시 정확한 목적.

DB CHANGE =
YES/NO
필요 시 migration 목적.
불필요한 DB 변경 금지.

MOBILE APP CHANGE =
반드시 0 또는 별도 승인 필요.

NATIVE/WINDOWS =
Electron main/preload/IPC/build 등 필요 여부.

IMPLEMENTATION =
실제 Agent가 수행해야 할 작업 순서.

VALIDATION =
관련 테스트만 명시.

DO NOT RUN =
이번 Task에서 불필요한
전체 suite/build/deploy 등을 명시.

PASS CRITERIA =
무엇을 확인하면 완료인가.

STOP CONDITIONS =
막혔을 때 Agent가 추측 구현하지 않고
중단해야 할 조건.

CREDIT RISK =
LOW/MEDIUM/HIGH.

EXPECTED AGENT ROUND =
가능하면 1회 / 2회 등의 예상.

NEXT TASK =
PASS 후 다음 Task.
