[긴급 수정 — SUPERADMIN 직접 X MODE 부여 시 Local Curriculum prerequisite만 우회]

현재 SUPERADMIN X MODE 수동 부여 기능은 Production PASS 상태입니다.

이번 변경 목적은 단 하나입니다.

현재:
신규 수영장 가입
→ Local Curriculum 등록/활성화
→ SUPERADMIN X MODE 부여

변경:
신규 수영장 가입
→ SUPERADMIN X MODE 즉시 부여
→ X MODE 활성화
→ 이후 해당 수영장에서 Local Curriculum 등록/활성화

단,
이 예외는 반드시 SUPERADMIN 직접 수동 부여 경로에만 적용합니다.

일반 결제/구독/자동 entitlement/X 설정 완료 경로의
기존 prerequisite 정책은 변경하지 마십시오.

━━━━━━━━━━━━━━━━━━━━━━

SUPERADMIN이:

X MODE = 활성

즉 결제도 없고 커리큘럼도 아직 없어도
SUPERADMIN 직접권한으로 X MODE에 들어갈 수 있어야 합니다.

4. 커리큘럼 없는 X pool 처리
━━━━━━━━━━━━━━━━━━━━━━

중요:

X MODE 활성화와
“Local Curriculum 준비 완료”는 별개 상태입니다.

커리큘럼이 없는데도
가짜 curriculum 데이터를 만들거나
Global Curriculum을 Local Curriculum인 것처럼 생성하지 마십시오.

커리큘럼을 필요로 하는 기능은
현재 기존 empty/not-ready 처리 방식을 유지하십시오.

예:

X Curriculum 화면
→ 커리큘럼 등록/업로드 가능

Parent Curriculum AI 등
실제 Local Curriculum 데이터가 필요한 기능
→ 데이터가 없으면 기존의 안전한 준비중/근거없음 처리

커리큘럼이 없는 상태에서
AI가 임의의 수영장 커리큘럼을 생성해서 정상 데이터처럼 사용하면 안 됩니다.

━━━━━━━━━━━━━━━━━━━━━━
5. xmode_config_status 확인
━━━━━━━━━━━━━━━━━━━━━━

현재 manual grant가
xmode_config_status = READY

를 설정하는 구조를 실제 코드에서 다시 확인하십시오.

이번 정책에서는:

“X 사용권 부여됨”
와
“Local Curriculum 준비됨”

을 혼동하면 안 됩니다.

따라서 현재 resolver가 mode=x를 위해 READY를 요구한다면
최소 수정으로 다음 의미를 보장하십시오.

SUPERADMIN manual entitlement = true
→ Local Curriculum 유무와 관계없이 mode=x

단:

paid/subscription 등 일반 경로의
READY prerequisite 정책은 그대로 유지.

가능하면 기존 schema/state를 재사용하고,
이번 한 건 때문에 새 대규모 상태 머신을 만들지 마십시오.

중요:
커리큘럼이 없다는 이유로 manual grant가 x_pending이 되어
X Curriculum 등록 화면 자체에 못 들어가는 구조가 되면 안 됩니다.

6. Growth Report
━━━━━━━━━━━━━━━━━━━━━━

커리큘럼이 없는 상태에서 SUPERADMIN이 X를 부여하더라도

잘못된 리포트 생성으로 이어지면 안 됩니다.

기존 Growth Report eligibility/readiness에서
실제 필요한 데이터 조건을 계속 검증하도록 유지하십시오.

이를 위해 Growth Report 전체를 재설계하지 마십시오.
