2. 발급대상 봉인
━━━━━━━━━━━━━━━━━━━━━━

119명이 확정됐으면
AI 실패 1명을 제거하여 118/118로 만드는 것 금지.

확정 대상 identity를 DB에 보존합니다.

기존 UNIQUE/constraint는 재생성하지 않습니다.

5. retry/backoff
━━━━━━━━━━━━━━━━━━━━━━

retry 가능한 오류만 자동 retry합니다.

retry scheduling은 DB에 보존합니다.

analysis_next_attempt_at 사용.

기존 analysis_retry_count 재사용.

retry/backoff/concurrency는
운영 설정으로 조정 가능하게 유지합니다.

pool/member 숫자를 business logic에 하드코딩하지 않습니다.

UNKNOWN과 definitive failure는
일반 transient retry와 분리합니다.

- 확정 이후 실제 상태변경이 발생
- 상태변경 시점/감사 근거 존재
- 발행 전 active/nondeleted 검사에서 발행 불가

정책상 발행제외로 귀결합니다.

AI 실패
ENGINE 오류
APP 오류
retry 소진
데이터 유실

을 policy exclusion으로 바꾸는 것 절대 금지.

최초 발급조건 미충족 EXCLUDED와도 구분합니다.

7. reconciliation 및 100% gate
━━━━━━━━━━━━━━━━━━━━━━

확정 대상 명단을 기준으로
각 대상의 실제 상태를 reconciliation합니다.

확인:

- missing
- duplicate logical identity
- wrong pool
- queued
- processing
- retry_pending
- failed
- unknown
- 정상 생성
- 정당한 사후 policy exclusion

발급조건 충족자 전원이
정상적인 최종 귀결 상태에 도달해야 합니다.

정상 귀결:

A. 정상 성장리포트 생성 완료
또는
B. 근거가 확인된 확정 이후 정책상 발행제외

READY 조건:

resolved_total == eligible_total

AND

queued = 0
processing = 0
retry_pending = 0
failed = 0
unknown = 0
missing = 0
duplicate = 0

정상 생성 수와 policy exclusion 수는
별도로 집계합니다.

예:

eligible 119
generated 119
policy excluded 0
→ 119/119 READY

eligible 119
generated 118
policy excluded 1
→ 처리 귀결 119/119 READY
→ 실제 생성 118
→ 정책상 제외 1

eligible 119
generated 118
failed 1
→ 118/119 NOT READY

실패를 분모에서 제거하는 방식은 금지합니다.
