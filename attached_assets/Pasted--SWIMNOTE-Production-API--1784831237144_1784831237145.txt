이번 작업은 하나도 빠뜨리지 말고 실제 Production 앱에서 직접 확인하면서 작업하십시오.

중요:
코드 수정, API 추가, 배포 완료만으로 절대 완료라고 하지 마십시오.

==================================================
현재 실제 앱 확인 결과
==================================================

1. 학부모 댓글 전송은 이제 성공함
2. 선생님은 댓글이 왔는지 홈에서 알 수 없음
3. 선생님이 직접 지난 일지를 찾아 들어가야 댓글을 볼 수 있음
4. 선생님 홈의 ‘쪽지·학부모 요청’ 편지함에는 댓글 알림이 안 들어옴
5. SWIMNOTE 운영팀 문의는 전송됨
6. 원장님에게 문의는 계속 전송 실패함
7. 추가 보호자 전화번호 입력 모달이 키보드에 가려짐
8. 전화번호를 입력해도 확인/저장 버튼을 누를 수 없음
9. 선생님 댓글 화면에서 이름 위에 `NaN:NaN`이 노출됨
10. 기능 수정 후 실제 앱 검증 없이 완료 보고하는 문제가 반복됨

==================================================
1. 학부모 댓글을 선생님 편지함에 연결
==================================================

학부모가 수업일지에 댓글을 작성하면,
해당 일지의 선생님에게 새로운 알림 항목이 생성되어야 합니다.

선생님 홈 화면의 편지함:

‘쪽지 · 학부모 요청’

에 댓글 알림이 표시되어야 합니다.

댓글 알림 표시 내용:

- 새 댓글
- 학생 이름
- 학부모 이름 또는 보호자 표시명
- 댓글 일부
- 수업일지 날짜
- 읽지 않음 상태
- 작성 시각

예시:

[새 댓글]
서태웅 보호자
7월 23일 수업일지
“왜하래”
방금 전

댓글 알림은 기존 일반 쪽지와 구분할 수 있어야 합니다.

권장 notification/message type:

diary_comment
diary_reply
parent_request
direct_message

댓글을 일반 쪽지 데이터로 억지로 섞더라도,
반드시 원본 diaryId, studentId, commentId를 저장해야 합니다.

==================================================
2. 댓글 알림 클릭 시 정확한 지난 일지 열기
==================================================

선생님 홈 편지함에서 댓글 알림을 누르면:

1. 댓글이 작성된 정확한 지난 수업일지 열기
2. 해당 일지의 반응 & 댓글 화면 표시
3. 해당 댓글 위치가 바로 보이도록 표시 또는 스크롤
4. 선생님이 그 자리에서 답글 작성 가능
5. 읽음 처리

반드시 전달해야 하는 값:

- diaryId
- studentId
- commentId
- classDate
- source=teacher_home_inbox

날짜만 전달해서 비슷한 일지를 찾지 마십시오.
반드시 diaryId 기준으로 정확한 일지를 여십시오.

==================================================
3. 댓글 화면 닫기 후 홈으로 복귀
==================================================

선생님이 홈 화면 편지함에서 댓글 알림을 눌러 들어온 경우:

댓글/지난 일지 화면에서 뒤로가기 또는 닫기를 누르면
반드시 선생님 홈 화면으로 돌아와야 합니다.

정상 흐름:

선생님 홈
→ 쪽지·학부모 요청
→ 댓글 알림 선택
→ 해당 지난 일지의 반응 & 댓글
→ 닫기/뒤로가기
→ 선생님 홈

다른 화면을 여러 번 거쳐서 돌아가게 만들지 마십시오.

단, 수업관리의 지난 일지 목록에서 직접 들어온 경우에는
기존 지난 일지 목록으로 돌아가야 합니다.

즉, 진입 경로에 따라 복귀 위치를 구분하십시오.

- source=teacher_home_inbox → teacher home
- source=past_diary_list → past diary list

4. 선생님 홈 미확인 댓글 표시
==================================================

새 댓글이 있으면 선생님 홈에서 바로 알아볼 수 있어야 합니다.

최소 구현:

- 편지함 아이콘 배지
- 미확인 댓글 수
- 쪽지·학부모 요청 목록에 새 댓글 항목
- 확인하면 읽음 처리
- 읽은 뒤 배지 감소

댓글이 있는데도 홈에서 아무 표시가 없으면 미완성입니다.

==================================================
5. 댓글 화면 `NaN:NaN` 제거
==================================================

현재 선생님 반응 & 댓글 화면에서
보호자 이름 아래에 `NaN:NaN`이 표시됩니다.

이것은 날짜 또는 시간 파싱 오류입니다.

확인할 항목:

- comment.createdAt
- created_at
- timestamp
- Date 객체 변환
- 서버 timezone
- null/undefined
- 잘못된 문자열 format
- iOS Date parsing

시간 데이터가 유효한 경우:

오후 3:08
또는
7월 24일 오후 3:08

처럼 표시하십시오.

시간값이 없거나 파싱에 실패하면:

- 빈칸 처리
- 또는 ‘시간 정보 없음’

으로 표시하십시오.

절대로 `NaN`, `Invalid Date`, `undefined`, `null`이 사용자 화면에 노출되면 안 됩니다.

추가로 앱 전체에서 사용자 화면에 노출되는 다음 문자열을 전수 검색하십시오.

NaN
Invalid Date
undefined
null
[object Object]

발견 시 모두 정상 표시값으로 수정하십시오.

==================================================
6. 원장님에게 문의 전송 복구
==================================================

현재 SWIMNOTE 운영팀 문의는 전송되지만,
‘원장님에게 문의’는 실제 Production 앱에서 전송 실패합니다.

두 문의는 수신 대상이 완전히 다릅니다.

SWIMNOTE 문의:
→ 플랫폼 운영자/슈퍼관리자

원장님 문의:
→ 해당 학생이 소속된 수영장의 원장 또는 관리자

원장 문의 전송 흐름을 처음부터 끝까지 확인하십시오.

학부모
→ 연결된 학생 확인
→ 학생의 centerId/poolId 확인
→ 해당 센터의 owner/admin 조회
→ 문의 저장
→ 원장 수신함 표시

실제 로그인 학부모 계정의 연결 데이터를 기준으로 테스트하십시오.

추측으로 ownerId를 넣지 마십시오.

확인할 데이터:

- parent user id
- student id
- parent_students 연결
- student center_id 또는 pool_id
- center owner/admin user id
- recipient id
- 문의 body
- created row

권장 요청:

POST /api/inquiries

{
  "inquiryType": "center_director",
  "studentId": "...",
  "centerId": "...",
  "body": "원장 문의 실제 테스트"
}

성공 응답:

201

{
  "success": true,
  "inquiryId": "...",
  "recipientId": "...",
  "centerId": "..."
}

수신할 원장 계정이 없으면 성공 처리하지 말고:

“문의 받을 원장 또는 관리자가 등록되어 있지 않습니다.”

라고 정확하게 표시하십시오.

==================================================

전송 API만 성공하면 완료가 아닙니다.

해당 수영장의 원장/관리자 앱에서:

완료 조건:

학부모 전송
→ Production DB 저장
→ 정확한 원장 수신
→ 원장 화면 표시
→ 원장 답변
→ 학부모 화면 표시

8. 추가 보호자 전화번호 모달 수정
==================================================

현재 추가 보호자 관리에서
‘+ 보호자 번호 추가’를 눌러 전화번호를 입력하면
키보드가 모달과 확인 버튼을 가립니다.

전화번호는 입력되지만 확인/저장 버튼을 누를 수 없습니다.

이 상태는 기능 미완성입니다.

단순히 모달 높이만 약간 늘리지 말고,
모든 iPhone 화면 크기와 키보드 상태에서
입력칸과 확인 버튼이 반드시 보여야 합니다.

필수 적용:

- KeyboardAvoidingView
- SafeAreaView
- ScrollView 또는 KeyboardAwareScrollView
- keyboardVerticalOffset 정확히 설정
- 모달 최대 높이 확보
- 입력창 자동 스크롤
- 하단 확인 버튼 키보드 위에 고정
- 키보드가 열려도 확인 버튼 노출
- 작은 화면에서도 사용 가능

권장 모달 구조:

상단:
추가 보호자 번호 등록
닫기

중앙:
보호자 이름 입력
전화번호 입력
관계 선택

하단 고정:
취소
등록하기

키보드가 열린 상태에서도
‘등록하기’ 버튼 전체가 보여야 하고 실제로 눌려야 합니다.

현재처럼 숫자 키보드만 보이고 버튼이 가려지는 화면은 실패입니다.

7. 학부모가 원장님에게 문의를 성공적으로 보낸 화면
8. 원장 앱 수신함에 문의가 표시된 화면
9. 원장이 문의를 열어본 화면
10. 추가 보호자 입력 모달에서 키보드가 열린 상태
11. 키보드가 열린 상태에서도 등록 버튼이 보이는 화면
12. 추가 보호자 등록 완료 후 번호가 목록에 표시된 화면

스크린샷은 코드 화면, 로그 화면, 브라우저 화면이 아니라
실제 iOS 또는 Android Production 앱 화면이어야 합니다.

13. 최종 완료 조건
==================================================

다음이 전부 실제 앱에서 작동해야 완료입니다.

- 댓글이 학부모 앱에서 전송됨
- 댓글이 선생님 홈 편지함에 도착함
- 알림 클릭 시 정확한 지난 일지가 열림
- 선생님이 댓글을 확인하고 답글 가능
- 닫기 후 선생님 홈으로 복귀
- 읽음/미확인 수가 정상 반영
- `NaN:NaN` 완전 제거
- 원장님 문의 전송 성공
- 정확한 원장에게 문의 도착
- 원장 답변이 학부모에게 표시
- 추가 보호자 모달이 키보드에 가려지지 않음
- 키보드가 열린 상태에서 등록 버튼 클릭 가능
- 보호자 전화번호 실제 저장
- 앱 재실행 후에도 모두 유지

이 중 하나라도 실패하면 완료가 아닙니다.

작업을 여러 개 했다는 긴 요약 보고서를 먼저 쓰지 마십시오.
실제 Production 앱에서 전부 통과시킨 뒤,
기능별 실제 스크린샷과 검증 결과를 제출하십시오.
