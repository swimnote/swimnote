→ 보강 대기

기존 연결 확인.

→ 목록 즉시 반영

이미 사용한 보강권 재사용 차단.

현재 구현 경로부터 추적.

O. 학부모 자동 연결 / 승인관리
━━━━━━━━━━━━━━━━━━━━━━

현재:
승인관리 > 학부모 연결
대기 요청 존재.

확정 제품 정책:

학생이 이미 수영장 DB에 등록되어 있고

- 학생 이름 일치
- 등록 보호자 전화번호와
  가입 학부모 전화번호 일치

하면 자동 승인.

관리자가 수동 승인할 이유 없음.

조사:

1.
현재 auto-link/auto-approve 코드.

2.
이름 matching.

3.
전화번호 normalization:
- 010
- hyphen
- space
- +82
- 보호자1
- 보호자2

4.
동명이인 처리.

5.
현재 Production에서 왜 대기가 남는지.

6.
기존 대기건을 현재 정책 기준으로 분류할 계획:

A.
명확히 match
→ 자동 승인 가능

B.
동명이인/불일치
→ 관리자 예외 처리

7.
정상 match 요청은
평소 대기 목록에 존재하면 안 됨.

8.
현재 카드:
“학생 이름 확인 필요”
“전화번호 확인 필요”
“학생 선택 필요”

실제 예외에서만 표시.

9.
승인 버튼의 돋보기 아이콘 제거/교체.

10.
승인 후:
- 회원카드 학부모미연결 배지 제거
- 초대 버튼 제거
- 운영현황 연결 학부모 수 반영

중요:
이번 설계도 단계에서는
기존 대기자를 실제 승인하지 말 것.
