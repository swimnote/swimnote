6. ADMIN APP — 보강
━━━━━━━━━━━━━━━━━━━━━━

Admin Mode의 보강 화면은:

“보강 운영”

이 아니라

“보강 현황 관리”

성격으로 정리합니다.

pool_admin에게 다음 mutation UI를 노출하지 마십시오.

- 배정
- 재배정
- 일정 변경
- 취소
- 완료
- transfer/handover
- extinguish

WP1에서 서버도 이미 Admin Mode read-only로 정리됐습니다.

관리자 화면 목적:

“어떤 보강이 밀리고 있는가?”

를 빠르게 확인하는 것.

기존 데이터 범위 내에서 우선 표시:

- 전체 미처리
- 아직 처리되지 않은 보강
- 오래된 순
- 만료 임박
- 만료/소멸 예정

가능하면 기존 필드만 사용하십시오.

expire_at 등 기존 SoT가 있으면 사용.
새 만료 계산식 만들지 마십시오.

필요한 상세 정보:

- 학생명
- 담당 선생님
- 원래 결석일
- 현재 상태
- 예정 보강일
- 잔여기한/만료일(기존 데이터가 있을 때)

과도한 대시보드/차트 추가 금지.
