==================================================
[추가 CRITICAL — SAME PHONE / SIMILAR POOL NAME 완전 분리]
==================================================

현재 실기기 증상:

- 스윔노트
- 스윔노트2
- 스윔노트3

처럼 이름이 유사한 수영장을 각각 생성하고
학부모 신규가입을 테스트하면

선택한 수영장과 다르게
기존 "스윔노트" 계정으로 연결되거나,

같은 전화번호를 사용했을 때
다른 수영장 계정/학생/리포트가 서로 겹치는 현상 발생.

이 문제는 반드시 구조적으로 해결한다.

==================================================
A. Pool 결정에 Phone 사용 금지
==================================================

전화번호는 절대로 다음에 사용하지 않는다:

- pool 결정
- existing account 자동 선택
- existing account 자동 재사용
- membership 자동 연결
- student 자동 연결
- report/notification 자동 연결

일반 신규가입에서:

phone이 동일하더라도
다른 pool이면 무조건 신규 account 생성.

예:

Pool A = 스윔노트
phone 010-1111-1111
→ account_A

Pool B = 스윔노트2
same phone
→ account_B

Pool C = 스윔노트3
same phone
→ account_C

반드시:

account_A != account_B != account_C

==================================================
B. Pool Name으로 Account 결정 금지
==================================================

수영장 이름은 display only.

금지:

- pool_name LIKE
- pool_name ILIKE
- startsWith
- includes
- prefix matching
- searchResults[0]
- first matching pool
- default pool fallback

로 account 귀속 결정.

사용자가 선택한 row의 정확한:

selectedPool.id

만 사용.

==================================================
C. 선택한 Pool ID 불변성 검증
==================================================

가입 시 다음 값이 전부 동일해야 한다:

중간에 pool_name으로 다시 resolve 금지.

==================================================
D. Same Phone 전역 Account Reuse 제거
==================================================

repository 전체에서 다음 패턴 전수 검색:

WHERE phone = ?
LIMIT 1

find account by phone

existingParentByPhone

existingUserByPhone

phone → account reuse

phone → membership attach

일반 signup/login 흐름에서
pool_id 없이 phone으로 account를 찾는 코드 = 0

단 예외:

본인인증 후
아이디/비밀번호 찾기 recovery flow에서
해당 phone의 계정 목록 조회만 허용.

==================================================
E. Parent Account Identity
==================================================

parent account는 pool-scoped.

최소 개념:

account identity
=
pool_id + account_id/login identifier

동일 phone이어도 pool이 다르면
서로 완전 별개.

==================================================
F. Student도 반드시 Pool별 신규
==================================================

같은 부모 전화번호라도:

스윔노트:
student_A

스윔노트2:
student_B

스윔노트3:
student_C

자동 merge 금지.

student 이름/생년월일/전화번호가 같아도
pool이 다르면 다른 record.

==================================================
G. 기존 데이터 섞임 원인 추적
==================================================

실제 현재 Production에서
같은 phone을 가진 parent account들을 조사.

보고:

phone
account_id
pool_id
pool_name
student_id
student_pool_id

그리고 다음 이상 여부 확인:

1.
account pool != student pool

2.
same account_id가 여러 unrelated pool에 사용됨

3.
same parent account가 phone 때문에
다른 pool membership을 자동 보유

4.
report가 다른 pool student/account에 노출 가능

5.
notification/feed가 account-global로 섞임

데이터 수정은 먼저 하지 말고 audit.

==================================================
L. Login / Signup 구분
==================================================

일반 Signup:
pool 선택 필수
→ 해당 pool 신규/기존 account 판단

일반 Login:
pool 선택 필수
→ 해당 pool account만 인증

Recovery:
phone 인증 후
→ 해당 phone의 전체 account 목록 조회 가능
→ 사용자가 정확한 pool/account 선택

이 3개 flow를 섞지 않는다.
