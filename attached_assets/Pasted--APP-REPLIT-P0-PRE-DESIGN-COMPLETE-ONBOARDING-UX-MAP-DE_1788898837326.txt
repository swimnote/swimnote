1. 제품 원칙 — 중요 기능은 반드시 안내
━━━━━━━━━━━━━━━━━━━━━━

이전의
"온보딩을 최대한 적게 만든다"
원칙을 절대적으로 적용하지 않는다.

새 기준:

사용자가 중요한 기능을 처음 사용할 때

"이건 뭐지?"
"어떻게 해야 하지?"
"누르면 어떻게 되지?"
"왜 안 되지?"
"먼저 뭘 해야 하지?"

라는 물음표가 생길 가능성이 있다면
반드시 onboarding/help 대상에 포함한다.

SWIMNOTE는 기능이 많고
운영자/선생님/학부모의 역할도 다르기 때문에

중요 기능에 대한 최초 안내는
조금 많더라도 꼼꼼하게 제공한다.

다만:

모든 안내를
full-screen tutorial로 만들지는 않는다.

목표:

"안내는 충분하지만 사용을 방해하지 않는 앱"

이다.

2. 온보딩 방식 4단계
━━━━━━━━━━━━━━━━━━━━━━

모든 기능을 아래 중 하나로 분류.

TYPE A — SETUP ONBOARDING

실제로 설정/입력을 완료해야 하는 중요 절차.

예:
- 신규 수영장 초기 설정
- 플랜 선택
- X Curriculum 설정

TYPE B — FIRST-USE GUIDE

해당 기능 첫 진입 시
짧게 기능 전체를 이해시켜야 하는 경우.

1~3개의 짧은 설명까지 허용.

TYPE C — COACH MARK

특정 버튼/영역의 의미만 알면 되는 경우.

화면 위에서 해당 UI를 가리켜 설명.

TYPE D — INLINE HELP

별도 modal조차 필요 없는 경우.

해당 화면 안에:

- 설명 1~2줄
- 도움말
- 정보 아이콘
- empty-state guidance

형태로 제공.

가장 작은 방식으로 해결하되
중요 기능 설명 자체를 빼지는 않는다.

8. PARENT 회원가입 자동승인 설명 — 필수
━━━━━━━━━━━━━━━━━━━━━━

매우 중요.

학부모 회원가입/자녀 연결 과정에서
승인 구조가 사용자에게 명확히 보여야 한다.

현재 실제 코드/API의 auto-link 조건을
먼저 정확히 확인한다.

제품정책상 반드시 전달해야 할 핵심:

"수영장에서 미리 등록한 학생 정보와
학부모 가입 정보가 일치하면
별도의 관리자 승인 없이 자동으로 연결될 수 있다."

이를 Parent 가입 과정에서
최소 1회 명확하게 안내.

단:

실제 코드상 어떤 값이 일치해야 하는지
반드시 확인 후 문구 작성.

예를 들어 실제 조건이:

- 수영장
- 자녀 이름
- 학부모 전화번호

등이라면
정확한 실제 조건만 설명.

존재하지 않는 자동승인 조건 창작 금지.

━━━━━━━━━━━━━━━━━━━━━━
9. 수영장에서 학생 등록 시 Parent 연결 안내
━━━━━━━━━━━━━━━━━━━━━━

관리자 회원등록 onboarding에도
반드시 설명 필요.

관리자가 학생을 등록하면서
학부모 연락처 등
현재 자동연결에 필요한 정보를 정확히 입력하면

향후 학부모가 가입할 때
자녀가 자동으로 연결될 수 있다는 사실을
관리자에게 설명.

즉:

"회원정보를 정확히 입력하는 이유"

까지 사용자가 이해하도록 한다.

단 실제 자동승인 조건과 100% 일치하게 작성.

━━━━━━━━━━━━━━━━━━━━━━
10. 추가 학부모 등록/연결 설명 — 필수
━━━━━━━━━━━━━━━━━━━━━━

추가 보호자 기능도
사용자가 헷갈리지 않게 반드시 안내.

제품정책:

이미 승인/연결된 학부모가
추가 학부모 정보를 입력하고,

그 추가 학부모가 해당 정보와 일치하게 가입하면
자동승인/자동연결될 수 있는 구조를 안내.

반드시 실제 현재 코드/API 조사:

- 누가 추가 보호자 정보를 입력하는지
- 어떤 화면인지
- 어떤 정보가 저장되는지
- 무엇이 일치해야 하는지
- 자동승인인지
- pending이 발생하는 예외는 무엇인지

확인 후 문구 작성.

예시 의미:

"다른 보호자도 함께 이용할 수 있어요.
현재 연결된 보호자가 추가 보호자 정보를 미리 등록하면,
해당 보호자가 가입할 때 정보가 일치하는 경우
자동으로 연결됩니다."

단 이 문구를 그대로 사용하지 말고
실제 구현 검증 후 최종 문구 제출.

━━━━━━━━━━━━━━━━━━━━━━
11. AUTO APPROVAL 예외도 설명
━━━━━━━━━━━━━━━━━━━━━━

자동승인 설명만 하고 끝내면 안 됨.

실제 시스템에서:

- 정보 불일치

자동승인이 되지 않을 수 있음.

사용자가

"자동으로 된다며 왜 안 돼?"

라는 상황이 생기지 않게

필요한 지점에서 짧게:

"정보가 일치하지 않으면 확인 절차가 필요할 수 있습니다."

형태의 예외 안내도 검토.

실제 조건 없는 예외 창작 금지.

17. 설명 품질 PASS 기준
━━━━━━━━━━━━━━━━━━━━━━

각 안내를 본 사용자가 최소한:

1. 이 기능이 무엇인지
2. 왜 사용하는지
3. 무엇을 하면 되는지
4. 완료하면 어떤 결과가 생기는지
5. 자동으로 되는 부분이 무엇인지
6. 직접 해야 하는 부분이 무엇인지
7. 안 되는 경우 왜 그런지

를 이해할 수 있어야 함.

그러면서도
한 화면에 장문의 매뉴얼을 넣으면 안 됨.

긴 설명이 필요하면:

핵심 설명
+
"자세히 보기"

구조 검토.
