- hasSelectedOccurrence=true

2. 실제 API body 확인
━━━━━━━━━━━━━━━━━━━━━━

미래 회차 assign 요청 body는 반드시 평면 값만 포함해야 한다.

정상 형태:

const requestBody = {
  class_group_id: selectedOccurrence.class_group_id,
  assigned_date: selectedOccurrence.occurrence_date,
};

body: JSON.stringify(requestBody)

금지:

- selectedOccurrence 객체 전체 전송
- assignTarget 객체 전체 전송
- PressEvent 전송
- Response 객체 전송
- AbortController 또는 signal 전송
- React state 객체 전체 전송
- options 객체 전체 재직렬화

오늘·과거 complete-direct도 동일하게 평면 값만 사용한다.

const requestBody = {
  class_group_id: selectedOccurrence.class_group_id,
  date: selectedOccurrence.occurrence_date,
};

━━━━━━━━━━━━━━━━━━━━━━
3. apiRequest 검사
━━━━━━━━━━━━━━━━━━━━━━

apiRequest 내부에서 다음 코드가 있는지 확인한다.

JSON.stringify(options)
JSON.stringify(error)
JSON.stringify(response)
JSON.stringify(requestInit)
JSON.stringify({ ...options, signal })

AbortSignal, Response, Error, Headers 또는 순환 객체를 통째로 stringify하면 안 된다.

진단이 필요하면 원시값만 기록한다.

예:

{
  method: options.method,
  path,
  hasBody: typeof options.body === "string",
}

토큰·body 전체·signal 객체를 로그용 JSON.stringify에 넣지 않는다.

6. 날짜 다시 선택 상태 정리
━━━━━━━━━━━━━━━━━━━━━━

별도로 발견된 상태 불일치도 함께 최소 수정한다.

기존:

onPress={() => setSelectedDate(null)}

수정:

onPress={() => {
  setSelectedDate(null);
  setSelectedOccurrence(null);
}}

단계 렌더 조건은 기존 구조를 유지하되
selectedDate와 selectedOccurrence가 항상 함께 설정·초기화되게 한다.
