[SWIMNOTE X PAYMENT]
[X02-D — iOS PURCHASE UI + REVENUECAT OFFERING CONNECTION]

목적:

X02-C에서 완성된 서버 결제 계약:

- POST /api/billing/x-reserve-slot
- POST /api/billing/sync-x-subscription
- RevenueCat V2 server verification
- slot / tier / product server-side 결정
- transaction binding
- cross-pool defense
- webhook idempotency
- paid/manual entitlement separation

위에 실제 iOS 구매 UI를 연결한다.

이번 WP는 APP + RevenueCat client purchase flow.

서버 정책 재설계 금지.
DB schema 변경 금지.
RevenueCat Dashboard 변경 금지.
App Store Connect 변경 금지.

15. USER CANCEL
==================================================

RevenueCat purchase에서 사용자가 취소한 경우:

기술 오류 Alert 금지.

friendly 상태:

"결제가 취소되었습니다."

reservation 자체는 서버에서 1시간 동안 RESERVED 유지 가능.

사용자가 같은 화면에서 다시 결제할 수 있어야 한다.

새 slot 예약 금지.
기존 reservation 재사용.

18. SYNC CALL
==================================================

purchase 성공 후:

POST /api/billing/sync-x-subscription

호출.

client가 body에:

entitlement=true
tier
poolId
productId

를 임의로 보내지 않는다.

현재 서버 contract가 body 없이 authenticated context로 처리한다면
그대로 사용.

필요한 최소 식별자만 현재 API contract에 맞춰 전송.

19. SYNC RETRY
==================================================

이 경우 절대:

"결제 실패"

라고 표시하지 않는다.

실제 결제는 성공했을 수 있기 때문.

표시:

"결제는 완료되었지만 X모드 활성화 확인이 지연되고 있습니다.
잠시 후 다시 확인해주세요."

그리고:

[활성화 다시 확인]

버튼 제공 가능.

이 버튼은:

sync-x-subscription

만 재호출.

purchasePackage 다시 호출 금지.
