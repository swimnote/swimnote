2. 5일 자동 실행 조건 확인
━━━━━━━━━━━━━━━━━━━━━━

현재 Production 코드 기준으로 다음을 정확히 추적하세요.

2026-09 리포트의 관리자 완료 알림이
2026-10-05에 자동 실행되는 실제 경로:

scheduler
→ monthly readiness
→ READY transition
→ readiness outbox
→ 관리자 PUSH

다음을 확인:

- 사람이 SuperAI에 로그인하지 않아도 실행됨
- 브라우저가 열려 있지 않아도 실행됨
- 서버 scheduler/worker가 자동 실행함
- 서버 restart 이후에도 정상 실행 가능
- 119/119 정상 귀결을 다시 계산함
- blocker=0을 확인한 뒤에만 READY
- 기존 5일 발급 시점 조건이 실제로 적용됨

“코드가 존재한다”가 아니라
Production에서 scheduler가 실제 활성 상태인지 확인하세요.

3. 날짜 조건
━━━━━━━━━━━━━━━━━━━━━━

2026-09 report_period의 관리자 완료 알림은
다음 달 5일인:

2026-10-05 KST

를 기준으로 해야 합니다.

UTC 날짜 혼동으로

실제 scheduler timezone과 실행 조건을 확인하세요.

임의로 현재 시간을 변경하거나
Production 시간을 우회해서 PUSH를 보내지 마세요.

Title:

Body:
이번 달 AI 성장리포트 발급이 완료되었습니다.

불필요하게 수정하지 마세요.

현재 문구가 단순히
“확인해 주세요”
수준이라 관리자 행동이 불명확하면
위 의미가 명확하도록 최소 수정합니다.

중요:

“학부모에게 이미 발송되었습니다”
라는 의미가 되면 안 됩니다.

6. 정확히 1회
━━━━━━━━━━━━━━━━━━━━━━

pool + report_month 기준
관리자 완료 PUSH는 논리적으로 정확히 1회여야 합니다.

확인:

- scheduler 중복 실행
- worker restart
- multi-instance
- PUSH timeout
- outbox replay

상황에서도 정상적으로 중복 발송되지 않는지
기존 dedupe/outbox 계약을 확인하세요.

이미 READY/PUSH 완료된 월에는
다음 scheduler tick에서 다시 보내면 안 됩니다.

━━━━━━━━━━━━━━━━━━━━━━
7. PUSH 실패 안전성
━━━━━━━━━━━━━━━━━━━━━━

PUSH provider 실패가 발생해도:

- 119개의 리포트 결과를 rollback하지 않음
- READY/report 상태를 깨뜨리지 않음
- 부모 PUBLISHED를 실행하지 않음

기존 outbox 정책에 따라 안전하게 처리되어야 합니다.

PUSH 전달 수락이 불확실한 경우
무조건 반복 발송해서 중복 PUSH를 만들지 마세요.

━━━━━━━━━━━━━━━━━━━━━━
8. 학부모 공개 경계
━━━━━━━━━━━━━━━━━━━━━━

5일 자동 시퀀스의 끝은:

관리자 PUSH

입니다.

그 뒤:

관리자 검수
→ 기존 관리자 개별/일괄 발송
→ 부모 PUBLISHED/PUSH

는 기존 수동 관리자 경로입니다.

5일 scheduler가:

- 부모 PUBLISHED
- 부모 PUSH
- 관리자 승인 우회

를 자동 실행하면 안 됩니다.

━━━━━━━━━━━━━━━━━━━━━━
9. 다음 달 이후 자동 반복
━━━━━━━━━━━━━━━━━━━━━━

이번 9월 데이터만 특수 처리되는 구조가 아니라
앞으로 모든 report_month에서 동일해야 합니다.

예:

2026-10 수업 데이터
→ 2026-11-01 자동 first-pass 시작
→ 정상/실패 처리
→ pool별 100% 정상 귀결
→ 2026-11-05 관리자 완료 PUSH

수영장 수가 증가해도
각 pool + report_month별 독립 READY/outbox를 사용해야 합니다.

한 수영장의 blocker 때문에
다른 완료 수영장의 5일 관리자 PUSH가 막히면 안 됩니다.

━━━━━━━━━━━━━━━━━━━━━━
10. 검증 방법
━━━━━━━━━━━━━━━━━━━━━━

Production은 READ ONLY 확인.

격리 test/fixture에서 검증하세요.

필수 검증:

1. 119/119 + blocker 0
2. 5일 이전 → PUSH 없음
3. 5일 도달 → READY/outbox 생성
4. 관리자 recipient만 대상
5. 정확히 1회
6. duplicate scheduler → 중복 없음
7. restart/replay → 중복 없음
8. 한 pool 실패 → 다른 완료 pool 정상 알림
9. 부모 PUBLISHED = 0
10. 부모 PUSH = 0
11. 관리자 수동 발송 경로 그대로 유지
12. 다음 report_month에서도 동일 반복

관련 테스트만 실행하세요.
전체 suite/typecheck 금지.
