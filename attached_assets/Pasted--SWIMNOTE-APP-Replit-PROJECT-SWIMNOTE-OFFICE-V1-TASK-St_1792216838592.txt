1. 업무 정책 정합성

사용자 확정 정책:
- 명확한 단일 회원의 일반정보 수정·반이동:
  검증 후 실행하고 변경 전후 보고.
- 대상·값·범위가 모호하면 질문/선택.
- 발송·결제·삭제·대량 변경 등은 실행 전 사용자 확인.

현재 “모든 AI 제안에 별도 확인”이 적용돼 있다면
이번 단계의 임시 제한인지 최종 정책인지 구분한다.
모델이 확인 정책을 정하지 못하게 하고,
메뉴·AI가 공통 업무 정책을 사용하도록 정리한다.
운영 실행은 계속 비활성 상태로 유지한다.

2. 저장·반이동의 교차 경로 검증

기존 격리 DB와 실제 관련 handler를 사용한다.

- 기존 앱/Web legacy 수정과 OFFICE 수정의 동시 실행.
- 반 정원 마지막 자리에 대한 동시 배정/이동.
- 같은 회원의 서로 다른 소속 변경.
- 현재 값과 행버전 불일치.
- 반이동이 주당 횟수·일정·수강 이력에 미치는 실제 영향.

검증 결과를 구분:
- OFFICE 경로 내부에서 보장되는 것.
- legacy 경로와 함께 실행해도 보장되는 것.
- 전체 경로 협조 없이는 보장하지 못하는 것.

행버전 방식의 정확한 종류·수명·직렬화·재사용 한계를 명시한다.
클라이언트 비교만으로 충돌 안전성을 주장하지 않는다.

문제가 발견되면 관련 경로의 최소 호환 수정까지 로컬에서 수행.
schema 변경·광범위 legacy 개편이 필요하면 해당 부분만 보류.
운영 데이터로 경쟁 실험하지 않는다.

3. 완료 기록·중복 방지 계약

pool_event_logs 사용에 대해 확인:
- 기존 schema·필수 필드·인덱스·권한.
- 기록과 변경의 원자성.
- 동시 동일 요청 처리.
- 같은 요청 번호의 다른 payload 거부.
- 사용자/Pool 간 상태 조회 격리.
- 기존 SSE·이벤트 소비자와의 호환.
- 정리·보존 기간·삭제 job.
- 보관 기간이 지난 요청과 미확인 요청의 처리.

로그 삭제 이후에도 무기한 중복 방지를 보장한다고 표현하지 않는다.
지원 가능한 재확인 기간과 만료 후 동작을 명시한다.
결과 불명 상태에서 새 요청 번호로 자동 재실행하지 않는다.
상태 조회 오류를 “처리되지 않음”으로 해석하지 않는다.

4. 모델 호출 준비

기존 APP 모델 경로·실제 모델 설정·Secret 존재 여부만 확인.
값·접두사·해시 출력 금지.

확인:
- 구조화 응답 검증과 지원 Action 제한.
- timeout·출력 한도·호출 횟수 상한.
- 해석 재시도와 업무 실행 재시도 분리.
- 동명이인·모호한 반·복합 지시·미지원 요청.
- 한 요청 안의 여러 작업은 지원/거부 범위를 명시.
- 민감정보 최소 전달·로그 기록 범위.

이번 실제 유료 모델 호출은 하지 않는다.
후속 합성 데이터 모델 검증의 요청 목록·호출 상한·
사용 모델과 비용 산정 근거를 준비한다.
실제 호출 전 모델 동작 PASS를 선언하지 않는다.

5. 운영 DB 계약 확인 경계

운영 업무 데이터 조회·쓰기 없이 판단한다.
기존 migration/schema 정의·확보된 배포 증거를 우선 사용한다.

실제 운영 schema 호환성이 확인되지 않으면 UNKNOWN 유지.
이를 이유로 mock 결과를 운영 호환 증거로 바꾸지 않는다.
후속 배포 전 필요한 최소 읽기 전용 메타데이터 확인 항목을 명시한다.
이번 운영 DB 접속·API startup은 실행하지 않는다.

- 기존 CORS·SSE 보완 포함 여부.

- 환경변수/gate 기본값과 활성화 조합.
- Desktop renderer/main/server 버전 호환 조건.
- API만 먼저 배포해도 기존 앱/Web에 미치는 영향.
- 비활성화·롤백 절차 및 기존 완료 기록과의 관계.

현재 개발 HEAD 전체를 배포 후보로 지정하지 않는다.
새 commit 없이 patch·파일 해시로 후보를 식별한다.
patch 식별값을 배포 가능한 commit SHA라고 표현하지 않는다.
