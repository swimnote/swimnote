==================================================
1. 앱 → SWIMNOTE API 서버 연결 실증
==================================================

실제 운영 앱이 사용하는 Base URL을 기준으로 다음을 직접 실행하십시오.

A.
GET 또는 HEAD:
https://swimnote.kr/api 또는 현재 운영 API health endpoint

B.
POST:
현재 앱이 실제 호출하는 Teacher Diary URL

반드시 다음 둘 다 실측하십시오.

- /api/ai/diary/generate
- /api/v1/teacher-diary/generate

각 요청마다 제출:

- 최종 전체 URL
- HTTP method
- HTTP status
- Content-Type
- Response Body 원문
- 응답 시간
- DNS/TLS/Network 오류 여부
- 요청이 Render 로그에 실제 찍혔는지

인증 없는 curl은 401이어도 정상입니다.
핵심은 서버까지 실제 도달하는지입니다.

==================================================
2. 유효한 앱 JWT로 API 실증
==================================================

가짜 토큰이나 무인증 curl로 끝내지 마십시오.

현재 운영 앱과 동일한 인증 구조로 유효한 테스트 JWT를 사용하여
Teacher Diary API를 실제 호출하십시오.

제출 항목:

- request_id
- HTTP status
- Response Body 원문
- 서버 로그에서 동일 request_id 확인
- 인증 통과 여부
- pool_id 권한 통과 여부
- class_id 검증 통과 여부
- students 검증 통과 여부

JWT 원문은 보고서에 노출하지 마십시오.

==================================================
3. SWIMNOTE API 서버 → AI Engine 연결 실증
==================================================

Teacher Diary 요청이 SWIMNOTE API 서버에 도착한 뒤,
실제로 AI Engine까지 전달되는지 확인하십시오.

다음 흐름을 request_id 하나로 끝까지 추적하십시오.

APP REQUEST
→ SWIMNOTE API ROUTE
→ AUTH
→ TEACHER DIARY HANDLER
→ AI ENGINE CLIENT/ROUTE
→ GROUNDED PIPELINE
→ TEMPLATE SEARCH
→ KNOWLEDGE SEARCH
→ NATURALIZER
→ RESPONSE

반드시 제출:

- 앱/API request_id
- SWIMNOTE 서버 수신 로그
- AI Engine 수신 로그
- AI Engine 호출 URL
- AI Engine HTTP status
- AI Engine Response Body
- 최종 앱용 Response Body
- 중간에 request_id 변경 여부
- timeout/network error 여부

==================================================
4. 실제 Grounded Pipeline 진입 증거
==================================================

“AI Engine 연결됨”이라고 말하지 말고 아래 로그를 제출하십시오.

- pipeline_mode
- engine_version
- generation_mode
- template_ids
- knowledge_ids
- grounding_validation
- latency_ms
- student_ref 반환값

다음 값이 없으면 Grounded Pipeline 연결 완료로 인정하지 않습니다.

==================================================
5. 실제 호출 경로 확정
==================================================

현재 앱의 grounded 모드 최종 경로는 반드시:

POST /api/v1/teacher-diary/generate

이어야 합니다.

만약 앱이 여전히:

POST /api/ai/diary/generate

를 호출한다면 그 사실을 숨기지 말고 보고하십시오.

제출:

- 런타임 mode
- 런타임 base URL
- 런타임 path
- 최종 합성 URL
- 이 값이 어느 파일/환경변수에서 결정되는지

==================================================
6. 앱 오류 분류 확인
==================================================

현재 화면은 NETWORK 오류처럼 표시됩니다.

실제 실패가 무엇인지 확인하십시오.

가능한 분류:

- DNS
- TLS
- fetch network error
- timeout
- 401
- 403
- 404
- 422
- 500
- content-type
- parse error
- contract error

실제 causeCode와 원본 오류를 제출하십시오.

“네트워크 오류로 보입니다” 같은 추정 금지.
