SWIMNOTE AI 성장리포트
발급 기준 / 관리자 명단 정비 최종 지시

현재 작업 방향은 맞지만 아래 기준으로 수정하십시오.

중요:
APP에서 이미 확정된 정책은

2026년 9월 리포트
=
2026년 8월 수업 분석

입니다.

이 기준을 절대 변경하지 마십시오.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. Summary 카운트 중복 수정
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

현재 growth_reports와
student_class_history JOIN으로 인해

주2회 이상 수강 학생은
동일 growth_report가 여러 행으로 증식할 수 있습니다.

growth_report 1행 = 학생 1명의 리포트 1건

이 원칙으로 집계하십시오.

전체 카운트뿐 아니라
모든 상태별 카운트를
DISTINCT growth_report id 기준으로 계산하십시오.

예:

COUNT(DISTINCT gr.id)

상태별 집계도 동일하게
DISTINCT gr.id 기준으로 처리하십시오.

검증:

- 전체
- 생성 전
- 분석 중
- 검수 대기
- 발송 대기
- 발행 완료
- 제외
- 실패

각 숫자의 합/관계가 실제 growth_reports row와 일치해야 합니다.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2. 명단 중복 제거
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

관리자 목록에서도

growth_report 1건
=
학생 1명
=
리스트 1줄

이어야 합니다.

주2회 / 주3회 학생을
반 개수만큼 여러 줄 표시하지 마십시오.

선택안은 B로 확정합니다.

예:

강아람
화 19:00 · 토 11:00
김수연

처럼
해당 학생의 반을 한 줄 안에 묶어서 표시하십시오.

임의로 첫 번째 반 하나만 선택하지 마십시오.

JOIN fan-out 이후 DISTINCT ON으로 우연히 하나를 고르는 방식보다
학생별 class 정보를 aggregate/subquery하여
명시적으로 묶는 방식을 우선하십시오.

3. 현재 반 표시와 분석대상 반을 혼동하지 마십시오
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

관리자 명단에 표시하는 반 정보는
현재 반 정보를 사용할 수 있습니다.

하지만 이것은 화면 식별용 정보입니다.

Growth Report 분석 데이터 선택에는
현재 active class 조건인

left_at IS NULL

을 사용하지 마십시오.

예:

2026년 9월 리포트

화면:
현재 9월 반 정보 표시 가능

분석:
반드시 2026년 8월 실제 수업기록만 사용

현재 반과
분석 원천 수업을 분리하십시오.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
4. 발급 월 / 분석 월 계약
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

공식 정책:

report_month = 2026-09
analysis_period = 2026-08-01 이상
                  2026-09-01 미만

즉:

9월 리포트 = 8월 수업 분석
10월 리포트 = 9월 수업 분석
1월 리포트 = 전년도 12월 수업 분석

입니다.

현재 서버 날짜를 이용하여
분석월을 추론하지 마십시오.

항상 report_month 기준으로
직전 calendar month를 계산하십시오.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
5. 발급 대상 자격
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

기존 "등록되어 있으면 전부 발급" 정책은 사용하지 않습니다.

무료 AI 성장리포트 대상은
다음 두 조건을 모두 만족해야 합니다.

A.
report_month에 재등록된 회원

B.
analysis_period에
AI가 분석할 수 있는 유효 수업기록이
최소 2건 이상 존재

예:

2026년 9월 AI 성장리포트

1.
9월 재등록 완료

AND

2.
8월 유효 수업기록 2건 이상

→ 발급 대상

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
6. 출석률 50%를 primary gate로 사용하지 마십시오
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

현재 제안된:

출석률 50% 이상
+
최소 2회

를 최종 발급 기준으로 사용하지 않습니다.

Growth Report는
출석 리포트가 아니라
실제 수업기록 기반 리포트입니다.

따라서 primary quality gate는:

"분석 가능한 실제 수업기록 수"

입니다.

출석 데이터는
보조 검증 및 향후 통계로 사용할 수 있지만

출석률만으로
리포트 생성 여부를 결정하지 마십시오.

예:

출석 5회 + 유효 수업기록 5건
→ 충분한 분석 가능

출석 8회 + 유효 수업기록 1건
→ 분석 근거 부족

이 차이를 반영하십시오.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
7. 데이터 부족 처리
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

analysis_period 유효 기록:

0건 또는 1건
→ 자동 리포트 생성 대상에서 제외

2건 이상
→ 생성 대상

이번 기준은 초기 Production 기준입니다.

향후 실제 운영 데이터를 보고
2건 → 3건 등으로 변경할 수 있도록
magic number로 여러 곳에 하드코딩하지 마십시오.

환경설정/정책 상수 하나로 관리하십시오.

예:

GROWTH_REPORT_MIN_SOURCE_RECORDS = 2

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
8. 제외 사유를 구분하십시오

EXCLUDED 하나만 저장하더라도

예:

INSUFFICIENT_SOURCE_DATA
NO_SOURCE_DATA
MANUAL_EXCLUDED
