[P0 — DIARY NAVIGATION CONSOLIDATION IMPLEMENTATION]

PRE-DESIGN 조사 완료.
이제 설계대로 실제 통합 구현한다.

새 구조 추가 금지.
서버 변경 금지.
기존 기능 누락 없이 화면/경로만 단순화한다.

━━━━━━━━━━━━━━━━━━━━━━
1. 최종 canonical 화면
━━━━━━━━━━━━━━━━━━━━━━

Admin diary list:
/(admin)/diary-hub

Teacher diary write/detail:
/(teacher)/diary

Detail:
teacher/diary?viewOnly=true

이 3개를 canonical 기준으로 사용.

━━━━━━━━━━━━━━━━━━━━━━
2. Admin 일지 목록 통합
━━━━━━━━━━━━━━━━━━━━━━

아래 진입은 전부 /(admin)/diary-hub 로 통일:

- 관리자 전체 일지
- 회원관리 → 학생 → 일지
- X Dashboard → AI 일지
- class-hub → 선생님별 일지

진입 param만 다르게 사용:

전체:
filter 없음

학생:
studentId={student.id}

AI:
aiFilter=true

선생님:
teacher_id={teacher.id}

별도 데이터 화면 추가 금지.

━━━━━━━━━━━━━━━━━━━━━━
3. admin/diary-write / diary-teacher-entries 제거
━━━━━━━━━━━━━━━━━━━━━━

두 화면은 diary-hub와 동일 class_diaries source를 사용하므로
기능 흡수 후 navigation에서 제거.

단 제거 전에 반드시:

- 일괄 삭제 기능
- 기존 조회 기능

을 diary-hub에 흡수.

기능 누락 확인 후에만 route 비노출/제거.

━━━━━━━━━━━━━━━━━━━━━━
4. Teacher 진입 단순화
━━━━━━━━━━━━━━━━━━━━━━

기본 원칙:

스케줄러
→ 수업카드
→ teacher/diary

classGroupId
lessonDate/date
backTo

를 그대로 전달.

이미 반/날짜를 알고 있으면
다시 반/날짜를 선택하게 하지 않는다.

━━━━━━━━━━━━━━━━━━━━━━
5. 날짜 변경
━━━━━━━━━━━━━━━━━━━━━━

다른 날짜 이동은:

teacher/diary 상단의
기존 날짜/요일 변경 UI만 사용.

새 날짜별 일지 화면 추가 금지.

날짜 이동을 위해 diary-index 등 다른 화면을 강제로 거치지 않는다.

━━━━━━━━━━━━━━━━━━━━━━
6. 반 변경
━━━━━━━━━━━━━━━━━━━━━━

teacher/diary 내부에
반 변경 picker/dropdown 추가 금지.

다른 반으로 이동:

Diary
→ Back
→ Scheduler
→ 다른 수업 카드 선택
→ Diary

이 흐름으로 고정.

━━━━━━━━━━━━━━━━━━━━━━
7. diary-index 역할 최소화
━━━━━━━━━━━━━━━━━━━━━━

teacher/diary-index가
Teacher 전체/학생별 목록에 필요한 기능이 있으면 유지 가능.

하지만:

- 날짜 이동용
- 반 선택용
- 불필요한 중간 경로

로 사용하지 않는다.

중복 진입점이면 제거/비노출 후보로 정리.

Teacher 학생 상세 → 일지 목록 기능이 필요하면
현재 teacher 권한에서 정상 작동하는 경로를 유지.

Admin diary-hub를 Teacher 토큰으로 재사용하지 말 것.

━━━━━━━━━━━━━━━━━━━━━━
8. 상세 화면 통일
━━━━━━━━━━━━━━━━━━━━━━

모든 Admin 일지 row:

→ /(teacher)/diary
   ?editDiaryId={id}
   &viewOnly=true

기존 canonical detail 사용.

Home 이동 금지.

━━━━━━━━━━━━━━━━━━━━━━
9. diary_upload 알림 버그 수정
━━━━━━━━━━━━━━━━━━━━━━

현재 diary_upload 알림:

→ teacher/diary
→ editDiaryId 없음
→ 빈 작성 화면

버그 수정.

알림 payload의 실제 diary id를 사용해서:

→ teacher/diary
   ?editDiaryId={diaryId}
   &viewOnly=true 또는 정책상 맞는 상세모드

로 직접 진입.

없는 diary id 생성/추측 금지.

━━━━━━━━━━━━━━━━━━━━━━
10. Back navigation
━━━━━━━━━━━━━━━━━━━━━━

Scheduler → Diary
→ Back = 동일 Scheduler

Admin diary-hub → Detail
→ Back = diary-hub + 기존 필터 유지

X Hub → diary-hub(AI)
→ Detail
→ Back = diary-hub(AI)
→ 다시 Back = X Hub

Member Detail → diary-hub(student)
→ Detail
→ Back = diary-hub(student)
