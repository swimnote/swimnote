[임시 Production 진단 OTA — iOS picker 순서 확인 전용]

직전 조사에서 preview OTA는
현재 App Store 설치본이 production-v2만 구독하므로
실기기로 전달할 수 없음을 확인했습니다.

따라서 이번에는
production-v2에 아주 제한적인 임시 진단 UI만 넣습니다.

목표:
실제 App Store iPhone에서

사용자 선택 순서
→ expo-image-picker result.assets 순서

가 일치하는지만 확인.

중요:
사진 업로드 금지.
서버 요청 금지.
DB write 금지.
API 수정 금지.
Native 변경 금지.
새 binary/store build 금지.

2. 진단 기능
━━━━━━━━━━━━━━━━━━━━━━

allowsMultipleSelection = true
orderedSelection = true
selectionLimit = 10

picker 완료 후:

result.assets 배열을 그대로 화면에 표시.

표시:

[1] thumbnail
[2] thumbnail
...
[10] thumbnail

즉:

result.assets[0]
result.assets[1]
...

순서 그대로.

금지:

- 업로드
- directUploadPhotos 호출
- API 요청
- R2 요청
- 파일명 표시
- URI 표시
- assetId 표시
- EXIF 표시
- console log
- analytics 전송

오직 로컬 thumbnail + 배열 index만 표시.

버튼:
- 다시 선택
- 닫기

4. 판정
━━━━━━━━━━━━━━━━━━━━━━

위 순서가 동일하면:

IOS PICKER ORDER = PASS

즉 현재 전체앨범 canonical path에서는

picker
→ client
→ upload_sort_order
→ DB
→ API
→ UI

전체가 순서 보존.

이 경우 제보 원인은
전체앨범 정상 직접 업로드 외의
다른 진입점/재시도/저장앨범/일지 등으로 다시 좁혀야 함.

picker badge와 result.assets가 다르면:

IOS PICKER ORDER = FAIL

FIRST BREAK POINT =
expo-image-picker/native picker result

로 확정.
