# SWIMNOTE 앱 Teacher Diary AI 연동

## 최종 설계 및 단계별 구현 지시서 V1.0

---

# 0. 문서 목적

이 문서는 SWIMNOTE 앱 Repository에서 Teacher Diary AI 기능을 안정적으로 연결하기 위한 최종 설계 및 작업 지시서이다.

이번 작업의 핵심은 다음과 같다.

```text
SWIMNOTE 앱
= 사용자 입력, 수업 사실, 학생 정보, Draft 표시, 최종 저장

SWIMNOTE AI Engine
= 학생 분리, 이름 매칭, 지식 검색, 문장 생성, 결과 검증
```

앱에서 AI 분석 로직을 구현하지 않는다.

전체 작업을 한 번에 진행하지 않는다.

각 단계는 반드시 다음 순서로 진행한다.

```text
작업 수행
↓
테스트
↓
결과 보고
↓
검토 및 승인
↓
다음 작업
```

Agent는 각 작업 꼭지가 끝나면 반드시 작업을 멈추고 보고해야 한다.

승인 없이 다음 단계로 넘어가면 안 된다.

---

# 1. 현재 Repository 기준 확인된 구조

## 1.1 앱

현재 앱에는 다음 기능이 존재한다.

```text
음성 녹음
Whisper STT
AI 요청
공통 일지 Draft 표시
학생별 일지 Draft 표시
교사 수정
기존 일지 입력란 적용
기존 Diary 저장
```

학생 정보는 다음 구조를 사용한다.

```ts
interface StudentOption {
  id: string;
  name: string;
  birth_year?: string | null;
}
```

정의:

```text
id
= student_ref로 사용 가능

name
= 학생 전체 이름
```

앱은 학생 이름을 분해하거나 변형하지 않는다.

---

## 1.2 반 및 수업 정보

현재 반 정보에는 다음이 존재한다.

```text
group.id
= class_id

swimming_pool_id
= pool_id

lesson_date
= 수업일
```

현재 Repository에는 별도의 `lesson_ref` 개념이 없다.

따라서 이번 작업에서는:

```text
class_id + lesson_date
```

를 수업 Context로 사용한다.

가짜 `lesson_ref`를 새로 만들지 않는다.

---

## 1.3 기존 Diary 저장

기존 Diary 저장 구조는 유지한다.

```json
{
  "class_group_id": "class_xxx",
  "lesson_date": "YYYY-MM-DD",
  "common_content": "공통 일지",
  "student_notes": [
    {
      "student_id": "student_xxx",
      "note_content": "학생별 일지"
    }
  ]
}
```

AI 응답은 Draft일 뿐이다.

최종 저장은 기존 Diary 저장 API를 그대로 사용한다.

# 3. 최종 Request Contract

앱은 AI Engine에 다음 구조로 요청한다.

```json
{
  "request_id": "diary_request_xxx",
  "schema_version": "1.0",
  "feature": "teacher_diary",
  "locale": "ko-KR",
  "input": {
    "text": "STT 원문 또는 교사 입력 원문"
  },
  "context": {
    "pool_id": "pool_xxx",
    "class_id": "class_xxx",
    "lesson_date": "2026-07-29",
    "student_refs": [
      "student_001",
      "student_002"
    ],
    "students": [
      {
        "ref": "student_001",
        "name": "서태웅"
      },
      {
        "ref": "student_002",
        "name": "김민수"
      }
    ]
  }
}
```

---

## 3.1 필드 정의

### request_id

앱에서 요청마다 생성한다.

요구사항:

```text
요청마다 고유할 것
재시도 시 새 ID인지 기존 ID인지 정책을 명확히 할 것
AI 응답의 request_id와 비교 가능할 것
로그 추적에 사용할 수 있을 것
```

권장 정책:

```text
사용자가 새로 “AI 생성”을 누르면 새 request_id

네트워크 계층의 자동 재시도는 같은 request_id 유지

사용자가 “다시 생성”을 누르면 새 request_id
```

기존 프로젝트에 ID 생성 Utility가 있으면 재사용한다.

불필요한 외부 패키지를 추가하지 않는다.

---

### input.text

다음만 허용한다.

```text
교사가 직접 입력한 원문
Whisper가 반환한 원문
양 끝 공백 trim
```

금지:

```text
문장 의미 변경
학생 이름 수정
조사 제거
오탈자 추정 교정
문장 재배열
공통/학생 구분
```

---

### pool_id

현재 `swimming_pool_id`를 사용한다.

`organization_ref`를 새로 만들지 않는다.

---

### class_id

현재 `class_group_id` 또는 `group.id`를 사용한다.

---

### lesson_date

기존 Diary에서 사용하는 `YYYY-MM-DD` 형식을 유지한다.

---

### student_refs

V1 호환을 위해 임시 유지한다.

```text
students[].ref 목록과 반드시 일치해야 한다.
```

장기적으로 AI Engine 안정화 후 제거할 수 있지만 이번 작업에서는 제거하지 않는다.

---

### students

학생 전체 목록을 전달한다.

```ts
type DiaryStudentContext = {
  ref: string;
  name: string;
};
```

규칙:

```text
ref = StudentOption.id
name = StudentOption.name
name은 전체 이름 그대로
given_name 생성 금지
성 제거 금지
조사 추가 금지
별칭 생성 금지
```

# 4. 최종 Response Contract

앱이 목표로 삼을 표준 응답:

```json
{
  "request_id": "diary_request_xxx",
  "schema_version": "1.0",
  "result": {
    "common": "공통 일지 문장",
    "students": [
      {
        "student_ref": "student_001",
        "content": "학생별 일지 문장"
      }
    ]
  },
  "usage": {
    "input_tokens": 0,
    "output_tokens": 0,
    "total_tokens": 0
  }
}
```

---

## 4.1 앱 응답 처리 우선순위

표준 필드:

```text
student_ref
content
```

임시 호환 필드:

```text
student_id
feedback
```

앱 처리 우선순위:

```ts
const studentRef =
  item.student_ref ??
  item.student_id;

const content =
  item.content ??
  item.feedback;
```

표준 필드가 존재하면 반드시 표준 필드를 우선 사용한다.

호환 필드는 AI Engine 전환 기간에만 유지한다.

---

## 4.2 request_id 검증

응답의 `request_id`는 요청 시 보낸 값과 같아야 한다.

다를 경우:

```text
응답을 현재 Draft에 적용하지 않는다.
표준 오류 처리로 전환한다.
개인정보 없이 mismatch 로그를 남긴다.
```

이 검증은 늦게 도착한 이전 요청의 응답이 현재 Draft를 덮어쓰는 문제를 방지한다.

# 6. 이번 프로젝트 작업 범위

전체 작업은 다음 6개 Work Package로 나눈다.

```text
WP0 현재 구조 재확인
WP1 Request Contract
WP2 Response Contract
WP3 안전성·로그·동시 요청 처리
WP4 통합 테스트
WP5 커리큘럼 구조 사전 조사
```

각 Work Package는 독립적으로 검토받는다.

WP0~WP4는 Teacher Diary AI 연결 작업이다.

WP5는 다음 대형 작업을 위한 조사만 수행한다.

WP5에서는 Migration이나 신규 DB를 만들지 않는다.

---

# 7. 공통 작업 규칙

각 Work Package마다 다음을 지킨다.

## 작업 시작 전

Agent는 먼저 다음을 보고한다.

```text

수정 이유
현재 코드 흐름
예상 영향 범위
테스트 계획
```

단, 이 보고 후 별도 질문 없이 해당 Work Package 범위는 구현해도 된다.

---

## 작업 완료 후

반드시 다음 형식으로 보고하고 멈춘다.

```text

```


# 9. WP1 — Request Contract 수정

## 목적

AI Engine에 학생 ref와 전체 이름, request_id를 정확하게 전달한다.

---

## 구현 항목

### 1. request_id 생성

새 AI 생성 요청마다 생성한다.

### 2. context.students 추가

```ts
students: options.students.map((student) => ({
  ref: student.id,
  name: student.name,
}))
```

실제 변수명은 현재 Repository 구조에 맞게 적용한다.

### 3. student_refs 유지

```ts
student_refs: options.students.map((student) => student.id)
```

### 4. Context 유지

```text
pool_id
class_id
lesson_date
```

### 5. 추가 금지

```text
organization_ref
lesson_ref
given_name
template 목록
knowledge 목록
curriculum 임의 값
```

---

## Request Type 정의

가능한 경우 기존 TypeScript 타입에 명시적으로 추가한다.

```ts
type TeacherDiaryAIRequest = {
  request_id: string;
  schema_version: "1.0";
  feature: "teacher_diary";
  locale: "ko-KR";
  input: {
    text: string;
  };
  context: {
    pool_id: string;
    class_id: string;
    lesson_date: string;
    student_refs: string[];
    students: Array<{
      ref: string;
      name: string;
    }>;
  };
};
```

중복 타입을 여러 파일에 만들지 않는다.

기존 공통 API 타입 파일이 있으면 재사용한다.

---

## Request 사전 검증

AI 호출 전에 최소 검증한다.

```text
request_id 존재
input.text가 비어 있지 않음
pool_id 존재
class_id 존재
lesson_date 형식 정상
students 배열 존재
students[].ref 존재
students[].name 존재
student_refs와 students[].ref가 일치
```

학생 이름을 수정하거나 분석하는 검증은 금지한다.

---

## WP1 테스트

최소 다음을 검증한다.

### 정상

```text
학생 1명
학생 여러 명
한글 이름
외국 이름
띄어쓰기가 있는 이름
STT 원문
직접 입력 원문
```

### 오류

```text
pool_id 없음
class_id 없음
빈 input.text
학생 ref 없음
학생 name 없음
student_refs와 students 불일치
```

---

## WP1 증거물

다음을 제출한다.

```text
수정된 Request Type
실제 Request 예시
개인정보를 마스킹한 개발 로그
테스트 결과
기존 AI 호출이 깨지지 않았다는 증거
```

실제 학생 이름이나 원문이 포함된 로그는 제출하지 않는다.

## WP1 통과 조건

```text
STT 원문 변형 없음
기존 Draft 화면 진입 가능
기존 Diary Save 변경 없음
TypeScript 오류 없음
```

WP1 완료 후 반드시 멈춘다.

# 10. WP2 — Response Contract 수정

## 목적

AI Engine의 표준 응답과 기존 응답을 안전하게 처리한다.

---

## 구현 항목

### 표준 응답

```text
student_ref
content
```

### 임시 호환

```text
student_id
feedback
```

### 공통 결과

```text
result.common
```

---

## 응답 변환 규칙

```ts
const studentRef =
  studentResult.student_ref ??
  studentResult.student_id;

const content =
  studentResult.content ??
  studentResult.feedback;
```

학생 ref가 없으면 결과를 임의 학생에게 적용하지 않는다.

학생 목록에 존재하지 않는 ref가 반환되면:

```text
해당 학생 결과는 적용하지 않음
안전한 오류 또는 경고 처리
개인정보 없이 invalid_ref 로그
```

---

## request_id 일치 검사

```text
request.request_id === response.request_id
```

일치하지 않으면 Draft에 적용하지 않는다.

---

## 중복 학생 처리

같은 `student_ref`가 여러 번 반환되면 임의로 합치지 않는다.

권장 처리:

```text
Response Contract 오류로 취급
Draft 적용 중단
오류 상태 표시
```

AI Engine Output Validator가 원칙적으로 막아야 하지만 앱도 방어한다.

---

## 누락 학생 처리

AI 응답에 일부 학생만 존재할 수 있다.

따라서:

```text
응답에 없는 학생의 기존 수동 입력은 유지
빈 문자열로 덮어쓰지 않음
전체 학생 결과가 반드시 반환된다고 가정하지 않음
```

---

## 기존 입력 보존

AI 결과를 적용할 때 기존 수동 입력을 삭제하지 않는다.

현재 앱의 기존 입력 보존 정책을 유지한다.

정확한 합성 방식은 현재 코드 동작을 기준으로 유지하고, 이번 Work Package에서 UX 정책을 변경하지 않는다.

---

## WP2 테스트

```text
표준 응답만 반환
구형 응답만 반환
표준과 구형 필드가 동시에 반환
request_id 불일치
알 수 없는 student_ref
중복 student_ref
학생 일부 누락
common만 반환
students만 반환
빈 students 배열
잘못된 JSON 또는 타입
```

---

## WP2 통과 조건

```text
student_ref/content 우선
구형 필드 임시 호환
request_id mismatch 차단
알 수 없는 학생 결과 차단
기존 수동 입력 보존
기존 Diary Save 구조 변경 없음
```

WP2 완료 후 반드시 멈춘다.

# 11. WP3 — 안전성·로그·동시 요청 처리

## 목적

중복 요청, 늦게 도착한 응답, 개인정보 로그 문제를 해결한다.

---

## 구현 항목

### 1. 개인정보 로그 제거

다음 로그를 모두 검색한다.

```text
GENERATE-REQ
GENERATE-RES
AI DIARY
Whisper transcript
student name
response body
Authorization
```

학생 이름·원문·결과 본문을 제거한다.

---

### 2. 중복 버튼 방지

AI 요청 처리 중에는 같은 생성 버튼을 연속 실행하지 못하게 한다.

기존 State Machine에 Processing 상태가 있으면 재사용한다.

---

### 3. 최신 요청만 적용

최신 활성 `request_id`를 보관한다.

응답이 도착했을 때 현재 활성 요청과 다르면 Draft에 적용하지 않는다.

---

### 4. 컴포넌트 종료 안전성

가능한 범위에서:

```text
unmount 후 State 업데이트 방지
요청 취소 가능 여부 확인
AbortController 사용 가능 여부 확인
```

기존 API Client 구조상 AbortController가 과도한 변경을 요구하면 억지로 추가하지 않는다.

대신 request_id 기반 stale response 차단을 반드시 구현한다.

---

### 5. 오류 메시지

서버의 내부 오류 문자열을 사용자에게 그대로 노출하지 않는다.

사용자 메시지와 개발 로그를 분리한다.

예:

```text
사용자:
AI 일지를 생성하지 못했습니다. 잠시 후 다시 시도해주세요.

개발 로그:
error.code, HTTP status, request_id
```

---

## WP3 테스트

```text
생성 버튼 빠르게 두 번 클릭
첫 번째 요청이 두 번째 요청보다 늦게 응답
화면 이동 후 응답 도착
네트워크 오류
401
403
429
500
Timeout
잘못된 Response
```

---

## WP3 통과 조건

```text
학생 이름 로그 없음
STT 원문 로그 없음
전체 AI 결과 로그 없음
Token 로그 없음
중복 클릭 방지
늦은 응답 덮어쓰기 방지
사용자에게 내부 서버 오류 미노출
```

WP3 완료 후 반드시 멈춘다.

# 13. WP5 — SWIMNOTE X 커리큘럼 통합 사전 조사

## 중요

WP5는 구현 작업이 아니다.

Teacher Diary만을 위한 별도 커리큘럼 DB를 새로 만들지 않는다.

SWIMNOTE X의 기존 또는 계획된 커리큘럼 구조와 통합하기 위한 조사다.

---

## 조사 목적

최종적으로 하나의 커리큘럼 데이터를 다음 기능이 같이 사용해야 한다.

```text

교재 순서

```

Teacher Diary 전용 커리큘럼과 X 전용 커리큘럼을 따로 만들면 안 된다.

---

# 16. Checkpoint 및 Rollback 규칙

각 Work Package 완료 후 Checkpoint를 생성한다.

권장 이름:

```text
checkpoint/teacher-diary-wp0-audit
checkpoint/teacher-diary-wp1-request-contract
checkpoint/teacher-diary-wp2-response-contract
checkpoint/teacher-diary-wp3-safety
checkpoint/teacher-diary-wp4-integration
```

Rollback 기준:

```text
기존 AI Diary 호출 실패
기존 Whisper 실패
기존 수동 일지 입력 실패
기존 Diary 저장 실패
다른 Teacher 화면 오류
TypeScript Build 실패
앱 실행 실패
인증 오류 증가
학생 Draft가 잘못된 학생에게 적용
```

문제 발생 시 해당 Work Package 시작 전 Checkpoint로 복귀 가능해야 한다.

# 17. Agent 최종 실행 명령

아래 규칙에 따라 작업한다.

```text
1. 지금은 WP0만 수행한다.

2. WP0에서는 코드를 수정하지 않는다.

3. WP0 보고서를 제출한 뒤 멈춘다.

4. 승인받기 전에 WP1을 시작하지 않는다.

5. 이후에도 Work Package 하나만 수행한다.

6. 각 Work Package 종료 시 테스트와 수정 파일을 보고한다.

7. 승인 없이 다음 Work Package로 넘어가지 않는다.

8. 관련 없는 리팩터링을 하지 않는다.

9. Production 배포를 하지 않는다.

10. 커리큘럼 DB와 Migration을 생성하지 않는다.
```
