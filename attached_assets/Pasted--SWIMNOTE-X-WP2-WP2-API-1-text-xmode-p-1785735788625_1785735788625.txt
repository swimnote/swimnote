# SWIMNOTE X — WP2 최종 수정 승인 지시

WP2 API 검증 결과를 확인했습니다.

현재 남은 결함은 다음 1건뿐입니다.

```text
xmode_purchased_at 또는 xmode_subscription_end_at에 숫자가 들어오면
new Date(number)가 유효한 날짜로 처리되어 400 검증을 통과함
```

이번 작업에서는 **날짜 필드 런타임 타입 검증만 수정**하십시오.

그 외 설계·코드·파일은 변경하지 마십시오.

2. 날짜 검증 확정 규칙
━━━━━━━━━━━━━━━━━━━━━━

두 필드는 다음 값만 허용합니다.

```text
string
null
undefined
```

의미:

* `undefined`: 요청에서 미제공, 기존 값 유지
* `null`: DB 값을 null로 변경
* `string`: 유효한 날짜 문자열일 때만 허용
* 숫자·boolean·object·array: 400

검증 순서:

```text
필드 제공 여부 확인
→ null이면 허용
→ string이 아니면 400
→ string이지만 유효한 날짜가 아니면 400
→ 유효하면 UPDATE에 사용
```

━━━━━━━━━━━━━━━━━━━━━━
3. 구현 형태
━━━━━━━━━━━━━━━━━━━━━━

`xmode_purchased_at` 검증:

```typescript
if (hasPurchasedAt && xmode_purchased_at !== null) {
  if (typeof xmode_purchased_at !== "string") {
    res.status(400).json({
      error: "xmode_purchased_at은 문자열 또는 null이어야 합니다.",
    });
    return;
  }

  if (Number.isNaN(new Date(xmode_purchased_at).getTime())) {
    res.status(400).json({
      error: "xmode_purchased_at이 올바른 날짜가 아닙니다.",
    });
    return;
  }
}
```

`xmode_subscription_end_at`에도 동일한 순서로 적용하십시오.

기존 오류 메시지 형식을 유지할 필요가 있다면 Repository의 현재 메시지를 사용하되, 숫자 입력이 반드시 400으로 차단되어야 합니다.

공통 함수나 별도 validation 파일은 만들지 마십시오.

* 변경 필드 없음 → 400
