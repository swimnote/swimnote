# 일지 삭제 후 재작성 경고 최종 안정화

현재 수정 방향은 승인합니다.

하지만 `justSaved`를 2초 동안 true로 두고
경고를 숨기는 방식은 임시 해결책에 가깝습니다.

이번 작업에서는 저장 성공 후
실제 서버 상태를 기준으로 UI를 갱신하도록 최종 안정화하세요.

다른 기능은 절대 수정하지 마세요.

==================================================
1. 현재 문제
==================================================

현재 구조

저장 성공
↓

justSaved = true

↓

2초 동안 경고 숨김

↓

justSaved = false

입니다.

이 방식은

- 화면 이동
- Pull To Refresh
- 앱 재실행
- 날짜 변경
- 반 변경

등 상황에서
실제 서버 상태와 UI 상태가 일시적으로 달라질 수 있습니다.

==================================================
2. 목표
==================================================

저장 성공 여부는

2초 타이머가 아니라

실제 서버 데이터를 기준으로 판단하세요.

==================================================
3. 저장 성공 후 처리
==================================================

권장 순서

1.
저장 API 성공

2.
성공 상태 확정

3.
오늘 일지 목록 또는 diarySet을
최신 서버 기준으로 다시 갱신

4.
중복 여부를
새로 받은 데이터 기준으로 계산

5.
UI 갱신

즉

저장 성공 후

임시로 경고를 숨기는 것이 아니라

실제 최신 상태를 받아와서

myDiaryExists를 계산하세요.

==================================================
4. 삭제 후 처리
==================================================

삭제 성공하면

반드시

- diarySet
- 기존 일지 상태
- 오늘 작성 여부
- 캐시
- 현재 선택된 diary

를 최신 상태로 갱신하세요.

삭제된 데이터를 기준으로

중복 판단하면 안 됩니다.

==================================================
5. 경고 표시 기준
==================================================

다음 경우만

"오늘 이미 일지가 작성되어 있습니다."

경고를 표시하세요.

실제로

오늘의 활성 일지가 존재하는 경우

삭제된 일지

비활성 일지

이미 제거된 일지

soft delete 상태

는

중복으로 판단하지 마세요.

==================================================
6. justSaved
==================================================

가능하면

justSaved를 제거하세요.

만약 구조상 꼭 필요하다면

UI를 숨기기 위한 용도가 아니라

저장 애니메이션이나

버튼 중복 클릭 방지

정도로만 사용하세요.

중복 여부 판단에는 사용하지 마세요.
