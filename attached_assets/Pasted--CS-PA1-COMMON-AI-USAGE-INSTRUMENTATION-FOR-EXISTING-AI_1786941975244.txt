[CS-PA1 — COMMON AI USAGE INSTRUMENTATION FOR EXISTING AI FEATURES]

목적:

현재 운영 중인 기존 AI 기능들에
공통 usage instrumentation을 연결하여

Partner Analytics와 Super Admin AI Operations에서
실제 사용량 / 토큰 / 비용 / 성공률 / 사용자 역할 / 모드 / latency를
정확하게 집계할 수 있게 한다.

이번 WP는
"계측 연결"만 한다.

AI 기능의 판단 로직/프롬프트/결과 품질은
변경하지 않는다.

8. REQUEST ID
==================================================

불필요하게 request_id 여러 개 생성 금지.

9. TRACE ID
==================================================

→ analysis
→ final generation

여러 provider call이 있으면
trace_id 공유,
request/event id는 개별 가능.

과도한 distributed tracing 구현 금지.

==================================================
11. COST CALCULATION
==================================================

실제 token usage가 있을 때만 계산 가능.

모델별 가격표는
서버 측 중앙 source로 관리.

중요:

하드코딩이 필요한 경우에도
한 파일의 pricing map source of truth.

각 AI 호출부에 가격 숫자 복붙 금지.

12. MODEL NAME
==================================================

과거 usage는 원래 model로 남아야 한다.

==================================================
29. FAILURE MUST NOT BREAK AI
==================================================

telemetry/event logging 실패 때문에
AI 기능 자체가 실패하면 안 된다.

AI result 성공
+
event log insert 실패

이면:

사용자 결과는 정상 반환
telemetry failure 별도 운영 로그

가능하도록 best-effort.

단 데이터 정합성상
현재 architecture가 transaction을 요구하면
그 이유 명확히 보고.
