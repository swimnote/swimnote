[P0 BILLING ADDENDUM — X → SWIMNOTE DOWNGRADE "준비 중" 제거]

Android 공식 X plan purchase CTA 수정과 함께
iOS/Android의 X → SWIMNOTE 기본플랜 변경 기능도 확인한다.

실기기 iOS 현재 상태:

현재 X1000 구독 중
→ "SWIMNOTE 기본플랜으로 변경"
→ "다음 결제일부터 SWIMNOTE로 변경 (준비 중)"

현재 정책상 이 기능은 실제 동작해야 하므로
왜 준비 중으로 막혀 있는지 정확한 원인을 조사 후 최소 수정.

━━━━━━━━━━━━━━━━━━━━━━

subscription.tsx 및 billing helper에서:

- downgradeReady false
- "준비 중" hardcode
- platform guard
- package missing
- offering/package finder
- purchase HOLD flag
- legacy billing condition

등 실제 원인을 확인.

단순히 버튼만 활성화하지 말고
실제 Store product/package 연결 가능 여부부터 확인.

━━━━━━━━━━━━━━━━━━━━━━

3. X → BASE 변경 정책
━━━━━━━━━━━━━━━━━━━━━━

현재 X300/X500/X1000 사용자가
SWIMNOTE 기본플랜으로 변경 가능해야 함.

중요:

변경 요청 성공
≠ 즉시 X 권한 제거

현재 X 구독은 기존 paid-through date까지 유지.

UI 문구 정책:

"다음 결제일부터 SWIMNOTE로 변경"

Apple/Google Store가 실제 product change를 접수한 경우
예약/변경 상태 표시.

현재 X 기능은 종료일까지 계속 사용.

실제 갱신 시:
→ SWIMNOTE ₩9,900
→ X paid entitlement 종료
→ BASE SWIMNOTE 유지
→ 기존 회원/반/출결/일지/데이터 삭제 0

4. iOS APP STORE 확인
━━━━━━━━━━━━━━━━━━━━━━

SWIMNOTE와 X300/X500/X1000이
동일 subscription group 내 product change가 가능한 구조인지 확인.

RevenueCat purchase/change flow로
X → SWIMNOTE downgrade 요청 가능 여부 확인.

Apple downgrade 특성에 따라
다음 renewal부터 적용되는 Store 동작을 그대로 사용.

앱이 임의로 서버 entitlement를 즉시 BASE로 변경하면 FAIL.
