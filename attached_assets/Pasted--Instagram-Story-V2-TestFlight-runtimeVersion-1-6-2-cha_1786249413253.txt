[Instagram Story V2 수정 — 현재 테스트 일지 그대로 재생성]

현재 TestFlight runtimeVersion:
1.6.2

현재 channel:
instagram-test

현재 테스트용으로 등록해놓은 긴 일지와 사진들은 절대 수정/삭제하지 않는다.

목표:

현재 등록되어 있는
"긴 일지 + 다수 사진"
데이터를 그대로 사용해서

Instagram Story를

"사진 우선 + 최대 10장 전부 노출 + Story 1장 완결"

구조로 변경한다.

중요:
먼저 현재 구현을 감리한 뒤 최소 수정한다.
DB/서버/원본 일지 데이터는 변경하지 않는다.

━━━━━━━━━━━━━━━━━━━━━━
1. 사진 표시 정책 변경
━━━━━━━━━━━━━━━━━━━━━━

현재:

사진이 많으면 일부 사진만 표시하고
마지막 셀에 "+N" 표시

이 정책을 제거한다.

Story에 첨부된 사진이 최대 10장이면
10장 모두 실제 이미지로 표시한다.

절대:
+6
+5
등으로 사진을 숨기지 않는다.

사진 개수별 레이아웃을 동적으로 변경한다.

기본 방향:

1장:
큰 대표 사진

2장:
2열

3~4장:
2×2 기반

5~6장:
3×2

7~8장:
4×2

9~10장:
5×2

단,
1080×1920 Story에서 실제 사진이 지나치게 찌그러지지 않도록
현재 resizeMode/crop 정책을 확인하고 적절한 cover 방식 유지.

사진 원본 aspect ratio를 강제로 왜곡하지 않는다.

사진 사이 gap은 작게 유지.

━━━━━━━━━━━━━━━━━━━━━━
2. 사진 영역 우선
━━━━━━━━━━━━━━━━━━━━━━

Story 레이아웃 우선순위:

1순위 사진
2순위 날짜/선생님/반
3순위 일지 내용
4순위 SWIMNOTE branding

사진이 10장이어도
10장 모두 보여야 한다.

사진 개수가 많아지면
사진 한 장의 크기를 줄여서 해결한다.

사진을 숨겨서 해결하지 않는다.

━━━━━━━━━━━━━━━━━━━━━━
3. Story는 기본 1장 완결
━━━━━━━━━━━━━━━━━━━━━━

현재 buildPages()가 긴 일지를
여러 Story 페이지로 나누고 있다면
이번 V2에서는 기본적으로 Story 1장으로 완결시킨다.

Instagram Story에 N개의 shareSingle을
연속 호출하는 방식은 사용하지 않는다.

StoryCapturePipeline에서 최종 공유 대상은
기본적으로 1개의 1080×1920 이미지.

따라서 기존 다중 Story share loop가 있다면
V2 구조에서 제거 가능한지 확인한다.

━━━━━━━━━━━━━━━━━━━━━━
4. 본문 정책
━━━━━━━━━━━━━━━━━━━━━━

원본 일지는 절대 수정하지 않는다.

DB에 저장된 원문도 변경하지 않는다.

Story에 표시되는 text만 별도로 처리한다.

정책:

A.
원문이 사진 영역 아래 Story text 영역에
정상적인 글자 크기로 전부 들어가면
→ 원문 그대로 표시

B.
원문이 영역을 초과하면
→ Story용 요약문 사용

C.
단순히 앞 N글자를 잘라서
"..."
처리하는 것을 최종 정책으로 사용하지 않는다.

D.
글씨 크기를 극단적으로 줄여
원문 전체를 억지로 넣지 않는다.

━━━━━━━━━━━━━━━━━━━━━━
5. AI 요약 연결 전 감리
━━━━━━━━━━━━━━━━━━━━━━

중요:

새로운 GPT/API 호출을 임의로 만들지 않는다.

현재 SWIMNOTE에 이미 존재하는:

- AI Engine
- AI Diary
- GPT 호출 경로
- 기존 요약 기능
- 서버 AI endpoint

중 Story 요약에 재사용 가능한 경로가 있는지 먼저 조사한다.

확인할 것:

1. 현재 Story 생성은 client-only인지
2. 기존 일지 생성 AI endpoint를 요약 용도로 재사용 가능한지
3. 이미 summary 관련 endpoint/function이 존재하는지
4. 새로운 endpoint가 반드시 필요한지
5. Story 버튼을 누를 때 AI 호출할 경우 예상 latency
6. 실패했을 때 fallback을 어떻게 할지
7. 추가 API 비용 발생 여부

기존 AI Diary endpoint에
의미가 다른 요청을 억지로 넣지 않는다.

요약 경로가 안전하게 존재하지 않는다면
이번 단계에서는 임의 구현하지 말고 보고한다.

━━━━━━━━━━━━━━━━━━━━━━
6. Story 요약 규칙
━━━━━━━━━━━━━━━━━━━━━━

AI 요약을 연결할 수 있는 구조가 확인될 경우에만 적용.

요약은 원문에 존재하는 사실만 사용한다.

새로운 수영 지식,
평가,
칭찬,
판단,
다음 계획을 창작하지 않는다.

우선 보존:

- 오늘 수업 내용
- 중요한 수행/변화
- 보완 내용
- 원문에 존재하는 다음 계획
- 학생별 내용이 포함되어 있다면 중요한 개인 피드백

목표는
"Story에서 빠르게 읽을 수 있는 짧은 수업 요약"

원문 의미를 바꾸지 않는다.

━━━━━━━━━━━━━━━━━━━━━━
7. 요약 실패 fallback
━━━━━━━━━━━━━━━━━━━━━━

AI 요약 요청을 실제 적용하게 된다면
AI 실패 때문에 Instagram 공유 전체가 실패하면 안 된다.

요약 실패 시:

- 원문에서 Story 영역에 들어가는 안전한 범위만 표시
- 또는 현재 확인된 기존 fallback 사용

단,
앱 원본 일지는 변경하지 않는다.

Alert 때문에 Story 공유 전체를 중단시키는 구조는 피한다.

━━━━━━━━━━━━━━━━━━━━━━

9. 현재 테스트 데이터 그대로 검증
━━━━━━━━━━━━━━━━━━━━━━

현재 앱에 이미 등록해놓은
긴 일지 + 다수 사진 데이터를 삭제하거나 새로 만들지 않는다.
