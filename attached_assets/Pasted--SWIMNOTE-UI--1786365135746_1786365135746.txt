[SWIMNOTE 선생님 모드 — 보강대기리스트 > 보강배정 날짜 좌우 이동 UI 제거]

목적:

수강생관리
→ 보강대기리스트
→ 보강배정

화면에 현재 날짜와 좌/우 이동 버튼이 표시되어 있다.

현재 사용자 확인상 좌우로 날짜를 변경해도
아래 보강배정 목록이나 실제 기능에는 변화가 없고
날짜 표시만 변경된다.

기능 없는 날짜 네비게이션은 UI만 복잡하게 만들기 때문에 제거한다.

단, 추측해서 바로 삭제하지 말고
현재 코드 연결 관계를 먼저 확인한다.

━━━━━━━━━━━━━━━━━━━━━━
1. 수정 전 조사
━━━━━━━━━━━━━━━━━━━━━━

보강배정 화면에서 다음을 확인한다.

A. 날짜 표시 component 위치
B. 좌측 화살표 handler
C. 우측 화살표 handler
D. 현재 선택 날짜 state
E. 날짜 state를 참조하는 모든 코드
F. 날짜 변경 시 API 재호출 여부
G. 날짜가 목록 filtering에 사용되는지
H. 날짜가 보강 가능반 조회에 사용되는지
I. 날짜가 실제 보강 배정 payload에 사용되는지
J. 날짜가 다른 화면/Modal에 전달되는지

중요:

단순히 화면상 변화가 없어 보인다는 이유만으로
날짜 state 전체를 삭제하지 않는다.

실제 dependency를 코드로 추적한다.

━━━━━━━━━━━━━━━━━━━━━━
2. 제거 대상
━━━━━━━━━━━━━━━━━━━━━━

조사 결과 날짜 네비게이션이 실제 기능에 사용되지 않는 것이 확인되면:

보강배정 화면의

[ < ]   날짜   [ > ]

형태의 날짜 네비게이션 UI를 제거한다.

포함:

- 좌측 날짜 이동 버튼
- 우측 날짜 이동 버튼
- 중앙 날짜 표시
- 해당 UI만을 위해 존재하는 style

제거 후 불필요해진:

- date navigation handler
- UI 전용 state
- UI 전용 helper

도 다른 기능에서 사용되지 않는 것이 확정된 경우에만 정리한다.

━━━━━━━━━━━━━━━━━━━━━━
3. 실제 배정에 필요한 날짜는 보호
━━━━━━━━━━━━━━━━━━━━━━

주의:

보강을 실제 배정할 때 필요한

- 보강 날짜
- 수업 날짜
- 선택된 반 날짜
- assignment date
- API payload date

등이 있다면 절대 제거하지 않는다.

이번 작업은

"기능 없는 상단 날짜 좌우 이동 UI 제거"

가 목적이다.

보강 시스템의 날짜 데이터 자체를 제거하는 작업이 아니다.

━━━━━━━━━━━━━━━━━━━━━━
4. 제거 후 화면
━━━━━━━━━━━━━━━━━━━━━━

Before:

보강배정

      <   8월 10일   >

[보강 가능한 목록...]
[보강 가능한 목록...]
[보강 가능한 목록...]

After:

보강배정

[보강 가능한 목록...]
[보강 가능한 목록...]
[보강 가능한 목록...]

불필요하게 빈 공간을 남기지 않는다.

날짜 영역이 사라진 만큼
목록이 자연스럽게 위로 올라오도록 한다.

별도의 안내문이나 새로운 UI를 추가하지 않는다.

Simple is best.

━━━━━━━━━━━━━━━━━━━━━━
5. 절대 변경 금지
━━━━━━━━━━━━━━━━━━━━━━

- 보강대기 학생 목록
- 학생 검색 인덱스
- 실시간 이름 필터
- 키보드 처리
- 보강반 배정
- 인계
- 소멸
- 직접완료
- 보강 가능반 조회
- 실제 배정 날짜
- API
- Server
- DB
- Notification

날짜 네비게이션 제거를 이유로
보강 로직을 재설계하지 않는다.

━━━━━━━━━━━━━━━━━━━━━━
6. 회귀 테스트
━━━━━━━━━━━━━━━━━━━━━━

CASE 1
수강생관리 → 보강대기리스트 진입
→ 기존 목록 정상

CASE 2
학생 이름 검색
→ 기존 실시간 검색 정상

CASE 3
학생 선택 → 보강배정
→ 상단 날짜 좌/우 네비게이션 없음

CASE 4
날짜 UI가 사라진 공간
→ 불필요한 빈 여백 없음

CASE 5
보강 가능한 목록
→ 기존과 동일하게 표시

CASE 6
보강반 선택
→ 정상

CASE 7
보강배정 완료
→ 기존과 동일하게 정상 처리

CASE 8
실제 assignment date
→ 기존 정상 값 유지

CASE 9
인계/소멸/직접완료
→ 회귀 없음

━━━━━━━━━━━━━━━━━━━━━━
