중요:
X MODE 활성화 기능은 이미 구현되어 있습니다.

새 기능을 설계하거나 만들지 마십시오.
새 entitlement 구조를 제안하지 마십시오.
RevenueCat 구조를 다시 설계하지 마십시오.
관련 없는 X roadmap을 재조사하지 마십시오.

이번 목적은 단 하나입니다.

“슈퍼관리자가 이미 구현된 기능으로 특정 수영장에 X MODE를 부여하면,
그 수영장이 실제로 X MODE로 활성화되어 정상 사용할 수 있는가?”

를 현재 코드/Production 기준으로 확인합니다.

━━━━━━━━━━━━━━━━━━━━━━
1. 기존 SUPERADMIN 활성화 경로 확인
━━━━━━━━━━━━━━━━━━━━━━

현재 구현된 실제 흐름만 추적:

SUPERADMIN
→ 수영장 선택
→ X MODE 활성화/부여
→ API
→ DB 상태 변경
→ 해당 pool의 X MODE Gate 활성화

다음을 실제 파일/endpoint/field 기준으로 보고:

- 슈퍼관리자 X 활성화 화면/버튼
- 호출 API
- 변경되는 DB table/column/value
- X MODE Gate가 읽는 최종 값

새 구조 제안 금지.

━━━━━━━━━━━━━━━━━━━━━━
2. 가장 중요한 연결 확인
━━━━━━━━━━━━━━━━━━━━━━

슈퍼관리자가 X MODE를 ON 했을 때

저장되는 값과
실제 앱/PC가 X MODE 활성 여부를 판단하는 값이

정확히 같은 source인지 확인하세요.

즉:

SUPERADMIN에서 ON
→ DB ACTIVE
→ pool admin이 X MODE로 인식

이 연결이 끊어져 있지 않은지 확인.

별도의 결제값 때문에
SUPERADMIN이 ON해도 다시 일반모드로 판단되는 경로가 있는지도 확인.

━━━━━━━━━━━━━━━━━━━━━━
3. 기존 X 기능 Gate 확인
━━━━━━━━━━━━━━━━━━━━━━

X MODE를 부여받은 pool에서
현재 이미 구현된 주요 X 기능이 같은 활성 상태를 정상 인식하는지 확인:

- 모바일 관리자 X MODE
- PC Dashboard X 기능
- X Curriculum
- X DOCX upload
- X diary/template 관련 기능
- Parent AI에서 X pool 판정

- 기타 현재 코드에서 X Mode Gate를 사용하는 핵심 기능

각각 PASS/HOLD만 보고.

새 기능 추가 금지.

4. SUPERADMIN OFF도 확인
━━━━━━━━━━━━━━━━━━━━━━

기존 비활성화 기능이 있다면:

SUPERADMIN
→ X MODE OFF

했을 때

- DB 상태 정상 변경
- 일반모드로 Gate 복귀
- 기존 데이터 삭제 없음

인지 확인.

실제 Production pool을 임의로 OFF 하지 마세요.
