──────────────────────────────────
2. WP3 목표
──────────────────────────────────

Teacher Diary AI 모달에서 녹음된 음성 파일을 Whisper STT로 전송하고, 변환된 텍스트를 입력창에 안전하게 반영하는 전체 경로를 검증한다.

목표 흐름

Voice Recording URI

↓

파일 유효성 확인

↓

Whisper 요청 생성

↓

Authorization 포함

↓

업로드

↓

응답 검증

↓

텍스트 추출

↓

사용자가 수정 가능한 입력창에 표시

이번 WP에서는 “음성을 텍스트로 바꾸는 단계”까지만 다룬다.

텍스트를 AI Engine에 분석 요청하는 단계는 다음 WP에서 진행한다.

──────────────────────────────────
5. Request 검증
──────────────────────────────────

Whisper 요청에서 다음을 확인한다.

- HTTP method가 올바른가
- Content-Type을 수동으로 잘못 지정하지 않는가
- FormData boundary를 React Native가 자동 생성하도록 하는가
- 음성 파일 필드명이 서버 계약과 일치하는가
- 파일명 존재
- MIME type 존재
- iOS file URI 처리 정상
- Android file URI 처리 정상
- 빈 URI 차단
- 0 byte 파일 차단
- 허용하지 않는 파일 형식 차단 또는 안전 처리
- locale 또는 language 설정이 필요한 경우 `ko` 또는 계약 값 사용
- request_id가 필요한 구조라면 정상 생성
- JWT Authorization 헤더 포함
- 로그에 토큰·음성 파일·사용자 개인정보를 출력하지 않음

직접 OpenAI API를 앱에서 호출하면 안 된다.

OpenAI API Key가 앱 번들에 포함되어서도 안 된다.

Whisper 호출은 반드시 서버 또는 AI Engine 프록시를 통해 수행해야 한다.

앱에 OpenAI API Key가 있거나 직접 OpenAI URL을 호출하면 심각한 보안 문제로 보고하고 수정한다.

──────────────────────────────────
6. Response 검증
──────────────────────────────────

Whisper 응답에서 다음을 확인한다.

- HTTP status 확인
- JSON 파싱 실패 처리
- 예상 스키마 확인
- transcript 또는 text 필드 추출
- 빈 transcript 처리
- 지나치게 짧은 transcript 처리
- 서버 에러 메시지 안전 표시
- 사용자가 이해할 수 있는 오류 문구
- 내부 서버 정보 노출 방지
- 중복 응답 방지
- 오래된 요청 응답 차단
- 이전 transcript를 새 실패 응답으로 덮어쓰지 않음

응답 필드가 여러 버전을 지원한다면 normalize 함수를 통해 한 곳에서 정규화한다.

예시:

- response.text
- response.transcript
- response.result?.text

실제 서버 계약을 먼저 확인하고, 불필요한 호환 코드를 임의로 추가하지 않는다.

──────────────────────────────────
7. 상태 관리 검증
──────────────────────────────────

STT 상태는 최소한 다음을 구분할 수 있어야 한다.

- idle
- uploading 또는 transcribing
- success
- error

다음을 확인한다.

- 변환 중 중복 요청 방지
- 버튼 연속 탭 방지
- 변환 중 버튼 상태 표시
- 변환 중 모달을 닫을 때 안전 처리
- 요청 취소 또는 AbortController
- timeout
- unmount 후 setState 방지
- stale response 차단
- retry 가능
- 새 녹음 시 이전 오류 상태 초기화
- 새 녹음 시 이전 transcript 처리 정책 명확화

기존 AIStateMachine이 있다면 중복 상태 시스템을 새로 만들지 말고 기존 구조를 사용한다.

──────────────────────────────────
8. 사용자 경험 검증
──────────────────────────────────

정상 흐름

1. 녹음 시작
2. 녹음 종료
3. 음성 변환 시작
4. 변환 중 상태 표시
5. 변환 완료
6. transcript가 입력창에 표시
7. 사용자가 직접 수정 가능

확인 사항

- transcript가 자동으로 AI 분석까지 넘어가지 않음
- 사용자가 내용을 검토하고 수정할 수 있음
- 기존 입력 텍스트가 있을 때 무조건 삭제하지 않음
- 기존 텍스트와 transcript 결합 정책을 확인
- 사용자의 기존 작성 내용 보존
- 오류 발생 시 기존 텍스트 보존
- 재녹음 시 동작이 명확함

기존 텍스트 처리 정책이 설계서에 없다면 임의로 바꾸지 말고 현재 구현을 보고한다.
