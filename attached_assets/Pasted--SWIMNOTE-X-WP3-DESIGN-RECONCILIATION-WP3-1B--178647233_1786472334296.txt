WP3 GAP AUDIT의 아래 결론은 승인하지 않는다:

"READY 사전조건 없음"
"pool_admin이 X 모드 활성화 버튼을 누르면
NOT_CONFIGURED → READY"

이 흐름은 기존 SWIMNOTE X 확정 설계와 충돌한다.

기존 X 상태 모델:

NOT_CONFIGURED
= X entitlement는 있으나
해당 수영장용 커리큘럼 준비 전

CURRICULUM_PENDING
= 수영장이 X 설정/커리큘럼 구축을 요청했고
관리 측에서 준비 중

READY
= 해당 수영장의 X용 커리큘럼/설정이 준비 완료

실제 X 사용 조건:

xmode_entitlement = true
AND
xmode_config_status = 'READY'

따라서 pool_admin이 임의로 READY를 만드는
단순 activation button 구현 금지.

이번 단계에서는
기존 curriculum setup/request 구조만 재검증한다.

코드 수정 금지.
DB write 금지.
Commit/Push/Render/OTA 금지.
