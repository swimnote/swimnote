## 오류 1

다음 코드는 금지합니다.

```typescript
let result: PoolModeResult;

result = computeMode(
  after.xmode_entitlement,
  after.xmode_config_status
);
```

`computeMode()`의 반환값은 `PoolMode` 문자열입니다.

다음처럼 실제 응답 객체를 구성하십시오.

```typescript
const mode = computeMode(
  Boolean(after.xmode_entitlement),
  after.xmode_config_status as XModeStatus
);

result = {
  pool_id: after.id,
  mode,
  xmode_entitlement: Boolean(after.xmode_entitlement),
  xmode_config_status: after.xmode_config_status as XModeStatus,
};
```

Transaction 안에서 `UPDATE ... RETURNING` 결과로 `PoolModeResult`를 구성하십시오.

PATCH 처리 후 `resolvePoolMode()`를 다시 호출하지 마십시오.

이유:

* 같은 요청에서 불필요한 DB 재조회 방지
* UPDATE 직후 반환된 확정값 사용
* 응답과 Audit의 after 상태 일치

## 오류 2

설계 예시에는 다음 변수명이 혼재합니다.

```text
before
beforeData

after
afterData
```

하나로 통일하십시오.

권장:

```typescript
const beforeData = { ... };
const afterData = { ... };
```

Audit INSERT에서도 같은 변수를 사용하십시오.

3. lib/xmode.ts 구현
━━━━━━━━━━━━━━━━━━━━━━

다음만 구현하십시오.

```typescript
export type XModeStatus =
  | "NOT_CONFIGURED"
  | "CURRICULUM_PENDING"
  | "READY";

export type PoolMode =
  | "normal"
  | "x_pending"
  | "x";

export interface PoolModeResult {
  pool_id: string;
  mode: PoolMode;
  xmode_entitlement: boolean;
  xmode_config_status: XModeStatus;
}
```

판정 함수:

```typescript
export function computeMode(
  entitlement: boolean,
  configStatus: XModeStatus,
): PoolMode {
  if (!entitlement) return "normal";
  if (configStatus === "READY") return "x";
  return "x_pending";
}
```

조회 함수:

```typescript
export async function resolvePoolMode(
  poolId: string,
): Promise<PoolModeResult | null>
```

규칙:

* `superAdminDb`에서 `swimming_pools` 조회
* pool 미존재 시 `null`
* JWT나 앱 전달 mode 사용 금지
* 캐시 추가 금지
* capability 추가 금지
* fallback 추가 금지
* 별도 오류 클래스 생성 금지

6. PATCH /super/operators/:id/xmode 구현
━━━━━━━━━━━━━━━━━━━━━━

파일:

```text
artifacts/api-server/src/routes/super.ts
```

인증:

```text
requireAuth
requireRole("super_admin")
```

`:id`는 `swimming_pool_id`입니다.

허용 Body:

```typescript
{
  xmode_entitlement?: boolean;
  xmode_config_status?:
    | "NOT_CONFIGURED"
    | "CURRICULUM_PENDING"
    | "READY";
  xmode_purchased_at?: string | null;
  xmode_subscription_end_at?: string | null;
  reason?: string;
}
```

`reason`을 제외한 변경 필드가 최소 1개 있어야 합니다.

`xmode_payment_failed_at`은 받지 마십시오.

## 입력 검증

반드시 검증:

* `xmode_entitlement`는 boolean만 허용
* `xmode_config_status`는 확정 ENUM 3개만 허용
* 날짜는 `null` 또는 유효한 날짜 문자열만 허용
* invalid date가 DB에 전달되지 않도록 차단
* 설계에 없는 Body 필드는 UPDATE에 사용하지 않음

새 검증 라이브러리를 추가하지 말고 기존 Route 검증 방식에 맞추십시오.

7. Transaction 고정 순서
━━━━━━━━━━━━━━━━━━━━━━

Transaction 밖:

```text
Body 검증
→ 변경 필드 0개면 400
```

Transaction 안:

```text
1. SELECT ... FOR UPDATE
2. pool 미존재면 throw
3. beforeData 구성
4. UPDATE ... RETURNING
5. afterData 구성
6. next_audit_version 발급
7. audit_logs INSERT
8. PoolModeResult 구성
9. Commit
```

Audit INSERT 실패 시 UPDATE도 Rollback되어야 합니다.

동적 UPDATE는 승인된 필드만 사용하십시오.

값이 제공되지 않은 필드는 기존 값을 유지해야 합니다.

## 단위 테스트

```text
false + NOT_CONFIGURED → normal
false + CURRICULUM_PENDING → normal
false + READY → normal
true + NOT_CONFIGURED → x_pending
true + CURRICULUM_PENDING → x_pending
true + READY → x
```

## API 읽기 테스트

안전한 기존 계정이 있을 때만:

* 일반 pool의 `GET /pools/x-mode`
* 인증 없음 401
* 불허 역할 403
* super_admin pool_id 누락 400
* 존재하지 않는 pool 조회 404

## PATCH 테스트

운영 수영장 상태를 변경하지 마십시오.

허용되는 안전한 검증:

* 변경 필드 없음 → 400
* 존재하지 않는 pool_id → 404
* 인증 없음 → 401
* 권한 없음 → 403

실제 존재하는 pool의 X 상태 변경 테스트는 별도 승인 전 금지합니다.
