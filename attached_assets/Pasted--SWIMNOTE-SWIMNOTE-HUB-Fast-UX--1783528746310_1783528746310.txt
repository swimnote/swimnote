현재 출시된 SWIMNOTE 앱의 기능과 화면 구조는 최대한 유지한 상태에서, 응답속도만 개선하고 싶습니다.

목표는 SWIMNOTE HUB에서 적용하려는 Fast UX 구조를 현재 SWIMNOTE 어린이 수영장 관리앱에도 적용하는 것입니다.

아래 항목 중에서 현재 코드 구조상 바로 적용 가능한 것, 일부 수정 후 가능한 것, 서버 구조 변경이 필요한 것을 구분해서 검토해주세요.

---

# 요청 사항

현재 앱에서 다음 원칙을 적용할 수 있는지 확인해주세요.

## 1. 캐시 우선 표시

앱 실행 시 서버 응답을 기다리지 않고,

* 로그인 정보
* 권한 정보
* 오늘 수업
* 반 목록
* 회원 목록
* 최근 일지
* 학부모 최근 알림

등을 로컬 캐시에서 먼저 보여주고, 이후 서버 최신 데이터로 조용히 갱신하는 구조가 가능한지 확인해주세요.

---

## 2. 출석 체크 Optimistic UI

출석 버튼을 눌렀을 때 서버 응답을 기다리지 않고 화면에 즉시 반영하고,

서버 저장은 백그라운드에서 처리하는 방식이 가능한지 확인해주세요.

흐름은 아래와 같습니다.

출석 터치
→ 화면 즉시 변경
→ 로컬 저장
→ 서버 동기화
→ 실패 시 재시도 또는 오류 표시

---

## 3. 수업일지 자동 임시저장

수업일지 작성 중 앱을 닫거나 네트워크가 끊겨도 내용이 사라지지 않도록,

로컬 임시저장 기능을 적용할 수 있는지 확인해주세요.

---

## 4. Sync Queue 적용

출석, 일지, 피드백, 사진, 영상 업로드 요청을 즉시 서버로 보내는 방식이 아니라,

로컬 Queue에 저장한 뒤 순서대로 서버에 동기화하는 구조가 가능한지 확인해주세요.

상태값은 아래처럼 구성하고 싶습니다.

* pending
* syncing
* success
* failed
* retrying

---

## 5. 사진·영상 백그라운드 업로드

사진과 영상을 선택하면 즉시 썸네일을 보여주고,

원본 또는 고화질 파일은 백그라운드에서 업로드되도록 변경할 수 있는지 확인해주세요.

앱 사용 중 업로드가 계속되고, 실패 시 재시도할 수 있는 구조가 필요합니다.

---

## 6. 학부모 홈 캐시 우선 표시

학부모가 앱을 열었을 때 최근 피드백, 사진 썸네일, 공지, 알림을 캐시에서 먼저 보여주고,

서버 데이터는 이후 갱신하는 구조가 가능한지 확인해주세요.

---

## 7. 리스트 가상화 적용

회원 수가 300명, 500명, 1000명 이상으로 늘어도 느려지지 않도록,

회원 목록, 반 목록, 사진 목록, 알림 목록, 피드백 목록에 리스트 가상화가 적용되어 있는지 확인해주세요.

적용되어 있지 않다면 현재 구조에서 추가 가능한지 확인해주세요.

---

## 8. BFF API 구조 적용 가능 여부

현재 화면 하나에서 여러 API를 동시에 호출하고 있다면,

화면별 통합 API로 묶을 수 있는지 확인해주세요.

예시:

GET /teacher/today-dashboard

응답값:

* 오늘 반 목록
* 회원 목록
* 출석 상태
* 최근 일지
* 보강 정보
* 알림 상태

운영자 대시보드, 선생님 오늘 수업, 학부모 홈, 회원 상세, 반 상세 화면에 적용 가능한지 검토해주세요.

---

## 9. 서버 캐시 / Redis 적용 가능 여부

자주 호출되는 데이터에 서버 캐시를 적용할 수 있는지 확인해주세요.

대상:

* 수영장 기본 정보
* 반 목록
* 회원 목록
* 레벨 설정
* 퀘스트 설정
* 일지 템플릿
* 공지사항
* 최근 알림

Redis 또는 서버 메모리 캐시 중 현재 서버 구조에서 적합한 방식을 추천해주세요.

---

## 10. 성능 개선 우선순위 제안

위 항목을 기준으로 현재 앱에 적용할 때,

1. 바로 가능한 작업
2. 프론트 수정만으로 가능한 작업
3. 서버 수정이 필요한 작업
4. DB 또는 인프라 변경이 필요한 작업
5. 리스크가 큰 작업

으로 나눠서 정리해주세요.

---

# 가장 중요한 조건

현재 출시된 SWIMNOTE 앱의 기능, 화면 구조, 사용자 데이터는 건드리지 않고,

응답속도와 체감 속도만 개선하는 방향으로 검토해주세요.

새 앱을 만드는 것이 아니라,

현재 앱의 데이터 처리 방식과 동기화 구조를 개선하는 작업입니다.

목표는 빠른 앱이 아니라,

현장에서 기다림 없이 사용할 수 있는 앱입니다.
