[긴급 실제 연결 수정 — Terminology APP Gateway → AI ENGINE Production 연결 오류]

현재 확정된 사실:

AI ENGINE Production은 정상이다.

Production ENGINE 확인 결과:

status:
READY
version=1
term_count=25

검색:
글라이드 → TERM-000002 / 200
스트림라인 → TERM-000001 / 200
DPS → TERM-000006 / 200
negative split → TERM-000009 / 200

따라서 현재 앱 오류 원인은
APP API Gateway → Professional AI ENGINE
server-to-server 연결 구간으로 한정한다.

이번 작업은:

실제 Production APP API 환경 확인
→ Gateway → ENGINE 직접 호출 재현
→ 원인 확정
→ 필요한 설정/코드 최소 수정
→ Production Render 반영
→ Live API 검증

까지 한 번에 진행한다.

중간 조사보고 후 STOP 하지 말 것.

https://swimnote-api.onrender.com

GET /api/terminology/search

404인지

2. Production APP API 환경변수 실제 확인
━━━━━━━━━━━━━━━━━━━━

Render Production APP API service에서:

PROFESSIONAL_ENGINE_BASE_URL
PROFESSIONAL_ENGINE_API_SECRET

두 값이 실제 runtime에 SET인지 확인.

secret 값 자체는 출력하지 않는다.

BASE URL은 다음 ENGINE service를 정확히 가리켜야 한다:

swimnote-professional-engine Production

중요 확인:

- http / https
- host
- trailing slash
- 이미 /api가 붙어 있는지 여부

예:

BASE_URL =
https://swimnote-professional-engine.onrender.com

라면 Gateway 최종 URL은:

https://swimnote-professional-engine.onrender.com/api/terminology/search

이어야 한다.

BASE_URL에 이미 /api가 들어있다면
/api/api/terminology가 되지 않는지 확인.

━━━━━━━━━━━━━━━━━━━━
3. Secret 동일성 검증
━━━━━━━━━━━━━━━━━━━━

APP API Render에 설정된:

PROFESSIONAL_ENGINE_API_SECRET

과

AI ENGINE Render에 설정된:

PROFESSIONAL_ENGINE_API_SECRET

이 실제 동일한 credential인지 확인.

값을 로그/보고서에 출력하지 않는다.

가능하면 안전한 방식으로:

- length
- hash fingerprint 일부
- 또는 실제 authenticated request 결과

로 동일성을 검증.

가장 확실한 검증:

APP API runtime에서 사용하는 exact secret으로
ENGINE search를 직접 호출했을 때
200이 나오는지 확인.

7. 수정 원칙

현재 main 최신 commit을 실제 Production에 배포.
