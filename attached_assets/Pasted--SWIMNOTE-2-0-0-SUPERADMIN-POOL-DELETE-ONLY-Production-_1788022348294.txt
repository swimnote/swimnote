[SWIMNOTE 2.0.0 — SUPERADMIN POOL DELETE 오류 원인 조사 ONLY]

현재 Production에서 실제 현상 발생.

대상 수영장:
"스윔노트"

현상:

1. Superadmin에서 수영장 삭제 실행
2. UI에서는 "삭제 중 오류가 발생했습니다" 계열 오류 표시
3. Superadmin 수영장 목록에는 해당 수영장이 계속 남아 있음
4. 하지만 해당 수영장 계정으로 실제 로그인 시도하면
   수영장이 존재하지 않아 로그인 불가
5. 즉 실제 core pool 삭제는 수행된 것으로 보이는데,
   Superadmin UI/API는 삭제 실패로 판단하고 있음

추가 조건:
해당 수영장은 X MODE를 활성화했던 이력이 있음.

이번 작업은 수정 금지.
배포 금지.
DB 변경 금지.
원인 조사만 수행하고 STOP.

==================================================

삭제 대상 "스윔노트"의 실제 pool_id를 특정.

다음 확인:

swimming_pools
→ 해당 pool_id 존재 YES/NO

users/admin
→ 해당 pool 관련 row

user_pool_memberships
→ 해당 pool 관련 row

X MODE 관련:
→ xmode subscription/status
→ X 설정
→ curriculum
→ reports
→ 기타 tenant rows

각각 남아 있는 row 수 보고.

중요:

어떤 테이블에서도 DELETE/UPDATE 하지 말 것.

DB에서는 pool 삭제 성공

5. X MODE 영향 조사
==================================================

X MODE 활성화 수영장일 때만 실행되는
삭제/후처리 로직이 있는지 검색.

대상:

xmode
x_mode
subscription
entitlement
global_template
curriculum
growth
ai
report
revenue
homepage
slug

등.

확인:

1. X MODE 활성 pool 삭제 시 추가 cleanup 존재 여부
2. FK/reference 때문에 오류 가능 여부
3. 이미 pool이 삭제된 뒤
   X 관련 row를 조회/삭제하면서 예외 발생 가능 여부
4. X MODE inactive pool과 delete flow 차이

X MODE가 원인이 아니면 명확히 NO라고 보고.
