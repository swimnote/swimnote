==================================================
2. GLOBAL MODAL PRINCIPLE
==================================================

전체 앱 공통 원칙:

1. 같은 목적의 Modal은 같은 구조
2. 작은 화면에서도 잘리지 않음
3. 내용이 길면 내부 scroll
4. 키보드가 버튼을 가리지 않음
5. 닫기 동작이 명확함
6. 배경 탭 dismiss 여부를 목적별로 통일
7. Back 동작 일관성
8. Primary / Secondary / Destructive 버튼 문법 통일
9. 불필요한 반투명/장식 border 제거
10. 중복 탭으로 동일 요청이 2회 실행되지 않음
11. Safe Area 준수
12. Modal 안 Modal은 가능하면 제거

==================================================
3. MODAL TYPE CLASSIFICATION
==================================================

각 Modal을 다음으로 분류:

A. INFORMATION
단순 확인/안내

B. FORM
입력 필요

C. SELECTION
항목 선택

D. CONFIRMATION
행동 확인

E. DESTRUCTIVE
삭제/취소/해제

F. FULL CONTENT
내용이 길어 sheet/full-height 필요

G. SYSTEM ALERT
Alert.alert 수준이면 충분

같은 목적에 서로 다른 구조를 쓰고 있는지 확인.

==================================================
4. SIZE RULE
==================================================

기본 Modal:

작은 고정 높이 금지.

권장:

width:
화면 좌우 여백 기준

maxHeight:
화면 높이의 안전 범위 내

content가 짧으면 자연 높이
content가 길면 내부 ScrollView

사용.

작은 iPhone에서:

- footer button 잘림
- title 잘림
- content overflow

없어야 함.

==================================================
5. FULL / LARGE MODAL
==================================================

내용이 많은 경우:

억지로 작은 중앙 Modal 안에
모든 내용을 넣지 않는다.

다음 조건이면
large sheet/full-height 계열을 우선 검토:

- 긴 목록
- 여러 입력
- 상세 정보
- 사진/영상 선택
- 일정 편집
- 복잡한 설정

단 navigation 구조 변경 금지.

기존 sheet/full modal이 있으면 재사용.

==================================================
6. OVERLAY RULE
==================================================

Modal background overlay를 통일.

문제 검사:

- 너무 투명해서 뒤 화면이 산만함
- 지나치게 검음
- Modal마다 opacity 다름

하나의 shared overlay token/style로 통일 가능한지 확인.

중요:

디자인적으로 "반투명 박스"처럼
content 자체가 비쳐 보이면 안 된다.

Content surface는 불투명.

==================================================
7. BORDER / SHADOW
==================================================

현재 Global Design System:

Borderless First

유지.

Modal container 기본:

- white/off-white surface
- radius
- subtle shadow

로 구분.

불필요한:

border + shadow 동시 사용
colored outline
thick border

제거.

단 실제 selected/input boundary는 유지 가능.

==================================================
8. HEADER RULE
==================================================

Modal header 기본 구조:

Title
Optional subtitle
Optional close icon

close icon이 있으면:

visual background 기본 제거
touch area 44×44 유지

Title alignment와 spacing을 통일.

단 confirmation alert는 별도 compact 구조 가능.

==================================================
9. FOOTER / ACTION BUTTON RULE
==================================================

Global Button System 적용.

PRIMARY
→ Navy

SECONDARY
→ 공통 Secondary

DESTRUCTIVE
→ Red

X라고 Primary CTA를 Steel Blue로 바꾸지 않는다.
Steel Blue는 X accent only.

버튼 순서를 목적별로 통일.

예:

[취소] [확인]

또는 vertical stack이 필요한 작은 화면은
일관된 규칙 사용.

같은 앱에서 화면마다
확인/취소 순서가 뒤집히지 않도록 조사.

==================================================
10. DESTRUCTIVE CONFIRMATION
==================================================

삭제/탈퇴/해제/취소처럼
복구 어려운 행동은 별도 분류.

확인:

- destructive action red
- primary와 혼동되지 않음
- 문구가 실제 결과를 명확히 설명
- 버튼 연속탭 방지
- 실행 중 loading
- 완료 전 Modal 중복 닫힘 방지

불필요한 2중/3중 confirmation은 피한다.

12. SCROLL HANDLING

실제 UX에 맞게 판단.

목록/폼이 길 경우
content 영역만 scroll 가능하도록 우선 검토.

중첩 ScrollView 문제도 확인.

15. DOUBLE TAP / DUPLICATE SUBMIT
==================================================

중요.

다음 action Modal 전수 검사:

저장
등록
삭제
확인
보강 생성
출결 변경
공지 저장
메시지 전송
X 설정
Super Admin control

사용자가 버튼을 연속 탭했을 때:

API 중복 요청
navigation 중복 push
중복 저장

이 발생하지 않아야 함.

기존 ref/state lock pattern이 있으면 재사용.

새로운 business logic를 만드는 것이 아니라
UI 중복 실행 방지만 한다.

25. SUPER ADMIN
