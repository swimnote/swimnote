0. 최우선 데이터 격리 원칙
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

일지 댓글 대화의 thread 단위는 반드시:

[특정 일지 diary_id]
+
[특정 학부모/학생 관계]

이어야 한다.

즉 같은 반, 같은 날짜, 같은 일지라도
학부모 A와 선생님의 대화를
학부모 B가 절대 볼 수 없어야 한다.

또한 같은 학부모라도:

8월 1일 일지 댓글
8월 8일 일지 댓글

은 서로 다른 thread다.

날짜를 직접 thread key로 사용하는 것이 아니라
각 날짜의 실제 diary_id가 다르므로
반드시 해당 diary_id 기준으로 분리되어야 한다.

최종적으로 다음 형태가 보장되어야 한다.

Thread =
diary_id + parent/student ownership

1. 현재 DB 구조부터 실제 확인
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

현재 보고상 댓글 저장은:

POST /diaries/:diaryId/comments

table:
diary_messages

message_type:
diary_comment

으로 되어 있다.

하지만 이것만으로 격리를 보장할 수 없다.

diary_messages 실제 schema를 조사하여 다음 필드를 보고하라.

- id
- diary_id 또는 diary reference
- sender_id
- sender_type / sender_role
- parent_id
- student_id
- recipient_id
- pool_id
- message_type
- created_at

실제 존재하는 컬럼만 보고할 것.

특히 어떤 컬럼을 이용해서
"어느 학부모와의 댓글 대화인지"
구분하고 있는지 확인한다.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2. 댓글 GET API 전수감리
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

학부모 댓글 조회 API와
선생님 댓글 조회 API를 모두 찾는다.

각 SQL WHERE 조건을 그대로 확인한다.

절대 다음처럼 diary_id만으로 조회하면 안 된다.

WHERE diary_id = :diaryId

이 경우 같은 일지에 달린 여러 학부모의 댓글이
서로 섞일 위험이 있다.

학부모 측에서는 최소한:

해당 diary
+
현재 로그인한 parent가 접근 가능한 학생/일지

조건으로 제한되어야 한다.

선생님 측에서는
특정 학부모 댓글 thread를 열었을 때:

해당 diary
+
해당 parent/student thread

만 조회되어야 한다.

3. 반드시 검증할 격리 CASE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

예:

DIARY-A = 2026-08-27 수업일지

학생 A / 학부모 A:
"우리 아이 오늘 어땠나요?"

학생 B / 학부모 B:
"호흡은 괜찮았나요?"

Teacher가 A thread를 열면:

A 질문
Teacher의 A 답변

만 보여야 한다.

B 질문은 절대 보여서는 안 된다.

Teacher가 B thread를 열면:

B 질문
Teacher의 B 답변

만 보여야 한다.

A 질문/답변은 절대 보여서는 안 된다.

4. 같은 학부모 + 다른 일지 격리
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

학부모 A가

DIARY-A (8/20):
"발차기 괜찮았나요?"

DIARY-B (8/27):
"오늘 호흡은 어땠나요?"

라고 작성한 경우

8/20 일지 댓글창에는
8/20 대화만 표시.

8/27 일지 댓글창에는
8/27 대화만 표시.

같은 parent_id/student_id라는 이유로
두 날짜의 댓글을 합치면 안 된다.

반드시 diary_id까지 thread boundary에 포함.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
5. Teacher 소식 → 댓글 thread 연결 검증
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

현재:

Parent 댓글 작성
→ diary_comment notification
→ Teacher 알림함 > 소식
→ 해당 일지 이동

구조가 구현되어 있다.

여기서 선생님이 댓글에 답장하려 할 때
단순히 diary 전체 댓글을 열면 안 된다.

notification을 발생시킨
정확한 parent/student thread를 식별해야 한다.

필요하다면 notification의 기존 ref/extra_data 구조를 확인해서

- diary_id
- parent/student 식별값
- comment/thread 식별값

중 기존 구조에서 가장 안전한 값을 사용한다.

새 DB 구조를 만들기 전에 기존 데이터로 해결 가능한지 먼저 확인.

6. Teacher 댓글 화면의 목록 구조 확인
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

하나의 일지에 댓글을 단 학부모가 여러 명이면
선생님이 각 학부모와 독립적으로 답장할 수 있어야 한다.

절대 모든 학부모 댓글을 하나의 공용 채팅창에 합치지 않는다.

필요한 UX는:

일지
 ├ 학부모 A 댓글 thread
 ├ 학부모 B 댓글 thread
 └ 학부모 C 댓글 thread

각 thread는 독립.

현재 구조가 이미 이렇게 되어 있으면
구조 변경하지 말고 실제 격리 조건만 증명할 것.

안 되어 있으면 최소 변경으로 수정.
