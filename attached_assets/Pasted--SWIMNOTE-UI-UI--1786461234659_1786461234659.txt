[SWIMNOTE 선생님 설정 화면 UI 통일 작업]

현재 첨부한 선생님 설정 화면 스크린샷을 기준으로 작업한다.

목적:
현재 설정 화면은 각 영역별 UI 디자인 규칙이 달라 통일감이 부족하다.
기능/데이터/네비게이션은 절대 변경하지 않고 UI와 레이아웃만 하나의 디자인 시스템으로 정리한다.

중요:
이번 작업은 UI 정리 작업이다.
기존 기능을 재구현하거나 handler/navigation/API를 수정하지 마라.

==================================================
1. 먼저 현재 코드 감사
==================================================

수정 전에 선생님 설정 화면의 실제 파일과 관련 컴포넌트를 확인한다.

다음 항목을 먼저 파악한다.

- 설정 화면 메인 파일
- 각 메뉴 onPress
- navigation destination
- toggle state 및 저장 함수
- 알림 설정 값
- 저장공간 데이터 표시 로직
- 업데이트 확인 함수
- 문의하기 함수
- 회원탈퇴 함수
- 현재 사용 중인 icon library
- 공통 MenuItem / Card / Section 컴포넌트 존재 여부

기존 동작을 모두 기록한 후 UI만 수정한다.

==================================================
2. 전체 디자인 원칙
==================================================

현재 SWIMNOTE의 기본 디자인 방향을 유지한다.

기본 색상:

NAVY = 현재 앱에서 사용 중인 SWIMNOTE 네이비
MINT = 현재 앱에서 사용 중인 SWIMNOTE 민트
WHITE = #FFFFFF

새로운 임의 색상을 추가하지 않는다.

현재 화면처럼

네이비
민트
주황
보라
초록
파랑

아이콘이 제각각 섞이는 구조를 정리한다.

설정 화면의 기본 아이콘은 NAVY로 통일한다.

상태나 강조 의미가 반드시 필요한 요소만 MINT를 사용한다.

위험 동작인 회원탈퇴만 기존 RED 계열을 유지한다.

==================================================
3. Header
==================================================

현재 구조 유지:

[뒤로가기]            설정            [홈]

기존 onPress/navigation 변경 금지.

버튼 크기, SafeArea, 터치 영역을 깨뜨리지 않는다.

==================================================
4. 상단 주요 설정 메뉴
==================================================

현재:

공지함
선생님 설정
일지 템플릿
알림함
사진·영상 업로드/앨범

5개 메뉴의 디자인을 완전히 동일하게 통일한다.

각 메뉴:

[아이콘] 메뉴명                              [chevron-right]

동일한:

- 높이
- border width
- border color
- border radius
- horizontal padding
- icon size
- text size
- chevron size
- 메뉴 간 vertical gap

을 사용한다.

현재 네이비 outline 카드 디자인을 기본으로 유지한다.

각 카드마다 다른 스타일을 만들지 않는다.

==================================================
5. 아이콘 색상 정리
==================================================

상단 주요 메뉴 아이콘:
NAVY 통일

하단 설정 Section 제목 아이콘:
MINT 통일

즉 시각적 계층을 다음처럼 만든다.

NAVY
= 실제 이동/실행 메뉴

MINT
= 설정 카테고리 제목 및 상태 강조

RED
= 회원탈퇴 같은 위험 동작

저장공간 내부의 사진/영상/메신저/일지/공지/시스템 아이콘도
현재처럼 무지개색으로 각각 강조하지 말고
전체 화면과 어울리도록 색상 사용을 최소화한다.

단, 색상이 실제 데이터 종류를 구분하는 중요한 기존 UX 역할을 하는지 코드/기존 디자인을 먼저 확인한다.
그렇지 않다면 NAVY 또는 MINT 중심으로 정리한다.

==================================================
6. Section 구조 통일
==================================================

상단 주요 메뉴 아래 영역은 모두 동일한 Section 규칙을 사용한다.

예:

[아이콘] 수업료 납부 관리

    납부 체크 기능 사용                     [toggle]
    수영장 전산 이용 시 끄세요


[아이콘] 알림 설정

    쪽지·메시지 알림                       [toggle]
    새 메시지 수신 시 알림

    보강 신청 알림                         [toggle]
    새 보강 요청 수신 시 알림

    일지 리마인더                          [toggle]
    미작성 일지 알림

    소식                                  [toggle]

    좋아요                                [toggle]
    학부모가 수업피드에 좋아요 시 알림

    일지 댓글                             [toggle]
    학부모가 일지 댓글 작성 시 알림


[아이콘] 저장공간

    storage summary card

    사진
    영상
    메신저
    수영일지
    공지
    시스템


[아이콘] 약관 및 정책

    이용약관                               >
    개인정보처리방침                        >
    환불 및 결제 정책                       >

Section 제목의:

- 좌측 margin
- icon size
- icon과 제목 간격
- 제목 font size/weight
- 위/아래 spacing

을 전부 동일하게 한다.

==================================================
7. Toggle row 통일
==================================================

모든 toggle 설정은 하나의 동일한 Row 규칙을 사용한다.

왼쪽:

제목
설명

오른쪽:

toggle

모든 toggle의:

- 크기
- 오른쪽 margin
- row 높이
- title font
- description font
- divider 위치

를 동일하게 한다.

현재 실제 toggle state 및 저장 로직은 절대 변경하지 않는다.

==================================================
8. 저장공간 영역
==================================================

기존 저장공간 기능 및 계산 로직은 변경 금지.

현재 storage summary card의 기능도 그대로 유지한다.

다만 주변 Section들과 어울리도록:

- 좌우 margin
- border radius
- border
- padding
- typography

를 SWIMNOTE 디자인 규칙에 맞춘다.

사진/영상/메신저/수영일지/공지/시스템 행도
동일한 row height와 정렬 규칙을 사용한다.

숫자/용량 값은 오른쪽 정렬 유지.

==================================================
9. 문의하기
==================================================

현재 문의하기만 민트 outline 대형 카드라
상단 NAVY 메뉴들과 디자인 언어가 충돌한다.

문의하기 역시 일반 설정 메뉴와 동일한 메뉴 구조로 정리한다.

[문의 아이콘] 문의하기                           >

단 기존 문의하기 onPress는 그대로 유지한다.

새 navigation을 만들지 않는다.

==================================================
10. 업데이트 확인
==================================================

업데이트 확인은 일반 navigation 메뉴가 아니라
실행 기능이므로 별도 Action Card로 유지해도 된다.

다만 전체 화면과 동일한:

- border radius
- horizontal margin
- typography
- icon sizing

규칙을 사용한다.

현재 업데이트 확인 로직,
Store Update,
OTA Update 관련 코드는 절대 수정하지 않는다.

==================================================
11. 회원 탈퇴
==================================================

화면 최하단 유지.

위험 동작이므로 RED 계열 텍스트 유지 가능.

기존 회원탈퇴 handler/dialog/API는 절대 수정하지 않는다.

==================================================
12. 반응형 레이아웃 필수
==================================================

특정 iPhone 화면 크기에 맞춰 고정 좌표를 사용하지 않는다.

금지:

- absolute positioning으로 메뉴 배치
- 화면 width를 가정한 고정 너비
- 고정 화면 높이
- 기기별 하드코딩
- 작은 화면에서 bottom tab과 콘텐츠 겹침

반드시 현재 ScrollView/SafeArea 구조를 확인하고 대응한다.

검증 대상:

- 작은 iPhone
- 일반 iPhone
- 큰 iPhone
- Android 소형 화면
- Android 일반 화면
- Android 대형 화면

화면이 작으면 자연스럽게 세로 Scroll되어야 한다.

마지막 회원탈퇴까지 정상적으로 접근 가능해야 한다.

Bottom Tab Bar가 마지막 콘텐츠를 가리지 않도록
기존 safe-area/bottom inset 구조를 확인한다.
