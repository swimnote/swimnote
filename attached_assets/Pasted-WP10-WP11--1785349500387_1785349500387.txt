WP10 최종 증거 재현 감사

이번 작업은 개발이 아니다.

새 기능 구현 금지
기존 코드 수정 금지
배포 수정 금지
WP11 진행 금지

목적은 포렌식 감사에서 증거가 없었던 아래 두 항목만 실제로 재현하고 증거를 저장하는 것이다.

1. production auth/login 성공
2. production auth/me 성공
3. 테스트 DB 데이터 생성 및 삭제

그 외 항목은 다시 조사하지 않는다.

================================
1. 감사 시작 Git 상태 저장
================================

다음을 실행하고 원문 전체를 증거 파일에 저장한다.

git status
git rev-parse HEAD
git branch -vv
git log -5 --oneline --decorate

증거 파일:

artifacts/audit/wp10-final-evidence.txt

기존 파일이 있으면 덮어쓰지 말고 timestamp를 붙인다.

================================
2. 재현용 스크립트 저장
================================

production 테스트에 사용하는 실제 스크립트를 반드시 Git working tree에 저장한다.

경로:

artifacts/api-server/src/scripts/wp10-final-evidence-test.ts

스크립트에는 반드시 다음이 포함되어야 한다.

- 실제 사용 BASE URL 출력
- 테스트 시작 timestamp
- 테스트 계정의 고유 ID
- 테스트 데이터 INSERT
- POST /api/auth/login
- GET /api/auth/me
- 각 요청의 URL
- HTTP method
- status
- content-type
- 응답 body의 개인정보 제거 요약
- 요청 시작·종료 timestamp
- cleanup DELETE
- cleanup 결과 확인
- 실패 시 stderr
- process exit code

비밀번호와 JWT 원문은 절대 출력하지 않는다.

================================
3. DB 생성 증거
================================

테스트 데이터 생성 전:

동일 테스트 계정이 존재하지 않는지 SELECT 한다.

INSERT 후:

동일 ID 또는 username으로 다시 SELECT 한다.

다음만 출력한다.

- record exists: true/false
- test user id
- role
- created_at

비밀번호 해시나 개인정보는 출력 금지.

INSERT 성공 여부는 스크립트 문장으로 주장하지 말고
INSERT 후 SELECT 결과로 증명한다.

================================
4. 실제 Production 요청
================================

반드시 production 주소를 사용한다.

https://swimnote.kr/api/auth/login
https://swimnote.kr/api/auth/me

localhost 사용 금지.

auth/login은 실제 생성한 테스트 계정으로 요청한다.

기록할 항목:

- URL
- method
- status
- content-type
- response success
- duration milliseconds

auth/me는 auth/login에서 실제 받은 토큰을 사용한다.

기록할 항목:

- status
- content-type
- returned user id
- returned role

토큰 원문은 기록하지 않는다.

================================
5. 원본 실행 출력 보존
================================

스크립트 실행 시 stdout과 stderr를 모두 증거 파일에 저장한다.

예:

npx tsx artifacts/api-server/src/scripts/wp10-final-evidence-test.ts \
  2>&1 | tee -a artifacts/audit/wp10-final-evidence.txt

PIPESTATUS를 이용해 실제 스크립트 exit code도 기록한다.

실행 결과를 보고서에 옮겨 적는 것으로 대신하면 안 된다.

tee로 저장된 원본 출력이 반드시 있어야 한다.

================================
6. Cleanup 증거
================================

테스트 완료 후 테스트 계정을 삭제한다.

삭제 후 다시 SELECT하여 다음을 기록한다.

record exists after cleanup: false

cleanup에 실패하면 PASS 금지.

================================
7. 파일·Git 보존
================================

감사가 끝나도 다음 파일을 삭제하지 않는다.

- wp10-final-evidence-test.ts
- wp10-final-evidence.txt

자동 커밋이 발생하더라도 삭제하지 않는다.

마지막에 다음을 실행하고 출력 원문을 증거 파일에 추가한다.

git status
git diff --stat
git diff
git rev-parse HEAD

이번 감사에서는 push 금지.

================================
8. 최종 판정
================================

다음 항목만 판정한다.

A. 테스트 DB INSERT 후 SELECT 확인
B. production auth/login 200 확인
C. production auth/me 200 및 role 확인
D. cleanup 후 데이터 부재 확인
E. 실행 원본 로그 파일 존재
F. 실행 스크립트 파일 존재

각 항목을 다음 형식으로 작성한다.

항목:
결과: VERIFIED / FAILED
증거 파일:
증거 줄 또는 실제 출력:
판정:

최종 결론은 둘 중 하나만 사용한다.

1. WP10 미확인 실행 항목 재현 완료
2. WP10 미확인 실행 항목 재현 실패

주의:

이 감사는 과거에 실제 실행했는지를 억지로 증명하는 작업이 아니다.

과거 보고서에서 증거가 부족했던 동일 실행을
현재 재현하고
스크립트·stdout·stderr·DB 확인 결과를 남기는 작업이다.

증거 파일이나 실행 스크립트가 없으면 완료로 보고하지 않는다.
