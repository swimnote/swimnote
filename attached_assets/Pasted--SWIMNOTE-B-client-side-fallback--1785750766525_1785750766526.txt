[SWIMNOTE 긴급 오류 수정 전 최종 보완 지시]

원인조사 보고서 확인.

오류 B의 client-side fallback 문제는 원인 확정으로 인정한다.
하지만 제시한 UI 수정만으로는 근본 해결이 아니다.

change-status가 student_class_history.left_at을 갱신하지 않으므로,
날짜 API만 사용하도록 바꾸면 연기·미배정 적용일 이후에도
학생이 기존 반에 계속 나타날 가능성이 있다.

따라서 오류 A와 오류 B를 아래 기준으로 보완한 뒤 구현안을 제출한다.

━━━━━━━━━━━━━━━━━━━━━━
A. 반이동 버튼 미작동
━━━━━━━━━━━━━━━━━━━━━━

현재 보고서는 원인 확정이 아니다.

today-schedule의 classGroups가 당일 반만 포함하는 문제는 실제 결함이지만,
my-schedule.tsx에서는 전체 groups를 전달한다고 보고했다.

사용자가 오류를 확인한 정확한 진입 경로가 my-schedule이라면
today-schedule 문제만 수정해서는 해결되지 않는다.

코드 수정 전 아래 런타임 로그를 추가해 실제 원인을 확정한다.

1. 반이동 버튼 onPress 진입 로그
   - student_id
   - student_name
   - current_group_id
   - classGroups.length

2. setMoveStudent 직후 상태 또는 effect 로그

3. SubSheetModal 렌더 로그
   - visible
   - moveStudent.id
   - moveTargetClasses.length

4. SubSheetModal이 렌더됐는데 화면에 안 보이는 경우
   - React Native Modal 중첩 여부
   - presentationStyle
   - transparent
   - zIndex/elevation
   - backdrop
   - visible prop
   - 부모 Modal 위에 두 번째 Modal이 표시되는지 확인

5. 정확한 진입 경로별 확인
   - my-schedule 월
   - my-schedule 주
   - my-schedule 일
   - today-schedule

판정:

- onPress 자체가 호출되지 않음
  → 터치/Responder 문제

- onPress와 상태 변경은 됐으나 SubSheetModal 미표시
  → 중첩 Modal/렌더링 문제

- SubSheetModal 표시되고 대상 0개
  → classGroups 전달 문제

이 셋을 구분한 뒤 직접 원인을 확정한다.

today-schedule에는 전체 반 목록을 전달해야 하는 것이 맞다.
그러나 이것을 반이동 미작동의 유일 원인으로 단정하지 않는다.

━━━━━━━━━━━━━━━━━━━━━━
B. 과거 학생명단 소급 삭제
━━━━━━━━━━━━━━━━━━━━━━

최종 정책:

학생의 배정 상태는 적용일을 기준으로 이력화한다.

예:
8월 3일부터 연기

- 8월 2일까지 기존 반에 표시
- 8월 3일부터 기존 반에서 제외
- 7월 과거 명단은 그대로 유지

필수 수정은 클라이언트와 서버 두 계층이다.

1. 클라이언트 수정

ClassDetailSheet가 과거·특정 날짜 학생명단을 표시할 때
현재 students.assigned_class_ids 또는 class_group_id 기반 fallback을 사용하지 않는다.

my-schedule:
- 날짜가 선택된 상태에서 studentsByDate가 로딩 중이면
  현재 학생 목록 fallback을 표시하지 않는다.
- 로딩 상태 또는 빈 skeleton을 표시한다.
- API 완료 후 날짜 기준 명단만 표시한다.

today-schedule:
- 상세 수업 날짜를 기준으로
  GET /class-groups/:id/students?date=YYYY-MM-DD 호출
- 해당 응답을 studentsByDate로 전달
- 현재 상태 기반 fallback 금지

ClassDetailSheet:
- 날짜 기반 화면에서는 studentsByDate가 undefined일 때
  현재 상태 기반 목록으로 대체하지 않는다.
- 날짜 기반 조회와 현재 반 관리 조회의 모드를 명시적으로 분리한다.

권장 prop:

studentListMode: "historical" | "current"

historical:
- studentsByDate만 사용
- 로딩 중 fallback 금지

current:
- 현재 students 상태 사용 가능

단순히 undefined를 []로 바꿔 증상을 숨기지 말고
로딩 상태와 실제 빈 명단을 구분한다.

2. 서버 수정

다음 즉시 적용 처리에서 기존 활성 배정 이력을 종료해야 한다.

- change-status suspended
- change-status withdrawn
- change-status unassigned
- remove-from-class 즉시 처리

적용일:
effective_date 또는 서버에서 확정한 적용 날짜

처리:

UPDATE student_class_history
SET left_at = effective_date
WHERE student_id = ?
  AND class_group_id = 기존 반
  AND left_at IS NULL;

그리고 students의 현재 상태를 변경한다.

반드시 동일 DB transaction에서 실행한다.

순서:

1. 기존 활성 반과 assigned_class_ids 조회 및 잠금
2. student_class_history 활성 row left_at 기록
3. students.status/class_group_id/assigned_class_ids 변경
4. audit 또는 기존 이력 기록
5. commit

실패 시 전체 rollback.

3. 날짜 경계 규칙 확정

현재 조회 SQL:

h.enrolled_at <= targetDate
AND (h.left_at IS NULL OR h.left_at > targetDate)

이 규칙에서는 left_at이 “해당 반에서 제외되기 시작하는 날짜”다.

따라서 8월 3일부터 연기라면:

left_at = 2026-08-03

결과:
- 8월 2일 포함
- 8월 3일 제외

이 의미를 모든 상태 변경·반이동·미배정에서 통일한다.

4. next_month 처리

예약 시점에는 history를 변경하지 않는다.

실제 효력 적용 Job 또는 처리 함수가 실행되는 날짜에:

- 기존 active history left_at = effective_date
- students 현재 상태 변경

을 동일 transaction으로 수행한다.

예약만 등록한 시점에 과거·현재 명단을 미리 변경하면 안 된다.

5. 반이동

기존 방식 확인:

- 이전 반: left_at = effective_date
- 새 반: enrolled_at = effective_date

이 규칙을 유지한다.

검증:

- effective_date 이전: 이전 반
- effective_date 당일 이후: 새 반
