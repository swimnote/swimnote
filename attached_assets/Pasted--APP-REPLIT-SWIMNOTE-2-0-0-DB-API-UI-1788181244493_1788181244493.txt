[보낼 곳: APP REPLIT]

SWIMNOTE 2.0.0 상품화 작업을 지금부터 시작한다.

이번 작업은 기능 구현 작업이 아니다.
현재 실제 코드/DB/API/UI 상태를 전수조사해서
"상품화 기준선(BASELINE)"을 만드는 기술검수 단계다.

코드 수정 / migration / deploy / OTA 금지.

==================================================
상품화 최상위 원칙
==================================================

SWIMNOTE 상품화의 제1원칙:

"모든 수영장의 매출을 올린다."

모든 기능은 최소 하나에 기여해야 한다.

1. 신규회원 증가
2. 등록 전환율 증가
3. 재등록 증가
4. 퇴원 감소
5. 객단가 증가
6. 학부모 추천/공유 증가

추가 원칙:

- 관리자 업무 증가 금지
- 선생님 업무 증가 금지
- 학부모 알림/정보 피로 증가 금지
- 사용 빈도가 극히 낮은 기능은 제거 후보
- 기술적으로 멋있지만 현장 가치가 낮으면 제거 후보
- 동일 기능 중복 UI 금지
- AI를 사용한다는 이유만으로 AI 기능을 만들지 않음
- 사용자가 데이터를 더 입력해야만 작동하는 구조는 최소화
- 가능한 기능은 자동화
- 실제 매출/재등록 효과를 측정할 수 있어야 함

4. Stress Audit
==================================================

아래 유형을 실제 코드/UI에서 찾아낸다.

- 필수입력 과다
- 같은 내용 반복입력
- 선택지가 지나치게 많음
- 관리자만 이해 가능한 용어
- 알림 과다 가능성
- 실패 이유 불명확
- 저장 여부 불명확
- 뒤로가기 시 내용 손실
- 로딩 시간이 긴데 상태표시 없음
- 같은 설정 여러 곳
- 사용빈도 낮은 기능이 메인 UI 점유

각 항목:
HIGH / MEDIUM / LOW
