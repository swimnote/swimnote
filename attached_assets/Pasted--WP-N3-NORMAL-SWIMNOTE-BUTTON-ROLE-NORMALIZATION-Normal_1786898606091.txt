[WP-N3 — NORMAL SWIMNOTE BUTTON ROLE NORMALIZATION]

목적:

Normal SWIMNOTE 전반에 흩어진 버튼 색상을
"기능명"이 아니라 "행동의 성격" 기준으로 통일한다.

현재 문제:

- 같은 저장/확인/등록 버튼이 화면마다 mint/navy/themeColor로 다름
- 같은 선택 버튼도 화면마다 mint/blue/purple 등 중구난방
- 일반 navigation 버튼과 semantic 버튼이 시각적으로 섞임
- 개발단계 UI처럼 보이는 가장 큰 원인 중 하나

이번 WP는
버튼의 ROLE + COLOR SYSTEM만 정리한다.

중요:

버튼 위치
버튼 그룹
화면 레이아웃
간격
라우팅
onPress
API
state
disabled 조건

은 변경 금지.

==================================================
2. PRIMARY_ACTION
==================================================

대상:

- 저장
- 등록
- 확인
- 완료
- 다음
- 제출
- 생성
- 적용
- 대표적인 1순위 CTA

Normal:

background
→ C.brandStrong #4F6F67

label/icon
→ 충분한 대비를 가진 밝은 text token

중요:

pure white를 무조건 쓰지 말고
현재 contrast 확인.

하지만 가독성 우선.

X:

기존 mode-aware component에서는
XT.primary 유지.

X 변경 금지.

==================================================
3. SECONDARY_ACTION
==================================================

대상:

- 보조 실행
- 이전
- 나중에
- 추가 옵션
- 같은 화면의 2순위 CTA

Normal:

background
→ C.brandSoft 또는 neutral soft surface

text
→ C.brandStrong 또는 C.textPrimary

border
→ 필요 시 C.brandPrimary / C.border

Primary보다 시각적 우선순위가 낮아야 한다.

==================================================
4. NEUTRAL_ACTION
==================================================

대상:

- 닫기
- 취소
- 돌아가기
- 일반 비강조 작업
- 보조 modal action

Normal:

neutral surface
+ C.textPrimary / C.textSecondary

brand color 과사용 금지.

==================================================
5. NAVIGATION_ACTION
==================================================

대상:

- 자세히 보기
- 화면 이동
- 설정 열기
- 목록 보기
- 관리 화면 진입

큰 filled primary CTA로 만들지 않는다.

권장:

text button
또는 subtle bordered/soft button

color:
C.brandStrong / C.textPrimary

중요:
Navigation과 Primary business action을 시각적으로 구분.

==================================================
6. SELECTION STATE
==================================================

Normal active/selected:

background
→ C.brandSoft

border/icon/text
→ C.brandStrong 또는 C.brandPrimary

작은 글자에서 contrast 부족하면
C.brandStrong 사용.

Normal inactive:

neutral surface
+ C.textSecondary

선택 상태를
mint/blue/purple/orange 등으로 화면마다 다르게 만들지 않는다.

단 FEATURE_FIXED / SEMANTIC_PROTECTED 제외.

==================================================
7. DESTRUCTIVE
==================================================

삭제
연결 해제
탈퇴
영구 삭제
취소가 실제 destructive 의미일 때만

semantic red 사용.

기존:

C.error
#D96C6C
#DC2626

혼재 감사.

가능한 경우 공식 semantic destructive token으로 통일.

단:

강한 danger confirmation에서 별도 strong red가
실제 semantic hierarchy로 사용 중이면
무조건 제거하지 말고 의미 확인.

"빨간색을 하나로 만들기"가 목적이 아니라
역할 없는 중복을 제거하는 것이 목적.

==================================================
8. WARNING
==================================================

경고가 필요한 실제 행동만
warning/amber.

일반 중요 버튼을
눈에 띄게 하려고 orange 사용 금지.

==================================================
9. SUCCESS
==================================================

success green은:

- 성공 상태
- 완료 상태
- 출석/승인 등 이미 의미가 정해진 경우

에만 사용.

일반 "저장 완료 버튼"이란 이유만으로
success green을 primary CTA 색으로 사용하지 않는다.

==================================================
10. DISABLED
==================================================

disabled는 별도 상태.

- 흐릿해서 읽을 수 없으면 안 됨
- active처럼 보여도 안 됨
- C.textMuted를 무조건 disabled text로 쓰지 않는다

기존 disabled token 체계를 감사하고 유지.

→ PRIMARY_ACTION → C.brandStrong

→ SELECTION_ACTIVE → C.brandSoft + C.brandStrong

→ FEATURE_FIXED → 유지

mint + scheduler classification
→ PROTECTED → 유지
