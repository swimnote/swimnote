[전달 대상: SWIMNOTE APP Replit]

PROJECT = SWIMNOTE OFFICE V1
TASK = 기존 제작 방식으로 Windows 검증 실행본 제작

1. 진행 방향 변경

사용자에게 Node·pnpm·PostgreSQL 설치,
소스 빌드·개발 환경 구성을 요구하는 방식은 중단한다.

사용자가 할 일은:
파일 다운로드 → 설치 또는 압축 해제 → 실행 → 결과 전달.

이전 지시의 Windows 검증본 패키징 금지를 이번 범위에서 해제한다.
운영 배포·공개 게시·코드 서명·유료 서비스 사용 승인은 포함하지 않는다.

2. 기존 방식 우선

저장소의 기존 Windows 설치본 제작 설정·스크립트·산출물을 확인하고
기존에 사용하던 제작 흐름을 우선 재사용한다.

기준 후보:
OFFICE-WIN-AUTH-fad5704318bc64c4

기존 source·미커밋 변경·후보·ZIP·증거 보존.
현재 HEAD와 기준 후보 차이를 기록.
현재 HEAD 전체를 임의로 검증본에 포함하지 않는다.
checkout/reset·commit/push 금지.

기존 Linux 정상 인증·업무·오류 복구 검증 증거는 재사용.
변경 없는 준비·전체 suite 반복 금지.

3. 전달할 결과

우선 기존 방식의 Windows x64 설치 파일(.exe)을 제작한다.
현재 환경에서 설치본 제작이 불가능하면,
필요한 런타임을 포함한 압축 해제형 Windows 실행본을 제작한다.

어느 방식이든 사용자 PC에서 다음이 필요 없어야 한다:
- Node·pnpm 수동 설치.
- PostgreSQL 수동 설치.
- package 설치·소스 컴파일.
- PowerShell 개발 명령 입력.

Electron·격리 API·합성 DB에 필요한 실행 요소를 준비하고,
사용자는 실행 진입점 하나로 시작하게 한다.
기존에 설치한 개발 도구가 없는 PC를 기준으로 구성한다.

다운로드한 파일을 기존 설치본과 분리해서 실행할 수 있게 한다.
검증본임을 이름·아이콘 또는 화면에서 식별한다.

4. 격리 실행 유지

운영 연결 대신 기존 정상 인증 합성 환경을 사용한다.

- 실제 제품 로그인·PIN/TOTP·JWT·권한 검증 유지.
- 합성 회원·반·Pool만 사용.
- 기록된 모델 응답만 사용, 신규 유료 호출 0회.
- 운영 DB·Secret·기존 제품 세션 사용 금지.
- 별도 userData·로컬 자격증명 유지.
- loopback 바인딩·단일 origin·IPC 보안 유지.
- 자격증명은 최초 실행 시 생성, 배포 파일에 고정 비밀 포함 금지.

로컬 API·DB 시작과 정상 종료를 실행본에서 관리한다.
기존 포트 점유자·다른 프로그램을 종료하지 않는다.
실패하면 이해 가능한 오류와 비밀 없는 진단 파일을 제공한다.
사용자에게 터미널 작업을 기본 해결책으로 넘기지 않는다.

검증용 로그인 정보는 앱의 로컬 안내 등으로 확인 가능하게 한다.
비밀번호·PIN·OTP를 진단 파일에 넣지 않는다.

5. 사용자 PC 설치 실패 기록

기존 소스 전달본의 pnpm 설치가
EXIT_CODE=-1073740791로 반복 중단됐다.

해당 로그는 보존하되 동일 설치 재시도를 요구하지 않는다.
이 실패를 앱 자체의 Windows 실행 실패로 혼동하지 않는다.
실행본 제작에 직접 필요한 경우에만 원인을 추가 조사한다.

사용자 PC의 기존 개발 도구를 제거하거나 변경하지 않는다.

6. 제작 환경의 한계

현재 Replit에서 Windows 실행 환경이 없다는 점은 유지한다.
Linux 빌드·교차 패키징 성공을 Windows 실행 PASS로 표현하지 않는다.

기존 도구로 만들 수 있는 산출물까지 실제 제작한다.
Windows 빌드 환경이 반드시 필요하면:
- 필요한 구체적 작업과 차단 원인을 보고.
- 기존에 연결·승인된 빌드 경로가 있으면 활용.
- 새 외부 계정·유료 CI·저장소 push가 필요하면 별도 보고.
- 사용자 PC에 개발 환경을 다시 설치시키는 방식으로 되돌리지 않는다.

7. 검증·전달

직접 확인 가능한 범위:
- 고정 후보 source와 포함 파일 일치.
- Windows 아키텍처·실행 파일·필수 의존성 누락 여부.
- 런타임·API·합성 DB 자원 경로.
- 비밀·운영 주소·기존 제품 데이터 혼입 여부.
- 시작·종료·오류 처리 계약.
- 설치본 또는 실행 ZIP의 무결성.

Windows 실제 실행·DPAPI·업무 수용은 미실행이면 NOT RUN.

완료 시:
- 다운로드 가능한 실제 설치본 또는 실행 ZIP.
- 파일명·크기·SHA-256.
- 사용자용 안내: 다운로드→설치/해제→실행.
- 최초 로그인 방법.
- 실패 시 전달할 진단 파일 위치.
- 직접 검증한 항목과 Windows 미검증 항목.

소스 ZIP만 다시 전달하고 제작 완료로 선언하지 않는다.

8. 금지

운영 DB·metadata·startup·migration.
운영 계정·회원·Pool 변경.
실제 발송·결제·환불·업로드.
신규 유료 모델 호출.
모바일·AI ENGINE 변경.
commit/push·main 반영·Render·OTA·공개 배포.

이번 승인 범위는 사용자에게 전달할
격리 Windows 검증본의 빌드·패키징이다.

완료 후 산출물과 결과를 보고하고 정지.
