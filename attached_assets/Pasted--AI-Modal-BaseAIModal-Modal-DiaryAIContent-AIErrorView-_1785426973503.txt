[AI 일지 Modal 런타임 상태 추적 — 수정 금지]

정적 분석상 BaseAIModal, Modal, DiaryAIContent, AIErrorView는 각각 1개이며
React Tree 중복 렌더 구조는 발견되지 않았다.

그러나 실기기에서는 이전 ERROR 화면 전체가 반투명하게 남고,
새 ERROR 화면과 겹치며 깜빡이는 현상이 실제로 발생했다.

이번에는 React mount 개수만 보지 말고
BaseAIModal의 네이티브 Modal 상태와 애니메이션 상태를
실기기 런타임에서 시간순으로 추적한다.

수정하지 말고 로그만 추가·수집한다.

1. BaseAIModal 상태 로그

다음 값이 변경될 때마다 timestamp와 함께 기록한다.

- visible prop
- nativeVisible
- rendered
- isClosing 또는 동등한 닫힘 상태
- current AI state
- error 존재 여부
- keyboard visible 여부

로그 형식:

[AI-MODAL-STATE]
time=
visible=
nativeVisible=
rendered=
isClosing=
aiState=
hasError=
keyboardVisible=

2. Modal lifecycle 로그

다음을 기록한다.

- Modal render
- onShow
- onRequestClose
- onDismiss
- visible true/false 전환

로그 형식:

[AI-NATIVE-MODAL]
event=render|onShow|onRequestClose|onDismiss
nativeVisible=
rendered=
time=

3. Sheet 애니메이션 로그

열기·닫기 애니메이션 각각:

- start
- finish
- cancelled 여부
- 완료 콜백 실행 여부

로그 형식:

[AI-SHEET-ANIMATION]
type=open|close
event=start|finish
finished=
time=

4. ERROR 전환 로그

다음을 모두 기록한다.

- ERROR dispatch 발생 시점
- 이전 state
- 다음 state
- requestId
- error code
- error message
- 동일 requestId의 ERROR dispatch 횟수

5. 키보드 로그

- keyboardDidShow
- keyboardDidHide
- ERROR 진입 당시 키보드 상태
- KeyboardAvoidingView behavior와 vertical offset

6. OTA 실제 적용 증명

앱 화면 또는 로그에 다음을 출력한다.

- appVersion
- runtimeVersion
- updateId
- createdAt
- isEmbeddedLaunch
- channel
- branch 또는 배포 식별값
- 커밋 9642537을 식별할 수 있는 JS bundle marker

수정본에 고유 문자열을 추가한다.

예:
DIARY_ERROR_ACTIONBAR_FIX_9642537

실기기 로그에서 해당 문자열이 출력되지 않으면
OTA 미적용으로 판정한다.

7. 재현 절차

A.
앱 완전 종료
→ 다시 실행
→ OTA 식별 로그 확인
→ 텍스트 입력
→ Generate
→ ERROR 발생

B.
같은 상태에서 다시 시도

C.
닫기 후 AI 모달 재진입

각 절차의 전체 로그를 제출한다.

최종 판정은 아래 중 하나로 한다.

A. OTA NOT APPLIED
B. nativeVisible/rendered STATE RACE
C. OPEN/CLOSE ANIMATION OVERLAP
D. MODAL DISMISS NOT COMPLETED
E. KEYBOARD + MODAL LAYOUT ARTIFACT
F. DUPLICATE ERROR DISPATCH
G. OTHER

주의:

- React Tree가 1개라는 이유만으로 PASS 처리하지 않는다.
- 실제 updateId와 고유 bundle marker 없이는 OTA 적용을 인정하지 않는다.
- 화면 수정 전에 런타임 로그로 원인을 증명한다.
