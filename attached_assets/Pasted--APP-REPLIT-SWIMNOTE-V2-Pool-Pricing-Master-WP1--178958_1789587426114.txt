[보낼 곳: APP REPLIT]

[SWIMNOTE 정산 V2 — Pool Pricing Master 정책 최종 확인]

WP1 최종 마감 수정 전에
가격정책의 의미를 명확히 고정합니다.

중요:

pool_class_pricing은
회원마다 입력하는 수업료가 아닙니다.

각 수영장이 미리 한 번 설정해두는
“센터 기준 수업료표”입니다.

━━━━━━━━━━━━━━━━━━━━━━
1. 가격 설정 구조
━━━━━━━━━━━━━━━━━━━━━━

수영장 관리자가 미리 설정:

weekly_1
→ 월 수업료
→ 월 기준 횟수

weekly_2
→ 월 수업료
→ 월 기준 횟수

weekly_3
→ 월 수업료
→ 월 기준 횟수

필요 시 custom_1 / custom_2.

이 가격표는:

pool_id

에 귀속됩니다.

학생마다 별도의 정상 수업료를
매번 입력하지 않습니다.

━━━━━━━━━━━━━━━━━━━━━━
2. 회원 등록 시 동작
━━━━━━━━━━━━━━━━━━━━━━

회원 등록/수정에서 사용자가 선택하는 것은:

주1회
주2회
주3회

즉:

students.weekly_count

입니다.

예:

weekly_count = 2

이면 자동으로:

현재 학생의 pool_id
+
type_key = weekly_2

의 pool_class_pricing을 조회.

따라서:

학생등록
→ 주2회 선택
→ weekly_count=2 저장
→ weekly_2 가격 자동 적용

이어야 합니다.

회원등록 화면에서
월수업료를 다시 입력하게 만들지 마십시오.

━━━━━━━━━━━━━━━━━━━━━━
3. 정산 계산 연결
━━━━━━━━━━━━━━━━━━━━━━

가격 Source:

pool_class_pricing

학생 가격유형 Source:

students.weekly_count

최종 매핑:

(pool_id, weekly_count=1)
→ weekly_1

(pool_id, weekly_count=2)
→ weekly_2

(pool_id, weekly_count=3)
→ weekly_3

→ monthly_fee
→ sessions_per_month

이 매핑은 서버 Settlement Service에서
자동으로 수행합니다.

APP/PC가 가격을 직접 결정하지 않습니다.

━━━━━━━━━━━━━━━━━━━━━━
4. 가격표 변경
━━━━━━━━━━━━━━━━━━━━━━

관리자가 센터 가격표를 변경하면:

AUTO 상태 정산
→ 다음 서버 재조회부터 새 가격표 즉시 반영.

별도 batch
재로그인
회원별 재저장

필요 없어야 합니다.

반면:

SAVED / CONFIRMED 정산

은 기존에 저장된:

auto_amount_snapshot
total_revenue

를 보호합니다.

가격표 변경으로
이미 저장된 과거 정산값을 자동 덮어쓰지 마십시오.

━━━━━━━━━━━━━━━━━━━━━━
5. PRICING 미설정의 의미
━━━━━━━━━━━━━━━━━━━━━━

pricing이 없는 학생이 많다는 것은

“회원마다 가격 설정을 안 했다”

는 뜻이 아닙니다.

해당 수영장의
센터 기준 가격표가 아직 설정되지 않았다는 뜻입니다.

따라서 UI에서는:

“회원 수업료 입력 필요”

가 아니라

“센터 수업료 설정 필요”

로 해석해야 합니다.

가능하면 관리자에게:

수업료 설정
→ unit-pricing 화면

으로 연결할 수 있는 구조를 유지하십시오.

이번 WP에서 UI 대규모 수정은 하지 마십시오.

━━━━━━━━━━━━━━━━━━━━━━
6. UNPRICED 처리
━━━━━━━━━━━━━━━━━━━━━━

센터 가격표가 없으면:

pricing_status = 'unpriced'

student_auto_amount = null

teacher allocation 없음.

0원 정상회원으로 처리 금지.

그러나 다른 정상 학생 계산까지
전체 실패시키면 안 됩니다.

unpriced_count 별도 반환.

━━━━━━━━━━━━━━━━━━━━━━
7. 정상 운영 플로우
━━━━━━━━━━━━━━━━━━━━━━

수영장 최초 설정:

관리자
→ 수업료 설정
→ 주1/주2/주3 가격 저장

이후 반복 운영:

회원 등록
→ 주1/주2/주3 선택
→ 자동 가격 연결
→ 시간표 기반 자동매출 계산

끝.

회원 한 명 등록할 때마다
가격을 다시 입력하는 workflow는 만들지 마십시오.

━━━━━━━━━━━━━━━━━━━━━━
