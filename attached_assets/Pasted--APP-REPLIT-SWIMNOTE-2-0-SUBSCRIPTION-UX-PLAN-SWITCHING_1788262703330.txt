# SWIMNOTE 2.0
# SUBSCRIPTION UX / PLAN SWITCHING STRUCTURE CORRECTION
# BEFORE STORE CONNECTION

현재 2.0 Subscription UI를 다시 정리합니다.

문제:

현재 SWIMNOTE / X Trial / X Active 상태에서
구독 상품과 진입 경로가 서로 섞여 있어
사용자가 어디서 무엇을 구매/변경해야 하는지 혼란스러울 수 있습니다.

이번 작업의 목표:

1. 구독 관리 진입점을 하나로 통일
2. 현재 mode/state에 따라 필요한 상품만 표시
3. X Active 상태에서 SWIMNOTE 기본플랜 구매카드 숨김
4. X300/X500/X1000 상호 플랜 변경 가능하도록 UX 준비
5. X 설정 화면의 중복 결제 UI 제거 또는 단일 구독화면으로 연결
6. 실제 RevenueCat/App Store/Google Play purchase 연결은 아직 하지 않음

1. 구독 관리 SINGLE ENTRY POINT
==================================================

구독 관리의 공식 진입점은 하나로 통일합니다.

권장:

설정
→
구독 및 요금제

현재 subscription 화면을
canonical subscription management screen으로 사용.

다른 화면에서 별도의 독립적인 결제 UI를 여러 개 만들지 마십시오.

==================================================
2. X 설정 화면
==================================================

X 설정 안에 구독 관련 메뉴가 필요하면:

"구독 및 요금제 관리"

한 항목만 둡니다.

탭:

→ canonical subscription screen

으로 이동.

X 설정 내부에
별도의 X300/X500/X1000 purchase UI를 중복 구현하지 마십시오.

즉:

X 설정
→ 구독 및 요금제 관리
→ 동일한 subscription screen

구조.

4. X TRIAL MODE
==================================================

x_trial 상태에서 subscription 화면:

SWIMNOTE 기본플랜을 X 가입과 동일한 레벨의
주요 구매 CTA로 섞지 마십시오.

핵심 CTA:

X300 가입
X500 가입
X1000 가입

Trial 사용자가
체험 후 바로 X 정식 플랜을 선택할 수 있어야 함.

필요하면 화면 하단에:

"일반 SWIMNOTE 이용하기"

정도의 secondary action은 가능.

하지만 X trial의 주 결제경로는 X plan 선택.

6. X PLAN SWITCHING
==================================================

X300/X500/X1000은
상호 plan change 가능해야 합니다.

지원 UX:

X300
→ X500
→ X1000

업그레이드 가능.

그리고:

X1000
→ X500
→ X300

다운그레이드도 가능.

X500
→ X300
또는
→ X1000

가능.

현재 플랜은:

"현재 이용중"

표시하고 purchase CTA 비활성.

다른 플랜은:

"플랜 변경"

CTA.

==================================================
7. MEMBER LIMIT SAFETY
==================================================

X plan downgrade 시
현재 active member count가
새 plan limit보다 많으면
그대로 변경 진행 UI를 보여주지 마십시오.

예:

현재 회원 480명
X500 사용중

X300 선택

Expected:

"현재 활성회원 수가 X300 한도 300명을 초과합니다."

표시.

다음 선택 안내:

- 회원수 조정
- X500 유지
- X1000 선택

기존 회원을 자동 삭제하거나
비활성화하지 마십시오.

실제 store downgrade policy는 WP4에서 연결.

==================================================
8. X → SWIMNOTE DOWNGRADE
==================================================

X Active 화면에서
SWIMNOTE 기본플랜 카드를 일반 상품처럼 보여주지 않습니다.

대신 별도 구독관리 action:

"SWIMNOTE로 변경"

또는

"다음 결제일부터 SWIMNOTE로 변경"

으로 표현.

이건 purchase card가 아니라
X subscription downgrade action입니다.

설명:

현재 X 기능은 결제기간 종료일까지 유지.

다음 결제기간부터:

SWIMNOTE
9,900원

으로 전환.

실제 store scheduled downgrade 연결은 WP4.

이번 단계에서는 UX/state 준비만.

→ 현재 결제기간 종료
→ active base subscription 없음
→ subscription_required

둘을 같은 버튼으로 처리하지 마십시오.

16. PLAN CHANGE CTA
==================================================

아직 WP4 이전이므로
실제 Store purchase/upgrade 연결은 금지.

현재 단계:

UI 및 action state 준비.

CTA는:

"플랜 변경 준비 중"

또는 현재 WP3의 disabled-state 정책을 사용.

단 내부 action contract는
다음 WP4에서 연결 가능하도록 구분.

예:

changeBasePlan("x500")

형태의 abstraction 준비는 가능.

실제 RevenueCat call 금지.
