TASK = 앱 내 X모드 PIN 설정 오류 추적
OFFICE F01/F02는 일시 중단한다.

실제 증상 =
사용자가 모바일 앱 내 X모드에서 PIN을 설정하려고 하면
“오류가 발생했습니다”가 표시된다.
실패 endpoint / HTTP status / error_code / request_id는 미확인.
발생 계정·OS·앱 버전은 확인된 정보 없이 단정하지 않는다.

GOAL =
PIN 설정의 실제 호출 경로와 실패 지점을 확인하고,
원인이 증명되면 운영 설정을 변경하지 않는 범위에서 최소 수정한다.

기존 확인 사실 =
- 일반 PC 로그인에 /auth/web-pin/verify 계약이 있음.
- 이것이 모바일 PIN 설정 API와 같다고 가정하지 않는다.
- 운영 계정 toykids와 swimnote의 정보·설정 변경은 금지됨.
- 사용자 비밀번호·PIN·JWT를 문서/로그/보고서에 기록하지 않는다.

진행 =
1. 현재 repo / branch / full HEAD / status 확인.
   기존 변경 보존. checkout/reset 금지.

2. 앱 X모드 PIN 설정 화면 →
   client service → 실제 endpoint →
   인증/권한 → validation → 저장 경로만 확인.

3. “오류가 발생했습니다”가 표시되는 조건을 확인.
   서버의 구체 오류가 앱에서 사라지는지도 확인한다.

4. 기존 로그가 접근 가능하면 관련 실패를 좁게 추적.
   request_id / HTTP / error_code / 최초 exception /
   file·function·line을 확보한다.
   과거 로그가 없으면 원인 미확정으로 남긴다.

5. 기존 테스트 또는 격리된 fixture/mock으로 재현한다.
   실제 운영 계정에서 PIN 설정·재설정 요청을 보내지 않는다.
   운영 DB·계정·권한·PIN·X 상태를 변경하지 않는다.

6. Root Cause가 증명되고 범위 내 수정이 가능할 때만 최소 수정.
   정상 설정·실패 재현·권한 거부 등 관련 테스트만 수행한다.
   실제 PIN 저장 성공 검증은 격리된 테스트 환경에서만 한다.

7. 운영 재현이 반드시 필요하면 먼저 필요한 증거를 보고한다.
   사용자의 직접 재시도 없이 성공할 수도 있는 쓰기 요청을
   Agent가 운영 계정에 실행하지 않는다.

금지 =
- OFFICE 개발 계속 진행
- PC 로그인/PIN 계약의 추측성 재설계
- PIN/X/권한 우회
- 운영 PIN 설정·초기화·비밀번호 변경
- PIN·비밀번호·token·전체 payload 로그
- 오류를 성공으로 위장하는 fallback
- 전체 Repository 감사·전체 suite
- 불필요한 dependency / migration
- commit / push / deploy / OTA
  배포가 필요하면 수정·검증 결과와 필요한 배포 범위를 먼저 보고
