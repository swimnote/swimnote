이번 OTA의 목적:

1. Native/Store Build 업데이트
   → 자동 version check
   → min_version 미달 시 강제 업데이트 Modal
   → 취소 불가
   → App Store / Play Store 이동
   → 구버전 사용 차단

2. Expo OTA 업데이트
   → 앱 자동 OTA 확인
   → 새 OTA 다운로드
   → 재시작 Modal
   → "지금 업데이트"
   → Updates.reloadAsync()
   → 최신 OTA 적용

3. parent_account / teacher / pool_admin
   → 역할과 관계없이 root _layout.tsx에서 자동 실행

특히 parent_account는 수동 업데이트 확인 버튼이 없으므로
자동 검사 경로가 필수이며 이번 코드가 그 역할을 담당한다.

5. OTA 이후 검증
━━━━━━━━━━━━━━━━━━━━━━

CASE 1 — 현재 최신 Native 앱

앱 완전 종료 → 재실행

기대:

- min_version 충족
- Native 강제 Modal 없음
- 이번 OTA 자동 감지
- OTA 다운로드
- "업데이트 준비 완료" Modal
- 버튼: "지금 업데이트"만 존재
- 버튼 탭 → reloadAsync()
- 앱 재시작
- 새 OTA 적용

CASE 2 — OTA 적용 완료 후 재실행

기대:

- 동일 OTA를 다시 다운로드하지 않음
- restart Modal 반복 없음
- 정상 앱 진입

CASE 3 — 구버전 Native 앱

현재 server min_version보다 낮은 경우:

- Native 강제 업데이트 Modal
- 취소 불가
- Store 이동
- OTA check 실행되지 않음

CASE 4 — parent_account

- 수동 업데이트 버튼 없이 자동 작동
- Native/OTA 모두 root에서 검사

CASE 5 — teacher

- 자동 작동

CASE 6 — pool_admin

- 자동 작동

CASE 7 — background → foreground

- runStartupChecks 실행
- 중복 Modal 없음
- 불필요한 polling 없음
