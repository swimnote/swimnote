[SWIMNOTE 잔여 운영 오류 2건 — 전체 경로 조사 후 최소 수정]

현재 실기기에서 다음 오류가 확인됐다.

오류 A.
보강 대기 화면에 7월 기간 지난 보강이 보이지 않는다.
실제 화면에는 8월 결석 보강만 표시된다.

오류 B.
학생 반이동에서 “다음 달부터 이동”을 선택하면
학생 상세에는 연기 상태로 표시되지만,
실제 현재 달 수업 명단에는 계속 학생이 노출된다.
즉 연기 상태와 반 명단 적용이 일치하지 않는다.

이번 작업은 두 오류를 한 번에 조사하고,
직접 원인이 코드·데이터로 확정되면 최소 수정까지 진행한다.

Push / Render / OTA / 운영 DB 수동 수정은 최종 검수 후 별도 승인 전 금지한다.

1. 실제 제보 교사 계정 확인

확인:

- original_teacher_id
- handed_to_teacher_id
- co_teacher_ids
- 7월 expired 중 유지훈 교사가 볼 수 있어야 하는 row 수

개인정보는 보고서에서 마스킹한다.

2. 운영 DB 실제 대상 row 조회

SELECT
  id,
  student_id,
  student_name,
  absence_date,
  status,
  expire_at,
  original_teacher_id,
  handed_to_teacher_id,
  original_class_group_id,
  swimming_pool_id,
  cancelled_at
FROM makeup_sessions
WHERE swimming_pool_id = :poolId
  AND absence_date >= '2026-07-01'
  AND absence_date < '2026-08-01'
  AND status IN ('waiting', 'expired')
ORDER BY absence_date ASC;

제출:

- 전체 건수
- expired 건수

4. 연기 상태 의미 확인

Repository 전체에서 student.status='postponed' 또는 '연기'를 검색한다.

확인:

- 연기 학생을 수업 명단에서 제외해야 하는지
- 연기 상태는 단순 표시용인지
- 연기 시작일/종료일이 있는지
- 현재 달 수업은 유지하고 다음 달부터 제외하는 정책인지
- 다음 달 이동 대상 반은 언제 반영하는지

7. 정책에 맞는 최소 수정

정책은 다음과 같이 일관되어야 한다.

“다음 달부터 이동” 선택 시:

- 이번 달 마지막 수업까지 기존 반에서 정상 노출
- 다음 달 1일부터 기존 반 명단에서 제외
- 다음 달 1일부터 새 반 명단에 포함
- 학생 상세는 ‘이동 예정’ 또는 정확한 예약 상태로 표시
- 단순 ‘연기’ 상태로 즉시 바꾸어 현재 상태와 모순되지 않게 함

현재 제품 정책이 정말 ‘연기’ 상태를 사용해야 한다면:

- 연기 시작일이 다음 달 1일로 저장되어야 함
- 명단 API도 수업일 기준으로 연기 시작일 이후 제외해야 함

둘 중 기존 설계와 맞는 하나만 사용한다.

임의로 status만 바꾸는 방식 금지.
