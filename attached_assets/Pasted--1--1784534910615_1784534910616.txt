1. today-schedule.ts 반 카드 수강생 수 수정

studentCountMap을 students.status,
class_group_id,
assigned_class_ids 기준으로 계산하지 마세요.

조회 날짜에 유효한 student_class_history 기준으로 계산하세요.

필수 조건:

h.swimming_pool_id = 수영장ID
AND h.class_group_id = 반ID
AND h.enrolled_at <= 조회날짜
AND (h.left_at IS NULL OR h.left_at > 조회날짜)
AND s.deleted_at IS NULL

반 카드의 “총 n명” 숫자와
실제 학생 상세 목록의 인원은
항상 같은 날짜 기준으로 일치해야 합니다.

기존 status 및 assigned_class_ids 기반 계산은 제거하세요.

2. attendance.ts 주간·월간 계산 방식 추가 검증

현재 조건:

주간:
h.enrolled_at <= endDate
AND (h.left_at IS NULL OR h.left_at > startDate)

월간:
h.enrolled_at <= monthEnd
AND (h.left_at IS NULL OR h.left_at > monthStart)

이 조건은 기간 중 하루라도 소속된 학생을
후보로 조회하는 기간 겹침 조건입니다.

후보 조회 용도로는 사용할 수 있지만,
다음 통계를 이 조건만으로 계산하면 안 됩니다.

- 예정 수업 수
- 출석 수
- 결석 수
- 출석률
- 수업 참여 횟수
- 반별 인원 집계

다음 내용을 실제 코드 기준으로 다시 확인해 보고하세요.

1. 각 수업 날짜마다
   h.enrolled_at <= 수업날짜
   AND (h.left_at IS NULL OR h.left_at > 수업날짜)
   조건을 다시 적용하는지

2. 첫 수업일 이전 날짜가 결석으로 계산되지 않는지

3. left_at 당일과 이후 날짜가 결석으로 계산되지 않는지

4. 기간 중 반 이동한 학생이 이전 반과 새 반에 중복 집계되지 않는지

5. 기간 중간에 등록한 학생의 이전 날짜가 예정 수업으로 계산되지 않는지

6. 기간 중간에 연기·퇴원한 학생의 이후 날짜가 예정 수업으로 계산되지 않는지

7. 기간 겹침 조건이 단순 후보 조회에만 사용되고,
   최종 통계는 실제 수업 날짜별로 계산되는지

코드 일부가 아니라
주간·월간 출결 결과를 만드는 전체 흐름을 확인하세요.

3. parent.ts 학부모 일지 날짜 필터 재검증

현재 제시한 조건:

WHERE ps.parent_id = parentId
AND ps.status = 'approved'

이 조건은 학부모와 학생의 연결 승인 상태만 확인합니다.

해당 일지 날짜에
학생이 실제 그 반에 소속되어 있었는지 판정하는 조건이 아닙니다.

따라서 “학부모 일지는 history 기반”이라는 결론은
현재 제시된 코드만으로 확인되지 않았습니다.

학부모 일지 조회 전체 쿼리에서 다음 조건이 실제로 존재하는지 확인하세요.

- 일지의 lesson_date
- 해당 날짜의 student_class_history
- 해당 학생
- 해당 반
- enrolled_at <= lesson_date
- left_at IS NULL OR left_at > lesson_date
- s.deleted_at IS NULL

즉,

현재 연결된 학생이라는 이유만으로
등록 전 일지,
연기 기간 일지,
퇴원 이후 일지,
다른 반 소속 기간의 일지가 보이면 안 됩니다.

학부모 출결 조회도 같은 방식으로 확인하세요.

==================================================

4. diary.ts 푸시 알림도 날짜 기준 검토 필요

보고서에서는 diary.ts의 푸시 알림 쿼리를
날짜 판정과 무관하다고 분류했습니다.

하지만 일지 업로드 시
현재 반에 연결된 학부모 전체에게 알림을 보내는 구조라면,

수업일 당시에는 소속되지 않았던 학생,
이미 연기·퇴원한 학생,
반 이동한 학생의 학부모에게
잘못된 알림이 갈 수 있습니다.

따라서 다음을 확인하세요.

- 푸시 대상이 현재 students.class_group_id 기준인지
- 해당 일지의 lesson_date 기준 history 유효 학생만 대상으로 하는지
- 과거 일지 수정 시 현재 반 학생들에게 잘못 발송되지 않는지

일지 내용 조회와 별개로,
푸시 발송 대상도 수업 날짜 기준이어야 합니다.
