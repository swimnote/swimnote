SWIMNOTE 앱 수정 작업 지시

이번 작업은 AI Engine이 아니라 SWIMNOTE 앱 및 기존 앱 서버 작업입니다.

두 문제 모두 화면에서 임시 필터링하지 말고,
실제 데이터 조회·저장·발송 경로를 끝까지 추적한 뒤
근본 원인을 수정하십시오.

추측으로 파일을 수정하지 마십시오.
먼저 현재 구현 경로와 관련 파일을 찾아 보고한 후 작업하십시오.

==================================================
작업 1. 해당 수업일 결석자는 전체일지 발송 대상에서 제외
==================================================

요구사항

특정 날짜의 특정 반에서 결석 처리된 학생은
그 날짜에 작성하는 ‘전체일지’의 발송 대상에서 자동 제외되어야 합니다.

예시

2026-07-31 A반

출석
- 김민수
- 이서준

결석
- 박태웅

전체일지 작성 및 발송 시

김민수, 이서준에게만 발송되고
박태웅에게는 해당 일지가 생성·저장·전송되지 않아야 합니다.

중요 조건

1. 학생의 일반 재원 상태가 아니라
   해당 날짜·해당 수업의 출결 상태를 기준으로 판단합니다.

2. 결석뿐 아니라 현재 출결 DB에서 실제 사용하는 상태값을 확인하십시오.

예:
- absent
- absence
- ABSENT
- 결석
- excused_absence
- no_show

상태값을 임의로 가정하지 말고 현재 스키마와 실제 저장값을 확인합니다.

3. 전체일지 작성 화면에서만 숨기는 것으로 끝내지 마십시오.

다음 모든 단계에서 결석자가 제외되어야 합니다.

- 전체일지 학생 목록 생성
- AI 일지 요청의 students 배열
- 일지 저장 대상
- 학부모 발송 대상
- 알림 푸시 대상
- 학생별 diary 레코드 생성 대상

4. 프론트 필터와 서버 검증을 모두 적용하십시오.

프론트:
- 결석 학생이 전체일지 대상 목록에 나타나지 않도록 처리

서버:
- 앱에서 잘못 포함되어 요청되더라도
  해당 날짜 결석 학생에게는 일지가 저장·발송되지 않도록 최종 검증

5. 이미 개별 일지가 작성된 뒤 출결을 결석으로 변경하는 경우의
현재 정책도 확인하십시오.

이번 요구사항의 최소 기준은
‘발송 시점에 해당 날짜 결석 상태이면 발송 제외’입니다.

구현 전 반드시 추적할 경로

출결 저장
→ 날짜별 반 출결 조회
→ 전체일지 작성 대상 조회
→ AI 생성 요청 students 구성
→ 일지 저장 API
→ 학부모 노출 및 푸시 발송

관련 테이블, API, 훅, 서비스, 화면 파일을 모두 찾아
실제 연결 경로를 먼저 보고하십시오.

==================================================
작업 2. 한 반에 선생님 2명 등록 시 일지작성 개별목록 누락 수정
==================================================

현상

한 반에 선생님이 2명 등록된 경우

- 다른 반 기능은 정상 작동
- 일지작성 화면 진입도 가능
- 그러나 일지작성 목록 화면에 학생 개별목록이 나타나지 않음

요구사항

한 반에 담당 선생님이 1명 또는 여러 명 등록되어도
해당 반에 배정된 모든 선생님에게 동일하게
일지작성 학생 개별목록이 표시되어야 합니다.

주의

교사가 두 명인 상황을
단일 teacher_id 비교로 처리하면 안 됩니다.

잘못된 가능성이 높은 형태:

class.teacherId === currentTeacherId

또는

WHERE class.teacher_id = ?

현재 구조가 다대다 관계라면 반드시
반-선생님 연결 테이블을 기준으로 권한과 목록을 조회해야 합니다.

예시 구조

classes
teachers
class_teachers 또는 teacher_class_assignments

조회는 다음 의미가 되어야 합니다.

현재 로그인 교사가
해당 반 담당 교사 목록 중 한 명이면
그 반의 학생 목록을 조회할 수 있다.

반드시 확인할 부분

1. 반 상세 화면에서 사용하는 교사 권한 경로
2. 일지작성 목록 화면에서 사용하는 반 조회 경로
3. 학생 개별목록 API의 teacher 조건
4. 프론트에서 teacherId 하나만 비교하는 필터
5. 배열과 단일 값 혼용
6. INNER JOIN 때문에 중복 또는 누락되는지
7. 두 명 등록 시 class 객체 구조가 달라지는지
8. 담당 교사 첫 번째 항목만 허용하는 코드가 있는지
9. 운영자와 선생님 역할별 조회 조건 차이
10. 센터 및 반 tenant 격리가 유지되는지

수정 원칙

- 주 담당 교사와 보조 담당 교사를 구분하는 정책이 없다면 둘 다 동일 권한
- 두 교사 모두 학생 개별목록 조회 가능
- 학생 목록은 중복 없이 한 번씩만 표시
- 한 명만 등록된 기존 반도 회귀 없이 정상
- 운영자는 기존처럼 전체 접근 가능
- 다른 센터 교사는 접근 불가

테스트 필수
==================================================

문제 1 테스트

A. 출석 학생 2명 + 결석 학생 1명
→ 전체일지 대상 2명

B. 결석 학생이 AI 요청 students에 포함되지 않음

C. 조작된 요청으로 결석 학생을 포함
→ 서버에서 저장·발송 차단

D. 출석 상태 변경 후 발송
→ 발송 시점 상태 반영

E. 다른 날짜에는 출석한 학생
→ 다른 날짜 일지에는 정상 포함

F. 푸시 알림도 결석자 제외

문제 2 테스트

A. 담당 교사 1명
→ 기존처럼 목록 표시

B. 담당 교사 2명
→ 두 교사 모두 동일 학생 목록 표시

C. 두 번째로 등록된 교사 로그인
→ 목록 정상 표시

D. 학생 중복 표시 없음

E. 담당하지 않은 교사
→ 접근 불가

F. 운영자
→ 정상 조회

G. 다른 센터 교사
→ 접근 불가
