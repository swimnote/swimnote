학부모 로그인 화면에서 "카카오 로그인"이 안 된다는 실제 사용자 제보가 있다.

이번에는 단순히 버튼/딥링크/UI만 보지 말고
1.6.3 운영 버전과 2.0.0 개발 버전 모두에서
카카오 로그인 전체 E2E 흐름을 조사해서
정확한 root cause를 확정하고 재발하지 않게 공통 구조로 수정한다.

중요:
- 추측으로 수정하지 말 것.
- 실제 코드 + 서버 로그 + 카카오 OAuth 응답 + 앱 딥링크/redirect + DB 계정 연결까지 확인할 것.
- 1.6.3과 2.0.0 둘 중 하나만 고치고 끝내지 말 것.
- 공통 backend/auth contract를 우선 수정하고, 앱별 차이가 있으면 각각 명확히 처리할 것.
- Production 개인정보, access token, refresh token, authorization code, client secret를 완료보고/로그에 원문으로 출력하지 말 것.
- 사용자 승인 없이 1.6.3 OTA 금지.
- Android OTA 금지.
- 2.0.0은 필요 시 iOS OTA 여부만 보고.

2. 반드시 실제 실패지점부터 확인
==================================================

"카카오 로그인이 안 된다"는 표현만 보고 UI 문제로 단정하지 않는다.

아래 단계 중 정확히 어디서 실패하는지 확정한다.

A. 카카오 로그인 화면 자체가 열리지 않음
B. 카카오 인증은 성공했는데 앱으로 돌아오지 않음
C. 앱으로 돌아왔지만 authorization code가 없음
D. code는 받았지만 서버 token exchange 실패
E. Kakao access token은 받았지만 profile 조회 실패
F. profile은 받았지만 parent account lookup/create 실패
G. parent account는 만들었지만 student/pool 연결 실패
H. JWT/session 저장 실패
I. 로그인 성공했지만 화면 전환 실패
J. 앱 재실행 시 세션이 사라짐

실제 로그와 코드 흐름으로 실패 단계 하나 이상을 확정한다.

5. redirect URI / deep link 완전 검증
==================================================

카카오 로그인 장애에서 가장 흔한 영역이므로 반드시 확인한다.

확인:

- 서버 callback URL
- iOS custom scheme

- TestFlight/Production build 차이
- URL encoding
- trailing slash
- http/https
- host/path 대소문자
- state parameter

등록값과 실제 runtime 값을 정확히 비교한다.

redirect mismatch가 있으면
운영/개발 환경이 섞이지 않게 환경별 상수/설정으로 정리한다.

6. Kakao token exchange 검증
==================================================

서버에서 확인:

- grant_type=authorization_code
- client_id
- redirect_uri
- code
- client_secret 필요 여부
- request content-type
- timeout

- 400/401/KOE code

- HTTP status

token/code/secret은 남기지 않는다.

7. Kakao profile/account linking 검증
==================================================

Kakao profile 조회 후
다음을 확인한다.

- kakao_user_id를 영구 external identity로 사용하고 있는지
- email이 항상 온다고 가정하고 있지 않은지
- email consent 미동의 시 가입이 깨지는지
- phone_number가 항상 있다고 가정하는지
- nickname/profile image 누락 시 깨지는지
- Kakao API scope 변경으로 null이 들어와도 안전한지

중요:
카카오 로그인 계정 식별은
email 하나에만 의존하지 말고
kakao_user_id를 1차 external identity로 사용해야 한다.

기존 parent와 연결할 때는:
1. kakao_user_id existing link
2. 없으면 명확한 verified matching policy
3. 중복 계정 생성 방지

이 순서로 확인한다.

8. 기존 일반 로그인 parent와 카카오 연동
==================================================

기존 parent가 전화번호/일반 로그인으로 이미 존재하는 경우
카카오 로그인 첫 사용에서 중복 parent_account가 생기면 안 된다.

확인:
- 동일 전화번호
- 동일 email
- 기존 student links
- same pool membership

정책을 코드로 명확히 한다.

가능하면:
기존 parent 확인
→ Kakao external identity link
→ 기존 child relation 유지
→ JWT 발급

중복 parent_account 생성 금지.

9. 형제/자녀 연결 회귀
==================================================

이번에 수정 중인 parent-register 형제 연결 로직과
카카오 로그인 flow가 충돌하지 않는지 반드시 확인한다.

케이스:
1. Kakao 신규 parent + 첫 자녀
2. Kakao 기존 parent + 같은 pool 두 번째 자녀
3. Kakao 기존 parent + 세 번째 자녀
4. 일반 로그인 parent가 Kakao 연동 후 기존 자녀 유지
5. Kakao 계정이 이미 있는데 child relation만 추가

same pool membership 때문에 409가 재발하면 안 된다.

개발 로그에서는 정확한 단계가 식별되어야 한다.

취소는 오류처럼 처리하지 않는다.

- 로그인 버튼 연속 탭
- authorization code 중복 전송
- 서버 token exchange 중복
- 앱 foreground 복귀 시 callback 두 번 처리

- 서버 5xx

정책:

- authorization code 재사용 금지
- 네트워크 transient failure는 안전한 범위에서만 retry
- 사용자 취소는 retry하지 않음
