2. Teacher 출결 UX
━━━━━━━━━━━━━━━━━━━━━━

목표:

수업 대상 학생은 기본적으로 "출석"으로 간주.

선생님은 결석 학생만 표시하면 됨.

기존 구조상 모든 학생의 present row 저장이 필수라면
DB 구조를 새로 바꾸지 말고
UI/서버 최소 변경으로 동일 UX를 만든다.

필수:

- 결석 지정 가능
- 결석 취소/출석 복원 가능
- 과거 수업도 합리적인 범위에서 결석 정정 가능
- 저장 중복 방지

불필요한 새 출석 시스템 생성 금지.

6. 보강 완료 → 대기 제거
━━━━━━━━━━━━━━━━━━━━━━

가장 중요.

선생님이 실제 보강 수업을 완료하면:

- 해당 makeup/entitlement 식별
- 상태 완료/사용 처리
- 재사용 불가
- pending count 감소
- 관리자 보강 대기 목록에서 제거 또는 완료 탭으로 이동
- teacher 화면도 즉시 최신 상태 반영

현재 이 연결이 끊겨 있으면 최소 수정.

"결석 소멸"과 "보강 완료"를 동일 상태로 뭉개지 말 것.

각 의미를 기존 canonical status에 맞게 유지.
