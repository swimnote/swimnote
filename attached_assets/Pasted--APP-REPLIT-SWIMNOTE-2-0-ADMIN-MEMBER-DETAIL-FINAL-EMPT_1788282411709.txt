0. 문제
==================================================

완료보고에서는:

Admin Member Detail
Basic edit background dismiss:
PASS

라고 보고했으나,

근거가:

ScrollView
keyboardDismissMode="on-drag"

뿐입니다.

이것은:

"스크롤하면 키보드 dismiss"

이지

"빈 배경을 tap하면 keyboard dismiss"

가 아닙니다.

사용자 고정 UX 규칙:

TextInput tap
→ keyboard visible

Button / Pressable / CTA tap
→ 첫 tap으로 action 실행

빈 화면 / 비활성 배경 tap
→ Keyboard.dismiss()

Scroll drag
→ Keyboard.dismiss()

입니다.

==================================================

첫 tap은 keyboard dismiss만 되고
두 번째 tap에 action 실행.

3. 권장 구현 원칙
==================================================

실제 구조를 보고
가장 안전한 방식으로 구현.

조건:

- TextInput 영역 tap → focus 유지
- Save tap → 첫 tap save
- Cancel tap → 첫 tap cancel
- Picker / Level / Class action → 첫 tap 실행
- Section header button → 첫 tap 실행
- 빈 content background → Keyboard.dismiss()
- scroll drag → 기존 on-drag dismiss 유지

가능하면
interactive content와 background dismiss layer를
명확히 분리.
