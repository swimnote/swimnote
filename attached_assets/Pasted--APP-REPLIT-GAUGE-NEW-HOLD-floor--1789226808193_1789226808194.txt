HOLD

계산식, 레벨 floor 정책, 하위복습 제외, 단조증가 방식은 승인합니다.

━━━━━━━━━━━━━━━━━━━━━━

1. 핵심 문제
   ━━━━━━━━━━━━━━━━━━━━━━

이전 Production 조사 기준 ToyKids 실질 재원 중
current_level_order가 설정된 학생은:

L1 = 5
L2 = 21
L3 = 28
L4 = 2
L5 = 3

총 59명이었습니다.

그런데 이번 backfill 보고는:

총 53명

이며 대상 조건도:

`current_level_order IS NOT NULL + 기존 SCP row 존재`

입니다.

GAUGE-NEW의 가장 중요한 원칙은:

"선생님이 레벨을 설정하면
일지/CPO가 없어도 해당 레벨 floor가 반드시 보인다"

입니다.

따라서 기존 SCP row가 없는 학생이
게이지 적용에서 빠지면 안 됩니다.

━━━━━━━━━━━━━━━━━━━━━━
2. 해야 할 일
━━━━━━━━━━━━━━━━━━━━━━

현재 ToyKids 실질 재원 중:

`current_level_order IS NOT NULL`

인 학생 전체를 다시 조회하십시오.

그리고 다음 두 그룹을 구분하십시오.

A.
SCP row 존재

B.
SCP row 없음

B가 존재한다면,
해당 학생도 최소한 현재 레벨 floor를 가진
`student_curriculum_progress` row가 생성되도록 처리하십시오.

예:

L1 → 0%
L2 → 20%
L3 → 35%
L4 → 50%
L5+ → 65%

CPO / 일지가 전혀 없어도 상관없습니다.

레벨 자체가 floor의 Source of Truth입니다.

━━━━━━━━━━━━━━━━━━━━━━
3. 복잡하게 만들지 말 것
━━━━━━━━━━━━━━━━━━━━━━

새로운 scoring,
새로운 상태값,
새로운 보간,
새로운 curriculum 분석

추가 금지.

단순히:

current_level_order 있음
→ SCP 없으면 생성
→ gauge_pct = 해당 level floor

이면 충분합니다.

기존 SCP가 있으면 현재 계산 로직 그대로 사용하십시오.

━━━━━━━━━━━━━━━━━━━━━━
4. level PATCH도 확인
━━━━━━━━━━━━━━━━━━━━━━

앞으로 처음으로 레벨을 설정하는 학생에게
SCP row가 아직 없어도:

PATCH level
→ SCP row 생성 또는 UPSERT
→ gauge_pct = 해당 level floor
→ 응답

이 정상 동작해야 합니다.

즉 기존 SCP 존재를 전제로 만들면 안 됩니다.

teacher/admin 두 PATCH 모두 확인하십시오.

━━━━━━━━━━━━━━━━━━━━━━
5. 최종 Runtime 검증
━━━━━━━━━━━━━━━━━━━━━━

수정 후 Production에서 개인정보 없이 count만 제출하십시오.

* 실질 재원 current_level_order != null 학생 수
* 그중 SCP row 보유 학생 수
* 그중 gauge_pct NOT NULL 학생 수
* level별 학생 수
* level별 gauge floor 미만 학생 수

최종 조건:

# `level 설정 학생`

# `SCP 보유 학생`

`gauge_pct 존재 학생`

이어야 합니다.

그리고:

L1 gauge < 0      → 0건
L2 gauge < 20     → 0건
L3 gauge < 35     → 0건
L4 gauge < 50     → 0건
L5+ gauge < 65    → 0건

이어야 합니다.
