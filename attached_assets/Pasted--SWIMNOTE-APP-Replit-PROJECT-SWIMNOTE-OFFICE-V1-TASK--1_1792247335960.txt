[전달 대상: SWIMNOTE APP Replit]

PROJECT = SWIMNOTE OFFICE V1
TASK = 기존 실행 버전 기준으로 기능 통합·완성 실행본 제작

최우선 원칙:
기존 앱·PC 구현을 최대한 재사용하고,
최소 변경으로 설치·실행 가능한 프로그램부터 완성한다.
완성 실행본에서 발견한 문제는 이후 수정한다.

1. 현재 우회 작업 중단

별도 로컬 PostgreSQL·격리 서버·합성 인증·검증 전용
설치본·추가 진단 환경 제작을 중단한다.

기존 작업·소스·후보·로그·증거는 보존한다.
삭제·reset·checkout으로 되돌리지 않는다.
검증 전용 환경의 DB 시작 오류를
제품 개발의 선행 조건으로 삼지 않는다.

2. 기존 정상 실행 버전에서 이어서 진행

기존에 설치·실행됐던 OFFICE 제품의
source·서버 연결·인증·빌드·패키징 경로를 확인한다.

현재 작업을 보존한 상태에서 그 제품 경로를 기준으로
이미 완성한 AI 레이아웃과 Stage 3 구현을 연결한다.
과거 버전으로 무조건 복원하거나 최신 기능을 버리지 않는다.

기존 실행본 식별과 차이 확인은 필요한 범위만 짧게 수행.
조사 보고만 하고 멈추지 말고 구현·빌드까지 이어간다.

3. 재사용 우선

이미 앱에 구현돼 사용하던 기능·API·인증·DB 계약을 우선 재사용.
이미 만든 PC 화면·공통 Action·상태 관리도 재사용한다.

- 동일 기능 재개발 금지.
- 완료한 레이아웃 재설계 금지.
- 별도 테스트용 업무 시스템 제작 금지.
- PC에 서버·DB를 새로 설치시키는 구조 추가 금지.
- 검증 목적으로 제품 범위를 확대하지 않음.

기존 증거와 검증 결과는 재사용한다.
PC 통합에서 실제 달라진 부분만 확인한다.

4. 당장 완성할 기능

현재 합의한 OFFICE V1 범위와 기존 구현을 기준으로
빠진 연결·동작을 완성한다.

이번 Stage 3의 우선 연결:
- AI 자연어 회원 검색.
- 지원하는 회원정보 수정.
- 지정 소속 반이동.
- 기존 AI 작업 카드·처리 결과·결과 보기.
- 기존 확인·권한·중복 실행 방지·충돌 처리 유지.

기존 회원관리·일반 편집·반이동 화면과 같은
실제 업무 경로를 사용한다.
이미 완성한 부분을 다시 만들지 않는다.

새 기능·새 단계·새 아키텍처를 임의 추가하지 않는다.
미지원 요청을 지원하는 것처럼 표시하지 않는다.

5. 서버 연결

기존 정상 실행 프로그램의 실제 서버 연결 방식을 사용한다.
검증용 localhost API·DB·가짜 계정·응답 재생을
일반 제품 실행본에 포함하지 않는다.

기존 API로 가능한 통합은 바로 진행한다.
서버 변경이 필요한 부분은 이미 만든 서버 후보를 검토해
필요한 변경만 추린다.

서버 배포·schema 적용이 기존 승인 범위에 있으면 그 범위대로 진행.
별도 승인이 필요한 경우에는:
- 필요한 변경·영향·적용/복구 방법을 구체적으로 준비.
- 해당 부분 외 클라이언트 통합·빌드·패키징은 계속 진행.
- 승인되지 않은 운영 변경을 몰래 적용하지 않음.
- 미연결 기능을 완료했다고 보고하지 않음.

6. 테스트는 변경 범위에 맞춰 최소 수행

필수 빌드와 변경 부분의 직접 관련 검사만 수행한다.
기존 전체 suite·검증 완료 항목을 반복하지 않는다.
새 검증 환경 구축을 종료 조건으로 추가하지 않는다.

실행본 제작을 막는 오류는 수정한다.
나머지 실제 사용 문제는 실행본에서 확인해 후속 수정한다.
인증·권한·데이터 보호를 제거해서 빌드만 통과시키지 않는다.

Windows에서 직접 실행하지 않았다면 그 사실만 명시한다.
이를 이유로 설치 파일 제작 자체를 반복 보류하지 않는다.

7. 실제 실행 파일 전달

기존 Windows 설치본 제작 방식을 재사용해
일반 사용자가 설치·실행할 수 있는 EXE를 만든다.

사용자에게 요구할 작업:
다운로드 → 설치 → 실행 → 화면/오류 전달.

사용자에게 Node·pnpm·PostgreSQL 설치,
소스 빌드·PowerShell 명령을 요구하지 않는다.

소스 ZIP·계획서·검증 도구만 전달하고 종료하지 않는다.
전달 용량 제한이 있으면 기존 방식으로 분할하되
최소 조작으로 설치할 수 있게 한다.

8. 범위와 보존

모바일·AI ENGINE은 이번 작업 때문에 변경하지 않는다.
기존 제품·데이터를 삭제하지 않는다.
기존 commit/push·운영 배포 승인 경계를 유지한다.
Windows 제품 실행본 빌드·패키징·사용자 전달은 진행한다.

9. 완료 보고 — 짧게

- 기준으로 사용한 기존 실행 버전.
- 재사용한 기능과 이번에 연결·수정한 부분.
- 설치 파일 다운로드·파일명·해시.
- 실제 연결된 기능과 남은 제한.
- 직접 수행한 빌드·최소 검사.
- 사용자 실행 방법.
- 운영 적용이 필요해 남은 항목.

목표는 검증 환경 완성이 아니라
기존 제품을 이어 만든 실제 OFFICE 실행본 전달이다.
