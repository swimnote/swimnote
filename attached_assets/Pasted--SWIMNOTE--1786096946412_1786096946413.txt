[SWIMNOTE 보강 기능 — 실패 시 강제 복구 기준서]

중요:

이 문서는 지금 즉시 새 작업을 시작하라는 지시가 아닙니다.

현재 진행 중인 보강 복구/배포/실기기 검증 결과를 먼저 확인합니다.

만약 이번 실기기 검증에서 보강 기능이 정상적으로 복구되지 않았다면,
그때부터 아래 내용을 “정상 기능 기준”으로 사용하여 다시 복구합니다.

절대 새로 설계하지 마십시오.

이번에도 안 되면:

“다른 방식으로 만들어보겠다”
“UI를 새로 바꾸겠다”
“API 구조를 다시 설계하겠다”
“DB를 맞추겠다”

같은 접근을 금지합니다.

아래 기능은 이미 구현·검증했던 기능입니다.

1. 실패 판정 조건
━━━━━━━━━━━━━━━━━━━━━━

이번 Production 실기기에서 아래 중 하나라도 실패하면
보강 복구 미완료로 판정합니다.

- 보강 대기 목록 정상 표시 실패
- 기간 지난 보강 표시 실패
- 실제 수업 회차 표시 실패
- 오늘/과거/미래 구분 실패
- 보강반 선택 실패
- 미래 보강 예약 실패
- 오늘/과거 보강 완료 실패
- 직접 완료 실패
- 날짜 undefined/누락
- 다른 반 선택 실패
- 빠른 반 전환 시 이전 응답 혼입
- 만석 처리 정책 오류
- 다른 수영장 반 접근 가능
- 기존 완료/인계/소멸 기능 회귀

하나라도 실패하면
“부분 성공”으로 완료 처리하지 않습니다.

━━━━━━━━━━━━━━━━━━━━━━
2. 실패 시 절대 기준 기능
━━━━━━━━━━━━━━━━━━━━━━

복구 대상 정상 기능은 다음 전체입니다.

- 보강반 실제 수업 회차 선택
- 오늘·과거·미래 회차 구분
- 미래 보강 예약
- 오늘·과거 사후 완료
- 정원 마감 미래 회차 서버 차단
- 오늘·과거 정원 초과 경고 후 처리
- complete-direct 서버 회차 검증
- occurrence_date 필드 통일
- occurrence 요청 race condition 방지
- 직접 완료 기능의 실제 반·실제 회차 선택 방식 통합
- /teacher/makeups/by-class 수영장 권한 검증
- /teacher/makeups/by-class 날짜 형식 검증
- 기간 지난 보강 표시
- expired 보강 표시
- 기존 배정/완료/인계/소멸 유지

이 기능들을 새로 설계하지 않습니다.

기존 정상 구현을 찾아 그대로 복구합니다.

━━━━━━━━━━━━━━━━━━━━━━
3. 정상 구현 기준점
━━━━━━━━━━━━━━━━━━━━━━

복구 기준으로 사용할 기존 작업 상태:

d73d8e4f

6 commits

branch:
hotfix/makeup-expiry-scroll-f928659a

8947422b

보강 기간 계산 기준 hotfix:

hotfix/makeup-date-range-clean

SHA:
1c0df48aa7345ac976876712b00602bf452e7045

하나의 SHA만 무조건 정상본이라고 가정하지 마십시오.

기능별 정상본을 실제 Git history와 당시 검증 보고 기준으로 찾아 비교합니다.

5. 복구 방식
━━━━━━━━━━━━━━━━━━━━━━

→ 실패 기능에 필요한 코드만 추출

→ Push
→ 서버 먼저 배포

→ Production OTA
→ 실기기 검증

입니다.

관련 없는 코드 정리 금지.
