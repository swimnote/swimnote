[긴급 수정 — 로그인 HTTP 403 비JSON 응답 직접 원인 확정 및 복구]

현재 로그인 화면:

Unexpected response (HTTP 403)

확정 사실:

- safeJson()이 response body JSON 파싱에 실패함
- 실제 서버 응답은 HTTP 403
- 기존 조사는 틀린 비밀번호로 401만 재현했으므로 실제 장애를 재현하지 못함
- “구버전 앱 문제” 판정은 증거 없으므로 폐기

이번 작업은 실제 운영 로그인 403을 재현하고 직접 원인을 수정한다.

━━━━━━━━━━━━━━━━━━━━━━
STEP 1. 기능 수정 즉시 금지 상태에서 실제 403 확보
━━━━━━━━━━━━━━━━━━━━━━

앱이 사용하는 정확한 URL:

POST https://swimnote-api.onrender.com/api/auth/unified-login

실제 toykids 운영 계정의 올바른 비밀번호로 요청한다.
비밀번호는 로그와 보고서에 절대 출력하지 않는다.

curl 예시:

curl -i -sS \
  -X POST \
  -H "Content-Type: application/json" \
  --data '{"identifier":"toykids","password":"<MASKED>"}' \
  "https://swimnote-api.onrender.com/api/auth/unified-login"

제출:

- HTTP status
- Content-Type
- response headers
- response body 원문
- body byte length
- JSON parse 성공 여부

틀린 비밀번호 테스트로 대체 금지.

STEP 3. 라우트 이전 미들웨어 전부 조사

app.ts에서 /api/auth/unified-login보다 먼저 실행되는 모든 middleware를 순서대로 제출한다.

특히 다음을 전체 원문으로 확인:

- requireNotDeactivated

- WAF/보안 middleware
- body parser
- proxy 관련 처리
- app.use("/api", ...)

- SPA fallback

requireNotDeactivated가 /api/auth/unified-login에도 적용되는지 확인한다.

확인 항목:

- 로그인 전 토큰이 없는 요청을 어떻게 처리하는가
- pool을 어떤 값으로 찾는가
- 차단 시 res.json인지 res.send인지
- next()가 호출되지 않는 분기
- 403을 반환하는 모든 분기
- 빈 body 또는 문자열 body를 반환하는지

STEP 6. 직접 원인별 최소 수정
━━━━━━━━━━━━━━━━━━━━━━

A. requireNotDeactivated가 로그인 요청을 차단하는 경우

공개 인증 경로를 미들웨어 검사에서 제외한다.

최소 제외 대상:

- /api/auth/unified-login
- /api/auth/login
- 회원가입·비밀번호 재설정 등 인증 전 공개 경로

단, 보호 API는 기존 차단 유지.

B. middleware가 비JSON 403을 반환하는 경우

모든 API 오류는 JSON으로 통일:

res.status(403).json({
  success: false,
  error: "<CODE>",
  error_code: "<CODE>"
});

HTML, plaintext, empty body 금지.

C. DB의 deactivated_at이 잘못 설정된 경우

코드 수정과 분리한다.
운영 DB 복구는 변경 원인과 감사 로그를 먼저 제출하고 별도 승인 전 금지.

D. 프록시/WAF가 반환하는 경우

Render 직접 주소에서 정상이고 swimnote.kr만 실패한다면
프록시 설정 문제로 확정한다.
앱 API_BASE는 Render 주소 유지.

STEP 7. 회귀 테스트
━━━━━━━━━━━━━━━━━━━━━━

반드시 실제 운영 경로로 검증:

1. 올바른 toykids 계정
   → HTTP 200
   → 로그인 성공

2. 틀린 비밀번호
   → HTTP 401 JSON
   → wrong_password

3. 비활성 수영장
   → HTTP 403 JSON
   → pool_deactivated

4. 승인 대기 계정
   → HTTP 403 JSON
   → 명시적 error_code

5. 앱 로그인 화면
   → Unexpected response 문구 없음

6. 기존 보호 API
   → 비활성 수영장 접근 차단 유지
