[SWIMNOTE 보강반 선택 실패 — 실제 실패 데이터·응답 확보 지시]

현재까지 코드 검토 결과:

- GET /teacher/makeups/:makeupId/eligible-occurrences 라우트는 존재함
- class_group_id 전달 구조는 정상임
- validateMakeupOccurrence는 회차 조회 API가 아니라 assign/complete-direct 단계에서 사용되므로 현재 실패와 직접 관련 없음
- calcExpireAt도 회차 조회 실패 원인 아님
- db와 superAdminDb는 동일 DB 인스턴스를 사용함
- 현재 남은 핵심은 실제 실패 요청의 makeupId, class_group_id, userId, HTTP status, response body 확인임

이번 작업은 수정하지 말고 실제 실패 데이터를 확보한다.

2. 실제 실패 HTTP 응답 확보
━━━━━━━━━━━━━━━━━━━━━━

실패 요청:

GET /teacher/makeups/:makeupId/eligible-occurrences
  ?class_group_id=:classGroupId

반드시 제출:

- 전체 요청 경로
- HTTP status
- response body 원문
- 요청 시각
- request_id가 있으면 포함

가능한 응답 예:

403 / POOL_NOT_FOUND
403 / MAKEUP_POOL_MISMATCH
404 / CLASS_NOT_FOUND
500 / ELIGIBLE_OCCURRENCES_FAILED
503 / DB_CONNECTION_LIMIT
200 / occurrences: []

HTTP status와 response body를 확보하지 못하면 원인 확정이라고 쓰지 않는다.

7. eligible-classes와 eligible-occurrences 조건 비교
━━━━━━━━━━━━━━━━━━━━━━

다음 두 라우트의 class_groups WHERE 조건을 나란히 제출한다.

A.

GET /teacher/makeups/eligible-classes

B.

GET /teacher/makeups/:makeupId/eligible-occurrences

비교 항목:

- swimming_pool_id
- is_deleted
- is_one_time
- teacher_user_id
- co_teacher_ids
- handed_to_teacher_id
- capacity
- student count
- role/mineOnly 필터

eligible-classes에는 표시되지만
eligible-occurrences에서는 CLASS_NOT_FOUND가 될 수 있는 조건 차이가 있는지
코드 원문 기준으로 표시한다.

판정은 다음 중 하나로만 작성한다.

- 조건 동일
- 조건 불일치 있음
- 확인 불가

8. schedule_days 실제 파싱 검증
━━━━━━━━━━━━━━━━━━━━━━

선택 반의 실제 schedule_days 값을 기준으로 parseDayNums 결과를 제출한다.

예:

schedule_days 원문:
"월,수,금"

parseDayNums 결과:
Set {1,3,5}

또는

schedule_days 원문:
"1,3,5"

parseDayNums 결과:
...

함수 원문도 함께 제출한다.

그리고 absence_date 다음 날부터 expire_at까지
실제 생성될 occurrence 날짜를 최소 5개 계산해서 제출한다.

중요:

API가 200인데 occurrences=[]인 경우에만 이 항목이 직접 원인 후보다.

API가 403/404/500/503이면 schedule_days 파싱은 직접 원인이 아니다.

━━━━━━━━━━━━━━━━━━━━━━
9. pool_holidays 조회 검증
━━━━━━━━━━━━━━━━━━━━━━

실패한 poolId와 날짜 범위로 조회한다.

SELECT
  id,
  pool_id,
  holiday_date,
  reason
FROM pool_holidays
WHERE pool_id = :poolId
  AND holiday_date >= :absenceDate::date
  AND holiday_date <= :endDate::date
ORDER BY holiday_date;

확인:

- 쿼리 자체 성공 여부
- 잘못된 컬럼명 사용 여부
- pool_id 컬럼 실제 존재 여부
- holiday_date 타입
- 전체 회차가 휴일로 제거되는지

10. 정원 계산 SQL 검증
━━━━━━━━━━━━━━━━━━━━━━

실패 classGroupId 기준으로 실행한다.

SELECT COUNT(s.id)::int AS cnt
FROM students s
WHERE (
  s.class_group_id = :classGroupId
  OR s.assigned_class_ids @> to_jsonb(:classGroupId::text)
)
AND s.status IN ('active', 'pending_parent_link', 'unregistered')
AND s.deleted_at IS NULL;

확인:

- SQL 성공 여부
- assigned_class_ids 타입
- to_jsonb 비교 오류 여부
- DB 예외 발생 여부
- count 결과

정원 마감은 회차 조회 실패 원인이 아니다.
정상이라면 is_full=true로 200 응답되어야 한다.
