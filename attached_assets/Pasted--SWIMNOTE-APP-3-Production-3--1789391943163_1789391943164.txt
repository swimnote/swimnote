[SWIMNOTE APP — 회원상세 3종 버그 Production 배포 승인]

회원상세 3종 수정안을 승인합니다.

별도 테스트 서버가 없으므로
코드/계약 검증이 완료된 현재 수정사항을 Production에 배포한 뒤
실기기에서 최종 확인합니다.

중요 정책 최종 확정:

수업일지와 앨범 사진은
작성 선생님/촬영 선생님의 개인 데이터가 아니라
학생에게 귀속되는 교육 기록입니다.

따라서:

현재 해당 학생 상세정보에 접근할 권한이 있는
pool_admin / teacher는

작성자
촬영자
과거 담당 선생님
당시 반

과 관계없이

해당 학생에게 귀속된
과거~현재 전체 일지와 앨범을 조회할 수 있어야 합니다.

READ 권한은 학생 접근권한 기준.

WRITE 권한은 기존 담당자 정책 유지.

작성자 필터나 촬영자 필터로
과거 기록을 차단하지 마십시오.

2. 배포 전 마지막 확인
━━━━━━━━━━━━━━━━━━

배포 직전 diff 확인:

- diary student 조회에 작성자 teacher_id 제한 없음
- album student 조회에 촬영자/과거 class 제한 없음
- pool isolation 유지
- teacher는 해당 student 접근권한 검증 유지
- admin은 자기 pool student 접근 가능
- WRITE 권한 확대 없음
- DB migration 없음
- AI ENGINE 변경 없음

문제 없으면 바로 진행.

━━━━━━━━━━━━━━━━━━

━━━━━━━━━━━━━━━━━━

━━━━━━━━━━━━━━━━━━

5. 배포 후 실기기 확인
━━━━━━━━━━━━━━━━━━

배포 완료 후 실제 APP에서 다음만 빠르게 확인:

1.
회원목록
→ 학생 상세
→ 뒤로가기
→ 원래 화면 복귀

2.
선생님모드 학생 상세
→ 일지보기
→ 해당 학생의 과거/현재 일지 표시

작성 선생님이 달라도 학생에게 귀속된 기록이면 표시.

3.
학생 상세
→ 앨범
→ 과거/현재 사진 표시

사진이 여러 페이지면
더 보기로 끝까지 조회.

4.
403/500이 발생하면
"사진 없음"으로 위장되지 않고 오류 표시.

이 검증은 Production 배포 후 실시합니다.
