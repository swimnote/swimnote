반드시 확인:

- 어떤 API/값과 version 비교하는지
- 2.1.0에서 무엇을 반환하는지
- true가 반환되면 왜 true인지
- network/error fallback이 true인지 false인지
- App Store production version과 TestFlight version 비교가
  OTA를 잘못 차단하는지

판정:

YES / NO

만약 YES면 이것이 1차 root cause.

8. 원인 확정 후 바로 처리
============================================================

이번에는 원인 확정 후 중간보고 기다리지 말 것.

CASE A
JS 코드 문제이며 현재 2.1.0 binary가 OTA 수신 가능
→ 최소 수정
→ commit
→ source SHA 확인
→ iOS runtime 2.1.0 / exact channel로 OTA 즉시 게시

CASE B
EAS channel/branch mapping 문제
→ 올바른 exact channel/branch로 OTA 다시 게시
→ 코드 수정 금지

CASE C
현재 2.1.0 binary의 expo-updates/bootstrap/native config 문제라
OTA 자체를 정상 수신할 수 없음
→ OTA 반복 게시 금지
→ NEW TESTFLIGHT BUILD REQUIRED = YES
→ 정확한 이유 보고
→ 임의 build는 하지 말고 STOP

CASE D
checkNativeVersion()이 OTA를 차단
→ OTA check가 강제업데이트 검사 때문에 막히지 않도록
  최소 수정
→ commit
→ 바로 2.1.0 iOS OTA 게시
단 현재 binary가 그 OTA를 받을 수 있어야 함.
