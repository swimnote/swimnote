[보낼 곳: APP REPLIT]

SWIMNOTE 상품화 구조를 수정한다.

이번 작업은 코드 수정이 아니라
Normal SWIMNOTE vs X MODE 기능경계 전수조사다.

절대 원칙:

1. 일반 SWIMNOTE와 X MODE의 차이는
   기본 운영기능/매출관리기능이 아니라
   AI 및 고급 교육시스템의 깊이여야 한다.

2. 아래 기능은 X 전용이면 안 된다.
   일반 SWIMNOTE에도 동일하게 제공되어야 한다.

- 재등록 관리
- 재등록 임박 알림
- 퇴원/이탈 관리
- 관리자 매출 관련 정보
- 신규회원 전환 지원
- 학부모 기본 관리
- 요청/보강
- 푸시알림
- 관리자 행동 대시보드
- 회원 증감
- 상담/등록/재등록 flow
- 학부모 기본 성장 체감
- 기본 공유
- 운영 자동화
- 교사 업무 절감
- 일반 편의기능

3. X MODE 차별은 아래 범주로 제한한다.

- AI 일지 고도화
- AI Curriculum Grounding
- AI 성장분석
- AI 성장리포트
- AI 인사이트 전략 리포트
- 고급 Curriculum/Progress
- AI Parent Search
- AI 기반 오류/원인/교정/Drill/Next Node
- X 전용 교육 데이터
- AI/교육 중심 PC Dashboard
- 고급 분석/리포트

==================================================
1. Normal vs X 기능 전수조사
==================================================

release/v2.0.0 실제 코드 기준으로
모든 기능을 아래 3개로 분류한다.

A. NORMAL_COMMON
일반 SWIMNOTE와 X 모두 사용해야 하는 기능

B. X_AI_PREMIUM
AI/고급교육 차별 기능

C. INTERNAL
super_admin/운영 내부 기능

각 기능마다 현재 실제 gate를 확인:

- xmode_enabled
- entitlement
- subscription
- role
- route guard
- UI hide
- API permission
- DB condition

추측 금지.

==================================================
2. 매출 관련 기능 X 종속 여부 전수조사
==================================================

다음 기능이 X mode에 묶여 있는지 확인한다.

- 재등록 상태
- 재등록 예정/임박
- 퇴원/탈퇴
- 회원 증가/감소
- 신규회원
- 상담중/미등록
- 보강
- 요청
- 출결
- 결석 패턴
- 관리자 알림
- 학부모 푸시
- 공지
- 앨범
- 일지
- 기본 성장 정보
- 레벨
- 승급/테스트
- 기본 Progress
- 공유
- referral 가능 구조
- 관리자 행동대상
- analytics 이벤트

각 항목:
COMMON / X_ONLY / PARTIAL / NOT_IMPLEMENTED
로 보고한다.

X_ONLY인 경우:
"왜 X에 묶여 있는지"
"Normal로 내려도 기술적으로 문제없는지"
를 반드시 보고한다.

==================================================
3. 학부모 가치 전수조사
==================================================

Normal mode 학부모와 X mode 학부모 화면을 비교한다.

다음 질문을 각각 Normal/X로 비교:

1. 오늘 무엇을 배웠는가
2. 최근 무엇이 좋아졌는가
3. 현재 어느 수준인가
4. 다음 목표는 무엇인가
5. 재등록할 이유를 느낄 수 있는가
6. 수영장 전문성을 느낄 수 있는가
7. 사진/피드/공지/일정 접근성
8. 요청/보강 편의성
9. 공유 가능성

Normal에서 빠진 기본 가치 중
AI가 아닌 것은 전부 COMMON 후보로 표시한다.

==================================================
7. X Gate 오용 탐지
==================================================

코드에서
xmode_enabled / entitlement 때문에
기본 기능까지 숨겨지는 모든 경우를 찾는다.

예:
if (!xmode) return null
if (!hasX) hide section
X route only
X API only

각 항목마다:

- 기능명
- 파일
- 현재 gate
- AI 기능 여부
- Normal 이동 필요 여부
- 이동 난이도
- dependency

보고한다.

==================================================
8. 상품화 기준으로 재분류
==================================================

모든 기능을 최종적으로:

COMMON_CORE
COMMON_REVENUE
COMMON_PARENT
COMMON_TEACHER
COMMON_ADMIN
X_AI
X_ADVANCED_EDUCATION
INTERNAL

중 하나로 재분류한다.

특히:

COMMON_REVENUE:
모든 수영장 매출에 직접 기여하는 기능

COMMON_PARENT:
학부모 만족/재등록을 높이는 비AI 기능

COMMON_TEACHER:
교사 업무를 줄이는 비AI 기능

COMMON_ADMIN:
운영을 단순화하는 비AI 기능

으로 명확히 구분한다.
