5. 3-SESSION CONFIRMATION RULE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

핵심 제품 규칙:

어떤 rank P 이상에서
서로 다른 실제 lesson_session 3회가 관찰되면
P를 confirmed rank로 인정.

예:

[56,70,87]
→ 56 이상 3회
→ confirmed rank=56

[56,70,70,87]
→ 70 이상 3회
→ confirmed rank=70

[78,81,85]
→ 78 이상 3회
→ confirmed rank=78

[70,87]
→ 2회
→ 새 confirmed 없음

결과가 동일하면 구현 방식은 자유.

가장 단순한 방식:
eligible ranks를 DESC 정렬 후
세 번째로 높은 rank가
newly confirmed rank와 동치인지 검증 후 사용 가능.

단:
중복 session이 구조적으로 1행인지 확인.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
6. Active Version Percent
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

activeConfirmedPct =
ROUND(
  activeConfirmedRank / activeConfirmedTotal * 100,
  1
)

activeConfirmedTotal은
현재 active curriculum version의
실제 active item count.

raw sort_order 사용 금지.

GAUGE-02의 1-based rank 좌표계와 동일해야 함.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
7. SCP Meaning Separation
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

반드시 구분:

A. activeConfirmedRank / activeConfirmedPct
→ 현재 active curriculum version의
   현재 유효 3-session evidence 기준 factual position

B. displayConfirmedPct
→ 학부모에게 보여주는 lifetime monotonic progress

둘을 혼동 금지.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
8. Same-Version Recalculation
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

예:

기존:
activeConfirmedRank=70
display=70%

일지 수정/삭제 후
현재 유효 CPO 재계산 결과:
activeConfirmedRank=50

그러면:

activeConfirmedRank=50
activeConfirmedPct=현재 version 기준 50 위치 %

BUT

displayConfirmedPct는
기존 display보다 내려가지 않음.

공식:

displayConfirmedPct =
MAX(
  existing.display_confirmed_pct,
  newlyComputedActivePct
)

즉 raw factual position은 내려갈 수 있지만
학부모 lifetime gauge는 내려가지 않는다.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
9. Cross-Version Monotonic
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

서로 다른 version의 rank를
절대 직접 비교하지 않는다.

예:

old:
140/200=70%

new:
200/400=50%

new rank가 더 커도:

display =
MAX(70,50)
=70%

version 변경 감지 시:

prev_curriculum_version_id
= old active version

prev_display_pct
= old display

active_curriculum_version_id
= new version

새 version session <3:
active rank=0
active pct=0
display old 유지

새 version confirmed pct가 old display 초과:
display 상승.

11. SCP UPSERT — RACE SAFE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

UNIQUE(student_id, swimming_pool_id)

DB UPSERT에서
display progress 하락을 구조적으로 막는다.

가능하면:

display_confirmed_pct =
GREATEST(
  student_curriculum_progress.display_confirmed_pct,
  EXCLUDED.display_confirmed_pct
)

application read→MAX→write만 사용 금지.

동시 수업 저장/재계산에서도
display 감소 불가.

version 변경 prev_* 처리도
race로 이상해지지 않도록
현재 PostgreSQL UPSERT 패턴 사용.

12. confirmed_at / display_updated_at
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

activeConfirmedRank 또는 activeConfirmedPct가
실제로 변경된 시각.
