[SWIMNOTE APP SERVER HOTFIX]
[GROUP 8 STARTUP MIGRATION IDEMPOTENCY FIX + PRODUCTION DEPLOY]

확정된 root cause:

파일:
artifacts/api-server/src/migrations/pool-db-x-init.ts

함수:
runGroup8_ParentAiUsageFeatureIsolation()

문제 위치:
parent_ai_daily_usage_feature_unique 생성 부분

현재 문제:

Production DB에는 이미 constraint가 존재함.

현재 migration은:

ALTER TABLE parent_ai_daily_usage
ADD CONSTRAINT parent_ai_daily_usage_feature_unique
UNIQUE (parent_account_id, feature, usage_date);

를 DO $$ + EXCEPTION WHEN duplicate_object 로 감싸고 있음.

하지만 PostgreSQL은
constraint 내부 index relation 중복 시:

SQLSTATE 42P07

을 발생시킬 수 있음.

duplicate_object는 42710만 포착하므로
startup migration 재실행 시 예외가 전파되고:

[FATAL] DB 초기화 실패
→ 서버 startup 실패
→ 모든 route 500

발생.

이번 작업 목적:

Group 8 migration을 진짜 idempotent하게 수정하고
Production API를 즉시 복구한다.

==================================================
1. CODE FIX
==================================================

기존 EXCEPTION 기반 duplicate handling 제거.

pg_constraint 사전 존재 확인 방식으로 변경.

개념:

DO $$
BEGIN
  IF NOT EXISTS (
    SELECT 1
    FROM pg_constraint
    WHERE conname = 'parent_ai_daily_usage_feature_unique'
  ) THEN
    ALTER TABLE parent_ai_daily_usage
      ADD CONSTRAINT parent_ai_daily_usage_feature_unique
      UNIQUE (parent_account_id, feature, usage_date);
  END IF;
END $$;

단 실제 repository SQL formatting / schema qualification 기준 사용.
