# 선생님 일지쓰기 — 문장 불러오기 검색창 가림 현상 수정

현재 선생님 모드의 일지쓰기 화면에서
`문장 불러오기` 모달의 검색창을 누르고 키보드가 열리면,
검색창이 모달 상단 프레임 밖으로 밀려 보이지 않는 문제가 있습니다.

이번 작업은 이 키보드·스크롤 레이아웃 문제만 수정합니다.

다른 일지 작성 기능, 템플릿 데이터, 검색 로직, 선택·삽입 기능은 절대 변경하지 마세요.

==================================================
1. 현재 문제
==================================================

재현 순서:

1. 선생님 모드에서 일지쓰기 진입
2. 문장 불러오기 모달 열기
3. 검색창 선택
4. 키보드 표시
5. 검색 결과 또는 빈 결과 화면으로 변경
6. 검색창이 모달 상단 프레임 밖으로 밀려 보이지 않음

현재 화면에서 사용자가 검색어를 수정하거나 지우려면
검색창이 보이지 않아 매우 불편합니다.

==================================================
2. 목표 구조
==================================================

모달 내부를 아래처럼 분리하세요.

고정 영역:

- 상단 핸들
- `문장 불러오기` 제목
- 닫기 버튼
- 검색창
- 검색 결과 개수
- 나의 템플릿 / 카테고리 필터 영역
  - 현재 화면 구조상 검색 중 숨겨지는 항목은 기존 동작 유지 가능

스크롤 영역:

- 문장 검색 결과 목록
- 검색 결과 없음 화면

하단 고정 영역:

- 삽입 예정 미리보기
- 바로 전 삭제
- 전체 삭제
- 취소
- 완료·삽입

즉, 키보드가 열려도 검색창은 항상 화면에 보여야 합니다.

==================================================
3. 핵심 수정 방식
==================================================

검색창을 문장 결과 목록을 담당하는 ScrollView 또는 FlatList 안에 넣지 마세요.

검색창은 스크롤 목록 밖의 상단 고정 영역에 배치하세요.

권장 구조:

<View style={modalContainer}>
  <View style={fixedHeader}>
    핸들
    제목 + 닫기
    검색창
    결과 개수 / 필터
  </View>

  <FlatList
    data={filteredSentences}
    ...
  />

  <View style={fixedFooter}>
    삽입 예정 미리보기
    하단 버튼
  </View>
</View>

검색 결과만 세로로 스크롤되어야 합니다.

==================================================
4. 키보드 대응
==================================================

모달 전체 또는 적절한 최상위 영역에
KeyboardAvoidingView를 적용하세요.

iOS:

behavior="padding"

Android:

현재 프로젝트에서 사용하는 안정된 방식에 맞게
behavior를 지정하거나 height 방식 사용

keyboardVerticalOffset은 실제 상단 Safe Area와
모달 위치를 기준으로 계산하세요.

무작정 큰 고정값을 넣지 마세요.

==================================================
5. 검색창 포커스 시 동작
==================================================

검색창에 포커스되어 키보드가 열려도:

- 검색창 전체가 보여야 함
- 입력한 검색어가 보여야 함
- 검색어 지우기 버튼이 보여야 함
- 검색 결과 개수가 보여야 함
- 검색 결과가 아래에서 스크롤 가능해야 함
- 닫기 버튼이 보여야 함

검색창이 화면 위로 잘리거나,
제목과 겹치거나,
모달 바깥으로 빠지면 안 됩니다.

==================================================
6. 스크롤 여유
==================================================

결과 목록의 contentContainerStyle에
충분한 상·하단 padding을 적용하세요.

특히 마지막 검색 결과가 하단의
`삽입 예정 미리보기` 영역에 가려지지 않아야 합니다.

단, 검색창 자체를 스크롤 영역에 넣고
padding만 늘리는 임시방편은 사용하지 마세요.

핵심은 검색창 고정입니다.

==================================================
7. 검색 결과 없음 화면
==================================================

검색 결과가 0개일 때도 동일합니다.

현재처럼:

- `전체 0개 문장 검색됨`
- `검색 결과가 없습니다.`

는 유지하되,

검색창은 항상 위에 보여야 합니다.

검색 결과 없음 화면이 검색창을 밀어내거나
전체 높이를 비정상적으로 차지하지 않도록 하세요.

빈 상태는 FlatList의 ListEmptyComponent 또는
결과 영역 안에서만 렌더하세요.

==================================================
8. 키보드가 열린 상태의 하단 영역
==================================================

현재 하단에는:

- 삽입 예정 미리보기
- 취소
- 완료·삽입

영역이 있습니다.

키보드가 열린 경우에도 화면이 깨지지 않아야 합니다.

우선순위:

1. 검색창이 항상 보일 것
2. 검색 결과를 스크롤할 수 있을 것
3. 완료·삽입 버튼을 사용할 수 있을 것

필요한 경우 키보드가 열린 동안
삽입 예정 미리보기 영역 높이를 줄이거나
최소 높이만 유지할 수 있습니다.

단:

- 선택된 문장 데이터 삭제 금지
- 완료·삽입 버튼 제거 금지
- 검색할 때마다 미리보기 상태 초기화 금지

==================================================
9. 키보드 닫기
==================================================

다음 동작을 지원하세요.

- 목록 드래그 시 키보드 닫기
- 검색 결과 문장 선택 시 키보드를 유지하거나 닫는 동작은 기존 UX 유지
- 모달 닫기 시 Keyboard.dismiss()
- 완료·삽입 시 Keyboard.dismiss()

FlatList 또는 ScrollView에는 적절히:

keyboardShouldPersistTaps="handled"
keyboardDismissMode="interactive"

를 적용하세요.

Android에서 interactive가 지원되지 않는 경우
현재 프로젝트에 맞는 값으로 처리하세요.

==================================================
12. Hook 안정성
==================================================

이번 작업 중 새 Hook을 추가하는 경우
모든 early return보다 위에 선언하세요.

조건문 내부 또는 early return 아래에:

- useState
- useEffect
- useMemo
- useCallback
- useRef

를 추가하지 마세요.

최근 발생했던:

Rendered more hooks than during the previous render

오류가 다시 발생하면 안 됩니다.
