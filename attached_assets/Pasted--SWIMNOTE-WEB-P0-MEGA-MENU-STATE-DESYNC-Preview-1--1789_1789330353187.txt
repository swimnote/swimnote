3. MEGA MENU는 즉시 UNMOUNT 방식으로 단순화
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

현재 Mega Menu에 AnimatePresence가

우선순위는 animation이 아니라 정상 UX입니다.

최종 구조는 가능한 단순하게:

{menuOpen && (
  <ExpandedMenu ... />
)}

형태로 구성하십시오.

menuOpen === false
→ Mega Menu DOM 자체가 즉시 unmount

되어야 합니다.

닫힘 animation 때문에
old panel DOM이 route 이동 후 살아남는 구조는 금지합니다.

필요하면 open animation만 CSS로 아주 약하게 적용하고,
close는 즉시 unmount해도 됩니다.

사용성 > animation 입니다.

기존 Transient UI 헌법에서
애매한 구현 세부사항은 제거하고
아래를 최상위 절대규칙으로 교체하십시오.

SWIMNOTE TRANSIENT UI CONSTITUTION:

1. NAVIGATION START
   → TRANSIENT UI CLOSE FIRST

2. ROUTE / VIEW CHANGE
   → TRANSIENT UI STATE RESET

3. ACTION COMPLETE
   → TRANSIENT UI CLOSE

4. OUTSIDE POINTER DOWN
   → TRANSIENT UI CLOSE

5. ESC
   → TRANSIENT UI CLOSE

6. DESKTOP POINTER LEAVES ACTIVE REGION
   → TRANSIENT UI CLOSE

7. CLOSE STATE
   → TRANSIENT UI DOM MUST BE UNMOUNTED

가장 중요한 추가 헌법:

"state=false인데 이전 transient UI DOM이 화면에 남아 있어서는 안 된다."

향후 PC Dashboard에서도 동일 적용:

- profile menu
- filters
- sort menu
- more menu
- notifications
- member actions
- class actions
- context menu

페이지/view 전환 전에 close하고,
새 view에서 이전 transient DOM을 절대 유지하지 않습니다.

이것이 이전 UX 헌법을 대체하는 최종 기준입니다.
