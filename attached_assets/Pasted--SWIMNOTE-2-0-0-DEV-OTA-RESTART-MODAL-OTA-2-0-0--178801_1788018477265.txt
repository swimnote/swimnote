[SWIMNOTE 2.0.0 — DEV OTA RESTART MODAL 임시 부활]

목표:

기존 OTA 업데이트 방식은 그대로 유지하고,
2.0.0 개발 편의를 위해
업데이트 적용 후 앱을 재시작하는 버튼이 있는
개발용 모달만 임시로 추가한다.

1.6.3은 건드리지 않는다.

==================================================
1. 기존 OTA 로직 유지
==================================================

현재 사용 중인 OTA:

- update check
- download/fetch
- 적용 방식
- production-v2 channel
- release-2.0.0 branch
- runtimeVersion 2.0.0

전부 그대로 유지.

기존 OTA architecture 변경 금지.

==================================================
2. DEV Restart Modal
==================================================

2.0.0에서 OTA update가 다운로드 완료되어
재시작이 필요한 상태가 되면 모달 표시.

예시 문구:

"새 업데이트가 준비되었습니다."

버튼:

[앱 재시작]

버튼 실행 시
현재 Expo Updates에서 실제 지원하는
reload/restart API를 사용해
다운로드된 OTA를 즉시 적용.

추측 API 사용 금지.
현재 Expo SDK / expo-updates 버전 확인 후 구현.

==================================================
3. 개발용으로만 표시
==================================================

이 모달은 2.0.0 개발기간에만 사용.

1.6.3:
표시 금지.

2.0.0:
표시 허용.

가능하면 별도 flag/config 사용:

DEV_OTA_RESTART_MODAL = true

또는 현재 프로젝트 구조에 맞는
동등한 명시적 feature flag 사용.

출시 직전:

false 또는 컴포넌트 제거

만으로 비활성화 가능해야 한다.

==================================================
4. 기존 UX 침범 금지
==================================================

기존 OTA 알림/업데이트 흐름은 변경하지 않는다.

추가되는 것은 오직:

update downloaded
→ restart modal 표시

뿐.

강제 재시작 금지.

사용자가 버튼을 눌렀을 때만 재시작.

==================================================
5. 모달 범위
==================================================

공통 root 영역에서
admin / teacher / parent 모두 사용 가능하게 한다.

화면별 중복 구현 금지.

가능하면:

DevOtaRestartModal

같은 독립 컴포넌트로 분리.

==================================================
6. 재실행 안정성
==================================================

다음 확인:

- 업데이트 다운로드 전에는 모달 표시 안 됨
- 다운로드 완료 후 한 번 표시
- 재시작 버튼 연타 방지
- reload 중 중복 실행 방지
- 재실행 후 동일 update로 모달 반복 표시 안 됨
- update 없는 경우 앱 동작 변화 없음
