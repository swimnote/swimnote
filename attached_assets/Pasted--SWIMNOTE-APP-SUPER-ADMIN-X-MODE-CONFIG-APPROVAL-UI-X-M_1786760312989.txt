[SWIMNOTE APP]
[SUPER ADMIN — X MODE CONFIG APPROVAL UI]

목적:

슈퍼관리자가 운영처의 X MODE 설정 심사를 직접 승인하여

xmode_config_status:
PENDING / REVIEWING 등 현재 상태
→ READY

로 변경할 수 있는 관리자 UI를 구현한다.

현재:

슈퍼관리자
→ 운영처 관리
→ 운영처 상세
→ X모드

화면에:

X 사용권 = X 활성
설정 상태 = 심사 중

까지 표시되고 있음.

현재 X 사용권 수동 활성/비활성 UI는 별도 구현 완료.

이번 작업은 entitlement가 아니라
X 설정 심사 승인 기능이다.

==================================================
1. CANONICAL RULE 유지
==================================================

절대 변경 금지:

xmode_entitlement = true
AND
xmode_config_status = READY
→ mode = x

xmode_entitlement = true
AND
xmode_config_status != READY
→ mode = x_pending

xmode_entitlement = false
→ mode = normal

==================================================
2. SERVER CONTRACT AUDIT
==================================================

먼저 기존 server에서:

xmode_config_status

를 변경하는 Super Admin API가 이미 존재하는지 확인.

가능한 기존 route / service / mutation을 repository에서 검색.

확인:

- endpoint
- payload
- allowed status
- auth
- audit log
- validation

기존 API가 있으면 재사용.

없으면
Super Admin 전용 최소 API만 추가.

일반 관리자/선생님/학부모가 호출할 수 없도록
Super Admin auth 필수.

==================================================
3. UI LOCATION
==================================================

현재 운영처 상세 > X모드 탭의

SWIMNOTE X 상태

카드에 설정 상태가 표시되고 있음.

그 아래 또는 별도 카드에:

"X 설정 심사"

영역 추가.

현재 READY가 아닐 경우:

[ X 설정 승인 ]

버튼 표시.

==================================================
4. APPROVAL FLOW
==================================================

버튼 클릭:

Alert:

제목:
X MODE 설정을 승인할까요?

내용:
이 운영처의 X MODE 설정 상태를 READY로 변경합니다.
X 사용권이 활성 상태라면 즉시 X MODE가 활성화됩니다.

취소
승인

승인 후:

xmode_config_status = READY

로 서버에 PATCH.

성공 후 반드시 서버 state 재조회.

==================================================
5. ENTITLEMENT 분리
==================================================

이 버튼은:

xmode_entitlement

를 변경하지 않는다.

예:

entitlement=false
config_status=READY

이면 최종 mode는 normal.

entitlement=true
config_status=READY

이면 최종 mode는 x.

두 개를 절대 한 버튼으로 묶지 않는다.

==================================================
6. REVOKE / RETURN TO REVIEW
==================================================

READY 상태에서는 관리자에게:

[ 심사 상태로 되돌리기 ]

기능도 제공 가능한지 기존 contract 확인.

안전한 canonical status가 존재할 경우에만 구현.

예:
REVIEWING 또는 PENDING

임의 status 문자열 생성 금지.

기존 schema enum/check를 source of truth로 사용.

==================================================
7. DATA SAFETY
==================================================

READY 승인 또는 심사 상태 변경으로:

삭제 금지:

curriculum
templates
diary
growth_events
growth_reports
members
classes
X configuration data

상태값만 변경.

==================================================
8. AUDIT LOG
==================================================

승인/취소는 audit_logs에 기록.

기존 audit infrastructure 재사용.

기록:

super admin
operator/pool id
before status
after status
timestamp

중복 audit 생성 금지.

SWIMNOTE X 상태
