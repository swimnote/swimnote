현재 선생님 ClassDetailSheet 수정 구조는 유지한다.

관리자 AdminClassDetailSheet에 남아 있는
세로 ScrollView 안의 세로 FlatList 중첩 구조만 제거한다.

현재 문제 구조:

<ScrollView>
  헤더·정보·버튼
  <FlatList data={students} />
</ScrollView>

이 구조는 금지한다.

1. 관리자 메인 화면 최종 구조

관리자 학생 목록도 하나의 FlatList가 전체 스크롤을 담당하게 한다.

권장 구조 A:

<FlatList
  data={students}
  renderItem={renderStudent}
  keyExtractor={...}
  ListHeaderComponent={
    <>
      반 정보
      담당 선생님
      정원
      기능 버튼
      학생 목록 제목
    </>
  }
  ListFooterComponent={
    <>
      보강 학생 영역
      하단 여백
    </>

  style={{ flex: 1, minHeight: 0 }}
  contentContainerStyle={{ paddingBottom: 64 }}
  keyboardShouldPersistTaps="always"
  keyboardDismissMode="on-drag"
  showsVerticalScrollIndicator={false}

금지:

- ScrollView 안에 FlatList
- FlatList 안에 같은 방향 ScrollView
- scrollEnabled={false} FlatList로 전체 렌더
- 학생 목록 map 복귀

서브뷰:

- transfer
- teacher
- add_co_teacher

각각 기존 단독 FlatList 구조를 유지한다.
메인 학생 목록 FlatList와 동시에 렌더하지 않는다.

━━━━━━━━━━━━━━━━━━━━━━
2. 제스처 영역 유지
━━━━━━━━━━━━━━━━━━━━━━

현재 구현한 정책 유지:

- PanResponder는 dragHandleArea에만 적용
- 학생 목록 FlatList는 panHandlers 밖
- sheetHeader 및 기능 버튼도 panHandlers 밖
- 서브시트 또는 subView가 열리면 메인 손잡이 drag 비활성
- X 버튼과 backdrop 닫기 유지

선생님 ClassDetailSheet 구조는 이 보완 과정에서 변경하지 않는다.

━━━━━━━━━━━━━━━━━━━━━━
3. handleDismiss 중복 실행 방지
━━━━━━━━━━━━━━━━━━━━━━

X 버튼, backdrop, 손잡이 dismiss가 동시에 호출될 가능성을 막기 위해
dismiss 진행 상태가 이미 있는지 확인한다.

없다면 ref 기반 가드를 추가한다.

const dismissingRef = useRef(false);

function handleDismiss() {
  if (dismissingRef.current) return;
  dismissingRef.current = true;

  Animated.timing(...).start(() => {
    sheetDragY.setValue(0);
    dismissingRef.current = false;
    handleCloseRef.current();
  });
}

모달이 새로 열릴 때 dismissingRef.current = false로 초기화한다.

선생님·관리자 모두 동일하게 확인한다.
