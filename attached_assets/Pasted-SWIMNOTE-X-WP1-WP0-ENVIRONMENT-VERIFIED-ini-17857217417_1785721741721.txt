SWIMNOTE X — WP1 설계서 반려 및 정정 제출 지시

WP0 추가 환경조사는 확인했습니다.

다음 사실은 ENVIRONMENT_VERIFIED로 인정합니다.

* initXModeSchema()가 운영 서버에서 이미 실행됨
* 운영 DB에 M-A~M-J가 이미 적용됨
* PART 2 대상인 parent_ai_daily_usage, parent_ai_usage_reservations, growth_reports도 이미 생성됨
* curriculum 관련 5개 테이블은 아직 없음
* 백업 DB에 X 스키마가 적용되지 않아 standby sync가 실패 중임

그러나 제출한 WP1 설계서는 SWIMNOTE X 최종 설계서 v3.3.4와 다른 기술 구조를 다수 포함하므로 승인하지 않습니다.

8. Curriculum 설계 원칙
━━━━━━━━━━━━━━━━━━━━━━

* curriculum_versions
* curriculum_items
* student_curriculum_assignments
* curriculum_requests
* curriculum_request_files

임의 기능 추가 금지.

student_curriculum_assignments에는 학생에게 배정된 커리큘럼 버전과 배정 이력을 저장합니다.

현재 진행 중인 curriculum_item을 별도 상태로 저장하는 구조는 승인되지 않았습니다.

따라서 다음 컬럼을 임의 추가하지 마십시오.

curriculum_item_id

진행도와 완료 여부는 growth_events를 기준으로 계산합니다.

학생 배정 테이블 최소 책임:

* student_id
* swimming_pool_id
* curriculum_version_id
* 배정 시점
* 배정 주체
* 활성 여부
* 종료 또는 비활성화 시점
* 이력 보존

정확한 컬럼명은 기존 Repository naming convention을 확인하여 제출하십시오.

9. Curriculum FK 원칙
━━━━━━━━━━━━━━━━━━━━━━

DB 무결성 보장을 위해 FK를 사용합니다.

원칙:

* curriculum_items → curriculum_versions
* student_curriculum_assignments → curriculum_versions
* curriculum_requests.result_version_id → curriculum_versions
* curriculum_request_files → curriculum_requests
* growth_events.curriculum_item_id → curriculum_items
* growth_events.curriculum_version_id → curriculum_versions

삭제 정책:

* 커리큘럼 버전과 항목은 과거 이력 보존을 위해 물리 삭제하지 않음
* 참조 데이터가 있으면 삭제 차단
* 기본적으로 ON DELETE RESTRICT
* SET NULL 사용 금지
* CASCADE는 request_files처럼 요청 자체에 종속되는 첨부 메타에만 검토

growth_events의 curriculum_item_id와 curriculum_version_id는 NOT NULL 유지가 원칙입니다.

10. Migration 실패와 서버 기동
━━━━━━━━━━━━━━━━━━━━━━

현재 index.ts의 다음 구조를 직접 확인하십시오.

  initPoolDb().catch(...),
  initSuperDb().catch(...)

Migration 실패가 catch 처리된 뒤 서버가 계속 기동할 수 있다면 헌법 위반입니다.

WP1 설계서에 다음을 제출하십시오.

* 실제 catch 코드
* 오류 재throw 여부
* initPoolDb 실패 시 HTTP 서버가 시작되는지
* initXModeSchema 실패 시 서버가 시작되는지
* Worker 모드도 같은지
* 백업 DB 초기화 실패 시 운영 서버가 시작되는지

목표:

필수 운영 DB Migration 실패
→ 서버 기동 중단

백업 DB 실패 정책은 운영 DB와 분리하여 실제 현재 정책과 위험을 보고하십시오.
