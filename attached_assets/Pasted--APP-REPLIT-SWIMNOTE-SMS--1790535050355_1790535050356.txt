[SWIMNOTE — 학부모 초대 SMS 자동문구 + 앱스토어 링크 적용]

현재 관리자/선생님 회원 상세 화면의
보호자 연락처 영역에서 문자 아이콘을 누르면
네이티브 문자 앱은 정상 실행되고 수신자 번호도 입력되지만,
문자 본문이 비어 있습니다.

목표:

문자 아이콘 1회 터치
→ 해당 보호자 번호가 수신자로 자동 입력
→ 수영장명 + 학생명 + SWIMNOTE 가입 안내문구
→ App Store / Google Play 설치 링크
까지 본문에 자동 입력
→ 사용자는 내용 확인 후 "전송"만 누르면 됨

문자를 앱에서 자동 발송하지 마십시오.
반드시 iOS/Android 기본 문자 작성창을 열고
사용자가 최종 전송 버튼을 누르는 방식으로 유지합니다.

━━━━━━━━━━━━━━━━━━━━━━
1. 먼저 현재 구현 확인
━━━━━━━━━━━━━━━━━━━━━━

스크린샷 기준 위치:

관리자
→ 회원 상세
→ 보호자 / 연락처
→ 보호자 전화번호 우측 문자 아이콘

현재 문자 아이콘의:

- 화면 파일
- handler 함수
- Linking.openURL 또는 사용 중인 SMS 호출 방식
- 현재 recipient 생성 방식

을 확인하십시오.

현재 정상 동작하는 전화번호 선택/전달 로직은
불필요하게 변경하지 마십시오.

━━━━━━━━━━━━━━━━━━━━━━

3. 실제 데이터 사용
━━━━━━━━━━━━━━━━━━━━━━

수영장명:
현재 로그인한 운영자/선생님의
해당 swimming_pool canonical name 사용.

예:
토이키즈스윔클럽

학생명:
현재 열려 있는 회원 상세의 student.name 사용.

예:
서태웅

보호자 번호:
현재 보호자 연락처에 표시되는 번호 사용.

예:
010-7787-1507

절대:

- 수영장명을 hardcode하지 말 것
- 학생명을 hardcode하지 말 것
- 전화번호를 hardcode하지 말 것

4. 학생명 예외
━━━━━━━━━━━━━━━━━━━━━━

학생명이 정상 존재하면:

“서태웅 회원님의 수업일지, 사진, 공지와 성장기록을…”

형태.

학생명이 없거나 비정상 값이면:

“자녀의 수업일지, 사진, 공지와 성장기록을…”

로 자연스럽게 fallback.

문장에 undefined / null / 빈칸이 노출되면 안 됩니다.

처럼 안전하게 fallback.

7. 네이티브 SMS 작성창
━━━━━━━━━━━━━━━━━━━━━━

새 SMS 서버나 문자발송 API를 만들지 마십시오.

기존 네이티브 문자 앱 호출 방식을 유지하면서
recipient + body를 함께 전달합니다.

React Native Linking을 현재 사용 중이라면
iOS / Android의 SMS URI 차이를 처리하십시오.

중요:

- body 전체 encodeURIComponent 처리
- 한글 깨짐 없어야 함
- 줄바꿈 유지
- App Store 링크 클릭 가능
- Google Play 링크 클릭 가능
- 수신자 번호 그대로 유지

iOS와 Android에서 query separator 차이가 있다면
Platform.OS 기준으로 정확하게 분기하십시오.

현재 코드가 Linking만으로 충분하다면
expo-sms 같은 신규 native dependency를 추가하지 마십시오.

불필요한 신규 native dependency 때문에
새 binary build가 필요한 구조를 만들지 마십시오.

10. 최소 테스트
━━━━━━━━━━━━━━━━━━━━━━

Case A
수영장명 있음
학생명 있음
보호자 번호 있음

예:
수영장 = 토이키즈스윔클럽
학생 = 서태웅

PASS:
- 보호자 번호 자동 입력
- 토이키즈스윔클럽 표시
- 서태웅 표시
- 두 Store 링크 포함
- 사용자는 전송만 누르면 됨

Case B
학생명 없음

PASS:
- undefined/null 없음
- “자녀의 수업일지…” 형태로 자연스럽게 생성

Case C
수영장명 없음

PASS:
- SWIMNOTE 기본 안내문구 사용
- crash 없음

Case D
iPhone 실기기

PASS:
- Apple 메시지 앱 열림
- 수신번호 자동입력
- 본문 자동입력
- 한글/줄바꿈 정상
- 두 링크 터치 가능

Case E
Android 실기기 또는 실제 Android SMS intent 검증

PASS:
- 기본 문자 앱 열림
- 수신번호 자동입력
- 본문 자동입력
- 한글/줄바꿈 정상
- 두 링크 정상

전화 아이콘 기능 regression 없어야 합니다.
