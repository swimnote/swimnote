# SWIMNOTE 학부모 홈 화면 최종 개편 지시문

이번 작업은 학부모 Home 화면 UX를 최종 구조로 개편하는 작업입니다.

현재 앱의 관리자·선생님·슈퍼관리자 접속 및 서버 기능은 수정하지 마세요.
이번 작업은 학부모 Home UI와 Home에서 사용하는 기존 데이터 연결만 다룹니다.

OTA 배포와 운영 Publish는 하지 마세요.
작업 완료 후 화면과 변경 내역만 보고하고 멈추세요.

========================================
1. 작업 전 안전조치
========================================

작업 시작 전 현재 상태의 Checkpoint를 생성하세요.

보고:

- Checkpoint ID
- Rollback 가능 여부
- 현재 기준 브랜치 또는 커밋

========================================
2. 이번 작업의 핵심 정의
========================================

학부모 Home은 대시보드가 아닙니다.

학부모 Home의 중심은 다음과 같습니다.

- 최신 수업일지
- 이전 수업일지
- 과거 수업일지

사용자가 Home을 아래로 계속 스크롤하면
지난 수업일지가 날짜순으로 계속 보여야 합니다.

Home에서 수업일지를 눌러 다른 페이지로 들어가는 구조가 아니라,
Home 자체가 수업일지 피드여야 합니다.

최신 일지부터 과거 일지까지 하나의 세로 피드로 연결하세요.

========================================
3. 전체 화면 비율
========================================

상단 정보 전체는 첫 화면 높이의 최대 30% 이내로 구성하세요.

상단 정보에 포함되는 항목:

- 수영장명
- 알림
- 설정
- 자녀 선택 탭
- 학생 이름
- 수업 요일 및 시간
- 앨범 보기
- 얇은 공지 배너

위 항목을 모두 합쳐도 화면의 30%를 넘지 않게 하세요.

나머지 70% 이상은 수업일지 본문이 보이도록 구성하세요.

첫 화면에서 최신 수업일지의 본문이 바로 보여야 합니다.

========================================
4. 최종 Home 화면 구조
========================================

화면 순서는 정확히 다음과 같이 구성하세요.

1. Slim Header
2. 자녀 선택 탭
3. 학생 정보 한 줄
4. 얇은 공지 배너
5. 최신 수업일지
6. 이전 수업일지
7. 더 이전 수업일지 계속 반복

========================================
5. Header 규칙
========================================

Header는 최대한 얇게 만드세요.

포함:

- 수영장명
- 알림 버튼
- 설정 버튼

금지:

- 큰 로고 영역
- 큰 프로필 카드
- 환영 문구
- 긴 설명 문구
- 큰 배경 이미지
- 불필요한 상단 여백

수영장명이 길면 한 줄 말줄임 처리하세요.

========================================
6. 자녀 선택 탭
========================================

자녀가 여러 명이면 가로 탭으로 표시하세요.

포함:

- 현재 선택된 자녀
- 다른 자녀
- 자녀 추가

자녀 탭은 높이를 작게 유지하세요.

자녀 전환 시:

- 해당 자녀의 학생 정보
- 해당 자녀의 수업일지
- 해당 자녀의 앨범

이 모두 함께 변경되어야 합니다.

========================================
7. 학생 정보 한 줄
========================================

학생 정보는 반드시 한 줄로 표시하세요.

왼쪽:

- 학생 이름
- 수업 요일과 시작 시간

오른쪽:

- 앨범 보기 버튼

예시:

서태웅    목 19:00                  앨범 보기 >

시간은 한 번만 표시하세요.

표시 허용:

- 목 19:00

표시 금지:

- 19:00~19:50
- 19:00
- 목요일 19:00반
- 수업시간 19:00
- 동일한 시간 중복 표시
- 종료 시간 중복 표시

학생 정보 카드의 세로 높이를 작게 유지하세요.

========================================
8. 앨범 표시 방식
========================================

Home에 최근 사진을 따로 표시하지 마세요.

Home에서는 작은 `앨범 보기` 버튼만 제공하세요.

`앨범 보기`를 누르면 기존 앨범 화면으로 이동해야 합니다.

금지:

- 최근 사진 카드
- 최근 사진 2장
- 새 사진 2장
- 사진 미리보기
- 대형 썸네일
- 가로 사진 슬라이더
- 최근 사진 섹션
- 사진 전용 Home 카드

수업일지에 첨부된 사진은 해당 일지 안에서만 표시하세요.

========================================
9. 공지 배너
========================================

공지는 얇은 한 줄 배너로 표시하세요.

조건:

- 높이를 작게 유지
- 제목 중심
- 긴 문구는 한 줄 말줄임
- 기존 클릭 기능 유지
- 기존 공지 상세 라우팅 유지

금지:

- 큰 카드형 배너
- 여러 줄 설명
- 큰 이미지
- 자동 슬라이드로 많은 높이 사용
- 화면 상단 30% 초과

공지 데이터가 없으면 빈 공간을 만들지 마세요.

========================================
10. 완전히 제거할 요소
========================================

학부모 Home에서 아래 항목은 표시하지 마세요.

- 새 사진 2장
- 최근 사진
- 최근 사진 미리보기
- 우리 아이 수영 성장을 기록해보세요
- 수영 꿀팁
- 성장 포인트
- 성장 기록 안내 문구
- 사진 전용 카드
- 최근 일지 요약 카드
- 기능 소개 카드
- 추천 콘텐츠
- 오늘의 팁
- 빈 카드
- 사용하지 않는 플레이스홀더
- 큰 배너
- 큰 학생 프로필 카드
- 중복된 수업 시간
- 하단 탭 바
- Home에서 필요하지 않은 바로가기 아이콘
- 일지를 누르도록 유도하는 화살표
- 일지 더보기
- 일지 접기
- 일지 펼치기

컴포넌트 파일 자체는 삭제하지 마세요.
Home 화면에서 import와 렌더링만 제거하세요.

다른 역할 화면에는 영향을 주지 마세요.

========================================
11. 수업일지 피드
========================================

Home 전체는 하나의 세로 FlatList 피드로 구성하세요.

최신 수업일지를 가장 위에 표시하세요.

그 아래에 이전 일지를 날짜 내림차순으로 계속 표시하세요.

사용자가 위로 올리며 스크롤하면:

최신 일지
→ 이전 일지
→ 더 이전 일지
→ 계속 과거 일지

순서로 자연스럽게 보여야 합니다.

각 일지는 독립된 피드 아이템이지만,
하나의 Home 화면 안에서 계속 이어져야 합니다.

========================================
12. 수업일지 표시 순서
========================================

각 수업일지는 아래 순서를 지키세요.

1. 날짜
2. 수업 요일 및 시간
3. 담당 선생님
4. 수업일지 전체 본문
5. 첨부 사진
6. 첨부 영상
7. 좋아요
8. 감사합니다
9. 쪽지달기
10. 다음 일지

사진이나 영상이 본문보다 먼저 나오면 안 됩니다.

========================================
13. 수업일지 본문 규칙
========================================

수업일지 본문은 반드시 전체 표시하세요.

금지:

- numberOfLines
- 말줄임
- 미리보기
- 요약
- 더보기
- 접기
- 펼치기
- 고정 높이
- 본문 내부 스크롤
- 본문을 누르면 상세 화면으로 이동

허용:

- 자연스러운 줄바꿈
- 문단 유지
- 읽기 좋은 lineHeight
- 전체 가로 폭 사용
- 실제 본문 길이에 따른 자연스러운 높이

글이 길어도 잘리지 않아야 합니다.

한 일지가 화면 대부분을 차지해도 정상입니다.

일지를 축소해서 한 화면에 여러 개를 억지로 보여주지 마세요.

========================================
14. 사진 표시 규칙
========================================

사진은 수업일지 본문 아래에 표시하세요.

사진 수에 따른 처리:

- 0장: 사진 영역 미표시
- 1장: 중간 크기, 과도하게 크게 표시하지 않음
- 2장 이상: 2열 그리드
- 최대 10장 전부 표시

사진 10장이면 2열 기준 5줄로 자연스럽게 이어지게 하세요.

사진은 본문보다 작고 보조적인 요소여야 합니다.

금지:

- 사진을 본문 위에 표시
- 사진을 본문 옆에 표시
- 사진 한 장이 화면 전체를 차지
- 가로 슬라이더
- 사진 내부 세로 스크롤
- 사진 전용 중첩 FlatList
- 사진 10장 중 일부만 표시
- +7 형태로 숨김
- 사진 더보기

사진 터치 시 기존 전체화면 보기 기능을 그대로 사용하세요.

========================================
15. 영상 표시 규칙
========================================

영상이 있으면 사진 다음에 표시하세요.

기존 영상 재생 방식과 기존 라우팅을 유지하세요.

영상도 본문보다 먼저 표시하면 안 됩니다.

영상이 없으면 빈 영상 영역을 만들지 마세요.

========================================
16. 좋아요·감사합니다·쪽지
========================================

각 수업일지 하단에 기존 기능을 유지하세요.

- 좋아요
- 감사합니다
- 쪽지달기

기존 API와 상태 처리 방식을 재사용하세요.

새 API를 만들지 마세요.

버튼은 과도하게 크게 만들지 말고,
일지 하단에 한 줄 또는 컴팩트한 형태로 배치하세요.

========================================
17. 하단 탭 제거
========================================

학부모 Home에서는 하단 탭 바를 표시하지 마세요.

단, 기존 라우트와 화면 파일은 삭제하지 마세요.

필요한 기능 이동 경로:

- 알림: Header
- 설정: Header
- 앨범: 학생 정보 행의 앨범 보기
- 수업일지: Home 피드
- 공지: 얇은 공지 배너

관리자·선생님·슈퍼관리자 화면의 탭과 네비게이션은 수정하지 마세요.

========================================
20. 빈 상태 처리
========================================

수업일지가 없는 경우에만 작은 빈 상태를 표시하세요.

예시:

아직 등록된 수업일지가 없습니다.

금지:

- 큰 일러스트
- 큰 카드
- 기능 설명
- 사진 업로드 유도
- 성장 기록 유도
- 과도한 빈 공간

사진이 없는 경우:

- 사진 영역 자체를 표시하지 않음

영상이 없는 경우:

- 영상 영역 자체를 표시하지 않음

공지 없는 경우:

- 배너 영역 자체를 표시하지 않음

========================================

- 빈 레이아웃 점유

오류 시에는 기존 재시도 방식을 유지하세요.

23. 수정 범위 제한
========================================

작업 전 예상 수정 파일을 먼저 보고하세요.

가능하면 다음 범위 안에서 처리하세요.

- app/(parent)/home 관련 파일
- parent Home 전용 컴포넌트
- parent Home 전용 스타일
- parent Home 전용 데이터 훅

공통 컴포넌트를 수정해야 한다면,
수정 이유와 다른 역할에 영향이 없는 근거를 먼저 보고하세요.

승인 없이 공통 파일을 수정하지 마세요.

========================================
24. 검증 시나리오
========================================

다음 항목을 모두 실제 화면 기준으로 검증하세요.

1. 상단 정보 전체가 첫 화면의 30% 이하인지
