# 지난 일지 삭제 기능 최종 검증 지시문

현재 삭제 로직 수정은 완료된 상태입니다.

구현된 내용:

- 삭제 성공 직후 `setDiaries(prev => prev.filter(...))`로 목록에서 즉시 제거
- `setDiarySet`에서도 해당 일지 키 즉시 제거
- 서버 재조회 후 삭제된 ID를 제외한 최신 데이터로 `diaries`와 `diarySet` 전체 교체
- TypeScript 오류 0건
- OTA 미배포 상태

이번 작업에서는 추가 기능을 만들지 말고,
현재 삭제 로직이 앱 재실행 후에도 유지되는지 실제 흐름을 최종 검증하세요.

==================================================
1. 검증 목적
==================================================

삭제 직후 화면에서만 사라지는 것이 아니라,

- 서버에서도 실제 삭제 상태가 유지되는지
- 앱을 종료하고 다시 실행해도 재등장하지 않는지
- 학부모 화면에서도 삭제 상태가 동일하게 유지되는지
- 삭제 후 같은 날짜에 새 일지를 작성할 수 있는지

확인해야 합니다.

==================================================
2. 선생님 지난 일지 삭제 검증
==================================================

다음 순서로 테스트하세요.

1. 동일한 반에 지난 일지를 최소 3개 준비
2. 지난 일지 목록 진입
3. 가운데 위치한 일지 1개 삭제
4. 삭제 완료 메시지 확인
5. 삭제한 일지가 목록에서 즉시 사라지는지 확인
6. 나머지 일지의 순서가 깨지지 않는지 확인
7. 다른 화면으로 이동
8. 지난 일지 목록으로 다시 진입
9. 삭제한 일지가 다시 나타나지 않는지 확인

==================================================
3. 앱 재실행 검증
==================================================

1. 일지 삭제 완료
2. 앱을 백그라운드로만 보내지 말고 완전히 종료
3. 앱 다시 실행
4. 동일한 선생님 계정과 동일한 반으로 이동
5. 지난 일지 목록 확인
6. 삭제한 일지가 다시 나타나지 않는지 확인

삭제한 일지가 재등장한다면 다음을 확인하세요.

- 삭제 API가 실제 서버 레코드를 삭제 또는 비활성화했는지
- 목록 API가 soft-delete 데이터를 반환하는지
- 앱 시작 시 사용하는 캐시가 삭제 전 데이터를 복원하는지
- 다른 목록 API와 현재 재조회 API가 서로 다른지
- 삭제된 일지를 필터링하는 조건이 모든 진입경로에 적용됐는지

단순히 화면에서 다시 필터링하는 방식으로 덮지 말고
재등장 원인을 정확히 찾아 보고하세요.

==================================================
4. 학부모 화면 동기화 검증
==================================================

1. 선생님 화면에서 일지 삭제
2. 연결된 학부모 계정으로 전환
3. 학부모 Home 새로고침
4. 삭제한 일지가 피드에서 사라졌는지 확인
5. 앱 완전 종료 후 다시 실행
6. 삭제한 일지가 다시 나타나지 않는지 확인

학부모 화면에서만 남는다면 다음을 확인하세요.

- 학부모 Home 캐시 무효화 여부
- studentId별 캐시
- diary feed 재조회
- 삭제된 레코드 필터
- 로컬 저장 데이터
- staleTime 또는 초기 캐시 복원

==================================================
5. 삭제 후 같은 날짜 재작성 검증
==================================================

1. 특정 날짜와 수업의 일지 삭제
2. 해당 날짜의 같은 반으로 이동
3. 새 일지 작성
4. 저장
5. 잘못된 중복 경고가 나오지 않는지 확인
6. 새 일지가 지난 일지 목록에 표시되는지 확인
7. 학부모 Home에 새 일지가 표시되는지 확인
8. 앱 재실행 후에도 새 일지만 표시되는지 확인
9. 삭제한 이전 일지가 다시 나타나지 않는지 확인

==================================================
6. 실패 시 롤백 확인
==================================================

삭제 API가 실패하는 상황도 확인하세요.

삭제 요청이 서버에서 실패하면:

- 낙관적으로 제거했던 일지를 목록에 복구
- `diarySet`도 원래 상태로 복구
- 사용자에게 삭제 실패 안내
- 실제로 삭제되지 않은 일지를 사라진 것처럼 유지하지 않음

현재 rollback 처리가 없다면
삭제 API 실패 시 상태 복구만 추가하세요.

다른 기능은 수정하지 마세요.

==================================================
7. 중복 및 상태 정합성 확인
==================================================

다음 상태를 확인하세요.

- `diaries`에는 삭제된 ID가 없음
- `diarySet`에는 삭제된 일지 키가 없음
- 서버 재조회 결과에도 삭제된 항목이 없음
- 목록 key 중복 경고 없음
- 같은 일지가 두 번 표시되지 않음
- 삭제 후 선택된 diary 상태가 남지 않음
- 삭제한 일지 수정 화면으로 다시 진입되지 않음

==================================================

==================================================

삭제 상태 동기화와 rollback 범위 안에서 수정하세요.
