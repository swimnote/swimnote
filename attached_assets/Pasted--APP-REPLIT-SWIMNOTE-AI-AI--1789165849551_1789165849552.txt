SWIMNOTE AI 성장리포트
발급 정책 확정 + 관리자 명단/스케줄러/배치 안정화 작업

이번 작업은 AI 성장리포트가
실제 운영환경에서 월별로 원활하고 오류 없이 발급되도록
발급대상 선정부터 관리자 검수 전 단계까지 정비하는 작업입니다.

중요:
아래 정책은 확정된 운영정책입니다.
임의로 출석률 방식이나 다른 기준으로 변경하지 마십시오.

0. 최종 확정 정책
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

AI 성장리포트는 다음 3개 조건을
모두 만족한 회원에게만 발급합니다.

A.
리포트 발급월에 재등록된 회원

AND

B.
분석 대상월 실제 출석 3회 이상

AND

C.
분석 대상월 유효 학생별 수업일지 3회 이상

즉:

재등록 O
+ 실제 출석 >= 3
+ 유효 수업일지 >= 3

인 경우에만 발급합니다.

이 정책은 절대 기준입니다.

출석률 50% 같은 비율 기준은 사용하지 않습니다.

주1회 / 주2회 / 주3회 회원 모두
동일하게 절대 횟수 3회를 기준으로 합니다.

예:

주1회 월 4회
→ 출석 3회 + 일지 3회면 발급

주2회 월 8회
→ 출석 3회 + 일지 3회면 발급

주3회 월 12회
→ 출석 3회 + 일지 3회면 발급

중간 입회 회원도 동일합니다.

예:

8월 중간에 신규등록한 회원이

8월 실제 출석 3회
+
8월 유효 학생별 일지 3회
+
9월 재등록

이면

9월 AI 성장리포트를 발급합니다.

가입일이 월초인지 월중인지 자체는
발급 제외 사유가 아닙니다.

10. 최종 Eligibility 함수
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

여러 쿼리와 worker에 중복 구현하지 마십시오.

가능하면 하나의 공통 policy/helper로 분리하십시오.

개념:

evaluateGrowthReportEligibility({
  reregistered,
  attendanceCount,
  sourceEventCount,
  manualExcluded
})

결과:

eligible: boolean

exclusionCode:
- NOT_REREGISTERED
- INSUFFICIENT_ATTENDANCE
- NO_SOURCE_DATA
- INSUFFICIENT_SOURCE_DATA
- MANUAL_EXCLUDED
- null

최종 조건:

if manual excluded
→ excluded

else if not reregistered
→ excluded

else if attendance_count < 3
→ excluded

else if source_event_count === 0
→ excluded

else if source_event_count < 3
→ excluded

else
→ eligible

단,
기존 관리자 수동 제외가 설정되어 있다면
scheduler가 자동으로 되살리지 마십시오.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

INSUFFICIENT_ATTENDANCE
NO_SOURCE_DATA
INSUFFICIENT_SOURCE_DATA
MANUAL_EXCLUDED
