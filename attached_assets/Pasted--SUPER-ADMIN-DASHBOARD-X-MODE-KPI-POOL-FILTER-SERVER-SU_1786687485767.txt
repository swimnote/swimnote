==================================================
1. CANONICAL X MODE SOURCE 확인
==================================================

현재 APP Server의 실제 canonical X Mode 판정 구조를 사용한다.

먼저 확인:

- swimming_pools.xmode_entitlement
- xmode_config_status
- approval_status
- resolvePoolMode()
- 현재 repository에서 "X Mode 활성 수영장"의 정확한 판정 기준

새 판정식을 임의 생성하지 마라.

Dashboard / Pool filter 모두
동일 canonical rule을 사용해야 한다.

==================================================
2. DASHBOARD X MODE KPI
==================================================

GET /super/dashboard-stats

응답에 additive field 추가.

예:

stats.xmode_operators
또는 기존 naming convention에 맞는 이름.

의미:

현재 canonical X Mode 활성 상태인 수영장 수.

단순 xmode_entitlement=true만으로
실제 X active가 아닌 경우가 있다면
canonical rule 전체를 적용한다.

예:
entitlement=true
+
config READY
+
approved

등 실제 resolvePoolMode 규칙과 일치시킨다.

Dashboard의 현재 X MODE KPI "—"를
실제 count로 교체한다.

==================================================
3. POOLS SUMMARY X MODE DATA
==================================================

GET /super/pools-summary

각 pool summary에 최소:

xmode_entitlement
xmode_config_status
resolved_mode 또는 실제 equivalent

중 UI/filter에 필요한 최소 정보만 additive 반환.

PII 추가 금지.

==================================================
4. X MODE FILTER
==================================================

기존 pools list filter에:

filter=xmode

지원.

결과:

canonical X Mode 활성 pool만 반환하거나,
현재 endpoint가 client-side filtering 구조라면
필요한 canonical fields를 제공하여
동일한 결과를 만든다.

가능하면 server-side filter 우선.

==================================================
5. CONSISTENCY
==================================================

매우 중요.

다음 세 곳이 서로 다른 기준을 사용하면 안 된다.

- resolvePoolMode()
- dashboard X MODE count
- pools?filter=xmode

동일 pool에 대해:

resolvePoolMode = X

이면:

Dashboard count 포함
+
X MODE filter 결과 포함

이어야 한다.

반대로 X가 아니면 둘 다 제외.
