[SWIMNOTE 학부모 반응 기능 단순화 — 좋아요 단일화 + 하단 3액션]

이번 작업 목표:

기존 학부모 반응 기능

좋아요
감사합니다

두 개를 하나로 통합합니다.

최종적으로 학부모 반응은
"좋아요" 하나만 남깁니다.

UI는 텍스트 없는 하트 아이콘으로 통일합니다.

━━━━━━━━━━━━━━━━━━━━━━
1. 최종 반응 정책
━━━━━━━━━━━━━━━━━━━━━━

삭제:

- 감사합니다 반응
- 감사합니다 버튼
- 감사합니다 알림
- 감사합니다 알림 설정
- 선생님이 받는 감사합니다 알림
- 소식알림의 감사합니다 ON/OFF 옵션

유지:

- 좋아요 반응
- 좋아요 알림
- 선생님이 받는 좋아요 알림
- 소식알림의 좋아요 알림 설정

최종 반응 타입은 사용자에게:

좋아요

하나만 노출합니다.

━━━━━━━━━━━━━━━━━━━━━━
2. 학부모 일지 하단 액션바
━━━━━━━━━━━━━━━━━━━━━━

현재:

[ 👍 ] [ 🙏 ] [ 💬 ] [ Instagram AI ]

변경:

[ ♡ ]       [ 💬 ]       [ Instagram AI ]

총 3개만 표시합니다.

3개 버튼은 동일한 폭으로 균등 배치:

flexDirection: "row"

각 action:
flex: 1
alignItems: "center"
justifyContent: "center"

marginLeft:auto 방식 금지.

3개 중심점 간격이 정확히 동일해야 합니다.

━━━━━━━━━━━━━━━━━━━━━━
3. 좋아요 아이콘
━━━━━━━━━━━━━━━━━━━━━━

기존 👍 이모지 사용 중단.

하트 아이콘으로 변경.

기본 상태:

♡
빈 하트

좋아요 선택 상태:

♥
빨간색 채워진 하트

권장:

Lucide heart 아이콘 사용.

unselected:
- fill="none"
- stroke = 기존 NAVY 또는 dark gray

selected:
- fill = red
- stroke = red

사용자가 다시 탭하면:

selected → unselected

기존 toggleReaction("like") 동작 유지.

기능상 좋아요 toggle 로직은 삭제하지 않습니다.

━━━━━━━━━━━━━━━━━━━━━━
4. 감사합니다 반응 제거
━━━━━━━━━━━━━━━━━━━━━━

UI에서:

toggleReaction("thanks")

버튼 제거.

하지만 바로 DB column/enum/schema를 삭제하지 마십시오.

먼저 기존 서버/DB 구조를 조사합니다.

확인:

- reactions 테이블 구조
- reaction_type enum 또는 문자열
- thanks 데이터가 기존 DB에 존재하는지
- API endpoint가 like/thanks 공용인지
- teacher notification이 reaction_type을 사용하는지

기존 데이터 파괴 금지.

이번 단계 기본 원칙:

"thanks 신규 생성 경로와 노출만 제거"

기존 과거 thanks 데이터는
DB migration 없이 그대로 보존 가능하면 보존합니다.

━━━━━━━━━━━━━━━━━━━━━━
5. 선생님 알림
━━━━━━━━━━━━━━━━━━━━━━

현재 선생님에게:

- 좋아요 알림
- 감사합니다 알림

이 각각 들어오는 구조를 조사합니다.

최종:

좋아요 알림만 생성.

감사합니다 알림 신규 생성 금지.

예:

학부모가 좋아요
→ 담당 선생님에게 좋아요 알림

학부모가 감사합니다
→ 이제 UI 자체가 없으므로 신규 발생 없음

기존 과거 감사합니다 알림은
삭제하지 않습니다.

━━━━━━━━━━━━━━━━━━━━━━
6. 선생님 알림 UI
━━━━━━━━━━━━━━━━━━━━━━

선생님 알림 목록에서
새로운 감사합니다 이벤트를 만들지 않도록 합니다.

기존 과거 알림이 DB에 남아 있다면
기존 기록 조회까지 강제로 삭제하지 말고
현재 정책상 어떻게 처리할지 먼저 보고하십시오.

권장:

과거 알림은 기록으로 유지
신규 thanks 발생만 차단.

14. CASE 테스트
━━━━━━━━━━━━━━━━━━━━━━

CASE 1
학부모 일지 최초 진입
→ 빈 하트 표시

CASE 2
빈 하트 탭
→ 빨간 채운 하트
→ 좋아요 저장
→ 선생님 좋아요 알림 생성

CASE 3
빨간 하트 다시 탭
→ 빈 하트
→ 좋아요 취소

CASE 4
감사합니다 버튼
→ UI에 존재하지 않음

CASE 5
신규 감사합니다 알림
→ 생성되지 않음

CASE 6
선생님 알림
→ 좋아요만 정상 수신

CASE 7
소식알림 설정
→ 좋아요 설정만 표시
→ 감사합니다 설정 없음

CASE 8
댓글
→ 정상 진입

CASE 9
Instagram AI
→ 정상 Story 공유

CASE 10
액션바
→ 3개 균등 배치

CASE 11
과거 thanks 데이터 존재
→ 앱 crash 없음
→ 신규 기능에 영향 없음
