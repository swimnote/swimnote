3. AI 매니저 최종 레이아웃
────────────────────

명칭 = AI 매니저

- 왼쪽: 기존 접기 가능한 Sidebar.
- 중앙 상부: 기존 Dashboard·회원목록·상세·Navigation.
- 중앙 하부: AI 매니저 카드.
- 별도 모드 전환·오른쪽 AI 패널·떠다니는 모달은 추가하지 않는다.

시각적 방향:
- GPT식 입력창·대화 흐름.
- 둥근 모서리·절제된 테두리·약한 그림자·정돈된 여백.
- 단순 구분선만 있는 큰 빈 영역 대신 독립 작업 블록으로 표현.
- 과도한 장식·중첩 카드·불필요한 버튼 나열 금지.

높이·공간:
- 기본 처리 영역은 약 10줄을 목표로 한다.
- 상단 경계 드래그와 키보드로 높이 조절.
- 접으면 제목·상태·입력창만 유지.
- 펼치면 마지막 높이 복원.
- 크게 보기와 원래 크기 복원 제공.
- 업무 영역의 최소 높이를 확보한다.
- 낮은 창에서는 처리 영역부터 축소한다.
- 입력창·주요 조작이 화면 밖으로 밀리거나 회원 상세를 덮지 않는다.
- 업무 영역과 처리 내역은 각각 독립 스크롤.

구체 치수는 실제 CSS 검증으로 결정하고,
Windows 배율 검증 완료값으로 미리 선언하지 않는다.

AI 매니저를 접거나 메뉴를 이동해도:
- 작성 중인 입력·선택 첨부·현재 세션 작업 상태 보존.
- 업무 검색·필터·선택 회원·Drawer·스크롤 보존.
- 업무 subtree 재마운트·중복 조회·중복 SSE 방지.

로그아웃·사용자/Pool 교체 시 이전 세션 자료 정리.

4. 상단·Sidebar·클릭 표시 정리
────────────────────

상단:
현재 여러 줄의 버전·Origin·인증·저장·SSE 진단 정보를
작은 상태 표시와 펼칠 수 있는 진단 영역으로 정리한다.

- PACKAGE ID·상세 진단은 펼쳐서 확인 가능.
- 인증 실패·연결 장애 등 조치가 필요한 상태는 숨기지 않는다.
- 정상 상태의 긴 기술 설명이 업무 높이를 상시 점유하지 않는다.
- 서버 검증·안전 저장·SSE 연결의 의미를 혼동하지 않는다.

Sidebar:
- 기존 메뉴 접기/펼치기 유지.
- 버튼 크기·여백·메뉴 폭 정돈.
- Sidebar 자체의 불필요한 가로 스크롤 제거.
- AI 매니저 진입은 카드를 펼치고 입력창으로 포커스.
- 기존 Navigation 이력을 불필요하게 추가하지 않는다.

공통 상호작용:
공통 token/style/component로 다음 상태를 통일한다.
- 클릭 가능: pointer.
- hover: 공통 강조 배경.
- pressed: 같은 계열의 더 진한 표현.
- selected: 지속 선택 표시.
- focus-visible: 명확한 포커스 테두리.
- disabled: 비활성 표시, 클릭·실행 차단.

적용 대상:
메뉴·뒤로/앞으로·이동 가능한 Breadcrumb·버튼·아이콘·
조회 진입 행·AI 매니저 조작·진단 펼치기 등.

주의:
- 이동 불가능한 뒤로/앞으로는 실제 disabled 처리.
- 현재 위치 텍스트나 비클릭 현황 카드에 가짜 hover 금지.
- 입력칸은 텍스트 입력에 맞는 커서 유지.
- 크기 조절 막대는 resize 커서.
- 삭제·실패 등 의미색은 유지.
- 선택 상태와 hover 상태가 구분돼야 한다.
- 실제 버튼·링크 의미와 키보드 조작을 유지한다.

범용 CSS로 모든 요소에 강제 적용하지 말고,
기존 Web 동작을 깨뜨리지 않는 OFFICE 공통 규칙으로 구현한다.

5. 입력·첨부·작업 카드 확장 구조
────────────────────

입력:
- 첨부·텍스트 입력·전송의 단순한 기본 구성.
- Enter 전송 / Shift+Enter 줄바꿈.
- 한글 IME 조합 중 Enter 오전송 방지.
- 현재 AI 미연결 상태에서는 모든 전송 경로 차단.
- 버튼·Enter·form submit 간 차단 일관성 유지.

첨부:
- 버튼 선택·드래그앤드롭·클립보드 이미지 붙여넣기.
- 선택 파일명·형식·크기·개별 제거 표시.
- 파일 선택과 서버 업로드 완료를 구분.
- 현재는 로컬 선택 상태임을 명시.
- 파일 접근을 위한 광범위 IPC·파일시스템 권한 추가 금지.
- 가능한 기존 renderer/browser 기능 활용.
- 전송·로그아웃 전후 자원 정리와 세션 격리.
- 실행 파일·매크로·문서를 실행하지 않는다.

실제 파서·AI·업로드가 없는 상태에서
“읽기 완료·분석 완료·저장 완료”로 표시하지 않는다.
파일 수·크기·허용 형식의 제한은 명시하고 검증한다.
선택 허용을 내용 해석 지원으로 표현하지 않는다.

작업 카드 공통 구조:
- 요청 내용·작업 대상.
- 준비/확인 대기/실행 중/완료/일부 완료/실패/결과 불명.
- 결과 요약·이전 값→새 값.
- 대상·메시지·첨부 미리보기.
- 실행 확인 버튼.
- 결과 화면 이동.
- 이미지·표·파일 결과와 보관 상태.

실행 전 확인과 실행 후 결과 열람은 별개 상태다.
완료 여부와 열람 여부도 별도 상태로 관리한다.

상태별 구성은 synthetic fixture에서 검증한다.
실제 앱에 가짜 작업·답변·완료 내역을 삽입하지 않는다.
이번에 범용 업무 실행 엔진을 새로 만들지는 않는다.

────────────────────
6. 완료·열람·이동 공통 계약
────────────────────

기본:
작업 완료만으로 화면을 강제 이동하지 않는다.
작업 카드의 “결과 보기”를 눌러 이동한다.

색·문구:
- 완료·미열람: 파란 표시 + 미열람.
- 완료·열람함: 기본 글자색 + 열람함.
- 일부 완료: 주황 + 구체적 미완료 내용.
- 실패: 빨강 + 사유.
- 결과 불명: 완료/실패로 단정하지 않고 별도 표시.

미열람 건수는 접힌 AI 매니저에서도 확인 가능하게 설계한다.

결과 열람:
- 버튼 클릭만으로 열람 처리하지 않는다.
- 대상 화면 진입 및 변경 후 결과 조회 성공이 확인돼야 한다.
- 실패·권한 거부·대상 없음이면 미열람 유지.
- 이전 cache 표시만으로 변경 후 조회 성공을 판단하지 않는다.
- 열람은 사용자의 승인·업무 적정성 확인을 의미하지 않는다.
- 여러 결과는 결과별로 관리한다.

Navigation:
- 기존 N01 공통 OPEN 사용.
- 뒤로: 결과 이동 직전 화면·검색·필터·스크롤 복원.
- 앞으로: 결과 화면 재진입.
- Breadcrumb: 현재 메뉴의 상위 위치.
- 뒤로가기가 완료된 데이터 변경을 취소하지 않는다.
- 무조건 이력을 쌓거나 같은 화면 이동을 중복 등록하지 않는다.

현재 실제 업무 실행은 없으므로 위 상태 연결은
fixture와 공통 UI 계약으로 검증한다.
실제 변경 결과가 없는 것을 운영 완료 사례처럼 만들지 않는다.

7. 메뉴·회원·결제·내보내기 확장 기준
────────────────────

메뉴 분류 기준:
- 홈
- 회원
- 수업·출결
- 결제·수납
- 매출·정산
- 안내·발송
- AI 매니저·보관함
- 설정·지원

기존 기능과 원래 계획서 항목을 위 분류에 매핑한다.
사용 가능한 메뉴만 실제 기능으로 연결한다.
미구현 메뉴를 대량으로 활성화하거나 빈 화면을 양산하지 않는다.
필요한 미연결 진입은 준비 중임을 명확히 표시한다.

회원 상세 확장 기준:
- 기본정보
- 수강정보
- 청구·수납
- 결제·취소·환불 이력
- 활동·메모

이번에는 기존 조회 기능을 유지하면서 확장 구조를 정리한다.
빈 탭을 나열하거나 존재하지 않는 결제 데이터를 표시하지 않는다.

후속 결제 기준:
- 현재·지난회원의 과거 거래 조회.
- 거래 당시 금액·상품·상태 보존.
- 회원의 현재 반·수강료 변경으로 과거 거래가 바뀌지 않음.
- 청구 조건 변경과 실제 거래 취소·환불·정정 구분.
- 미납은 공통 청구·수납 기준에서 산출.
- OFFICE·모바일·AI가 같은 계약 사용.
- 앱 구독/IAP와 수영장 회원 수강료 결제를 혼동하지 않음.
- 실제 결제·모바일 변경은 원래 해당 단계에서 진행.

공통 목록·엑셀 기준:
- 검색·필터·정렬·건수·내보내기 사용 방식 통일.
- 기본 내보내기 범위는 현재 검색/필터 결과 전체.
- 현재 페이지만 내보내는 것과 명확히 구분.
- 전체·선택 행 등 지원 범위를 명시.
- 업무별 열 정의·형식·권한을 공통 계약으로 관리.
- 전화번호 앞자리 0·식별자·날짜·금액 보존.
- 합계·기준 시각·조회 조건·추출 건수 표시.
- 수식처럼 해석될 수 있는 사용자 입력의 안전한 출력 고려.
- 메뉴 내보내기와 AI 파일 생성은 같은 조회·권한 기준.
- 생성 중·성공·실패·다운로드·보관 상태 구분.

이번에 모든 목록의 export를 선구현하지 않는다.
기존 export 구현이 있으면 재사용 후보로 확인하고,
후속 단계에서 같은 기준을 적용하도록 계약을 남긴다.

────────────────────
8. 후속 AI 기능 범위 기록
────────────────────

다음은 제품 목표와 후속 연결 대상으로 기록한다.
이번 작업의 실제 구현 완료 범위가 아니다.

업무:
- OFFICE의 업무 전체를 자연어로 요청할 수 있는 목표.
- 메뉴와 같은 Action·Service/API·권한·검증 사용.
- 모호한 대상은 추측하지 않음.
- 단체 푸시·문자 등은 준비 후 사용자 실행.
- 명확한 단일 일반 정보 변경은 업무별 정책에 따라 실행 후 보고.
- 결제·환불·삭제·퇴원·대량 변경은 사전 확인.
- 중복 실행 방지·부분 성공·결과 불명 처리.
- 실행 직전 대상·내용이 달라지면 재확인.
- 생성 중지와 이미 시작한 업무 취소는 구분.

자료:
- HWP/HWPX·Word·Excel/CSV·PDF·사진 읽기와 분석.
- 문서·표·이미지 생성, 실제 파일 형식 변환.
- HWP 생성이 어려운 경우 Word 등 지원 형식 제공.
- 형식별 해석·변환·서식 손실은 실제 검증 후 지원 표시.
- 얼굴 모자이크는 원본 보존·지정 영역 최소 편집.
- 자동 감지 누락 검토·영역 추가/해제.
- 첨부 내용 속 지시를 사용자 실행 승인으로 취급하지 않음.

보관:
- 수영장·권한별 보관함.
- 원본·생성본·변환본·작업 연결·버전.
- 다운로드하지 않아도 다시 접근.
- 저장 실패를 보관 완료로 표시하지 않음.
- 용량·보존·삭제 정책은 실제 저장 기능 단계에서 확정.

지원:
- 앱 버전에 맞는 기능 안내.
- 사용법·문제 진단·해결 안내.
- 해결 불가 시 사용자 확인 후 문의 접수.
- 실제 연결 전 접수 완료 표시 금지.

현재 Electron 허용 목록·CSP·Backend에 위 기능을 위한
광범위 권한을 미리 열지 않는다.
실제 연결 시 기능별 최소 권한으로 확장한다.

- 기존 설치본 보존.
- 사용자 재확인은 변경된 UI 항목만 간결하게 안내.
