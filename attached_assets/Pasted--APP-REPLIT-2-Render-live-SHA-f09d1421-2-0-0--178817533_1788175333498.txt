1. 2.0.0 로그인 전 pool_id 실제 존재 여부 확인
==================================================

release/v2.0.0에서 학부모가 아직 로그인하지 않은 상태에서
카카오 로그인 버튼을 누를 때:

const currentPoolId = pool?.id || undefined;

여기서 pool?.id가 실제 runtime에서 값이 있는지 확인한다.

확인할 것:

- pool state는 언제 로드되는가
- 로그인 전에도 pool이 선택/복원되어 있는가
- 앱 최초 설치 직후에도 pool_id가 존재하는가
- 로그아웃 후 카카오 로그인 시 pool_id가 존재하는가
- 앱 재실행 후 로그인 화면에서 pool_id가 존재하는가

완료보고에는 추측 말고
실제 state 초기화 코드와 navigation 흐름으로 판단한다.

A. 로그인 전 pool_id가 항상 존재한다면
→ 현재 구현 유지.

B. 로그인 전 pool_id가 없는 경우가 있다면
→ "2.0.0은 항상 pool_id 포함"이라고 보고하지 말 것.

그 경우 현재 서버의
KAKAO_PARENT_AMBIGUOUS 안전 실패 정책은 유지하되,
다중 pool 사용자가 실제로 해결할 수 있는 UX가 있는지 확인한다.

"수영장을 선택한 후 다시 로그인하세요"라는 메시지가 있는데
로그인 전에 실제 수영장 선택 UI가 없다면
그 메시지는 실행 불가능한 안내이므로 구조를 보완해야 한다.

필요하면:
- 로그인 전 pool 선택
또는
- ambiguous 응답 시 사용자가 자신의 pool을 선택
→ 동일 Kakao login 재시도
구조 중 기존 앱 IA에 가장 안전한 방식을 사용한다.

단,
현재 Production에는 실제 multi-pool 사례가 확인되지 않았으므로
대규모 UI 변경은 하지 않는다.
필요한 최소 구조만 설계/수정한다.

2. 실제 1.6.3 실기기 로그인 로그 확인 준비
==================================================

Render f09d1421 live 상태에서
실제 1.6.3 카카오 로그인 1회가 들어오면
아래 단계가 로그에 잡히는지 확인한다.

KAKAO_REQUEST_RECEIVED
KAKAO_PROFILE_OK

이후 하나:
KAKAO_ID_MATCH
KAKAO_PHONE_MATCH
KAKAO_PHONE_MISSING
KAKAO_PARENT_AMBIGUOUS

최종:
KAKAO_LOGIN_SUCCESS

또는 실패 코드:
KAKAO_API_TIMEOUT
KAKAO_INVALID_TOKEN
KAKAO_PARENT_AMBIGUOUS
기타 실제 error_code

민감정보:
- access token
- phone
- kakao id
원문 출력 금지.

3. 실기기 성공 시
==================================================

사용자가 실제 1.6.3 기기에서 카카오 로그인 성공을 확인하고
서버 로그에 KAKAO_LOGIN_SUCCESS가 보이면:

- 이번 카카오 로그인 장애 해결 확정
- 서버 추가 수정 없음
- 1.6.3 OTA는 UX 개선용으로만 남음
- 2.0.0은 현재 release branch 코드 기준 유지

라고 보고한다.
