2. MEDIA — 기존 백엔드 우선 재사용
==================================================

현재 확인:

GET /photos/private/:studentId

기존 backend endpoint 존재.

따라서 media는
새 backend를 만들 이유가 없습니다.

기존 endpoint의:

- permission
- pool isolation
- teacher access
- returned media semantics

를 그대로 사용.

==================================================
3. MEDIA APP SCREEN 최소 확장
==================================================

현재:

app/(teacher)/photos.tsx

가 studentId route param을 받지 않아
Teacher 자신의 일반 private album context로 동작.

이를 최소 additive하게 확장.

예:

/(teacher)/photos?studentId=<id>

로 진입하면:

GET /photos/private/:studentId

를 사용하여
해당 학생의 사진/영상만 표시.

studentId가 없으면:

기존 photos.tsx 동작 그대로.

즉 backward compatibility:

studentId 없음
→ 기존 화면

studentId 있음
→ student-scoped mode
