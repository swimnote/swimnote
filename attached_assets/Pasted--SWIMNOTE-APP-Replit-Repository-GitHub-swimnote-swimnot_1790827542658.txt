1. 조사할 목표 운영 흐름
━━━━━━━━━━━━━━━━━━━━━━

최종적으로 만들 시스템의 시간축은:

매월 1일
→ 전월 리포트 cycle 자동 준비 시작

1일~4일
→ 대상자 산출
→ snapshot 생성
→ ENGINE 분석
→ 성공 결과 저장
→ 실패 항목 재시도
→ restart/recovery
→ 성공 결과 보존
→ 중복 GPT 방지

5일
→ 관리자가 해당 월 리포트들을 확인할 수 있는 상태

이다.

이번 WP에서는 이것이 현재 코드에서
어디까지 구현돼 있는지만 조사한다.

아직 원하는 동작으로 수정하지 않는다.

무료 월간 AI 성장리포트와 관련된 모든:

- scheduler
- cron
- startup recovery
- worker
- cycle preparation
- batch preparation
- retry
- recovery

코드를 추적한다.

정확히 보고:

A. 매월 몇 일 몇 시에 시작되는가
B. timezone은 무엇인가
C. 1일 자동 시작이 현재 존재하는가
D. 서버 restart 시 미완료 cycle을 복구하는가

F. 이미 성공한 학생을 다시 분석하지 않는가
G. 실패한 학생만 재시도 가능한가
H. retry 횟수/간격/종료 조건
I. process crash/restart 후 이어서 처리 가능한가

4. 5일 동작 집중 조사
━━━━━━━━━━━━━━━━━━━━━━

가장 중요하다.

현재 코드에서 매월 5일에:

- 자동 PUBLISHED 되는가
- 관리자 승인 없이 학부모에게 공개되는가
- parent feed가 생성되는가
- PUSH가 자동 발송되는가
- 어떤 scheduler/job이 실행하는가
- 몇 시에 실행하는가
- 실패 후 재실행되는가
- 중복 publish 방지가 있는가
- 중복 PUSH 방지가 있는가

를 코드 근거로 정확히 확인한다.

"관리자가 5일에 확인 가능"과
"5일 자동 학부모 공개"를
절대 같은 의미로 취급하지 않는다.

현재 구현 사실을 각각 분리해서 보고한다.

- 발급월 M은 전월 M-1 분석
- Asia/Seoul
- 전월 1일 00:00 KST 이상

- 전월 class-history overlap
- 다음 달 1일 active/continuing 조건

- scheduled lessons - absences + completed makeups
- holiday/no-class 미포함

- 공통 수업내용만으로 diary 조건 충족 금지

- 이미 PUBLISHED된 리포트는 이후 퇴원해도 row 보존
- 실패/invalid/processing 상태 publish 금지

9. 최종 GAP 분석
━━━━━━━━━━━━━━━━━━━━━━

목표:

1일 자동 준비
→ 1~4일 분석/재시도/복구
→ 5일 관리자 확인 가능

과 현재 구현을 비교한다.

각 항목을:

PASS = 이미 정확히 구현
PARTIAL = 일부 구현
MISSING = 없음
CONFLICT = 현재 구현이 목표와 충돌

중 하나로 판정한다.

특히 별도 판정:

A. 1일 자동 시작
B. 1~4일 지속 처리
C. restart recovery
D. 실패-only retry
E. 성공 결과 보존
F. duplicate GPT 방지
G. 5일 관리자 조회
H. 5일 자동 parent publish
I. 관리자 승인 기능 존재 여부
J. parent feed/PUSH 시점
K. 다음 달 자동 새 cycle
L. 장기 반복 실행 안전성
