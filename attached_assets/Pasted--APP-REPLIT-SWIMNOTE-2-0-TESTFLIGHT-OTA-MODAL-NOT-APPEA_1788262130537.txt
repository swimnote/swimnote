# SWIMNOTE 2.0
# TESTFLIGHT OTA MODAL NOT APPEARING — DIAGNOSIS ONLY

현재 SWIMNOTE 2.0 개발 정책:

TestFlight Build 252에서
새 OTA update를 수신하면

앱 내부 개발용 Update Modal이 표시되고

사용자가:

"앱 재실행하기"

버튼을 눌러
새 OTA를 적용하는 구조입니다.

현재 문제:

production-v2 OTA는 publish 되었다고 보고되었으나
실기기에서 해당 Update Modal이 나타나지 않습니다.

따라서 이번 작업은:

"왜 2.0 TestFlight Build 252가
production-v2 OTA를 감지하지 못하는지"

진단하는 작업입니다.

새 OTA 발행 금지.
새 build 생성 금지.
코드 수정 금지.

==================================================
1. 현재 기대 동작 확인
==================================================

현재 앱에서 OTA 처리 흐름을 실제 코드로 확인하십시오.

확인할 것:

- expo-updates 또는 Updates API 사용 여부
- checkForUpdateAsync 호출 위치
- fetchUpdateAsync 호출 위치
- reloadAsync 사용 여부
- update available modal을 띄우는 조건
- 앱 시작 시 OTA 체크 시점
- foreground 복귀 시 재확인 여부
- update check 실패 시 로그 처리

완료보고에 실제 파일/함수 기준으로 설명.

6. Update Modal 코드 감사
==================================================

현재 개발용 modal이
어떤 조건에서 뜨는지 확인.

예:

if (update.isAvailable) {
  fetchUpdateAsync()
  setShowUpdateModal(true)
}

같은 구조인지 실제 코드 기준으로 확인.

특히 확인:

- __DEV__ 조건에 묶여 있는가
- production/TestFlight에서는 modal code가 제거되는가
- appVersion 2.0.0에서만 활성화되는가
- 특정 channel에서만 활성화되는가
- production-v2에서 정상 활성화되는가
- AsyncStorage/local flag 때문에 이미 본 update로 처리되는가
- update ID 비교 조건이 잘못되어 있는가

==================================================
7. TestFlight에서 modal이 실제 동작 가능한지 확인
==================================================

중요:

TestFlight build는 일반적으로 __DEV__ = false일 수 있습니다.

따라서 현재 "개발중 OTA modal"이

__DEV__

조건 내부에 있다면
TestFlight에서는 절대 뜨지 않을 수 있습니다.

반드시 실제 코드를 확인.

만약 그렇다면:

ROOT CAUSE:
MODAL DISABLED IN TESTFLIGHT

라고 보고.

수정은 아직 하지 마십시오.

9. 자동 update check 실행 여부
==================================================

TestFlight 앱 실행 시
실제로:

Updates.checkForUpdateAsync()

가 호출되는지 확인.

호출 조건이:

- development build only
- admin only
- 특정 role only
- 특정 env only

등으로 제한되어 있지 않은지 확인.

11. 이미 동일 update로 판단되는지 확인
==================================================

현재 앱의 embedded update 또는 cached update와
01a05cb1 update가 동일/이전으로 판단될 가능성 확인.

확인:

- current update ID
- embedded update ID
- latest OTA update ID
- createdAt
- manifest metadata

현재 Build 252가 이미 01a05cb1을 받고 있는 상태인데
UI만 구버전처럼 보이는지도 확인.

12. 캐시/rollback 여부 확인
==================================================

launch 실패 후 rollback했는지 확인.

가능한 경우:

- failed launch count
- rollback marker
- rejected update
- runtime error

확인.
