[SWIMNOTE 선생님 알림 허브 확장 — 소식 / 쪽지함 / 학부모 요청]

현재 선생님 홈의 편지 아이콘과
쪽지보관함 구조를 확장한다.

이번 목표는 기존 기능을 깨지 않고
선생님용 알림 허브를 만드는 것이다.

최종 탭:

[소식] [쪽지함] [학부모 요청]

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. 홈 아이콘 변경
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

현재 선생님 홈의 편지 모양 아이콘을
알림/소식 성격의 아이콘으로 변경한다.

기존 envelope-only 개념이 아니라
다음 전체 unread를 나타내는 허브다.

- 소식 unread
- 쪽지 unread
- 학부모 요청 unread
- 학부모 요청 대화 unread

하나라도 있으면 빨간점/배지 표시.

기존 홈 layout을 크게 변경하지 않는다.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2. 기존 쪽지보관함을 알림 허브로 확장
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

현재:

[쪽지함] [학부모 요청]

을:

[소식] [쪽지함] [학부모 요청]

3개 탭으로 변경한다.

소식 탭을 맨 앞에 둔다.

기존 쪽지함/학부모 요청 기능은 그대로 유지.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
3. 소식 탭 역할
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

소식은 업무 요청이나 일반 메시지가 아니다.

선생님의 수업/피드에 대한
학부모 반응 및 활동 알림을 모은다.

최소 이벤트:

A. diary_like
학부모가 일지에 좋아요

B. diary_thanks
학부모가 일지에 감사합니다

C. diary_comment
학부모가 일지 댓글 작성

D. instagram_share
향후 학부모가 일지를 Instagram에 공유

이번 구현에서는 현재 실제 존재하는
좋아요 / 감사합니다 / 일지댓글부터 연결한다.

Instagram 공유는
아직 공유 기능이 구현되지 않았다면
event type/확장 구조만 고려하고
가짜 알림을 만들지 않는다.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
4. 소식 데이터 Source of Truth
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

먼저 현재 Repository에서 실제 이벤트 저장 구조를 확인한다.

확인 대상:

- 일지 좋아요 저장 API/table
- 감사합니다 저장 API/table
- diary comment API/table
- notifications 관련 기존 table
- teacher recipient 식별 방식

가능하면 기존 notifications 또는
현재 활동 이벤트 저장 구조를 재사용한다.

동일 반응을 위해 새 DB를 불필요하게 만들지 않는다.

하지만 현재 선생님용 소식 저장 구조가 전혀 없다면
최소 schema/API를 설계해 구현한다.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
5. 좋아요 알림
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

학부모가 받은 일지에서
좋아요를 누르면:

반응 저장 성공
↓
해당 일지 담당 선생님에게 소식 생성
↓
Teacher unread 증가
↓
홈 알림 아이콘 빨간점
↓
소식 탭에 표시

표시 예:

"서태웅 학부모님이 수업피드에 좋아요를 눌렀습니다."

학생명/학부모명은
현재 실제 데이터 구조에서 안전하게 가져온다.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
6. 감사합니다 알림
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

학부모가 감사합니다를 누르면:

"서태웅 학부모님이 수업피드에 감사합니다를 보냈습니다."

형태로 소식 생성.

좋아요와 별도 event type.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
7. 일지 댓글 알림
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

→ 해당 일지 담당 선생님에게 소식 생성

예:

"서태웅 학부모님이 수업피드에 댓글을 남겼습니다."

필요하면 preview 1~2줄 표시.

댓글 전체를 소식 카드에 길게 표시하지 않는다.

8. Instagram 공유 소식 확장
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

11. unread
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

소식의 unread를 별도로 관리한다.

홈 알림 허브 배지:

totalUnread =
  unreadNews
+ unreadMessages
+ unreadParentRequests
+ unreadParentRequestMessages

기존 unread count를 제거하지 않고 합산.

소식 확인 시 해당 소식만 read 처리.

전체를 자동 읽음 처리하지 않는다.

15. 기존 기능 보호
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

알림 구현 때문에 변경하지 않는다.

16. 중복 알림 방지
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

좋아요/감사합니다 토글 구조를 확인.

예:

좋아요 ON
→ news 생성

좋아요 OFF
→ 새 news 생성 금지

다시 ON
→ 정책에 따라 중복 여부 결정.

최소한 동일 action 요청이 중복 호출되어
알림이 여러 개 쌓이지 않게 idempotency 적용.

댓글은 실제 새 댓글 1개당 소식 1개.
