[P0 BLOCKER — X_TRIAL ACTIVE BUT X FEATURES STILL ACT LIKE BASE]

실기기 iOS 확인:

구독관리 화면에는 정상적으로
- "X AI 기능 무료체험 중"
- 종료일
- "체험 중"

이 표시됨.

따라서 trial activation / DB / ModeContext 문제는 해결됨.

그러나 사용자가 앱을 사용할 때 여전히 일반 SWIMNOTE처럼 동작한다고 확인.

목표:
mode=x_trial 상태에서
정책상 trial 허용된 모든 X 기능이 실제로 활성화되게 한다.

1. 원인 추적
━━━━━━━━━━━━━━━━━━━━━━

앱/서버 전체에서 다음 패턴을 targeted search:

mode === "x"
mode !== "x"
isXMode
xmode
requireX
X entitlement guard

등.

특히 feature access를
paid X와 잘못 동일시한 곳 확인.

절대:

mode === "x" = paid

로 해석하지 말 것.

확정 의미:

feature access:
canonical mode resolver 기준

paid:
x_paid_entitlement

manual:
x_manual_entitlement

HQ:
x_management_override

trial:
mode === "x_trial"

2. X_TRIAL 기능 정책
━━━━━━━━━━━━━━━━━━━━━━

x_trial은:

BASE 기능 전체 유지
+
trial 허용 X 기능 활성

최소 기존 확정 trial 범위:

- X AI Diary
- X Growth 관련 trial 허용 기능
- AI Growth Report trial+READY
- X UI/설정 중 trial에서 보여야 하는 영역

단:

- paid entitlement 전용 기능
- AI Insight 유료 구매
- DATA add-on
- 정식 X 계약/결제 상태 전용 기능

은 trial로 위조하지 말 것.

━━━━━━━━━━━━━━━━━━━━━━
3. 공통 ACCESS RESOLVER
━━━━━━━━━━━━━━━━━━━━━━

이미 canonical feature-access helper가 있으면 그것을 사용.

없으면 대규모 refactor 금지.

최소한 반복되는:

mode === "x"

조건에서
feature access 의미인 경우만:

mode === "x" || mode === "x_trial" || 기존 허용 상태

로 canonical 정책에 맞게 수정.

중요:
billing/paid 판정 조건까지 x_trial을 포함시키면 FAIL.
