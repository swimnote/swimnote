현재 수영·훈련용어 APP 구현은 유지한다.

단,
현재 보고된:

"PROFESSIONAL_ENGINE_BASE_URL 미설정 시 자동 mock 모드"

구조는 Production 안정성 기준에서 허용하지 않는다.

환경변수/ENGINE 연결 문제를
가짜 샘플 데이터로 정상처럼 보이게 해서는 안 된다.

이번 작업은 해당 부분만 안전하게 정리한다.

━━━━━━━━━━━━━━━━━━━━
1. Production Mock 자동 fallback 제거
━━━━━━━━━━━━━━━━━━━━

Production에서는:

PROFESSIONAL_ENGINE_BASE_URL 미설정
ENGINE 연결 실패
ENGINE timeout
ENGINE 5xx

어떤 경우에도
20개 sample term을 사용자에게 반환하면 안 된다.

반드시 실제 오류로 처리한다.

예:

ENGINE 설정 없음
→ ENGINE_UNAVAILABLE 또는 CONFIGURATION_ERROR

ENGINE 연결 실패
→ ENGINE_UNAVAILABLE

APP:
→ 기존 오류 UI + 재시도

샘플 데이터를 실제 검색결과처럼 반환 금지.

━━━━━━━━━━━━━━━━━━━━
2. Mock은 개발/테스트에서만 허용
━━━━━━━━━━━━━━━━━━━━

20개 sample fixture 자체는
개발과 테스트를 위해 유지 가능.

단 아래처럼 명시적인 조건에서만 사용:

- test environment
또는
- explicit development flag

예:
TERMINOLOGY_USE_MOCK=true

그리고 Production에서는
이 flag가 켜져 있어도 차단하는 방식을 우선 검토.

중요:
"환경변수가 없으니까 mock"
방식은 제거.

Mock 사용은 반드시 의도적이어야 한다.

━━━━━━━━━━━━━━━━━━━━
3. Gateway Source of Truth
━━━━━━━━━━━━━━━━━━━━

실서비스:

APP
→ SWIMNOTE API Gateway
→ Professional Engine
→ Terminology DB

이 경로만 정상 상태.

ENGINE이 없으면
기능이 준비되지 않은 것으로 처리.

가짜 fallback 금지.

━━━━━━━━━━━━━━━━━━━━
