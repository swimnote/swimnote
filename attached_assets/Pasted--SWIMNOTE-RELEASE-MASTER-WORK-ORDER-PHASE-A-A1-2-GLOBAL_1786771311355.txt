==================================================
0. DESIGN GOAL — FIXED
==================================================

SWIMNOTE 전체 디자인 목표:

1. 고급스럽다
2. 차분하다
3. 묵직하다
4. 밝고 깨끗하다
5. 눈이 편하다
6. 기능을 찾기 쉽다
7. 색상이 난잡하지 않다
8. 불필요한 테두리가 없다
9. 화면마다 같은 UI 문법을 사용한다
10. 초보자가 개별 화면마다 꾸민 느낌이 없어야 한다

중요:

"묵직하다" = Dark Theme가 아니다.

전체 화면을 어둡게 만드는 방향 금지.

기본은:

- 밝은 surface
- white/off-white background
- navy text
- 낮은 채도
- 제한된 색상
- 충분한 여백
- 명확한 typography hierarchy

이다.

2. BORDER RULE AUDIT
==================================================

전체 Repository에서 다음을 조사한다.

borderWidth
borderColor
borderTopWidth
borderBottomWidth
borderLeftWidth
borderRightWidth
outline
stroke

각 사용처를 다음으로 분류:

A. STRUCTURAL_REQUIRED

예:
- calendar grid
- scheduler time/grid
- table
- chart boundary
- segmented control
- input/select
- 실제 선택영역

→ 유지 가능

B. INTERACTION_REQUIRED

예:
- 선택 가능한 control
- unchecked checkbox
- focused input

→ 필요 최소한으로 유지

C. SEMANTIC_REQUIRED

예:
- error
- warning
- selected state

→ 의미 전달에 필요하면 유지

D. DECORATIVE

단순히 카드처럼 보이게 하기 위한 테두리

→ 제거 후보

E. REDUNDANT

여백/배경/타이포만으로 구분 가능한데
추가로 border가 존재

→ 제거 후보

==================================================
5. COLOR SEMANTIC RULE
==================================================

최종 구현 후보 규칙은 다음이다.

단 이번 Audit에서 구현 금지.

NORMAL SWIMNOTE:

기본:
Navy 중심

Mint:
브랜드 accent / selected / 필요한 일부 active state

SWIMNOTE X:

Steel Blue 중심

상태색은 제품 identity와 분리.

Green:
실제 success/complete만

Amber/Gold:
실제 pending/warning만

Red:
error / destructive / danger만

Gray:
disabled / tertiary / inactive

중요:

다음 이유로 색을 다르게 사용하지 않는다.

- 메뉴가 다르니까
- 화면이 심심하니까
- 아이콘이 다르니까
- 버튼 종류가 많으니까

색에는 항상 의미가 있어야 한다.
