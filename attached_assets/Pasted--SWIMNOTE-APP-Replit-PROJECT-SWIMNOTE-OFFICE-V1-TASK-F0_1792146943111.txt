2. 열린 SSE의 인증 만료·권한 회수
- 기존 token·세션·권한 검증 계약을 먼저 확인.
- 연결 시작 시뿐 아니라 연결 중에도 인증 만료와
  OFFICE 접근에 필요한 현재 권한을 확인할 수 있도록 보완.
- 기존 검증 함수를 재사용하고 새 인증 체계를 만들지 않는다.
- token 만료 이후 연결이 유지되지 않도록 한다.
- 권한 회수·계정 비활성화·Pool 접근 상실의 반영 방식과
  최대 지연을 구체적으로 정하고 보고한다.
- 기존 변경 알림 경로가 있으면 활용.
  주기 조회가 필요하면 연결별 과도한 DB 조회를 피하고
  검사 간격·부하·실패 정책을 명시한다.
- 인증 확인 실패와 일시적 통신 실패를 구분.
- 권한을 확인할 수 없는 상태에서 데이터 전송을 계속하지 않는다.
- 종료 시 listener·timer·DB 자원 정리.
- token을 URL query·로그·이벤트 본문에 노출하지 않는다.
- 기존 Web SSE와 Pool 격리 정책을 보존.

3. 재접속 후 재조회
- 기존 query/cache 구조로 관련 조회를 재동기화.
- 단절 중 이벤트를 놓칠 수 있으므로 재접속 성공만으로
  최신 데이터 확보 완료를 표시하지 않는다.
- 최초 연결과 재연결을 구분하고 재조회 중복을 제한.
- 계정/Pool 변경 후 이전 연결의 응답·재조회 결과가
  새 계정 화면에 반영되지 않도록 한다.
- 서버에 영구 이벤트 재생 기능을 불필요하게 추가하지 않는다.

4. 편집 충돌 보호
- 기존 편집 상태·query 갱신 경로를 확인.
- 재조회나 이벤트로 사용자 입력을 무단 덮어쓰지 않는다.
- 편집 중 원격 변경은 갱신 필요/충돌 상태로 표시.
- 실제 편집 화면이 아직 연결되지 않았다면
  공통 처리와 격리 fixture로 검증하고
  화면별 적용은 미검증으로 명시.
- revision이 없는 API에 임의 버전값을 만들거나
  충돌 안전성을 확보했다고 주장하지 않는다.
- 저장 시 버전 검증이 미구현이면 후속 필수 Gate로 기록.
