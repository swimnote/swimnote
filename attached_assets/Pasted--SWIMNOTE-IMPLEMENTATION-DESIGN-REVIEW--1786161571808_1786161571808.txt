3. Request Result Notification Contract 확정
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

PATCH /parent-requests/:id 처리 성공 시

현재:

status update
→ sendPushToUser

구조를 정확히 제출한다.

notifications INSERT를 추가한다면
기존 notifications schema와 기존 INSERT pattern에 맞춰:

recipient
type
title
body
ref_type
ref_id

각 필드에 정확히 무엇을 넣을지 설계한다.

목표 논리값:

type = parent_request_result
ref_type = request
ref_id = parent_student_requests.id

단 실제 schema/기존 convention과 충돌하면
현재 코드 convention을 우선하고 차이를 보고한다.

중복 INSERT 방지도 설계한다.

동일 요청을 done으로 여러 번 PATCH했을 때
알림이 무한 중복 생성되면 안 된다.

4. Push와 Notification DB 관계
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

↓
