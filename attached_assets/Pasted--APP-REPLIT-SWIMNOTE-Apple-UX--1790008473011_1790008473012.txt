[SWIMNOTE — 사진 전체앨범 ‘선택한 순서 그대로 업로드’ 전면 재조사 / 카카오·Apple식 업로드 UX 벤치마킹]

중요:
이번 단계에서는 코드 수정하지 마십시오.
APP OTA 금지.
API 배포 금지.
DB 수정 금지.
기존 사진 UPDATE/DELETE 금지.

사용자 실제 기기에서
사진 여러 장을 한 번에 선택해 업로드하면
전체앨범에서 여전히 사용자가 선택한 순서와 다르게 표시됩니다.

이 기능은 이미 여러 차례 수정했지만
실기기에서 완전히 해결되지 않았습니다.

이번에는
“현재 버그 한 군데”만 찾지 말고,

카카오톡이나 Apple Photos처럼

1. 사용자가 사진을 선택한 순서를 명확히 확정
2. 압축/업로드는 병렬이어도 논리적 순서는 불변
3. 서버 저장 후에도 선택순서 유지
4. 다른 일지에 첨부되어도 전체앨범 순서는 불변
5. 다시 앱을 열어도 동일 순서

가 되는 구조인지
처음부터 끝까지 다시 검증하십시오.

0. 목표 동작을 먼저 고정
━━━━━━━━━━━━━━━━━━━━━━

SWIMNOTE의 최종 제품 계약은 다음입니다.

예:

사용자가 사진 선택창에서

사진 A = 1번째
사진 B = 2번째
사진 C = 3번째
...
사진 J = 10번째

순서로 선택했다면

전체앨범에서는 반드시:

A → B → C → ... → J

순서로 표시되어야 합니다.

압축 완료 순서,
R2 PUT 완료 순서,
session 생성 순서,
finalize 완료 순서,
network 속도,
DB insert timing

은 표시 순서에 영향을 주면 안 됩니다.

또한 이후 A/C/F 사진을
서로 다른 일지에 다른 순서로 첨부하더라도

전체앨범의 최초 업로드 순서는
영구적으로 변하면 안 됩니다.

이 원칙을 기준으로 조사하십시오.

1. Apple / Expo 공식 ordered selection 확인
━━━━━━━━━━━━━━━━━━━━━━

현재 설치된:

expo-image-picker

정확한 버전을 package-lock/yarn lock/package.json 기준으로 확인하십시오.

그리고 현재 실제 코드:

launchImageLibraryAsync({
  ...
})

에

orderedSelection

옵션이 존재하는지 확인하십시오.

특히 iOS에서:

orderedSelection: true

가 설정되어 있는지 확인.

Expo 공식 동작 기준:

iOS 15+에서 orderedSelection=true이면

- 선택한 사진에 선택순서 번호 badge 표시
- assets가 사용자가 선택한 정확한 순서로 반환됨

반대로 false/default에서는
선택순서 반환이 항상 보장되지 않습니다.

따라서 이전 보고의:

“PHPicker이므로 result.assets는 무조건 탭 순서”

라는 결론을 그대로 재사용하지 마십시오.

현재 실제 option을 기준으로 재판정하십시오.

보고:

- expo-image-picker 실제 버전
- orderedSelection 현재 값
- 명시 여부
- iOS에서 번호 badge가 실제 활성화되는 설정인지
- selectionLimit
- allowsMultipleSelection

다시 조회/재실행해도 동일 순서

어디까지 충족하고 어디서 깨지는지 표로 보고하십시오.
