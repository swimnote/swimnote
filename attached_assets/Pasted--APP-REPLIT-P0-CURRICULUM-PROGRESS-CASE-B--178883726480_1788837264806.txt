조사 결과 CASE B 확인.

확정 사실:

- Toykids active curriculum 정상
- curriculum_items 50개 정상
- AI 검색 필수 metadata 정상
- DOCX 업로드 생략은 GAUGE 미작동 원인이 아님

따라서 provisioning 쪽은 더 건드리지 않는다.

하지만 보고서의
"기술적 버그 없음 / adoption 문제"
판정은 제품 요구와 맞지 않는다.

현재 구조적 결함:

curriculum_matches가
AI 일지 생성 후 저장할 때만 만들어짐.

그래서:

수동 Diary
→ curriculum_matches 없음
→ growth_events 없음
→ CPO 없음
→ SCP 없음
→ Parent Gauge 0

이 구조를 수정한다.

제품의 canonical 요구는:

"학생에게 저장된 실제 수업일지 내용"
→ curriculum item 비교
→ evidence 생성
→ progress 계산
→ Admin / Parent / X Dashboard 반영

AI 일지 생성 버튼 사용 여부가
진도 게이지 작동 조건이 되어서는 안 된다.

1. CurriculumEvidenceResolver를 단일 진입점으로 만든다
━━━━━━━━━━━━━━━━━━━━━━

→ SCP

AI Diary / 수동 Diary / 템플릿 Diary가
서로 다른 progress pipeline을 사용하지 말 것.

━━━━━━━━━━━━━━━━━━━━━━
2. Evidence 우선순위
━━━━━━━━━━━━━━━━━━━━━━

Resolver는 다음 순서로 사용:

1. 이미 curriculum_matches가 전달된 AI Diary
   → 그대로 검증 후 사용

2. diary에 template_id / structured metadata가 존재
   → deterministic curriculum item mapping

3. stroke / domain / atomic_skill / skill_group / level 등
   기존 structured field로 curriculum_items와 매칭

4. 위 정보가 부족한 자유서술 수동 Diary
   → 기존 SWIMNOTE AI Engine의 curriculum/template 검색 기능 재사용

새 일반 GPT classifier 만들지 말 것.

AI Engine이 이미 제공하는
검색/grounding 구조를 재사용.

━━━━━━━━━━━━━━━━━━━━━━
3. 수동 Diary도 자동 매핑
━━━━━━━━━━━━━━━━━━━━━━

선생님이 직접 일지를 작성해도:

저장
→ diary 내용 분석
→ curriculum candidate
→ evidence
→ progress

자동 실행.

선생님에게 별도:
"오늘 가르친 커리큘럼 선택"

UI 추가 금지.

업무를 늘리지 않는다.

━━━━━━━━━━━━━━━━━━━━━━
4. AI Diary 기존 경로 유지
━━━━━━━━━━━━━━━━━━━━━━

AI Diary에서 이미 받은 curriculum_matches는
다시 AI에 보내지 않는다.

기존 match_token 검증 경로 유지.

즉:

AI Diary = 빠른 direct evidence
Manual Diary = resolver가 evidence 생성

최종 downstream은 둘 다 동일:

growth_events
→ CPO
→ SCP

5. 기존 342개 Diary Backfill
━━━━━━━━━━━━━━━━━━━━━━

기존 수동 diary 342개를 버리지 않는다.

Backfill pipeline:

→ 기존 structured data 먼저 확인

→ 불충분한 diary만 AI Engine 검색
→ curriculum evidence 생성
→ CPO
→ SCP 재계산

derived evidence만 생성.

deterministic mapped
engine mapped
ambiguous
unmapped

estimated cost
