A. Back Navigation ROOT CAUSE 최종 확인
━━━━━━━━━━━━━━━━━━━━━━

현재 실기기에서:

Home
→ Modal
→ 알림함(messages-inbox)
→ 알림 선택
→ diary-reactions 또는 growth-report-reactions
→ Back
→ Home

으로 이동함.

이전 Modal close → requestAnimationFrame → router.push 수정으로도 해결 안 됨.

따라서 이제 Modal timing 가설은 폐기하고
실제 navigation stack / target back handler를 확인.

반드시 확인:

1. messages-inbox에서
diary_like / diary_comment 선택 시
정확한 router 호출 방식

2. growth_report_like / growth_report_comment 선택 시
정확한 router 호출 방식

3. diary-reactions.tsx
- source param
- handleBack
- router.back / replace / push 여부

4. growth-report-reactions.tsx
- onBack 구현
- custom home 버튼과 back 버튼 구분

5. target 화면 진입 시
messages-inbox route가 stack에 실제 남아 있는지

6. Expo Router Tabs/Stack 구조에서
해당 화면들이 어느 navigator에 속하는지

최종적으로:

왜 target Back이 messages-inbox가 아니라 Home으로 가는지
한 가지 ROOT CAUSE로 확정.

━━━━━━━━━━━━━━━━━━━━━━
B. 원하는 최종 Back 동작
━━━━━━━━━━━━━━━━━━━━━━

알림함에서 진입한 경우:

Home
→ messages-inbox
→ notification target

Back:
notification target
→ messages-inbox

Back:
messages-inbox
→ Home

이 순서가 반드시 유지.

단,
Diary 화면 등 다른 곳에서
diary-reactions / growth-report-reactions로 직접 진입한 경우에는
기존 source로 정상 복귀해야 함.

따라서 target 화면의 back destination을
무조건 Inbox로 하드코딩하지 말고
"진입 source" 기반 최소 설계 우선.

예:

source=news_inbox
→ back to messages-inbox

source=teacher_diary
→ back to diary

등.

현재 source param 체계가 이미 있다면 재사용.
