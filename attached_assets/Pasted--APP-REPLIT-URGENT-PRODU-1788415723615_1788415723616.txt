1. 먼저 유지훈 OLD / NEW 계정 정확히 식별
============================================================

Production DB에서 유지훈 선생님 계정을 조사.

찾아야 하는 두 계정:

A. OLD KAKAO TEACHER
- name = 유지훈
- kakao_id IS NOT NULL
- 기존 Kakao 로그인 계정
- archive/disabled 상태일 수 있음

B. NEW GENERAL TEACHER
- name = 유지훈
- 일반가입으로 최근 생성
- kakao_id 없음 또는 General auth 방식
- 현재 로그인 가능한 새 계정

반드시 phone + swimming_pool_id + 기존 migration 관계까지 확인.

이름만으로 매칭 금지.

2. ambiguity safety
============================================================

아래 조건을 만족할 때만 WRITE 진행:

- OLD Kakao 유지훈 계정 정확히 1개
- NEW General 유지훈 계정 정확히 1개
- 동일 normalized phone
- 동일 swimming_pool_id
- role = teacher
- old/new가 실제 migration pair임을 확인

동명이인 또는 여러 계정이 존재해
pair가 100% 확정되지 않으면:

STOP.

Production write 하지 말고
후보 ID만 보고.

6. IMMUTABLE HISTORY는 이동 금지
============================================================

과거 작성자 identity/history는
기존 정책 유지.

예:

- diary_messages.teacher_user_id
- teacher_absences.teacher_user_id
- 기타 historical author/audit record

이런 immutable history는
OLD archived account를 가리킨 채 보존 가능.

ACTIVE ownership만 NEW로 이전.

즉:

ACTIVE:
OLD → NEW

HISTORY:
필요 시 OLD 유지
