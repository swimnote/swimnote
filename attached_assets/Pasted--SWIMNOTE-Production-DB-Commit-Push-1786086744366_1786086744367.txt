[SWIMNOTE 긴급 — Production 실행 환경 신원 검증]

현재 모든 개발 작업을 중단합니다.

코드 수정 금지.
DB 수정 금지.
Commit / Push / Render / OTA 금지.

현재 의문:

Replit이 조사하고 있는 서버 코드와
실제 SWIMNOTE Production 앱이 호출하는 서버가
동일한 코드인지 아직 증명되지 않았습니다.

브랜치 이름을 근거로 Production이라고 판단하지 마십시오.

이번 작업의 목적은:

실제 Production 앱
→ 실제 API URL
→ 실제 Render Service
→ 실제 Live Deployment SHA
→ 해당 SHA의 서버 코드

를 하나의 체인으로 증명하는 것입니다.

4. Render 현재 LIVE Deployment 확인
━━━━━━━━━━━━━━━━━━━━━━

가장 중요합니다.

Render service의:

- configured branch
- current Live deployment ID
- current Live commit SHA
- deployment status
- deployedAt

을 실제 Render API/Dashboard 기준으로 조회하십시오.

보고:

Configured Branch:
Live Deployment ID:
Live Commit SHA:
Live Status:
Live Deployed At:

중요:

Configured Branch와 Live Commit을 혼동하지 마십시오.

예를 들어:

Configured Branch = deploy-photo-clone

이어도

Live Commit SHA = release branch에서 commitId로 직접 배포한 SHA

일 수 있습니다.

반드시 Live SHA를 기준으로 판단하십시오.

━━━━━━━━━━━━━━━━━━━━━━
5. deploy-photo-clone HEAD와 Live SHA 비교
━━━━━━━━━━━━━━━━━━━━━━

다음을 조회:

git rev-parse origin/deploy-photo-clone

그리고:

Render Live SHA

와 비교하십시오.
