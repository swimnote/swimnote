3. 실제 Server Route 확인
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

parent-requests.ts에서 실제 등록된 메시지 route를 확인한다.

확인:

router.post(...)

정확한 path.

그리고 이 router가 server/app에서
어떤 prefix로 mount되는지 끝까지 추적한다.

예:

app.use("/api", ...)
router.use(...)
parentRequestsRouter mount

등.

중요:

파일 안에

POST /parent-requests/:requestId/messages

가 있다고 해서
실제 Production URL이 자동으로 그 값이라고 판단 금지.

router mount prefix까지 합친
최종 URL을 확정한다.

4. 404 직접 원인 확정
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

실기기 메시지:

"요청한 경로를 찾을 수 없습니다."

가 실제로 어떤 HTTP status/code에서 생성되는지 확인한다.

반드시 확보:

Teacher POST:
- final URL
- HTTP status
- content-type
- raw JSON error/code

Parent POST:
- final URL
- HTTP status
- content-type
- raw JSON error/code

404라면:

A. Client path 오류
B. Server router mount 오류
C. Production 서버에 신규 route 미배포
D. route ordering/catch-all 문제

중 무엇인지 실제 증거로 확정한다.

추측 수정 금지.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
