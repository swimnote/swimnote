[FAST TRACK — STEP 10 학부모 자동연결 / 대기건 정리]

목표:
학생이 이미 등록되어 있고

- 학생 이름 일치
- 등록 보호자 전화번호 일치

하면 학부모 가입/연결 요청이
관리자 승인대기에 남지 않고 자동 연결되도록 한다.

기존 auto-link-v2 재사용.
새 연결 시스템 금지.

━━━━━━━━━━━━━━━━━━━━━━
1. 현재 경로 추적
━━━━━━━━━━━━━━━━━━━━━━

이미 확인된:
auto-link-v2.js

를 다시 설계하지 말고 아래만 추적.

학부모:

가입
→ 학생 연결 요청
→ 어떤 route
→ pending 생성
→ auto-link-v2 호출 여부
→ 성공 시 어떤 row/status 업데이트

확인.

핵심:
왜 정상 매칭 가능한 요청이
승인관리 대기에 남는지 정확히 찾는다.

━━━━━━━━━━━━━━━━━━━━━━
2. 확정 자동연결 조건
━━━━━━━━━━━━━━━━━━━━━━

자동 연결 허용:

A.
학생 이름 일치

AND

B.
학부모 가입 전화번호가
학생에 등록된 보호자 전화번호 중 하나와 일치

전화번호 normalization 반드시 기존 로직 사용:

- 01012345678
- 010-1234-5678
- 공백
- +82
등

보호자1 / 보호자2 둘 다 확인.

동명이인은
전화번호까지 일치한 정확한 student만 연결.

이름만 같다고 연결 금지.

━━━━━━━━━━━━━━━━━━━━━━
3. 기존 pending 원인 분류
━━━━━━━━━━━━━━━━━━━━━━

현재 Production 대기 요청들을
데이터 변경 전에 먼저 분류.

각 요청을:

A. 이름 + 전화번호 명확 일치
B. 이름만 일치
C. 전화번호만 일치
D. 둘 다 불일치
E. 동명이인/복수 후보
F. 학생 미등록

로 집계.

개인정보는 마스킹.

━━━━━━━━━━━━━━━━━━━━━━
4. 최소 수정
━━━━━━━━━━━━━━━━━━━━━━

정상 요청이 pending에 남는 이유가:

- auto-link trigger 누락
- normalization 경로 불일치
- 보호자2 미확인
- request 생성 후 auto-link 미호출
- 성공 후 pending status 미정리

중 하나라면
그 원인만 최소 수정.

금지:

- fuzzy 이름 매칭 확대
- 전화번호 없이 자동 승인
- 새로운 DB table
- migration
- tenant scope 완화
- 관리자 수동승인 기능 삭제

수동승인은 예외 처리용으로 남겨둔다.

━━━━━━━━━━━━━━━━━━━━━━
5. 기존 대기건 정리
━━━━━━━━━━━━━━━━━━━━━━

코드 수정 검증 후에만 수행.

현재 정책을 명확히 만족하는
A 유형만 자동 승인/연결 처리.

B~F는 자동 승인 금지.

처리 후 기대:

정상 매칭 가능한 요청:
대기 목록에서 제거

진짜 예외:
대기 목록에 유지

목표는
평상시 정상 가입자가 승인관리 화면에 쌓이지 않는 것.

━━━━━━━━━━━━━━━━━━━━━━
6. 연결 완료 후 동기화
━━━━━━━━━━━━━━━━━━━━━━

자동 연결 성공 시 확인:

- parent ↔ student 연결 row 정상
- pending request 정상 완료/제거
- 회원관리의 "학부모미연결" 상태 해제

- 학부모 앱에서 자녀 접근 가능

기존 API/상태 이용.

7. 승인관리 UI 최소 정리
━━━━━━━━━━━━━━━━━━━━━━

정상 match는 자동 처리되므로
승인관리에는 예외만 남도록.

현재 승인 버튼의 돋보기 아이콘이
실제 승인 액션에 부적절하면:

→ check/check-circle 또는 텍스트 버튼

으로 변경.

카드의:

- 학생 이름 확인 필요
- 전화번호 확인 필요
- 학생 선택 필요

는 실제 해당 문제가 있을 때만 표시.

큰 UI 재설계 금지.

필수 케이스:

1.
이름 + 보호자1 번호 일치
→ 자동 연결

2.
이름 + 보호자2 번호 일치
→ 자동 연결

3.
하이픈 유무 차이
→ 자동 연결

+82 / 010 normalization
→ 기존 정책상 허용되는 경우 정상

6.
이름만 일치
→ 자동 승인 금지

7.
번호만 일치 + 이름 불일치
→ 자동 승인 금지

8.
다른 pool 학생
→ 절대 연결 금지

9.
이미 연결된 parent/student
→ 중복 row 생성 금지
