사용자에게 Xcode·Metro 콘솔 로그 수집을 요구하지 마세요.

저는 실기기에서 발생한 증상과 화면을 이미 제공했습니다.
코드와 실행 환경에 접근할 수 있는 개발 Agent가 직접 원인을 조사하고 해결해야 합니다.

현재 문제:

- AI 일지에서 텍스트 입력 후 오류 발생
- ERROR 화면과 버튼이 중복되거나 잔상처럼 겹침
- 화면이 심하게 깜빡임
- 잠시 기다리면 일부가 정상으로 돌아오기도 함
- 정적 코드 분석에서는 Modal과 Content 중복 구조가 확인되지 않음
- 따라서 OTA 적용 여부, Modal lifecycle, 애니메이션 경합, 상태 전환을 런타임에서 조사해야 함

다음 작업을 직접 수행하세요.

1. 현재 실행 가능한 환경을 확인하세요.

- Expo 개발 실행
- iOS Simulator 또는 사용 가능한 테스트 환경
- 서버 연결 상태
- AI 요청을 실제로 발생시킬 수 있는지
- 실제 ERROR를 만들 수 있는 테스트 방법

실기기만 있어야 재현된다고 단정하지 말고,
우선 Simulator와 자동화된 상태 재현으로 조사하세요.

2. 사용자 조작 없이 ERROR 상태를 재현할 수 있는 개발용 테스트 경로를 만드세요.

예:

- 개발 환경에서 AI 요청을 강제로 실패시키는 mock
- 특정 입력일 때 ERROR를 반환하는 debug flag
- 네트워크 오류 mock
- API 500 mock
- timeout mock
- reducer에 테스트 ERROR event를 전달하는 개발 전용 장치

운영 코드에 노출되지 않도록 development 환경에서만 사용하세요.

4. OTA 여부를 사용자에게 확인시키지 말고 코드와 배포 설정에서 직접 확인하세요.

확인 항목:

- 현재 production channel
- runtimeVersion
- 배포된 updateId
- OTA commit 또는 bundle marker
- 앱 버전과 runtimeVersion 호환성
- 해당 수정이 실제 production/preview 어느 채널에 배포됐는지
- 이전 OTA가 캐시될 가능성
- 개발 빌드가 어떤 채널을 읽는지

DIARY_ERROR_ACTIONBAR_FIX_9642537 문자열이 실제 배포 번들에 들어 있는지도 직접 확인하세요.

5. 자동화 테스트 또는 컴포넌트 테스트를 추가하세요.

반드시 검사:

A.
ERROR 상태에서 AIErrorView는 정확히 1개

B.
ERROR 상태에서 DiaryAIActionBar는 0개

C.

E.

F.
nativeVisible=false 전환 전에 새 open animation이 시작되지 않음

G.
빠르게 닫기·재시도·재진입해도 중복 UI가 생기지 않음

7. 원인을 찾으면 최소 범위로 수정하세요.

임시로 버튼을 숨기는 방식만 반복하지 마세요.
실제 원인이 상태 경합이면 상태 경합을 고치고,
애니메이션 문제면 애니메이션 lifecycle을 고치고,
중복 mount면 mount 원인을 제거하세요.

권장 구조를 검토하세요.

- Modal 표시 상태의 단일 소스
- visible/nativeVisible/rendered의 불필요한 다중 상태 제거
- close 완료 전 재오픈 차단
- animation ref 취소 후 새 animation 시작
- ERROR 진입 시 키보드 dismiss
- retry 전에 error와 request 상태 초기화
- onDismiss 후에만 rendered=false 처리

단, 실제 코드 구조와 로그를 확인한 후 필요한 변경만 적용하세요.
