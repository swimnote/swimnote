1. 수정 방향
━━━━━━━━━━━━━━━━━━━━━━

ParentPromoStrip.tsx의 현재:

fetch(`${API_BASE}/platform/banners?type=strip`)

무인증 호출을 수정하십시오.

우선순위:

1순위:
SWIMNOTE APP에서 이미 사용하는
공통 authenticated API client/helper 재사용.

해당 helper가 자동으로:

Authorization: Bearer <JWT>

를 넣는 구조라면
반드시 그것을 사용하십시오.

2순위:
공통 helper로 처리할 수 없는 경우에만
현재 APP의 실제 auth hook/context에서 token을 가져와
Authorization header를 명시적으로 추가하십시오.

새 인증 방식 만들지 마십시오.

━━━━━━━━━━━━━━━━━━━━━━
2. AUTH 초기화 시점
━━━━━━━━━━━━━━━━━━━━━━

앱 시작 직후 auth/token이 아직 준비되지 않은 상태에서
먼저 banner fetch를 실행하여 다시 401이 발생하지 않게 하십시오.

현재 auth context에:

loading
isReady
initialized

등의 기존 상태가 있다면 재사용.

최소 원칙:

유효한 로그인 세션/token 확인 후
banner request 실행.

별도 auth system 추가 금지.

━━━━━━━━━━━━━━━━━━━━━━
3. FALLBACK 정책은 유지
━━━━━━━━━━━━━━━━━━━━━━

현재 fallback:

“스윔노트 — 우리 아이 수영 성장을 기록해보세요”

는 유지합니다.

다음 경우에만 fallback:

- 활성 strip banner가 실제로 없음
- 정상 인증 요청 자체가 실패함

정상 등록되어 있는 활성 배너가 있는데
인증 누락 때문에 fallback이 뜨는 현상만 수정하십시오.
