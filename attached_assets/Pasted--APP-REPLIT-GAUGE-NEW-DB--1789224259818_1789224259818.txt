1. LEVEL별 계산식 검증
   ━━━━━━━━━━━━━━━━━━━━━━

현재 제안:

현재 `current_level_order` 이상의 CPO만 수집
→ 3-session 확인
→ confirmed item 수 / 해당 레벨 전체 item 수
→ 레벨 구간에 반영

여기서 반드시 확인할 것:

예를 들어 빨간모자(Level 3) 학생에게
Level 3 CPO와 Level 4 CPO가 동시에 존재할 경우,

Level 4 item이 Level 3의 분모에 섞이는 구조가 되어서는 안 됩니다.

각 curriculum item의 실제 level/order 구조를 확인하고,
필요하다면 LEVEL별로 독립 계산하십시오.

후보 방식:

각 Level L >= current_level에 대해

confirmed_L
= 해당 Level에서 3-session 조건을 통과한 item 수

total_L
= 해당 Level의 전체 계산 대상 item 수

ratio_L
= MIN(confirmed_L / total_L, 1)

candidate_L
= 해당 Level floor + ratio_L × 해당 Level width

최종:

raw_gauge
= MAX(
current_level floor,
각 Level candidate
)

gauge_pct
= MIN(
80,
MAX(previous_gauge_pct, raw_gauge)
)

단, 이 공식을 무조건 구현하지 말고
현재 CPO / curriculum rank / level 구조를 확인해서
같은 의도를 가장 정확하게 구현하는 공식을 제출하십시오.

2. current_level_order 전체 매핑 확인
━━━━━━━━━━━━━━━━━━━━━━

실제 Production에서 `students.current_level_order`가 어떤 값을 사용하는지 확인하십시오.

반드시 전체 매핑 제출:

* 1
* 2
* 3
* 4
* 5
* 6
* 7
* 그 외 존재 값

특히 현재 설계에는:

Level 1 흰색 = 0~20
Level 2 파란 = 20~35
Level 3 빨간 = 35~50
Level 4 검정 = 50~65
마스터즈 = 65~80

만 정의되어 있습니다.

Production에서 금 / 챔피언 / 슈퍼챔피언 등이 별도 `current_level_order`로 존재한다면
이 값들이 어떤 gauge band에 매핑되는지 반드시 확정해야 합니다.

임의 매핑 금지.

실제 DB/UI/API 기준으로 보고하십시오.

3. 레벨 변경 즉시 Gauge 반영
━━━━━━━━━━━━━━━━━━━━━━

현재:

`/teacher/students/:id/level`
`/admin/students/:id/level`

에서 `students.current_level_order`를 저장한다고 보고되어 있습니다.

실제 코드를 확인하십시오.

예:

빨간모자
gauge_pct = 38%

→ 선생님이 검정모자로 승급

검정 floor = 50%

이 경우 다음 일지를 기다리지 않고
레벨 변경 직후 gauge_pct가 최소 50%가 되어야 합니다.

현재 level PATCH 뒤에 SCP 재계산이 실행되는지 확인하십시오.

안 된다면 level PATCH 성공 후
어느 service/function에서 재계산시키는 것이 안전한지 제안하십시오.

4. 레벨 하향/오입력 정정 정책
━━━━━━━━━━━━━━━━━━━━━━

기존 SCP의 `GREATEST` 단조증가를 그대로 사용하면:

실수로 검정 입력
→ gauge 50%
→ 빨강으로 다시 정정

했을 때 gauge가 50%에 고정될 수 있습니다.

확인:

* level downgrade가 현재 UI/API에서 가능한가
* 실제 운영에서 downgrade가 존재하는가
* 단순 오입력 정정이 가능한가

GAUGE-NEW에서는 일반 일지 누적 시에는 단조 증가를 유지하되,
레벨 자체가 관리자의 명시적 정정으로 변경되는 경우
잘못된 과거 floor가 영구 고정되지 않도록 정책이 필요합니다.

현재 시스템에 맞는 처리 방식을 제안하십시오.

7. AI 의미 정의
━━━━━━━━━━━━━━━━━━━━━━

`gauge_pct`는 절대로:

"수영 실력 50%"
"수영 능력 50점"

이라는 뜻이 아닙니다.

의미:

"현재 커리큘럼/레벨 진행 위치"

입니다.

예:

gauge_pct = 50
current_level_order = 4
current_level_label = 검정모자

→ 검정모자 구간 시작점에 위치.

이 의미가 ENGINE에 전달될 수 있도록
APP snapshot contract에서 의미가 명확한 구조를 제안하십시오.
