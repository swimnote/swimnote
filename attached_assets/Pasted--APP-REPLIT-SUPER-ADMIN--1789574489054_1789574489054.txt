[SUPER ADMIN — 통합 배너 광고 관리 시스템 구현]

이전 배너 관련 구현 지시문은 폐기합니다.

이번 목표는 단순히
“strip 문구를 Super Admin에서 수정”
하는 것이 아닙니다.

SWIMNOTE Super Admin에
실제 광고판으로 운영할 수 있는
“통합 배너 관리” 기능 하나를 완성하십시오.

0. 최종 목표
━━━━━━━━━━━━━━━━━━━━━━

Super Admin
→ 배너 관리

메뉴 하나에서:

- 이미지
- 제목
- 설명
- 링크
- 활성/비활성
- 노출 시작일
- 노출 종료일
- 슬라이드 순서
- 배너별 노출 시간
- 여러 배너 자동 순환

을 관리할 수 있어야 합니다.

관리자가 설정한 내용은
APP 재배포 없이 즉시 서버 데이터로 반영되어야 합니다.

현재 학부모 홈의:

1. ParentPromoStrip
2. ParentAdBanner

두 광고 영역을
같은 관리 시스템에서 운영합니다.

별도 “가로 배너 관리”
“카드 배너 관리”

메뉴를 두 개 만들지 마십시오.

최종 메뉴:

배너 관리

1개입니다.

1. 기존 구조 우선 재사용
━━━━━━━━━━━━━━━━━━━━━━

현재 존재하는:

platform_banners

구조와 기존 banner API를 우선 재사용하십시오.

현재 banner_type:

- strip
- slider

의 의미도 가능하면 유지하십시오.

의미:

strip
→ ParentPromoStrip
→ 학부모 홈 상단 프로모션 광고

slider
→ ParentAdBanner
→ 학부모 홈 카드형 광고

새 광고 테이블을 별도로 만들지 마십시오.

단 아래 기능을 구현하는 데
현재 platform_banners에 필드가 없는 경우에만
additive migration을 허용합니다.

기존 데이터를 파괴하거나
banner_type 값을 일괄변환하지 마십시오.

2. 최종 배너 데이터 모델
━━━━━━━━━━━━━━━━━━━━━━

먼저 현재 platform_banners 실제 schema를 확인하고
이미 존재하는 필드는 그대로 재사용하십시오.

최종적으로 각 배너가 최소 아래 의미를 가져야 합니다.

- id
- banner_type
  - strip
  - slider

- title
- subtitle 또는 description
- image_url nullable

- link_type
  - none
  - external
  - internal

- link_url nullable

- is_active

- starts_at nullable
- ends_at nullable

- sort_order

- display_seconds

- created_at
- updated_at

현재 이름이 다른 동일 목적 컬럼이 있으면
새 컬럼을 중복 생성하지 마십시오.

예:

priority가 이미 sort_order 역할이면
기존 컬럼 재사용 가능.

duration_seconds가 존재하면
display_seconds 새로 만들지 않음.

- WEBP

Super Admin 편집 화면에서
현재 이미지를 미리 볼 수 있어야 합니다.

이미지 교체 / 제거 가능.

4. ParentPromoStrip 표시 방식
━━━━━━━━━━━━━━━━━━━━━━

현재 ParentPromoStrip 자리를
실제 광고 슬롯으로 업그레이드합니다.

기존 strip banner가 1개라면:
→ 해당 광고 하나 표시.

2개 이상이라면:
→ 자동 슬라이드 순환.

각 banner의:

display_seconds

값을 사용하여
각 광고별 노출 시간을 다르게 설정할 수 있게 합니다.

예:

배너 A
5초

배너 B
10초

배너 C
4초

→ 5초 → 10초 → 4초 순환.

display_seconds 기본값:

5초

허용범위:

3~30초

비정상 값은 서버/API에서 방어하십시오.

6. 광고 스케줄
━━━━━━━━━━━━━━━━━━━━━━

각 배너에:

노출 시작
starts_at

노출 종료
ends_at

을 설정할 수 있게 합니다.

둘 다 nullable.

예:

시작 없음 + 종료 없음
→ 활성화되어 있는 동안 계속 표시

2026-09-20 09:00
~
2026-09-25 23:59

→ 해당 기간에만 노출.

실제 노출 조건:

is_active = true

AND

starts_at IS NULL
OR starts_at <= NOW()

AND

ends_at IS NULL
OR ends_at > NOW()

서버 기준으로 필터하십시오.

APP이 시계를 기준으로
광고 활성 여부를 임의 판단하지 않게 하십시오.

DB timestamp는 기존 기준을 따르고
Super Admin UI에는 사용자 로컬 시간으로 표시.

현재 노출 가능한 strip banner가 0개라면

“스윔노트 — 우리 아이 수영 성장을 기록해보세요”
