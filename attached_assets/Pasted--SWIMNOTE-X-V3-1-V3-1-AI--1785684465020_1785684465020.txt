1. GPT의 curriculum_item_id 직접 생성 금지
━━━━━━━━━━━━━━━━━━━━━━

현재 설계에서는 GPT가 다음 값을 직접 반환하도록 되어 있습니다.

- curriculum_item_id
- confidence
- evidence

이 구조는 GPT가 실제 DB에 존재하지 않는 ID를 생성하거나
잘못된 항목을 연결할 위험이 있습니다.

반드시 아래 구조로 변경하십시오.

처리 흐름:

1. 서버 또는 AI Engine이 curriculum 후보를 검색
2. 실제 DB에서 후보 목록 생성
3. 후보마다 서버가 고정된 candidate_index 부여
4. GPT에는 실제 ID 대신 후보 index와 설명만 전달
5. GPT는 후보 중 선택한 candidate_index만 반환
6. 서버가 candidate_index를 실제 curriculum_item_id로 다시 매핑
7. 요청 후보 목록에 없는 값은 즉시 폐기

예시:

서버가 GPT에 전달:

{
  "candidates": [
    {
      "candidate_index": 0,
      "skill_name": "자유형 측면 호흡",
      "description": "호흡 시 머리를 과도하게 들지 않고 옆으로 회전"
    },
    {
      "candidate_index": 1,
      "skill_name": "자유형 팔 리커버리",
      "description": "팔꿈치를 부드럽게 들어 앞으로 이동"
    }
  ]
}

GPT 반환:

{
  "selected_candidates": [
    {
      "candidate_index": 0,
      "evidence_text": "호흡할 때 고개를 옆으로 돌리는 동작이 좋아졌습니다."
    }
  ]
}

서버 최종 변환:

{
  "curriculum_item_id": "ci_xxx",
  "candidate_index": 0
}

절대 원칙:

- GPT가 curriculum_item_id 직접 작성 금지
- 후보 목록 밖 index 반환 시 무효
- DB 매핑 실패 시 growth_event 생성 금지
- curriculum_item이 해당 학생 배정 버전에 속하는지 서버에서 재검증
- 다른 수영장 curriculum_item 연결 금지
- archived curriculum version 항목 자동 연결 금지

2. Confidence 계산 책임 분리
━━━━━━━━━━━━━━━━━━━━━━

GPT가 confidence 숫자를 임의로 생성하면 안 됩니다.

최종 confidence는 서버 또는 AI Engine이 계산합니다.

권장 입력값:

- template similarity
- curriculum similarity
- concept overlap
- keyword overlap
- parser confidence
- evidence coverage
- candidate rank
- 학생 배정 curriculum version 일치 여부

예시:

final_confidence =
  curriculum_similarity × 가중치
  + concept_overlap × 가중치
  + evidence_coverage × 가중치
  + parser_confidence × 가중치

정확한 수식과 가중치는 Repository 조사 및 파일럿 결과에 따라 확정하십시오.

V3.2 설계서에 반드시 포함:

- confidence 계산 위치
- 사용 변수
- 변수별 범위
- normalization 방식
- 최종 0.0~1.0 변환 방식
- threshold 0.6 유지 여부
- threshold 미달 처리
- score 계산 실패 처리
- 버전별 confidence 산식 추적 방법

GPT는 다음만 반환할 수 있습니다.

- 선택 candidate_index
- evidence_text 또는 evidence span
- 선택 이유에 해당하는 제한된 구조화 결과

GPT가 최종 confidence를 직접 결정하지 않도록 하십시오.

3. Evidence 구조 개선
━━━━━━━━━━━━━━━━━━━━━━

현재 evidence가 자유 텍스트 한 줄로 되어 있습니다.

장기적으로 근거 추적과 UI 강조 표시가 가능하도록 구조화하십시오.

권장 구조:

interface EvidenceSpan {
  source_type: 'teacher_input' | 'generated_content';
  student_ref: string;
  sentence_index: number;
  start_offset: number;
  end_offset: number;
  text: string;
}

또는 현재 파이프라인 구조상 offset 계산이 어렵다면 최소 구조:

{
  "source_type": "teacher_input",
  "sentence_index": 2,
  "text": "호흡 타이밍이 좋아졌어요."
}

정책:

- evidence는 실제 입력 또는 최종 생성문 안에 존재해야 함
- 존재하지 않는 문장을 GPT가 새로 만들어 근거로 사용하면 안 됨
- evidence 검증 실패 시 curriculum match 폐기
- 개인정보 로그에는 evidence 원문 전체를 남기지 않음
- Debug 환경에서만 마스킹된 evidence 확인 가능

권장 응답:

{

서버는 응답을 앱에 보내기 전에 다음을 재검증합니다.

- student_ref가 요청 학생 목록에 존재
- curriculum_item_id가 실제 DB에 존재
- curriculum_item_id가 해당 pool 소속
- curriculum_item_id가 학생 배정 curriculum version 소속
- candidate_index와 curriculum_item_id 매핑 일치
- confidence가 0~1 범위
- evidence가 실제 source 문장에 존재
- 중복 curriculum_item_id 제거
- grounding_validation 실패 시 match 전체 폐기

6. Global Template Set 버전 관리
━━━━━━━━━━━━━━━━━━━━━━

현재 template_scope='global'만으로는
히든 템플릿 2,000개 세트를 교체하거나 롤백하기 어렵습니다.

다음 구조를 설계하십시오.

global_template_sets

- id
- version_name
- status: DRAFT | ACTIVE | ARCHIVED
- description
- created_by
- activated_at
- archived_at
- created_at

diary_templates

- global_template_set_id nullable
- template_scope='global'인 경우 set_id 필수

제약:

- ACTIVE global_template_set은 최대 1개
- 파일럿 50개는 DRAFT 세트
- 승인 후 ACTIVE 전환
- 기존 ACTIVE는 ARCHIVED
- 검색은 ACTIVE 세트만 대상
- 과거 growth_event에는 사용된 template_set_version 저장
- 문제 발생 시 이전 세트를 ACTIVE로 롤백 가능

필수 제약 예시:

CREATE UNIQUE INDEX ...
ON global_template_sets(...)
WHERE status='ACTIVE';

정확한 PostgreSQL 문법과 실제 naming convention에 맞춰 제출하십시오.

12. 성장 이벤트 자동 반영 안전장치
━━━━━━━━━━━━━━━━━━━━━━

confidence >= 0.6만으로 자동 성장판 반영 여부를 결정하면 부족할 수 있습니다.

최소한 다음 조건을 모두 검증하십시오.

- event_role=progress

- request_id 일치

- growth_event progress 생성 금지
- 필요하면 observation event로만 저장
- 실패 사유 trace 기록

자동 반영 정책 후보를 비교하십시오.

A안
- 기준 통과 시 자동 progress 반영

B안
- 교사가 체크한 match만 progress 반영

C안
- 높은 confidence 자동, 중간 confidence 교사 확인, 낮은 confidence 폐기

권장안은 C안 검토:

- high threshold 이상: 자동
- middle range: 교사 확인
- low: 미반영

정확한 threshold는 50개 파일럿 결과로 확정하십시오.

0.6을 최종 고정값으로 구현하지 말고 설정값으로 분리하십시오.
