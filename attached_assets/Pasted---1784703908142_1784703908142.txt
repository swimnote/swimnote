# 문장 불러오기 모달 높이 고정 수정

현재 문장 불러오기 모달의 기능은 정상입니다.

하지만 레벨 선택 버튼을 누른 뒤 레벨 검색창에 타이핑을 시작하면
키보드가 올라오면서 모달 전체 높이가 줄어듭니다.

이후 아래 템플릿 목록을 누르거나 키보드가 내려가면
모달이 다시 원래 높이로 커집니다.

이 때문에 모달이 위아래로 움직이고 크기가 계속 바뀌는 문제가 있습니다.

첨부 화면 기준:

- 키보드가 없을 때: 모달이 화면 높이의 약 90%
- 키보드가 올라올 때: 모달 자체가 아래쪽의 작은 높이로 축소됨
- 키보드가 내려갈 때: 모달이 다시 90%로 확대됨

원하는 동작은 다음과 같습니다.

==================================================
1. 핵심 수정
==================================================

키보드 표시 여부와 관계없이
모달 외부 컨테이너의 위치와 높이를 항상 동일하게 유지하세요.

모달 높이:

- 항상 화면 높이의 약 90%
- 키보드가 올라와도 90% 유지
- 키보드가 내려가도 90% 유지
- 검색창 포커스 변경 시에도 위치와 높이 변화 없음
- 레벨 검색창과 통합 검색창 사이를 이동해도 크기 변화 없음

키보드 때문에 모달 컨테이너 자체의 height, maxHeight, top, bottom,
translateY 값이 변경되면 안 됩니다.

==================================================
2. KeyboardAvoidingView 구조 수정
==================================================

현재 KeyboardAvoidingView 또는 키보드 높이 상태가
모달 전체 컨테이너를 감싸면서 모달 높이를 줄이는 구조인지 확인하세요.

그렇다면 다음 구조로 변경하세요.

잘못된 구조 예시:

KeyboardAvoidingView
 └─ 모달 전체 컨테이너

원하는 구조:

고정 높이 모달 컨테이너
 └─ KeyboardAvoidingView 또는 키보드 대응 내부 영역
     └─ 검색창
     └─ 템플릿 리스트
     └─ 미리보기 및 하단 버튼

즉, 키보드 대응은 모달 내부 콘텐츠에만 적용하고
모달 외곽 프레임의 높이와 위치에는 적용하지 마세요.

==================================================
3. 모달 고정 크기
==================================================

모달 외부 컨테이너는 다음 기준으로 고정하세요.

- height: 화면 높이의 약 90%
- maxHeight만 사용하는 방식보다 명시적인 height 우선
- bottom sheet의 상단 위치 고정
- 키보드 이벤트에 따라 height를 다시 계산하지 않음
- keyboardVisible 상태에 따라 모달 높이를 바꾸지 않음
- 키보드 높이를 빼서 모달 높이를 계산하지 않음

예시 방향:

const screenHeight = Dimensions.get('window').height;
const MODAL_HEIGHT = screenHeight * 0.9;

modalContainer:
{
  height: MODAL_HEIGHT,
  maxHeight: MODAL_HEIGHT
}

Safe Area는 정상 반영하되
키보드가 열릴 때 MODAL_HEIGHT 자체가 달라지면 안 됩니다.

==================================================
4. 키보드가 올라왔을 때 내부 처리
==================================================

키보드가 올라와도 모달 프레임은 그대로 두고
모달 내부의 사용 가능한 영역만 자연스럽게 처리하세요.

다음 중 현재 구조에 가장 안전한 방식을 적용하세요.

방법 A:
KeyboardAvoidingView를 모달 내부에만 적용하고
behavior="padding" 또는 iOS에 적합한 방식 사용

방법 B:
FlatList의 contentContainerStyle 또는
하단 영역에 keyboardHeight만큼 paddingBottom 적용

방법 C:
키보드가 하단 일부를 덮도록 두되,
현재 구현된 검색창 오른쪽 '완료' 버튼으로 키보드를 내릴 수 있게 유지

중요한 것은 키보드가 올라왔다고
모달 전체가 축소되면 안 된다는 점입니다.

==================================================
5. 레벨 검색 포커스 처리
==================================================

다음 순서에서도 모달 크기가 바뀌지 않아야 합니다.

1. 문장 불러오기 모달 열기
2. 레벨 선택 누르기
3. 레벨 검색창에 포커스
4. 키보드 표시
5. 검색어 입력
6. 검색 결과 스크롤
7. 템플릿 문장 선택
8. 키보드 내리기
9. 통합 검색창 다시 선택
10. 키보드 재표시

위 모든 과정에서:

- 모달 상단 위치 동일
- 모달 높이 동일
- 모달 모서리 위치 동일
- 화면이 위아래로 튀지 않음
- 모달이 축소되거나 다시 확대되지 않음

==================================================
6. 기존 키보드 내리기 기능 유지
==================================================

현재 구현된 다음 기능은 그대로 유지하세요.

- 리스트 드래그 시 키보드 내리기
- 빈 영역 탭 시 Keyboard.dismiss()
- 검색창 오른쪽 완료 버튼
- 완료 버튼을 누르면 키보드가 내려가는 기능

이 기능들을 제거하거나 변경하지 마세요.

==================================================
7. 기존 기능 변경 금지
==================================================

다음 기능은 수정하지 마세요.

- 통합 검색
- 레벨 검색
- 레벨 선택
- 나의 템플릿
- 문장 선택
- 문장 추가 버튼
- 삽입 예정 미리보기
- 바로 전 삭제
- 전체 삭제
- 완료·삽입
- 취소
- 카테고리와 레벨 데이터
- 문장 카드 디자인
- 현재 색상과 디자인 스타일

이번 작업은 오직
키보드 표시 여부에 따라 모달 크기가 변하는 문제만 수정합니다.

==================================================
8. 확인 항목
==================================================

수정 후 다음을 코드상 확인하세요.

- keyboardVisible에 따른 모달 height 분기 없음
- keyboardHeight를 모달 height에서 빼는 코드 없음
- KeyboardAvoidingView가 모달 외곽 크기를 변경하지 않음
- 모달 컨테이너 높이가 항상 화면의 약 90%
- 검색창 포커스 전환 시 레이아웃 점프 없음
- 키보드가 열리고 닫혀도 모달 상단 위치 고정
- FlatList 스크롤과 문장 선택 정상
- 키보드 완료 버튼 정상
