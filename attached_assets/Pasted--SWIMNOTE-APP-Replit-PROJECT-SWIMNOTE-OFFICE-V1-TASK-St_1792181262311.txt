2. 실제 공간 분할
────────────────────

업무 영역과 AI 매니저를 정상 layout 흐름에서 상하 분할한다.

- AI 카드가 커지면 업무 영역의 실제 높이가 감소.
- 회원 상세 Drawer도 업무 영역 높이 안에서 동작.
- AI 카드가 업무 화면·Drawer·버튼을 덮지 않음.
- fixed/absolute 위치로 겹침만 숨기는 해결 금지.
  내부 요소의 적절한 위치 지정까지 일괄 금지하는 뜻은 아님.
- CSS transform:scale, zoom, Electron zoom으로
  대시보드 전체를 축소해 끼워 넣지 않음.
- 글자·버튼·입력칸의 읽기 및 조작 크기 유지.
- 업무 내용은 재배치·내부 스크롤로 대응.

가로 폭이 바뀌지 않고 높이만 줄면:
- 카드 열 수를 불필요하게 바꾸지 않음.
- 보이는 내용 높이와 스크롤 영역만 조정.

가로 폭이 줄면:
- 기존 카드의 4/2/1열 반응형 동작 유지.
- 회원표 최소 열 폭·줄바꿈 정책·내부 가로 스크롤 유지.
- 앱 전체 가로 스크롤로 문제를 넘기지 않음.

3. AI 매니저의 세 상태
────────────────────

A. 일반
- 기본 처리 영역 약 10줄을 목표로 하되 창 높이에 맞게 조정.
- 경계 드래그·기존 키보드 조절 유지.
- 업무 영역에 실제 사용 가능한 최소 높이 확보.
- 일반 조절의 최대 높이는 남는 공간을 기준으로 제한.

B. 접기
- 제목·연결 상태·입력창·첨부 조작 유지.
- 처리 내역 영역은 완전히 숨김.
- 반쯤 잘린 안내·작업 카드·불필요한 스크롤바가 남지 않음.
- 펼치면 이전 선호 높이를 현재 창 크기에 맞춰 복원.

C. 크게 보기
- 사용자가 명시적으로 선택한 AI 집중 상태.
- 일반 상태보다 넓은 AI 영역을 허용.
- 업무 영역은 겹침 없이 줄이고 스크롤 가능하게 유지.
- “원래 크기”로 직전 일반 높이·조회 상태 복원.
- 자동 확대·입력 포커스만으로 확대 금지.
- 매우 낮은 창에서는 모든 영역의 과도한 최소 높이 합계로
  입력창·버튼이 화면 밖으로 밀리지 않도록 우선순위 적용.

일반 상태의 업무 최소 높이와 각 상태 치수는
현재 컴포넌트의 실제 CSS·상호작용 검증으로 결정하고 보고한다.
모든 화면에 동일한 고정 px를 강제하지 않는다.

4. 카드 내부 구조 수정
────────────────────

항상 다음 순서로 구성:
제목·상태·조작
→ 남은 공간을 사용하는 처리 내역
→ 첨부 목록·입력창·간단한 안내

- 입력창은 카드 하단에 위치.
- 확대 시 입력창 아래에 큰 빈 공간이 생기지 않음.
- 증가한 높이는 처리 내역이 사용.
- 처리 내역과 업무 영역은 독립 스크롤.
- 긴 입력은 상한 안에서 확장 후 내부 스크롤.
- 첨부가 늘어도 입력창·제거·주요 조작 접근 가능.
- 실제 데이터가 없는 처리 영역을 가짜 결과로 채우지 않음.

카드 형태:
기존 둥근 모서리·절제된 테두리·약한 그림자 유지.
중첩 카드·불필요한 장식·큰 빈 여백 추가 금지.

────────────────────
5. 안내와 조작 정돈
────────────────────

- 상단 진단 접기 구조 유지.
- 중요한 장애 상태는 계속 확인 가능.
- 정상 시 긴 기술 안내가 업무 공간을 상시 차지하지 않음.
- 현재 기능 제한 안내는 작은 “조회 전용” 표시와
  필요 시 펼치는 설명으로 정리.
- AI 미연결 안내는 짧고 명확하게 표시.
- 파일 형식·용량 제한 상세는 첨부 도움말로 이동.
- 실제 첨부 오류는 해당 위치에 표시.
- 도움말은 마우스뿐 아니라 키보드·클릭으로 접근 가능.
- 같은 내용을 제목·본문·입력창 아래에 반복하지 않음.

기존 공통 hover/pressed/selected/focus-visible/disabled 유지.
뒤로·앞으로·이동 가능한 Breadcrumb는 클릭 영역과 여백 확보.
현재 위치는 비클릭 텍스트로 구분.
사용 불가 이동은 실제 disabled 처리.
일반 Web 스타일·동작에 OFFICE 규칙을 무단 확대하지 않음.

6. 검은 세로줄 원인 확인·최소 수정
────────────────────

사용자 사진에서 “홈 현황”, “회원목록” 앞에
텍스트 커서처럼 보이는 검은 세로줄이 관찰됐다.

사진만으로 원인을 확정하지 않는다.

관련 요소에 한정하여 확인:
- 의도된 border·pseudo-element·선택 표시 여부.
- contentEditable·텍스트 selection·focus 처리.
- Electron/Chromium caret browsing 관련 설정·키 처리.
- 가능한 경우 동일 packaged 조건의 재현.

확인된 원인에 맞춰 최소 수정한다.
코드와 재현 근거 없이 원인을 확정하거나 수정 완료로 보고하지 않는다.

금지:
- 앱 전체 outline 제거.
- 모든 요소의 caret-color:transparent 적용.
- 광범위 user-select:none.
- 키보드 탐색·접근성 기능 일괄 차단.
- 실제 입력창의 커서·텍스트 선택 기능 훼손.

현재 위치는 굵기·배경 등 명확한 스타일로,
키보드 포커스는 focus-visible 테두리로 구분한다.

원인이 이 환경에서 확인되지 않으면:
해당 항목만 미확인으로 남기고,
완료 가능한 나머지 배치 보완을 진행한다.
원인 없는 임시 CSS로 숨기지 않는다.
