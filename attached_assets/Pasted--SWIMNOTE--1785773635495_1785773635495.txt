1. BUG-1 — occurrence_date 필드 통일
━━━━━━━━━━━━━━━━━━━━━━

서버 응답 계약을 기준으로 클라이언트를 수정한다.

확정 필드:

occurrence_date: string

수정 파일:

- artifacts/swim-app/components/teacher/my-schedule/ClassDetailSheet.tsx
- artifacts/swim-app/app/(teacher)/makeups.tsx

모든 아래 사용을 수정한다.

- occ.date
- selectedOccurrence.date
- key={occ.date}
- fmtOcc(occ.date)
- 저장 API에 전달되는 date
- 섹션 정렬·비교에 사용되는 date

전부 다음으로 통일:

- occ.occurrence_date
- selectedOccurrence.occurrence_date

클라이언트 타입도 정확히 선언한다.

예:

interface MakeupOccurrence {
  class_group_id: string;
  class_name: string;
  occurrence_date: string;
  schedule_time: string;
  teacher_id?: string | null;
  teacher_name?: string | null;
  is_mine: boolean;
  available_slots: number;
  is_full: boolean;
  is_past: boolean;
  is_today: boolean;
  is_future: boolean;
}

금지:

- 서버 필드를 date로 다시 변경
- date와 occurrence_date를 동시에 지원하는 임시 fallback
- any 타입으로 숨기기

서버·클라이언트 Contract를 occurrence_date 하나로 고정한다.

2. 공통 회차 검증 함수 작성
━━━━━━━━━━━━━━━━━━━━━━

assign과 complete-direct가 서로 다른 검증을 하도록 중복 구현하지 않는다.

대상 파일:

artifacts/api-server/src/routes/teachers.ts

해당 파일 내부 helper 또는 적절한 신규 lib 파일에
보강 회차 검증 공통 함수를 만든다.

권장 구조:

async function validateMakeupOccurrence(params: {
  txOrDb: typeof db;
  makeupSession: MakeupSessionRow;
  classGroupId: string;
  occurrenceDate: string;
  poolId: string;
}): Promise<{
  classGroup: ClassGroupRow;
  occurrenceDate: string;
  kstToday: string;
  availableSlots: number;
  isFull: boolean;
  isPast: boolean;
  isToday: boolean;
  isFuture: boolean;
}>

검증 항목:

1. occurrenceDate가 YYYY-MM-DD 형식인지
2. 실제 존재하는 날짜인지
3. occurrenceDate > absence_date
   - 현재 eligible-occurrences가 결석일 다음 날부터 생성하므로
     저장 API도 동일 정책을 적용한다
4. occurrenceDate <= expire_at
5. expire_at이 없으면 기존 서버 기본 유효기간 규칙과 동일한 종료일 사용
6. class_group_id가 존재하는지
7. 해당 반이 makeup session과 같은 swimming_pool_id인지
8. 해당 반이 삭제·비활성 상태가 아닌지
9. occurrenceDate의 요일이 class_group.schedule_days에 포함되는지
10. pool_holidays에 해당 날짜가 등록되어 있지 않은지
11. 현재 정원과 available_slots 재계산
12. KST 오늘을 기준으로 past/today/future 재산출

중요:

클라이언트가 전송한 다음 필드는 신뢰하지 않는다.

- is_future
- is_today
- is_past
- is_full
- available_slots

서버가 occurrenceDate와 현재 DB를 기준으로 다시 계산한다.

5. 정원 계산 정확성 재확인
━━━━━━━━━━━━━━━━━━━━━━

현재 eligible-occurrences의 정원 계산은 다음을 사용한다.

SELECT COUNT(*)
FROM students
WHERE class_group_id = class_group_id
  AND status IN (...)
  AND deleted_at IS NULL

하지만 SWIMNOTE는 assigned_class_ids 다중 반 배정 구조도 사용한다.

따라서 실제 기존 정원 계산 표준을 Repository에서 확인한다.

확인 항목:

- class_group_id만 세는지
- assigned_class_ids에 포함된 학생도 세는지
- 이미 해당 회차에 배정된 보강생을 추가로 세는지
- 기존 eligible-classes의 available_slots 계산과 동일한지

보강 회차 API와 저장 API는 반드시 같은 정원 계산 helper를 사용한다.

정원 계산이 다르면 다음 오류가 발생한다.

- 목록에서는 자리가 있는데 저장 시 마감
- 목록에서는 마감인데 실제로는 자리 있음
- 다중 반 학생 누락
- 기존 보강 예약 인원 누락

기존 표준 계산을 찾으면 재사용한다.
없으면 공통 helper를 만들되 일반 반배정 로직은 변경하지 않는다.

9. eligible-occurrences API 검증 보완
━━━━━━━━━━━━━━━━━━━━━━

현재 API의 날짜 생성은 대체로 맞지만 아래를 확인·보완한다.

1. expire_at 변환에
   new Date(expire_at).toISOString().slice(0,10)
   사용 시 KST 날짜가 하루 달라질 가능성 확인

expire_at이 timestamptz라면 Asia/Seoul 기준 날짜로 변환한다.
date 타입이면 문자열을 그대로 사용한다.

2. 기본 endDate +56일 계산도 UTC/KST 혼용을 제거한다.

3. parseDayNums와 Date.getDay()가 서버 timezone 영향 없이
   date-only 값 기준으로 일치하는지 확인한다.

날짜 전용 helper를 사용하여
YYYY-MM-DD 문자열을 UTC/KST 변환 과정에서 하루 이동시키지 않는다.

10. Transaction·중복 방지
━━━━━━━━━━━━━━━━━━━━━━

assign과 complete-direct 모두:

BEGIN
  SELECT makeup_sessions ... FOR UPDATE
  상태 검증
  회차 검증
  정원/날짜 정책 검증
  makeup_sessions UPDATE
  필요한 attendance UPSERT
COMMIT

동일 보강 세션에 동시에 두 요청이 들어오면
한 요청만 상태 변경하도록 한다.

complete-direct 재호출 정책:

- 이미 completed이고 같은 assigned_date/class_group_id라면
  기존 결과 반환을 선택할 수 있음
- 다른 회차로 재완료하려 하면 409
- 최소한 attendance나 완료 횟수가 이중 생성되면 안 됨

현재 코드와 가장 작은 변경으로 구현하고,
정책 선택을 완료 보고서에 명시한다.
