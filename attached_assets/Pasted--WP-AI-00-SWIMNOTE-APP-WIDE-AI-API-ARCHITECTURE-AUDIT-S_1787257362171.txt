# [WP-AI-00 — SWIMNOTE APP-WIDE AI/API ARCHITECTURE AUDIT]

목적:

SWIMNOTE 전체 앱/서버/백그라운드 기능을 전수 조사하여

1. GPT nano / GPT / OpenAI API를 적용하면
   정확도·속도·자동화·운영효율이 크게 증가하는 기능

2. 외부 전문 API를 적용하면
   직접 구현보다 효율성이 크게 증가하는 기능

3. AI/API를 붙이지 않고 기존 deterministic code/SQL로
   유지하는 것이 더 적절한 기능

을 실제 현재 코드 기준으로 분류한다.

이번 작업은
READ-ONLY ARCHITECTURE AUDIT ONLY.

코드 수정 금지.
DB write 금지.
외부 API 실제 호출 금지.
Render deploy 금지.
Expo OTA 금지.
전체 regression test 금지.

==================================================
0. 현재 확정된 제품 방향
==================================================

앞으로 아래 기능은 AI 적극 활용 방향:

- Customer Support
- Parent Curriculum Search
- AI Diary
- Future Growth Report

기본 AI architecture:

DB / verified data
→ broad retrieval
→ Evidence Pack
→ GPT nano 적극 활용
→ grounded output
→ server validation

복잡한 자연어 의미 이해를
regex / intent / action / facet 규칙으로 계속 확장하지 않는다.

deterministic logic은:

- auth
- role
- tenant/pool isolation
- payment
- entitlement
- quota
- DB integrity
- policy enforcement
- source validation

등 확정적 판단이 필요한 곳에 유지.

4. 기능별 AI/API 기회 분석
==================================================

각 실제 기능마다 다음 중 하나를 지정.

TYPE A
NANO GROUNDED

DB/verified data retrieval
→ nano
→ grounded output

TYPE B
NANO INTERPRETATION

자연어 해석/분류/정리/라우팅

TYPE C
ADVANCED GPT

복합 분석/추론/리포트처럼
nano만으로 부족할 가능성이 높은 기능

TYPE D
EXTERNAL SPECIALIZED API

전문 API를 붙이는 것이 직접 구현보다
명확하게 효율적인 기능

TYPE E
DETERMINISTIC ONLY

AI/API 필요 없음.
