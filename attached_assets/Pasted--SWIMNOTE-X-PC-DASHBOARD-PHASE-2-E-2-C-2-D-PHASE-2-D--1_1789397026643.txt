1. 2-D 잔여 #1
pool_admin Growth Report 승인 route 확인
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

현재 Dashboard 승인 API:

POST /teacher/growth-reports/:id/review

입니다.

PC Dashboard는 pool_admin 전용이므로
반드시 Backend route의 auth middleware와 role 조건을
코드에서 직접 확인하십시오.

확인:

- pool_admin 허용 여부
- teacher만 허용인지
- pool isolation
- report access validation

pool_admin이 실제 허용되면:
현 구현 유지.

pool_admin이 403 구조라면:
기존 admin용 승인/review contract가 있는지 조사.

기존 정상 admin endpoint가 있으면 교체.

없고 관리자 검수 workflow가 실제로 막히는 구조라면
Frontend 우회 금지.

최소 Backend 수정이 정말 필요할 경우에만
기존 review service를 재사용하는 admin route 수준의
최소 수정 허용.

DB/schema 변경 금지.

단:

POST /admin/growth-reports/:id/mark-reviewed

가 단순 admin_reviewed_at 기록만 하고
실제 APPROVED transition을 하지 않는다면
승인 대체 endpoint로 사용하지 마십시오.

최종적으로:

pool_admin
→ 개별 승인
→ 실제 APPROVED

가 되어야 합니다.
