==================================================
3. MEMBER LIFECYCLE ELIGIBILITY
==================================================

무료 발급 대상은
5일 발급 시점에 정상 재원/수강 상태인 회원.

제외:

- 연기
- 휴회
- 퇴원
- 수강 종료/비활성에 해당하는 기존 실제 상태

중요:

DB/code에 존재하는 실제 lifecycle source-of-truth와
실제 enum/value를 먼저 조사할 것.

상태 이름 추측 금지.

퇴원 후 보강수업 일정이 남아 있어도
무료 리포트 발급 대상 아님.

scheduled lesson / makeup existence보다
member lifecycle status가 우선.

이미 과거 PUBLISHED 된 리포트는
회원 상태 변경으로 삭제하지 않음.

4. ELIGIBILITY RECHECK
==================================================

==================================================
5. REVIEW / PUBLISH STATE
==================================================

현재 Growth Report state transition을 실제 코드 기준으로 확인:

OPEN
PREANALYZING
...
COMPLETE
REVIEW_REQUIRED
PUBLISHED

등 실제 존재하는 전체 상태.

특히:

현재 REVIEW_REQUIRED가 사람 검토 gate인지,
자동 publication 경로가 이미 있는지 조사.

REVIEW_REQUIRED를 임의로 제거하거나
자동 PASS 처리하지 말 것.

"5일 자동발급"과
현재 review safety를 어떻게 연결할지
설계안만 제시.

==================================================

새 item type으로 넣을 수 있는지 확인.

요구사항:

- 매월 report history 유지
- 새 report가 이전 report를 overwrite하지 않음
- latest는 가장 최근 PUBLISHED 기준
- 새달 report가 FAILED/OPEN/REVIEW_REQUIRED이면
  이전 PUBLISHED가 latest에서 사라지면 안 됨

필요:
- 현재 feed table/model
- item type 구조
- parent feed query
- deep link 구조
- report detail route
