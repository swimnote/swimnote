# SWIMNOTE 학부모 Home 최종 보완 작업 지시문

이번 작업은 이미 완성된 학부모 Home 피드 구조를 유지하면서,
사진 크게 보기·사진 저장·묶음 다운로드·영상 접근 UX를 최종 보완하는 작업입니다.

이번 작업이 끝나면 학부모 Home 개편을 종료할 예정입니다.

절대 Home 전체를 다시 작성하지 마세요.
현재 완료된 레이아웃과 데이터 구조를 유지하고,
아래 명시된 기능만 정확히 보완하세요.

OTA 배포와 운영 Publish는 금지합니다.
작업 완료 후 검증 보고서를 제출하고 대기하세요.

4. 사진 묶음의 정확한 기준
==================================================

사진은 단순히 날짜 문자열만으로 묶지 마세요.

기본 묶음 기준은 반드시 다음과 같습니다.

- 동일한 diary_id
- 동일한 학생
- 동일한 수업일지

한 일지에 포함된 다음 사진은 모두 하나의 사진 묶음으로 취급하세요.

- common photos
- individual student photos

현재 코드의 다음 결합 구조를 유지할 수 있습니다.

allPhotos = [...commonPhotos, ...individualPhotos]

단, 중복 사진이 있으면 ID 또는 원본 URL 기준으로 중복 제거하세요.

같은 날짜에 일지가 여러 개 존재할 수 있으므로,
다른 diary_id의 사진을 하나의 묶음에 섞지 마세요.

화면 문구는 사용자에게 이해하기 쉽게 아래처럼 표시할 수 있습니다.

- 이 수업 사진 모두 저장
- 이 일지 사진 모두 저장

기술적인 묶음 기준은 diary_id입니다.

==================================================
5. Home 사진 그리드 유지
==================================================

현재 2열 사진 그리드는 유지하세요.

사진 수별 동작:

- 0장: 사진 영역 미표시
- 1장: 왼쪽 한 칸에 표시
- 2장 이상: 2열 그리드
- 최대 10장 전부 표시
- 숨김 없음
- +N 처리 없음
- 가로 슬라이더 없음

사진을 누르면 해당 사진의 index를 기준으로 전체화면 사진 뷰어를 여세요.

예:

onPress={() => openViewer({
  diaryId: entry.id,
  photos: allPhotos,
  initialIndex: index,
})}

==================================================
6. 전체화면 사진 뷰어
==================================================

사진을 누르면 전체화면 Modal 또는 기존 프로젝트 표준 전체화면 뷰어가 열려야 합니다.

필수 구성:

상단:

- 닫기 버튼
- 현재 위치 표시
- 예: 3 / 8

중앙:

- 현재 사진
- 화면에 맞춰 표시
- 원본 비율 유지
- 왜곡 금지
- 검은색 또는 어두운 배경

하단:

- 현재 사진 저장
- 이 수업 사진 모두 저장

필요하다면 공유 버튼을 유지할 수 있지만,
불필요하게 많은 버튼을 추가하지 마세요.

권장 버튼 구성:

[현재 사진 저장] [전체 저장]

또는

[저장] [이 수업 사진 모두 저장]

==================================================
7. 좌우 이동 범위
==================================================

전체화면 사진 뷰어에서는 같은 일지의 사진만 좌우로 이동할 수 있어야 합니다.

허용 범위:

- 현재 diary_id의 allPhotos 배열

금지:

- 다음 일지 사진으로 자동 이동
- 이전 일지 사진으로 이동
- 다른 날짜의 사진으로 이동
- 다른 학생의 사진으로 이동
- 앨범 전체 사진으로 이동

예:

7월 22일 일지 사진 8장
→ 1번부터 8번까지만 이동 가능

8번에서 더 넘기면 종료되거나 그대로 유지해야 하며,
다음 일지 사진으로 넘어가면 안 됩니다.

==================================================
8. 좌우 스와이프
==================================================

전체화면 사진 뷰어에서 좌우 스와이프를 지원하세요.

권장 구현:

- 수평 FlatList
- pagingEnabled
- initialScrollIndex
- getItemLayout
- onMomentumScrollEnd로 현재 index 계산

또는 현재 프로젝트에서 이미 안정적으로 사용하는 사진 뷰어 방식이 있다면 재사용하세요.

중요:

- 수평 이동만 사용
- 세로 FlatList 중첩 금지
- 스와이프 중 index가 정확히 갱신
- 1 / N 표시가 정확히 갱신
- 마지막 사진 이후 다른 묶음으로 이동 금지

==================================================
9. 확대·축소
==================================================

프로젝트에 이미 안정적으로 사용하는 확대 뷰어가 있다면 핀치 줌을 재사용하세요.

기존 안정된 확대 컴포넌트가 없다면,
이번 작업에서 무리하게 신규 외부 라이브러리를 설치하지 마세요.

우선순위:

1. 기존 프로젝트 확대 컴포넌트 재사용
2. 현재 설치된 라이브러리로 구현
3. 불가능하면 원본 비율 전체화면 표시까지만 구현하고 보고

신규 패키지 설치는 승인 없이 금지합니다.

확대를 구현할 경우:

- 핀치 줌
- 더블탭 확대는 선택
- 확대 상태에서 사진 왜곡 금지
- 사진 전환 시 확대 상태 초기화

==================================================
10. 현재 사진 저장
==================================================

`현재 사진 저장` 버튼은 현재 보고 있는 사진 1장만 기기 사진첩에 저장해야 합니다.

반드시 기존 프로젝트의 권한 처리 방식과 저장 방식을 재사용하세요.

필수 동작:

1. 사진 라이브러리 권한 확인
2. 권한이 없으면 권한 요청
3. 거부되면 명확한 안내
4. 원본 또는 앱이 제공하는 최고 화질 URL 다운로드
5. 사진첩 저장
6. 성공 안내
7. 실패 안내

성공 문구 예:

- 사진이 저장되었습니다.

실패 문구 예:

- 사진을 저장하지 못했습니다. 다시 시도해 주세요.

권한 거부 문구 예:

- 사진 저장 권한이 필요합니다.
- 설정에서 사진 접근 권한을 허용해 주세요.

저장 중 중복 탭을 막으세요.

==================================================
11. 묶음 다운로드
==================================================

`이 수업 사진 모두 저장` 버튼은 현재 일지의 사진만 전부 저장해야 합니다.

대상:

- 현재 diary_id의 allPhotos
- 공통 사진 + 해당 학생 개별 사진
- 중복 제거 후 전체

예:

현재 일지 사진이 8장이면
8장 모두 저장

다른 일지 사진은 절대 포함하지 않음

==================================================
12. 묶음 다운로드 확인창
==================================================

전체 저장 버튼을 누르면 바로 저장하지 말고 확인창을 표시하세요.

예:

제목:
이 수업 사진 모두 저장

본문:
사진 8장을 기기에 저장하시겠습니까?

버튼:

- 취소
- 저장

사진이 1장뿐이어도 전체 저장 버튼을 숨길 필요는 없지만,
UX가 중복된다고 판단되면 2장 이상일 때만 표시해도 됩니다.

선택한 방식을 완료 보고서에 적으세요.

==================================================
13. 묶음 다운로드 진행 상태
==================================================

여러 장 저장 시 진행 상태를 반드시 보여주세요.

예:

- 사진 저장 중...
- 8장 중 3장 저장 중
- 3 / 8

저장 중에는:

- 전체 저장 버튼 비활성화
- Modal 닫기 방지 여부는 현재 UX에 맞게 결정
- 중복 실행 방지
- 같은 사진을 동시에 여러 번 저장하지 않음

권장:

순차 저장 또는 제한된 동시 저장

모든 사진을 무제한 병렬 다운로드하지 마세요.

모바일 메모리와 네트워크 과부하를 방지하세요.

==================================================
14. 일부 저장 실패 처리
==================================================

묶음 다운로드 도중 일부 사진이 실패할 수 있습니다.

전체 작업을 즉시 중단하지 말고,
가능한 사진은 계속 저장하세요.

완료 후 결과를 구분해서 표시하세요.

전부 성공:

- 사진 8장이 저장되었습니다.

일부 실패:

- 사진 8장 중 6장이 저장되었습니다.
- 2장은 저장하지 못했습니다.

전부 실패:

- 사진을 저장하지 못했습니다. 다시 시도해 주세요.

완료 결과 데이터:

- total
- successCount
- failedCount

오류가 발생해도 앱이 Crash하면 안 됩니다.

==================================================
15. 파일명과 저장 방식
==================================================

운영체제 사진첩 저장 방식상 파일명이 보존되지 않을 수 있습니다.

가능한 경우 다운로드 임시 파일 이름은 아래 구조를 사용하세요.

swimnote_{date}_{diaryId}_{index}.jpg

예:

swimnote_20260722_abcd1234_01.jpg

단:

- 확장자는 실제 MIME 타입 기준
- jpg로 강제 변환 금지
- 원본 포맷을 최대한 유지
- 기존 저장 유틸이 있다면 기존 방식 우선

==================================================
16. 사진 URL 처리
==================================================

사진 객체에서 실제 저장 가능한 URL 필드를 정확히 확인하세요.

예상 후보:

- url
- original_url
- file_url
- download_url
- media_url

화면 표시용 썸네일 URL과 저장용 원본 URL이 다르면:

- 화면: thumbnail URL
- 저장: original URL

을 사용하세요.

필드명을 추측하지 말고 실제 PhotoItem 타입과 API 응답을 확인하세요.

URL이 없거나 유효하지 않은 사진은 건너뛰고 실패 개수에 포함하세요.

==================================================
17. 캐시 및 Blob 정리
==================================================

사진 저장을 위해 임시 파일을 생성한다면,
저장 성공 또는 실패 후 임시 파일을 정리하세요.

금지:

- 임시 파일 계속 누적
- Blob URL 누수
- 다운로드 작업 후 cleanup 미처리
- 컴포넌트 unmount 후 state 업데이트

필요하면 취소 플래그 또는 mountedRef를 사용하세요.

==================================================
19. 영상 UX 최종 보완
==================================================

현재 영상은:

Home
→ diary 화면
→ 해당 일지
→ 영상 재생

구조입니다.

이번 작업에서는 가능하면 Home에서 바로 영상에 접근할 수 있도록 개선하세요.

단, 기존 Home 피드와 사진 기능을 깨뜨리면서 무리하게 구현하지 마세요.

우선순위:

1. 기존 영상 재생 Modal 또는 기존 DiaryPhotoStrip의 영상 플레이어를 Home 전용으로 안전하게 재사용
2. Home에서 `영상 N개 보기`를 누르면 현재 일지의 영상 목록 Modal 표시
3. 영상 선택 시 기존 영상 플레이어 실행

영상 묶음도 반드시 현재 diary_id 기준이어야 합니다.

다른 일지 영상이 섞이면 안 됩니다.

==================================================
20. 영상 직접 재생이 위험한 경우
==================================================

기존 영상 플레이어를 Home에서 재사용하려면 공통 코드 대규모 수정이 필요하거나,
새로운 Runtime Error 위험이 큰 경우에는 무리하게 수정하지 마세요.

그 경우 현재 방식은 유지하되 아래를 개선하세요.

- `영상 N개 보기` 버튼 클릭
- diary_id 전달
- diary 화면 해당 일지로 정확히 스크롤
- 해당 DiaryCard 자동 열림
- 해당 영상 영역이 바로 보이도록 가능하면 스크롤
- backTo=home 정상 작동

현재 방식 유지 시 완료 보고서에 정확히 이유를 적으세요.

==================================================
21. 앨범 보기 회귀 검증
==================================================

기존 버튼:

/(parent)/photos?backTo=home

이 실제로 정상 작동하는지 확인하세요.

검증:

- 선택된 자녀 기준 앨범
- 뒤로가기 시 Home 복귀
- 다른 자녀로 바꾼 후 앨범도 함께 변경
- Runtime Error 없음

필요한 수정이 없다면 코드 변경하지 마세요.

23. AsyncStorage 캐시 검증
==================================================

현재 일지 캐시는 아래 순서여야 합니다.

1. 캐시 데이터가 있으면 즉시 표시
2. 동시에 최신 API 호출
3. API 성공 시 최신 데이터로 교체
4. 최신 데이터를 다시 캐시에 저장
5. API 실패 시 캐시 유지
6. 다른 자녀 캐시와 키 분리

캐시만 표시하고 API 호출을 생략하면 안 됩니다.

캐시 키에 studentId를 포함하세요.

예:

parent_home_diary_${studentId}

오래된 자녀의 일지가 다른 자녀에게 표시되면 안 됩니다.
