경로:

- 두 개의 인증 상태를 따로 유지하지 않는다.
- 기존 API·Pool·역할·X 정책 재사용.

- 기존 Web 경로의 동작 보존.
- 다른 메뉴는 이번에 구현하거나 실행 검증하지 않는다.
- 미지원 메뉴가 빈 화면이나 잘못된 성공 상태로

4. 조회와 쓰기 분리
- 회원 수정·반 배정·퇴원·삭제·등록 등 쓰기 동작은
  이번 Desktop 검증 범위에서 실행할 수 없도록 처리.
- 기존 Web의 편집 기능은 임의로 제거하지 않는다.
- 읽기 화면 연결에 저장 revision 계약을 새로 요구하지 않는다.
- 저장 경쟁 안전성은 쓰기 연결 전 필수 Gate로 유지.
- Backend 계약이 필요한 저장 기능은 이번에 확장하지 않는다.

5. SSE·화면 상태
- 기존 event→query mapping으로 관련 조회 갱신.
- 재연결 후 실제 조회가 끝나야 최신 상태로 표시.
- 검색·필터·선택한 회원·Drawer 상태가 갱신으로
  불필요하게 초기화되지 않도록 한다.
- 늦은 응답·계정/Pool 교체·로그아웃 시
  이전 사용자의 데이터가 남지 않도록 한다.
- 편집 가능한 입력이 있다면 공통 draft 보호 적용.
- 단순 검색 입력과 저장할 업무 편집 상태를 구분.
- 운영 데이터 변경 없이 fixture로 이벤트·재조회 흐름 검증.
- 실제 운영 변경→SSE 갱신은 미검증으로 남긴다.
