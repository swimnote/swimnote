WP-CS10
FULL APP SUPPORT COVERAGE SCAN FOUNDATION

Evidence verification 결과 Coverage Registry의 기본 구조는 확인되었으나
24개의 UNMAPPED_SCREENS가 존재한다.

새로운 절대 성공조건:

모든 launch-relevant route/action은 반드시

A. Coverage Record에 매핑

또는

B. EXCLUDED_WITH_REASON으로 명시

되어야 한다.

최종:

UNMAPPED_CORE_SURFACES = 0

이어야 WP-CS10을 PASS할 수 있다.

이번 작업은 새로운 WP가 아니다.
WP-CS10 종료를 위한 최소 보완 작업이다.

각 항목의 실제 source를 열고 다음 중 하나로 분류한다.

MAPPED
= launch-relevant이며 기존 Coverage Record가 이미 실제 기능을 커버.
이 경우 해당 coverage_id와 source_ref를 명시적으로 연결한다.

NEW_COVERAGE_REQUIRED
= launch-relevant인데 현재 Coverage Record가 실제로 없음.
이 경우 기존 registry contract를 재사용하여 최소 Coverage Record를 추가한다.

EXCLUDED_WITH_REASON
= launch support surface에서 의도적으로 제외 가능한 항목.

추측으로 제외하지 않는다.

2. EXCLUDED_WITH_REASON 규칙
━━━━━━━━━━━━━━━━━━━━━━

단순히:

"중요하지 않음"
"내부 기능"
"나중에"

같은 이유 금지.

각 제외 항목은 최소 다음을 명시한다.

* source_ref
* route/screen/action
* exclusion_reason_code
* human-readable reason
* launch relevance 판정 근거

허용 가능한 reason 예:

SUPER_ADMIN_INTERNAL_ONLY
DEVELOPER_DIAGNOSTIC_ONLY
DEAD_OR_UNREACHABLE_ROUTE
DUPLICATE_ALIAS_OF_MAPPED_SURFACE
NON_USER_ACTIONABLE_VIEW
POST_LAUNCH_FEATURE_DISABLED

실제 repository 근거가 있어야 한다.

특히 일반:

pool_admin
sub_admin
teacher
parent_account

사용자가 접근 가능한 surface를
편의상 제외하지 않는다.

━━━━━━━━━━━━━━━━━━━━━━
3. Route뿐 아니라 Action도 검사
━━━━━━━━━━━━━━━━━━━━━━

화면이 Coverage Record에 있다고 해서
그 화면의 핵심 action이 모두 covered라고 가정하지 않는다.

24개 surface와 관련된 실제 사용자 action을 확인한다.

예:

save
submit
approve
reject
upload
delete
invite
grant
filter
open detail
review
retry
generate

등.

launch-relevant action마다:

* existing coverage_id
* new coverage_id
* EXCLUDED_WITH_REASON

중 하나가 있어야 한다.

최종적으로:

UNMAPPED_CORE_ROUTES = 0
UNMAPPED_CORE_ACTIONS = 0

이어야 한다.

그리고 통합값:

UNMAPPED_CORE_SURFACES = 0

을 산출한다.

4. 기존 64 Coverage Record 재사용 우선
━━━━━━━━━━━━━━━━━━━━━━

새 record를 무조건 늘리지 않는다.

기존 Coverage Record가 동일 support intent/failure surface를
실제로 커버한다면:

source_refs
related route/action metadata

를 연결하여 재사용한다.

기능적으로 다른 support 문제를
숫자를 줄이기 위해 억지로 하나의 record에 합치지 않는다.
