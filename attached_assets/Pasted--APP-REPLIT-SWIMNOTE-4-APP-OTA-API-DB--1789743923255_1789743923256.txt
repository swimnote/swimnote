여러 사진이 중복 등록됨.

단순 UI 중복 렌더링인지,
실제로 DB/스토리지에 중복 저장되는지부터 구분하십시오.

확인:

- 선택한 local asset 개수
- upload 요청 횟수

- API insert 횟수
- DB 생성 row 수
- 업로드 완료 후 client state append/refetch 흐름

특히 다음 가능성 확인:

- upload handler 중복 호출
- 버튼 double trigger
- Promise/loop 이중 실행
- optimistic append 후 refetch 결과를 다시 append
- pagination 첫 페이지 중복 merge
- 동일 asset이 FormData에 여러 번 포함
- 서버 retry가 insert를 중복 실행

추측하지 말고 실제 코드 흐름으로 확정하십시오.

[현상 4] 업로드 사진 순서 뒤죽박죽
━━━━━━━━━━━━━━━━━━━━━━

한 번에 여러 사진을 선택해서 업로드하면
전체앨범에 표시되는 순서가
사용자가 선택한 순서 또는 촬영 순서와 다르게
뒤죽박죽 섞입니다.

확인:

APP:
- image picker 반환 배열 순서
- upload loop 순서
- Promise.all 사용 여부
- 각 사진별 sort/index/order 값 전달 여부

API/DB:
- created_at precision
- sort_order / display_order 존재 여부
- INSERT 순서 보존 여부

조회:
- 전체앨범 ORDER BY 기준
- created_at만 정렬하는지
- 동일 timestamp에서 안정적인 secondary sort가 있는지
- client가 다시 sort하는지

“업로드 완료 속도 순서” 때문에
표시 순서가 결정되는 구조인지도 확인하십시오.
