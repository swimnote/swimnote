==================================================
1. 핵심 원칙
==================================================

Teacher Review의 목적:

- 학생이 맞는지 확인
- 수업 맥락이 맞는지 확인
- 부모에게 보여주면 안 되는 오해 가능성 확인
- 명백한 사실 오류 확인
- Report publication 승인

Teacher가 하면 안 되는 것:

- F001~F070 의미 재판정
- evidence confidence 임의 변경
- 새로운 AI 분석 생성
- 근거 없는 문장 추가
- Fact Package 변조
- 수영 전문판단을 APP에서 새로 생성

==================================================
2. REVIEW ELIGIBILITY
==================================================

Teacher Review 가능 Product status:

REVIEW_REQUIRED

NOT_OPEN

QUESTION_AVAILABLE
READY_FOR_ANALYSIS

==================================================
5. REPORT FACT PACKAGE
==================================================

Fact Package는 Product DB에 보존.

Teacher Review에서
전체 JSON raw dump를 UI에 그대로 보여주지 않는다.

필요한 trace를
사람이 읽을 수 있는 형태로 제공 가능.

예:

- 이 문장이 어떤 관찰에 근거했는지
- confidence/limitation
- source count

하지만 raw diary 전체 공개는 최소화.

==================================================
6. REVIEW ACTIONS
==================================================

최소 Action:

APPROVE
REQUEST_REANALYSIS

필요하다면:
REJECT_PUBLICATION

별도 Product 상태를 새로 만들지 말고
현재 lifecycle 안에서 처리.

REVIEW_REQUIRED
→ APPROVED

REQUEST_REANALYSIS:

REVIEW_REQUIRED
→ ANALYZING

또는
READY_FOR_ANALYSIS
→ ANALYZING

현재 GR1 allowed transition과
GR3 Worker 구조를 고려하여
canonical transition 사용.

==================================================
7. REQUEST_REANALYSIS 의미
==================================================

Teacher가 재분석 요청했다고 해서
ENGINE Fact를 직접 수정하지 않는다.

Teacher는 최소 structured reason을 남긴다.

예:

WRONG_CONTEXT
STUDENT_ATTRIBUTION_CONCERN
INSUFFICIENT_CONTEXT
PARENT_VISIBILITY_CONCERN
TECHNICAL_FACT_CONCERN
OTHER

free text note optional.

이 정보가 Engine Snapshot의
teacher_review optional 필드로 들어갈 수 있도록 연결.

단 APP이 Metric 판단은 하지 않는다.

==================================================
8. TEACHER REVIEW INPUT CONTRACT
==================================================

최소:

{
  action:
    'APPROVE'
    | 'REQUEST_REANALYSIS',

  reason_code?: string,

  note?: string
}

APPROVE에는 note optional.

REQUEST_REANALYSIS에는
reason_code 필수 권장.

==================================================
9. TEACHER REVIEW SNAPSHOT INTEGRATION
==================================================

GR3 Snapshot contract에 이미:

teacher_review?: string | null

이 존재.

GR5에서는
REQUEST_REANALYSIS note/reason을
후속 ENGINE Snapshot에 전달할 수 있게
명확한 structured representation을 만든다.

가능하면 string 한 줄보다:

teacher_review: {
  reason_code,
  note
}

가 ENGINE contract와 충돌한다면
기존 contract를 깨지 말고
safe serialization/adaptation 사용.

Contract 변경이 필요하면
backward-compatible하게.

==================================================
10. NO DIRECT CONTENT EDITING
==================================================

V1 FREE Report에서는
Teacher가:

summary_text 수정
section 문장 수정
sns_summary 수정

하는 자유편집 기능을 만들지 않는다.

이유:

Grounding Validator를 통과한 ENGINE 결과를
APP에서 수정하면
Claim Trace가 깨질 수 있음.

즉:

Approve
OR
Request Reanalysis

방식.

==================================================
13. REQUEST REANALYSIS
==================================================

REQUEST_REANALYSIS 시:

teacher review metadata 저장

새 analysis request가 필요하도록
상태 전환.

중요:

기존 report_content를 즉시 삭제하지 않는다.

새 ENGINE result가 성공적으로 들어오기 전까지
기존 결과는 audit/history/debug 목적으로 보존 가능.

하지만 Parent에게 아직 publish되지 않았으므로
current review UI에서는
“재분석 중” 상태로 전환.
