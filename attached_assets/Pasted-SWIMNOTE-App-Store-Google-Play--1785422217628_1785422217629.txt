SWIMNOTE 앱 업데이트 확인 기능 오류 조사 및 수정

현재 현상:

- App Store 또는 Google Play에는 새 앱 버전이 게시돼 있음
- 기존 설치 앱에서 “업데이트 체크” 버튼을 누르면
  “최신 업데이트입니다”라고 잘못 표시됨
- 스토어에 직접 들어가면 “업데이트” 버튼이 표시됨

현재 업데이트 체크가 EAS OTA만 검사하고
스토어 네이티브 버전을 검사하지 않는 것으로 추정된다.

추측 수정하지 말고 먼저 현재 구조를 조사한다.

================================
1. 현재 업데이트 체크 구현 조사
================================

확인:

- 업데이트 체크 버튼이 있는 파일
- 버튼 onPress 함수
- expo-updates 사용 여부
- checkForUpdateAsync 호출 여부
- fetchUpdateAsync / reloadAsync 사용 여부
- 앱 설치 버전 조회 방식
- iOS buildNumber 조회 방식
- Android versionCode 조회 방식
- App Store / Play Store 최신 버전 조회 여부
- 서버에 latest-version API가 존재하는지
- 강제 업데이트 정책이 있는지

현재 기능이 다음 중 무엇인지 판정:

A. OTA만 확인
B. 스토어 버전만 확인
C. 둘 다 확인하지만 비교 오류
D. 다른 원인

================================
2. 올바른 업데이트 구조
================================

업데이트 체크는 반드시 두 단계를 분리한다.

1단계 — 스토어 네이티브 앱 업데이트

비교 항목:

- 현재 설치 앱 version
- 현재 설치 앱 buildNumber/versionCode
- 서버가 제공하는 최신 iOS version/buildNumber
- 서버가 제공하는 최신 Android version/versionCode
- 최소 지원 버전

스토어 최신 버전이 설치 버전보다 높으면:

제목:
새 버전이 있습니다

내용:
더 안정적인 SWIMNOTE 사용을 위해 앱을 업데이트해 주세요.

버튼:
- 나중에
- 업데이트하기

업데이트하기 클릭:

iOS:
App Store SWIMNOTE 페이지

Android:
Google Play SWIMNOTE 페이지

로 이동한다.

강제 업데이트 조건이면 “나중에” 버튼을 숨길 수 있도록 구조화한다.

2단계 — EAS OTA 업데이트

스토어 버전이 최신일 때만:

- Updates.checkForUpdateAsync()
- OTA 존재 시 다운로드
- 적용 전 안내
- reloadAsync

OTA가 없을 때만:

“현재 최신 버전을 사용하고 있습니다.”

표시한다.

================================
3. 버전 정보 관리
================================

Render 서버에 버전 설정 API를 만드는 방향을 우선 검토한다.

예시:

GET /api/app/version

응답 예시:

{
  "ios": {
    "latestVersion": "1.6.0",
    "latestBuild": 242,
    "minimumVersion": "1.5.5",
    "forceUpdate": false,
    "storeUrl": "..."
  },
  "android": {
    "latestVersion": "1.6.0",
    "latestBuild": 233,
    "minimumVersion": "1.5.5",
    "forceUpdate": false,
    "storeUrl": "..."
  }
}

주의:

- 앱 코드에 최신 버전을 하드코딩하지 않는다.
- 이후 스토어 업데이트마다 OTA를 다시 배포하지 않아도
  Render 설정만 변경해 업데이트를 감지할 수 있어야 한다.
- 버전 문자열은 단순 문자열 비교 금지
  예: 1.10.0과 1.9.0을 정확히 비교할 semantic version 비교 사용
- iOS와 Android를 분리한다.

================================
4. OTA 가능 여부 확인
================================

현재 프로젝트에 설치된 모듈만으로 다음 값을 읽을 수 있는지 확인:

- native app version
- iOS buildNumber
- Android versionCode
- platform

기존 expo-constants 또는 이미 설치된 모듈로 가능하면
새 네이티브 모듈을 추가하지 않고 OTA로 구현한다.

새 네이티브 패키지 추가는 금지한다.

새 네이티브 패키지 없이 불가능한 경우에만 보고하고
사용자 승인 전 package.json 또는 app.json 수정 금지.

================================
5. 오류 처리
================================

다음 상황을 구분한다.

- 스토어 버전 API 조회 실패
- 인터넷 연결 실패
- OTA 확인 실패
- 스토어 URL 열기 실패
- 이미 최신 네이티브 버전
- 네이티브는 최신이나 OTA 존재
- 네이티브와 OTA 모두 최신

버전 API 조회 실패를
“최신 버전입니다”로 표시하지 않는다.

대신:

“업데이트 정보를 확인할 수 없습니다. 잠시 후 다시 시도해 주세요.”

표시한다.
