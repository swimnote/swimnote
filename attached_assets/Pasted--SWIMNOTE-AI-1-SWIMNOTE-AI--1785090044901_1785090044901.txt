# SWIMNOTE AI 기능 1차 구현 작업설계 요청

현재 SWIMNOTE 앱에 AI 기능을 본격적으로 구현하려고 합니다.

이번 요청에서는 절대 코드를 수정하거나 구현하지 마세요.

현재 실제 코드베이스를 직접 조사한 뒤, 우리가 합의한 AI 구조를 구현하기 위한 상세 작업설계 보고서만 작성해주세요.

중요:
- 추측으로 답하지 마세요.
- 실제 관련 파일을 열어보고 현재 구현 상태를 기준으로 평가하세요.
- 기존 보고서 내용을 그대로 반복하지 말고, 현재 코드와 실제 연결 관계를 다시 확인하세요.
- 이번 단계에서는 코드 수정, 패키지 설치, DB 변경, API 추가를 하지 마세요.

==================================================
1. 이번에 구현할 범위
==================================================

이번 1차 범위는 실제 GPT 및 SWIMNOTE AI Engine 연결 전 단계입니다.

더미 AI 결과를 사용해 다음 흐름까지 완성하는 것이 목표입니다.

선생님이 일지 작성 화면에서 AI 버튼 실행
→ BaseAIModal 열림
→ 교사가 수업 내용을 텍스트 또는 현재 지원되는 입력 방식으로 입력
→ 더미 AI가 구조화된 JSON 결과 반환
→ 공통 일지가 기존 commonContent에 적용
→ 학생별 일지가 기존 studentNotes에 적용
→ 수정 화면에서는 기존 editNotes 또는 editNewNotes에 올바르게 적용
→ 교사가 결과 검토
→ 기존 저장 버튼 사용
→ 기존 handleSave / handleEditSave로 저장

실제 AI API는 이번 범위에 포함하지 않습니다.

==================================================
2. 반드시 유지할 기존 시스템 원칙
==================================================

다음 원칙은 절대 훼손하면 안 됩니다.

1.
AI를 사용하지 않으면 현재 앱과 완전히 동일하게 동작해야 합니다.

2.
AI는 직접 저장하지 않습니다.

3.
AI는 기존 화면의 state만 채웁니다.

4.
기존 handleSave와 handleEditSave는 수정하지 않습니다.

5.
기존 일지 저장 API는 수정하지 않습니다.

6.
AI 관련 컴포넌트를 제거하면 기존 일지 기능이 그대로 남아야 합니다.

7.
기존 onInsert 콜백은 공통 일지 삽입 용도로 그대로 유지합니다.

8.
학생별 일괄 삽입은 별도 콜백을 추가하는 방식으로 설계합니다.

9.
기존에 교사가 입력한 내용을 AI가 무조건 덮어쓰면 안 됩니다.

10.
Write 화면과 Edit 화면의 서로 다른 state 구조를 안전하게 처리해야 합니다.

==================================================
3. 목표 AI 결과 형식
==================================================

더미 AI와 향후 실제 SWIMNOTE AI Engine은 동일한 결과 계약을 사용해야 합니다.

예상 형식:

{
  "common": "오늘 수업의 공통 일지 내용",
  "students": [
    {
      "student_id": "101",
      "content": "학생 101의 개별 일지 내용"
    },
    {
      "student_id": "102",
      "content": "학생 102의 개별 일지 내용"
    }
  ]
}

student_id의 실제 타입이 현재 코드에서 number인지 string인지 반드시 확인하고, 현재 코드에 맞는 타입을 추천해주세요.

AI가 반환한 student_id가 현재 선택된 반의 학생 목록에 없으면 적용하지 않아야 합니다.

==================================================
4. 개인정보 처리 방향
==================================================

외부 AI 또는 향후 AI Engine에 학생 이름을 직접 전달하지 않는 구조를 목표로 합니다.

앱 내부:
- student_id와 학생 이름을 매핑

AI 전달:
- student_id 또는 익명 student_ref
- 수업에 필요한 비식별 Context

AI 반환:
- student_id 기준 결과

앱 적용:
- student_id 검증
- 내부 학생 데이터와 매핑
- 기존 state에 적용

현재 코드에서 이 구조가 가능한지 확인해주세요.

현재 UI 표시나 기존 state에 학생 이름이 포함되어 있더라도, AI 요청 payload를 만들 때 이름을 제외할 수 있는지 실제 코드 기준으로 평가해주세요.

5. 적용 정책 설계
==================================================

다음 상황에서 어떤 정책이 가장 안전한지 현재 코드 기준으로 제안해주세요.

A. 공통 일지가 비어 있는 경우
B. 공통 일지에 기존 내용이 있는 경우
C. 학생별 일지가 비어 있는 경우
D. 학생별 일지에 교사가 입력한 기존 내용이 있는 경우
E. 동일 학생에 AI 결과를 다시 적용하는 경우
F. AI 결과에 존재하지 않는 student_id가 들어온 경우
G. AI 결과의 common 또는 content가 빈 문자열인 경우
H. 일부 학생 결과만 반환된 경우
I. Write 화면에서 적용하는 경우
J. Edit 화면에서 기존 DB 노트가 있는 학생에게 적용하는 경우
K. Edit 화면에서 기존 DB 노트가 없는 학생에게 적용하는 경우

자동 덮어쓰기, 기존 내용 뒤에 추가, 사용자 확인 모달 중 어떤 정책을 사용할지 제안하고 근거를 작성해주세요.

7. 추천 구조
==================================================

아래 구조가 현재 코드에 적합한지 평가해주세요.

BaseAIModal
→ DiaryAIContent
→ useDiaryAI 또는 DiaryContextBuilder
→ Dummy AI Adapter
→ DiaryAIResult Parser
→ Write/Edit Apply Adapter
→ 기존 state
→ 기존 저장 버튼

역할을 다음처럼 분리하는 것이 적절한지도 평가해주세요.

Context Builder:
- AI에 보낼 입력 데이터 구성

AI Adapter:
- 현재는 더미 JSON 반환
- 나중에는 SWIMNOTE AI Engine API 호출로 교체

Result Parser:
- 반환 JSON 형식 검증
- 잘못된 student_id 및 빈 데이터 제거

Apply Adapter:
- Write state 적용
- Edit state 적용
- 기존 내용 병합 정책 수행

BaseAIModal은 학생 정보나 일지 state를 직접 알지 않는 공통 UI로 유지합니다.

9. 작업 단계 분리
==================================================

한 번에 전체를 구현하지 않도록, 실제 코드 기준으로 가장 안전한 구현 단계를 설계해주세요.

- 현재 AI 모달 크래시 및 기존 테스트 완료

- DiaryAIResult 타입과 더미 응답 계약만 추가

Stage 2
- 공통 일지 적용만 검증

Stage 3

Stage 4

10. 실제 앱 검증 원칙
==================================================

코드 컴파일 성공이나 API 200 응답만으로 완료 처리하지 않습니다.

각 단계는 반드시 실제 Production 또는 현재 검증 대상 앱을 실행하고 직접 조작해 확인해야 합니다.

최소 검증 시나리오:

1.
AI를 전혀 사용하지 않고 기존 공통 일지 작성 및 저장

2.
AI를 전혀 사용하지 않고 기존 학생별 일지 작성 및 저장

3.
AI 더미 결과로 공통 일지 자동입력

4.
AI 더미 결과로 여러 학생 개별 일지 자동입력

5.
기존 내용이 있는 상태에서 AI 적용

6.
존재하지 않는 student_id 결과 무시

7.
AI 적용 후 기존 저장 버튼으로 정상 저장

8.
저장된 일지를 다시 열어 내용 유지 확인

9.
Edit 화면에서 기존 학생 노트 수정

10.
Edit 화면에서 신규 학생 노트 추가

11.
AI 모달 닫기, 재실행, 취소 시 기존 화면 상태 이상 없음

12.
AI 관련 코드를 사용하지 않는 다른 화면에 회귀 문제 없음

각 검증 결과는 성공/실패와 실제 화면 스크린샷으로 제출하는 계획을 포함해주세요.
