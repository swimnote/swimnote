[긴급 수정 — 선생님 알림함 좋아요 알림 딥링크 오류]

현재 Production에서 실제 오류 확인.

현상:

선생님 모드
→ 알림함
→ 소식
→ "새 좋아요" 알림 선택
→ 해당 일지를 확인하는 화면이 아니라
→ "일지 수정" 화면으로 이동하고 있음.

실제 화면에서 확인 완료.

이 연결은 잘못되었다.

━━━━━━━━━━━━━━━━━━━━━━
1. 수정 전 반드시 현재 라우팅 구조부터 조사
━━━━━━━━━━━━━━━━━━━━━━

아직 코드 수정하지 말 것.

먼저 아래를 추적해서 보고:

A. 선생님 알림함 "소식" 목록을 렌더링하는 파일

B. notification item onPress handler 위치

C. like notification의
- notification type
- entity type
- diaryId
- deep_link
- metadata
등 실제 전달값

D. 좋아요 알림을 눌렀을 때 현재 어느 route로 push/replace 하는지

E. 현재 "일지 수정" 화면 route

F. 선생님이 기존 일지를 단순 조회할 때 사용하는 화면/route가 따로 존재하는지

G. 학부모 피드의 해당 일지를 선생님이 읽기 전용으로 볼 수 있는 기존 화면이 있는지

H. 댓글 알림의 현재 destination도 함께 조사.
좋아요와 동일하게 일지 수정 화면으로 잘못 연결되어 있는지 확인.

I. 서버 notification 생성 시 deep_link를 잘못 만들고 있는지,
아니면 클라이언트 notification onPress가 임의로 일지 수정 route로 변환하고 있는지 구분.

━━━━━━━━━━━━━━━━━━━━━━
2. 원하는 최종 동작
━━━━━━━━━━━━━━━━━━━━━━

좋아요 알림:

선생님
→ 알림함
→ 소식
→ 새 좋아요
→ 해당 좋아요가 발생한 "수업피드/일지" 확인

절대로 자동으로 "일지 수정" 화면으로 보내지 말 것.

좋아요는 학부모의 반응을 확인하기 위한 알림이다.
따라서 조회 목적의 destination이어야 한다.

━━━━━━━━━━━━━━━━━━━━━━
3. 댓글도 함께 검증
━━━━━━━━━━━━━━━━━━━━━━

"새 댓글" 알림 역시 조사.

댓글 알림은 사용자가 해당 댓글을 확인할 수 있는
기존 댓글/피드 조회 화면이 있다면 그쪽으로 연결하는 것이 우선.

단,
이번 작업에서 새로운 댓글 UI나 새로운 피드 화면을 임의로 만들지 말 것.

현재 존재하는 화면 구조를 조사한 뒤
가장 적절한 기존 destination을 보고할 것.
