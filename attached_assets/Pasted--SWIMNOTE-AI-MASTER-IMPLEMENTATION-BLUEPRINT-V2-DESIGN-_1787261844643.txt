# 0. 최상위 사업/기술 목표

SWIMNOTE AI의 목표는:

> AI 호출을 최소화하는 것이 아니다.

목표는:

> 필요한 곳에는 AI/API를 적극적으로 사용하여
> 병목을 제거하고,
> 정확도와 사용자 만족도를 높이고,
> 운영 인건비를 줄이되,
> 모든 비용을 측정하고 즉시 통제할 수 있는 시스템을 만드는 것.

세 가지 최상위 기준:

## A. PERFORMANCE

AI/API가 들어갔을 때:

* 검색 정확도 증가
* 응답 품질 증가
* 자연어 이해 증가
* 자동화 증가
* 사용자 만족도 증가
* 운영 업무 감소

가 크다면 적극적으로 도입한다.

## B. COST CONTROL

운영자는 반드시 알 수 있어야 한다.

* 오늘 얼마 사용했는가
* 이번 달 얼마 사용했는가
* 어떤 기능이 돈을 가장 많이 사용하는가
* USER_ACTION 비용은 얼마인가
* SYSTEM_MAINTENANCE 비용은 얼마인가
* 어떤 provider/model이 비싼가
* pool별 비용은 얼마인가
* 호출 1건 평균 비용은 얼마인가

그리고 과도한 비용이 발생하면
운영자가 즉시 억제할 수 있어야 한다.

## C. COST PERFORMANCE

조금 더 좋은 결과를 위해
몇 배 비싼 모델을 기본 사용하지 않는다.

기본 우선순위:

1. 충분한 품질
2. 낮은 단가
3. 빠른 응답
4. 안정성
5. 그 다음 최고 품질

즉:

"비싸지만 약간 더 좋음"

보다

"충분히 좋고 훨씬 싸고 빠름"

을 기본 선택한다.

상위 모델은 실제 품질 차이가
비용 차이를 정당화할 때만 사용한다.

# 3. AI 호출 자체도 최적화

AI 품질을 낮추는 것이 아니라
불필요한 호출을 없앤다.

예:

나쁜 구조:

Nano classification
→ Nano reranking
→ Nano answer

가능하면:

Nano 1회
→ query 이해
→ Evidence 선택
→ answer

로 통합.

단 한 호출에 과도한 Evidence를 넣어
token cost/latency가 커지는 것도 금지.

# 12. 비용 통제 Layer

이번 V2에서 중요한 추가 헌법.

관측만 하고 끝나면 안 된다.

운영자는 비용이 비정상적이라고 판단했을 때
신속하게 억제할 수 있어야 한다.

다만 현재 단계에서 자동 차단을 바로 활성화하라는 의미는 아니다.

최종 구조상 다음 Control Point를 지원할 수 있어야 한다.

### A. Feature Control

예:

SUPPORT_AI
CURRICULUM_AI
AI_DIARY
GROWTH_REPORT
STT

별 enabled/disabled 가능.

### B. Provider/Model Control

예:

특정 비싼 model 사용 중단
↓
저비용 model로 변경

가능.

### C. Background Control

SYSTEM_MAINTENANCE가 과도하면:

* Worker frequency 감소
* batch size 감소
* retry 감소
* pause

가능.

### D. Quota

필요할 경우:

pool
user
feature

별 quota 조정 가능.

### E. Emergency Kill Switch

비용 폭증/Provider 장애 시
특정 AI 기능 또는 provider 호출을
운영자가 빠르게 정지할 수 있는 구조.

# 15. Retry 비용 헌법

Retry도 돈이다.

따라서:

logical request_count
와
actual provider call count

를 구분해야 한다.

예:

Growth Report 1건

provider 최초 호출
+
retry 2회

이면:

logical feature request = 1

actual API calls = 3

retry_count = 2

비용은 3회 실제 사용량 기준.

Retry가 비용 폭증을 만들면
Dashboard에서 보여야 한다.
