그러나 최신 OTA에서도 API_BASE가:

https://swimnote.kr/api

로 들어가 있다.

eligible-occurrences 역시 이 주소로 실제 요청됐고
JSON 대신 '<'로 시작하는 응답을 받아 JSON parse가 실패했다.

따라서 이번 보강 오류의 직접 원인은
보강 날짜/정원/classGroupId 로직이 아니라
Production 앱의 잘못된 API_BASE다.

정상 API endpoint:

https://swimnote-api.onrender.com/api

이전 수정이 실제 Production bundle에 반영되지 않았다.
