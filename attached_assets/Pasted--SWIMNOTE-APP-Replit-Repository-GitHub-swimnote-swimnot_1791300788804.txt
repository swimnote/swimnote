[선생님관리 목록 — /admin/teachers 통계 JOIN 폭증 성능 수정 + 오류 UI 구분]

Production 원인 조사 완료.

확정 원인:

- teacher user rows = 8
- /api/admin/dashboard-stats = 8 정상
- /api/admin/teachers도 최종적으로 8건 반환
- 그러나 응답시간 약 84,981ms
- 통계 JOIN 중간 행 약 5,142,155건
- 모바일 apiRequest timeout = 30초
- timeout 후 teachers 초기 [] 유지
- UI가 timeout과 진짜 0명을 구분하지 않아
  “선생님이 없습니다” 표시

따라서 데이터 손실이 아니라
API query fan-out + client error-state 부재 문제입니다.

Kakao 로그인 문제는 이번 수정 범위에서 제외합니다.

원칙:

teacher users를 기준 집합으로 먼저 고정하고,
각 통계는 teacher_id 기준으로 먼저 aggregate한 뒤

예:

  SELECT teacher_id, ...
  GROUP BY teacher_id
) stats

여러 one-to-many 테이블을 raw 상태로 동시에 JOIN하여
곱집합을 만들지 마세요.
