2. 장애 A 조사 — Production 서버가 왜 1건만 반환하는지 증명
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

대상:

GET /teacher/makeups?status=waiting

Production:
https://swimnote.kr/api

반드시 실제 Production 실행 환경을 기준으로 조사.

DB 전체 건수만 다시 세지 마라.

현재 로그인 teacher가 실제 요청했을 때 적용되는
userId / poolId / SQL 조건을 그대로 적용하여 단계별 COUNT를 제출.

단 개인정보 원문/JWT 출력 금지.

다음 순서대로 COUNT:

A.
pool_id 일치
AND cancelled_at IS NULL
AND status IN ('waiting','expired')

→ total / waiting / expired

B.
A 조건
+ handed_to_teacher_id 조건

C.
A 조건
+ original_teacher_id = 현재 teacher userId

D.
A 조건
+ co_teacher 조건

E.
실제 최종 WHERE 전체 적용

→ total / waiting / expired

실기기 결과:

FINAL = total 1 / expired 0

와 서버 조사 결과가 일치해야 한다.

일치하지 않으면
현재 조사 DB/서버가 Production 요청 경로와 다른 것이다.

그 상태에서는 코드 수정 금지.
