normal

임의로 추가하지 않는다.

==================================================
3. ENTITLEMENT ACTIVATE
==================================================

Super Admin에서
X entitlement를 활성화했을 때 확인:

- entitlement true 저장
- config가 READY가 아니면 x_pending
- 즉시 x로 잘못 열리지 않음
- 기존 운영처 데이터 삭제 없음
- RevenueCat 상태를 임의로 변경하지 않음
- subscription date를 가짜로 생성하지 않음
- audit 기록 생성

==================================================
4. CONFIG READY
==================================================

entitlement true 상태에서
config를 READY로 승인했을 때:

- canonical mode = x
- Owner/Admin X entry 정상
- Teacher X entry 정상
- Parent X entry 정상
- X setup 상태 정상
- AI 기능 visibility 정상

확인.

==================================================
5. X_PENDING
==================================================

entitlement true
config != READY

상태에서:

- canonical mode = x_pending
- 실제 X AI 실행 entry 차단
- 필요한 setup/review UI만 노출
- X 기능이 완전히 활성화된 것처럼 보이지 않음

확인.

==================================================
6. ENTITLEMENT DEACTIVATE
==================================================

X entitlement를 비활성화했을 때:

- canonical mode = normal
- X 전용 UI 숨김
- X 전용 AI entry 숨김
- 일반 SWIMNOTE 기능 정상
- 기존 X 데이터 삭제 없음
- Growth data 삭제 없음
- Curriculum data 삭제 없음
- Diary data 삭제 없음
- config 값 자체를 임의로 초기화하지 않음
- audit 기록 생성

==================================================
7. RE-ACTIVATE
==================================================

동일 운영처를 다시 X 활성화했을 때:

기존 config가 READY라면
현재 canonical contract 기준으로
mode가 어떻게 복귀하는지 확인.

중요:

기존 contract를 보고 검증.

임의로 config reset 하지 않는다.

==================================================
8. MANUAL ENTITLEMENT VS REVENUECAT
==================================================

현재 수동 entitlement는
Super Admin 운영/테스트용 기능.

확인:

- RevenueCat subscription을 가짜 생성하지 않음
- purchase transaction 생성하지 않음
- subscription 날짜 조작하지 않음
- entitlement만 기존 API contract대로 제어
- UI에서 수동 제어와 실제 결제를 혼동시키지 않음

RevenueCat Product/Offering/Purchase를
이번 A5에서 새로 구현하지 않는다.
