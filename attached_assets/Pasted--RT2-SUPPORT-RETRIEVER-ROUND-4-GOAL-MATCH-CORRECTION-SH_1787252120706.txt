==================================================
1. 핵심 문제
==================================================

현재 scoring은:

- 반대 action
- wrong object
- troubleshoot mismatch

는 잘 제거하지만,

query가 명확한 action/goal을 가지고 있는데
KI가 그 action/goal을 전혀 다루지 않는 경우

충분한 penalty가 없음.

예:

query:
HOW_TO + DISABLE + NOTIFICATION

KI:
DESCRIPTION + UNKNOWN_ACTION + NOTIFICATION

→ 같은 concept/object라 score가 높게 남음.

이를 수정.

==================================================
2. GOAL / TASK SLOT 추가
==================================================

Semantic slots에 user goal을 추가.

최소:

SETTINGS_MANAGE
BEHAVIOR_CONDITION
TROUBLESHOOT
FEATURE_DESCRIPTION
USAGE_LIMIT
REQUIREMENT
MATERIAL_SUBMISSION
OTHER

예:

"알림끄는거 어디서해?"
→ SETTINGS_MANAGE

"푸시 알림 설정"
→ SETTINGS_MANAGE

"어떤 경우에 알림이 오나요?"
→ BEHAVIOR_CONDITION

"알림이 안 와요"
→ TROUBLESHOOT

"성장리포트가 뭐야"
→ FEATURE_DESCRIPTION

"월 몇 번 써?"
→ USAGE_LIMIT

==================================================
3. QUERY GOAL이 명확하면 MATCH 우선
==================================================

query.goal != OTHER인 경우:

KI.goal == query.goal
→ strong boost

KI.goal이 명확히 다름
→ strong penalty

KI.goal = OTHER/UNKNOWN
→ mild penalty

중요:

같은 concept/object라도
goal이 다르면 top-1 우선하지 않는다.

==================================================
4. REQUIRED ACTION MATCH
==================================================

query.action이 UNKNOWN이 아닌 경우:

KI.action == query.action
→ boost

KI.action이 opposite
→ 기존 strong penalty 유지

KI.action = UNKNOWN
→ penalty

즉:

query DISABLE
KI UNKNOWN

을 neutral로 두지 않는다.

사용자가 행동을 명확히 말했으면
그 행동을 설명하는 KI가 우선되어야 한다.

로 처리.

==================================================
6. DESCRIPTION KI PENALTY
==================================================

query가 SETTINGS_MANAGE/HOW_TO인데

KI가:

"어떤 경우에..."
"언제..."
"무엇인가요..."
"어떤 기능..."

등 DESCRIPTION/BEHAVIOR_CONDITION이면
top-1에서 밀어낸다.

예:

"푸시 알림 설정"
vs
"어떤 경우에 알림이 오나요?"

→ concept/object는 같아도 goal mismatch.

==================================================
7. NO FORCED WRONG ANSWER
==================================================

만약 active Knowledge 중
정확한 SETTINGS_MANAGE KI가 없다면:

관련 없는 "알림 발생 조건" KI를
억지로 top-1으로 선택하지 않는다.

그 경우:

- 관련 setting KI 여러 개가 있으면 GROUNDED_AI
- 충분한 근거 없으면 INSUFFICIENT_EVIDENCE

로 처리.

"아무 관련 KI 하나" 선택 금지.
