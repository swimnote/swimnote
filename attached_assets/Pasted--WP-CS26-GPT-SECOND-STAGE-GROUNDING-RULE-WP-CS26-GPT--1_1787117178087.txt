[WP-CS26 보완 지시 — GPT SECOND STAGE GROUNDING RULE]

기존 WP-CS26의 GPT 단계에 아래 원칙을 추가하고,
충돌하는 표현이 있으면 본 보완 지시를 우선 적용한다.

━━━━━━━━━━━━━━━━━━━━━━
A. GPT는 자유 답변기가 아니다
━━━━━━━━━━━━━━━━━━━━━━

2차 GPT 상담은
사용자 질문만 GPT에 전달해서
자유롭게 답변하게 하는 구조가 아니다.

반드시 먼저 SWIMNOTE 고객지원 DB / Knowledge Server에서
관련 자료를 검색한 뒤
검색된 검증 자료만 GPT의 근거로 제공한다.

최종 구조:

USER
→ 동일 문제 연속 3회
→ [문의사항 보내기]
→ QUERY / INTENT 분석
→ SWIMNOTE SUPPORT DB SEARCH
→ VERIFIED KNOWLEDGE RETRIEVAL
→ GPT GROUNDED REASONING
→ 사용자 답변

━━━━━━━━━━━━━━━━━━━━━━
B. GPT에 제공할 근거
━━━━━━━━━━━━━━━━━━━━━━

가능한 Context:

Canonical Answers
Support Knowledge
SOLUTION
FAQ
RULE
Frontend Map
Role/Mode Permission
verified error/recovery Knowledge
필요 시 안전한 DB state

현재 문의와 관련된 항목만 검색하여 전달.

관련 없는 Knowledge 대량 전달 금지.

━━━━━━━━━━━━━━━━━━━━━━
C. GPT의 역할
━━━━━━━━━━━━━━━━━━━━━━

GPT는 검색된 여러 Knowledge를 기반으로:

* 사용자의 질문 의도 해석
* 기존 대화 맥락 이해
* 이미 시도한 해결책 제외
* 여러 근거 조합
* 상황별 우선순위 판단
* 단계별 해결절차 구성
* 자연스러운 상담사 존댓말 작성

을 수행한다.

즉 GPT는:

"지식을 생성"

하는 것이 아니라

"SWIMNOTE DB에 존재하는 검증 지식을
사용자 상황에 맞게 추론·조합"

하는 역할이다.

━━━━━━━━━━━━━━━━━━━━━━
D. DB 우선
━━━━━━━━━━━━━━━━━━━━━━

GPT 호출 전에 반드시:

1. 현재 intent
2. 최근 동일 문제 대화
3. 기존 Direct Answer
4. 관련 Knowledge retrieval
5. role/mode/pool scope

를 확정한다.

그 결과를 GPT Input Context로 사용.

━━━━━━━━━━━━━━━━━━━━━━
E. 기존에 시도한 답변 인식
━━━━━━━━━━━━━━━━━━━━━━

연속 3회 문의라는 것은
앞선 Direct Answer만으로 문제가 해결되지 않았다는 의미다.

따라서 GPT는
같은 Canonical Answer를 그대로 반복하는 것이 아니라:

"사용자가 이미 어떤 안내를 받았는가"

를 Context로 받아야 한다.

예:

DB 1차:
"자녀 연결 상태를 확인해 주세요."

사용자:
"연결돼 있는데 안 보여요."

GPT는 다시:

"자녀 연결을 확인하세요."

만 반복하면 안 된다.

검색된 다른 verified 원인/해결책이 있다면
그 다음 가능성을 안내한다.

━━━━━━━━━━━━━━━━━━━━━━
F. Grounded Reasoning
━━━━━━━━━━━━━━━━━━━━━━

GPT가 추론 가능한 범위:

검색된 verified facts 사이의 관계
사용자 상태에 맞는 조건 선택
이미 배제된 원인을 제외
해결 순서 정렬
여러 Answer를 하나의 자연어 답변으로 결합

GPT가 추론하면 안 되는 것:

DB에 없는 SWIMNOTE 기능
DB에 없는 원인
DB에 없는 UI 경로
DB에 없는 권한
DB에 없는 가격/환불/계약 정책
DB에 없는 처리 시간
DB에 없는 장애 원인

━━━━━━━━━━━━━━━━━━━━━━
G. 근거 부족
━━━━━━━━━━━━━━━━━━━━━━

관련 Knowledge를 검색했으나
현재 문제를 충분히 해결할 근거가 없으면
GPT가 빈칸을 창작하지 않는다.

답변 예:

"현재 확인 가능한 안내만으로는 이 문제를 정확히 해결하기 어렵습니다."

이후:

"문제가 해결되었나요?"

[해결됐어요]
[아직 해결되지 않았어요]

를 표시.

사용자가:

[아직 해결되지 않았어요]

선택 시에만 Human escalation.

━━━━━━━━━━━━━━━━━━━━━━
H. Retrieval Scope Security
━━━━━━━━━━━━━━━━━━━━━━

GPT에 전달할 Knowledge는 반드시:

role
mode
pool
scope

검증 후 전달.

다른 역할
다른 모드
다른 pool

Knowledge가 Context에 섞이면 안 된다.

필수:

GPT_CONTEXT_ROLE_LEAKAGE = 0
GPT_CONTEXT_MODE_LEAKAGE = 0
GPT_CONTEXT_POOL_LEAKAGE = 0

━━━━━━━━━━━━━━━━━━━━━━
I. Dynamic DB State
━━━━━━━━━━━━━━━━━━━━━━

현재 시스템에서 안전하게 조회 가능한
실시간 상태가 필요한 질문이면:

승인된 server-side DB state resolver를 사용.

GPT가 raw DB에 자유롭게 접근하는 구조 금지.

허용:

구조화된 verified state 결과만 GPT Context에 전달.

예:

x_status = x_pending
makeup_status = requested

등.

━━━━━━━━━━━━━━━━━━━━━━
J. GPT Context 예시
━━━━━━━━━━━━━━━━━━━━━━

예:

USER ISSUE:
"아이 사진이 계속 안 보여요."

PREVIOUS DIRECT ANSWER:
"자녀 연결 상태를 확인해 주세요."

USER FOLLOW-UP:
"연결돼 있는데도 안 보여요."

RETRIEVED KNOWLEDGE:

K1:
연결된 학생에게 등록된 사진이 없는 경우
학부모 화면에 사진이 표시되지 않을 수 있습니다.

K2:
개별 사진 URL 로딩에 실패하면
해당 사진만 표시되지 않을 수 있습니다.

K3:
네트워크 연결 문제로 사진 조회가 실패할 수 있습니다.

GPT TASK:

위 검증된 내용만 사용하여
사용자가 이미 자녀 연결을 확인했다는 점을 고려하고
다음으로 확인할 사항을 상담사 존댓말로 안내한다.
