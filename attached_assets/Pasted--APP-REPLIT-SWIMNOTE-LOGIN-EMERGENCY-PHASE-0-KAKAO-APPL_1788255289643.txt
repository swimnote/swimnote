1. 카카오 공식 방식 기준 조사
==================================================

현재 SWIMNOTE 구현을
일반적인 Kakao OAuth/OIDC 로그인 방식과 비교하십시오.

확인해야 할 이상적인 흐름:

사용자
→ 카카오 로그인 버튼
→ Kakao 인증
→ authorization/token
→ Kakao stable user identifier 획득
→ SWIMNOTE 서버에서 기존 연결 계정 조회

IF 기존 연결 계정 존재:
    SWIMNOTE LOGIN

ELSE:
    신규 SWIMNOTE 계정 생성 또는
    필요한 추가정보 입력 후 가입 완료

즉:

카카오 LOGIN 버튼
카카오 SIGNUP 버튼

을 각각 별개 authentication path로 둘 필요가 있는지 검토.

하나의 "로그인/회원가입" entry point로 통합 가능한지
현재 코드와 비교해 설계하십시오.

7. 중복계정 위험 감사
==================================================

매우 중요.

예:

같은 사람이

일반 ID 가입
+
카카오 가입

또는

카카오
+
Apple

을 사용했을 때
서로 다른 SWIMNOTE 계정이 생기는지 확인.

또한:

같은 전화번호
같은 이메일
같은 학부모
같은 센터 사용자

가 중복 생성될 가능성 조사.

다음 케이스를 설계:

A.
이미 Kakao-linked account 있음
→ 로그인

B.
Kakao ID는 처음이지만
동일 verified email/phone의 기존 SWIMNOTE account 있음

→ 자동 merge 여부
→ 명시적 linking 여부
→ 별도 account 생성 여부

가장 안전한 방식을 제안.

자동 merge로 인한 account takeover 위험도 검토.

8. 카카오 비밀번호 찾기 UX
==================================================

현재 "비밀번호 찾기" 화면과 로직 감사.

카카오로만 가입한 사용자는
SWIMNOTE password가 없을 가능성이 있습니다.

이 사용자를 일반 password reset에 넣어:

"계정 없음"
"아이디 없음"
"비밀번호 찾을 수 없음"

같은 dead-end로 보내면 안 됩니다.

최종 설계 목표:

사용자가 계정 찾기/비밀번호 찾기에 들어갔을 때
가입 provider를 알 수 있는 경우:

카카오 계정
→ "카카오로 로그인해주세요"
→ 카카오 로그인 entry point

Apple 계정
→ "Apple로 로그인해주세요"
→ Apple 로그인 entry point

일반 ID 계정
→ 기존 SWIMNOTE password reset

이 흐름이 가능한지 검토.

9. 카카오 계정 비밀번호 자체 복구
==================================================

SWIMNOTE가 카카오 비밀번호를 직접 변경/재설정하면 안 됩니다.

카카오 인증 중 사용자가:

카카오 계정 비밀번호를 잊음
카카오 계정 접근 불가

상태라면

Kakao Account 공식 인증/복구 UI로 이어지는
일반적인 방식이 무엇인지 조사.

SWIMNOTE 내부에서
카카오 비밀번호 reset을 구현하려 하지 마십시오.

UX에서는:

"카카오 계정으로 계속하기"

를 통해 Kakao 인증화면으로 이동하고,
Kakao 쪽 계정 복구 기능을 사용하게 만드는 방향을 검토.

14. Apple 특수사항 감사
==================================================

Apple 로그인은 반드시 아래를 확인:

- 최초 authorization 때만 받을 수 있는 정보
- private relay email 가능성
- email이 이후 로그인에서 null일 때 동작
- stable Apple identifier로 기존 user lookup
- credential revoked 상태
- user cancel
- Sign in with Apple credential state 검증 여부

현재 코드가 email을 필수 identity로 사용한다면
위험 여부 보고.
