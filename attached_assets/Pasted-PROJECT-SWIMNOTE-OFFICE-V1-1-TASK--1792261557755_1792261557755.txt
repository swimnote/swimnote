PROJECT = SWIMNOTE OFFICE V1.1
TASK = 기존 앱 이식 기능 + 추가 요구사항 전체 대조·통합 분석
목표 = 기존 설계를 유지하면서 누락·중복·재사용 가능성·개발 순서를 검토

[1. 이번 요청]

현재까지 앱/Web에서 OFFICE로 가져온 기능과 아래 추가 요구사항을 전체적으로 대조해라.

기존 Stage 1~10과 V1.1 설계를 새 설계로 교체하지 않는다.
Stage 5~8을 중심으로 필요한 운영 기능을 보완하고, Smartro 실연동 전까지 완성할 범위를 명확히 한다.

이번 요청은 분석·의견 제출이다. 분석 자체를 위한 새 구현·빌드·설치본 제작·운영 적용은 시작하지 않는다.
기존 진행 작업은 상태를 보존하고 현재 완료·진행 중·미착수 범위를 밝혀라.
분석안은 사용자 검토 전 최종 확정하지 않는다.

[2. 현재 구현 확인 방법]

최신 branch/HEAD와 작업 상태를 확인하고 기존 소스·설치본·증거를 보존한다.
과거 보고서를 그대로 완료 증거로 사용하지 말고 관련 코드와 기존 검사 결과로 대조한다.

각 기능은 다음을 구분한다.
- 메뉴·화면 연결
- 실제 조회 연결
- 실제 저장·재조회 연결
- 서버·schema·권한·활성화 대기
- 외부 연동 대기
- 미구현
- 실제 사용자 실행으로 확인한 범위

이번 분석을 위해 전체 suite·monorepo 타입검사·Linux 통합 검증을 반복하지 않는다.
관련 소스와 기존 자료를 필요한 범위에서 확인한다.

[3. 전체 대조 범위]

A. 기존 앱/Web 이식 기능
회원·보호자·등록·일괄등록·지난회원·퇴원·Archive,
반·정원·시간표·출결·보강,
일지·사진·영상·앨범,
커리큘럼·템플릿·레벨·성장리포트·발행 이력,
학부모 요청·대화·공지,
직원·역할·권한·통계·강사정산·설정,
기존 Stage 3 Action·AI 구현.

기존에 보고한 관리자 보강 권한, 영상 재생주소 등 잔여 항목도 유지한다.

B. 회원정보·가족·운영정보
- 회원번호·이름·생년월일·학교·학년·연락처·필요한 선택 정보
- 복수 보호자·관계·대표 연락처·비상연락 우선순위·형제자매
- 유입 경로·소개자·상담 담당자·다음 연락일
- 수강별 기간·요일·시간·주당 횟수·강사·레벨·평가 이력
- 귀가 방법·허용된 인계 대상·당일 변경
- 배차 이용 요일·정류장·편도/왕복·적용 기간
- 수업 안전에 필요한 최소 주의사항과 열람 범위
- 신청서·약관 버전·동의·서명·변경 이력

연락처·보호자 등록과 앱 계정 연결·접근 권한을 구분한다.
금액·잔여횟수·미납액은 원장에서 계산하고 회원정보에 중복 수기 관리하지 않는다.
기존 회원에게 새 항목을 일괄 필수로 요구하지 않는다.

C. 상담·체험·대기·등록 전환
문의 접수·담당자·후속 연락·상담 예약,
체험·레벨테스트 예약/참석/취소/노쇼/평가,
희망 요일·시간·레벨·차량,
대기 순서·우선순위 사유·자리 제안·응답 기한,
미등록 사유·등록 전환.

D. 수강 변경·회원 유지
복수 수강·중도등록·반이동·승급·재등록,
휴원·복귀·퇴원·재입회,
신청일/적용일·미래 변경 예약·자리 유지 여부,
잔여횟수·보강·청구·차량에 미치는 영향과 이력.

E. OFFICE 통합 스케줄러
앱의 일정 확인보다 강력한 실제 운영 편성 기능이 필요하다.
- 일/주/월/목록 보기
- 강사별·레인별·반별 보기
- 반복 수업 생성·복사·이동·시간 조정
- 이번 수업/이후 수업/전체 시리즈 변경 구분
- 날짜별 정규·체험·보강·예약 인원·잔여 자리
- 회원·강사·레인 중복과 정원 초과 확인
- 정기휴무·공휴일·임시휴강·시설보수
- 대강·강사 부재·미배정
- 반이동·휴복귀·퇴원 적용일 반영
- 일정에서 명단·출결·보강·일지·전달사항 연결
- 수업/상담·체험/직원/차량/시설 일정 선택 표시
- 시간표·출석부·강사표·차량표 출력

반의 반복 일정, 회원 수강기간, 실제 수업 예약, 출결을 구분하되 연결한다.

F. 상품·수강료·할인
회차권·기간권·체험권·자유수영·묶음상품,
총횟수·기간·주당 횟수·실제 반/수업 배정,
가격표·정액/정률 할인·할인 사유·적용 기간,
중복 적용·계산 순서·반올림·수동 조정 권한,
중도등록·휴강·휴원·반이동에 따른 계산.

묶음상품의 레슨·자유수영 등 이용 권리는 각각 관리한다.
가격표 변경으로 과거 계약·거래 조건을 덮어쓰지 않는다.
센터 운영정책을 임의로 확정하지 말고 필요한 결정을 추려라.

G. 청구·수납·환불·모바일 결제 수용
재등록·Invoice·납부기한,
부분납·분납·미납·수동수납,
수동환불·청구 취소·감액·조정,
과납·미배분금·거래 이력·일일 마감.

모바일 결제도 같은 서버 원장을 사용하도록 한다.
회원/결제자, 결제 출처/수단/처리경로를 구분한다.
결제 대기·실패·확인 중·완료·취소·부분환불을 구분하고 중복 반영을 방지한다.
결제 승인과 정산 입금을 구분한다.
앱 구독/IAP를 학생 수강료 장부로 사용하지 않는다.

Smartro 연결 전 구현할 기능과 실제 연동 후 완성할 부분을 명확히 구분한다.

H. 대표용 경영관리
운영 수입·지출·지급 예정·반복 지출,
분류·거래처·지급수단·담당자·사유·증빙,
수납·환불·강사정산·차량비 등 기존 기록 연결,
자금수지·지출 통계·수납 마감.

은행 자동연동·복식부기·세무신고 시스템으로 확대하지 않는다.
운영 자금수지를 회계상 순이익으로 표시하지 않는다.

I. 소통·직원 업무
조건별 대상 선정·회원/보호자 구분,
Push/SMS 구분·템플릿·개인화·중복 처리,
예약·발송 이력·실패 대상 확인,
담당자·기한·처리 결과·인수인계,
민원·사고·보호자 연락·후속 조치.

형제자매의 같은 번호라도 내용이 다르면 단순 누락시키지 않는다.
Push 실패로 유료 문자 발송이 자동 발생하지 않도록 한다.

J. 태블릿 회원가입·전자계약
기존 관리자 앱 안의 회원 작성 전용 모드,
고정 신청/계약 양식·센터 설정,
회원/보호자 정보 입력,
상품·기간·횟수·가격·약관 자동 채움,
작성자의 직접 동의·서명,
직원 확인·중복 확인·등록,
최종 문서 보관·PDF·앱 확인.

자동 동의·자동 서명은 하지 않는다.
완료 문서는 덮어쓰지 않고 변경 문서를 연결한다.
태블릿에서 다른 회원정보·관리자 메뉴가 노출되지 않게 한다.
계약 완료와 수납 완료는 구분한다.

K. 무료 배차·승하차·귀가 인계
전달한 무료 배차 설계서를 기준으로 한다.
차량·기사·인솔자·정류장·이용 신청,
요일별 이용·적용 기간·당일 변경,
반복 템플릿·고정 조건·배차 초안·수정·승인·게시,
버전 확인·기사 안내·승하차·센터/보호자 인계,
지연·미탑승·미처리·운행 종료 확인,
차량 정비·보험·검사 기록.

네비게이션·GPS·실시간 도로 ETA는 이번 범위에 추가하지 않는다.
수업 출석·차량 탑승·귀가 완료를 같은 상태로 처리하지 않는다.
PC·기사/인솔자 앱·학부모 앱의 필요한 연결을 구분한다.

L. 전체현황·회원/수납 분석
- 오늘 수업·상담·체험·신규·휴복귀·종료 예정
- 미확인 출결·미배정 보강·미처리 요청·인계 상태
- 회원 증감·신규/재등록·상담 전환·휴퇴원
- 반/강사/레벨/연령/학교/학년별 구성·정원
- 반별/상품별/채널별 청구·수납·환불·미납
- 전월·전년 동기간 비교
- 집계 선택→같은 조건의 상세 목록→업무 처리

회원 수·수강 건수·청구 건수·납입 거래 수를 구분한다.
조회 실패·미입력·과거 자료 없음은 0으로 표시하지 않는다.
진행 중인 달은 전년 같은 날짜까지 비교할 수 있게 한다.
화면 명칭은 ‘전체현황’을 우선 검토한다.

M. 시설·물품 운영
간단한 개장/마감 점검,
수질·수온 등 실제 측정 기록,
시설 이상·보수 요청·조치 상태,
용품·교재 구매/지급/미지급/반납,
직원 근무·대강·실제 담당 수업과 기존 정산 연결.

별도 IoT·자동제어·대형 재고/인사 시스템을 추가하지 않는다.

N. 대회·플랫폼 운영지원
수영대회 정보·회차·일정·장소·요강·공식 접수처,
연령 산정 기준·참가 자격·종목·기준기록,
센터 참가 희망자·개인 종목·계영 팀,
보호자 확인·제출 명단·접수/수정/취소 상태,
출전 기록·성적 이력.

향후 플랫폼 직접 접수와 직접 대회 개최가 예정돼 있다.
단순 공지로만 만들지 말고 주최자/참가 센터의 역할과 대회·참가 데이터 관계를 검토한다.
센터 내부 신청을 주최측 접수 확정으로 표시하지 않는다.
현재 필요한 정보·명단 관리와 이후 경기 운영 기능을 구분한다.

용품·공급업체,
지역/설비별 긴급 관리업체·출장 범위·취급 장비·연락처·확인일,
강사 교육·안전·운영 품질 향상 자료도 포함한다.

O. 본사→가맹점 공지·이벤트·판매 안내
게시판·배너·상세 모달,
대상 센터·노출 기간·신청 항목,
센터정보 재사용·신청/열람/처리 상태,
취소·마감·내보내기.

게시판을 원본 정보 보관 장소로 하고 배너·알림·모달은 같은 정보로 연결한다.
광고·홍보가 수납·서명·편집 중인 작업을 가로막지 않게 한다.
본사 관리 메뉴는 권한 있는 계정에만 표시한다.

P. AI 작업창·챗봇·이용 가이드
기존 AI 작업창에서 사용법 안내·메뉴 이동·실제 조회·문구 초안·업무 실행을 통합한다.
현재 화면·선택 회원·조회 조건을 필요한 범위에서 사용한다.
메뉴와 AI는 동일한 Action/API를 사용한다.
실제 조회·제안·초안·실행 결과를 구분한다.
정형 메뉴 이동·고정 도움말을 불필요한 모델 호출로 처리하지 않는다.

업무별 짧은 가이드·검색·현재 화면 도움말·AI 안내를 같은 자료로 연결한다.
실제 구현 버전과 메뉴명을 기준으로 작성한다.

Q. Excel·PDF·인쇄·기존 자료 가져오기
각 업무에서 필요한 출력 위치를 명시한다.
- Excel/CSV: 회원·상담·대기·출결·보강·거래·미납·지출·통계
- PDF/인쇄: 계약·신청·평가·리포트·시간표·명세·참가 명단·운행표
- 현재 조회 전체/선택 행 구분
- 센터명·기간·집계 기준·출력일 표시
- 권한·개인정보·내부 메모 제외 기준
- 화면 합계와 출력 합계 일치

기존 회원·미납·잔여 수강·보강을 가져올 때 기준일·출처·중복·미확정 항목을 관리한다.
이전 결제 기록을 새 승인 거래로 표시하지 않는다.

[4. 모든 메뉴의 공통 정보 구조·디자인]

익숙한 상용 업무 프로그램의 사용성을 우선한다.

- 왼쪽 메뉴→업무 목록→상세→탭
- 짧은 등록·수정은 공통 모달
- 깊은 탐색은 상세 화면·탭·펼치기·뒤로가기
- 필요한 보조 선택/확인은 허용하되 중첩 모달을 기본 탐색 방식으로 사용하지 않음
- 검색·필터·선택·스크롤·작성 내용 보존
- 저장 성공 후 원래 화면 갱신
- 실패 시 입력 유지, 결과 불명 시 중복 실행 방지
- 버튼 위치·용어·표·날짜·금액·상태·로딩·오류 표현 통일
- 기존 Side Workspace를 재사용한 AI·검색·알림·오늘 할 일·빠른 등록
- 메뉴·AI·바로가기 모두 같은 화면과 업무 처리 사용

전면 디자인 재개발을 시작하지 않는다.
기존 OFFICE 기반으로 공통 구조와 필요한 수정 범위를 제안한다.

[5. 분석 결과 제출 형식]

1) 분석 기준
branch/HEAD, 진행 작업, 확인한 소스·기존 자료, 직접 확인하지 못한 범위.

2) 전체 기능 대조표
업무 / 현재 상태·근거 / 재사용 대상 / 누락 /
클라이언트·서버·DB·앱 추가 작업 /
의존성·정책 결정 / 출력물 / 기존 Stage 배치.

3) 전체 메뉴 조감도
기존 메뉴와 추가 메뉴를 통합하고 중복 제거.
센터 업무·운영지원·본사 관리 구분.
각 업무의 정식 진입점과 상세·모달·AI 연결 방식 표시.

4) 핵심 흐름의 누락 분석
상담→등록→계약→수강→청구,
결석→보강→소진,
휴강/반이동/휴원→일정·금액·차량,
재등록→다음 기간,
탑승→수업→귀가,
환불/조정→잔액·수강권·통계,
평가→승급·반이동,
대강→실제 담당 수업·정산을 대조.

5) 최소 데이터·API 보완안
기존 관계 재사용과 실제 신규 필드/API를 구분.
미래 대비만을 위한 미사용 구조·범용 엔진은 제안하지 않는다.

6) 개발·통합 전달 순서
기존 Stage 5~8 안에서 큰 업무 묶음으로 제안.
준비된 기능 우선, 승인 대기는 해당 동작에만 적용.
기능 하나마다 설치본 제작·사용자 확인을 요구하지 않는다.

7) 보완 의견
추가로 발견한 필수 기능은
실제 운영 상황 / 빠졌을 때 문제 / 최소 구현 / 기존 Stage를 함께 제시.
필수·권장·후속을 구분하고 임의로 확정하지 않는다.

[6. 유지할 경계]

기존 APP/Web/API·인증·Pool·권한·DB·저장소·Action을 재사용한다.
PC와 앱의 별도 업무 원장·별도 업무 서비스를 만들지 않는다.
태블릿 신청서·배차 등 이번에 요청한 앱 기능을 과거 client-only 조건으로 일괄 제외하지 않는다.

운영 schema 적용·배포·실발송·실거래·신규 유료 호출은 기존 승인 범위를 유지한다.
해당 의존성이 독립 기능 전체의 개발을 막지 않도록 구분한다.

별도 격리 DB·합성 인증 플랫폼·검증 전용 설치본·불필요한 전체 검사 반복은 추가하지 않는다.
이번에는 분석안과 의견을 제출하고, 사용자 검토 후 구현 범위와 계획서를 통합한다.
