# SWIMNOTE 2.0 LOCKED MASTER DESIGN
# WP2A CORRECTION — VIDEO STORAGE LIMIT CONSISTENCY CHECK

WP2A 완료보고 검수 중 LOCKED DESIGN과 충돌 가능성이 있는 1건이 발견되었습니다.

이번 작업은 WP2A 보정입니다.
WP2B로 넘어가지 마십시오.

==================================================
1. 문제
==================================================

WP2A 완료보고에 다음 변경이 기록되어 있습니다.

subscriptionResolver.ts:

videoEnabled = true

videoStorageLimitMb = 1024 * 1024
→ 전 플랜 1TB

하지만 LOCKED MASTER DESIGN에는
"영상 전용 1TB 저장공간" 정책이 없습니다.

LOCKED 저장공간 정책은:

SWIMNOTE = 10GB
X300 = 300GB
X500 = 500GB
X1000 = 1000GB

그리고:

사진 + 영상 = 동일 unified storage quota

입니다.

영상에 별도 1TB quota를 부여하면 안 됩니다.

==================================================
3. LOCKED 동작
==================================================

최종적으로 영상 저장한도는
별도 고정 1TB가 아니라
pool의 실제 effective storage quota와 일치해야 합니다.

즉:

effective_storage_gb
=
base_plan_storage_gb
+
swimming_pools.extra_storage_gb

사진과 영상이 동일 quota를 공유합니다.

따라서 `videoStorageLimitMb`가 legacy compatibility 때문에
반드시 response에 남아야 한다면:

videoStorageLimitMb
=
effective_storage_gb * 1024

또는 현재 계약상 동일 의미가 되는
실제 plan storage 기반 파생값으로 반환하십시오.

예:

SWIMNOTE 10GB
→ 10240MB

X300 300GB
→ 307200MB

X500 500GB
→ 512000MB

X1000 1000GB
→ 1024000MB

DATA pack이 추가되면
해당 field가 실제 total effective quota를 의미하는 계약이라면
extra storage까지 포함해야 합니다.

단 실제 field 의미가 "video 전용 limit"이 아니라
legacy UI 용도 등 다른 의미라면
사용처 근거를 먼저 제시한 뒤
LOCKED DESIGN과 모순이 없도록 최소 변경하십시오.

5. Production rollout lock 추가 확인
==================================================

현재 WP2A 서버를 Production deploy하면:

billing/features
→ video_enabled=true

가 기존 1.6.3 Coach 사용자에게도 전달되고
영상 업로드 버튼이 열립니다.

그러나 WP5 1080p client compression은 아직 미구현입니다.

따라서 다음 rollout lock을 명시하십시오.

PRODUCTION ROLLOUT RULE:

WP2A server changes containing
global video_enabled=true / video gate removal

은 WP5 영상 압축 구현 및 최종 회귀검증 전
Production에 배포하지 않는다.

현재 release/v2.0.0 branch 코드 수정은 허용.

Production deploy는 금지.

이 정책을 코드로 임시 feature flag 추가하라는 뜻이 아닙니다.
현재 배포 순서 규칙으로 기록만 하십시오.
