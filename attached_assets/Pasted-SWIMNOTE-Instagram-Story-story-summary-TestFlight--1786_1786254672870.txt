학부모 일지 상세

2. 클라이언트 실제 호출 코드 확인
━━━━━━━━━━━━━━━━━━━━

TestFlight runtimeVersion 1.6.2에서
Story 버튼이 실제 호출하는 코드 확인.

반드시 제출:

- 파일 경로
- 실제 URL
- API_BASE
- diaryId 전달값
- Authorization header 사용 여부
- request body/query
- response parsing 코드

  "스토리 요약을 만들지 못했습니다"

response.ok === false 때문인지

또는

response JSON의 key/schema가 클라이언트 기대값과 달라

3. 실제 diaryId 확인
━━━━━━━━━━━━━━━━━━━━

Story 버튼을 누른 현재 일지의 실제 diaryId를 확보.

빈 문자열 / classGroupId / studentNoteId와 혼동 금지.

확인:

client diary.id
→ story-summary request diaryId

두 값이 동일한지 제출.

━━━━━━━━━━━━━━━━━━━━
4. 실제 parent 권한 경로 확인
━━━━━━━━━━━━━━━━━━━━

현재 로그인한 parent가
해당 화면에서 실제 태웅 학생 일지를 볼 수 있으므로,

story-summary 권한 검증이
기존 parent diary 조회 권한보다 더 강하거나
다른 조건을 쓰는지 비교.

비교:

A. 기존 parent diary/detail API 권한 조건
B. story-summary API 권한 조건

두 조건이 다르면 정확한 차이 제출.

특히:

- parent ↔ student 연결
- diary student note 연결
- class membership
- pool
- current/withdrawn student
- guardian phone/link

중 어떤 조건에서 거절되는지 확인.

━━━━━━━━━━━━━━━━━━━━
5. HTTP 200인데 앱 실패하는 경우

서버 response 실제 JSON을 제출.

예:

{
  "summary": "..."
}

인지,

{
  "data": {
    "summary": "..."
  }
}

인지 등 실제 구조 확인.

클라이언트가 기대하는 property와 정확히 비교.

summary:
- string인지
- null인지
- empty인지
- 길이 제한 검사에서 실패하는지

확인.

━━━━━━━━━━━━━━━━━━━━
