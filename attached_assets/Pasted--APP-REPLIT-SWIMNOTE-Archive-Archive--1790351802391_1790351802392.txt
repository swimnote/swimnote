1. 핵심 문제 — student note 기반 snapshot 금지
━━━━━━━━━━━━━━━━━━━━━━

현재 설계에는:

withdrawn_diary_archives 생성
→ class_diary_student_notes 기반

이라고 되어 있습니다.

하지만 SWIMNOTE 일지는:

class_diaries.common_content
+
class_diary_student_notes.student_note

구조입니다.

따라서 학생별 note가 없는 수업이라도
그 학생이 실제로 볼 수 있었던
class diary가 존재할 수 있습니다.

Archive 목표는:

“학생별 note가 존재했던 일지”

가 아니라

“퇴원 직전까지 해당 학생이 실제로 볼 수 있었던
과거 수업일지 전체”

입니다.

이 차이를 정확히 조사하십시오.

━━━━━━━━━━━━━━━━━━━━━━
2. 기존 canonical diary visibility 재사용
━━━━━━━━━━━━━━━━━━━━━━

현재 Parent diary 접근 정책에는 이미:

- student_class_history
- 현재 class 직접 일치
- lesson_date
- student.created_at
- attendance absent 제외
- completed makeup 허용

퇴원 Archive snapshot에서
새로운 자체 규칙을 만들지 마십시오.

현재:

GET /students/:id/diary

또는 이를 구성하는 canonical query/helper 기준으로

“퇴원 시점까지 이 학생이 실제 열람 가능한 diary”

를 결정할 수 있는지 확인하십시오.

목표:

Archive 대상 diary 집합
=
Parent가 퇴원 직전에 정상적으로 조회할 수 있는
과거 diary 집합

이어야 합니다.

7. swim_diary legacy 6건
━━━━━━━━━━━━━━━━━━━━━━

현재 보고:

이라고 했습니다.

따라서 이 6건 중 실제 학생 교육기록이 존재하면
Archive 없이 삭제될 수 있습니다.

- Archive에 포함해야 하는지

실제 사용자 기록이면
무조건 제외하지 마십시오.

완전히 폐기 가능한 legacy임을 증명하지 못하면
Archive 대상에 포함하는 안전한 방법을 제안하십시오.

9. 회원 Archive 식별키
━━━━━━━━━━━━━━━━━━━━━━

현재 회원 snapshot에 전화번호 원문은
보존하지 않는 방향을 유지합니다.

다만 관리자가 수동 연결 후보를 찾을 때
동명이인을 구분할 수 있도록

퇴원 직전 normalized parent_phone을 이용한:

parent_phone_hash

추가를 검토하십시오.

예:

SHA-256(normalized_phone)

원문 전화번호 저장 금지.

용도:

- 관리자 수동 연결 후보 확인 보조
- 동일 전화번호 여부 확인

금지:

- 자동 archive link
- parent auto approval
- bulk duplicate matching
- 자동 재가입 복구

Archive는 절대 자동연결 source가 아닙니다.

12. 최종 구현 기준
━━━━━━━━━━━━━━━━━━━━━━

Archive 대상 diary는 반드시:

“note가 있는 diary”

가 아니라

“해당 학생의 canonical visibility 기준에 포함되는 diary”

여야 합니다.

각 diary에 note가 있으면 같이 snapshot,
없으면 NULL.

Archive snapshot 성공 후에만
기존 canonical purge 진행.

기존 연기/퇴원 정책은 변경하지 않습니다.
