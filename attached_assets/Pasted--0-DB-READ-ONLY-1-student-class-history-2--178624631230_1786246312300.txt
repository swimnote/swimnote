[승인 — 일지 학생 0명 오류 DB READ-ONLY 원인 확정]

현재 직접 원인은 아직 미확정이며 후보는:

1. student_class_history 날짜 범위 문제
2. attendance status 때문에 diary.tsx에서 학생 제거

두 후보를 구분하기 위해 DB 조회만 승인한다.

중요:
이번 단계는 READ-ONLY 조사다.

1. 실제 ID 확정
━━━━━━━━━━━━━━━━━━━━━━

먼저 2026-08-13 / 목 19:00반 기준으로 실제:

- class_group_id
- 서태웅 student_id

를 현재 API 응답 또는 DB에서 확인한다.

이름 문자열을 임의로 ID 대신 사용하지 않는다.

개인정보 원문은 보고서에서 마스킹 가능.

2. student_class_history 조회
━━━━━━━━━━━━━━━━━━━━━━

실제 ID로 SELECT만 실행:

SELECT
  student_id,
  class_group_id,
  enrolled_at,
  left_at
FROM student_class_history
WHERE class_group_id = '<ACTUAL_CLASS_GROUP_ID>'
  AND student_id = '<ACTUAL_STUDENT_ID>'
ORDER BY enrolled_at DESC;

확인:

- row 존재 여부
- enrolled_at
- left_at
- 2026-08-13이
  enrolled_at <= date
  AND (left_at IS NULL OR left_at > date)
  조건에 포함되는지

━━━━━━━━━━━━━━━━━━━━━━
3. attendance 조회
━━━━━━━━━━━━━━━━━━━━━━

SELECT
  student_id,
  class_group_id,
  status,
  date
FROM attendance
WHERE class_group_id = '<ACTUAL_CLASS_GROUP_ID>'
  AND student_id = '<ACTUAL_STUDENT_ID>'
  AND date = '2026-08-13';

확인:

- row 존재 여부
- 실제 status
- present / late / absent 중 무엇인지

4. 필요하면 students 현재 배정도 조회
━━━━━━━━━━━━━━━━━━━━━━

fallback /students?class_group_id=...가 왜 0을 반환했는지도 확인하기 위해
현재 students row를 READ-ONLY로 확인:

SELECT
  id,
  class_group_id,
  assigned_class_ids,
  status,
  deleted_at
FROM students
WHERE id = '<ACTUAL_STUDENT_ID>';

확인:

- class_group_id
- assigned_class_ids 안에 해당 반 ID 존재 여부
- status
- deleted_at

5. 서버 로직과 실제 값 대입
━━━━━━━━━━━━━━━━━━━━━━

실제 DB 값을 아래 로직에 대입하여 결과를 계산한다.

today-schedule 조건:

enrolled_at <= '2026-08-13'
AND
(left_at IS NULL OR left_at > '2026-08-13')
AND
deleted_at IS NULL

diary.tsx 추가 필터:

status not in deleted/archived
AND
student_id not in absentIds

그리고 다음을 확정한다.

A.
today-schedule students 배열에
서태웅이 포함되어야 하는가 YES/NO

B.
attendance 필터 후 diary classStudents에
서태웅이 남아야 하는가 YES/NO

C.
fallback /students?class_group_id 결과에
서태웅이 포함되어야 하는가 YES/NO
