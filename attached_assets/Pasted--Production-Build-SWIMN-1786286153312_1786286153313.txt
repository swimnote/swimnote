[최우선 작업 — 현재 검증 완료 상태 영구 동결 백업 / 이후 작업 금지]

중요:

지금부터 Production Build 준비보다 먼저
현재 실기기에서 검증 완료된 SWIMNOTE 1.6.2 상태를
절대 손실되지 않는 복구 기준선으로 별도 보존한다.

이 작업이 완료되기 전:

- 코드 수정 금지
- merge 금지
- rebase 금지
- reset 금지
- checkout으로 작업상태 변경 금지
- OTA 금지
- Native Build 금지
- Render 배포 금지
- DB 변경 금지
- app.json/eas.json 변경 금지

현재 상태의 단 한 가지 기능도 손실되면 안 된다.

2. 현재 코드 기준선 Backup Branch 생성
━━━━━━━━━━━━━━━━━━━━━━

현재 검증 완료 HEAD를 기준으로
전용 backup branch를 생성한다.

권장 이름:

backup/swimnote-1.6.2-pre-production-final-20260809

중요:

- 현재 HEAD를 정확히 가리켜야 함
- 다른 branch HEAD 사용 금지
- main 기준으로 만들지 말 것
- 과거 production 1.6.1 기준으로 만들지 말 것
- 현재 실기기 검증된 최신 HEAD 기준

remote origin에 반드시 push한다.

3. Immutable Git Tag 생성
━━━━━━━━━━━━━━━━━━━━━━

같은 exact SHA에 tag도 만든다.

권장:

swimnote-1.6.2-pre-production-final-20260809

또는 기존 tag naming 규칙이 있다면
동일 의미로 맞춘다.

tag는 반드시 현재 exact HEAD SHA를 가리켜야 한다.

remote origin에 push한다.

Backup branch SHA와 Tag SHA가
현재 HEAD와 정확히 동일한지 다시 검증한다.

8. 복구 명령까지 작성
━━━━━━━━━━━━━━━━━━━━━━

만약 이후 Production Build 준비 중 문제가 생기면
현재 상태로 즉시 돌아오는 정확한 방법을 작성한다.

예:

git checkout <exact backup tag>

또는 새 복구 branch:

git switch -c recovery/swimnote-1.6.2 \
  swimnote-1.6.2-pre-production-final-20260809

중요:

복구 절차에서
기존 backup branch/tag를 강제로 이동시키지 않는다.

force push 금지.

9. Backup 무결성 검증
━━━━━━━━━━━━━━━━━━━━━━

반드시 확인:

current HEAD
==
backup branch SHA
==
backup tag SHA

세 값이 완전히 동일해야 한다.

그리고:

git diff <backup-tag>..HEAD

결과:

0 files

이어야 한다.

설정 Snapshot도 동일해야 한다.

다음이 origin에 실제 존재하는지 확인:

origin/backup/swimnote-1.6.2-pre-production-final-20260809

tag:
swimnote-1.6.2-pre-production-final-20260809

remote 조회로 재확인한다.
