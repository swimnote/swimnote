10. STAGING 필요 개수 결정
============================================================

코드 구조를 바탕으로 다음 중 하나를 판정.

CASE A:
Staging Supabase 1개면 충분

조건:
두 Production URL 중 하나가 legacy/unused이거나
하나의 Staging DB에서 두 역할을 안전하게 재현 가능.

CASE B:
Staging Supabase 2개 필요

조건:
MAIN DB와 POOL DB가 실제 별도 logical database이며
둘 다 runtime에서 사용되고
schema/role이 독립적.

CASE C:
한 프로젝트 내 서로 다른 schema/database로 재구성 가능하지만
현재 production architecture와 달라 테스트 fidelity가 떨어짐.

가장 안전한 선택을 추천.

비용보다 안전성 우선.
