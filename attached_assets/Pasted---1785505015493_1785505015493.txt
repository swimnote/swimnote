보조교사 학생목록 미표시 버그 재수정 요청

현재 상태

- 보조교사로 로그인하면 오늘 수업 카드와 반 상세 화면까지는 정상 진입됩니다.
- 그러나 반 상세 화면의 학생 목록에
  “배정된 학생이 없습니다”
  라고 표시됩니다.
- 즉 today-schedule 조회는 수정됐지만,
  실제 반 학생목록 조회 경로는 아직 보조교사를 허용하지 않는 상태입니다.

현재 화면 확인

반:
금 19:00반

날짜:
2026-07-31

보조교사 로그인:
반 상세 진입 가능

학생목록:
0명 / “배정된 학생이 없습니다”

1. 추측 수정 금지
━━━━━━━━━━━━━━━━━━━━━━

today-schedule.ts를 다시 수정하는 것으로 끝내지 마십시오.

이 화면이 실제로 학생목록을 가져오는 전체 경로를 추적하십시오.

반드시 확인할 것:

- 이 화면 컴포넌트 파일
- 학생목록을 불러오는 hook
- service 함수
- 실제 호출 API URL
- 서버 route
- repository/query
- 권한 체크 함수
- student_class_history 또는 class-student 관계 조회 조건
- primary teacher만 허용하는 조건 존재 여부

2. 실제 원인 후보
━━━━━━━━━━━━━━━━━━━━━━

아래 가능성을 모두 확인하십시오.

A.
학생목록 API 내부에서

class_groups.teacher_user_id = currentTeacherId

만 검사하는 경우

B.
반 조회는 co_teacher_ids까지 허용하지만,
학생목록 조회 API의 권한 검사에서는 주담당 교사만 허용하는 경우

C.
프론트에서 currentTeacherId === teacher_user_id 조건으로
학생 배열을 비우는 경우

D.
반 상세 객체에는 co_teacher_ids가 포함되지 않아
프론트 권한 판정이 실패하는 경우

E.
학생 조회가 class_group_id가 아니라
teacher_user_id를 기준으로 조회되는 경우

F.
student_class_history JOIN에서 teacher 조건이 들어가
보조교사에게 학생이 누락되는 경우

━━━━━━━━━━━━━━━━━━━━━━
3. 올바른 권한 조건
━━━━━━━━━━━━━━━━━━━━━━

현재 로그인 사용자가 다음 중 하나이면
해당 반 학생목록을 조회할 수 있어야 합니다.

- 운영자
- class_groups.teacher_user_id와 일치하는 주담당 교사
- class_groups.co_teacher_ids에 포함된 보조교사

권한 판정은 다음 의미여야 합니다.

isOwner
OR isPrimaryTeacher
OR isCoTeacher

단, 학생 조회 자체는 teacher_id가 아니라
class_group_id 기준으로 수행해야 합니다.

즉:

1. 해당 사용자가 반 접근 권한이 있는지 검증
2. 권한이 있으면 class_group_id에 속한 학생 전체 조회

교사 ID로 학생을 직접 필터링하지 마십시오.

5. 테스트
━━━━━━━━━━━━━━━━━━━━━━

A. 주담당 교사 로그인
→ 학생목록 정상 표시

B. 첫 번째 보조교사 로그인
→ 동일 학생목록 정상 표시

C. 두 번째 보조교사 로그인
→ 동일 학생목록 정상 표시

D. 운영자 로그인
→ 정상 표시

E. 담당하지 않은 교사
→ 접근 불가

F. 다른 센터 교사
→ 접근 불가

G. 학생 수가 10명이면
→ 정원 10명과 별개로 실제 배정 학생 10명이 표시되는지 확인

H. 수업일지 화면에서도
→ 동일 학생목록 표시 확인
