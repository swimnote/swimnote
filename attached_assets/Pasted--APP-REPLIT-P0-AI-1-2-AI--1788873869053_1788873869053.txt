[P0 — AI 일지피드 / 일반 일지 목록 통합]

현재 관리자에:

1. 일반 일지 목록
2. AI 일지피드

두 개의 일지 목록 화면이 따로 존재한다.

실제 저장 구조상 AI Diary도 기존 Diary로 저장되므로
별도 AI 일지 목록을 유지할 실익이 있는지 먼저 코드 기준으로 확인한다.

새 기능 개발/리팩터링 금지.
목표는 일지 조회 경로 단순화.

1. 현재 두 화면 비교
━━━━━━━━━━━━━━━━━━━━━━

실제 코드 기준으로 아래만 확인:

- AI 일지피드 route/component
- 일반 관리자 일지 목록 route/component
- 각각 사용하는 API
- 각각 조회하는 DB source
- AI 일지가 일반 diaries에도 존재하는지
- ai_generated / ai_trace_id 등으로 AI 여부 필터 가능한지
- 상세 화면 route

결론을 먼저 보고하지 말고,
구조상 별도 유지가 필수가 아니라면 바로 아래 통합까지 수행.

━━━━━━━━━━━━━━━━━━━━━━
2. 최종 구조
━━━━━━━━━━━━━━━━━━━━━━

canonical 일지 목록 화면은 하나만 사용.

기존 관리자에서 정상 동작하는
일반 일지 목록 화면을 기준으로 통합.

여기서:

- 전체 일지
- AI 작성 일지
- 일반 작성 일지

를 필터 가능하게 한다.

AI 여부는 기존 ai_generated 등
실제 canonical field 사용.

새 Diary DB/table 만들지 말 것.

━━━━━━━━━━━━━━━━━━━━━━
3. AI 일지피드
━━━━━━━━━━━━━━━━━━━━━━

현재 별도 AI 일지피드 목록 화면은
중복이면 일반 사용자 navigation에서 제거.

X Dashboard의:

AI 일지 건수

는 유지.

숫자/카드 클릭:

→ canonical 통합 일지 목록
→ AI 필터 자동 적용

되게 연결.

즉:

AI 일지피드 = 별도 데이터 화면이 아니라
통합 일지 목록의 AI 필터 view.

━━━━━━━━━━━━━━━━━━━━━━
4. 기존 일지 목록 진입
━━━━━━━━━━━━━━━━━━━━━━

회원관리 등 기존 일반 일지 진입도
동일 canonical 목록 사용.

예:

회원관리 → 학생 → 일지
→ 동일 일지 목록
→ 해당 학생 filter

X Dashboard → AI 일지
→ 동일 일지 목록
→ AI filter

관리자 전체 일지
→ 동일 일지 목록
→ filter 없음

목록 component/page를 여러 개 유지하지 말 것.

━━━━━━━━━━━━━━━━━━━━━━
5. 일지 클릭 동작 수정
━━━━━━━━━━━━━━━━━━━━━━

현재 AI 일지피드에서
일지 card 클릭 시 Home으로 튀는 오류가 있음.

수정:

일지 card
→ 해당 diary의 기존 canonical detail 화면

Home 이동 금지.

뒤로가기:
detail
→ 직전에 보던 일지 목록

AI filter / 학생 filter / 날짜 filter 유지.

Production 실데이터로:

A. 관리자 전체 일지 목록
→ AI + 일반 모두 표시

B. AI filter
→ AI 일지만 표시

C. 일반 filter
→ 일반 일지만 표시

D. X Dashboard AI 일지 건수 클릭
→ AI filter 적용된 동일 목록

E. 회원관리 학생 일지
→ 같은 목록 + 해당 학생 filter

F. 일지 card 클릭
→ 상세 정상

G. 뒤로가기
→ 이전 목록/필터 유지

H. Home으로 튀는 현상 0
