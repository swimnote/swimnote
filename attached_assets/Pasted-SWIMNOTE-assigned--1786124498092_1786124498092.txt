SWIMNOTE 보강 — "날짜 다시 선택" 실제 버튼 복구 재조사

방금 제출한 설계는 승인하지 않는다.

이유:
사용자가 요청한 것은 assigned 탭 카드에 신규 버튼을 추가하는 것이 아니다.

사용자가 말한 것은
보강 배정 과정에서 이미 존재하는

"날짜 다시 선택"

버튼이 예전처럼 다시 정상 작동하게 만드는 것이다.

너의 조사에서도 현재:

artifacts/swim-app/app/(teacher)/makeups.tsx
line 약 1115~1125

"날짜 다시 선택"
onPress={() => setSelectedDate(null)}

버튼이 실제 존재한다고 확인했다.

따라서 assigned 카드에 신규 버튼 추가 계획은 폐기한다.

현재 존재하는 "날짜 다시 선택" 버튼의 전체 흐름을 추적한다.

2. setSelectedDate(null)만으로 충분한지 확인
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

현재 버튼은:

setSelectedDate(null)

만 실행한다.

그런데 날짜 하나를 선택할 때 함께 설정되는 state가 무엇인지 조사한다.

특히:

setSelectedDate(...)
setSelectedOccurrence(...)

가 같이 설정된다면,

"날짜 다시 선택" 시
selectedDate만 null로 만들고
selectedOccurrence가 이전 값으로 남는지 확인한다.

또 다음 값들이 남아서
UI가 다시 날짜 목록으로 정상 복귀하지 못하는지도 확인:

- selectedOccurrence
- occError
- occErrorDetail
- occLoading

실기기 증상과 연결해서 판정한다.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━
3. 렌더 조건 전체 확인
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

배정 모달 단계가 어떤 조건으로 나뉘는지 원문 제출.

예:

A.
!selectedClassId
→ 반 선택

B.
selectedClassId && !selectedDate
→ 날짜 선택

C.
selectedClassId && selectedDate
→ 배정 확정

실제 코드를 그대로 확인한다.

"날짜 다시 선택" 클릭 후
정확히 B 상태로 돌아가기 위해
어떤 state를 초기화해야 하는지 확정한다.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━

- selectedDate만 초기화하고 selectedOccurrence가 남음
- Pressable이 disabled

정확한 원인 하나를 코드로 특정한다.
