[SWIMNOTE RELEASE MASTER WORK ORDER]
[PHASE A / A2 — NORMAL SWIMNOTE AI VISIBILITY CLEANUP]

목적:

일반 SWIMNOTE에서는 X 전용 AI 기능의 사용자 노출을 제거하고,
SWIMNOTE X에서만 해당 AI 기능이 정상적으로 노출되도록 정리한다.

중요:

이번 작업은 AI 기능 삭제가 아니다.

- AI ENGINE 삭제 금지
- APP AI API 삭제 금지
- DB 구조 삭제 금지
- 기존 AI 결과 로직 변경 금지
- Prompt 변경 금지
- Knowledge 변경 금지
- Growth Report 로직 변경 금지
- Parent Curriculum 로직 변경 금지
- X entitlement/config canonical rule 변경 금지
- 현재 디자인 시스템 대규모 재수정 금지

오직:

NORMAL / X_PENDING / X

상태에 따른
AI 기능의 visibility / entry access를 정리한다.

==================================================
1. CANONICAL MODE — FIXED
==================================================

반드시 기존 canonical mode 사용:

normal
x_pending
x

판정 규칙은 기존 구현을 그대로 재사용한다.

새로운 X mode 판정 함수 생성 금지.

기존 resolvePoolMode 또는 현재 canonical resolver를 사용.

==================================================
2. NORMAL MODE
==================================================

normal에서는
X 전용 AI 기능의 사용자 진입점을 노출하지 않는다.

중요:

기능 자체를 삭제하지 않는다.

다음 전체 Role에서 조사:

OWNER / ADMIN
TEACHER
PARENT

normal 사용자가:

- 홈
- 대시보드
- 설정
- 하단탭
- 메뉴
- 바로가기
- 카드
- 버튼
- empty state
- modal
- deep link

등을 통해
X 전용 AI 기능에 진입할 수 있는지 전수 확인한다.

==================================================
3. X MODE
==================================================

mode === "x"에서는
현재 구현 완료된 X/AI 기능을 정상 노출한다.

기존 노출 기능을 실수로 숨기지 않는다.

X에서 현재 실제 존재하는 AI 기능만 유지.

구현되지 않은 AI 기능을 새로 표시하지 않는다.

==================================================
4. X_PENDING
==================================================

mode === "x_pending"에서는
실제 AI 기능을 사용할 수 있는 것처럼 노출하지 않는다.

기존 정책에 맞게:

- 설정 진행 필요
- 심사 중
- 준비 중

등의 안내 entry가 필요한 경우만 유지.

실제 AI 실행 버튼이 노출되어
실패하게 만드는 구조 금지.

기존 x_pending 안내 UX가 있다면 재사용.

8. GROWTH REPORT
==================================================

Growth Report가
Normal과 X에서 동일 제공되는 기존 Product 정책이 있는지
현재 코드 기준으로 확인한다.

중요:

AI라는 이유만으로 무조건 X 전용으로 숨기지 말 것.

현재 SWIMNOTE Product 정책상
Normal에서도 제공되어야 하는 Growth Report 기능이면 유지한다.

즉:

"AI"라는 기술 구현 여부가 아니라
"상품 정책상 X 전용 기능인가"

를 기준으로 visibility를 결정한다.

불확실한 항목은 코드 수정 전에 보고.
