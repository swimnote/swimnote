2. 100% 이식의 기준

센터 관리자·선생님이 기존 앱에서 수행하는 운영 업무를 기준으로,
PC에서도 해당 권한으로 필요한 조회·등록·수정·처리가 가능해야 한다.

학부모 전용 화면이나 모바일 기기 전용 동작을
그대로 복제하라는 뜻은 아니다.
해당 기능에 대응하는 센터 관리 업무를 PC에 연결한다.

모바일에서만 가능한 입력·전송 방식은 제약을 명시하고
기존 PC 대응 방식이 있으면 재사용한다.
임의 누락하거나 완료로 표시하지 않는다.

3. 기존 확인 결과로 누락 목록 정리

새 전수감사 없이 기존 앱 메뉴·실제 handler·앞선 이식 목록을
대조해 짧은 기능 목록 하나로 관리한다.

각 기능은 다음만 표시:
- 기존 앱/Web 구현
- PC 조회 연결
- PC 입력·저장·처리 연결
- Action·AI 연결
- 남은 제약 또는 승인

26개 목적지가 있다는 사실을 기능 완료로 계산하지 않는다.
메뉴만 있는 상태·읽기 전용·실제 저장 가능을 구분한다.

목록 작성만 하고 멈추지 말고 바로 연결 작업을 이어간다.

6. 구현 방식

기존 Web 화면·API가 준비된 기능부터 큰 묶음으로 연결한다.
앱 전용 기능은 기존 데이터·권한·Service/API를 재사용하고
필요한 PC 입력 화면만 보완한다.

업무 단위:
화면 + 메뉴/목적지 + 필요한 API 허용 +
공통 Action + 결과 갱신 + 기존 방식의 AI 연결.

모든 API 일괄 개방 금지.
별도 PC 업무 서비스·중복 원장·로컬 DB 추가 금지.
범용 AI 재설계 때문에 앱 기능 이식을 막지 않는다.

저장 기능은 실제 API에 저장되고 재조회에 반영돼야 한다.
화면의 임시 상태만 바꾸고 저장 완료로 표시하지 않는다.
실패·실행 전 거부·저장 결과 불명을 구분한다.

개별 메뉴·기능마다 설치본을 전달하지 않는다.
