SWIMNOTE Teacher Diary AI
WP12 — 사용자 경험 및 예외 처리 완성

목적

WP12는 새로운 AI 기능을 추가하는 작업이 아니다.

현재 Teacher Diary AI의 기존 구조와 동작은 그대로 유지하면서,
선생님이 실제 앱에서 사용할 때 발생할 수 있는
이탈, 취소, 실패, 재시도, 메시지 중복 문제를 정리하는 단계이다.

================================
작업 원칙
================================

- 기존 기능 파손 금지
- AI Request Contract 변경 금지
- AI Response Contract 변경 금지
- DiaryInsertResult 변경 금지
- Student Resolution 변경 금지
- Save Payload 변경 금지
- Teacher Diary 저장 구조 변경 금지
- 대규모 리팩터링 금지
- 불필요한 파일 이동 금지
- UI 전면 개편 금지
- 최소 수정 원칙

================================
1. AI 작업 중 화면 이탈 처리
================================

다음 상태에서 화면을 닫거나 뒤로가기를 시도할 때 동작을 확인한다.

- 음성 업로드 중
- AI 생성 중
- 결과 편집 중
- 일지 삽입 직후
- 저장 중

실제 데이터 손실 또는 요청 중단 가능성이 있는 경우에만
확인 모달을 표시한다.

단순히 AI 화면을 열었다가 아무 작업 없이 닫는 경우에는
불필요한 경고를 표시하지 않는다.

================================
2. 뒤로가기 및 닫기 확인
================================

다음 조건을 구분한다.

A. 입력·결과·편집 내용 없음
→ 즉시 닫기

B. 작성한 입력 또는 생성 결과가 있음
→ 작성 내용이 사라질 수 있다는 확인 표시

C. AI 요청이 진행 중
→ 요청 취소 여부 확인

D. 저장 중
→ 저장 완료 전 중복 이탈 또는 화면 파손 방지

Android hardware back과
화면 내 닫기 버튼의 동작이 서로 모순되지 않아야 한다.

================================
3. 취소 처리
================================

사용자가 AI 생성 취소를 선택하면

- 현재 AbortController 호출
- timeout 정리
- loading 상태 해제
- 이전 요청의 늦은 응답 무시
- 화면을 다시 사용할 수 있는 상태로 복원

취소를 오류로 표시하지 않는다.

사용자에게 필요한 경우에만
'AI 작성을 취소했습니다' 수준의 짧은 피드백을 표시한다.

================================
4. 생성 실패 후 재시도 UX
================================

AI 생성 실패 후 다음이 가능해야 한다.

- 입력 내용 유지
- 학생 선택 상태 유지
- 수업 컨텍스트 유지
- 재시도 가능
- AI 화면 전체 초기화 금지

재시도 시 이전 실패 요청의 상태나 requestId가
새 요청과 충돌하지 않아야 한다.

================================
5. 네트워크 오류 안내
================================

다음 오류를 구분한다.

- 인터넷 연결 없음
- 서버 연결 실패
- 요청 시간 초과
- 인증 만료
- 서버 오류
- 잘못된 응답
- 알 수 없는 오류

내부 오류 코드, stack trace, JWT, 개인정보를
사용자 화면에 노출하지 않는다.

사용자 메시지는 짧고 행동 가능하게 작성한다.

예시 방향:

인터넷 연결 없음
→ 인터넷 연결을 확인한 뒤 다시 시도해 주세요.

시간 초과
→ 응답이 지연되고 있습니다. 잠시 후 다시 시도해 주세요.

인증 만료
→ 로그인이 만료되었습니다. 다시 로그인해 주세요.

================================
6. 오류·성공 메시지 중복 방지
================================

동일한 요청에서

- Alert
- Toast
- 인라인 오류
- 모달

이 중 여러 개가 동시에 중복 표시되지 않도록 확인한다.

한 사건에는 원칙적으로
하나의 주요 사용자 피드백만 표시한다.

빠른 연속 탭이나 React 재렌더링으로
동일 토스트가 여러 번 나타나지 않게 한다.

================================
7. Loading 상태 표시 정리
================================

다음 상태가 사용자에게 혼동되지 않도록 확인한다.

- 음성 처리 중
- AI 작성 중
- 취소 중
- 일지 삽입 중
- 저장 중

Generate, Insert, Save의 loading 상태를
하나의 공통 boolean으로 합치지 않는다.

각 상태는 기존 state machine과
WP11 중복 방지 로직을 유지한다.

로딩이 끝났는데 버튼이 계속 비활성화되거나,
로딩 중 버튼이 다시 활성화되는 문제가 없어야 한다.

================================
8. 성공 피드백 정리
================================

다음을 구분한다.

- AI 생성 완료
- 일지에 삽입 완료
- 최종 일지 저장 완료

각 단계의 성공 메시지가
사용자에게 같은 의미로 보이지 않도록 한다.

'AI 생성 완료'가
'일지 저장 완료'로 오해되지 않아야 한다.

기존 앱의 저장 성공 UX가 있다면
그 방식을 우선 유지한다.

================================
9. 입력 및 결과 보존
================================

오류나 취소가 발생했을 때
사용자가 직접 입력한 내용은 원칙적으로 보존한다.

다음 작업에서는 초기화 가능하다.

- 사용자가 명시적으로 새로 시작 선택
- 삽입 및 저장 완료 후 기존 정책에 따른 초기화
- 화면을 버리겠다고 사용자가 확인

예상치 못한 오류만으로
선생님의 원본 입력을 삭제하지 않는다.

================================
10. 기존 안정성 로직 보존
================================

WP11에서 확인된 다음 로직을 유지한다.

- isInFlightRef
- isInsertingRef
- if (saving) return
- requestId stale response 차단
- AbortController cleanup
- timeout cleanup
- isMountedRef
- Generate / Insert / Save 독립 상태

WP12 수정으로 이 로직을 제거하거나 약화하면 안 된다.

================================
11. 검증
================================

가능한 범위에서 다음 시나리오를 확인한다.

시나리오 A
AI 화면 열기 → 작업 없음 → 닫기

시나리오 B
텍스트 입력 → 닫기 → 이탈 확인

시나리오 C
Generate 시작 → 취소 → 로딩 복원 → 재시도

시나리오 D
Generate 실패 → 입력 유지 → 재시도

시나리오 E
Generate 성공 → Insert → 중복 Insert 차단

시나리오 F
Save 시작 → 뒤로가기 또는 재탭 → 중복 저장 차단

시나리오 G
Timeout → 적절한 메시지 → 재시도 가능

시나리오 H
Abort → 일반 오류 메시지 미표시

실기기나 런타임 검증을 하지 못한 항목은
PASS라고 쓰지 말고 UNVERIFIED로 구분한다.

================================
12. Git 및 TypeScript
================================

작업 전 실행:

git status
git branch -vv
git rev-parse HEAD

작업 후 실행:

git diff --stat
git status
git rev-parse HEAD

TypeScript 검사 실행.

기존 오류와 신규 오류를 구분한다.

기존 오류가 있더라도
WP12 신규 오류가 0개인지 확인한다.

완료 조건
================================

다음 조건을 모두 충족해야 WP12 구현 PASS이다.

- 화면 이탈 조건이 구분됨
- 진행 중 요청 취소 가능
- Abort가 오류로 표시되지 않음
- 실패 후 입력 유지 및 재시도 가능
- 사용자 오류 메시지가 정리됨
- 중복 메시지가 방지됨
- Generate/Insert/Save 상태가 서로 침범하지 않음
- WP11 중복 방지 로직 유지
- Contract 및 Save Payload 무변경
- 신규 TypeScript 오류 0개
- 실제 검증하지 못한 항목은 UNVERIFIED로 표시
