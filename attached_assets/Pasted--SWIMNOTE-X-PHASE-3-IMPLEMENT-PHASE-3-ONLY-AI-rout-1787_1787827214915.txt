4. "오늘 수업" KPI 정의
━━━━━━━━━━━━━━━━━━━━━━

중요:

`class_schedules` 테이블은 없음.

따라서 존재하지 않는 schedule table 사용 금지.

이전 최종 Contract에서 V1 기준:

`class_diaries`의 당일 실제 데이터 기준으로 집계.

단 "오늘 수업"이라는 문구가
실제 예정된 전체 수업 수처럼 오해될 수 있으므로
정확한 데이터 의미에 맞춰 구현.

권장 KPI 문구:

1. 오늘 일지
2. 작성 완료
3. 미작성
4. AI 생성

여기서 "오늘 일지"는
해당 날짜 `class_diaries` row 수.

만약 repository의 실제 운영 흐름상
수업이 시작될 때 diary row가 미리 생성되어
미작성 row(content NULL)가 존재하는 구조라면
미작성 KPI 사용 가능.

반대로 diary row 자체가
작성 시점에만 생성되는 구조라면
"미작성"을 정확히 계산할 수 없음.

반드시 실제 write flow 확인 후:

A. diary row가 수업 전에 존재한다
→ 미작성 KPI 구현

B. diary row가 작성할 때만 생성된다
→ 미작성 KPI 구현 금지
→ 해당 KPI는 "직접 작성" 또는 다른 실제 계산 가능한 값으로 교체

이 판단만 이번 구현 전에 targeted 확인.

광범위한 재조사 금지.
