1. Archive diary의 최종 범위
━━━━━━━━━━━━━━━━━━━━━━

Archive 대상:

해당 student가 실제로 귀속되었던
전체 과거 수업일지.

기존 canonical diary ownership/visibility 의미 중:

유지:

- cd.is_deleted = false
- student 생성 이전 diary 제외
- student_class_history 기반 실제 반 재원기간
- 현재 class 직접 귀속 fallback
- attendance absent 제외
- completed makeup 포함
- note 없는 common diary 포함
- 과거 A→B→C 반 이력 전체 포함
- 다른 학생 diary 제외

제외:

- education_started_at cutoff

즉:

장기연기 전 segment의 diary도
퇴원 Archive에는 보존해야 합니다.

예:

2026-01~06 수강
→ 장기연기
→ 2026-09 재등록
→ education_started_at=2026-09
→ 2027 퇴원

Archive에는:

2026-01~06 정상 귀속 diary
+
2026-09 이후 정상 귀속 diary

모두 포함.

단 결석으로 실제 귀속되지 않은 diary는 제외.

6. parent phone hash 보안
━━━━━━━━━━━━━━━━━━━━━━

normalized parent phone의
단순 SHA-256은 사용하지 마십시오.

전화번호 공간은 작아서
offline brute-force가 쉽습니다.

원문 전화번호는 Archive에 보관하지 않으면서
관리자에게 “동일 전화번호 여부”만 제공해야 합니다.

우선순위:

1.
프로젝트에 이미 존재하는
keyed HMAC/hash helper가 있으면 재사용.

2.
없다면 dedicated secret 기반:

HMAC-SHA256(
  ARCHIVE_PHONE_HASH_SECRET,
  normalized_phone
)

사용.

JWT secret 등
다른 목적의 secret 재사용 금지.

Archive API가 hash 값 자체를
APP/WEB에 노출할 필요는 없습니다.

관리자 연결 후보 비교 시 서버가:

phone_match: true/false

정도만 반환.

Teacher에게 phone hash/match 정보 노출 불필요.
