SWIMNOTE Teacher Diary AI
WP1~WP6 독립 코드 감사(AUDIT) 실행 지시서

중요:

이번 작업은 기능 추가 작업이 아니다.

기존 WP1~WP6 보고가 실제 Git·현재 코드·실행 구조와 일치하는지 검증하는 감사 작업이다.

기존 보고서를 증거로 사용하지 않는다.

반드시 아래를 직접 확인한다.

- Git commit
- Git diff
- 현재 파일
- 실제 함수
- 실제 호출 경로
- 실제 OTA 기록
- 실제 수행한 테스트

추측 금지.

확인하지 못한 내용은 반드시 “미확인”이라고 보고한다.

허위·과장·모호한 보고가 하나라도 발견되면 즉시 명시한다.

작업 중 코드 수정 금지.

감사가 끝날 때까지 commit, push, OTA, EAS Build, production 배포를 절대 수행하지 않는다.

7. Draft 편집·Insert·Save 감사
──────────────────────────────────

각 값이

- 어디에서 생성되는지

- 언제 초기화되는지

특히 다음을 직접 검증한다.

1. Common Draft 수정값이 실제 Insert에 사용되는가
2. Student Draft 수정값이 실제 Insert에 사용되는가
3. student_ref가 student_id로 안전하게 연결되는가
4. 이름 기준 매칭 코드가 없는가
5. Insert가 자동 Save를 호출하지 않는가
6. AI가 직접 /diaries를 호출하지 않는가
7. 기존 Save 버튼만 POST /diaries를 호출하는가
8. Common만 존재할 때 Insert 가능한가
9. Student만 존재할 때 Insert 가능한가
10. 둘 다 비었을 때 Insert가 어떻게 되는가
11. 기존 학생 메모가 유지되는가
12. 동일 학생 메모는 덮어쓰는가
13. Common 기존 내용은 교체인지 병합인지

가능한 실제 명령을 사용한다.

예:

eas update:list

각 Update ID에 대해

- 존재 여부
- 채널
- 브랜치
- 플랫폼
- commit
- 생성 시각
- 메시지

를 확인한다.

EAS 인증이나 네트워크 문제로 확인할 수 없으면 “미확인”으로 보고한다.

보고서에 ID가 있다는 이유만으로 실제 OTA로 인정하지 않는다.

- TypeScript 일부 파일 검사와 전체 프로젝트 통과를 혼동

- “회귀 없음”을 실행 없이 단정
- “앱 크래시 없음”을 실행 없이 단정

- TRUE
- PARTIAL
- FALSE
- MISLEADING
- UNVERIFIED

수정된 정확한 표현:

문제를 발견해도 수정하지 말고 증거와 함께 보고만 한다.

──────────────────────────────────
18. 최우선 원칙
──────────────────────────────────

이번 감사의 목적은 좋은 평가를 만드는 것이 아니다.

실제 상태를 밝히는 것이다.

기존 보고가 맞으면 맞다고 증명한다.

기존 보고가 틀리면 틀렸다고 보고한다.

코드가 존재해도 실행하지 않았다면 “실기기 미검증”이다.

호출 경로가 있어도 서버 성공 응답을 받지 않았다면 “E2E 미검증”이다.

Save 함수가 있어도 실제 DB 저장을 확인하지 않았다면 “DB 저장 미검증”이다.

확인하지 못한 것은 반드시 “미확인”이라고 쓴다.

감사 완료 후 반드시 멈추고 사용자 승인을 기다린다.
